# T944 - A probe of a window we do not own has no synchronous capture - say so in the script instead of leaving the torn photo unremarked

## Summary

The tail of T843. Some probed windows are not our window classes and can never
answer `WM_PRINTCLIENT`: the owner-drawn popup menu in `dark-menus.ps1`, and
the RichEdit composer in `ViewerFeedbackBar` (whose own source already records
that the subclass ignores `WM_PRINT`/`WM_PRINTCLIENT`). Anything T941-T943
leave behind for a reason belongs here too.

The point is not to convert them — it is that a probe still on the
asynchronous capture must SAY it is, and why, at the call site. Otherwise the
next reader cannot tell a deliberate exception from one nobody got to, which is
the same failure mode the `CAPTURE LIMIT` header in `TestDesktop.ps1` already
exists to prevent for the terminal surface.

Consider whether the exception should be enforced rather than commented — an
allowlist in the harness, the way `-AllowTerminalSurface` gates the
`GhozttyTerminal` refusal — so a NEW torn probe cannot be added silently.

## In plain terms

A couple of things the tests photograph belong to Windows, not to us, so they
cannot be asked to pose. Those spots should say so out loud, so nobody later
mistakes them for work that was forgotten.

## Goals

- [x] The torn capture is an explicit, reasoned opt-in rather than the default
- [x] Every remaining torn probe says which window it is and why it cannot pose
- [x] A new unexplained torn probe fails, both at run time and statically

## Validation criteria

- [x] Every remaining non-`-Sync` `Get-TestWindowPixels` call carries a comment
      naming the window and why it cannot be captured synchronously — verified
      by `printclient-audit.ps1` C8 (0 findings) and by reading the six sites
- [x] A count is recorded here: **92 probes on `-Sync`, 6 declared torn** —
      `dark-menus.ps1` (user32's `#32768` popup menu, WndProc not ours) and five
      in `test-desktop-harness.ps1` (the async-path self-test, the class-refusal
      demonstration, and three measurements of the terminal-surface limit). No
      probe targets the `ViewerFeedbackBar` RichEdit directly; the bar itself is
      captured `-Sync`, so it needs no exemption.
- [x] Enforcement added: `Get-TestWindowPixels` refuses a call with neither
      `-Sync` nor `-TornReason` (and one with both), proved by two new assertions
      in `test-desktop-harness.ps1` (ALL PASS, 80); `printclient-audit.ps1`
      section C sweeps every call site in `test\win32`, with fixtures C1/C6
      showing a bare call IS a finding (ALL PASS, 18). `dark-menus.ps1` ALL PASS
      (10) on the new flag.
