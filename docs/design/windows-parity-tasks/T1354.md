# T1354 - The Edit menu shows Ctrl+Ins / Shift+Ins for Copy and Paste instead of Ctrl+C / Ctrl+V

## In plain terms

Open the Edit menu on Windows and the Copy row advertised "Ctrl+Insert" - the old
OS/2-era chord - and the Paste row showed no shortcut at all, rather than the Ctrl+C
and Ctrl+V everybody actually presses. Both now show Ctrl+C and Ctrl+V, in the menu
bar and the right-click menu alike. The menu is where a new user learns the
shortcuts, so it should name the one they will use.

## Summary

**Verify this reproduces before building it.** The reasoning is from reading the
code, not from looking at the menu.

`menuItemLabel` (`src/apprt/win32/Window.zig` ~6757) labels each menu row from
`keybind.set.getTrigger(action)`, which reads the binding set's REVERSE map. And
`Binding.Set.putFlags` (`src/input/Binding.zig` ~2550) deliberately does not
track performable bindings in that map - `track_reverse = !flags.performable` -
because a performable chord may decline, so it is a poor thing to advertise.

Every Windows copy/paste binding that a user would actually press is
performable: ctrl+c, ctrl+v, ctrl+shift+c/v, shift+insert (T156) and now
ctrl+insert (T522). The only NON-performable ones are the plain `put()`s in the
generic non-darwin block - ctrl+insert for copy, shift+insert for paste - so
those are what stays in the reverse map and what the menu should be showing.
Note the removal branch is also gated on `track_reverse`, so re-binding
ctrl+insert as performable in T522 did not evict the stale entry either.

Fix shape is a design call, not a one-liner - the reverse map is shared core:
teach the win32 menu labeller a preferred-accelerator override for the handful
of commands where the mirror chord is the one to advertise, rather than changing
what `putFlags` tracks (which would change GTK and the C API too).

## Goals

- [x] Copy and Paste advertise Ctrl+C / Ctrl+V in the menu bar, the right-click menu and the command palette
- [x] A user who rebinds ctrl+c/ctrl+v sees their real chord, not a promise the key no longer keeps
- [x] Shared core (Binding.Set, GTK, C API) unchanged
