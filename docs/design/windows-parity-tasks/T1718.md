# T1718 - A -LoadKind build soak's workers mostly fail their builds within a minute (OutOfMemory, clang exit 45/5/66), so the 'loaded' soak runs on failed builds rather than compiles

## Summary

T954 re-run 2026-09-24 (soak label t954-repro, D:\ghoztty-soak-load\t954-repro-20260924-014216): 8 build workers on a 32-core box all exited 1 on their first iteration in 56-82s; worker logs hold 4x 'error: OutOfMemory', clang exited with code 45 (14x), 5 (4x), 66 (2x), and 'failed to parse clang diagnostics: FileNotFound'. The summary still reported load=8:build and counted 4 of those failed builds as worker-crash, so a loaded-soak verdict overstates both its load and its crash count. Find the cause (8 unbounded -j32 cold builds contending for memory/temp, a shared TMP for clang diagnostic files, or the shared global cache) and bound it: cap per-worker -j, give each worker a private TMP, and have the summary separate a worker build FAILURE from a worker CRASH and say when the load was degraded.
