# T1746 - Machine chooser session cards have no Show / Resume buttons like Mac rows do

## Summary

Filed by the T1633 chooser comparison; summary written at the 2026-09-26 triage.

Every live session row in Mac's chooser detail carries a small button on its
trailing edge: **Show** ("Bring this session's window to the front") when the
session is already open in a window here, **Resume** ("Resume this session in a
new window") when it is not, beside the kill button
(`sessionDetailRow`, `macos/Sources/Features/Remote/MachineChooserView.swift`
~L815-900). The win32 chooser resumes a session only by double-click or Return
on the row (`src/apprt/win32/MachineChooser.zig` resume path, T320), so the
action is invisible until you guess it, and nothing tells you a row is already
open versus detached. Fix: the per-row Show/Resume button with Mac's labels and
tooltips, wired to the existing resume/focus path.

## In plain terms

In the "open a session" dialog, each session card on Windows had only an "x"
to end it; to actually open it you had to know to double-click it. Now every
card carries a small button, like on Mac: **Show** when that session already has
a window here (it brings that window forward), **Resume** when it does not (it
opens the session in a new window). Hovering it explains which.

## Goals

- [x] A Show / Resume button on every live session card, beside the end button
- [x] It does exactly what Return / double-click on the card does
- [x] Mac's labels and hover text

## Validation criteria

- [x] A live, not-open session row shows a Resume button; clicking it resumes exactly as Return does - `test/win32/chooser-resume.ps1` section 2b: hover names the orphan's row with "Resume this session in a new window", the click logs `action button Resume id=<orphan>`, the same `resume session: attaching local session id=<orphan>` line Return produces follows, the chooser closes, and `+sessions --json` (dialling the agent directly) flips that id to attached.
- [x] A session already open in a window shows Show instead, and clicking it focuses that window without opening a duplicate - section 2b: hover says "Bring this session's window to the front", the click logs `action button Show id=<resumed>`, `session already open, focusing its pane` increments, and the attach count is unchanged.
- [x] Exited sessions show neither; tooltips match Mac's wording - `chooser_sessions.actionLabel` returns null for a dead session (unit test, none lane; exited rows are also not listed at all since T1364), and `chooser_help` asserts both sentences verbatim against Mac's `.help` strings.
- [x] Layout - `withAction` unit tests at 1.0/1.25/1.5/2.0: the button shares the Kill square's vertical frame, sits a 4 DIP painted gap before it and clear of its hit box, the text column clears it by the old Kill gap, nothing else on the card moves, and a too-narrow card keeps a non-negative text column. Screenshot of the rendered chooser reviewed (temp/t1746-chooser.png).
- [x] Floor: `floor-lane.ps1 -Lane all` ALL LANES PASS (lib/none/win32/agent).

## Decisions made here

- The button is one width on every card (the measured caption width of "Resume", the wider label) rather than sized to its own word, so the button column, the Kill column and the text's right edge are a single x down the roster.
- Its rest face is the section 2.2 hover shade of the card and its hover the pressed shade: a labeled button must read as a button at rest, where an icon button may sit bare.
- Click routes to the existing `resumeRow`, which already focuses an open session instead of attaching a second viewer (T330's deliberate divergence), so Show and Return cannot disagree.
- The redundant green "open" chip is left for T1760 (Mac dropped it for the same reason; removing it moves the chooser-sessions.ps1 pixel oracle).
