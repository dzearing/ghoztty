# T2871 - A strip name's TextOutW into the desk stalls 2-6 ms about once in 170 glide name paints (mean 0.05 ms): lay the label from a cached coverage bitmap, as the fold face already does, instead of GDI text every tick

## In plain terms

While a pane folds into a stack, the name written on each folded strip is
redrawn on every frame of the glide. Usually that costs almost nothing, but
now and then Windows takes several milliseconds to draw it, and that frame
can come in late.

## Summary

Split from T2732 (2026-11-09). The `stack trace vacated ...` line
(`GHOZTTY_STACK_TRACE=ring`) splits the vacated-strip desk paint; its
`textout=` field is the time `paintStripLabel` spent in `TextOutW` while
`layNames` drew the strip names into the desk's composed DIB. Release
sandbox, the T2732 glide probe: mean 0.05 ms, but 12 of ~2000 name paints
took 2-6.4 ms. The trim loop (`GetTextExtentPoint32W`, 1-3 calls, 0.02 ms)
is not it, and caching the strip fonts instead of re-creating them per paint
made no difference (A/B x3, tried and reverted in T2732), so it is not font
realization. It lands in a tick over 8.3 ms about once per two runs.

Direction: the names are the same text, font and ink tick after tick; only
where they sit changes. Render each strip's label once to a coverage bitmap
(white on black, as `declareStripFace` and `declareMovingStrip` already do for a face handed to the compositor)
keyed on text, size, axis and ink, and lay it into the desk's pixels with
`strip_face.inkFromCoverage`-style CPU blending - no GDI text on the glide
path at all. That also makes the strip's name the same pixels as the face
that hands over to it. Check the stack-strip pixel tests (pane-stack-strip,
stack-fold-slide F13) against the new blend.

## Goals

- [x] no GDI text on the glide path: each strip name drawn once, laid from its picture after that
- [x] the old path kept behind an A/B switch for the probe (`GHOZTTY_STRIP_LABEL_GDI=1`)

## Validation criteria

- [x] the probe's `textout=` max under 0.5 ms on three runs (release sandbox, `GHOZTTY_STACK_TRACE=ring`) - glide probe, release sandbox, three runs with the new `misses=` field: cached paints max 43 / 74 / 474 us (mean 9 us), one miss per run at 55-83 us; GDI arm on the same build: max 3.2 / 8.7 / 3.9 ms, 3-5 paints over 0.5 ms a run, mean 33-44 us
- [x] strip names pixel-match or are visually indistinguishable from the GDI path (pane-stack-strip, stack-fold-slide acceptance green) - stack-fold-slide ALL PASS 45; pane-stack-strip 30 pass, its one red is D6 (the dragged pane arrives as a different window), T2918's acked defect, every strip assertion green
