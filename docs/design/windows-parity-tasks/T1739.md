# T1739 - A successful delivery leaves go-loop-health reporting the pre-delivery deliver=wrong verdict until the next day's audit

## Summary

Found by T1569 on 2026-09-25. `scripts\deliver-windows-build.ps1` delivered a
release into both portables and its own `-VerifyOnly` read back `AUDIT OK`, yet
`scripts\go-loop-health.ps1` kept reporting `deliver=wrong(7)`: the verdict it
reads is `%LOCALAPPDATA%\ghoztty\deliver-audit.json`, which
`scripts\deliver-audit.ps1` writes once a day and skips for the rest of it
(`already run today`). So a fixed state reads broken until tomorrow's claim,
unless someone knows to run `deliver-audit.ps1 -Force`.

Fix: a delivery that ends `DELIVER OK` refreshes the watermark itself (run the
audit with `-Force`, or write the watermark from the verify it just did), so
the health line follows the last measurement rather than the last calendar day.

## Validation criteria

- [ ] After a successful `deliver-windows-build.ps1` run, `go-loop-health.ps1` reports `deliver=ok` without a hand-run `deliver-audit.ps1 -Force`.
- [ ] A failed delivery does not overwrite the watermark with `ok` (covered in `test\win32\deliver-windows-build.ps1`).
