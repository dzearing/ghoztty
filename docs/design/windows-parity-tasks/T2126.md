# T2126 - Stacked panes: undoing a close brings back the row's folded strips exactly as they were

## Summary

Split from T2084 (Mac 2811a3043 undo restores the stack state saved with the tree). CloseUndo must capture PaneStackState.saved() alongside the tree when a pane closes and restore() it on undo; rows off screen keep no stale collapse that could come back over the focused pane. rowsDidChange no longer keeps the old row's pin for an undo, so this is the only path. Unit test over Saved round-trip; the on-box half is T2119's undo step.

## In plain terms

When some panes of a row are folded into thin strips and you close a pane,
then press undo, the pane comes back but the row's strips did not: the row
came back laid out however the close had left it. Now undo puts the row back
exactly as it was before the close, strips and all, and a pane that was a
strip comes back as a strip instead of popping open. Folds you made in other
tabs while the undo waited are left alone.

## Goals

- [x] closing a pane saves which panes of every stacked row were on show, with the tree
- [x] undoing it puts that tab's rows back exactly; other tabs keep their own changes
- [x] a pane that comes back as a strip stays a strip (the caret does not land on it)
- [x] closing a whole tab and undoing it does the same for that tab's rows

## Design

Mac (2811a3043) captures `paneStackState.saved` in `replaceSurfaceTree` and
`restore`s it in the undo after assigning the old tree, so the tree setter's
`rowsDidChange` runs first and the restore wins. Win32 notes tree changes
lazily at layout (`noteStackRows`), so the same order is made explicit:
`Window.restoreStackRows` notes the undone tree first (updating the seen rows,
so the next layout carries nothing), then `PaneStackState.restoreScoped` puts
back only the rows made of the restored tab's panes. Scoping is the win32
translation of Mac's per-window state: one `PaneStackState` serves every tab
here, and a wholesale `restore` would take back folds made in another tab
during the undo window. A saved row that is not on screen after the undo is
dropped, so nothing comes back over panes that left for good.

`CloseUndo` carries the `Saved` on `ParkedPane` and `ParkedTab` (a closed
window is parked whole, so its state never left) and frees it on every exit:
restore, finalize, cancelPark, and push failure.
