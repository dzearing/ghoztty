# T1834 - The focused Windows pane is marked only by dimming the others: Mac's elevated style gives it a soft outer glow and a brighter rim

## Summary

Elevated style only, and only when a window has several panes: the focused pane gets a subtle white outer glow from its edges reaching about 8pt and never the next pane (9755dc1f7), plus a slightly brighter rim (51573daf0). Final tuning is the softer value of 7966780ae; the inner wash was dropped (0d8de3436). Pure rule covered by PaneFocusGlowTests on Mac; Windows needs the equivalent unit test plus a pixel check on the test desktop.

## In plain terms

With several panes open, Windows only showed which pane you were typing in by
dimming the others. On a Mac the focused pane is also softly backlit: a faint
white light spills a few pixels onto the background around it, and its thin
outline is a touch brighter. Windows now does the same, and the light glides
to whichever pane you move to.

## Goals

- [x] The focused card lights the desk around it (Mac's final, softer values), never itself and never the next pane
- [x] Its rim is brighter (solid and glass, light and dark themes)
- [x] Only among several panes: a lone, zoomed or hero pane gets no glow
- [x] The light moves with focus on Mac's 0.25s ease-out

## Validation criteria

- [x] Pure rule: Mac's `PaneFocusGlowTests` mirrored in `pane_elevation.zig` (lit 3pt outside, unchanged 6pt inside, gone by the 10pt gap, desk far away untouched) for solid and glass; reach ~8pt per DPI; rim alphas; ease-out fade; half-faded glow weaker - `zig test src/apprt/win32/pane_elevation.zig`, 50/50.
- [x] On screen: `test/win32/pane-elevation.ps1` run 1c on the test desktop - of two cards exactly one lifts the desk beside it (+31 vs -2, channel sum), and a goto_split moves it (-2 vs +27) - ALL PASS (50); `-NegativeControl` fails as it must.
