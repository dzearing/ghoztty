# T2988 - PA-W04: a title change in a tucked or stashed pane of the active tab invalidates the whole window, so a spinner title in a folded pane forces ~10 full chrome paints a second (Window.zig:18101)

## Summary

PA-W04 (audit-1, T2960). Window.zig:18101-18103 runs `if (tab_idx == self.active_tab) if (pane.hwnd()) |h| if (w32.IsWindowVisible(h) == 0) InvalidateRect(wh, null, 0)` BEFORE the title-unchanged guard at :18112, so every title update from a hidden pane in the active tab (an agent spinner, ~10 Hz) repaints the whole window: caption, strip, desk memo check (PA-W03, PA-W09, PA-W10, PA-W12 all ride on it). Fix: invalidate only that pane's strip rect, and only when the label text actually changed. Risk low.

## Validation criteria

- [ ] a spinner title in a tucked pane invalidates only the strip rect, and nothing when the text is unchanged (unit test or trace)
- [ ] idle CPU with a tucked spinner pane drops versus before (perf-baseline-style 60 s sample)
- [ ] tucked-strip labels still update (existing stack-strip acceptance green)
