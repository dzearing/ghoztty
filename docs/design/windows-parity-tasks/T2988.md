# T2988 - PA-W04: a title change in a tucked or stashed pane of the active tab invalidates the whole window, so a spinner title in a folded pane forces ~10 full chrome paints a second (Window.zig:18101)

## Summary

PA-W04 (audit-1, T2960). Window.zig:18101-18103 runs `if (tab_idx == self.active_tab) if (pane.hwnd()) |h| if (w32.IsWindowVisible(h) == 0) InvalidateRect(wh, null, 0)` BEFORE the title-unchanged guard at :18112, so every title update from a hidden pane in the active tab (an agent spinner, ~10 Hz) repaints the whole window: caption, strip, desk memo check (PA-W03, PA-W09, PA-W10, PA-W12 all ride on it). Fix: invalidate only that pane's strip rect, and only when the label text actually changed. Risk low.

## In plain terms

When a pane is folded away into a stack, only a thin strip with its name shows.
An AI agent in that pane animates its title several times a second, and every
one of those changes made the whole window redraw - title bar, tabs and all.
Now only that pane's strip is redrawn, and only when the name it shows actually
changes.

## Goals

- [x] a hidden pane's title change repaints its strip's rectangle, not the window
- [x] no repaint at all when the strip already shows that name (or the pane has no strip: stashed, hero or zoomed tab)
- [x] folded strips still follow their pane's title on screen

## Validation criteria

- [x] a spinner title in a tucked pane invalidates only the strip rect, and nothing when the text is unchanged (unit test or trace) - `strip_label_memo.zig` (6 tests, `none` lane green) covers the "nothing when unchanged" decision, including a name changed by the banner path never being mistaken for current; the rect is `tuckedStrips`' tab for that pane, by reading `invalidateTuckedStripName` (no trace: a per-tick log is the T1935 cost again)
- [ ] idle CPU with a tucked spinner pane drops versus before (perf-baseline-style 60 s sample) - NOT DEMONSTRATED. Measured with the new opt-in `pane-stack-strip.ps1 -SpinnerCpuSeconds 30` (premise asserted: 4 distinct titles seen), HEAD build vs this build, two rounds each: flat 0.9/1.7% before vs 2.1/1.4% after; elevated 2.4/2.4% before vs 1.2/2.7% after. On the background test desktop a whole-window repaint at 10 Hz costs under ~2.5% of a core, and the run-to-run noise is as big as any difference, so the audit's estimated cost is not reproducible here. The change is still strictly less work per tick (a strip rect instead of the client area, and zero when the name is unchanged).
- [x] tucked-strip labels still update (existing stack-strip acceptance green) - `pane-stack-strip.ps1` flat ALL PASS (35 assertions) with the new D9: a cmd `title` (OSC 0) in a tucked pane lengthens its strip's name 18 -> 275 px and back to 18. Caveat recorded in the script: with the new invalidation removed D9 still passed (another repaint - most likely the busy light of the command that ran - also reaches the strip), so D9 guards "still updates", not "updates through this path". Elevated leg: same 5 D1/D7 failures on the HEAD build and this one, already T2334.
