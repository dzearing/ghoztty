# T1754 - The palette's update row does not look or read like Mac's, and there is no Cancel or Skip Update beside it

## Summary

Found landing T1676, which made the Windows row conditional like Mac's. What is still different (TerminalCommandPalette.swift updateOptions): Mac titles the row 'Update Ghoztty and Restart' (Windows: static 'Install Available Update', no version), shows it emphasized in its own section ABOVE the rest with the version as a badge, and pairs it with 'Cancel or Skip Update' (updateViewModel.state.cancel()), which dismisses the offer. Windows has no palette way to dismiss an offer, and no per-version skip at all - check what the badge/menu row should do after a skip before building (the offer record in update_badge.zig would need a skipped-version field). Deps: T1676.

## In plain terms

When an update is waiting, the Mac command palette puts it at the very top in
its own highlighted row — "Update Ghoztty and Restart", with the new version in
a small pill — and right under it a "Cancel or Skip Update" row that puts the
offer away. On Windows the row was just another line in the list, with no
version and no way to say "not now". After this, Windows shows the same two
rows, the same way, in the same place.

## Goals

- [x] the install row is titled like Mac's and shows the pending version as a badge
- [x] it is set apart: a section of its own above Recent/All, a strong title and an accent outline
- [x] "Cancel or Skip Update" sits beneath it and dismisses the offer (dot, menu row and palette rows go; it returns at the next re-offer)
- [x] neither row joins Recent (Mac's update rows carry no identifier)

## Decisions made on the way (mechanism, recorded rather than filed)

- **"Skip" is a dismiss, not a per-version skip.** Mac's row calls
  `updateViewModel.state.cancel()`, which for an available update is Sparkle's
  `reply(.dismiss)` — "not now", re-offered at the next scheduled check. So no
  skipped-version field was added to `update_badge`; `App.dismissUpdate` clears
  the pending state and the durable record, and the next automatic re-offer
  (once T1563's daily re-notify window runs out) or a manual check brings it
  back.
- **Empty query starts on the first ordinary command.** Mac selects nothing on
  an empty query; Windows has always selected the top command. Keeping that,
  but skipping the pinned rows, means a blind "open palette, Enter" never turns
  into an update dialog. Typing selects the first match, pinned included, which
  is what Mac does (`selectedIndex = 0` on a query).
- **No leading icon.** Mac's row has a shippingbox glyph; no Windows palette
  row has an icon, so the emphasis is carried by the outline, weight and badge.
