# T1675 - Does the Mac build also lose a missed update offer, and should it wear the same persistent mark?

## Summary

The other seat of T1673 (platform symmetry, CLAUDE.md standing rule). Windows
now keeps a PERSISTENT mark while an update is waiting - a dot on the menu
button that escalates green -> amber -> red with staleness, an "Install Update
X.Y.Z" row at the top of the popup, and a durable record so both survive a
restart - because the balloon-only offer left the reporter eighteen releases
behind with the packages already staged.

This seat cannot answer whether Mac has the same hole. Sparkle's offer is a
window rather than a balloon, which is far harder to miss, but the question
T1673 turned on is what happens AFTER it is dismissed or deferred: does
anything in the Mac window still say an update is waiting, and does anything
say how long it has been waiting?

What to do here: run the Mac build against a fake appcast, take the offer,
choose "Later", and look. If nothing persists, translate T1673's answer into
Mac's idiom (its own menu/status affordance, not a copy of the win32 dot) and
say so in this file. If something already persists, record WHAT it is - that
becomes the reference the Windows side should have been matching, and the
win32 shape may want revisiting against it.

Reference: `src/apprt/win32/update_badge.zig` is the whole model, including the
rule that a re-offer must not reset the staleness clock.

## In plain terms

On Windows, if you miss the "an update is ready" popup, the terminal now keeps
a small mark in the corner until you install it. Nobody has checked whether the
Mac version does the same, or whether missing its popup means you simply never
hear about that update again.

## Goals

- [ ] establish, on a Mac, what remains visible after an update offer is deferred
- [ ] if nothing does, give Mac an equivalent persistent affordance
- [ ] record the finding here either way, so the two platforms stop being unmeasured

## Validation criteria

- [ ] the deferred-offer state observed on a real Mac build, described here
- [ ] parity call made explicitly (equivalent exists / equivalent built / deliberately different, with the reason)
