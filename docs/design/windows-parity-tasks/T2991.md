# T2991 - PA-W07: the visibility poll wakes the UI thread four times a second for the life of the process, even minimized or locked (App.zig:1065)

## Summary

PA-W07 (audit-1, T2960). App.zig:1065 SetTimer(msg_hwnd, VISIBILITY_TIMER_ID, 250 ms) is never killed. Each tick pollVisibility (App.zig:1467-1475) refreshes low-power mode and calls occlusion.windowHidden per window: a z-order walk with ~5 user32/DWM calls per top-level above it (occlusion.zig:141-156); a hidden window re-runs setActiveTabVisible(false) every tick (Window.zig:4729-4731). Estimated 4 wakeups/s in every state, ~2% of the measured idle rate. Fix: stop the timer while session_hidden or all windows are minimized (WM_SIZE restore and WM_WTSSESSION_CHANGE already re-evaluate), and/or back off to 1-2 s while state is stable; a WinEvent hook for cloak/foreground/location is the fuller answer. Risk medium: reveal latency (T1951, T2914) needs acceptance for each stop path. Distinct from PA-R16 (the per-resize walk).

## Validation criteria

- [ ] minimized or locked, no VISIBILITY_TIMER ticks fire (trace)
- [ ] reveal after restore/unlock/uncover still presents within the T1951/T2914 bounds (their acceptance green)
