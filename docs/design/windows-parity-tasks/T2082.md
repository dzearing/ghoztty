# T2082 - Stacked panes: the 300 DIP minimum, the strip layout and the carousel slide that brings a minimized pane on show

## In plain terms

Panes never get thinner than about 300 DIP. A row that cannot fit all its
panes side by side keeps the ones that fit, and minimizes the rest into
titled strips at its edge. Clicking a strip, a sidebar row, a goto_split or
a focus link slides that pane into view, and the run moves over like a
carousel.

- [x] The layout itself, as one pure function shared by everything that

## Scope (split 2026-10-20)

This task is now **the layout engine**. The whole feature is four more
pieces of work, each a turn of its own, and the window cannot use the engine
until the stack state that feeds it exists:

- T2100 — `PaneStackState`: focus history, pins, shares, the run last shown.
- T2101 — the win32 grid lays out through the engine: the 300 DIP minimum,
  strips painted and labelled, strip click / goto_split / sidebar / focus
  link. Carries this task's acceptance criterion and T2085's strip label.
- T2102 — the carousel slide, one terminal resize per slide.
- T2103 — `+list` minimized state. Mac's `+list` reports nothing of the kind
  today, so this is a two-platform CLI change, not a Windows field.

What the engine is: `compute(nodes, root, rect, metrics, provider)` over a
flat node array the window builds index-for-index from
`SplitTree(PaneView).nodes`, so `Divider.node` and `Result.displayed_ratio`
name splits of the real tree. DIPs in, DIPs out; the window scales.
`Provider` carries the four Mac closures (rank, pin, shares, shown). Also
ported: `waterFill`, `visibleRun`, `stickyRun` (d26e51183's sticky run),
`Pin.restoring/removing/adding/carrying/restacking`, `Squeeze`, `chain`,
`squeezedShares` (T2084's drag chain), `rows`, `minimumExtent`, `paintOrder`.

## Summary

Mac 86b7e3410 (`feat(macos): stacked panes - a 300pt minimum, and rows that
don't fit stack`):

- Panes stop at 300pt. A row that can't fit keeps as many on show as fit
  and minimizes the rest into titled strips at its edge. Focusing a
  minimized pane slides it into the run, on Core Animation, so no
  terminal resizes mid-slide.
- Dragging a divider past a pane's minimum minimizes it mid-drag; dragging
  back restores it. Grips resize the cards on show and widen a collapsed
  row.
- The run is highest in elevation. Strips step down away from it, so their
  shadows fall outward. Nested rows keep their own collapse.
- A strip drags its whole card (no drag image) and swaps on drop.
- Layout is one pure function shared by the grid and the stash slots
  (`PaneLayout.swift`, 707 lines, with `PaneLayoutTests.swift`).

Windows translation:

- A pure `pane_stack_layout.zig`: tree + container size + DPI + focus +
  pins -> per-pane rects plus strip rects. A port of PaneLayout with its
  tests, in the `none` lane.
- 300 pt -> 300 DIP, scaled by the window's DPI.
- Strips are pane-card chrome: a titled vertical tab at the run's edge, in
  the elevated/glass style.
- The slide: animate the cards' visuals (or DWM thumbnails / a snapshot
  bitmap) and resize each terminal ONCE when it ends. Never resize a
  ConPTY per animation frame (T1835 already debounces resizes).
- Focus paths that must bring a pane on show: strip click, goto_split,
  pane sidebar, `ghoztty://focus/` links, `+split --target` / IPC focus.
- `+list` reports a pane's minimized state (CLI symmetry: Mac's `+list`
  output is the reference).
