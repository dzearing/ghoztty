# T889 - Chooser share toggle should say when the RUNNING agent predates the sharing reconciler

## Summary

T547's "Share this machine" toggle writes `sharing.json` and relies on the
running local agent's 5-second reconciler (T546) to raise the uplink. The
app-agent lazy-upgrade contract deliberately keeps an OLDER agent running
until an idle swap, and an agent built before T546 never reads `sharing.json`
— so on such a box the checkbox reads ON while nothing is being served, with
no hint of why. The gap: after enabling, detect that the running agent
predates the reconciler (the HELLO handshake's capability/build stamp — the
same probe `refreshLocalAgentIfStale` already reads) and put one plain
sentence in the chooser's footer: sharing will start after the agent's
pending update. Additive detection only; no wire change (compatibility
boundary rules in docs/claude/sessions.md).

## In plain terms

Turning on "Share this machine" ticks the box and tells you your other devices
can now open terminals here. On a machine whose background terminal process is
still an older build — which is normal, because that process keeps your
sessions alive and only replaces itself when it can do so without losing them —
nothing is actually served, and the box said otherwise. Now the toggle says
sharing starts once that background process finishes the update already waiting
for it, so a checked box never means less than it says.

## Goals

- [x] The chooser can tell whether the running agent acts on the sharing flag
- [x] A stale agent gets its own footer sentence; a current one is unchanged
- [x] Detection is additive — no new opcode, no new field, safe in both skews

## Validation criteria

- [x] With a pre-T546 agent running and sharing toggled on, the chooser hint
      says the agent needs its pending update before sharing starts —
      `test\win32\share-machine.ps1` section G, against a real agent run with
      `GHOSTTY_AGENT_SUPPRESS_CAPS=sharing_reconcile`: the footer read
      "Sharing is on - this machine starts serving once its background terminal
      process finishes the update that's already waiting."
- [x] With a current agent, no such hint appears (negative control) — section H,
      same fixture with nothing suppressed: "Sharing is on - your other devices
      can open terminals on this machine.", and the run asserts the two
      sentences differ so the gate can score both ways. ALL PASS (41).
- [x] Unit-tested capability comparison; no protocol CHANGE — the wire is
      untouched (no opcode, no field). `negotiate: sharing_reconcile is the
      intersection, and an old agent reads false` in `src/remote/protocol.zig`
      plus three `ShareMachineRow` tests; all four zig lanes PASS.
