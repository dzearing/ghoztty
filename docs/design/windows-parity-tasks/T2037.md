# T2037 - crash-catch, crash-databreak, soak-daemon, test-binary-soak and the CrashCatch/CrashDump/DataBreak libs still default -Repo to D:\git\ghoztty, so a bare run from lane B diagnoses lane A's binaries

## Summary

Found in T2026. floor-lane.ps1 now resolves -Repo from its own checkout and passes it to every lib call, so the floor is fixed; but a bare crash-catch.ps1 / crash-databreak.ps1 / soak-daemon.ps1 / test-binary-soak.ps1 / t857-boost-ab.ps1 run from D:\git\ghoztty-b still reads D:\git\ghoztty, and the lib functions (Resolve-LaneTestBinary, Get-NewestBuiltBinary, Get-FailingTestBinaryFromLog, Get-LaneTestBinary, Invoke-CrashCatch, Invoke-CrashDumpAnalysis, Invoke-DataBreak*) keep the literal as their parameter default. Fix: same shape as T2026 / daily-publish (empty default, resolve to Split-Path PSScriptRoot -Parent), make the lib params mandatory or default from the caller; soak-daemon needs a lane check since it is a machine-wide daemon. upgrade/watchdog-ghoztty/launch-upgrade are lane-A-only by design (T1984) and stay.

## In plain terms

The crash and soak diagnostic tools assumed they always lived in the main
checkout. Run by hand from the second loop's checkout, they quietly examined
the main checkout's builds instead, so a crash report could describe the wrong
program. Now each tool looks at the checkout it was run from, and the box-wide
idle soak can only be started from the main checkout.
