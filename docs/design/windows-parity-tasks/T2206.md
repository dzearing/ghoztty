# T2206 - test-desktop-spike.ps1's capture assertions fail 20 of 20: the terminal surface no longer reads as flat on a background desktop, likely because glass panes (T1833) put the window gradient behind it

## Summary

Found by T1280 on 2026-10-24. A background-desktop-only copy of the edited spike (SendInput + SetForegroundWindow removed, nothing else) ran 20 times: every run FAILED 'the terminal SURFACE comes back flat on a background desktop (meanLum=42, distinct=1281)' and 'chrome and surface differ by an order of magnitude (chrome=453 vs surface=1281)'. T1115 measured distinct=2 over the surface on 2026-09-02. Likely cause, unverified: T1833 (771a1a264) made panes glass by default, so PrintWindow now sees the window's GDI gradient behind a transparent surface and the distinct-colour oracle counts the gradient. Verify (e.g. launch with an opaque background-opacity and re-measure), then re-score the oracle on something the gradient cannot fake (e.g. a known-glyph fixture vs blank) and update the ANSWERS header if the capture answer itself changed. The real script was not run (it is @input-desktop-exception).

## In plain terms

A test that checks whether Ghoztty's automated tests can run hidden, on a desktop of their own so they never steal the user's screen, had gone red. The test was right to fail, but for two reasons nobody had written down. First, the app changed: a screenshot of the hidden window now shows the terminal's real text, where in September it came back blank, and the test still insisted it must be blank. Second, single-window mode changed how the app names its windows, so the test could no longer find its own window. Once this lands the test measures what is true today, and the better capture is a lead (T3705) on running more tests off the user's screen.
