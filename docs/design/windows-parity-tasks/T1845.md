# T1845 - No right-click menu, Alt-click swap or trash mode in the Windows pane sidebar

## Summary

Follow-up of T1828 (Mac 597a193cc). Right-click a grid row: Stash / Move to New Window / Close Pane; a stashed row: Restore / Swap with Focused Pane / Move to New Window / Close Pane (Close goes through the normal close path, confirmation and remote Disconnect included). Alt-click a stashed row swaps it with the focused pane (Mac Option-click). Header trash button: every row/tile gets a solid red x that kills with no confirmation and no undo window; Escape or the button again leaves it; never persisted.

## In plain terms

On a Mac, the pane list down the side of a window is where you act on a pane:
right-click it for Stash / Move to New Window / Close, Option-click a put-away
pane to swap it with the one you are looking at, or flip on a trash mode that
puts a red x on every pane for one-click cleanup. On Windows the list could
only focus and stash. After this, Windows does all of it (Alt-click for the
swap), so cleaning up or juggling panes from the list works the same on both.

## Goals

- [x] Right-click menu on rows and rail tiles, with Mac's items and order
- [x] Alt-click a stashed row swaps it with the focused pane
- [x] Trash mode: header button, red x on every row and tile, kill without confirmation or undo, Escape leaves
- [x] The open card holds open while its menu is up (the T1842 note)

## Design notes

- Close Pane on a terminal runs the pane's own `close_surface` binding, so a
  running process is confirmed and a remote pane offers Disconnect exactly as
  Ctrl+Shift+W does; a viewer closes directly.
- Kill = `closeSplitPane` with `CloseUndo.bypass` raised, so nothing is
  parked and the session ends now (Mac replaces the tree without registering
  an undo). A window's last pane takes the window with it, as on Mac.
- Swap = `pane_stash.exchange`: `SplitTree.swap` of the two leaves, then the
  stash mark moves to the formerly focused pane at the SAME stash position
  (Mac `exchanging(stashed:with:)`).
- Alt is read at the PRESS (and OR'd with the release): a swap the user began
  holding Alt is a swap even if Alt comes up first. It is also what makes it
  testable from a background desktop, where the harness's faked key state is
  cleared right after the posted button-up.
- The rail tile's x is a 13 DIP disc on the tile's top-left corner, opposite
  the question badge; it is a hit target only in trash mode.
- Menu text is Windows-style: access keys, and the swap item shows
  `Alt+Click` where Mac shows the Option glyph.
