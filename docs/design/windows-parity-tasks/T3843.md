# T3843 - acceptance-parallel due starts @input-desktop-exception scripts once the box reads idle: translucent-window.ps1 ran in T2547's sweep, which go.md's NEVER PULL FOCUS rule forbids the loop to start

## Summary

On 2026-11-26 T2547's acceptance-parallel due sweep (logs %TEMP%\ghoztty-acceptance-parallel\20261126-193321) ran test\win32\translucent-window.ps1 to completion: the first sweep at 19:29 SKIPPED it on user-present (input 228s ago), the second ran it once 5 idle minutes passed. AcceptanceParallel.ps1:103 only treats 'input-desktop-exception' as an exclusive (run-alone) marker, not as never-run-by-the-loop. go.md's top rule says do not run any @input-desktop-exception script, and memory idle-is-not-absent says 5 minutes idle is not the user away. Fix: due/run must refuse (report NOT RUN: input-desktop-exception, user starts it) every script whose header carries the marker unless an explicit user opt-in switch is passed; add a negative demonstration. Related T2478 (same rule for next's idle re-queue).

## In plain terms

A few tests can only work by using the real screen and mouse, so only the user may start them. The automatic test runner waited until the computer had been idle for five minutes and then ran one anyway, which can grab the screen while the user is in a game or a video. After this fix the runner lists those tests as "not run, the user starts it" and never launches them.
