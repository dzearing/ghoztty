# T2443 - pane-sidebar-all-windows.ps1 section 9 'setup: the effects went off' times out beside other scripts (passes alone): mark it or fix the low-power seam wait

## Summary

Found by T2425 (2026-10-28): `acceptance-parallel.ps1 run -Scripts pane-sidebar-drag.ps1,pane-sidebar-all-windows.ps1` failed exactly one assertion of pane-sidebar-all-windows.ps1 beside the other worker - section 9's `setup: the effects went off (log)`, a 6 s `Wait-Log 'low-power: visual effects off'` after writing the seam file and posting WM_WTSSESSION_CHANGE (0x02B1) - and the runner's alone re-run was ALL PASS (114 assertions). The runner printed PARALLEL-SENSITIVE. Every later section 9 assertion passed in the failing run, so the effects did go off; only the log wait missed.

Fix: find why the low-power log line is late or missed under load (the seam read is on a timer? the line written before `$mark` was taken?) and make the wait robust; only if the cause is genuinely a shared resource, mark the header `# @parallel-unsafe`. Evidence: `%TEMP%\ghoztty-acceptance-parallel\20261028-223018\01-pane-sidebar-all-windows.log`.

## In plain terms

One check in the sidebar test failed now and then when other tests ran at the
same time, even though the app did the right thing. The test was looking for a
log line in the wrong place: when the machine was busy, the app sometimes wrote
the line a moment before the test started looking. The test now starts looking
first. Nothing changed in the app.

## Goals

- [x] find why the low-power log line was missed under load
- [x] make the wait robust without marking the script parallel-unsafe

## Validation criteria

- [x] pane-sidebar-all-windows.ps1 green beside other scripts in `acceptance-parallel.ps1 run` three times running, not only alone. Verified 2026-11-26: `acceptance-parallel.ps1 run -Scripts pane-sidebar-drag.ps1,pane-sidebar-all-windows.ps1` three times in a row, both workers ALL PASS each time (all-windows 188 assertions, drag 132). Harness floor (scoped) and unwired-hook-audit also green and re-stamped.

## Resolution

Root cause: the app's 250 ms visibility poll (`App.zig` `pollVisibility` -> `refreshLowPower`) reads the remote-session seam file as well as the `WM_WTSSESSION_CHANGE` handler. Section 9 wrote the seam and only then took `$mark = Get-LogCount`, a full log read that is slow under load. When the poll fired in that gap, `low-power: visual effects off` was logged before the mark, and `Wait-Log` only looks at lines after it. That is why every later section-9 assertion passed in the failing run. Fix: take the mark before the seam write. It is a test-only change, and the script stays parallel-safe.
