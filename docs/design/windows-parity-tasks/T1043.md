# T1043 - skip-visibility is red at HEAD: fork-identity's verdict names its skip count through a variable the analyzer cannot see

## Summary

`test\win32\skip-visibility.ps1` exits 1 at HEAD on section B1:

```
FAIL B1 no script violates the rule without being a named exception
     fork-identity.ps1
       L445 unreported: 1 skip site(s), but the ALL PASS line names no skip count
```

## In plain terms

One of the self-checks that keeps the test suite honest is failing, and it has
been failing at HEAD with nothing pointing at it. The rule it enforces is small
but load-bearing: if a test skipped part of its work, the one line anybody reads
has to say so - otherwise a run that measured half the feature looks exactly
like a run that measured all of it.

## Details

At RUNTIME `fork-identity.ps1` does report its count: it builds `" / N skipped"`
into a `$note` variable one line above the verdict and interpolates it. But
`SkipAudit`'s `Test-SkipVerdictReports` matches the word `skip` in the verdict
LITERAL, and that literal is `"FORK-IDENTITY: ALL PASS ($script:passes$note)"` -
no such word in it. So the finding is about the SHAPE, not about a count that is
actually missing.

Two ways to close it, and the choice is the point:

- **Fold the count into the verdict literal** (recommended). It is the shape the
  rest of the suite uses, it is what a reader of the last line can trust, and it
  is a step toward putting this script on `Write-TestVerdict`, which owns this
  wording and this exit code.
- **Teach the analyzer to follow a variable.** This weakens the check: the whole
  rule is about what the one line anybody reads says, and an analyzer that
  chases assignments will eventually chase one that is conditional.

Found while running the suite sweeps for T331; unrelated to that work.
`skip-visibility` has no `guard-due` row (T1010 is that task), which is why it
could go red at HEAD with nothing obliging anyone to notice.

## Resolution

Already fixed by **aa615ffbf** (2026-09-12, T1511), which moved
`fork-identity.ps1` onto `Write-TestVerdict -Skipped $script:skips` - the
recommended option above. 7317fec93 then taught the analyzer to read a
scorer call's `-Skipped` as the verdict's count. No new code in this turn;
the re-verification is the deliverable.
