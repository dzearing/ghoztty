# T3619 - Harness audit: refuse a +split --target=<pane> that names a pane an earlier unfocused split in the same script created (the T1797/T2032 shape)

## Summary

T2032 found 14 lines in 10 harnesses that split off a freshly created pane with --target=<name>, which resolves to the window and splits its ACTIVE pane - the original one since T1797 - so three of them measured a layout their comments never described. Nothing stops the next harness doing the same. Add a harness-floor member (scripts\lib\HarnessFloor.ps1) that flags a +split --target=<X> where X was --name'd by an earlier +split without --focus in the same file, with a negative control; the T2032 scanner (a 25-line regex walk) is the starting point.
