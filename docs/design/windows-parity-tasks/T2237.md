# T2237 - The quoted-mention exemption in the text lints pairs quote marks left to right, so one stray quote earlier in a file flips every later quotation into prose

## Summary

Found building T1342. `test/win32/merge-terminology.ps1` (T1097) and the new
`test/win32/lib/RetiredClaims.ps1` both exempt a double-quoted span with
`"[^"]*"`, bounded at 800 characters and no blank line. The regex pairs quote
marks left to right across the whole file, so an odd quote mark earlier in a
long file (a code sample, a `"` inside backticks, an inch mark) shifts every
later pair by one. A real quotation then reads as prose and a finding fires, or
prose between two quotations reads as a quotation and a real use is hidden.
Measured: a new paragraph at the end of `docs/claude/testing.md` quoting the
T490 claim inside straight quotes was reported as a bare use. The paragraph was
reworded to the past tense to keep the tree green, so nothing is red today.

The fix belongs in one shared place: pair quotes within a paragraph (split on
blank lines first), skip quote marks inside backtick code spans, and give both
lints the same helper so they cannot drift.

## Validation criteria

- [ ] A fixture with one stray quote early and a real quotation later: the quotation is still exempt and a bare use after it is still found
- [ ] merge-terminology.ps1 and doc-claims.ps1 share one quotation helper, and both stay green on the live tree

## In plain terms

Two of the checks that read the repo's docs let you quote a banned phrase
inside quote marks. They match quote marks in pairs from the top of the file
down, so one stray quote mark near the top throws off every pair below it. The
check can then flag a legitimate quote, or miss a real use.
