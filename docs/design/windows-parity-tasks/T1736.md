# T1736 - win32 +new-remote-window --name= does not pin the relay pill's machine name the way Mac's namePinned does

## Summary

Mac's IPCServer passes an explicit --name to openRemoteWindow as the Machine's display name with namePinned=true, so the pill says the caller's label and an account rename never overwrites it (AppDelegate: fallbackName ?? reportedHostname ?? device; namePinned && fallbackName != nil; restored windows re-pin via RemoteSessionManifest.Entry.namePinned). On win32 --name is only the IPC registry name: after T1418 the pill shows the directory name (or HELLO hostname) and adoptRelayNames renames it on the next listing regardless. Fix: carry a pinned name on RemoteMachine.relay (a flag beside T1418's name), set it from the verb's --name, skip pinned machines in adoptRelayNames, and persist the pin through session-layout restore. Extend test\win32\remote-pill-relay-name.ps1 with an arm: --name=X shows X and survives a listing.
