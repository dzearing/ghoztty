# T3028 - PA-I14: neither side's outbound frame queue has a bound, so a wedged peer lets the other grow without limit (server.zig:822, connection.zig:1885)

## Summary

PA-I14 (audit-1, T2962). Agent: src/remote/agent/server.zig:822 write_queue.append with no cap; the only brake is the client's FLOW pause (:2455), so if the app stops reading (the T48 freeze shape) while a pane floods, agent memory grows without bound. App: connection.zig:1863 dupes each payload and :1885 appends to write_queue unbounded; input frames and 3 s pings accumulate if the agent is wedged (growth only at typing/paste speed). Fix: per-connection byte cap; past it the agent stops streaming that session and relies on ring gap-fill at resume, and the app fails writeInput. Risk medium: exercises the resync path; no wire change. Shared code: Mac half filed. Findings: docs/design/perf-audit/audit-1/I-findings.md.
