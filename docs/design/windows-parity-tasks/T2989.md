# T2989 - PA-W05: the perf baseline cannot say which threads cause the 160-210 idle context switches a second, or what the ~51 USER objects and +10 handles per cycle are (perf-baseline.ps1:264)

## Summary

PA-W05 (audit-1, T2960). Tooling. perf-baseline.ps1:264 sums context switches across all threads. Reading the code, the apprt explains ~6/s of the measured 164-213/s at idle (4/s visibility poll PA-W06, ~1.7/s blink PA-R04, the rest minute-scale timers; FrameClock, IPC listeners and parked pool threads block). The remaining ~150/s is presumably GL/D3D11/DComp driver and OS pool threads, but no code reading can confirm it. Likewise the cycle phase leaves ~51 USER objects, 12 threads and +10 handles/+5 USER per cycle that no apprt site explains. Fix: have the snapshot keep per-thread deltas grouped by start address/module and thread name (renderer/io/io-reader are already named) and report the top 10; add a handle-type diff (NtQuerySystemInformation handle info or handle.exe -s style) before/after each cycle. Risk none (script only).

## Validation criteria

- [ ] perf-baseline.ps1 idle phase reports the top 10 threads by context switches with their module/name
- [ ] the cycle phase reports a per-type handle and USER-object diff
- [ ] the remaining idle wakeups are attributed in a follow-up task (or proven to be driver threads)
