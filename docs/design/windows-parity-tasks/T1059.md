# T1059 - The digest names every open PR and its CI health, so a red or stalled PR is a morning read

## Summary

User directive, 2026-08-21: the digest should outline the PRs that need merging,
and posted PRs should be monitored so they are building correctly and passing
tests. The daily digest (go.md step 0.5,
`docs/design/windows-parity-digests/<date>.md`) is already the first thing a
turn reads, and it already renders in the dashboard - so PR state goes there
rather than into a new surface nobody opens.

## In plain terms

Once work ships as proposals rather than straight onto the branch, a proposal
can sit there for a week going red and nobody would know. The morning read
should just tell you: here is what is waiting to merge, here is what is broken,
here is what has gone quiet. No dashboard to remember to check.

## Goals

- [x] A new digest section lists every open PR: title, branch, age, CI status,
      and whether it is waiting on review or waiting on merge. ->
      `scripts\pr-health.ps1 -Format markdown`, pasted by go.md step 0.5 as
      `### Open pull requests` under `## Commentary`.
- [x] CI status is real - read from the checks on the PR (`gh pr list --repo
      dzearing/ghoztty --json statusCheckRollup,...`), not inferred.
- [x] A red PR and a stalled PR are visually distinct from a healthy one; the
      digest says which of them needs a turn spent on it. -> three bands
      (Needs a turn / In flight / Healthy), needs-a-turn sorted first with the
      reason (failing job names, conflict, changes requested, stalled Nd, no
      checks ran).
- [x] Absence is handled: no open PRs prints the empty state, and an unreachable
      GitHub prints "unknown", never a fabricated green.

## Validation criteria

- [x] Run against the live repo and the section renders correctly in both the
      markdown and the dashboard view. **Verified**: live run answers
      `PR HEALTH NONE OPEN dzearing/ghoztty` in 0.85s (the fork has no open PR
      today - every PR so far is closed, so the "at least one open PR" half is
      covered by fixtures until the cutover makes PRs routine); the block is in
      today's digest (2026-10-17). Dashboard: the inline renderer's link
      pattern is `[^\]]+`, so bracketed titles are rewritten to parentheses
      (A17b) and every line uses only the bold/link/code forms it renders.
- [x] A PR with a failing check is shown as failing, and a network/auth failure
      prints unknown rather than passing. **Verified**: `test\win32\pr-health.ps1`
      A2/A3 feed the fork's real PR #12 rollup (build-test FAILURE, captured
      verbatim) and get NEEDS A TURN naming build-test only; C2-C6 launch stub
      gh processes for not-signed-in, missing exe, non-JSON and overrun - all
      UNKNOWN, exit 0.
- [x] The digest generation stays inside its time budget with the extra calls,
      and does not block the turn when GitHub is slow. **Verified**: a real
      deadline (`-TimeoutSeconds`, default 20) kills the gh process TREE; C7
      proved the first version (Kill() on the process only) still blocked the
      caller 30.6s through an orphaned child holding the pipe, fixed with
      `taskkill /T`; now back inside the budget.
- [x] Follows the digest protocol already in force: written for today only,
      never backfilled. **Verified**: it reads live state only and takes no
      date; go.md step 0.5 runs it when writing today's file.
