# T1144 - The stderr-capture audit fails on a caller with no console instead of saying so

## Summary

Run test\win32\stderr-capture-audit.ps1 from a host with no real console (any tool or CI runner that redirects output - the buffer width reads as 1) and section A scores 3 FAILURES: the host cannot format, so the decoration those assertions measure never appears. The same run under conhost is ALL PASS (25). A harness whose subject IS host-dependent formatting should detect a host that cannot format and Write-TestAssertedNothing with that reason, the way it already does when git is absent - a red verdict that means 'you called me wrong' is indistinguishable from a real regression, and guard-due will keep the guard due either way.

## In plain terms

One of the checks that guards the test suite used to report "3 failures" when
it was started from a window that has no real console - even though nothing
was broken. Now it notices it was started from such a window, says so, skips
only the part that genuinely needs a console, and still runs the rest.

## Goals

- [x] section A (the live formatter measurement) is skipped by name, not scored red, on a host too narrow to format
- [x] sections B-D (the actual sweep of the test tree) still run and score on that host
- [x] a run that skipped section A does not stamp the guard, so it stays due until a real console runs it
- [x] the gate is proven both ways, so it can neither red a narrow host nor skip one that could answer

## Design

Mechanism call (mine, per go.md 5b): the gate reads the width off the
**formatter itself** - the longest line of a formatted 1000-character
information record - not `$Host.UI.RawUI.BufferSize`. The first cut read
RawUI and was wrong: an embedded runspace has no RawUI at all yet still
formats at a default 120, so that cut skipped a host that could answer.
Floor = 40 columns, twice the measured minimum (`Out-String -Width`: A1-A3
and A7 all hold from width 20; A1 breaks at 15). The task text proposed
`Write-TestAssertedNothing`; rejected because B-D score the test tree, not
the host, and throwing them away would hide a real sweep regression behind
a skip. The verdict on a skipped run is `ALL PASS (22 assertions, 8
SKIPPED)` with no stamp.

## Validation criteria

- [x] width-1 host reproduces the defect against the OLD script: `3 FAILURE(S) (22 assertions passed)` - A1, A2, A7 (scratch custom PSHost reporting a 1-column buffer, run in an embedded runspace)
- [x] same host, NEW script: `SKIP section A (8 assertions)` named, `ALL PASS (22 assertions, 8 SKIPPED)`, no STAMPED line
- [x] ordinary console: `ALL PASS (30 assertions)`, stamped; `-TeethCheck` still ALL PASS
- [x] section E (always runs, uses `Out-String -Width`): E1 below the floor the formatter cannot carry A's phrase; E2 at the floor it can; E3/E4 gate decisions; E5 the probe reads the wrap point (10 -> 10, 60 -> 60)
