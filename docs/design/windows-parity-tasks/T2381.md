# T2381 - Frame scorer for the T2373 lab: classify one captured frame's bleed classes (B1 background flash, B2 stale size, B3 stretch, B4 chrome tear, B5 overlay lag, B6 garbage) against a deterministic scene, and compute the smoothness metrics (advance rate, stalls, jitter, input-to-photon lag, reversals) from a frame series - pure logic, proved on synthetic frames with planted defects

## Summary

Split out of T2373 (user-directed 2026-10-27: no bleeding during window/pane resize; smoothness measured). See T2373's Summary for the full design; this card is one piece of it.

## In plain terms

To prove the terminal never "bleeds" while you resize it (flashes of
background, content the wrong size, stretched or torn frames) and moves
smoothly, the lab will photograph every frame the screen shows. This piece is
the judge that looks at each photograph and says what is wrong with it, and
turns a run of them into smoothness numbers. It is tested on fake frames with
known defects first, so it can be trusted on real ones.

## Goals

- [x] Per-frame bleed classifier for B1-B6 against a deterministic scene (`test\win32\lib\FrameScore.ps1`, `Measure-FrameBleed`)
- [x] Motion metrics: advance rate, stalls, step jitter, curve deviation, lag p50/p95, reversals (`Measure-FrameMotion`) plus T2373's targets (`Test-FrameMotionTargets`)
- [x] Acceptance on synthetic frames with planted defects and negative controls (`test\win32\frame-score.ps1`), guard row `frame-score`

## Design notes

- B4/B5 elements are located in the frame and compared with an expected rect
  the CALLER derives from the same frame (e.g. the divider must fill the gap
  between the two located rings). That keeps the scorer free of layout
  knowledge: T2384 builds the expectations per interaction.
- B6 needs no edge mask: a pixel on the RGB segment between two palette colours
  (within Tol) is an anti-alias blend; anything off every segment is garbage.
  Rounded corners are excused by the arc only (A7 proves a pixel in the corner
  square but inside the arc is still caught).
- Motion "due" and "reversal" are judged against the pointer path shifted back
  by the measured median lag. Without that shift the first two refreshes of
  every drag read as a stall and a lagging edge finishing its stroke after the
  pointer turned read as a jank (both caught by C1/C10 during development).
- Due refreshes run from the first advance to the last, extended to the window
  end when the edge never reaches the pointer's final position (a stuck edge is
  the longest stall); a run where nothing moved but the pointer did reads rate 0.

## Validation criteria

- [x] Every bleed class B1-B6 caught when planted, on the planted pane only - `test\win32\frame-score.ps1` section B (17 assertions), ALL PASS 41.
- [x] Clean, anti-aliased (off-palette blend pixels shown to exist, A3) and rounded-corner frames score nothing; the corner mask's negative control finds the corners - section A.
- [x] Motion metrics read the T2373 cases: perfect 120 Hz drag rate 1 / lag exactly 2; 40 fps rate 0.333; planted 3-refresh stall; planted back-jank (with and without a pointer); back-and-forth lagging edge 0 reversals; curve, jitter, timestamp noise, unlocated frames, pointer pause - section C.
