# T2048 - floor-lane -Lane harness times out at its 1800s default cap when the scoped sweep widens to set=all: a full 31-member sweep took 1920s with no lock contention

## Summary

Found in the T2009 turn. `floor-lane.ps1 -Lane harness` (scoped) widened to `set=all` and ran into its `-TimeoutSeconds` default (1800s) at member 25 of 31: `LANE harness TIMEOUT in 1806s ... WALL-CLOCK CAP: the lane was still making progress`. That run shared the `Global\GhozttyHarnessFloor` lock with lane B. Run again with `-TimeoutSeconds 3600` and nothing contending, the same sweep PASSED in 1920s, so a full sweep now needs more than the default allows. The turn lost about 35 minutes to the timed-out run plus a partial `-Include` re-run of the 6 unrun members. That re-run PASSED but did not stamp: "not a completion of the last full run".

Fix: size the cap from the sweep it is actually running (a set=all widening needs the full-sweep budget, plus headroom), or raise the default and keep it above the measured full sweep. A TIMEOUT that ran out while still making progress could also name the members it never started, and print the `-Include` command that would complete the sweep.
