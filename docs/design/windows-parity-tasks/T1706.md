# T1706 - Re-point viewer-feedback.ps1 (typing, undo, send, caret, IME arms) from the RichEdit fallback to the web composer

## Summary

viewer-feedback.ps1 sets GHOZTTY_COMPOSER_SURFACE=richedit directly and drives typing, Enter/Backspace, Escape close, send-and-empty, Home/selection caret edits, wrap, cut/copy/paste/undo, Tab focus ring and the IME WM_IME_* arms through the RichEdit. Move each onto the web page, or retire an arm that is RichEdit-specific (IME messages, EM_* caret) in favour of the ViewerPane.zig host floor test, naming the replacement coverage. Split out of T1703, which landed the pattern on viewer-feedback-alpha.ps1: arm ONE DevTools port per script with Enable-WebViewCdp before the first launch, open the composer, Find-CdpComposer (pass -Exclude for pages an earlier app used), then type with Send-CdpComposerText / Send-CdpKey, paste pictures with Send-CdpComposerImage, and read back with Get-/Wait-CdpComposerText (test\win32\lib\WebViewCdp.ps1). Chords NATIVE owns (Ctrl+Enter, Esc) still go through the band's window messages. Assert Wait-ComposerSurface 'web' instead of pinning 'richedit'. When done the script no longer calls Set-ComposerSurface 'richedit' or reads a RichEdit50W, which is what T1704 needs before it deletes the fallback.

## Validation criteria

- [ ] The script no longer asks for the RichEdit fallback and asserts the composer opened on the web surface
- [ ] Every editing arm drives the web page (or is retired with its replacement coverage named)
- [ ] The script runs ALL PASS on the box
