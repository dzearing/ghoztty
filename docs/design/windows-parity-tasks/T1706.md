# T1706 - Re-point viewer-feedback.ps1 (typing, undo, send, caret, IME arms) from the RichEdit fallback to the web composer

## Summary

viewer-feedback.ps1 sets GHOZTTY_COMPOSER_SURFACE=richedit directly and drives typing, Enter/Backspace, Escape close, send-and-empty, Home/selection caret edits, wrap, cut/copy/paste/undo, Tab focus ring and the IME WM_IME_* arms through the RichEdit. Move each onto the web page, or retire an arm that is RichEdit-specific (IME messages, EM_* caret) in favour of the ViewerPane.zig host floor test, naming the replacement coverage. Split out of T1703, which landed the pattern on viewer-feedback-alpha.ps1: arm ONE DevTools port per script with Enable-WebViewCdp before the first launch, open the composer, Find-CdpComposer (pass -Exclude for pages an earlier app used), then type with Send-CdpComposerText / Send-CdpKey, paste pictures with Send-CdpComposerImage, and read back with Get-/Wait-CdpComposerText (test\win32\lib\WebViewCdp.ps1). Chords NATIVE owns (Ctrl+Enter, Esc) still go through the band's window messages. Assert Wait-ComposerSurface 'web' instead of pinning 'richedit'. When done the script no longer calls Set-ComposerSurface 'richedit' or reads a RichEdit50W, which is what T1704 needs before it deletes the fallback.

## In plain terms

The main automated test for the viewer's feedback box used to type into an old, hidden text box that people never see. It now types into the real box, which is a small web page. Moving it found a real bug straight away: the box grew as you typed but never shrank when you deleted text. That bug is fixed as T1714.

## Goals

- [x] The script stops asking for the old text box and proves it got the real one
- [x] Typing, caret moves, selection, cut/paste, undo, wrap, send, Escape, the Tab walk and IME all run against the real box
- [x] ALL PASS on the box

## Outcome

- **Surface.** The script calls `Set-ComposerSurface 'web'` and asserts `Wait-ComposerSurface 'web'`. It no longer reads a RichEdit50W; the only RichEdit mentions left are comments that explain the history.
- **Page-owned input** goes over the DevTools driver: typing, Enter/Backspace, Home, Shift+Arrow selection, Shift+End, Ctrl+A, Ctrl+X/Ctrl+V on the real clipboard, and Ctrl+Z. The word-undo arm types key by key, so the engine's typing group is what gets tested. Read-back is the page's own serialization. Because every close destroys the page, each reopen opens a fresh session (`Connect-Composer`, with `-Exclude` for pages already used).
- **Native-owned chords** (Ctrl+Enter, Esc, Tab and Shift+Tab from the text) are posted as `WM_APP_COMPOSER_CHORD` (WM_APP+2, vk plus input.Mods bits) to the band. That is the web surface's real second hop out of `AcceleratorKeyPressed`. The first hop cannot be driven synthetically, because native reads modifiers from `GetKeyState`. The script header says so.
- **IME arm, retired and replaced.** The `WM_IME_*` messages meant nothing to a Chromium window. The arm now runs a real engine composition (`Input.imeSetComposition`, then an `Input.insertText` commit) and asserts three things: the text lands, the caret rests AFTER the commit (the RichEdit arm could not ask that), and the host buffer carries the exact UTF-8 bytes. The candidate window and reconversion stay in the manual check (`windows-parity-ime-manual.md`).
- **Send-and-empty** is now proved on the host's buffer rather than a control: the page a reopen builds is seeded empty.
- **Harness fix:** `Get-ContentTop` skips the composer's own `Chrome_WidgetWin_0`, which is a descendant of the pane and sits above the page. Without the skip, "page top" was the text box.
- **Found:** T1714 (P1, fixed in the same commit). The pill never shrank, and an emptied box held a newline.
