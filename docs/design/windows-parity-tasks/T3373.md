# T3373 - pr-health.ps1 and delivery-version.ps1 run taskkill bare on their timeout path, so a failed kill throws instead of returning the timeout answer

## Summary

Found while fixing T3364. scripts\pr-health.ps1:157 (under its own $ErrorActionPreference='Stop') and scripts\delivery-version.ps1:336 (inside a try with no catch, under whatever preference its caller set) both run '& taskkill.exe /T /F /PID ... *> $null' when a child overruns its deadline. PS 5.1 turns taskkill's stderr ('could not be terminated', or 'not found' when the child exits in the gap) into an ErrorRecord that throws under Stop, so the timeout answer the code is about to return becomes an exception instead. Fix: move Stop-ApProcessTree (scripts\lib\AcceptanceParallel.ps1, T3364) into a small shared lib both can dot-source, and call it here; add a check in test\win32\pr-health.ps1 that a planted failing tree killer still yields the 'did not answer' result. suite-run.ps1's two calls are already inside try/catch and were checked.
