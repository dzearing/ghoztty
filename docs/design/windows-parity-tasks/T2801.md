# T2801 - Composition step 5d-5b: a busy pane's sidebar sheen (glint sweep + drift) runs on the compositor - per busy pill a clipped visual whose offset loops on an animation with AddRepeat, fading in/out on its effect - so the column no longer repaints every vblank while an agent works

## Summary

The sheen is the column's only CONTINUOUS motion: while any agent is busy, TIMER_ANIM repaints the column at the display rate for as long as the work runs (pane_sidebar_motion.zig glint every 2 s + drift every 5 s, fade 0.6 s). On T2765's tree, give each busy pill a rounded-rect-clipped visual holding the pre-rendered slanted band and drift gradient, declare their offsets once as repeating DComp animations phased to the shared clock, and the busy fade as an opacity animation. Rows that move (scroll, reorder, fold) re-place the clip. Oracle: film with GHOZTTY stall seam + stepped control, plus the log's motion frames=0 while busy.

## In plain terms

While an agent works, its row in the pane sidebar shows a soft moving shine.
The app used to redraw that shine itself, sixty-plus times a second, so it
hitched whenever the app was busy - which is exactly when agents are working.
Now Windows itself plays the shine, so it stays smooth and the app stops
spending effort on it.

## Goals

- [x] each busy pill's sheen is three pieces on the sidebar's own tree (drift, glint band, busy rim) under a pill-shaped, rounded, antialiased clip, looping on their own
- [x] both loops share one phase origin with the stepped paint, so rows sweep in step and a fallback frame matches
- [x] the busy fade-in/out is a compositor opacity animation, picking up wherever the fade is
- [x] the motion clock drops from the display rate to a 250 ms roster poll while every moving pill is the compositor's
- [x] anything the pieces cannot stand for - a transition, a drag, a pill half under the pinned head or out of the viewport, Reduce Motion, no tree - stays stepped as before

## Design

- `pane_sidebar_sheen_layers.zig` (pure): `Plan` renders the drift strip
  (its whole repeating gradient, slant included), the band (only the glint's
  lit stretch) and the rim from the same `pane_sidebar_motion` functions the
  stepped paint samples, and fits the loops (`driftLoop` linear 5 s,
  `bandLoop` the eased 0.8 s sweep then a hold to 2 s). `originMs`/
  `originQpc` put both loops on one 10 s origin (a multiple of both periods),
  on the performance counter DComp begin times use.
- `pane_sidebar_sheen_comp.zig`: up to 16 entries, each a box layer (offset at
  the pill, `setRoundClip`, opacity = the fade) with the three pieces
  `attachUnder` it. The live paint (`WM_PAINT` only - never a transition's
  snapshot or a probe's `WM_PRINTCLIENT`, which still draw the GDI sheen)
  `place`s every moving pill; a placed pill gets level 0 from `sheenFor`, so
  GDI draws no sheen there and it adds no dirty rect. Moved rows re-offset;
  a resize, theme or device generation change rebuilds. A full live paint
  drops what it did not ask for; the poll reaps faded-out entries and
  repaints their pills.
- `comp_overlay.Layer`: `setRoundClip` (rectangle clip with the eight corner
  radii, visual border mode SOFT) and `loopOffsetX` (SetAbsoluteBeginTime +
  AddCubic + AddRepeat on SetOffsetX).
- Mechanism trade-off (my call, recorded): the tree is TOPMOST on the GDI
  window, so the sheen lies over the label rather than under it. Invisible on
  dark; on light the glint dims the label while it passes. Filed T2844 to lay
  the text over it.
