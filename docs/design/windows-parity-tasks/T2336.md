# T2336 - Windows pane sidebar is one shared state across every window, as Mac's now is: expanded/collapsed, hidden, width, all-windows toggle, search, folds, list order and scroll position change in one window and every window shows it

## Summary

Mac b07b7fa0b + 9a1f14230 (main intake 2026-10-27). PaneSidebarSharedState.shared holds expanded/hidden/width/all-windows/search/window+group folds/window order/scroll; per window only its pane order, windowID (persisted with the window) and drawing details. Only the key window redraws live; others catch up when they become key (isLive/catchUp), including the column collapse/hide and grid resize. A clicked row in the all-windows list draws selected at once in the window it was clicked in. Narrow-window rail stays per window (<720pt). Scroll: last list scrolled wins, taken up on becoming key or appearing, never mid-scroll; rail and panel each keep their own; this-window lists not synced. Restore applies only the per-window part; flags come from app-wide defaults. Folds are absolute by windowID; turning all-windows off forgets folds and search. Mac ref: docs/reference/pane-sidebar.md 'Shared across windows'; tests PaneSidebarSharedStateTests, PaneSidebarSyncWindowTests.

## In plain terms

On Mac the pane sidebar is now one sidebar shared by every window: collapse it, widen it, search it or fold a group in one window and every other window shows the same thing when you switch to it. On Windows each window still keeps its own. After this, clicking through Windows windows shows the same sidebar every time.

## Goals

- [x] Expanded/collapsed, hidden, width, all-windows toggle, search and folds are app-wide; pane order and window identity stay per window
- [x] Background windows catch up when they are next focused (no per-frame redraw of every window)
- [x] All-windows list scroll position follows the last list scrolled
- [x] A clicked row in another window's group is drawn selected at once
- [x] Restore applies only the per-window part; the shared flags come from app-wide settings

## What landed

- `src/apprt/win32/pane_sidebar_shared.zig` (new, pure): `Shared` holds the scope, the search, the folds - ABSOLUTE by window group (`unfolded` for the all-windows list, opened with the window the scope was turned on from; `folded_this` for each "this window" list; `folded_projects`) - and the all-windows list's scroll per layout (rail/panel), with a `gen` counter. Turning the scope off forgets the search, the window folds and the scroll; project folds stay (Mac `setShowsAllWindows`).
- `PaneSidebar.zig`: `PaneSidebar.shared` is the app-wide state; each sidebar draws a copy (`takeShared`) as of `seen_gen`. Scope/fold/search changes go through `shared` and are taken back at once in the window that made them; `catchUp` (window activated) takes what another window changed, clears the clicked-row selection and takes up the shared scroll. A new sidebar starts from the shared state. A clicked foreign row is drawn selected (`clicked`, Mac `clickedPane`). The relative `toggled`/`open_key` fold model and `outline.windowFolded` are gone.
- `Window.zig`: `paneSidebarCatchUp` on WM_ACTIVATE applies the shared expanded/hidden/width (`PaneSidebar.remembered`) with the column glide, then the sidebar's catch-up. `setPaneSidebarWidth` no longer relays out every window per drag move - others take it on activation. The narrow-window rail stays per window (`paneSidebarMode` still takes the window's width).
- `App.zig`: restore no longer applies the manifest's `pane_sidebar_pinned/hidden` (Mac b07b7fa0b); each window still records its copy for an older build. `restorePaneSidebar` removed.
- Mechanism decision (no user-visible fork, so not a decision file): the per-window drawn copy + generation counter mirrors Mac's isLive/catchUp exactly; roster deferral for background windows (Mac `PaneRoster`) is a pure perf follow-up filed as T2347.
