# T2336 - Windows pane sidebar is one shared state across every window, as Mac's now is: expanded/collapsed, hidden, width, all-windows toggle, search, folds, list order and scroll position change in one window and every window shows it

## Summary

Mac b07b7fa0b + 9a1f14230 (main intake 2026-10-27). PaneSidebarSharedState.shared holds expanded/hidden/width/all-windows/search/window+group folds/window order/scroll; per window only its pane order, windowID (persisted with the window) and drawing details. Only the key window redraws live; others catch up when they become key (isLive/catchUp), including the column collapse/hide and grid resize. A clicked row in the all-windows list draws selected at once in the window it was clicked in. Narrow-window rail stays per window (<720pt). Scroll: last list scrolled wins, taken up on becoming key or appearing, never mid-scroll; rail and panel each keep their own; this-window lists not synced. Restore applies only the per-window part; flags come from app-wide defaults. Folds are absolute by windowID; turning all-windows off forgets folds and search. Mac ref: docs/reference/pane-sidebar.md 'Shared across windows'; tests PaneSidebarSharedStateTests, PaneSidebarSyncWindowTests.

## In plain terms

On Mac the pane sidebar is now one sidebar shared by every window: collapse it, widen it, search it or fold a group in one window and every other window shows the same thing when you switch to it. On Windows each window still keeps its own. After this, clicking through Windows windows shows the same sidebar every time.

## Goals

- [ ] Expanded/collapsed, hidden, width, all-windows toggle, search and folds are app-wide; pane order and window identity stay per window
- [ ] Background windows catch up when they are next focused (no per-frame redraw of every window)
- [ ] All-windows list scroll position follows the last list scrolled
- [ ] A clicked row in another window's group is drawn selected at once
- [ ] Restore applies only the per-window part; the shared flags come from app-wide settings

## Validation criteria

- [ ] Unit tests for the shared/per-window split and the catch-up rule (none + win32 lanes)
- [ ] On-box acceptance: two windows, a change in one (collapse, width, fold, search) shows in the other once it is focused
- [ ] -NegativeControl goes red
