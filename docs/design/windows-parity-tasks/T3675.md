# T3675 - Linux L11a-3: a GTK remote window shows its connection - the pill naming the machine and link state, and reconnecting in place when the link drops

## Summary

Port the connection pill and in-place reconnect (win32 remote_pill.zig, RemoteReconnect.zig; Mac's remote surface chrome) to GTK. Today a Linux remote window's link state is only visible in +list (connection.state, RemoteLink.listState); when the link drops, nothing on screen says so and nothing re-dials. Show the machine and state on the window (libadwaita, parity is behavior and information), drive the shared connection's reconnect/reattach ladder, and let the user retry or Disconnect from it. Split from T3563.

## In plain terms

On Linux, a window whose terminals run on another machine gives no sign of
which machine that is, and when the network link to it drops nothing on screen
changes and nothing tries to get it back - the panes just stop answering. After
this, the window's title bar carries a small pill naming the machine, it turns
amber and counts its retries when the link drops, the panes come back on their
own with their shells intact when the machine answers again, and when it gives
up the pill turns red and clicking it tries again.

## Goals

- [x] A remote window's header shows a pill naming its machine; a local window has none
- [x] A dropped link is retried on its own (1/2/4/8/15 s, then every 45 s) and the panes re-attach to the same shells in place
- [x] The pill says what is happening: the name, "Reconnecting... n/5", "Reconnect", "Version mismatch"
- [x] Clicking a red pill reconnects now; if the far sessions are gone, the same layout comes back with fresh shells
- [x] `+list` reports the ladder's state (attempt, self_healable, reason) like win32
