# T3649 - Linux L11k2: single-window mode on GTK - switch workspaces from the pane sidebar's all-windows list, goto_tab/goto_window walk them in sidebar order, every open path opens a workspace

## Summary

A click on a workspace's row in the sidebar all-windows list puts it on show (Mac bringForward); goto_tab previous/next/last/N and goto_window walk the workspaces in the sidebar's order; a new tab is a new workspace; Ctrl+Shift+N, menus, palette, sidebar +, +new-window, drag-out and undo open a workspace; focus policy: a manual open goes on show, +new-window without --focus stays parked, --focus puts it on show. win32: T3182, T3194, T3205. Spec: docs/reference/window-modes.md (Opening, switching, closing).

## In plain terms

With the "one window" setting on Linux, every extra window lives inside the
single window you see, but until now you had no way to move between them.
Now clicking one in the sidebar's list of all windows, or using the
next/previous tab and window shortcuts, swaps it into view, and anything that
opens a new window or tab (shortcuts, menus, dragging a pane out) opens it
inside that one window instead of popping up a second one.

## Goals

- [x] a click on a window's row, tile, or one of its panes' rows in the all-windows list puts that workspace on show
- [x] next/previous/last/N tab and goto_window walk the workspaces in the list's order
- [x] a new tab, Ctrl+Shift+N, a pane popped out (tested) and the sidebar's + / menus / palette (the same `initAndShowWindow` path as Ctrl+Shift+N) and a tab dragged out (`bringForward`, untested) open a workspace on show, never a second window
- [x] focus policy: +new-window stays parked; --focus (new, existing, or a split) puts it on show
- [x] window-level key controllers act for the workspace on show
- [ ] undo of a close re-opens a workspace on show - needs GTK window-close undo (existing card) and T3652's closing
