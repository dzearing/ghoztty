# T3654 - Linux L11k7: single-window mode on GTK - the window shows the most urgent activity of all its workspaces, and a parked workspace that needs input still asks for attention

## Summary

Roll-up of busy/needs_input across workspaces (workspace_host rolledUpActivity, win32 T3186) into the GTK window's activity (window_activity.zig) and urgency hint; the title suffix stays the on-show workspace's own. Spec: docs/reference/window-modes.md (Parked counts as hidden, state never pauses).

## In plain terms

With "All in one window" on Linux, only one workspace is on show at a time. Before this, a hidden workspace that started a long job or stopped to ask a question did not count: the window looked idle and nothing asked for your attention. Now the window reports the most urgent thing any of its workspaces is doing, and a hidden workspace that starts waiting on a question marks the window as wanting attention when it is in the background. The title's "(busy)" / "(question)" still describes the workspace you are looking at.
