# T1747 - Machine chooser hides the Activity button on the local row; Mac offers Activity Monitor for This Mac

## Summary

Filed by the T1633 chooser comparison; summary written at the 2026-09-26 triage.

Mac now offers "See Activity" for **This Mac** as well as remote machines
(`seeActivityButton`, `macos/Sources/Features/Remote/MachineChooserView.swift`
~L788-802: "the most common case - inspecting your own machine - had no entry
point here at all"; `machine == nil` opens the Local source without a dial).
The win32 chooser still carries the old rule: `openActivityMonitor` returns
early on `.local` with the comment "Mac shows no Activity button on the local
row" (`src/apprt/win32/MachineChooser.zig` ~L4739), and `compositionFor`
(test "Activity and the menu appear together, on remote rows only", ~L4982)
hides the button there. Fix: show Activity on the local row and open
`ActivityMonitor` on the local source, keeping the `…` menu remote-only if Mac
still gates it.

## In plain terms

In the machine chooser, remote machines have an "Activity" button that opens
the Activity Monitor, but your own PC does not - so the most common case,
looking at what is running on this machine, had no button. Now the This PC row
gets the same Activity button, and it opens the monitor for this PC straight
away, as the Mac app does for This Mac.
