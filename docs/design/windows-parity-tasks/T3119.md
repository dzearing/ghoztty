# T3119 - At an idle prompt 87% of the app's wakeups (about 127 of 147 a second) are NVIDIA driver threads: find whether our idle GL and D3D11 objects keep them spinning

## Summary

T2989's per-thread attribution (perf-baseline.ps1 -Phase idle, Debug, 1 pane, NVIDIA box) split the 146-149 idle context switches a second: nvwgf2umx.dll (D3D11 user-mode driver) 3 threads ~75/s, nvoglv64.dll (OpenGL driver) 2 threads ~50/s, ghoztty main thread ~10/s, renderer ~10/s. 55 nvwgf2umx threads exist at idle. Driver threads normally park when nothing presents, so find what of ours keeps them waking: the DComp/D3D11 present path (frame-latency waitable, flushes), the GL helper context, or a timer. A/B with the composition path off and with no pane rendering; compare against a bare D3D11 swapchain app at idle. Fix whatever of ours drives it, or record that it is the driver's own floor.
