# T820 - The sprite-face reference test writes its actual-image PNGs into the source tree and cannot find its reference data outside floor-lane

## In plain terms

Running the test suite from anywhere but the top of the repo — a
`zig build test -Dapp-runtime=win32` started while sitting in
`src/apprt/win32/`, say — left 36 stray PNG files behind in that directory
and reported a failure that had nothing to do with the code under test. It was
noise that made a real failure harder to see, and it dirtied `git status` for
whoever worked next. The test now finds its reference images however it is
started, and when it really does fail it leaves the evidence in `zig-out`
where it belongs.

## Goals

- [x] The sprite reference test finds its reference images from any cwd
- [x] A failing run writes its actual-image and diff PNGs under `zig-out`,
      never into the source tree
- [x] The cwd-independence is covered by something that runs from a
      directory other than the repo root, since the floor lane never does

## Details

Found while running T467's floor. `test.sprite face render all sprites`
(`src/font/sprite/Face.zig`) opens its reference images by the RELATIVE path
`./src/font/sprite/testdata/…`, so it resolves against the test binary's cwd,
not the repo. Run through `scripts\floor-lane.ps1` it passes; run bare it logs

```
[font_sprite] (err): Can't open reference file ./src/font/sprite/testdata/U+2500...U+25FF-18x36+4.png: error.FileNotFound
```

for every page, fails, and writes its actual-image dumps as
`sprite_face_test-U+….png` into whatever the cwd is — which for a bare
`zig build test` is `src/apprt/win32/`. 36 untracked PNGs were left there by
this turn's runs; they are not in `.gitignore` either.

Two halves, both worth fixing: resolve the reference and output paths from a
build-time root (or an env var the build sets) rather than from cwd, so the
lane behaves the same however it is invoked; and make the failure path not
scatter artifacts into the source tree.

Windows-seat framing: this is upstream shared-core code, so a fix here should
be one both platforms want. Check whether the same test misbehaves on the Mac
seat before changing anything, and file the other half if not.

## Validation criteria

- [x] `zig build test -Dapp-runtime=win32` from the repo root passes the sprite
      test and writes no files into the source tree
- [x] The same run through `scripts\floor-lane.ps1 -Lane win32` still passes
      (and `-Lane all`: lib / none / win32 / agent all green, 2026-09-17)
- [x] The 36 stray `src/apprt/win32/sprite_face_test-*.png` files are removed
      (user-gated deletion — offer it, do not delete unasked): the tree was
      already clean at claim time, and the only ones this turn created were
      its own reproduction's, removed with it
- [x] Run from a directory that is NOT the repo root (`src/apprt/win32`, the
      cwd the defect was found in) passes and writes no PNGs into the tree
- [x] A FAILING run puts all 36 actual-image PNGs under
      `<root>/zig-out/sprite-face-test`, never the cwd
- [x] `test\win32\sprite-testdata.ps1` is green, and red under
      `-NegativeControl`
