# T3406 - fork-ci release-parity goes red on a GitHub API rate limit, failing CI for commits that changed nothing it checks

## Summary

Fork CI run 45046769228 (commit 14b236f46) failed only in the release-parity job: scripts/check-release-parity.ps1 called gh api repos/dzearing/ghoztty/releases and got HTTP 403 'API rate limit exceeded for installation', exited 2, and the run concluded failure. Every claim/validate then reads CI RED and turns need -NoCiCheck for a red that says nothing about the code. Make the checker retry with backoff on a rate-limit 403 (honoring x-ratelimit-reset / retry-after) and, if still limited, report a neutral 'could not check' (exit 0 with a ::warning::) rather than a failure; T1836 is the publish-side sibling.
