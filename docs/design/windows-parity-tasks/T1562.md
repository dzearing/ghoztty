# T1562 - The feedback-capture clipboard sentinel shares the session clipboard, so anything copied mid-run fails the harness

## Summary

viewer-feedback-capture.ps1 seeds a GUID sentinel on the REAL system clipboard and later asserts it is unchanged, which is how it proves the capture never clobbers what the user had copied (D44's whole point). But the clipboard is per-SESSION, not per-desktop, so the assertion is also measuring every other process in the user's session. Observed on 2026-09-14 during T721's guard sweep: both clipboard assertions failed holding the string '---' (box-drawing U+2500 x3), which nothing in the run writes; an immediate re-run with no code change was ALL PASS (92). So the harness reported a product defect that does not exist, in the one script whose subject IS the clipboard. Wanted: the sentinel arms should distinguish 'the app overwrote it' from 'somebody else did' - e.g. re-read the clipboard sequence number (GetClipboardSequenceNumber) around the capture and name the owning window of a foreign write (GetClipboardOwner), so the arm can SKIP with a reason instead of failing when the writer was not the app under test.
