# T1506 - A stolen session's old viewer is never told, and can still type into the shell somebody else is now using

## In plain terms

A terminal session can only be shown in one window at a time, and the newest
window to ask for it wins. The window that loses it is told nothing: its pane
keeps sitting there looking like a working terminal, and anything typed into it
is still delivered to the shell the OTHER window is now driving. So two people —
or one person with two windows — can be typing into the same shell, with only
one of them able to see what happens.

## Goals

- [x] The window that loses a session says so in that pane ("Session opened
      elsewhere"), instead of looking alive forever.
- [x] Nothing typed (or resized, or Ctrl-C'd) in the losing pane reaches the
      shell the other window now drives.
- [x] Old apps and old agents keep working: no other pane is ever disturbed.

## Summary

Found while resolving T703, which settled the OTHER half of §5.3: the agent
binds a live session to the newest `ATTACH` and never refuses, so
`attached_elsewhere`/`force` are reserved fields nothing sets or reads. The
eviction half of that section is equally unimplemented, and unlike the refusal
it has a user-visible consequence:

- **No attach epoch.** §5.3 specifies a monotonic epoch stamped at each attach,
  with C→A frames carrying a stale epoch dropped. `grep` over `src/remote/`
  finds no such field; the old bridge's `DATA`/`SIGNAL`/`RESIZE` frames are
  accepted exactly like the new bridge's.
- **No `DETACHED` (0x05) ever sent.** The CLIENT handles the opcode
  (`connection.zig` drives the FSM to DEAD and records the eviction), but no
  agent code path sends the frame. `bindLocked` repoints the bridge and returns.

So a stolen-from viewer shows a live-looking pane forever, and its keystrokes
reach the PTY. Locally T851's `.skip_live_holders` probe policy makes the steal
rare (restore and Restore All withhold sessions somebody holds), but it is not a
guarantee: the remote arms deliberately keep `.attachable`, and the chooser can
resume a session another window has open.

## Approach

Two candidate shapes, and the choice is a mechanism call:

1. **Tell the loser** — send `DETACHED{reason=stolen}` to the previous bridge in
   `bindLocked`, capability-gated so an older client is unaffected, and let the
   client's existing eviction path paint the notice it already has.
2. **Fence as well as tell** — the full §5.3: stamp an epoch per attach and drop
   C→A frames carrying a stale one, so an in-flight keystroke cannot land after
   the steal.

(1) is most of the user-visible value; (2) closes the input race (1) leaves. The
wire additions are additive either way, and the skew rule from T703 applies:
never redefine an existing field.

## What landed

Mechanism choice (mine, per go.md 5b - the options differ only in mechanism):
both halves of the Approach, but the fence WITHOUT a wire epoch.

- **Tell the loser** - new capability `session_taken`. In `bindLocked`, when the
  session's bridge belongs to ANOTHER connection, the agent queues
  `DETACHED{reason:"taken"}` on the **session's own channel** to that
  connection, only if it negotiated the capability. The existing client
  `.detached` arm was connection-wide (FSM DEAD for every pane the connection
  carries), so a DETACHED to an older client would have killed all its panes:
  that is why it is gated. The client now reads a per-channel DETACHED as that
  pane only (`Channel.signalTaken`), and `termio/Remote.zig` prints
  `session_notice.taken_notice` once and stops input and resizes. The pane
  stays open. Control-channel DETACHED keeps its old meaning.
- **Fence** - `Server.takenFromUsLocked`: DATA, SIGNAL and RESIZE from a
  connection are dropped when a DIFFERENT connection holds the session's
  bridge. No wire change, so it protects old clients too. Unbound sessions
  (`bridge_ctx == null`) are not fenced, matching `handleClose`'s rule. §5.3's
  per-attach epoch is unnecessary: the agent already knows which connection
  each frame came from, which is exactly what the epoch was standing in for.

Shared core (`src/remote/`, `src/termio/`), so it lands for macOS and Windows
in the same change.

## Validation criteria

- [x] A second viewer's ATTACH over a bound session makes the previous viewer's
      pane say it lost the session: agent lane test "T1506: the viewer a session
      is taken from gets DETACHED{taken} on that session's channel only";
      client test "T1506: a DETACHED on a pane's channel marks only that pane
      taken; the connection stays up"; notice wording pinned by
      "taken_notice: ..." in `session_notice.zig`. On-box acceptance arm NOT
      written - filed as a follow-up (see Progress log).
- [x] Input from the evicted bridge does not reach the child after the steal:
      "T1506: input, signals and resizes from the viewer a session was taken
      from never reach it" (agent lane; run against an OLD client, the case
      that is never told).
- [x] Both skew directions: old client vs new agent = "a viewer that predates
      session_taken is not sent DETACHED"; new client vs old agent = "without
      session_taken negotiated, a per-channel DETACHED marks no pane taken";
      intersection = protocol test "T1506 session_taken negotiates on the
      intersection".
- [ ] T851's local probe policy still withholds held sessions - untouched by
      this change (no chooser/probe code edited); harness not re-run here.
