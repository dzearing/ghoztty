# T1506 - A stolen session's old viewer is never told, and can still type into the shell somebody else is now using

## In plain terms

A terminal session can only be shown in one window at a time, and the newest
window to ask for it wins. The window that loses it is told nothing: its pane
keeps sitting there looking like a working terminal, and anything typed into it
is still delivered to the shell the OTHER window is now driving. So two people —
or one person with two windows — can be typing into the same shell, with only
one of them able to see what happens.

## Summary

Found while resolving T703, which settled the OTHER half of §5.3: the agent
binds a live session to the newest `ATTACH` and never refuses, so
`attached_elsewhere`/`force` are reserved fields nothing sets or reads. The
eviction half of that section is equally unimplemented, and unlike the refusal
it has a user-visible consequence:

- **No attach epoch.** §5.3 specifies a monotonic epoch stamped at each attach,
  with C→A frames carrying a stale epoch dropped. `grep` over `src/remote/`
  finds no such field; the old bridge's `DATA`/`SIGNAL`/`RESIZE` frames are
  accepted exactly like the new bridge's.
- **No `DETACHED` (0x05) ever sent.** The CLIENT handles the opcode
  (`connection.zig` drives the FSM to DEAD and records the eviction), but no
  agent code path sends the frame. `bindLocked` repoints the bridge and returns.

So a stolen-from viewer shows a live-looking pane forever, and its keystrokes
reach the PTY. Locally T851's `.skip_live_holders` probe policy makes the steal
rare (restore and Restore All withhold sessions somebody holds), but it is not a
guarantee: the remote arms deliberately keep `.attachable`, and the chooser can
resume a session another window has open.

## Approach

Two candidate shapes, and the choice is a mechanism call:

1. **Tell the loser** — send `DETACHED{reason=stolen}` to the previous bridge in
   `bindLocked`, capability-gated so an older client is unaffected, and let the
   client's existing eviction path paint the notice it already has.
2. **Fence as well as tell** — the full §5.3: stamp an epoch per attach and drop
   C→A frames carrying a stale one, so an in-flight keystroke cannot land after
   the steal.

(1) is most of the user-visible value; (2) closes the input race (1) leaves. The
wire additions are additive either way, and the skew rule from T703 applies:
never redefine an existing field.

## Validation criteria

- [ ] A second viewer's ATTACH over a bound session makes the previous viewer's
      pane say it lost the session, rather than looking alive (agent lane test
      plus an on-box acceptance arm).
- [ ] Input from the evicted bridge does not reach the child after the steal, if
      the epoch fence lands.
- [ ] Both skew directions asserted for whatever capability is introduced: an
      old client against a new agent, and a new client against an old agent.
- [ ] T851's local probe policy still withholds held sessions (no regression in
      `test/win32/chooser-restore-all-adopt.ps1`).
