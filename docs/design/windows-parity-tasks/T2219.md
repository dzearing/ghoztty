# T2219 - Tunnelled file viewers: remote file fetch with granted roots, live reload push, relative assets, remote git diff (Windows + shared)

## Summary

See docs/design/remote-viewer-tunnel.md (T1297 design). Decision 1/4 + live reload. A --view of a remote path arrives via T2217; the win32 viewer must load its bytes from the agent (rpc fetch scoped to the granted directory, local size cap), serve relative images/.md links from that root through a separate virtual host, re-fetch on agent viewer_changed pushes, and render git-status/git-diff from git output the agent runs remotely (parsing stays local). Feedback reports are written on the remote machine through the proxy.

**What this task landed (first slice, the shared half):** the wire and the
agent's read policy. A new gated capability `viewer_fetch` with six opcodes
(`VIEWER_OPEN` 0x82 / `VIEWER_OPENED` 0x83 / `VIEWER_FETCH` 0x84 /
`VIEWER_DATA` 0x85 / `VIEWER_CLOSE` 0x86, plus the `VIEWER_CHANGED` 0x87
live-reload push, defined now so every peer advertising the capability knows
it) in `src/remote/protocol.zig`, and `src/remote/agent/viewer_grants.zig`:
OPEN grants the directory of the file's real path; every FETCH is a path
relative to that root, refused when it climbs out (`..`, absolute,
drive-relative, NUL) and refused again when the OS-resolved path (links
followed) lands outside the root; files over 32 MiB (the local viewer's own
`max_file_bytes`) are refused before a byte is read; reads come in base64
pieces of at most 1 MiB so one big file cannot hold the control lane; at most
64 grants per connection, never evicted. The agent advertises the capability
and answers on the request channel, and answers nothing to a peer that did not
negotiate it. Nothing on the app side calls it yet, so no user sees a change.

**Split** (same shape as T2217): T3714 (win32 viewer reads a remote file
through the grant, separate virtual host for relative assets), T3715 (agent
watch + `VIEWER_CHANGED` push, scroll-keeping re-fetch), T3716 (remote git
status/diff run by the agent, parsed locally), T3717 (feedback written on the
remote machine), T3718 (GTK half, seat: linux). Mac stays T2220.

## In plain terms

When a pane on another machine asks to show a file, the window you are
looking at has to get that file's contents from the other machine - and the
other machine must not hand over anything else. This lands the rule and the
pipe on the other machine's side: it hands out a file and the pictures next to
it, and refuses anything outside that folder. Nobody sees a difference yet;
the window-side half is the next task.

## Goals

- [x] A gated, additive wire for reading a file on the agent's machine
- [x] The agent's policy: one granted directory per opened file, nothing outside it, size-capped, chunked
- [x] The agent serves it, and stays silent to older peers
- [x] The remaining halves filed as their own tasks

## Validation criteria

- [x] Capability negotiates only on the intersection; the two answers are parked-on replies, the rest are not; a full base64 chunk fits a frame - `protocol.zig` test "T2219 viewer_fetch negotiates ...", `zig build test-agent -Dtest-filter=T2219` (and the none/win32 lanes, whose `connection.zig` reply-dispatch walk covers every new opcode).
- [x] Every way out of the root is refused textually (`..`, `/x`, `\x`, `C:\x`, `C:x`, empty, NUL) and a sibling directory sharing the root's prefix is not "under" it - `viewer_grants.zig` tests, agent lane.
- [x] Open grants the file's directory; the file and its relative picture read; offset/max_len pieces with `eof` on the last; a directory, a missing file, a bogus grant and a closed grant are each refused with their own reason; ids are never reused - `viewer_grants.zig` "Grants: open grants ..." test, agent lane.
- [x] Over-cap file refused before read (sparse 32 MiB + 1); grant count bounded at 64 and the first grant still reads - agent lane.
- [x] A symlink inside the root pointing out is refused after realpath - agent lane test (skipped on Windows, where creating a link needs a privilege; runs on the Mac and Linux seats).
- [x] Over the real agent wire: OPEN -> OPENED on the request channel, two FETCH pieces decode to the file, `../` refused as `outside_root`, CLOSE then FETCH reads `no_grant`; and a peer without the capability gets no `VIEWER_OPENED` - `server.zig` tests "T2219 VIEWER_OPEN/FETCH/CLOSE ..." and "... never answered", agent lane.
