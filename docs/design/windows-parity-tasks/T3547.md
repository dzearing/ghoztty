# T3547 - conpty-sync-hold.ps1 only stubs the classic Ink frame, not the fullscreen one every Windows pane now runs: add Claude Code's alt-screen resize shape (?2026h ?25l ED2 ?2026l, no ED3)

## Summary

T1818 measured Claude Code 2.1.330 under in-box ConPTY. In fullscreen mode (CLAUDE_CODE_NO_FLICKER=1: the T1801 default, and the user's own settings.json `tui`) EVERY resize leaves conhost as `ESC[?2026h ESC[?25l ESC[2J ESC[?2026l` on the ALT screen, followed ~9ms later by an unbracketed paint. In a Debug pane with GHOZTTY_CONPTY_SYNC_HOLD=0 all 6 resizes were shown blank; with the hold, all 6 were held (how=idle, ~22ms). The classic renderer did not erase at all on resize.

So the hold is load-bearing for the main workload, but `test\win32\conpty-sync-hold.ps1` stubs only the classic main-screen shape (`?2026h 2J 3J H rows ?2026l`). Add a stub mode that enters `?1049h` and redraws with ED2 only (no ED3), run it in sections A (local pane) and B (agent pane), and keep -NegativeControl proving the blank frames come back for it too.
