# T3606 - Linux L10d: pane sidebar hover buttons on GTK - stash/restore and x on pane rows, + and x on window and group headers, the panel header's +

## In plain terms

On Linux the pane sidebar lists every pane, but its rows did nothing beyond
a click to focus. On the Mac, moving the mouse over a row shows small buttons
to tuck the pane away (stash), bring it back, or close it, and window and
group rows get a + to add a pane or window and an x to close them. This
brings those buttons to the Linux sidebar, with the same rules: closing from
the sidebar never asks "are you sure?" and never steals focus.

## Summary

Split from T3557 (which landed the list, the rail/panel button, Ctrl+Shift+S,
shared persisted flags and macos-pane-sidebar on GTK). This task is the
sidebar's hover buttons (docs/reference/pane-sidebar.md "Rows and tiles",
"Adding from the sidebar", "Closing from the sidebar"):

- a panel row of this window offers - (stash) or the restore, then x; another
  window's pane row the x alone; the rail none;
- a window row, a project header and the Ungrouped header offer + then x
  where the count was; the panel header has a + (a new window);
- every close from the sidebar asks nothing, raises nothing and runs on the
  next main-loop turn; a window's last pane closes the window;
- a window row's + splits that window's focused pane in the last direction
  split by hand (the GTK split action now records it, `+split` does not); a
  project's + opens `<project>: new` (else the first free `new-N`) in the
  group; the Ungrouped header's an untitled window.

The rest of the original scope - this window's own header row and the rail's
+, rename in place, the hover tint, the busy sheen, the width grip and hero
suppression - is T3695.
