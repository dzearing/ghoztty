# T2251 - At a shell prompt a Windows resize still waits out the debounce and can flash the prompt blank; Mac now reflows the prompt live and holds the last frame until the shell redraws (main a81db68f9)

## Summary

Mac a81db68f9 (shared core): at a prompt a resize applies at once (ResizePace.now), the next resize waits only for the shell's redraw (after_redraw, 4ms poll), and the renderer holds the last frame while the cleared prompt is redrawn (Terminal.flags.awaiting_prompt_redraw, released when output goes quiet, capped at 250ms). After T2249 merges the core, prove it holds on Windows: ConPTY's own reflow/repaint, the session-agent round trip, and cmd/pwsh/wsl prompt marks (T1757 history) - a drag-resize of a pwsh pane at a prompt must reflow on every step and never show the prompt blank; a running program still debounces.

## In plain terms

When you drag a divider or the window edge with a shell sitting at its prompt,
the prompt should re-flow to the new width as you drag and never blink empty,
the way it now does on the Mac. On Windows it only did that in PowerShell; in a
cmd pane every resize after the first still waited until you stopped dragging.
Now both re-flow live, and a program that is running still gets the calmer,
batched resizes so it does not flicker.
