# T2684 - Settings change toast on Windows appears and vanishes instantly; Mac's slides up from the bottom and fades (SettingsToast .transition(.move(edge: .bottom).combined(with: .opacity)))

## Summary

Filed from T2676. The Settings window's "Saved - Show Change - Undo" toast
(`settings_advanced_view.paintToast`) is painted the moment a write records a
change and erased the moment it is dismissed or times out. Mac's
`SettingsToast` (`SettingsView.swift`, 9287de0ff) enters with
`.transition(.move(edge: .bottom).combined(with: .opacity))` and leaves the
same way (`withAnimation { model.dismissLastChange() }`), and Show Change
grows it in place. Port the motion: a short slide-up + fade on appear and the
reverse on dismiss / timeout, driven by a timer on the Settings window's own
hwnd, respecting the system's reduce-animation setting the way the other
win32 animations do. Mac visuals port faithfully (user, 2026-10-25), so this
is not optional polish.

**Re-verified against the Mac source on claim (2026-11-04): only the TIMEOUT
animates on Mac.** A SwiftUI transition plays only inside an animated
transaction. The one `withAnimation` around the toast is the six-second
timeout's `dismissLastChange()`; the write that raises it, the x button,
Undo and Show Change all run outside any animation, so on Mac the toast
*appears* instantly, the x/Undo remove it instantly, and Show Change resizes
it without motion. The faithful port is therefore: timed-out exit = slide
down off the form's bottom edge + fade, SwiftUI's default ease-in-out
(0.35 s); everything else instant, exactly as Mac shows it.

## In plain terms

After you change a setting, a small "Saved" note appears at the bottom of the
Settings window. On a Mac, when that note times out it glides down and fades
away; on Windows it just blinked out. Now it glides and fades on Windows too,
and simply disappears if you have turned animations off in Windows.

## Goals

- [x] The timed-out toast slides down off the form and fades, on the app's frame clock
- [x] Instant when Windows' "Animation effects" is off (or over Remote Desktop)
- [x] A change, x or Undo during the exit cuts it short, as on Mac
- [x] The frames are observable through the `settings` IPC seam
