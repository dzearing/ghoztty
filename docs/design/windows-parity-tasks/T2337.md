# T2337 - Windows all-windows sidebar list reorders by drag: a window row among its siblings and a project header among the top level, the order shared across windows and persisted, as on Mac

## Summary

Mac b07b7fa0b, c4dbe30be, 9a1f14230, 97afdaf5a. Reorders the LIST only (no window or pane moves). Siblings slide by the dragged item's pitch (bounded 0.2s, none at drop); the item follows the pointer lifted over a solid backing, kept in its list, glides into place after the new order is laid out; Escape cancels; chevron and x are outside the drag source; click still raises/folds. Dragging a group folds every group first (held header stays under pointer), dragging a window folds every window to its row; folds return after drop/cancel. No hover while dragging; rows re-sync from pointer on land. Order is shared + persisted (keys project:<name>, window:<windowID>); a new window/group lands after its name-order neighbour; closed windows pruned on the next move, never on close; windowID restored with the window so relaunch keeps its place. Mac ref: docs/reference/pane-sidebar.md 'Reordering windows and groups'; tests PaneSidebarWindowOrderTests, PaneSidebarItemReorderTests, PaneSidebarSyncWindowTests.dragReordersAWindowAndAGroup.

## In plain terms

On Mac you can drag windows and project groups up and down in the sidebar's all-windows list to put them in the order you want, and that order sticks across windows and restarts. On Windows the list is always alphabetical. After this, Windows lets you drag them the same way, with the same sliding animation.

## Goals

- [x] A window row drags among its siblings and a project header among the top level; nothing moves on screen
- [x] Siblings slide, the dragged item lifts and glides into place; Escape cancels
- [x] Dragging folds every group (or every window) first and restores the folds afterwards
- [x] No row hover lights up mid-drag
- [x] The order is shared, persisted, and a new window lands after its name-order neighbour

## How it is built

- `src\apprt\win32\pane_sidebar_window_order.zig` (pure): keys `project:<name>` / `window:<tab uuid>` (the tab id session restore re-adopts, T1048), `arrange` (Mac `sections(_:order:)` over `pane_sidebar_order`'s rules, compared byte for byte - `pane_sidebar_order.By(eql)`), `allKeys`, `moving`, Mac `PaneSidebarItemReorder` (`target` by the leading edge, `pitch`, `landingTop`, `clamp` with the grab point), and the file `%LOCALAPPDATA%\ghoztty\pane_sidebar_order[-debug]` (one key per line).
- `pane_sidebar_shared.Shared.window_order` holds the order (a shared change every window catches up on, T2336), `foldProjects` / `foldWindows` / `restoreFolds` the drag's folds.
- `PaneSidebar.zig` "Reordering windows and groups": a `.head` press past the drag threshold in the expanded all-windows list picks the item up (the chevron, + and x are other hits); siblings slide on `reorder.Tween`s, the held header is painted lifted (backing + shadow) and glides `reorder.settle_ms` to its laid-out place; the sticky header and hairlines stand down while it is held; Escape is routed by `App.cancelPaneDrag`, a lost capture cancels. Header tooltips in the all-windows list say "drag to reorder", as Mac's help does.
- Decisions taken (mechanism, not experience): the drag-start fold and the drop's unfold are instant rather than animated (filed as polish, see below); while a search filters the list the drag moves among the items shown and hidden ones keep their place, as on Mac.
