# T2721 - Ctrl+V with an image AND text on the clipboard (browser Copy Image) pastes the text into Claude Code instead of attaching the image

## In plain terms

Right-click "Copy image" in some browsers puts the picture on the clipboard
together with some text (its address, or HTML). Pressing Ctrl+V in a Claude
Code pane then pastes that text rather than attaching the picture. Screenshots
work since T2694, because they carry no text.

## Summary

On Windows, Ctrl+V is Ghoztty's paste keybind. T154 passes ^V through to the
program only when the clipboard has no `CF_UNICODETEXT`
(`Surface.clipboardRequest` returns false, `src/apprt/win32/Surface.zig`
~2829), and T2694 binds Chat `ctrl+v` to `chat:imagePaste` in Claude Code's
`~/.claude/keybindings.json`. So with an image-only clipboard Claude gets the
^V and attaches the image; with image + text, Ghoztty pastes the text and
Claude never sees the key.

Constraint from the T2694 report: do NOT rewrite Ctrl+V for arbitrary
programs, since a shell or editor in a pane owns its own ^V and wants the
text. Any fix has to be specific to the pane running Claude Code (Ghoztty
already knows that from the Claude hooks / activity markers), or decide which
format wins by what the clipboard actually holds. First, record exactly which
formats Chrome, Edge and Firefox "Copy image" put on the clipboard. That
answers whether the text is even plain text or only `HTML Format` (which would
not trip the `CF_UNICODETEXT` check at all).

Mac comparison: Cmd+V is paste there and Ctrl+V always reaches Claude, so the
Mac user never hits this.

## Validation criteria

- [ ] The clipboard formats from Copy Image in Chrome, Edge and Firefox are recorded here.
- [ ] Image + text on the clipboard, Ctrl+V in a Claude Code pane: the image is attached (on-box acceptance, test desktop).
- [ ] The same clipboard, Ctrl+V at a plain pwsh prompt: the text is pasted, as it is today.
