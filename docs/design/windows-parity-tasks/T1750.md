# T1750 - macOS: --shell= with no --command is ignored; +new-window/+split --shell=zsh should open that shell (Windows half landed in T1665)

## Summary

`macos/Sources/Features/IPC/IPCServer.swift` reads `--shell` only inside `wrapCommandInShell` (handleNewWindow ~L394, handleSplit ~L637), so `ghoztty +new-window --shell=/bin/bash` or `+split --shell=/bin/bash` with no `--command` silently opens the default shell. Windows now opens the named shell on every path (T1665: `apprt.ipc.args.localExecArgv` on the exec path, and `--shell` counts as explicit for `+split` on the agent path); docs/claude/cli.md states the contract for both platforms. Fix: when `parsed.shell` is set and there is no command, set the surface command to the shell as an interactive login shell (`<shell> -li`, Mac convention), on both the plain and the session-persistence (agent `OPEN.shell`) paths. Validate: a Mac acceptance run that opens `+new-window --shell=/bin/bash` and `+split --shell=/bin/bash` and proves the pane runs bash (e.g. `echo $BASH_VERSION` prints a version).
