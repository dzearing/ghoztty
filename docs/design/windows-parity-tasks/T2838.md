# T2838 - A divider-glide pass that resizes a viewer pane costs 4.8 ms in the pane batch instead of 0.8: the viewer's WM_SIZE runs the WebView2 bounds sync (nav bar place + put_Bounds, ~2.5 ms) synchronously inside EndDeferWindowPos, once per tick

## In plain terms

When a divider drag squeezes a markdown/web viewer pane, every frame that
changes the viewer's size takes several milliseconds longer than one that
doesn't. On a 120 Hz screen those frames can miss a refresh.

## Summary

Found on T2732 (2026-11-08, lane b), release build at e961d2e97, the T2732
glide probe (5 panes, a viewer second, 120 Hz, 1875x1125, ring trace):

- Pane batch (`stack trace batch` qpc..end) on passes whose `stack trace
  place` lines change the viewer hwnd's size: **n=48, mean 4.83 ms, p50
  4.14, p90 5.93, max 15.4**. On every other pass: n=1286, mean 0.84.
- Diagnostic A/B (temporary knob, reverted): with the viewer's `WM_SIZE`
  skipping `syncBounds` those same passes fall to **mean 2.29 ms** (p90
  2.92). So ~2.5 ms is the bounds sync inside `EndDeferWindowPos`, and
  ~1.5 ms is the host window's own resize (a windowed WebView2: the browser's
  child HWND lives in another process).
- `syncBounds` itself: nav bar `place` ~0.9 ms (tip sync ~0.4, paint ~0.3,
  bar move ~0.2) + `put_Bounds` 0.3-0.6 ms, with outliers: `bounds_us=9752`
  once, and one whole viewer sync of **320 ms** in one run (`owner=tick_viewer
  before_viewer_us=320182`).

Directions: (a) take the bounds sync out of the batch and coalesce it, so
it runs once per tick after `EndDeferWindowPos` rather than inside it (the
nav bar already defers its EDIT move and its window during a window-edge
drag, T2538/T2767); (b) keep the nav bar's per-tick work to the band move
(tooltip sync once the glide settles); (c) find the 320 ms outlier
(cross-process put_Bounds stall?) on a cold run.

Probe: `glide-probe.ps1` + `vb.py` (viewer-resized vs not batch split) in
session ca6bf5d2's scratchpad.

## Validation criteria

- [ ] viewer-resize passes' pane batch within 1 ms of the other passes' on the T2732 probe (release, ring trace, `vb.py`)
- [ ] the viewer's content still follows the pane live during the drag and is exact at drop (viewer-panes acceptance green)
