# T3655 - Linux L11k8: single-window mode on GTK - a relaunch brings every window back as a workspace with the one that was in front on show, and a manifest from either mode restores in the other

## Summary

Session layout manifest: Entry.frontmost (additive) marks the workspace on show; restore brings the frontmost entry back last (frontmostLast) so it is on show in single and in front in separate; a single-mode manifest read in separate mode is windows. App-agent wire contract unchanged (the blob is opaque). win32 T3187, T3137. Spec: docs/reference/window-modes.md (Persistence).

## In plain terms

With "All in one window" chosen on Linux, quitting or crashing and coming
back should give you every workspace you had, each still running the same
programs, with the one you were looking at on screen - not whichever one
Linux happened to remember last. And switching the setting between "All in
one window" and "Separate windows" should never lose anything: what you had
in one mode comes back in the other.

## Goals

- [x] single mode records one entry per workspace, on show first, each at the shared window's size, and marks only the one on show as in front
- [x] a relaunch puts that one back on show (and in front in separate mode), whichever entry carries the mark
- [x] a single-mode layout reads in separate mode as windows at one size, and a separate-mode layout reads in single mode as workspaces

## Design (as built)

- `SessionLayout.capture`: in single mode the windows are listed in
  `Workspaces.order()` (on show, then most recently shown), then any window
  that is no workspace in GTK focus order. Only the shared toplevel is ever
  focused, so GTK's own order cannot tell parked workspaces apart - which is
  what the old capture used, so it marked whichever window GTK last focused.
- Every workspace records the shared toplevel's size and maximized state
  (`Workspaces.physical()`, the frame after T3652), since its own GtkWindow
  never maps. The workspace on show is the entry marked `frontmost`.
- `SessionLayout.restore` builds back to front with the frontmost-marked
  entry last (`session_layout_rules.restoreOrder`, unit-tested), wherever it
  is listed. Every restored window is presented with activate, so the last
  is on show in single mode and presented last in separate mode, and the
  workspace order round-trips. Each build is logged (`building window=`).
- Wire contract unchanged: the manifest is the app's own file and the
  `frontmost` field already existed in the shared schema (win32 T3137).
- Known gap, not this card's: a restored PARKED workspace re-attaches its
  session on first show, not at launch (T3786, born-parked start).
