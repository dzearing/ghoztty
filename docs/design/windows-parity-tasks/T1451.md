# T1451 - Nothing makes anyone run the manual pre-release IME checklist

## In plain terms

Some things about typing Japanese into Ghoztty can only be checked by a person
with a Japanese keyboard installed. That checklist now exists, but nothing asks
anyone to run it, so in practice it will not be run.

## Summary

T642 wrote `docs/design/windows-parity-ime-manual.md`: the IME checks that
cannot be automated on this box (the candidate window, the underlined
intermediate string, reconversion, where the caret rests after a commit)
because they are drawn and read by the input method through the input context,
and this machine has one input method installed.

A checklist nobody is prompted to run is the same as no checklist. Windows
releases are published automatically by `scripts/daily-publish.ps1`, and there
is no pre-release human step anywhere for it to hang off.

Pick a home for it and wire it, rather than adding a document nobody opens:

1. A `docs/design/windows-parity-release-checklist.md` that the publish script
   NAMES in its release notes or its log line, so the checklist is visible at
   the moment a release exists.
2. Or a periodic prompt: a row in the daily digest's Commentary when the manual
   check has not been recorded for the current Mac version line.

The check itself needs a box with a Microsoft IME installed, which this one
deliberately is not — so whatever the mechanism, it has to survive being
deferred rather than blocking a publish.

## Goals

- [x] A record of who ran the checklist, for which release line, and the result
- [x] The publish names an owed checklist at the moment it cuts a release
- [x] The morning digest's source (`daily-publish.ps1 -Status`) names it too
- [x] Never a gate: an owed check never holds a release back

## What landed

Both options from the summary, joined up, because neither works alone: a
release-time log line is read by nobody unless something carries it to a
person, and a digest row needs a record to know whether the check was done.

- `docs/design/windows-parity-manual-checks.json` - committed record of runs,
  keyed by release LINE (Major.Minor, the Mac line every win-v patch walks on).
  A check is owed for a line until a PASS for that line is recorded; a FAIL
  keeps it owed, and a pass on an older line does not carry forward.
- `scripts/lib/ManualChecks.ps1` - the catalogue (today: `ime` -> the IME
  manual) and the pure verdict. Adding another person-only check is one row.
- `scripts/manual-check.ps1 status|record` - records a run; refuses an unknown
  check, a result that is not pass/fail, and a FAIL whose note names no task.
- `scripts/daily-publish.ps1` logs `MANUAL CHECK OWED: ime ... Deferred - it
  never blocks a publish` right after `DUE:` (so `-Check` and dry runs show it
  too) and in `-Status`; `go.md` step 0.5 tells the digest to carry it under
  Decisions. Not in the release notes: those are user-facing What's New text.

Live on this box today (`-Status`): `MANUAL CHECK OWED: ime ... for the 1.54
line (never run for this line)`.
