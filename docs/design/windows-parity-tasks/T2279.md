# T2279 - The Windows sidebar rail shows monogram tiles and a busy shimmer; Mac's rail is now the expanded rows minus their text (same pill, same kind glyph, nothing moves on toggle) with a right-to-left sheen across a busy pane's pill (Mac d2fd04a19, 919fba868, 2924ea5cc, 75dc046e3)

## Summary

Mac 919fba868: rail tiles show the pane KIND's glyph instead of a letter (monogram removed). 75dc046e3: a rail tile is the expanded row without its text - the same pill, the same glyph at the same place (the rail card is exactly that pill, 52pt), so toggling moves no icon; the tiles' glass, white ring and glyph shimmer are gone. Busy = the same sheen across the pill in both modes: an upright band crossing the pill right to left, starting and ending fully off it (2924ea5cc), fading in when work starts, sweeping every 2s at 25% white (919fba868). 919fba868: busy means PaneView.isWorking - the hook-set activity state OR an OSC 9;4 progress report on screen, i.e. exactly what animates the pane's border; Mac read only the activity state before and a working Claude pane's icon sat still. Check the Windows sidebar's busy source against the border's (T1899).

## In plain terms

When the pane list on the left is collapsed, each pane used to show as a
little square with two or three letters in it, and a busy pane's letters
shimmered. Now the collapsed list looks like the expanded one with the words
taken away: the same rounded bar, the same little icon in the pane's colour,
in exactly the same spot - so opening or closing the list doesn't make the
icons jump. A busy pane, in either view, gets a soft band of light sweeping
across its bar every couple of seconds, and that now also happens when a
program reports progress (the same thing that lights the pane's border).
