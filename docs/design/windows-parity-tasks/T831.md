# T831 - Hoist the wall-clock test wait into one shared helper, and sweep for the spin-count oracles that are left

## Summary

T472 replaced five spin-count test oracles in src/remote/connection.zig with a local TestDeadline, and found that src/remote/agent/pty_child.zig had independently arrived at the same answer for the same reason (waitContains, wall-clock bounded, dumping what it captured on timeout - T89b, where 30k spins was ~8 minutes of timeout per miss because Thread.sleep(100us) rounds up to Windows' 15.6ms tick). Two implementations of one idea, in two files, each written after the other's lesson was already paid for - and nothing stops the third from being a spin count again. Wanted: one shared test-wait helper both call, and a sweep of the remaining test waits across src/ for any oracle that counts iterations rather than elapsed time. The sweep is the deliverable; the helper is what makes the next one cheap.

## In plain terms

Tests that wait for something used to give up after counting to a number
instead of watching a clock. On a busy machine that number runs out while the
thing being waited for is still perfectly on time, so a healthy build goes red
for no reason — and whoever is watching learns to shrug at red. Two different
files had each invented the same clock-based fix independently, so nothing
stopped a third from going back to counting. Now there is one shared timer
every test uses, a sweep that says the tree is clean, and a check that fails
the next time somebody counts. The one place a user could feel it: `+send-keys
--when-idle --idle-timeout=30` now really gives up after thirty seconds,
instead of after thirty seconds plus however long the machine took to answer
each poll.
