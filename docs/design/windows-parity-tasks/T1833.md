# T1833 - Windows panes are opaque over the window backdrop: Mac's glass panes are translucent sheets tinted 40% with the terminal background

## Summary

Mac macos-pane-glass (default true, elevated style): each pane is a sheet tinted with the terminal's background (40% after 0d8de3436) and the gradient runs up under the titlebar. Every opaque layer in between goes: the renderer's terminal background (pane_glass in src/renderer/generic.zig), the banner strip's base fill, viewer template pages (pane-glass class in src/viewer/viewer.css; websites/HTML keep their own background), the titlebar backdrop. The unpinned sidebar card is tinted glass too (ec71db251) with a lighter tint and no lifting wash (733b03e58). Windows: the custom title bar and tab strip, the banner, viewer panes; relate to T1788 (acrylic blur) and T1787 (solid text over translucency). Screen validation needs the user away (T1794 gate).

**Scope landed here: the terminal panes and their cards** - the part every
glass window shows. The banner/header bands (T1884), viewer pages (T1885),
the title bar (T1886) and the sidebar overlay card (T1887) are filed as their
own tasks.

## In plain terms

On a Mac, each terminal pane is now a sheet of tinted glass: the window's
colourful background shows faintly through every pane, not just in the gaps
between them. On Windows the panes were solid blocks of the terminal colour.
Now a Windows pane shows the same background through it at the same strength,
and its rounded edge blends into it with no visible seam. A window with a
see-through background setting keeps its old see-through panes.

## Goals

- [x] A terminal pane in the elevated style is 40% terminal background over the gradient under it, by default (`macos-pane-glass`, read under Mac's key)
- [x] The card's rim, corners and shadow are painted as glass too, and meet the pane's own pixels without a seam
- [x] `macos-pane-glass = false` gives the solid card back; a live reload switches an open window
- [x] A pane a split creates, moves or resizes gets its new slice of the gradient
- [x] The rest of Mac's glass surfaces are filed: T1884 (banner/header), T1885 (viewer pages), T1886 (title bar), T1887 (sidebar overlay)

## Decisions recorded

- **How a GL child shows the desk.** A pane is its own OpenGL child window,
  so nothing the parent paints can show through it (and a transparent pixel
  would show the *desktop*, T1787's mechanism). Instead the renderer draws the
  desk itself: the window hands each terminal the slice of the gradient its
  child covers (new renderer message `pane_backdrop`, platform-neutral, sent
  only by win32), and the existing background-image pipeline draws it at
  opacity 0.6 over the terminal background - exactly Mac's 40% tint. The pane
  stays opaque, so nothing about composition changes. The slice is rendered
  at a quarter of the pane's size (linear sampling; the gradient has no detail)
  and re-sent only when the pane moves or the desk changes.
- **One mix on both sides of the edge.** Windows' default `alpha-blending` is
  linear-corrected, so the renderer mixes in linear light; the parent's
  rim/corner pixels use the same linear mix (`pane_elevation.glassMix`, table
  driven). Measured: the pane edge is 3 levels (sum of channels) from the
  computed glass-over-desk beside it.
- **Glass shadow and rim follow Mac's pre-Liquid-Glass `PaneGlass`:** one
  soft drop (radius 9, y 6, cast at the sheet's 40% alpha) kept off the sheet
  itself, and the brighter glass rim (white 10% / black 8%).
- **A configured `background-image` wins** over the desk slice (the pane
  keeps the user's image); on Mac glass hides it entirely, which is worse.
- **Translucent windows keep solid panes.** With `background-opacity` below
  1 the desk is still opaque on Windows (T1852), so glass would replace the
  desktop showing through with the desk. Glass applies to opaque windows
  until T1852 lands.
- **The card fill is the app's configured background**, as for the solid
  card; a pane whose background was changed at runtime (T67) tints its own
  interior correctly but its rim uses the configured colour - the same
  pre-existing gap the solid card has.
