# T3628 - Linux L11e-5: a side pane opened without focus comes on show on GTK (featured pane), and a split from a minimized pane goes in beside the pane on show nearest it

## Summary

Follow-up of T3567 (docs/reference/stacked-panes.md 'A side pane opened without focus comes on show'). An agent +split (focus is opt-in) into a GTK row with no room is born a strip nobody sees: PaneStackState.feature is never called on GTK. Call it from the GTK split paths when focus is false (newSplitAt, the viewer split), make the caller the strip when even that is not enough while it keeps the caret, and anchor a background split off a minimized pane to paneOnShow (backgroundSplitAnchor). Acceptance: stacked-panes.sh section - a non-focus +split into a full row is on show and the caller keeps focus.

## In plain terms

On Linux, when an agent opens a side pane without taking the keyboard, and the
window has no room for another pane, the new pane used to be squeezed into a
thin strip nobody could see. Now it comes on show (other panes fold away to
make room) while you keep typing where you were. And a side pane opened from a
pane you had folded away goes in next to a visible pane, so it does not drag
your folded panes back out.

## Goals

- [x] A split that leaves the caret where it is comes on show (the featured pane), in GTK `newSplitAt` - the path every GTK split (IPC `+split`, viewer split, inline `+new-window` split, link side pane) goes through
- [x] The caller keeps the caret, and becomes the strip itself when even featuring is not enough (the shared `layoutRank`)
- [x] A background split off a minimized pane goes in beside the pane on show nearest it (`backgroundSplitAnchor`)
- [x] A focus change ends the featuring as it happens (`propSurfaceFocused` -> `noteFocusMoved`, win32 `adoptsFocus`)
