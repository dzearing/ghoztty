# T1030 - The cappedLuminance hue sweep only ever tests red - its 0..360 loop feeds a 0..1 hue

## Summary

test-coverage hole found while fixing T325: the sweep looks like 72 hues and is one

## In plain terms

A test that is supposed to check the close button's red hover — and every
other saturated color the chrome can produce — against a brightness ceiling
actually only ever checks one color: red. It looks like it sweeps the whole
rainbow. Nothing is broken for a user today; the point is that the safety net
covering "white must stay legible on a colored fill" is a twelfth the size it
appears to be, so a future change could break green or blue and no test would
notice.

## Where

`src/apprt/win32/color_math.zig`, the `cappedLuminance: the ceiling holds on
the 8-bit color it returns` test. It loops `h` from 0 to 360 in steps of 5 and
passes it to `hsbToRgb`, whose hue parameter is a **0..1 turn** (`hp = h * 6`),
matching `rgbToHsb`'s `h /= 6.0`. Every multiple of 5 makes `hp` an even
multiple of 30, so `x` collapses to 0 and the `else` branch returns pure red at
the loop's brightness/saturation. `h = 0` returns red too.

Found 2026-08-20 while writing T325's own sweep, which was copied from this one
and had the same bug before it was caught.

## Goals

- [x] The sweep iterates hue as a 0..1 turn, so it really is a hue circle
      (72 integer steps of 1/72, i.e. every 5 degrees).
- [x] It still passes - `cappedLuminance` holds the ceiling on all 72 hues x
      3 saturations, so no defect task was needed.
- [x] A grep for other `hsbToRgb` callers passing degrees comes back clean:
      `pale_red` was the one other suspect and is fixed (`.h = 5.0 / 360.0`,
      and its hue check now converts the 0..1 result to degrees, so the
      `< 15` comparison is no longer vacuous). `randomDark`, the round-trip
      test and both `desk_palette.zig` callers already pass 0..1.

## Validation criteria

- [x] `zig test src\apprt\win32\color_math.zig` green: All 25 tests passed.
- [x] The `none` and `win32` lanes green via `scripts\floor-lane.ps1 -Lane all`:
      `FLOOR SUMMARY: lib#1=PASS none#1=PASS win32#1=PASS agent#1=PASS`.
- [x] Asserted in the test itself: the sweep records which sixth of the hue
      circle each input lands in (`rgbToHsb(base).h`) and requires all six.
      Negative control: putting the degree feed back (`* 5.0`) fails exactly
      that assertion (`color_math.zig:937`, 24 passed / 1 failed), and the
      file was restored after (no BOM, diff limited to the two test edits).
