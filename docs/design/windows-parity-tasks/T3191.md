# T3191 - Single-window mode: a parked workspace has no window - Window.hwnd is null while parked and its pane HWNDs live under a hidden park host; the shared HWND is surrendered and adopted (controller, chrome, title, tab colour, desk, sidebar, fullscreen/maximize) by carrying out workspace_host.zig decisions

## Summary

Child of T3181 (split 2026-11-16; P0 by user directive via T3136). Spec docs/reference/window-modes.md; decisions come from src/apprt/win32/workspace_host.zig. Acceptance: a section of test/win32/single-window-mode.ps1.

## In plain terms

With "All in one window" chosen, opening a second window should not put a second window on screen: the new one waits behind the one you are looking at, and switching to it swaps what the one window shows. This lands that swap: the window stays the same window (no flash, no new taskbar button), and a terminal waiting behind it keeps running.

## Goals

- [x] App owns the workspace host and a hidden park host in single mode only
- [x] A workspace that starts parked has no window of its own; its panes are made under the park host
- [x] The hand-off: the one on show surrenders the window (panes out, chrome/sidebar/timers released) and the other adopts the SAME HWND (panes in, chrome rebuilt, fullscreen/placement/opacity state carried)
- [x] A programmatic open stays parked; `--focus` and a pane dragged out go on show
- [x] The shared window closing under parked workspaces: the most recent one loads a window of its own
- [x] A debug IPC seam (`workspaces`) to read the host and drive a hand-off until the sidebar switch (T3182)
