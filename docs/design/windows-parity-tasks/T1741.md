# T1741 - no on-box acceptance proves a cd in a dialed cmd.exe pane reaches +list --json and the saved layout (T1583 follow-up)

## Summary

T1583 made the agent push META{cwd} when a session's directory moves and the pane apply it unless the shell reports OSC 7. Unit tests cover each hop (agent push-on-change, connection routing, ring hand-off) but nothing on the box drives the whole path: a dialed pane whose shell has no integration, a real 'cd', then +list --json and session-layout.json naming the new directory within ~10 s. Build it on the loopback remote harness, with a negative control that turns the push off.

## In plain terms

When you work in a terminal on another machine and change folder, Ghoztty is
supposed to notice, so a new split or a reconnected window opens where you
are now. The pieces were tested one at a time; nothing had ever tried the
whole thing on a real machine. Now two scripts do: one watches the folder
change arrive, and one disconnects the machine and checks the fresh terminal
comes back in the folder you moved to.

## Goals

- [x] a real `cd` in a dialed pane with no shell integration reaches `+list --json`
- [x] a second `cd` is followed too
- [x] the restore half: the folder you moved to is where a Reconnect opens the fresh shell
- [x] a negative control that proves the main check can fail

## Scope change (decided while building it)

The Summary asked for `session-layout.json`. A cross-machine window is never
in that manifest: `captureSessionLayout` skips any window with `remote_dialed`
(`src/apprt/win32/App.zig`, the loop over `self.windows`). A dialed window's
recorded directory is used by the Reconnect swap instead, which captures that
one window through the same `captureWindow` and opens fresh shells from it.
So the restore half is arm C6/D2 of `test\win32\remote-reconnect-fresh.ps1`.

The negative control is the inverted assertion (`-NegativeControl`) plus the
A2 baseline, not a product switch that turns the push off. That would need a
test-only flag in the shipping agent, and A2 already shows the oracle can
read a stale value.
