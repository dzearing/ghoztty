# T2217 - Remote pane IPC reaches the local app: agent-hosted per-session proxy endpoint, app_ipc frames, scoped verb policy (Windows + shared)

## Summary

See docs/design/remote-viewer-tunnel.md (T1297 design). Decisions 2 and 4. Today a remote pane's GHOZTTY_IPC_SOCKET names a LOCAL pipe/socket, so ghoztty +verbs run there hit nothing or the remote box's own Ghoztty (misroute). Build: agent serves an owner-only per-session endpoint on the remote machine and rewrites GHOZTTY_IPC_SOCKET to it; capability app_ipc; app_request/app_response frames forwarded through mux/relay; win32 dispatcher seeds caller pane from the session binding and enforces origin scope (send-keys/read/close/list only on panes of that machine; split/new-window without --view create REMOTE panes). Fix stale comment pty_child.zig:1283 and cli.md remote-pane IPC line. Unit tests for negotiation + scope policy; acceptance via loopback agent.

## In plain terms

Typing a `ghoztty` command inside a pane that runs on another machine should
act on the window you are looking at, not silently fail or pop something open
on that other machine. This first slice defines the message the two sides will
exchange and the safety rule: a remote machine may show you things and manage
its own panes, but it can never type into, read, or start a shell on yours.
The plumbing that actually carries the messages lands in T3710 and T3711.

## Scope of this task (split 2026-11-25)

The original card bundled the wire, the agent's proxy endpoint, the env
rewrite, the app's dispatcher and the policy - several contexts of work. Split
per the context rule:

- **T2217 (this)**: `capability.app_ipc`, `APP_REQUEST` 0x80 / `APP_RESPONSE`
  0x81 and their payloads (`src/remote/protocol.zig`), and the shared
  remote-origin policy (`src/apprt/ipc/remote_origin.zig`). Nothing advertises
  `app_ipc` yet, so no peer behaves differently.
- **T3710**: the agent's per-session proxy endpoint and the
  `GHOZTTY_IPC_SOCKET` rewrite; the stale `pty_child.zig` comment.
- **T3711**: the win32 app serving forwarded requests under the policy; the
  `docs/claude/cli.md` line.
- **T3712** (`seat: linux`): GTK's half of T3711.

Policy decisions made here (mechanism calls, not experience forks):
`+new-remote-window` and the handoff-quit action are refused from a remote
origin (dialling a machine uses the local user's credentials); `+version` is
unscoped; `+list` is filtered; `+split`/`+new-window` create panes on the
remote machine; every other verb acts only on the origin's own panes, and an
out-of-scope target reads as not found so local pane names cannot be probed.

## Validation criteria

- [x] `app_ipc` negotiates on the intersection only; both frames ride control, are not client RPC replies, and round-trip through a frame with the IPC JSON intact - `protocol.zig` test "T2217 app_ipc ..." (`zig test src/remote/protocol.zig --test-filter T2217`, and the none lane)
- [x] every IPC verb has a remote scope (exhaustive switch; a new verb does not compile without one), decision 4's named verbs are origin-scoped, `+new-remote-window`/handoff-quit are refused - `remote_origin.zig` tests, none lane
- [x] a local target (no machine) or another machine's is never in scope; the caller pane is always the session's bound pane - `remote_origin.zig` tests, none lane
