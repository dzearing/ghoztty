# T2217 - Remote pane IPC reaches the local app: agent-hosted per-session proxy endpoint, app_ipc frames, scoped verb policy (Windows + shared)

## Summary

See docs/design/remote-viewer-tunnel.md (T1297 design). Decisions 2 and 4. Today a remote pane's GHOZTTY_IPC_SOCKET names a LOCAL pipe/socket, so ghoztty +verbs run there hit nothing or the remote box's own Ghoztty (misroute). Build: agent serves an owner-only per-session endpoint on the remote machine and rewrites GHOZTTY_IPC_SOCKET to it; capability app_ipc; app_request/app_response frames forwarded through mux/relay; win32 dispatcher seeds caller pane from the session binding and enforces origin scope (send-keys/read/close/list only on panes of that machine; split/new-window without --view create REMOTE panes). Fix stale comment pty_child.zig:1283 and cli.md remote-pane IPC line. Unit tests for negotiation + scope policy; acceptance via loopback agent.
