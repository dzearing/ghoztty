# T1955 - Turns take ~64 min where the code takes ~13: cut end-of-turn validation to ~15-20 min

## In plain terms

Most of each loop turn is spent re-running tests, not writing the fix.
T1936's code was done and passing in 13 minutes; the turn took 97. Make
the end-of-turn checks fast without making them weaker: re-run only what
failed, run independent work at the same time, refuse to test a stale
build, and stop running checks that never catch anything on every turn.

## Work, ranked by minutes saved

1. **Targeted harness-floor re-run.** A full green sweep, plus a green
   re-run of only the failed member after a fix, counts as passed. Today a
   one-line fix forces a full new sweep (`go.md:507-510`,
   `testing.md:929-934`, `harness-floor.ps1:154-162`). ~20 min on about
   half of turns. Low risk: the members stamp themselves.
2. **Scope the per-turn harness floor to what the turn touched.** Run the
   members that cover the edited scripts, plus everything when
   `test\win32\lib\**` changed. Run the full sweep once a day (the digest
   step) and on demand. Saves 12-20 min on about 80% of turns. Medium
   risk: the cross-suite audits (`test-reach`, `command-resolve`) rely on
   the daily sweep.
3. **Move `test-reach-audit` (215 s) and `command-resolve-audit` (196 s) to
   the daily sweep.** 0 failures in 41 runs. ~7 min per floor run.
4. **Run the four floor lanes in parallel**, each with its own
   `--cache-dir` / `--prefix` (the soak daemon's T401 isolation pattern).
   `go.md:491` forbids lanes beside acceptance, not lanes beside lanes.
   16-19 min becomes ~7-8. Watch for global-cache lock stalls.
5. **Run due acceptance tests about 4 at a time.** They already isolate
   pipes and agents (`Isolation.ps1`, `GHOZTTY_PIPE_SUFFIX`) on background
   desktops. Timing-sensitive tests declare `# @timing-sensitive` and run
   alone (shares the T1937 mutex idea). ~16 min becomes ~5.
6. **Build-fresh gate FIRST.** `build-fresh-guard.ps1` exists but runs
   inside the floor, after the GUI tests. Run it (and rebuild) before any
   test. This saves the 10-30 min stale-build re-run T1936 hit.
7. **Fail fast:** run the changed feature's own acceptance first and stop
   at the first red, before the lanes and the floor.
8. **`skip-visibility.ps1` fails 41 of 41 runs:** a permanent known red,
   27 s each, no signal. Fix it, or quarantine it with a task until fixed.
9. **Narrow the over-broad due globs.** Split the ~15 any-test-edit rows
   so a script edit triggers only the audits about that script's family.
   Review the 17 `Window.zig` rows for ones that cover a sub-area.

Target: typical validation ~50 min -> ~15-20 min (inferred from the
phase numbers). Nothing gets weaker: every check still runs at least
daily, and a red still blocks the close.

## Validation criteria

- [ ] Each rule change is written into go.md / testing.md where the old
      rule was, citing this task. No silent drift.
- [ ] Targeted re-run: a deliberately broken audit, fixed, then re-run
      alone, lets the close proceed. A different audit left red still
      blocks it (negative control).
- [ ] Parallel lanes produce the same verdicts as serial ones on the same
      tree (both run once, compared), and the wall time is recorded.
- [ ] A stale zig-out is refused before any acceptance script starts
      (scripted).
- [ ] The daily full sweep exists and is reported in the digest.
- [ ] Measured over the next 10 closed tasks: median claim -> close, and
      validation minutes per turn, against the table above.
