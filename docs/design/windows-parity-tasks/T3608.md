# T3608 - Linux L10e: pane sidebar group editing on GTK - the window-row menu and the project and Ungrouped headers' + / x / pencil

## Summary

Split from T3558. The GTK all-windows list (`pane_sidebar_all.zig`) groups `<project>: <worktree>` windows under project headers and an Ungrouped header, but offers none of the Mac's GROUP editing: a window row's right-click menu (Create Group..., Move to Group, Remove from Group; Mac `PaneSidebarView.windowMenu`, win32 `pane_sidebar_menu`), and a project or Ungrouped header's hover tools - + (a new window in that group), x (close every window under it, the matches while searching) and the Ungrouped header's pencil that names its windows into a group (win32 `pane_sidebar_add`, `pane_sidebar_rename`). A window or pane row's own + / x / pencil is T3606. docs/reference/pane-sidebar.md 'All windows', 'Adding from the sidebar', 'Closing from the sidebar'. Extend test/linux/cli-sidebar-all.sh through the pane-sidebar seam.

## In plain terms

On Linux, the sidebar's "all windows" list groups windows named like
`project: worktree`, but there was no way to put a window into a group or take
it out from the list itself. Now right-clicking a window offers Create
Group..., Move to Group and Remove from Group, and the "Ungrouped" header has a
pencil that names all the loose windows as one group - the same as on the Mac
and Windows.

## Goals

- [x] a window row's right-click menu: Create Group..., Move to Group (the other groups), Remove from Group (grouped only)
- [x] Move / Remove retitle the window `<group>: <name>` / back to `<name>`, pinned as the user's
- [x] Create Group... opens an in-place "Group name" field: Return names it, Escape or empty changes nothing, a bad name changes nothing
- [x] the field survives a redraw with what was typed
- [x] the Ungrouped header's pencil (first of its buttons) names every lone window as a group
- [x] seam + acceptance: `test/linux/cli-sidebar-groups.sh`
