# T1020 - nothing sweeps the harness for banker's-rounding DIP arithmetic, so T257's defect surfaced a fifth time in T314

## In plain terms

Nothing here is broken for a user. This is about the tests: several of them
work out "how many pixels is 4 points at this screen scale?" using a
PowerShell rounding rule that disagrees with the one the app uses. On the
common screen scales the two agree, so the mistake hides; on a 112.5% screen
they differ and the test measures the wrong pixel. It has been found and fixed
by hand four times now, each time in whichever script somebody happened to be
reading. This makes the machine look for it instead.

## Summary

`test/win32/lib/ChromeGeometry.ps1`'s `Get-TestChromeDip` is the one correct
DIP conversion — `[Math]::Round($dip * $scale, [MidpointRounding]::AwayFromZero)`,
matching the layout modules' `px()` (`@intFromFloat(@round(...))`). PowerShell's
bare `[Math]::Round()` is BANKER'S rounding, which agrees at 100/125/150/200%
and diverges at 112.5%.

The history is the argument for a sweep:

- **T257** found it in `tab-strip.ps1` and `tab-color.ps1`, hoisted the helper,
  and swept "the four scripts that measured the tab strip".
- **T314** found the identical private helper still live in
  `ipc-machine-chooser.ps1`, which was never in that sweep because it measures
  its own dialog through its own helper.

Four hand sweeps have not closed it, and the reason is structural: the sweeps
were scoped to a *subject* (the tab strip, the chooser) while the defect is
scoped to an *idiom*. The harness already has the right shape for this —
`printclient-audit.ps1`, `verdict-exit-audit.ps1`, `stderr-capture-audit.ps1`
and `isolation-meta.ps1` each enumerate EVERY script in `test/win32/` for one
defect class and fail on the ones that have it.

## What to build

A `test\win32\dip-rounding-audit.ps1` in that family:

1. Enumerate every `.ps1` under `test/win32/` (including `lib/`).
2. Flag any `[Math]::Round(` / `[math]::Round(` call whose argument list
   multiplies by something scale-shaped (`$scale`, `$dpi`, `/ 96`) and that
   does NOT pass `MidpointRounding` — i.e. the exact `Dip` shape T257 and T314
   each found by eye.
3. Flag any function named `Dip`-alike that shadows `Get-TestChromeDip`.
4. Allow-list the sites that are legitimately not DIP conversions, each with a
   reason in the script, the way the sibling audits do.
5. Add a `guard-due.ps1` row so an edit to `ChromeGeometry.ps1` or to any
   script re-runs it.

Known already-correct private copies at filing time (`key-state-pill.ps1`,
`readonly-badge.ps1`, `hero-mode.ps1`, `split-divider.ps1`) pass the rounding
rule but still restate the conversion; the audit should report them as a
second, non-failing class ("correct but private") so a future hoist has a list.

## The half an audit cannot catch

T314's other finding does not reduce to a grep and should be written up in the
audit's header as the rule it CANNOT enforce: **a script must not re-derive a
number the module composes.** `chooser_rows.rowMetrics` builds `text_x` as a
sum of six individually-rounded terms, so rounding the 68 DIP total is wrong at
112.5% at ANY rounding mode (79 composed vs 77 half-away vs 76 banker's). The
fix there was to compose the same terms in the script. Same rule T235 and T257
keep arriving at from different directions.

## Outcome (2026-10-14)

The re-check found the defect had spread well past the four scripts named at
filing: 54 sites across 33 scripts (`bare-round` and the `[int]`-cast form,
which rounds half-to-even too). Fixing them inline would have re-dued ~30 GUI
harness guards in one turn, so they are a per-file **ratchet**
(`test\win32\dip-rounding-audit.baseline.json`, the unroll-count-audit
pattern) and **T1931** works them down. New sites, and a second
`Get-TestChromeDip`, fail now.

Also measured (audit section B): the filing premise that the two roundings
agree at 125% and 150% is not general - 18 DIP at 125% is 22 vs 23, and any
odd DIP at 150% diverges. ChromeGeometry's header repeats the claim; T1931
corrects it.

Built: `test\win32\lib\DipRoundingAudit.ps1` (AST analyzer),
`test\win32\dip-rounding-audit.ps1` (34 assertions: fixtures, negative
control, ratchet, scope, teeth), guard row `dip-rounding`, harness-floor
member, docs in `test\win32\README.md` and `docs/claude/testing.md`.
