# T2479 - Mac: under a divider drag the growing pane holds its grid too and reflows once at a rest or release (core Surface.holdResize, T2459), if D105 keeps the Windows choice

## Summary

T2459 (Windows) holds every terminal's GRID under a divider or grip drag and
the glide it starts: resizes stay pending in termio (`Termio.resize_held`, set
through the shared-core `Surface.holdResize(on)`), and releasing flushes the
latest size once - at the drag's end, the glide's end, or a 150 ms rest of the
hand mid-drag. Measured: a 40-move drag is 80 resizes and 2 applied.

Mac's `PaneStageView` already freezes a SHRINKING card's content
(`glideFreeze` = max(start size, target)), but a GROWING card's content follows
the target, so it reflows on every step. D105 asks the user whether the growing
side should wait too. If D105 keeps the Windows choice (recommended), make Mac
match: call `surface.holdResize(true)` for every terminal on show while
`PaneStackState.isGesturing` or a resize glide runs, release it after the
settle and after a 150 ms rest, and drop the max-with-target growth from
`glideFreeze` (or keep the frame and let the grid hold). If D105 picks "fill as
you drag", this task is skipped and Windows changes instead.

## Validation criteria

- [ ] A divider drag over a prompt is applied once per pane (Mac analog of test/win32/prompt-reflow.ps1's Score-Held / resize-debounce.ps1 B2), and `aFastPullKeepsTheGlideOnTheHand` is updated to the agreed growing-side rule.
