# T1520 - Harnesses read a job's log file while the job appends to it, so a collision scores a real hit as a missing one

## Summary

T1517 found this scoring a phantom product defect: relay-account.ps1 read the fake relay's hit log with Get-Content while the background job's Add-Content held it, the read threw 'the file is being used by another process', ErrorActionPreference=Continue turned that into an empty string, and the assertion reported 'FAIL signing back in RE-ENROLLED this machine (T1425)' over traffic that WAS in the log. That file is fixed on both sides (the writer retries, the reader opens with FileShare::ReadWrite and retries), but the shape is not unique to it: every harness whose oracle reads a file a background job writes has the same race, including lib\FakeRelay.ps1's Get-FakeRelayLog (plain Get-Content) and its six callers. The failure is worse than a hang because it is PLAUSIBLE - it names a real product behavior and sends the next turn looking for a bug that is not there. Sweep the suite for reads of a job-written log and route them through one shared helper that shares the write handle and retries; consider making it an audit rule the way job-teardown.ps1 section D is, so a new fixture cannot reintroduce it.

## In plain terms

Many of our automated tests run a small fake server in the background that writes down every request it gets, and the test then reads that list to check the app made the right call. The two sides were fighting over the file: when they touched it at the same instant, the test saw an empty list (or the server lost the line), and the test reported a believable but false product bug. After this, the background writer and the test reader share the file safely, and a new test cannot reintroduce the fight without its own check going red.

## Goals

- [x] measure the race rather than assume it (which side collides, how often)
- [x] one shared, share-tolerant reader that fails loudly instead of returning an empty log
- [x] every background-job writer in the suite appends in the non-locking way
- [x] an audit that turns red if a new job body appends with `Add-Content`

## Root cause (measured 2026-11-19)

The WRITER is the load-bearing half. In a 4 s race (a job appending every ~15 ms,
the harness reading in a loop) the `Add-Content` writer made 2,538 of 2,620
`Get-Content` reads fail (97%) and dropped 240 of its own lines; in
job-teardown.ps1 section G it dropped 141-150 lines even against the
share-tolerant reader, because `Add-Content` refuses to open while anyone reads.
`[IO.File]::AppendAllText` (append, FileShare.Read, close at once) failed 0 of
2,370 reads and dropped 0 lines, with plain `Get-Content` readers unchanged.

## Fix

- `test\win32\lib\SharedLog.ps1`: `Read-SharedLog` opens ReadWrite|Delete shared,
  retries for 2 s, emits lines like `Get-Content` (or `-Raw`), and THROWS a
  "harness error, not a product result" when it truly cannot read - an empty
  log is what scored the phantom FAIL.
- All 15 job-side appends (FakeRelay, FakeAgentRelay, PipeBridge, and 11
  harnesses' own fake servers) now use `[IO.File]::AppendAllText`.
- `Get-FakeRelayLog`, `Get-FakeAgentRelayLog` and relay-account.ps1's `Get-Hits`
  read through `Read-SharedLog`.
- job-teardown.ps1 section G runs the race live (Add-Content collides;
  AppendAllText + Read-SharedLog loses no read and no line; the throw path is
  bounded); section H sweeps every `Start-Job` body in test\win32 for
  `Add-Content` / `Out-File -Append`, with `-TeethCheck` planting violators.

## Validation criteria

- [x] the race reproduces with the old writer and is gone with the new one - job-teardown.ps1 section G, green (add-content arm: 8-10 read failures + 141-150 dropped lines; AppendAllText arm: 0 / 0, 154 of 154 lines read back)
- [x] Read-SharedLog: missing file is empty, an unreadable file throws in bounded time (319 ms) - section G
- [x] the sweep finds every pre-fix site and none now - analyzer run over `git show HEAD:` text found 15 sites in 14 files; working tree 0; section H green
- [x] the sweep can go red - `job-teardown.ps1 -TeethCheck` ALL PASS (H flags planted Add-Content and Out-File -Append, ignores AppendAllText, comments, and Add-Content outside a job)
