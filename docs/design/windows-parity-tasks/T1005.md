# T1005 - The floor wrapper's own contract is proven by a harness nothing obliges anyone to run

## Summary

scripts\floor-lane.ps1 is deliberately outside every guard-due row (the comments in scripts\guard-due.ps1 argue that stall-detector and lane-table edits would make the crash/heal/leak rows noisy). T982 was a defect IN that file - the wrapper aborting mid-run on its own sample - and nothing obliged a re-run of test\win32\floor-lane-leak-sweep.ps1, whose wiring arms would have caught it. Decide the tradeoff deliberately: either add scripts\floor-lane.ps1 to the lane-leak-sweep row and accept re-running a ~2 minute harness on every wrapper edit, or give the wrapper its own thin row over just the contract arms (15, 16 and the wiring block). Today it is neither, which is the only option nobody chose.

## In plain terms

Before every commit, a script runs the whole test suite and watches it. That
watcher has its own self-test, but nothing ever required anyone to re-run the
self-test after changing the watcher - which is how a bug that crashed the
watcher mid-run (T982) could have slipped past. Now changing the watcher marks
its self-test as owed, and the commit gate refuses to go through until it has
been run green again.

## Goals

- [x] decide the tradeoff deliberately (full row vs a thin arm-subset row)
- [x] an edit to scripts\floor-lane.ps1 makes the leak-sweep harness due
- [x] the harness runs green over the code as it stands and re-stamps

## Decision

Option A: `scripts\floor-lane.ps1` joins the `lane-leak-sweep` row's Covers.
Why not a thin row over arms 10/15/16: the "noise" argument that kept the file
out had already been conceded - the `lane-stall-sampling`, `lane-releasesafe`
and `build-cache` rows all cover the wrapper today, so every wrapper edit
already obliges three re-runs. The whole leak-sweep harness measured 46s on the
box (not the ~2 min feared at filing), and a subset row would need an arm
filter plus a second stamp for the same script, stamping a weaker proof under a
second name. The row comment in `scripts\guard-due.ps1` records this, and the
build-cache row's note that cited T1005 as keeping the file out is corrected.
