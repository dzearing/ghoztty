# T1676 - The command palette lists Install Available Update even when no update is available

## Summary

Found while landing T1673. `install_update` is a real command in
`src/apprt/win32/commands.zig` so that the menu row and any future surface
dispatch through one path - which is the house rule (T189) and right. The side
effect is that the command palette lists "Install Available Update"
unconditionally, including on the overwhelmingly common day when there is no
update to install.

Picking it then is not harmful: `Surface.performCommand` falls through to a
manual check, which is a reasonable answer to "install the update" when the app
is not holding one. It is still a row that is a lie 364 days a year, and the
palette's value is that everything in it is something you can do.

Fix direction: the palette needs a notion of a row that is conditionally
present (or conditionally greyed), which it does not have today - every
registry entry is listed. Check how Mac's `TerminalCommandPalette` handles a
command whose target does not exist before inventing a mechanism; the menu's
own answer (`menu_bar.flags`) greys rather than hides, and "grey it when
nothing is pending" may be the cheaper and more Windows-native shape.

## In plain terms

Open the command palette and you will see "Install Available Update" listed
even when your Ghoztty is perfectly up to date. Choosing it just runs an update
check, so nothing bad happens - but the palette should only offer you things
you can actually do.

## Goals

- [x] the palette does not offer installing an update that does not exist
- [x] whatever mechanism that needs is general, not a special case for this one row (`Command.when` + `commands.available`)

## Validation criteria

- [x] with no offer pending, the palette's update row is absent or greyed - observed, not asserted (palette-order.ps1 O8a: filter + Enter runs nothing, no confirmation)
- [x] with an offer pending, it is there and it installs (O8b: same keystrokes run install_update and reach the GhozttyConfirmDialog install confirmation)
- [x] `test\win32\menu-bar.ps1` and the palette harness stay ALL PASS (palette-order ALL PASS 44; menu-bar ALL PASS 81; floor lanes lib/none/win32/agent all PASS)

## Resolution

Hidden, not greyed - Mac's `updateOptions` returns nothing unless
`updateViewModel.state.isInstallable`, and a palette is a search over what you
can do. Every registry `Command` now carries `when: Condition` (`always` by
default, `update_pending` for `install_update`); the pure
`commands.available(cmd, State)` decides, and `Surface.filterPaletteEntries`
feeds it `App.pendingUpdate() != null` - the same state the menu's
`Install Update <ver>` row and the update dot key on, so the three surfaces
cannot disagree. Unit tests in `commands.zig` pin the row's condition and that
no other command carries one. Presentation differences from Mac (title, badge,
emphasis, Cancel or Skip Update) filed as T1754.

Negative control: with the `available` check replaced by `_ = state;`, O8a
FAILS (`got: install_update`), so the arm can go red; O8b is O8a's positive
control - the same keystrokes, with an offer seeded on disk.
