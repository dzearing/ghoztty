# T1676 - The command palette lists Install Available Update even when no update is available

## Summary

Found while landing T1673. `install_update` is a real command in
`src/apprt/win32/commands.zig` so that the menu row and any future surface
dispatch through one path - which is the house rule (T189) and right. The side
effect is that the command palette lists "Install Available Update"
unconditionally, including on the overwhelmingly common day when there is no
update to install.

Picking it then is not harmful: `Surface.performCommand` falls through to a
manual check, which is a reasonable answer to "install the update" when the app
is not holding one. It is still a row that is a lie 364 days a year, and the
palette's value is that everything in it is something you can do.

Fix direction: the palette needs a notion of a row that is conditionally
present (or conditionally greyed), which it does not have today - every
registry entry is listed. Check how Mac's `TerminalCommandPalette` handles a
command whose target does not exist before inventing a mechanism; the menu's
own answer (`menu_bar.flags`) greys rather than hides, and "grey it when
nothing is pending" may be the cheaper and more Windows-native shape.

## In plain terms

Open the command palette and you will see "Install Available Update" listed
even when your Ghoztty is perfectly up to date. Choosing it just runs an update
check, so nothing bad happens - but the palette should only offer you things
you can actually do.

## Goals

- [ ] the palette does not offer installing an update that does not exist
- [ ] whatever mechanism that needs is general, not a special case for this one row

## Validation criteria

- [ ] with no offer pending, the palette's update row is absent or greyed - observed, not asserted
- [ ] with an offer pending, it is there and it installs
- [ ] `test\win32\menu-bar.ps1` and the palette harness stay ALL PASS
