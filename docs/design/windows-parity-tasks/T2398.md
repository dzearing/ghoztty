# T2398 - Frame lab live scene for the window-moving cells (T2397 follow-up): caption-dblclick, aero-snap and maximize-button move the whole window (window-left/top edges, a maximized or snapped window with no backdrop beyond it and no border, so the still-frame offsets change); New-FrameLabCellSceneSpec marked them Unsupported (cell reads incomplete) until this landed. The pane-top/pane-set half is T2727

## Summary

Filed from T2397 (2026-10-28). `New-FrameLabCellSceneSpec`
(`test\win32\lib\FrameLabLiveScene.ps1`) builds the live scene for the drags
whose moving edges are window-right/bottom, a divider or the sidebar edge
(frame-right, frame-bottom, frame-corner, divider, sidebar-edge, blade-glide).
Every other catalogued interaction gets `Unsupported` and its cell reads
`incomplete`:

- **caption-dblclick, aero-snap, maximize-button** move the window as a whole.
  The scene needs window-left/window-top edges too, and the maximized/snapped
  states break two assumptions: there is no backdrop beyond a window that fills
  the work area (the scan finds no edge: LOC on every maximized frame), and a
  maximized window has no border, so the still-frame offsets are off by the
  border width (false B2). Likely shape: per-state calibration (restored and
  maximized/snapped still frames), with the state on each frame decided from
  the window's located edges.
- **banner** tracks `pane-top` (a horizontal edge that is not a divider);
  **hero, tab-switch, split-close** change the pane set mid-run. **Split out
  to T2727** on 2026-11-05: this task is the three window-moving cells.

Proof the same way T2397's was: synthetic frames from geometry in
`test\win32\frame-lab-live-scene.ps1`, then the live run.

## In plain terms

The frame lab films every frame a window shows during an interaction and
judges each one. Until now it could only judge drags that stretch the window
from its right or bottom edge; anything that moves or maximizes the whole
window - double-clicking the title bar, snapping it to the side of the screen,
the maximize button - could not be judged at all. Now it can follow the window
wherever it goes, including when it fills the screen and loses its border.
Nothing changes for a user; it is what lets the lab grade those three
interactions in its live run.

## Goals

- [x] The window's left and top edges are tracked too, and a window that fills the screen still has edges
- [x] Dividers and the sidebar edge are followed after the window moves and resizes
- [x] A maximized window is judged against a second starting picture of it maximized, not the restored one
- [x] A maximizing run that never maximized is a miss, never a clean pass
- [ ] The live run on the real app - with T2395, which launches it (user-started)

## What landed

- `test\win32\lib\FrameLabScene.ps1` (the C# scorer):
  - `window-left` / `window-top` edge kinds; `GfsEdge.Open` - a backdrop edge on
    the work area's boundary, where a line that starts on the window locates
    the edge AT the boundary instead of not at all.
  - Carried scans: `CarryX`/`CarryY` (near edge) and `CarryX2`/`CarryY2` (far
    edge) map an edge's scan range and lines through the window's movement -
    affine over left..right / top..bottom when both are known, so a scan that
    began inside a pane of a ratio split is still inside it after a maximize
    or snap. `GfsMap`; `StillPos` (the still frame's positions) is the origin.
  - `IsMaximized` (every Open edge on its boundary; a snapped window keeps a
    side with backdrop, so it is not), `GfsRecord.Maximized`, per-card
    `OffsetMax`, and `CalibrateMaximized(still)`: the window must read
    maximized, the cell size and padding must equal the restored ones, and the
    still must score clean. A maximized frame with no such calibration fails
    as `LOC` saying why. Card measurement factored into `MeasureCard`/`SetOffsets`.
- `test\win32\lib\FrameLabLiveScene.ps1`: the three interactions are
  supported; a window-moving spec has all four window edges (Open), every
  divider/sidebar edge carried, every card side touching no divider riding its
  window edge, `Moving`/`Maximizes` on the spec; backdrop on every side at the
  start is required (Unsupported otherwise). `New-FrameLabCellScene
  -MaximizedStill`, refused without one for a maximizing cell.
  `Get-FrameLabSceneScore -ExpectMaximized` and `MaximizedFrames`.
- `test\win32\lib\FrameLabDriver.ps1`: a maximizing cell's scene hook
  maximizes the window (`GflWin.Maximize`), takes `still-max.png`, restores,
  then takes the restored still; Score passes `-ExpectMaximized`.
- `test\win32\frame-lab-live-scene.ps1` section G (10 assertions; 38 total).

Assumptions recorded (the live run is what checks them): a Win11 snapped
window keeps its 1 px border (only "maximized" drops it); the DWM
maximize/restore animation frames, if the capture sees them, will read as
bleed frames - that is what the lab reports, not something the scene hides.
