# T2240 - drag-perf.ps1 prints the 2-pane row twice and never measures 4 panes

## Summary

Every shape in drag-perf.ps1 (serial, fanout, batched) prints two identical panes=2 rows and no panes=4 row, while assertion A still reports 3/3 summaries - so the 4-pane drag is either measuring the 2-pane layout again or the harness is returning the previous sample. Seen on 2026-10-24 in two runs in a row (T1350). Find out which, and make A fail when two pane counts return the same sample.

## In plain terms

The test that measures how smooth it is to drag a split divider was meant to
time it with 2, 4 and 8 panes open. It was quietly timing the 2-pane case
twice and calling the 4-pane result measured. The cause was fixed by T1854.
This task adds the check that would have caught it, so the test fails if a
row is ever filled with another layout's numbers again.
