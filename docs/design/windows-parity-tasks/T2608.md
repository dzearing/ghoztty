# T2608 - Divider drag rate on the INPUT desktop, 1.51.5 vs 1.51.6 (user 2026-11-01 said pane resize is slow too): the background-desktop bench (drag-perf.ps1) measured 15.5 ms per move on both builds, but it has no compositor pacing; measure moves/s and frame waits with DWM composing (ghost window, as resize-sync-onscreen.ps1 does) before ruling the divider half of T2603 out

## In plain terms

The user said dragging the line between two panes felt slow too. Our earlier
test measured it on a hidden desktop that never draws to the screen, so it
could have missed a slowdown that only shows up when Windows is actually
putting frames on the monitor. This measures the same drag on the real
screen (in a hidden-behind-everything window that never takes focus) for the
build before the slowdown report and for today's build.

## Goals

- [x] An on-screen divider-drag meter that runs without disturbing the person at the desk
- [x] Numbers for win-v1.51.5 and the current build, on screen and on the hidden desktop
- [x] A verdict on whether the divider half of T2603 is real

## Summary

VERDICT: the divider half of T2603 is ruled out on screen. (1) The input
desktop costs the same as the background bench, within 0.3 ms a move on
every row: the frame wait never includes a vblank on either desktop, so
drag-perf.ps1 was not blind to compositor pacing here. (2) Today's build
drags faster than 1.51.5 - 30% more moves a second at 2 panes, 13% at 4 -
because T2623's held grid took the per-move frame wait to zero (waits=0 vs
one wait per move on 1.51.5).

1.51.6 itself was not built: T2603 measured it equal to 1.51.5 on the
divider (15.5 ms both, background), and what the user receives next is HEAD,
which is measured above. Still not measured: a REAL pointer (coalesced
WM_MOUSEMOVE at the mouse's rate). Posted moves are not coalesced and paint
waits behind them, so this is the per-move cost, not the felt frame rate; a
real-input drag needs the user away and the cursor, and is not this task.

The meter: `scripts\divider-drag-onscreen.ps1` runs each build as a
`GHOZTTY_DEBUG_GHOST=bottom` window (opaque, bottom of the z-order, never
activates) on the input desktop and on a background test desktop, drags the
ROOT divider (found as the one boundary every pane sits wholly on one side
of) with POSTED mouse messages, reads the app's `divider drag ...` line
(GHOZTTY_PERF), and times the drag from outside by polling the left pane's
edge until it reaches the drag's end. It asserts the ghost never took the
foreground and SKIPS the input rows when a fullscreen app is up. A build from
another worktree is copied under `zig-out-v1515\` (gitignored) because the
kill helper only touches builds under this repo.

## Validation criteria

- [x] On-screen numbers for both builds - `scripts\divider-drag-onscreen.ps1`, ALL PASS (22), results in %TEMP%\ghoztty-divider-onscreen\20261101-210333 (table above)
