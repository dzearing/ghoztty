# T2461 - Blades: the carried fold's face is a fresh full-card DIB plus a per-pixel band fill and blend every frame - measure it on a 4K window and keep every frame of the fold under 16.7 ms (T2457 perf)

## Summary

T2457's carried fold paints the whole visible card into the strip face each frame: StripFace.begin creates a new DIBSection per frame, fillGlass maps every pixel through the glass LUT, blendContent blends every pixel, makeOpaque walks it again, then keep() copies it. At 4K the first frames of a fold cover a ~2000x2000 card. Measure (drag-perf style frame timing) on a release build at 4K; if over budget, keep one DIB across the glide, fuse fill+blend+opaque into one pass, and skip the band where content alpha is 255.

## In plain terms

When a pane folds into its blade, every frame of that animation repaints a
picture of the whole pane. On a 4K screen that picture is about four million
pixels, and the old code rebuilt it from scratch each frame, which took up to
14 ms of the 16.7 ms a smooth frame has. The fold now paints that picture in
about a third of the time, so the motion has room to stay smooth on big
screens.

## Goals

- [x] Measure the face's per-frame cost at 4K on an optimized build
- [x] One bitmap per glide instead of a new one every frame, and no per-frame copy for screenshots
- [x] Skip painting the band where the pane's picture covers it completely
- [x] Opaque and blend in one pass, eight pixels at a time; the band lookup reuses its last answer along the desk's flat runs
- [x] The face's cost is reported on the `GHOZTTY_PERF` glide line and held to one frame by `drag-glide.ps1` E, at any window size

## Validation criteria

- [x] The face pipeline at a 4K card (1900x2100, 60-frame fold, glass band) on ReleaseFast: worst 14.4 ms / avg 7.1 ms before, worst 4.4 ms / avg 2.2 ms after on an adversarial noise desk, worst 3.0 ms / avg 1.6 ms on a gradient desk like the real one (scratch micro-bench, `zig run -OReleaseFast` against `strip_face.zig`; numbers in the progress log)
- [x] In-app, debug build: `drag-glide.ps1` E green at 1600x900 (104 face paints, max 2.9 ms) and at `-Width 3800 -Height 2100 -TravelPx 2600 -StepPx 24` (137 paints, 4 of 5 panes folded, mean 4.2 ms, max 7.8 ms)
- [x] The face still looks the same: `stack-fold-slide.ps1` ALL PASS flat (45) and `-PaneStyle elevated` (41, the glass band path)
- [x] Pure: `finish` blends pinned, bottom-up, clipped content and makes the rest opaque without touching past the frame's width; the packed 8-wide blend rounds exactly like `(x + 127) / 255` for every alpha (sampled channels, lane leaks would show); `fillSolid`/`fillGlass` honour the stride and the hole, and the band clamps only off the desk's edges - none lane
- [ ] Whole-frame budget at 4K on a RELEASE build - T2462 (the debug build's whole glide tick at 4K is 28 ms mean / 67 ms max, faces ~15% of it)
