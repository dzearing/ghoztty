# T2323 - Windows pane sidebar gets the Mac's three + buttons: new window from the header, new window in a project group, and a window row's + that splits its focused pane the way you last split by hand

## Summary

Mac 44aa923f0 (main intake 2026-10-26): header + (expanded panel, left of All windows) = Ctrl+Shift+N from this window's focused pane (inherited cwd, random gradient, remote parent's machine); project header + = same from the group's first listed window, titled '<project>: new' or first free 'new-N'; window row + raises the window and splits its focused pane in the last MANUAL split direction (PaneSplitMemory, app-wide, default right, not persisted; keybinds/menu/palette/context-menu splits set it, ghoztty +split never does). All three are manual surfaces that take focus; a click never starts a row drag. Mac ref: docs/reference/pane-sidebar.md 'Adding from the sidebar', macos/Sources/Features/PaneSidebar/PaneSidebarAdd.swift, tests macos/Tests/PaneSidebar/PaneSidebarAddTests.swift.

## In plain terms

On Mac the pane sidebar has + buttons: one in its header that opens a new
window, one on each project heading that opens a new window inside that
project, and one on each window heading that adds a pane to that window the
same way you last split one yourself. Windows had only the close buttons.
After this, the Windows sidebar has all three, in the same places, doing the
same things.
