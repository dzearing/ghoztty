# T3007 - PA-M07: every pane's config_change re-runs the whole app-level reload (deep config clone, every window's chrome, global hotkeys, Settings), 11x the work at 10 panes (win32 App.zig:9202)

## Summary

PA-M07 (audit-1, T2961). The core delivers config_change per surface (src/App.zig:139-141 -> src/Surface.zig:2598-2603) and then once for .app; the win32 handler (src/apprt/win32/App.zig:9202-9258) never reads target, so each delivery clones the config, deinits the old one, recreates the brush, calls onConfigChange on every window, refreshes ShortcutGuide and Settings, and unregisters/re-registers global hotkeys. A surface-scoped soft reload also overwrites App.config with that surface's conditional-state variant. Fix: do app-level work only for target == .app; surface targets get surface-local work at most. Risk low: the .app action always comes last. Baseline: docs/design/perf-audit/baseline-1.json (T2958); findings: docs/design/perf-audit/audit-1/M-findings.md.

- [ ] config reload acceptance (theme/background change reaches every window's chrome) green
