# T3821 - Linux: the app intermittently segfaults inside Mesa d3d12 (libgallium) while destroying GL programs during its SIGTERM quit

## Summary

Found by T3677: about one cli-remote-disconnect.sh run in three ends with the GTK app aborting at teardown - received SIGTERM, quitNow -> window.destroy -> surface unrealize -> opengl program destroyed ... -> Segmentation fault at address 0x8 in libgallium-25.2.8 (WSLg Mesa d3d12; unwind info unavailable). The test verdict is unaffected (hl_stop runs after hl_finish) and hl_stop now prints the log tail of a process that died of a signal (T3677). Same driver and teardown path as T3656 (quit hang, 8s _exit backstop) and T3796 (window-close hang). Check: does it reproduce with LIBGL_ALWAYS_SOFTWARE=1 (llvmpipe)? If not, it is the d3d12 driver; find what GL object outlives its context at unrealize (the renderer thread still holding a texture/program after Destroying EGL context?) and release it in order, or skip GL teardown on quit since the process is exiting. Also check a real-screen quit (WSLg) does not crash the same way.
