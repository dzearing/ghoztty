# T2602 - Begin the terminal's draw at a new size as soon as its grid size is known, not at the end of the window-resize pane batch (the composition swap chain does not need the HWND at its new size)

## Summary

T2598 lever (3), not attempted there. During a window-edge drag the
terminal's draw at a new size cannot begin until the UI thread's pane batch
(`batch-begin` -> `batch-end` on the resize trace) ends, ~6.7 ms after the
frame change on the T2577 trace. On the composition path (T2466) the frame
goes into a swap chain's shared texture, and since T2598 step 1 that swap
chain takes a new size as a source rectangle, so nothing about the draw needs
the pane HWND to have its new size yet. Hand the renderer the new grid/pixel
size when the layout computes it, so the draw overlaps the rest of the batch.

Why it waits on T2580: T2598 step 1's film showed the terminal already
reaching the new width before the viewer page on grow drags (extra `gap=`
frames, `right=` unchanged). Making the terminal earlier still only widens
that disagreement until the page keeps up, so measure this after T2580.

## In plain terms

When you drag a window edge, the terminal waits for the whole window layout
to finish before it starts drawing at the new size. This lets it start as
soon as it knows its own new size, so it keeps up with the window outline.
