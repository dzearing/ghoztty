# T1712 - The go-loop's composer probe reads Claude Code's greyed prompt suggestion ('keep going') as text somebody typed and never sent

## Summary

Found while fixing T1711. The watchdog's `composer=pending` has carried the text `'keep going'` on every idle-session stall since at least 2026-09-07, and loop-session.ps1 still says the "source of the text is still unidentified - it matches no script, no nudge, and no transcript". The likeliest source is Claude Code's own **prompt suggestion**: `~/.claude.json` has `tengu_prompt_suggestion: true`, and the TUI renders a greyed suggested next prompt in an idle composer. `ghoztty +read` returns plain text with no SGR, so `Get-PaneComposerText` cannot tell dim suggestion text from typed text, and `ComposerPlaceholders` only knows `Try`/`Ask`/`Type`/`for shortcuts`/`?`.

Why it matters even after T1711: the stall LINE blames "unsent text" for what is really a plain idle session, which sent three incident write-ups after a phantom typist. The verdict is right for the wrong reason, and the composer arm (45m, `session=unknown`) can fire on text nobody typed.

Fix direction: first confirm it by reading an idle Claude pane with styling (a `+read` mode that keeps SGR, or compare against a pane with suggestions off). Then classify dim composer text as a placeholder, or have the probe report `composer=suggestion` separately so the log stops saying 'unsent'.

## Validation criteria

- [ ] Evidence either way on whether the 'keep going' text is Claude Code's prompt suggestion (styled read of an idle pane).
- [ ] If yes: the composer probe no longer reports a suggestion as pending text, with a go-loop-guard case built from the real pane shape.
- [ ] The 'source still unidentified' comments in loop-session.ps1 and go-loop-guard.ps1 say what the source is.
