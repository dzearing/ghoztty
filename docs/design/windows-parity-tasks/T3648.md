# T3648 - Linux L11k1: single-window mode foundation on GTK - one shared toplevel; each workspace keeps its own Window and only its content moves in on show and out when parked

## Summary

Mechanism (decided in T3573): in single mode the physical toplevel is one GTK window; every workspace keeps its own Window object (title, tabs, split trees, sidebar, config) and its template content (the TabOverview subtree) is moved into the shared toplevel on show and held off-window, ref'd, while parked. Every widget->window lookup (about 24 getAncestor/getRoot sites) goes through one owner-of helper that maps a widget to the workspace it is in, parked or not (Mac BaseTerminalController.owner(of:)); the workspace's 'win' action group is inserted on its content root so accelerators and menus reach the right workspace. Membership and decisions come from win32's pure workspace_host.zig Host(*Window) (startsParked/admit/show/close). Parked content is unmapped, so window_seen/Surface.syncSeen already stops its terminals drawing (parked counts as hidden). A debug seam reports active/parked/order. win32 counterparts: T3181, T3191, T3192. Spec: docs/reference/window-modes.md (The rule, The hand-off, Parked counts as hidden).

## In plain terms

With "All in one window" chosen, Linux Ghoztty now really keeps one window:
opening another window adds a hidden workspace to it instead of a second
window, and switching hands the one window over to that workspace without
rebuilding anything or touching its programs. The buttons to switch from the
sidebar come in the next card; this one builds the machinery under them.

## Goals

- [x] one shared toplevel: only the first workspace's GtkWindow ever maps
- [x] a parked workspace's content is out of every window, held whole, unseen
- [x] the hand-off moves content in and out with no rebuild and no process touched
- [x] every widget-to-window lookup answers the workspace a widget is in (owner-of)
- [x] the workspace's `win` actions sit on its content root
- [x] closes never take another workspace's content down (the close experience is T3652)
- [x] a debug seam reports active/parked/order and can switch

## Design (as built)

- `src/apprt/gtk/Workspaces.zig` (new) is the GTK half; membership and every
  decision are win32's pure `workspace_host.zig` `Host(*Window)`, unchanged.
- The toplevel is the GtkWindow of the workspace that loaded it. Each
  workspace's content is its template root (`Adw.TabOverview`): set as the
  toplevel's content on show, held by its own reference while parked
  (`Window.holdContent` / `releaseContentInto`).
- Owner-of: the content root carries qdata naming its `Window`
  (`Window.workspace_qdata_key`), and `ext.getAncestor` reads it before the
  widget tree for any type that declares the key - so all ~45 existing
  `getAncestor(Window, ...)` call sites became owner-of lookups at once, with
  no change of answer in separate mode.
- Seen: `Window.syncSeen` reads the toplevel's map/state for the workspace on
  show and `false` for a parked one; the toplevel's map/state changes re-sync
  the workspace on show.
- Titles: the workspace on show titles the toplevel; the toplevel's own
  workspace, parked, keeps its title held.
- Leaving: the content root's `win` group references its Window (a cycle
  through its own content) and GTK clears a destroyed window's `application`
  without a notify, so a workspace leaves the host on the application's
  `window-removed` (`Window.leaveWorkspace`), also called from dispose.
- Seam: debug-only `workspaces [--show=<pane|window>]`.

Rejected: a dedicated host GtkWindow that is no workspace's own. It would
need its own copy of every window behavior the `Window` class carries
(close-request, realize/winproto, fullscreen/maximize, CSS, the desk
snapshot) and still route each to the workspace on show.
