# T1727 - The P1 and P2 floor scripts still read results after a fixed sleep that a slow box can outrun

## Summary

T1156 root-caused P3's one-in-N red to a fixed sleep between an action and the assertion reading its effect, and added Wait-FloorState (test\win32\lib\FloorFixture.ps1) - a clock-bounded poll that parks a NOTE SLOW STATE when it only settles past the old sleep. ipc-p2.ps1 has the same shape at every sleep->Assert pair (e.g. sections 3-5: +split then sleep 2 then read the tree; +send-keys 'title ...' then sleep 2 then +list), and ipc-p1.ps1 at lines ~119/181/190/204. Convert each to Wait-FloorState with NominalMs = the sleep it replaces; keep a negative wait only after a positive one. Validate: each script 20x back-to-back ALL PASS, plus one run with the pane-side step artificially slowed (T1156 used [Threading.Thread]::Sleep inside the typed command - NOTE Start-Sleep with a space is mangled by the send-keys quoting) scoring green with SLOW notes, and a run with the effect removed scoring red.

## In plain terms

Two of the basic checks every change has to pass waited a fixed second or two
after each action and then looked at the result. On a busy or slow machine the
result can arrive a moment later, and the check then fails even though nothing
is broken. Now they keep looking until the result shows up (or a generous
limit runs out), and say so when it was slow.

## Goals

- [x] every positive sleep->assert pair in ipc-p1.ps1 and ipc-p2.ps1 polls through Wait-FloorState, NominalMs = the old sleep
- [x] the two "no duplicate" checks keep a short settle, with the reason written beside it (there is no positive state to poll)
- [x] no negative read happens before the positive it depends on (p2 section 7 reordered)
