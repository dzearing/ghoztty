# T3359 - Linux GUI tests cannot capture pixels: give the headless harness a screenshot from the app's own GTK render

## Summary

test/linux/lib/headless.sh (T3333) runs the GTK app in a private headless Weston, which offers clients no capture, and Wayland has no global capture either. So Linux GUI tests can only assert on logs, ptys and processes. Add the in-app snapshot path from the linux-port.md translation table (gtk_widget_snapshot / GdkTexture -> PNG) behind the same screenshot surface the Mac/Windows CLI uses, and an hl_screenshot helper plus a check in test/linux/headless-harness.sh. Likely lands with or after the GTK IPC server (T3335). Triage: P2, a test capability for later Linux UI tasks; nothing user-facing is blocked today.

## In plain terms

Automated tests of the Linux app run it inside an invisible private display
that cannot take screenshots, so no test could check what the app actually
looks like. Now the app itself hands a test a picture of any pane or whole
window, so Linux UI work can be checked by its pixels, not just its logs.
Nobody using the app sees a difference; it is a tool for the test suite.

## Goals

- [x] the GTK app answers win32's debug-only `capture-pane` request from its own render (pane, `--window`, `--width/--height`)
- [x] the headless harness has `hl_screenshot` (plus `hl_ipc`, `hl_png_stats`, `hl_first_pane`)
- [x] an acceptance check proves the picture shows what the pane drew

## Validation criteria

- [x] a capture of a terminal pane is a PNG of what it drew: H16/H17 of `test/linux/headless-harness.sh` (pane paints 24-bit red, shot is 97% red), run via `wsl-run.ps1 -CommandFile test\linux\headless-harness.sh`, ALL PASS
- [x] the reply's size matches the PNG: H18
- [x] `--window` captures the whole window and the pane's x/y place it inside: H19 (window 800x600, pane 800x512 at 0,88)
- [x] `--width/--height` scale the whole pane: H20 (200x100, still >50% red; a debug run measured 93.6%)
- [x] unknown pane / missing `--path` are refused and write nothing: H21
- [x] pure half (`capture_seam.zig`) unit-tested in the none lane: `scripts/linux/floor.sh`
- [x] release builds compile the seam out (`comptime !build_config.is_debug` -> `.unhandled` -> `unknown action`), by construction as on win32
