# T2730 - foreground-audit does not require a script to be declared interactive-by-design when it reaches the input desktop only through an input-desktop-helper's functions (Invoke-FrameLabInput, Start-FrameCapture): divider-ghost.ps1 -Live injects SendInput and its declaration read as stale

## Summary

Found by T2441 (2026-11-05). `test\win32\divider-ghost.ps1 -Live` drives the
real pointer with `Invoke-FrameLabInput` (SendInput, lib\FrameLabInput.ps1)
and photographs with `Start-FrameCapture` (WGC), so it can only run on the
input desktop. Declaring it in lib\TestDesktop.ps1's `@input-desktop-exception`
list made `foreground-audit.ps1` FAIL C1/C3 with `stale-declaration - ...
no longer needs the input desktop`: the detector (lib\ForegroundAudit.ps1)
sees direct API sites and `New-TestDesktop -Interactive`, and a lib helper
carrying `# input-desktop-helper:` exempts the HELPER, but nothing makes the
helper's CALLERS input-desktop sites. That is exactly the T780 hole from the
other side: a script that calls an input-desktop helper is input-desktop-only
while the sweep reads none of it, so its presence gate (section F) is never
required either. divider-ghost.ps1 is gated (`Assert-UserAbsent`) and was
left undeclared so the audit stays green.

Fix: have each `# input-desktop-helper:` file name its entry points (or derive
them: exported functions whose body reaches a site), treat a call to one from
a top-level script as an input-desktop site, then declare divider-ghost.ps1
(and any other caller the sweep newly finds).

## Validation criteria

- [ ] foreground-audit section B gains a fixture: a script calling a helper entry point is a finding until declared, and a declared one with no gate is `ungated`.
- [ ] divider-ghost.ps1 is declared in lib\TestDesktop.ps1 and foreground-audit.ps1 is ALL PASS.
