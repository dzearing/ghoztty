# T1828 - No pane sidebar on Windows: Mac lists every pane in a pinned panel or a hover mini-rail, with busy shimmer, needs-input badges, click-to-focus and drag

## Summary

Mac 597a193cc (design: docs/design/pane-sidebar.md): pinned = flat edge-to-edge panel; unpinned = glass card collapsed to a 68pt mini rail that opens over the grid on hover without resizing any terminal. Rows list grid panes (focused selected) then stashed ones; busy panes shimmer, needs_input shows a question badge, a bell on a stashed pane shows a dot; rail tiles use title monograms (a path title shows its last component). Click focuses/restores, Option-click swaps a stashed pane in, rows drag through the one drop resolver (.stash / .joinWindow targets), right-click menu, trash mode = one-click kill. toggle_pane_sidebar keybind + Window menu items; pinned/hidden persist. Polish: the selected row follows focus (d71c18bb5), trash-mode buttons align (1ec258f14), the mock's icons, animated folds, steady hover (e628f3933, 51573daf0), equal gutters around the rail (557e4f978), the pinned edge resizes and never unpins under a drag (7855941f7). Translate to win32 chrome per docs/design/win32-design-system.md; Windows chord for toggle_pane_sidebar comes from the shared Binding.zig defaults.

**Scope as landed (the core):** the column itself in both states - the pinned
flat panel and the unpinned mini rail - listing grid panes then stashed ones,
with the selection following focus, a question badge for `needs_input` and a
busy dot, click to focus or restore, a hover button to stash or restore, the
pin, `toggle_pane_sidebar` on Ctrl+Shift+S (forwarded from a focused viewer
too), and Mac's narrow-window fallback to the rail. The rest is split into
follow-ups, each depending on this one:

- **T1842** (P1, M1) the rail opening into the full card on hover, and tile tooltips

- **T1844** (P1, M1) dragging panes into and out of the sidebar, and the `.stash` drop target
- **T1845** right-click menu, Alt-click swap, trash mode
- **T1846** drag-resizing the pinned panel, and pulling the rail out to pin it
- **T1847** pinned/hidden surviving a restart (per window, plus the new-window default and width)
- **T1848** Window-menu entries
- **T1849** (found here) `stash_pane` is swallowed by a focused viewer pane

The all-windows scope was already **T1829**.

## In plain terms

On a Mac, every window now has a sidebar listing all of its panes, so you can
see which agent is busy or waiting on you, click one to jump to it, and tuck
panes away and bring them back. Windows had nothing like it. Now a slim column
of pane tiles sits on the left of every window; the pin opens it into a full
list with names and working folders, and Ctrl+Shift+S hides it.

## Goals

## Design (win32)

- **Pure rules in `src/apprt/win32/pane_sidebar.zig`** (unit-tested in every
  lane): Mac's `PaneSidebarState` modes and widths (hidden / expanded / mini,
  the 720 DIP narrow fallback, 240 default clamped to 180-380), Mac's
  `PaneSidebarText` monogram / title / banner-line / distinct rules plus the
  Windows path shapes a shell titles itself with (`C:\...\pwsh.exe` -> `pws`),
  the roster order (grid panes in SCREEN order via `leafIterator`, then the
  stash newest first), and all panel/rail geometry and hit-testing, asserted at
  1.0 / 1.25 / 1.5 / 2.0.
- **Numbers.** Rows import the viewer side panel's (`viewer_toc_layout`) -
  Mac's design says the two are "the same card, not a lookalike". The rail is
  Mac's 44 DIP card inside the design system's `lg` 12 DIP margin (68 DIP, Mac's
  exact column), with 28 DIP tiles (the standard icon-button square) at the
  `sm` gap. The pin is a standard icon button, the row action a compact one.
- **Look.** Pinned: the terminal background lifted by the card wash, square,
  with a rule in the split divider's own color and width against the grid.
  Unpinned: the banner card's material (`banner_card.render`), whose 12 DIP
  margin is the rail margin. Selection is the Windows 11 list vocabulary
  (`list_selection.rowPaint`: neutral fill + accent bar), not Mac's tinted pill.
  Icons are the system icon font (Fluent / MDL2), as `icon_button_paint` does.
- **One child HWND per window** (`PaneSidebar.zig`, class
  `GhozttyPaneSidebar`), created on the first layout and never on the Quick
  Terminal. `Window.surfaceRect` takes the column off the grid's left the way
  the chrome takes the top, so every layout, drop zone and hit test that starts
  there lays the grid out beside the column. `syncPaneSidebar` runs from the
  layout/focus fan-out (`updateDimOverlays`), title and activity changes; it
  hashes what the roster shows and rebuilds only on a change, because a divider
  drag is a layout pass per mouse move.
- **Chord.** Mac's Ctrl+Cmd+S carried the way every Cmd chord is here (Cmd ->
  Ctrl+Shift): Ctrl+Shift+S, unbound before. A mechanism call per the
  experience test, so no decision filed.
- New windows start from the last pin/hidden choice (Mac's
  `rememberForNewWindows`), in memory for now - T1847 makes it survive a
  restart.
