# T1597 - A harness header holding a SINGLE declaration parses as zero declarations in the sibling audits

## Summary

T780 found this in Get-ForegroundAuditDeclarations and fixed it there: the parser assigns [string[]]$Text through an if, which unrolls a ONE-ELEMENT array to a bare string, and then indexes it - so $lines[0] is a CHARACTER and a header holding exactly one declaration parses as zero. Zero declarations reads as 'the list is empty', which in ForegroundAudit is itself a finding but in a sibling may simply turn every violation into a pass. Get-DesktopLaunchAuditDeclarations has the identical shape and indexes today. Six more parsers copy the assignment without indexing (AssertedNothingAudit, BodyCompleteAudit, ExitCodeAudit, SkipAudit, StderrCaptureAudit, VerdictExitAudit) and are safe only by accident of iterating instead. Fix: wrap each in @(), and give at least the indexing one a single-line fixture, since that is the case no existing fixture covers - every one of them passes a multi-line array.
