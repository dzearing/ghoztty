# T955 - floor-lane calls a confirmed test-binary crash a plain FAIL, so the lane word never says a process died

## In plain terms

When a test run dies because the program crashed, the checker that runs it
still announces "FAIL" -- the same word it uses when a test simply got the
wrong answer. It then prints the crash details right underneath, so the
information is there, but the one-line verdict everybody actually reads says
nothing died. A crash and a wrong answer are very different problems, and
right now they look identical at a glance.

## Summary

Found while fixing T877. `scripts\floor-lane.ps1` has exactly three non-pass
results -- `FAIL` (1), `STALL` (2), `TIMEOUT` (3) -- so a lane whose test
binary was killed by an exception reports `LANE none FAIL in 5s`, then prints
the `-- crash diagnostics --` block that names the dead process directly
below it. The 2026-08-15 22:07 occurrence is exactly that transcript.

T877 fixed the layer above: `test-binary-soak.ps1` now reads floor-lane's own
decoded block (`Get-CrashOccurrenceLine` in `scripts\lib\CrashDiag.ps1`) and
counts such a round as `crash=`, not `fail=`. But floor-lane itself still
says FAIL, so:

- `FLOOR SUMMARY: none#1=FAIL` is what a turn pastes into a task file, and it
  reads as a red test to every human and every script,
- anything else that classifies from floor-lane's verdict word has to
  re-derive the crash decision the way the soak now does, instead of being
  told.

Fix direction: add a `CRASH` result to `Invoke-Lane`, chosen when the
crash-diagnostics pass confirms one of `$TEST_EXE_NAMES` died (the same
condition `Invoke-LaneCrashCatch` already gates on, so the evidence is
already computed). Exit code needs care -- it is a compatibility surface;
`EXIT_FAIL` (1) is the conservative choice for CRASH so no existing caller
changes meaning, with the distinction carried in the printed word and the
summary. `Get-CrashOccurrenceLine` is the shared definition to classify by.

## Goals

- [x] A lane whose test binary crashed prints `CRASH`, not `FAIL`
- [x] `FLOOR SUMMARY` carries the same word, so a pasted line is unambiguous
- [x] A genuinely red lane still prints `FAIL`
- [x] The soak's own classification is unchanged by it (it already agrees)

      access-violation crash of a test-binary-named exe also reads CRASH, in
      section 6 of `test\win32\crash-first-chance.ps1` (70/70).
- [x] A staged lane that just fails its tests still reports `FAIL` in both
      places (negative control) -- arm 37 of the same harness; and
      `floor-lane-compiler-crash.ps1` (32/32) shows a crashed COMPILER stays
      FAIL, so the T451 retry still keys on it.
- [x] `test\win32\test-binary-soak.ps1` stays ALL PASS (88/88) -- the soak now
      also counts a `CRASH` lane word as a crash, which agrees with the evidence
      it already read.
- [x] The floor lanes still exit 0 when green and nonzero when not, with no
      change to the code a green/red lane returns -- `-Lane all` ALL LANES PASS
      exit 0, `-Lane harness` PASS exit 0; staged FAIL and CRASH both exit 1
      (arm "a CRASH exits 1" in verdict-detail).
