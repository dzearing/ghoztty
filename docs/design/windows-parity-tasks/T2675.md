# T2675 - Settings window shell on Windows: open_config / Ctrl+, opens a native window with a searchable page sidebar, the generic row (docs, changed dot, reset, inline rejection) and Advanced > All Settings (Mac 9287de0ff)

## Summary

Split from T2584, which landed the read model underneath it. Build the native
win32 Settings window on the design system (`docs/design/win32-design-system.md`
+ `docs/claude/win32-ui.md`; `ShortcutGuideWindow.zig` is the closest existing
precedent for a standalone app window): `open_config`, Ctrl+, and the
menu bar's Settings item open it (focus it if open) instead of
`App.openConfigFile` ShellExecuting the file; "Open Config File..." stays one
click away. A sidebar of pages with a Search box (Mac `SettingsView.swift`:
typing searches every row's label, key, docs and value, and switching page
clears the query). The generic row (Mac `RawSettingRow` /
`SettingsRowView.swift`): the key, its doc summary
(`SettingsCatalog.summary`) with the full doc on demand, the changed-from-default
dot (`Reader.isModified`), Reset (`SettingsModel.reset`), a text field for a
plain key and the value list for a repeatable one, the model's inline problem
("invalid value ... - not saved"), and a read-only state with an Open link when
a later include sets the key (`SettingsSources.overriding`). Advanced >
All Settings lists every schema key with the All / Changed filter
(`Reader.allSettings`). Writes go through `SettingsModel` with
`model.sources` set, and the window refreshes (catalog effective values,
sources, file) on every config reload. The curated pages are T2585; the rest of
Advanced (path, includes, backups, toast) is T2676.

## In plain terms

On the Mac, pressing Cmd+, opens a real Settings window. On Windows, Ctrl+,
(and the menu's Settings item) just opened the raw config text file in
Notepad. Now it opens a Settings window too: a searchable list of every
setting with its explanation, where you can change a value, reset it, and see
straight away when a value is wrong or is being overridden by another file.

## Goals

- [x] Ctrl+, / the Settings menu item / the palette open a native Settings window (one, reused)
- [x] Advanced > All Settings lists every setting, with All / Changed and sidebar Search
- [x] Each row shows the key, changed dot, summary, full docs on demand, Reset, and an editable value (or value list)
- [x] Bad values are refused inline and never reach the file; a value another file overrides is read-only with an Open link
- [x] "Open Config File..." stays one click away; the window refreshes on every config reload

## Decisions made in passing (mechanism, not experience)

- Fields are drawn by the window and it routes every key itself (the
  shortcut guide's pattern), not EDIT children: one look on the design
  system, and no cross-process `SetWindowText` cache for tests to trip on.
- Mac's doc popover is an inline expansion under the row here - a popover
  over a custom-drawn list has no native win32 counterpart that keeps
  scrolling, and the content is the same.
- The sidebar has one page (Advanced) until T2585 adds the curated pages;
  All Settings' third filter ("Not on other pages") arrives with them, since
  until then every key is on no other page.
- A debug-only `GHOZTTY_SETTINGS_BACKUP_DIR` seam keeps test runs out of the
  box's real `config-backups` folder.
