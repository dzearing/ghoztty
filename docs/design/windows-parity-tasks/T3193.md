# T3193 - Single-window mode: parked content is laid out at the shared window size, re-laid 0.3s after a resize settles and at once on a tree change in the parked workspace

## Summary

Child of T3181 (split 2026-11-16; P0 by user directive via T3136). Spec docs/reference/window-modes.md; decisions come from src/apprt/win32/workspace_host.zig. Acceptance: a section of test/win32/single-window-mode.ps1.

## In plain terms

In "all in one window" mode, the workspaces you are not looking at used to
have no size at all: one opened in the background ran its shell one character
wide, and resizing the window did nothing to the hidden ones, so switching to
one showed it at the wrong size until it caught up. Now every hidden workspace
is kept at the window's real size - from the moment it opens, a moment after
you finish resizing the window, and straight away when a pane is added or
closed in it - so it is ready the instant you switch to it.

## Goals

- [x] A workspace opened in the background has the window's grid from birth
- [x] A resize of the shared window reaches every hidden workspace once it settles (0.3s)
- [x] A pane added to or closed in a hidden workspace re-lays it out at once
- [x] Switching to a hidden workspace shows it at the grid it already had

## Design (decided here)

- `Window.contentClientRect` / `layoutHwnd`: a parked controller measures
  against the SHARED window (the one on show) - client rect, caption style,
  and the pane sidebar's column - and still takes its own chrome off, the way
  Mac lays a parked container out with the titlebar's inset. Born parked, it
  takes the shared window's scale.
- `PARKED_RELAYOUT_TIMER_ID` on the shared HWND, re-armed by every WM_SIZE
  while there is more than one workspace; on fire `App.layoutParkedWorkspaces`
  lays out `workspace_host.parkedInto` (every parked workspace). Not in
  `window_timer_ids`, so a switch inside the 0.3s keeps it armed and it fires
  to the adopter.
- A tree change in a parked workspace already ran `layoutSplits`; with a real
  rect it now lays out at once. `presentWorkspace(.stay_parked)` lays out too.

## Validation criteria

- [x] F1: a born-parked workspace has the on-show workspace's grid (72x25 vs 72x25) - `single-window-mode.ps1` F1 (was 1 column before; 79 vs 72 until the sidebar column was counted).
- [x] F2: shrinking the shared window reaches a parked workspace after the settle (35 -> 28 cols) and logs `parked workspaces laid out why=resize-settled count=1` - section F2.
- [x] F3: on show it has exactly the grid it had parked (rows included; caught the caption-height miss) - section F3.
- [x] F4: closing a pane in a parked workspace re-lays it at once (28 -> 59 cols) - section F4.
- [x] F5: growing the window back reaches it too - section F5.
- [x] B3 reads the parked shell's output with no line-joining workaround.
- [x] Unit: `workspace_host: a settled resize lays out every parked workspace, never the one on show` (none/win32 lanes).
