# T743 - Four acceptance launches never state their session persistence, so persistence-flag.ps1 is red

## In plain terms

One of the test suite's own self-checks has been failing. It exists to make sure
every test that starts the terminal says whether it wants yesterday's windows
restored — because a test that does not say gets them, and then measures the
wrong thing. Four places stopped saying, so the check is red, and a check that is
always red stops being read.

## Summary

`test\win32\persistence-flag.ps1` A1 reports `undeclared: 4 of 168`:

- `test\win32\url-scheme.ps1:359, 368, 381` — the three
  `Start-OnTestDesktop -Exe $exe -Arguments @("$debugScheme://open/urlwin")`
  activations (landed with `6ecea2507`). These are the forward-and-exit second
  instances go.md names as a legitimate `# persistence: <reason>` marker case,
  but the marker was never written.
- `test\win32\agent-attach-refused.ps1:276` — `-Arguments @()` (landed with
  `d545a15ca`). The agent family generally WANTS persistence on, so this most
  likely wants a marker stating that, not a `false` flag.

Pre-existing; found while T613 added `test\win32\palette-close-crash.ps1` and
ran the harness audits over it.

## Details

The rule (T158) is *state which you want*, not *always pass the flag*: pass the
flag, pass something built from it, have every caller of your helper pass it, or
write a `# persistence: <reason>` marker. Decide each of the four on its own
merits — a marker asserting "this launch wants a restore" is a real declaration
and is the right answer for at least the agent one.

## Where

- `test\win32\url-scheme.ps1` (3 sites), `test\win32\agent-attach-refused.ps1`
  (1 site).
- `test\win32\lib\PersistenceSweep.ps1` — the enumerator.
- `test\win32\persistence-flag.ps1` — the audit.
