# T1809 - Viewer (HTML/markdown/diff/web) panes must never dim; one dimmed and never undimmed

## In plain terms

An HTML pane sometimes went dim and stayed dim, even after you clicked
into it. The user does not want viewer panes dimmed at all. Remove the dim
from viewer panes completely. Terminal panes keep their unfocused dim as
before.

## Summary

User report and directive (2026-10-10): "i see a big bug where sometimes the
html pane dims and never 'undims'. I don't ever want html panes to dim."

The directive reverses T380 ("Viewer panes get no unfocused-split dim
overlay"), which added a `DimOverlay` to viewer panes on Windows. Its Mac
mirror T559 is skipped by this task, so both platforms converge on "viewers
never dim". Mac viewers never had the overlay.

**Assumption (recorded, not asked):** "html panes" means every viewer pane
(HTML, markdown, code, git diff, website, image), because they all share the
T380 overlay path, and a stuck dim on any of them is the same defect. If the
user meant HTML only, re-enabling the others is a one-predicate change.

Work:

1. **Remove the overlay from viewer panes.** No `DimOverlay` is ever created or
   shown for a `ViewerPane`, regardless of `unfocused-split-opacity`.
   Candidate sites: `src/apprt/win32/DimOverlay.zig`, `PaneView.zig`,
   `ViewerPane.zig`, `chrome_fanout.zig`, `overlay_zorder.zig`.
2. **Find out why it got stuck anyway.** A dim that never clears on a viewer
   is likely a focus-tracking gap: WebView2 takes focus in its own child
   HWND, so the pane never sees the focus-in that clears the dim. The same
   lifecycle hole could strand a dim on a TERMINAL pane, for example when
   focus moves into a viewer and back. Confirm whether terminal panes can
   stick too. If they can, fix that here or file it.
3. Update or retire the T380 acceptance coverage (`split-dim-viewer.ps1`) so
   it asserts the opposite: a viewer pane is never dimmed. Keep
   `split-dim.ps1` for terminal panes. Mind T1101 (the dim probe reading as no
   colour) when choosing the oracle.

## Validation criteria

- [ ] An unfocused viewer pane next to a focused terminal pane, with
      `unfocused-split-opacity` < 1: no dim overlay window exists for the
      viewer pane (enumerated, not eyeballed), across focus moves in both
      directions and through a WebView2 click. Script runs on the test
      desktop.
- [ ] Terminal panes still dim when unfocused and undim on focus (positive
      control), including after focus passes through a viewer pane.
- [ ] Why the dim was stranded is named with evidence, and whether the same
      cause can strand a terminal dim.
- [ ] `floor-lane.ps1 -Lane all` and `ipc-p1/p2/p3` green.
