# T2790 - A broad edit (the T2514 composition-default flip) leaves ~40 guard rows DUE at once: score a row due by whether its verdict could have changed (the changed lines reach code the harness exercises), not by any byte of a covered file moving

## Summary

The 2026-11-07 claim listed roughly forty `GUARD DUE` rows after the T2514
composition-default flip and its follow-ups touched files shared by many
harnesses (rearrange-*, pane-stack-*, stack-*, viewer-*, close-confirm,
remote-disconnect, the audits). `scripts\guard-due.ps1` marks a row due when
ANY byte of a covered file differs from the stamp, so a one-constant flip in a
widely covered file obliges every harness that lists it, whether or not the
changed lines are on a path that harness exercises.

Explore a narrower "could the verdict have changed" test, for example:
per-row function-level coverage (the covered file plus the decls the harness
reaches), or a row-declared list of seams/knobs, so a change confined to code
a harness never reaches does not make it due. The conservative fallback (any
byte) must stay for rows that declare nothing.

Evidence: the claim output of turn 77 (2026-11-07 06:24), digest
`docs/design/windows-parity-digests/2026-11-07.md` Reflection.

## Validation criteria

- [ ] A row that declares a narrower scope is NOT due after an edit outside that scope, and IS due after an edit inside it (both demonstrated in the guard-due acceptance).
- [ ] A row that declares nothing behaves exactly as today (any byte of a covered file).
- [ ] gate-negatives still shows the guard-due gate going red on a real in-scope change.
