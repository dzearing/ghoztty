# T3272 - Hovering a Ghoztty window steals focus from whatever app is active

## Summary

User report 2026-11-20: on the installed Windows build, moving the mouse over a Ghoztty window brings it forward / takes keyboard focus without a click. Ruled out by reading: Surface.focusFollowsMouse (Surface.zig:6517) refuses to act unless the parent window is already active; PaneGrabHandle is WS_EX_NOACTIVATE + SWP_NOACTIVATE + MA_NOACTIVATE. Not yet checked: the other hover handlers in the run loop and WndProcs (BannerOverlay, PaneSidebar, Scrollbar, KeyStateIndicator, viewer bars, WebView2 viewer panes taking focus on hover), any ShowWindow/SetWindowPos on hover missing SWP_NOACTIVATE, and deferSetFocus/WM_APP_SETFOCUS firing on an inactive window. Repro first: two apps side by side, focus the other one, hover a Ghoztty pane (terminal, viewer, sidebar, banner, tab strip) and record which surface steals. Acceptance: a background-desktop script proving hover over each surface kind leaves GetActiveWindow/foreground unchanged. Mac parity: hover must never activate there either - verify.
