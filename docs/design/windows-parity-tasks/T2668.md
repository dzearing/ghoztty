# T2668 - No harness proves the Windows shortcut guide rebuilds on a config reload: ShortcutGuideWindow.configChanged is wired to App config_change but test/win32/shortcut-guide.ps1 cannot vary the disk config it reloads

## Summary

Follow-up to T2591. Drive the guide harness from a temp --config-file instead of CLI --keybind flags, rewrite the file to add/unbind a chord, +reload, and assert the open guide's rows change (customized flag, keys) without reopening.

## In plain terms

The Keyboard Shortcuts window is supposed to update itself when you edit your
config and reload it, so a chord you just added or removed shows up without
closing and reopening the window. It already did, but no test checked it, so it
could break without anyone noticing. Now the shortcut-guide test edits a real
config file while the window is open, reloads, and checks the rows change.

## Goals

- [x] the harness reads its keybinds from a temp config file instead of `--keybind` flags
- [x] a new section rewrites that file, runs `+reload --config`, and checks the open guide's rows change in the same window
- [x] the file going back to the start state and reloading restores the original rows

## Validation criteria

- [x] Before the reload, rewriting the file alone leaves the open guide unchanged (control): `shortcut-guide.ps1` section J, via `acceptance-parallel.ps1 run -Scripts shortcut-guide.ps1` (ALL PASS, 77 assertions, 2026-11-28).
- [x] After `+reload --config`: the removed Ctrl+Alt+Z leaves New Tab (defaults Ctrl+T/Ctrl+Shift+T kept, not CUSTOM); the sidebar toggle has Ctrl+Shift+S back and is not CUSTOM; the newly added Ctrl+Alt+Y lands on Toggle Full Screen marked CUSTOM. Same run, section J.
- [x] Same guide HWND before and after the reload (rebuilt, not reopened). Same run, section J.
- [x] Reloading the starting file restores the added chord as CUSTOM, so sections C-I still see B's state. Same run.
- [x] The harness can still fail: `-NegativeControl` run fails on its inverted B assertion (1 failure, 76 passed).
