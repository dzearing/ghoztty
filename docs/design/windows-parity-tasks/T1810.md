# T1810 - +rearrange (and any other verb that calls deferSetFocus) may activate a background Ghoztty window: SetFocus on a child of an inactive top-level activates it

## Summary

Found during T1797. The CLI-create verbs now open in the background, but +rearrange still ends with App.deferSetFocus(focused pane) in IpcHandlers (the post-swap focus restore). When the rearranged window is NOT the active one, SetFocus on its child activates that window within our queue - a smaller cousin of the focus steal T1797 removed. Mac's 3081022ec did not list +rearrange. Measure on the test desktop (rearrange a background window while another is active; read GetGUIThreadInfo), and if it activates, only restore focus when the window was already active. Same audit for +close of a pane in a background window (closeSplitPane focuses the next pane).
