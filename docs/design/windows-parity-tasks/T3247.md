# T3247 - A debug agent running from another worktree sweeps this worktree's debug pty holders: pty-host.ps1 C0/C1 read SHUTDOWN within 3 s and session-shell-exit went red while D:\git\ghoztty-t3239's agent held the debug pipe

## Summary

Seen in T3236 (2026-11-19). A hand-run debug holder (zig-out\bin\ghoztty-agent.exe --pty-host --session-id x) logged 'SHUTDOWN received' ~3 s after start while D:\git\ghoztty-t3239\zig-out\bin\ghoztty-agent.exe owned \\.\pipe\ghoztty-agent-debug-David; pty-host.ps1 C0/C1 and session-shell-exit A-D.1 were red in that window and green once that agent exited. T1594 put lineage in the holder pipe namespace, but every worktree's Debug build shares the 'debug' lineage, so one worktree's orphan sweep can still take another's holders. Fix candidates: a per-worktree lineage for dev builds, or make the harnesses that launch bare holders take a private agent instance. Verify which process sent the SHUTDOWN first.
