# T2571 - Composition step 5c-2: in pane-tree mode the stack glide and blade fold/unfold move each pane's content visual on every tick and leave its child window where it is; each pane window is placed once, when the glide lands

## Summary

Split of T2554. stackSlideTick runs layoutSplitsLive every tick, which SetWindowPos-es every sliding pane child (and re-cuts its region) so the visual follows on WM_WINDOWPOSCHANGED. In GHOZTTY_COMP_PANE_TREE mode put the slide's rect/card (Window.stackSlideRect / stackSlideCardRect, slideClip) straight onto the pane visual (Host.panePlace with an offset clip, one commit per tick for all panes) and skip the child moves while the glide runs; endStackSlide places each pane window once at its slot with the grid held through the motion (T2102 paneContentFreeze; drag_hold). Still ticked on the UI thread - handing the motion to DWM is 5c-3. Viewer panes (WebView2) have no tree visual and keep the window path. Oracle: a 'stack glide child moves' debug line per glide reads 1 per pane in tree mode (N per tick on the old path); WGC film of a stretched fold, tree vs on arm, card edges match frame for frame; the T2485 chain-fold film reads 0 bad frames in tree mode.

## In plain terms

When panes slide sideways in a stack (clicking a tucked pane's strip, folding one away), every frame of the slide used to physically move each pane's window, which is heavy work the system has to finish before the frame can show. In the new composition mode the picture of each pane now slides on its own and the window underneath is moved once, when the slide lands. Nobody sees a difference in the motion itself; it is the groundwork that lets the next step hand the whole slide to the system compositor.

## Goals

- [x] In pane-tree mode a gliding pane's visual is placed where the glide has it on every tick, and its child window is left where it is
- [x] Each pane window is placed once, when the glide lands (plus a frame where a pane is shown or hidden)
- [x] One composition commit per tick for every pane, its card shape and the desk paint
- [x] The desk fills what a moving visual leaves: the still window's region follows the visual
- [x] Off the tree (viewers, a glide that resizes a pane, `GHOZTTY_GLIDE_TREE=0`) nothing changes
