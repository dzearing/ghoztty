# T1849 - stash_pane does nothing from a focused viewer pane on Windows: the chord is not forwarded to the window

## Summary

Found during T1828. viewer_accel.forwardsTag forwards toggle_pane_sidebar (T1828) but not stash_pane / restore_stashed_pane (T1827), so ctrl+shift+m pressed in a markdown or website pane is swallowed by the page. Mac classifies both as pane/window actions a focused viewer forwards.

## In plain terms

Pressing the "stash this pane" shortcut (Ctrl+Shift+M) while a markdown,
web or diff pane had focus used to do nothing - the page swallowed the key.
It now puts that viewer pane away, and the "bring a stashed pane back"
shortcut works from a viewer too. Anyone who keeps docs open beside their
terminal notices.

## Goals

- [x] The stash shortcut answers from a focused viewer and stashes the viewer itself
- [x] The restore shortcut answers from a focused viewer
- [x] An on-box test presses both chords at a real viewer

## Resolution

**Already fixed in passing by T1803** (commit 1121071d6, 2026-10-12), filed the
day after this card: it admitted `stash_pane` and `restore_stashed_pane` to
`viewer_accel.nativeTag` and gave `Window.performViewerBindingAction` arms that
stash the VIEWER pane (not the host terminal the core would have performed it
through) and restore the top of the active tab's stash. Its unit test covers
the classification; nothing on the box had ever pressed the chord at a viewer,
so the deliverable here is that validation: arms S5/S6 in
`test\win32\viewer-window-chords.ps1`.

## Validation criteria

- [x] ctrl+shift+m (the Windows DEFAULT, not a --keybind) at a focused viewer stashes the viewer and not the terminal, and the page never sees the chord - `viewer-window-chords.ps1` S5, ALL PASS (48 assertions) on zig-out debug, 2026-10-13
- [x] a bound restore_stashed_pane chord at a focused viewer brings a +stash'd terminal back, page never sees it - same run, S6
- [x] the new arms can fail: `-NegativeControl` run exits 1 with S5 and S6 (inverted) both red, alongside S1-S4
- [x] `viewer_accel` unit test `native: window/app commands yes...` asserts both tags native (from T1803)
