# T3137 - Session restore on Windows honors the manifest's additive 'frontmost' field (Mac 3f772a2f0): the window that was in front at quit comes back in front

## Summary

Mac 3f772a2f0 adds an additive frontmost field to the session layout manifest (SessionLayoutManifest.swift) so a restore brings the front window back last. Windows session-layout restore (App.zig restore path) should write and read the same field so a manifest restores the same on both platforms, independent of single-window mode. Additive, no agent wire change.

## In plain terms

When you quit with several terminal windows open, the next launch should bring
back the one you were working in on top. Windows already did this for its own
saved layouts; a Mac layout restored on Windows lost the fact, and Windows did
not record it in the shape Mac reads. Now both platforms record "this one was in
front" the same way, and every restore path honours it.

## Goals

- [x] Captured layouts mark the window that was in front (`frontmost`, Mac's key).
- [x] A Mac layout's front window comes across that way when restored on Windows.
- [x] Launch restore builds the front window first (it is the one shown in front).
- [x] Restore All builds it last (each built window activates, so the last one ends in front).

## Design

- `session_layout.Window.frontmost` (additive, `true` or absent, Mac spelling).
  Capture marks the most recently activated window (`markFrontmost`, the
  `last_activated_ms` stamp win32 already keeps = Mac `isMainWindow || lastMain`).
- Launch restore: `restore_pacing.order` puts a frontmost window ahead of every
  stamp. The launch builds the first window in front and paces the rest behind
  it, so first-built here is Mac's `frontmostLast` for this builder. It matters
  for a Mac blob, which carries no stamp, only the mark.
- Restore All (local and relay): `restore_pacing.frontmostLast`, Mac's helper
  verbatim, because that path activates each window it builds.
- `mac_layout_blob` reads `Entry.frontmost`; any tab entry of a group marks the
  group's window.
- No agent wire change (blobs are opaque to the agent). Single-window mode itself
  is T3180-T3187.

## Validation criteria

- [x] Capture marks exactly one window, the most recently focused, and the key is additive (unit: `session_layout` "T3137: the most recently focused window is marked frontmost", none + win32 lanes).
- [x] A Mac entry's `frontmost` reaches its translated window, through a tab group (unit: `mac_layout_blob` "T3137: a Mac entry's frontmost mark comes across").
- [x] Launch order puts the frontmost first, ahead of stamps; Restore All order puts it last (unit: `restore_pacing` T3137 tests).
- [ ] On-box launch restore of a multi-window manifest: NOT RUN as a live check - it needs the input desktop to observe which window is foreground (go.md focus rule); the order is covered by the unit tests above, and the build path is unchanged except for the index order.
