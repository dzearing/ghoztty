# T2403 - The pane sidebar's column glide repaints the whole panel and allocates three DIBs every frame (8-11 ms per frame against an 8.3 ms period at 120 Hz), so the glide drops frames; cache the incoming panel and the backdrop once per glide and only compose per frame

## Summary

Found by T2401. With `GHOZTTY_PERF`, each column glide logs `pane sidebar column glide done ... frames= gap_max_us= paint_max_us=`. Off-desktop on a 120 Hz box, `paint_max_us` ran 8-11 ms, which is more than the 8.3 ms period. So even with the first frame anchored (T2401), the glide can skip refreshes.

`PaneSidebar.paintColumn` (via `pane_sidebar_xfade.zig`) re-renders the incoming panel and the backdrop into fresh DIBs on every frame. Those two images do not change during a 240 ms glide. Fix: render them once when the glide starts, and per frame only compose (crossfade and clip to the current width).

## In plain terms

When you collapse or expand the pane sidebar, its width animates. Every frame of that animation redrew the whole panel from scratch, which took longer than a frame lasts on a 120 Hz screen, so the motion stuttered. Now the panel is drawn once when the animation starts and each frame only blends the pictures, so every frame fits.

## Goals

- [x] The incoming panel, the backdrop and the compose buffer are drawn once per glide, before its first frame
- [x] Per frame the glide only blends (integer crossfade, copy-only spans)
- [x] An edge drag that changes the target width mid-glide does not force a redraw every frame
- [x] The glide harness guards it: each button glide lands with `drawn=1`

## Validation criteria

- [x] `paint_max_us` in the column glide's done line stays under one period (8.3 ms at 120 Hz) across button and edge-drag glides - measured on the Debug build in `pane-sidebar-glide.ps1` (flat style, 330 x 826 column): before 8.7-13.8 ms, after 2.8-6.2 ms across all five glides (median frame 1.7 ms), `drawn=1` (2 when the drag outgrew the kept width). NOT measured with a viewer pane in the layout: `paint_max_us` times the column's own paint only, which a viewer pane does not enter, so it was measured without one.
- [x] `pane-sidebar-glide.ps1` (47 assertions, incl. the new `drawn=1` pair) and `pane-sidebar-resize.ps1` (69) green via `acceptance-parallel.ps1`; 20 further sidebar harnesses green; zig floor `-Lane all` green.
