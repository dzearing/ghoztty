# T3124 - Audit page_allocator buffers that shrink: zig 0.15 shrinks in place with MEM_RESET on Windows, so a shrink keeps the commit charge (T3002 finding)

## Summary


T3002 found that zig 0.15.2's `std.heap.PageAllocator.realloc` on Windows answers a shrink IN PLACE with `NtAllocateVirtualMemory(MEM_RESET)` (lib/std/heap/PageAllocator.zig ~:160), which never decommits: `ArrayListUnmanaged.shrinkAndFree` (and any `allocator.remap`/`resize` down) on `std.heap.page_allocator` leaves every page committed, so the process's private bytes do not move. The first T3002 harness run read identical numbers with and without the fix for exactly this reason. About 30 files under src/apprt/win32 and src/renderer use page_allocator directly; any of them that shrink a buffer expecting memory back get nothing. Do: list each page_allocator buffer that is ever shrunk (shrinkAndFree, resize-down then remap, realloc down), and where memory return is the intent, release-and-reallocate the way `PaneDesk.fitList` now does. Measure with test\win32\lib\ProcessMemory.ps1 Get-Sample (PrivMB).
