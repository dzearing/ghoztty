# T3582 - No check that pasting an image pane's copy into Word, Outlook, Teams or a Chromium page still inlines the PICTURE now that the file rides beside it (T1909)

## Summary

T1909 put CF_HDROP + Preferred DropEffect on the clipboard AFTER the PNG/CF_DIBV5 picture formats, on the reasoning that readers take the first format they know and Explorer (no bitmap reader) is the only one left holding the file. That ordering argument was not observed against real readers: this box has no Office or Teams, and pasting into them would take the user's focus. Check by hand on a box that has them: ctrl+C an image pane, paste into Word, Outlook (compose), Teams chat and a Chromium contenteditable page; each must insert the picture inline, not attach the file. If any attaches, file the experience gap as a decision (picture-only vs picture+file) rather than reorder silently.
