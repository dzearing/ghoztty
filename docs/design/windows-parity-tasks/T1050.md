# T1050 - Every turn that reads windows-parity-tasks.md pays for 1300 lines of frozen history to reach the live part

## Summary

go.md tells a fresh turn that windows-parity-tasks.md is worth reading for its narrative sections, and the resume protocol says the same. As of T345 almost none of it is live: the state table has been a historical snapshot since 2026-07-29, windows-parity-details.md's contents were copied into task files, and Current priorities was frozen on 2026-08-21 once every task it named had closed. What remains live is the resume protocol at the top and the code-landmarks section - a few dozen lines inside a 1500-line file that a turn opens with a clean context. The frozen material has real archival value (it is the record of what the user asked for and when), so this is a split rather than a delete: move the frozen state table and Current priorities into a history file, leave the live sections and a one-line pointer, and update the three docs that route readers here. The context rule exists because a turn's attention is the scarce resource, and the cheapest fix for a doc nobody can read selectively is to make the live part the whole file.

## In plain terms

was a frozen record nobody uses any more. Every fresh session paid to read it.
Now the start-here document is the 140 lines that still matter, and the record
lives in its own file, unchanged.
