# T1503 - +read rejoins soft-wrapped rows, so a caller cannot address a single screen row

## Summary

A live Claude Code pane read with '+read --lines=40' comes back with the composer row and the status row glued into ONE line: the composer is full-width, so the terminal marks the next row a wrap continuation and +read rejoins them. Measured 2026-09-12 while fixing T1502 - the clear gate had to cut the composer's content at the first run of two spaces to keep the status text out of its answer. Rejoining a genuinely wrapped line is right; gluing the row BELOW a full-width one is not, and it makes every screen-row oracle (+read is the only one we have) guess where a row ended. Decide which +read owes its callers, and if the rejoin stays, say so in '+read --help' so the next caller does not discover it by measurement.
