# T1503 - +read rejoins soft-wrapped rows, so a caller cannot address a single screen row

## Summary

A live Claude Code pane read with '+read --lines=40' comes back with the composer row and the status row glued into ONE line: the composer is full-width, so the terminal marks the next row a wrap continuation and +read rejoins them. Measured 2026-09-12 while fixing T1502 - the clear gate had to cut the composer's content at the first run of two spaces to keep the status text out of its answer. Rejoining a genuinely wrapped line is right; gluing the row BELOW a full-width one is not, and it makes every screen-row oracle (+read is the only one we have) guess where a row ended. Decide which +read owes its callers, and if the rejoin stays, say so in '+read --help' so the next caller does not discover it by measurement.

## In plain terms

When a script reads a pane's text, a very long line that the terminal wrapped
onto two screen rows comes back as one line - which is what you want for
searching output. The side effect is that in a Claude Code pane the input box
and the status line below it can come back stuck together. This task decided
to keep the joining (both on Mac and Windows) and to say so plainly in
`+read --help`, so the next script author is told rather than surprised.

## Goals

- [x] Root cause measured: the soft-wrap mark on a full-width row survives an erase-and-rewrite of the row below it (xterm behaviour, `Terminal.eraseLine(.complete)`), and +read's dump follows soft wraps.
- [x] Decision made: the rejoin stays (it is what keeps long output greppable; a row-exact default would split every long line at the pane width).
- [x] `+read --help` says a line is a logical line and names the glued-row case.
- [x] docs/claude/cli.md documents the contract next to the flag.
- [x] A unit test pins the contract so a change cannot land silently.

## Decision

Keep the rejoin. Shared core, so Mac and Windows already behave identically and
the help text is the same Zig doc comment on both - no seat divergence. No new
flag: no caller needs row-exact output today (the one screen-row oracle, the
T1502 clear gate, already cuts at a double space), and adding CLI surface would
need the Mac seat too. If a caller does need it, file "+read --rows" for BOTH
seats.
