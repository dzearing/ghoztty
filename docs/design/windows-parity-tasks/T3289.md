# T3289 - Mac +list --json does not name the machine a cross-machine window is on (Windows has machine since T1557)

## In plain terms

On Windows, a script that lists your windows can now see which machine each
remote window is on. On the Mac the same script cannot — the name is only
published to accessibility tools. This brings the Mac's `+list` up to the same
answer, so a script works the same on both.

## Summary

T1557 added an optional `machine` string to each window entry in the Windows
`+list --json` (`List.Window.machine` in `src/apprt/ipc/list.zig`, filled from
`Window.machineDisplayName()` in `src/apprt/win32/IpcHandlers.zig`), and a
`[machine: <name>]` tag to the human `+list` output (`src/cli/list.zig`, which
is shared, so the Mac CLI already PRINTS the tag once its server sends the
field).

Mac publishes the same fact only as the `AXGhosttyMachine` accessibility
attribute. Add the field to the Swift IPC server's `WindowData`:

- `machine`: the window's machine display name — the SAME string the pill
  speaks (`Machine.name` for a relay machine, the dialed host for tcp), not a
  second derivation;
- **absent** for a local window (not the AX attribute's literal `"Local"`),
  matching `connection` and the Windows encoder;
- written after `connection` in the encoder, so the field order matches.

Then drop `"machine"` from the allowed-extras list of the golden Mac-shape test
(`expectMacShape(... "struct WindowData" ...)` in `src/apprt/ipc/list.zig`)
once the Swift struct carries it — that test is what proves the two encoders
agree.

## Validation criteria

- [ ] Mac `+list --json` on a remote window carries `machine` equal to the
      pill's name; a local window carries no `machine` key
- [ ] Mac `+list` human output shows `[machine: <name>]` on the remote window
- [ ] The golden shape test passes with `machine` removed from the WindowData
      extras list
