# T3738 - The Settings window does not scroll with a trackpad (over Remote Desktop especially): small wheel deltas below 120 are truncated to zero

## Summary

User report 2026-11-25: in the Settings window, on a Windows machine reached over Remote Desktop, the trackpad does not scroll - other apps scroll fine. Cause found by reading: SettingsWindow.zig:3502-3505 handles WM_MOUSEWHEEL as notches = divTrunc(delta, WHEEL_DELTA) and drops the remainder, so a precision touchpad (and an RDP-forwarded trackpad in particular) that sends many small deltas below 120 rounds every one to zero; a mouse wheel's 120 still works. Fix: accumulate the remainder per window (and reset it on a direction change), or scroll by delta * wheel_step / 120 pixels directly; handle WM_MOUSEHWHEEL the same way where the page scrolls sideways. Audit every other win32 surface that divides the wheel delta the same way (grep WHEEL_DELTA under src/apprt/win32: Activity Monitor, the machine chooser, the pane sidebar, menus/popups, the viewer chrome) and fix them together. Acceptance: a unit test of the accumulator (six deltas of 20 scroll exactly one wheel_step; a reversal does not carry), plus a GUI test that posts WM_MOUSEWHEEL deltas of 15 to the Settings window and asserts its scroll offset moves.

## In plain terms

Scrolling the Settings window with a laptop trackpad - especially over Remote
Desktop - did nothing, while a mouse wheel worked. A trackpad sends lots of
tiny scroll nudges and the window threw each one away as "less than one
click". Now the nudges add up, so the page follows the trackpad smoothly; the
same fix applies to every other scrolling panel in the app.

- [x] `pane_sidebar_scroll` wheel test still green with its `Wheel` now delegating to the shared accumulator.
- [x] `test\win32\settings-window.ps1` section W on the test desktop: one WM_MOUSEWHEEL of -15 moves the page 0 -> 7px; eight of -15 move exactly as far as one -120 detent (60 vs 60); small upward deltas return it to 0. ALL PASS (173 assertions).

## Audit (every `WHEEL_DELTA` division under src/apprt/win32)

Fixed to carry the remainder through `wheel_accum.Accum`: SettingsWindow,
ShortcutGuideWindow, WhatsNewWindow, WhatsNewNotesView, ViewerFeedbackBar
(thumbnail carousel, whole detents), Activity Monitor (card carousel and table
rows, one accumulator each), ViewerTOCPanel (was proportional but dropped the
remainder), MachineChooser session list (the opposite bug: EVERY delta scrolled
three whole cards, so a touchpad flung it to the end - now proportional), and
the pane sidebar (already carried; now shares the module and gains the
reversal reset).

Left as they are, deliberately: the terminal surface (`Surface.handleMouseWheel`)
and the hero carousel (`Window.heroWheel`) already scale the delta as a float,
so small deltas move them. WM_MOUSEHWHEEL: none of these surfaces scrolls
sideways (the carousels are wheel-driven vertically by design), so there is no
horizontal handler to fix.
