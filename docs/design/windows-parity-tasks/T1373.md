# T1373 - Test-ExactPixel spends about 2.5 seconds to answer 'no', which makes it useless as a poll

## Summary

The shared pixel probes exit early when the color IS present and walk every pixel of the box when it is NOT - about 60k GetPixel calls for a full-width bottom band, ~2.5s per answer on this box (measured in T561: a wait loop built on it reported 2626ms for a dismissal that actually takes ~140ms). Any wait-for-condition oracle built on the negative answer therefore measures its own cost and burns wall clock on every acceptance run. Give the harness a sampled-grid probe (step in x and y, sized against the smallest feature it must not miss) and point the polling callers at it.

## In plain terms

Some of the automated screen checks look for a particular colour in a strip of a
window. Saying "it's there" was quick, but saying "it's gone" took about two and a
half seconds, so a check that waits for something to disappear was really timing
itself. After this, both answers take about a millisecond and every pixel is still
looked at.

## Goals

- [x] a shared exact-colour scan that is fast on the "not there" answer
- [x] it still examines every pixel (no sampling grid to size or outgrow)
- [x] the activity-monitor probes, including the dismissal poll, use it

## Validation criteria

- [x] the compiled scan gives the same answer as the old PowerShell walk (present, first hit, count, centroid, pixels examined), including boxes off the capture and an odd-origin half-pixel centroid - `test\win32\pixel-scan.ps1` section A, ALL PASS
- [x] a single 1px feature in the last pixel of a 1200x60 band is found - section B
- [x] a "no" over a 1200x60 band costs under 100ms (measured 0.2ms; the old walk ~6.4s on the same band, the negative control) - section D
- [x] activity-monitor.ps1 green with the migrated probes - acceptance-parallel run, ALL PASS (210 assertions); section J's poll now reports the banner gone after 15ms where T561 recorded 2626ms

## Approach

Not the sampled grid the Summary proposed: a grid has to be sized against the
smallest feature it must not miss, and that sizing is a claim nobody re-checks.
`test\win32\lib\PixelScan.ps1` scans a LockBits copy in C# at full fidelity, so
the negative answer is cheap without giving anything up. The cost of the old walk
was mostly the PowerShell function call per pixel, not GetPixel itself. T561's
grid in `Test-BannerUp` was retired back to full fidelity.
