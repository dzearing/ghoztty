# T3034 - PA-V02: the WebView2 browser, GPU and utility processes stay up for the rest of the session after the last viewer closes (webview2.zig:494)

## Summary

PA-V02 (audit-1, T2963). Host.deinit (webview2.zig:494-503) is the only environment release and runs only at app exit (App.zig:2848); Host.state never returns to .idle (:511-529). Cost (estimated from typical idle WebView2 trees, not measured): 150-300 MB over about four processes after any viewer has opened. Fix: count live controllers (viewer panes and the feedback composer); at zero start a 60 s grace timer, then release the environment and reset to .idle so the next viewer re-creates it. Risk: the next viewer pays a cold start (0.3-1 s, estimated); a second process on the same user-data folder keeps the tree alive anyway. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## In plain terms

The audit worried that once you open a document or web page in a side pane,
the hidden browser processes that draw it would keep running, and using
memory, until you quit Ghoztty. Measured on this box, they don't: about five
seconds after the last such pane closes, all of them exit by themselves, and
the next pane starts them again. Nothing needed changing. A test now checks
that this stays true.

## Goals
