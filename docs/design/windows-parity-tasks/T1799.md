# T1799 - Clean copy out of TUIs on Windows

## Summary

Mac commit d886ba4b5 (merged d1a2235bc, 2026-10-07) adds
`formatter.Options.reflow` and `src/terminal/hard_wrap.zig`. When a TUI
(Claude Code, anything on Ink/wrap-ansi) hard-wrapped and re-indented text
itself, copy rejoins the rows and strips their shared left margin. Deeper
indentation survives, a gutter glyph hangs in the margin, and author-wrapped
text (a 72-col git log body) stays byte-identical. URL detection follows the
same seams, so a URL a TUI broke across rows highlights, opens, previews and
copies whole. Reflow is always on for copy, copy-on-select and
`read_selection`; `+read`, `read_text` and `search_selection` stay raw, and
rectangle selections are untouched.

Everything is in shared `src/` (Surface.zig, terminal/, renderer/), so T1796
brings it. The Windows work is to confirm that every win32 copy route goes
through the reflowing core path rather than a raw dump: Ctrl+Shift+C and
Ctrl+C with a selection, copy-on-select, the context-menu Copy, and link
hover/open in `src/apprt/win32/`. Look for any win32-side selection-string
call that bypasses the core copy.

## In plain terms

When Claude Code (or any program that wraps its own text) prints a paragraph,
it breaks it into rows and indents every row. Copying that used to bring the
indentation and the row breaks along. Mac now cleans this up on copy; this task
proves Windows does the same no matter how you copy - keyboard, right-click
menu, or select-to-copy - and that a link broken across two rows is still one
link.

## Goals

- [x] Audit every win32 copy route for a path that skips the shared cleanup
- [x] An on-box script that replays Claude-Code-shaped output and copies it every way
- [x] Prove a broken URL is detected whole on hover, and `+read` stays raw

## Validation criteria

- [x] After T1796: replaying Claude-Code-shaped output (a wrapped paragraph,
      an indented code block, a long URL split across rows) into a pane and
      copying it through each win32 copy route gives the Mac result: no
      margin, the paragraph rejoined, code indentation kept, the URL whole.
      `test\win32\tui-copy-reflow.ps1` arms A-E: ctrl+shift+c, ctrl+c with
      a selection, ctrl+insert, context menu Copy, copy-on-select - ALL PASS
      (43 assertions).
- [x] A wrapped URL highlights on hover - arm F: a ctrl-hover on EITHER row
      of the broken URL puts the whole 89-char URL in the link bubble, which
      is the same reflowed link the click opens. The click itself is NOT RUN:
      opening a URL launches a browser on the user's desktop (go.md: never
      pull focus). Static check: `processLinks` reads the same
      `linkAtPos` selection with `.reflow = true`.
- [x] `+read` output for the same screen is unchanged (raw) - arm G, which
      also proves the reflow oracle rejects raw text (sensitivity control).
- [x] The script reads the clipboard through its own API, runs on the
      background test desktop, and takes no foreground - asserted by the
      foreground watcher at the end of the run.

## Findings

Static audit (`src/apprt/win32/`): the menu bar, the context menu, the
command palette and every keybinding dispatch the core `copy_to_clipboard`
action, whose formatter runs with `.reflow = true`; copy-on-select and link
hover/open/copy-URL are core code. The only win32-side selection dump is
`+read` (`IpcHandlers.zig`), which passes `reflow = false` on purpose. No
bypass exists, so no app code changed: the deliverable is the harness and its
guard row (`tui-copy-reflow` in `scripts\guard-due.ps1`).
