# T3377 - A crash the teardown postmortem reports never reaches the preserved red transcript (Write-Host bypasses the Tee)

## Summary

Every teardown crash report - Write-TestDesktopPostmortems and Write-TestDesktopUnclaimedCrashes, both via Write-GuiPostmortem / Write-GuiUnclaimedCrashDump in test\win32\lib\GuiPostmortem.ps1 - prints with Write-Host, which in PS5.1 goes to the information stream. The floor scripts capture their body as `& { ... } 2>&1 | Tee-Object -FilePath $transcript`, and 2>&1 does not carry stream 6, so the GUI POSTMORTEM block never reaches the transcript that Complete-TestTranscript preserves on a red run. Demonstrated 2026-11-21: `& { 'piped'; Write-Host 'hosted' } 2>&1 | Tee-Object f` leaves only "piped" in f. Consequence: the P1 red at 14:12 (T3376) had a ghoztty.exe crash dump written one second earlier and the preserved transcript says nothing about it. Fix shape: make the teardown blocks reach the transcript (e.g. 6>&1 / *>&1 at the Tee site in every floor script, or have the writers also emit to the pipeline where the caller does not | Out-Null them), with a harness audit so a new floor script cannot regress it, and a negative control.

## In plain terms

When an automated test run fails and the app crashed during it, the saved log of that failed run is supposed to say so. It did not: the crash report was printed to the screen but left out of the saved log, so whoever reads the log later sees a failure with no mention of the crash. After this change the crash report is in the saved log, next to the failure.

## Goals

- [x] the crash blocks the teardown prints reach the transcript a red run preserves, for every teed floor script at once
- [x] a negative control proving the Tee alone drops them
- [x] no double copy for a caller whose Tee already carries the host stream

## Fix

Not a change at the ~40 Tee sites. `lib\GuiPostmortem.ps1` now routes both writers through `Write-GuiPostmortemHosted`, which prints AND remembers each block (`Get-GuiPostmortemHostedBlocks`). `lib\Transcript.ps1`'s `Complete-TestTranscript` - the trailer every teed harness already must end on (section F of fail-transcript.ps1 enforces that) - calls `Add-TranscriptHostedPostmortems` after the Tee has closed the file and before a red run is copied, so the block lands in the preserved file ahead of the verdict line. A block already in the file (a `*>&1` caller) is skipped. The regression audit the Summary asked for is that existing section F rule: a new floor script cannot tee without ending on Complete-TestTranscript, and Complete-TestTranscript is now where the hand-off lives.

## Validation criteria

- [x] a red teed child run that prints a GUI POSTMORTEM in its body leaves that block in the preserved transcript, before the verdict - fail-transcript.ps1 I1-I4, ALL PASS (63)
- [x] negative control: the same run with the hand-off removed has the block on the console and NOT in the preserved file - I5
- [x] a `*>&1` caller gets it exactly once - I6; a green run preserves nothing but its live file carries the block - I7/I8
- [x] gui-postmortem.ps1 still ALL PASS (58) over the rerouted writers; guard rows fail-transcript now covers lib\GuiPostmortem.ps1
