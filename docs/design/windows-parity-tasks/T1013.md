# T1013 - Five win32 files are still mega files (4.8k-9k lines); ViewerPane.zig is 9,048

## In plain terms

Nothing a user can see. Several files behind the Windows app have grown so
large that the rules inside them — the ones that decide when a connection is
closed, when memory is freed, when a thread is joined — are impossible to find
and therefore impossible to check. T299 fixed the worst-behaved one and, more
usefully, worked out a way to do it that can be PROVEN not to change behavior.
This is the same job for the five that are bigger.

## The method T299 established

Worth reusing verbatim, because the risk in a refactor this size is not the
design, it is silently dropping a line:

1. **Cut on the section banners the file already has.** They mark the seams the
   author already saw.
2. **Each plane gets `const Owner = @import("Owner.zig");` and its functions
   become `pub fn f(self: *Owner, ...)`.** Circular imports are fine in Zig,
   and a `const f = plane.f;` alias in the owner file keeps `self.f(x)` method
   syntax working at every existing call site — which is what makes the diff
   mechanical instead of a rewrite.
3. **The alias block IS the owner's public surface.** Put it at the top under
   its own banner, and document it as such.
4. **Move the header commentary with the code it describes.** A rule read where
   it is enforced is the whole point of the split.
5. **Prove it is a pure refactor rather than asserting it**: compare the set of
   top-level function signatures before and after (must be identical), and
   diff the multiset of non-comment code lines — every difference must be one
   of four shapes (a `pub` marker, a moved declaration, a `self.f(x)` rewritten
   to `f(self, x)`, or a static now qualified with its owning file).
6. **Prove the moved tests still run** by deliberately breaking one in each new
   file and watching it go red under its new module name, then reverting.
