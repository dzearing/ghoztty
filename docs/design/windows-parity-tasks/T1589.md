# T1589 - The session roster and machine chooser still talk over a WEDGED local-agent link instead of saying it is unreachable

## Summary

Found landing T764. sharedConnection now refuses to hand a wedged link (state reconnecting/reattaching) to a NEW surface, but sharedConnectionIfWarm still gates on 'not dead' - so SessionRoster's probe, the machine chooser's local warm connection and the agent upgrade check all still send requests over a connection that answers nothing, and each pays its own timeout before it can say anything to the user. The chooser is the visible one: opening it during a wedge should say the local machine is unreachable rather than sitting on a spinner until the probe gives up. Decide per caller whether 'warm' should mean 'live' (agent_recovery.handsToNewSurface) or whether the caller needs the wedged link on purpose - the upgrade check reads peerBuildVersion, which is cached locally and needs no round trip.

## In plain terms

When the background helper that keeps your terminal sessions alive stops
answering — it is still running, it has just stopped talking — the app did not
notice. Opening the machine list, or the list of your saved sessions, kept
talking into that silence and sat on a spinner until it gave up, one slow
timeout at a time. After this, the app checks whether the link is actually
carrying anything before it uses it: if it is not, it asks the helper again
over a fresh connection, and if that gets nowhere it tells you the machine is
unreachable instead of spinning.

## Goals

- [x] One place decides whether the shared link can carry a request, with its
      own name and its own test
- [x] The machine chooser, the session list and the upgrade check all ask that
      question instead of "is it not-dead"
- [x] The one caller that sends nothing keeps the old gate, and says why in the
      code

## Validation criteria

- [x] `agent_recovery.carriesRequests` returns false for `reconnecting` /
      `reattaching` / `dead` and true for `connected` / `degraded`, and cannot
      silently diverge from `handsToNewSurface` (unit test, `none` lane).
- [x] No caller that spends a timeout on a round trip still gates on
      `sharedConnectionIfWarm` (source check over `src/apprt/win32/`).
- [x] `pushLayoutBlobs` deliberately still gates on warm, with the reason in
      the code (it enqueues without waiting, and skipping would lose the push
      because convergence is keyed on connection identity).
- [x] The standing floor is green: `floor-lane.ps1 -Lane all` (lib + none +
      win32 + agent).
