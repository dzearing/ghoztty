# T1589 - The session roster and machine chooser still talk over a WEDGED local-agent link instead of saying it is unreachable

## Summary

Found landing T764. sharedConnection now refuses to hand a wedged link (state reconnecting/reattaching) to a NEW surface, but sharedConnectionIfWarm still gates on 'not dead' - so SessionRoster's probe, the machine chooser's local warm connection and the agent upgrade check all still send requests over a connection that answers nothing, and each pays its own timeout before it can say anything to the user. The chooser is the visible one: opening it during a wedge should say the local machine is unreachable rather than sitting on a spinner until the probe gives up. Decide per caller whether 'warm' should mean 'live' (agent_recovery.handsToNewSurface) or whether the caller needs the wedged link on purpose - the upgrade check reads peerBuildVersion, which is cached locally and needs no round trip.
