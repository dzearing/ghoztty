# T3611 - Acceptance scripts still call Get-CimInstance unbounded (about 100 scripts, 190 calls): convert them to Get-OsProcess / Get-BoundedCimProcess and widen wmi-bound-audit's gate from lib\ to the whole suite

## Summary

T2024 gave test\win32\lib a kernel process table (lib\ProcessTable.ps1: Get-OsProcess, which carries ProcessId/ParentProcessId/Name/ExecutablePath/CreationDate and -CommandLine) and a bounded WMI query (Get-BoundedCimProcess, which throws 'WMI did not answer' instead of returning an empty list), converted the shared libraries, and gated them with test\win32\wmi-bound-audit.ps1 section C. The acceptance scripts themselves were left: wmi-bound-audit prints 'INFO: <n> acceptance script(s) still make <m> unbounded WMI call(s)' every run. Convert them in batches (a process lookup by name/path/parent -> Get-OsProcess; anything reading PrivatePageCount, WorkingSetSize or similar -> Get-BoundedCimProcess and a verdict line naming a WMI timeout), re-run each converted script's harness, and when the count reaches 0 turn the INFO line into a gate over test\win32 so an unbounded call cannot come back. Watch cleanslate-audit: a private ghoztty kill via Get-OsProcess still matches its Get-<X>Process query pattern, which is intended.
