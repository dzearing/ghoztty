# T1872 - Ctrl+C in an image viewer pane copies the picture to the clipboard (Mac 1d513083a, split from T1803)

## Summary

Mac's image pane copies the image on Cmd-C (ViewerImageView, commit 1d513083a). On Windows an image pane is a WebView2 page and Ctrl+C with nothing selected copies nothing. Translation: claim ctrl+c in an image-mode ViewerPane (viewer_accel pane chord, image mode only), decode the file with WIC and put CF_DIBV5 + PNG on the clipboard. Validation: a test-desktop script presses ctrl+c at an image pane and reads the clipboard's image dimensions back.

## In plain terms

When you open a picture in a side pane and press Ctrl+C, nothing used to be
copied, so pasting into a chat or a document gave you nothing. Now Ctrl+C (or
Ctrl+Insert) copies the picture itself, the way it does on the Mac, and text
panes copy their selected text exactly as before.

## Goals

- [x] Ctrl+C / Ctrl+Insert at an image pane copies the picture
- [x] Every app that pastes pictures can read it: a standard bitmap, plus the original PNG when the file is one
- [x] Text, markdown and website panes keep their own copy

## What landed

- `src/apprt/win32/image_copy.zig` (new): WIC decodes the viewed file's first
  frame to straight-alpha BGRA. The clipboard gets `CF_DIBV5` (bottom-up,
  BI_BITFIELDS, sRGB; the system synthesises CF_DIB/CF_BITMAP) and, per
  `pngPlan`, a `"PNG"` format: the file's own bytes when it IS a PNG, a fresh
  encode only for a see-through non-PNG, nothing for an opaque photo.
  WIC rather than the existing GDI+ decoder because GDI+ has no WebP/AVIF/HEIF.
- `src/apprt/win32/image_clipboard.zig` (new, pure, none lane): the DIBV5
  packing, the PNG plan, signature and alpha checks.
- `viewer_accel.copyChord` + `ViewerPane.claimsChord`/`WM_APP_VIEWER_ACCEL`:
  an image-mode pane claims the copy chords ahead of `pageOwns`; every other
  mode leaves them to the page.

Left for follow-ups: the file half of Mac's copy (T1909), EXIF orientation
(T1910), SVG (T1911).

## Validation criteria

- [x] Ctrl+C at a focused image pane puts the image on the clipboard (dimensions read back by a test-desktop script). `test\win32\viewer-image.ps1` section K: K1 a 4000x3000 PNG reads back 4000x3000 with a PNG format whose length equals the file's; K2 an 800x400 JPEG reads back 800x400 with no PNG; K3 ctrl+Insert copies too. ALL PASS (51), and `-NegativeControl` still scores exactly its 2 failures.
- [x] Ctrl+C in a markdown/website pane is unchanged (the page's own copy). Section K4: ctrl+A, ctrl+C in a `.txt` viewer puts the file's text on the clipboard and logs no image copy.
- [x] Unit tests: `image_clipboard.zig` (none lane: header parsed back by `dib_packed.parse`, bottom-up rows, refusals, PNG plan), `image_copy.zig` (win32 lane: a real WIC decode keeps straight alpha; a non-picture is refused), `viewer_accel.copyChord`.
