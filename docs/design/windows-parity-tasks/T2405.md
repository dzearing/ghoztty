# T2405 - Renaming a window or group in the Windows pane sidebar (or Change Window Title) never moves anything in the all-windows list, as on Mac (Mac 7e2d0a9da)

## Summary

Mac main 7e2d0a9da: committing a rename writes the list as shown into the shared order (PaneSidebarWindowGrouping.renaming over pinned), so neither the never-dragged name order nor a name-neighbour placement re-sorts the renamed item, in every window's list. Only moves are what the new name asks for: a window given another group's '<project>: ' goes into it at the edge nearest where it was; a new group's name makes that group where it was; losing '<project>: ' stays beside the group it left. A renamed group keeps its place (its order key renamed); named as another group it merges into that one where that one is; emptied, its windows stand where it was. Change Window Title renames the same way; programmatic titles (+rename, +new-window --title) still place by name. Windows: pane sidebar order/grouping code (T2337/T2339) - apply the same rules and add acceptance in the sidebar rename/order scripts. Ref docs/reference/pane-sidebar.md on main ('A rename never moves anything').
