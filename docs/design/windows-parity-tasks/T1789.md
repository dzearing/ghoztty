# T1789 - a config reload that changes background-opacity does not make open windows translucent (or opaque): only window creation applies it

## Summary

Found by T1787. Window.onConfigChange re-applies background-blur (applyBackgroundBlur) but never background-opacity: setTranslucent runs only at window creation, and composeOpaqueLayer (viewer hosts, tab-rename box) only when a child is created under a translucent config. Mac re-syncs window opacity on reload. Reloading 1.0 -> 0.6 leaves every open window opaque (the renderer's alpha is ignored until setTranslucent(true)); new windows are fine. Fix: on reload, call setTranslucent(opacity < 1 and not toggled-opaque) per window and composeOpaqueLayer on existing viewer hosts; cover with a reload step in test\win32\translucent-window.ps1.
