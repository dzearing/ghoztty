# T950 - A CLI flag written without its value (--target dev) is still dropped in silence

## In plain terms

`ghoztty +close --target dev` looks right and does nothing. Every flag that
carries a value wants an `=` — `--target=dev` — and writing it with a space
instead leaves the flag empty and the word `dev` floating loose, which the
terminal quietly ignores. T852 made a MISSPELLED flag say so; a flag spelled
correctly but written the other way is still silent.

## Summary

Carved out of T852. That task gave each forwarding verb an allowlist of flag
NAMES (`src/cli/verb_flags.zig`) and rejects any `--flag` not on it. It
deliberately does not look at whether a flag that needs a value got one: the
check splits at the `=` and compares only the name, so `--target dev` matches
the entry `target`, passes, and is forwarded as a valueless `--target` that
`parseVerbArgs` never binds.

Two shapes, both silent today:

- **A value flag with no value**: `--target dev`, `--lines 20`,
  `--title my window`. The value becomes a stray positional; on
  `+set-banner` it silently becomes banner text instead.
- **A bare flag given a value**: `--clear=1`, `--no-activate=true`. Harmless
  today (the server matches on the exact string and drops it), but it is the
  same wrong-shape-accepted-quietly hole.

The fix belongs in the same place: `Spec.flags` grows a notion of "carries a
value" (an entry written `target=` versus a bare `no-activate` reads well and
costs nothing at the call sites), and `unknownFlag` reports a distinct
`ValueRequired` shape — the message should say the form, `--target=<value>`,
not just "wrong".

Watch out for:

- **`+send-keys` has its own parser** and the same gap (`--target foo`);
  fix both or say why not.
- **The `-e` tail and post-`--` text are never checked** and must stay that
  way — a command's own flags are not ours.
- **Positive controls per verb**: every flag in the T852 allowlist must still
  be accepted in its `=` form.

## Resolution

`Spec.flags` now encodes the shape: an entry ending `=` carries a value, a
bare entry is a switch. The switches are exactly the five arguments both
servers match whole (`no-activate`, `from-focused`, `cwd-implicit`,
`config`, `clear` — `parseVerbArgs`' `std.mem.eql` arms and IPCServer.swift's
`arg ==` arms), and a none-lane test pins that set so a future switch cannot
be added as a value flag or vice versa. `checkFlag` returns a `Problem`
(`unknown` / `value_required` / `value_not_allowed`); the `Checker` also keeps
the word after a valueless flag, so the message shows the literal fix
(`write it as --target=dev`). `+send-keys` keeps its own parser and borrows
`checkFlag` only to word the error. Both platforms: the CLI is the shared Zig
core, so the Mac binary gets the same check (the `lib` lane compiles it).
