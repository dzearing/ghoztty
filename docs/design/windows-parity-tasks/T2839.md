# T2839 - The installed release crashed in the NVIDIA OpenGL driver's own worker thread (nvoglv64 DrvPresentBuffers, access violation) and took every window down

## Summary

2026-11-08 13:54:20. The installed release crashed: C:\Users\David\AppData\Local\Programs\Ghoztty\ghoztty.exe, v26.11.8.437, pid 48348. Exception 0xc0000005 in nvoglv64.dll 32.0.16.1664 at offset 0xa71735. WER APPCRASH, report e3455717-0d7a-46d9-822b-cd1f33520a5b. Dump: %LOCALAPPDATA%\CrashDumps\ghoztty.exe.48348.dmp (67 MB). The faulting thread is entirely driver-owned: BaseThreadInitThunk -> nvoglv64 (DllMain, DrvSwapLayerBuffers, DrvValidateVersion) -> nvoglv64!DrvPresentBuffers+0x2f015, with no ghoztty frame on it. That is the shape of the driver's threaded-optimization worker presenting for a context or surface the app had already torn down or resized. Every window disappeared. The sessions survived in ghoztty-agent: both go-loop lanes' claude processes (25104, 12384) kept running, and the health checks then read windows=0 for both lanes. Investigate: (1) the other threads in the dump at the crash, especially whether a ghoztty thread was mid wglMakeCurrent / wglDeleteContext / DestroyWindow / resize; (2) whether NVIDIA threaded optimization (a per-app profile 'Threaded optimization = Off', or __GL_THREADED_OPTIMIZATIONS) avoids it; (3) whether the T48 freeze watchdog should also relaunch the app after a crash, so a GPU-driver fault costs seconds rather than every window until the user notices.
