# T2329 - No on-box check drags a pane over the all-windows sidebar and sees the empty stash well open under this window's last pane, then close on release (T2313 follow-up; unit-tested only)

## Summary

T2313 ported Mac b7de64ce8: in the all-windows scope the empty tray's well
appears only while a pane is dragged, under this window's last pane, and the
rows below it open to make room (`pane_sidebar.addDragWell`, called from
`PaneSidebar.rawLayout` while `drag_active`). It is covered by unit tests in
`pane_sidebar.zig` only. The geometry line already carries it: `pane sidebar
outline ... tray=<x>,<y>` during the drag, `tray=-` at rest (logged from
`setDragActive`). An on-box check belongs beside the existing pane-drag
harness (`test\win32\pane-sidebar-drag.ps1`): start a pane drag with the
sidebar in all-windows, read `tray=` and a lower window head's Y moving down
by one row, drop into the well and see the pane stashed, and read `tray=-`
after release.

## Validation criteria

- [ ] during a drag in all windows the outline line reports `tray=<x>,<y>` under this window's last pane, and the next window head sits one row lower than at rest
- [ ] dropping on the well stashes the pane; after release the line reads `tray=-` and the heads are back where they were
- [ ] no well while this window already has a stashed pane
