# T2329 - No on-box check drags a pane over the all-windows sidebar and sees the empty stash well open under this window's last pane, then close on release (T2313 follow-up; unit-tested only)

## Summary

T2313 ported Mac b7de64ce8: in the all-windows scope the empty tray's well
appears only while a pane is dragged, under this window's last pane, and the
rows below it open to make room (`pane_sidebar.addDragWell`, called from
`PaneSidebar.rawLayout` while `drag_active`). It is covered by unit tests in
`pane_sidebar.zig` only. The geometry line already carries it: `pane sidebar
outline ... tray=<x>,<y>` during the drag, `tray=-` at rest (logged from
`setDragActive`). An on-box check belongs beside the existing pane-drag
harness (`test\win32\pane-sidebar-drag.ps1`): start a pane drag with the
sidebar in all-windows, read `tray=` and a lower window head's Y moving down
by one row, drop into the well and see the pane stashed, and read `tray=-`
after release.

## In plain terms

With the sidebar listing every window, dragging a pane opens an empty "drop
to stash" slot under this window's panes, and the windows below shuffle down
to make room; letting go closes it again. Only unit tests checked that. Now a
real drag on the test desktop checks it, so a regression shows up red.

## Goals

- [x] an on-box drag in the all-windows sidebar that sees the well open, take a drop, and close
- [x] the same drag with a pane already stashed opens no well

## Validation criteria

- [x] during a drag in all windows the outline line reports `tray=<x>,<y>` under this window's last pane, and the next window head sits one row lower than at rest - `pane-sidebar-foreign-drag.ps1` section C: `tray=165,297` under the last row (y=247, same x), the head below moved 298->347 (49 px), A's first row unmoved
- [x] dropping on the well stashes the pane; after release the line reads `tray=-` and the heads are back where they were - section C: `tray hot=1` over the well, `pane drop stashed index=`, visible panes 2->1, the row is `g0s`, `tray=-`, head back at y=298
- [x] no well while this window already has a stashed pane - section D: dragging the stashed row, every mid-drag outline line reads `tray=-`; Escape cancels and the pane stays stashed
