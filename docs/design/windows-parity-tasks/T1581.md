# T1581 - Nothing checks that the viewer's two MIME tables still agree, so they drifted for a month unnoticed

## Summary

viewer_content.mimeType carries a doc comment saying it is byte-identical with Mac's ViewerView.mimeType(forExtension:), and that claim is enforced by nobody. T1183 added ten image rows to the Zig table alone on 2026-09-05 and the divergence survived until T750 read both files by hand on 2026-09-15. The same is true of highlightLanguage next door. Wanted: an audit that parses both tables and fails when the row sets differ, in a lane this seat runs (a PowerShell harness under test\win32\ can read both files without a Swift toolchain). It is the only thing that makes 'byte-identical' a fact rather than a comment.
