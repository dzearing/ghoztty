# T1556 - The Windows About box is one text blob where Mac has labelled Version / Build / Commit rows

## Summary

Mac's About panel (`macos/Sources/Features/About/AboutView.swift`) is a
structured card: an app icon, a name, a tagline, then LABELLED rows - Version,
Build, Commit - each selectable, with the linked ones rendered as links in
place. It also names a tip build "Tip Release" rather than printing the raw
version string.

The win32 About box is a single block of preformatted text
(`Surface.showAboutDialog`) with `Ghoztty <version>` on top and
`Commit: / Mode: / Runtime: / PID: / Started: / Executable:` underneath, and
since T714 a row of links beneath that. It answers the same questions, but it
reads as a diagnostic dump rather than an About panel, and the version string a
tip build shows (`1.4.0-users-dzearing-windows-amd64-+8bf37b334`) is the raw
build id where Mac shows two words.

Worth noting what is deliberately NOT parity here: the win32 box carries
provenance Mac does not (Mode, Runtime, PID, Started, Executable) because it is
also the answer to "which of my several installs is this window running" - the
T52/T1205 job. So this is a presentation task, not a content cut: the same
facts, laid out as labelled rows, with the stale-build paragraph kept.

## In plain terms

The Windows About box lists everything it knows in one paragraph of text, which
makes it look like a debug readout. The Mac one lays the same facts out as tidy
labelled rows and says "Tip Release" instead of printing a long internal build
id. This is about making the Windows one read like the Mac one.

## Goals

- [ ] Version / Build / Commit read as labelled rows, not a text block
- [ ] A tip build says so in words instead of printing its raw build id
- [ ] The Windows-only provenance (mode, runtime, pid, started, exe) keeps its
      place - this is a layout change, not a content cut
- [ ] The stale-build warning and its Restart offer are unchanged
- [ ] The T714 link row still sits under the rows

## Validation criteria

- [ ] Layout is a pure, unit-tested function like every other dialog band here
- [ ] `test\win32\ipc-version.ps1` still reads the build's real commit and
      version out of the box
- [ ] A pixel or control probe shows the rows aligned in both themes
