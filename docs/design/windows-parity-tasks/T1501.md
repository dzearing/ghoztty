# T1501 - A test fixture can plant a filename Windows quietly renames, so the harness proves less than it says

## Summary

Measured on this box during T1499: Set-Content -Path (Join-Path $d '._.') creates a file named '._' - PowerShell strips the trailing dot and reports success - so a fixture that means to plant an AppleDouble root sidecar plants something else and the harness is quietly weaker than it reads. That is exactly what happened to T1436's torn-package fixtures: they reproduced the real package's contents "exactly" apart from the one name that defeats the delete, so every arm stayed green while the real heal could not delete the real package, and the box went red for four lanes. The fix in T1499 was local (write fixtures through an extended '\\?\' path). What is missing is the general guard: a meta-audit over test/win32/ that flags a fixture whose planted filename PowerShell cannot create verbatim - a trailing dot or space, a reserved device name (CON, NUL, AUX, COM1..9), a name differing from its intended form only by characters the parser strips - and says which call site to convert. Same shape as the existing script-wide audits (body-complete, verdict-exit): cheap, non-interactive, and it fails on a planted example of its own.
