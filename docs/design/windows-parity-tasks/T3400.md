# T3400 - Linux L8e: when the local agent dies or restarts under a running GTK app, its windows recover in place

## Summary

The Mac (T12e, LocalAgentManager link observer) and win32 (LocalAgent.setStateObserver, recover_now) watch the shared connection and rebuild agent-backed windows in place when the agent restarts; win32 also refreshes a stale agent and handles protocol skew through the mandatory-update path. The GTK LocalAgent (T3337) only notices a dead agent when the NEXT pane asks for a connection, so existing panes go dead with no recovery. Port the link-state observer, the settle-then-recover rule, stale-agent refresh and the skew notice.

## In plain terms

On Linux, if the background process that keeps your shells alive crashed or
was restarted while Ghoztty was open, every terminal pane froze until you
quit and relaunched the app. Now the app notices within a few seconds,
starts a fresh background process, and puts each pane back exactly where it
was - same split, same name, same folder - with a note that the session was
restarted. Viewer panes are not disturbed.

## Goals

- [x] Watch the shared agent link; settle a drop for 5 s, waive it when the agent pid is confirmed dead (win32's pure `agent_recovery.zig`, shared)
- [x] Rebuild only the terminal panes that rode the dead link, in their slots, re-attaching or relaunching their sessions; viewers untouched
- [x] Replaced panes DETACH (session spared); a user close still ENDS
- [x] Retry a failed re-dial on win32's backoff schedule, then give up loudly
- [x] A new pane opened while the agent is dead re-dials and triggers the rebuild (`newSurfaceVerdict`); a wedged link gives an exec pane
- [ ] Stale-agent refresh and the protocol-skew notice -> split to T3600
