# T3797 - Linux AppImage: opening a link hands the host browser AppRun's LD_LIBRARY_PATH, GIO and GStreamer paths

## Summary

T3658's AppRun sets LD_LIBRARY_PATH, GIO_MODULE_DIR, GST_* and GDK_PIXBUF_MODULE_FILE into the AppImage mount and records the originals (GHOZTTY_APPIMAGE_ORIG_*/GHOZTTY_APPIMAGE_UNSET). appimage_env.restore() gives them back to pane shells and the agent, but not to the two URL paths: internal_os.open (src/os/open.zig, xdg-open; shared code - its snap branch already drops LD_LIBRARY_PATH) and Viewer.zig's gtk_uri_launcher_launch, which spawns through GIO with this process's env. A host browser started from a link in an AppImage launch loads the AppImage's libraries. Fix: restore for both (open.zig: an env map through appimage_env when the marker is set; the URI launcher: a GAppLaunchContext with the variables set/unset, or route through the same open path). Validate in test/linux/package-appimage.sh with a fake xdg-open that dumps its env.
