# T1658 - A reset leaves the dying turn's acceptance batch running, and the next turn's own test runs collide with it

## Summary

On 2026-09-18 turn N launched a 10-script acceptance batch in the background and then reset context. The batch kept running under the old session; turn N+1 claimed the loop, read the batch's partial summary file, and started its own acceptance scripts - which overlapped the still-running batch. Three scripts scored red inside that batch (chooser-sessions-remote 2 FAIL, chooser-resume-remote 3 FAIL, activity-monitor-dialed 10 FAIL) and all three were ALL PASS standalone minutes later, so the overlap cost a full re-run of each and very nearly cost a mis-filed flake task. go.md step 3 already forbids overlapping lanes and scripts, but nothing at a turn boundary can SEE a batch the previous turn left behind: the claim reports stranded FILES, not stranded RUNS. Give the claim (or floor-lane/suite-run) a way to notice a live acceptance run owned by another session - a lock file or pid marker that suite-run takes and a stale one clears - so the next turn is told to wait rather than discovering it through red scripts.
