# T3070 - Windows font discovery ignores bold and italic when matching a family, so a styled slot gets the first face of the family (discovery.Windows matches)

## Summary

Found in passing by audit-1 (T2964, PA-C07). src/font/discovery.zig:1091-1099 `DiscoverIterator.matches` checks only family and codepoint; Descriptor carries bold and italic (:61-62) and the fontconfig path honours them (:136-143), but the Windows scanner does not, so SharedGridSet's bold/italic discovery for a configured font-family returns whichever face of the family it opens first (INFERRED: the faces' enumeration order decides). Fix: score faces by weight/slant (FreeType style flags or OS/2 usWeightClass) and prefer the exact style. Risk: low. Windows only. Findings: docs/design/perf-audit/audit-1/C-findings.md.
