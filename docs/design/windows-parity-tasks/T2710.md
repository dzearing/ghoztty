# T2710 - pane-drag-ghost.ps1 does not drive a rearrange-header drag, a strip drag or a sidebar-row drag: the ghost's 'header shows it, strip and row do not' rule is held only by a unit test

## Summary

Filed from T2703. `test/win32/pane-drag-ghost.ps1` proves the ghost card for grab-handle drags of a terminal and a viewer. Three entry points are not driven:

- a rearrange-mode header drag, which should show the card (same `beginRearrangeDrag` -> `updateRearrangeDrag` activation as the handle);
- a strip (tucked pane) drag, which should show none (`RearrangeDrag.blade`);
- a pane-sidebar row drag, which should show none (`RearrangeDrag.list`).

Today the rule is held by `pane_drag_ghost.wantsGhost` (unit test) and the gate in `Window.updateRearrangeDrag`. Add the three claims, borrowing setup from `rearrange-drag.ps1` (header), `stack-collapse-drag.ps1` (strip) and `pane-sidebar-drag.ps1` (row).
