# T1629 - git-commit-guard reports SWALLOWED WORK for every file a wildcard -Paths entry legitimately matched

## Summary

scripts\git-commit-guard.ps1 commit -Paths 'test\win32\*.stamp.json' stages and commits the right files, then REFUSES the commit (exit 5, 'SWALLOWED WORK: 18 path(s) it was never asked to commit') because the readback compares the commit's file list against the literal pathspec strings rather than expanding globs. Hit on 2026-09-16 closing T805: a correct commit had to be reset --soft and re-made with 26 paths spelled out. The T948 protection is right to exist - it must keep catching another window's work - so the fix is to expand wildcards (git's own pathspec matching) when checking the readback, with an arm in section W of test\win32\go-loop-guard.ps1 proving a genuine foreign path still fails while a glob-matched one passes.
