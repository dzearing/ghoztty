# T3062 - PA-C05: the ConPTY output pipe is created at the 4 KB default size, so conhost blocks whenever the reader holds the lock (pty.zig CreatePipe nSize 0)

## Summary

PA-C05 (audit-1, T2964). src/pty.zig:417 `CreatePipe(&pty.out_pipe, &pty.out_pipe_pty, null, 0)` (upstream code, Windows-only branch) takes the system default buffer, while the reader's buffer is 64 KB (Exec.zig:1560). At 2 MB/s 4 KB is ~2 ms of output, so any reader stall (lock wait, a +read, a Debug parse) blocks conhost's write, and batch size is capped at the pipe size. Cost: small in steady state (lock wait 2.6-2.8% in T1464); it is the prerequisite for PA-C03's coalescing. Fix: pass nSize 64 KB-1 MB; re-check the '~4 KiB pieces' assumption documented at Remote.zig:2219. Risk: low. Findings: docs/design/perf-audit/audit-1/C-findings.md.
