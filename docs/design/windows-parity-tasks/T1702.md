# T1702 - Let acceptance scripts type into and read the web feedback composer from the background test desktop

## In plain terms

The box you type feedback into is a small web page. Our automated tests run on a hidden desktop that has no keyboard, so until now they could check that the box opened but could not type into it. They had to test an older, hidden text box instead. This task adds a test-only way to type into the real box and read it back. The old box can now be retired (T1703, T1704). Nothing changes for users.

## Summary

The six viewer-feedback harnesses drive the composer with window messages, which only reach the RichEdit fallback; a Chromium window takes no posted WM_CHAR and SendInput is dead on the test desktop (T233). Build a test-only driver - the WebView2 DevTools protocol over a remote-debugging port (Input.insertText / Input.dispatchKeyEvent / Runtime.evaluate on the composer page) in test\win32\lib - so a script can type, press chords and read the document back on the web surface. Feasibility first: webview2.zig calls EmbeddedBrowserWebView.dll's CreateWebViewEnvironmentWithOptionsInternal directly, bypassing WebView2Loader, so WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS may not be honoured; if not, pass environment options carrying the port only when a test-only env var asks for it, and prove a release build ignores it. Split out of T937.

## Outcome

- **Feasible with no product code.** The runtime reads `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` inside `EmbeddedBrowserWebView.dll`, so the loader-less path honours it. Probe on 2026-09-23 (runtime 153.0.4234.48): the debug app's browser process ran with `--remote-debugging-port=<n>` and `/json/list` returned the viewer page. The user's installed release, running at the same moment, had no such switch. The app never reads the variable, so no release-build guard is needed. It is the runtime's own documented switch and is only set in the environment of an app a test launches.
- **Driver:** `test\win32\lib\WebViewCdp.ps1`.
  - `Enable-WebViewCdp` draws a port with `Resolve-TestPort` and arms the env var.
  - `Find-CdpComposer` finds the composer by its `#c` plaintext-only box and turns on focus emulation.
  - `Send-CdpComposerText` / `Send-CdpKey` (named keys, letters, digits, Ctrl/Shift/Alt) type into it.
  - `Get-CdpComposerText` / `Wait-CdpComposerText` read the document back using the page's own `walk()` rule, not `innerText`, which miscounts the placeholder `<br>`.
  - Everything rides a `ClientWebSocket` CDP client (`Invoke-Cdp`, `Invoke-CdpEval`).
- **Limit, documented in the lib header:** chords that NATIVE claims (Ctrl+Enter sends, Esc closes) are not proven by this driver. Native reads modifiers from `GetKeyState`, which a synthetic CDP event does not move. T1703 keeps driving those through the band's window messages.
- **Found on the way:** T1705. An Enter at the end of the box can leave the engine's text-form placeholder (`"x\n\n"`), which `walk()` counts as a second break.

## Goals

- [x] Prove (or disprove) that the loader-less environment honours the runtime's remote-debugging switch
- [x] A reusable driver in test\win32\lib: type, press keys and chords, read back
- [x] Acceptance that uses it against the real composer from the background test desktop

## Validation criteria

- [x] The runtime exposes a DevTools endpoint for a test-launched debug app. Verified by a scratch probe (`/json/list` answered with the viewer page) and by section H of `test\win32\viewer-composer.ps1` finding the composer's page on a drawn port.
- [x] Negative control: an unarmed port lists no pages (section H, first assertion).
- [x] Typed text plus an Enter reads back from the page (`héllo\nworld`), including a non-ASCII letter.
- [x] Page-owned chords work: Ctrl+Z takes the typing back, Ctrl+Y restores it, Backspace removes exactly one character.
- [x] The typing reached the HOST. After a close and reopen, the new page echoed `bytes=11 lines=2` (the UTF-8 size of `héllo\nworl`) and read back the same text, seeded from the pane's buffer.
- [x] `test\win32\viewer-composer.ps1`: ALL PASS (41 assertions), stamped. The guard-due `viewer-composer` row now covers the lib.
