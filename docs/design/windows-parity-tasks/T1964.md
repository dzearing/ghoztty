# T1964 - Mac half of T1950: a standalone probe a user runs inside a Screen Sharing session that reports what renders, CPU, busy threads, fps and echo latency, with the remote-effects mode off vs auto

## In plain terms

Windows now has a script a user can run inside a Remote Desktop session that
says where Ghoztty's cost goes there. A Mac reached over Screen Sharing has
no equivalent, so a "it is slow over Screen Sharing" report would start from
guesswork, the way the Windows one did.

## Summary

Platform symmetry for T1950's `scripts\rdp-perf-probe.ps1` (read its header
and `docs/claude/build.md`, "Slow over Remote Desktop or on a Cloud PC").
Translate the instrument, not the implementation:

- Snapshot (read-only): whether the session is remote (Screen Sharing:
  `CGSessionCopyCurrentDictionary` / `kCGSSessionOnConsoleKey`, or the
  screensharingd process), the GPU (`system_profiler SPDisplaysDataType`), and
  for each running Ghoztty: version, CPU in cores over N s, busy threads,
  memory, windows/panes from `+list --json`, and the renderer's log lines.
- `-Measure`: a separate, isolated instance (own socket via
  `GHOZTTY_IPC_SOCKET`/suffix, persistence off, `GHOZTTY_PERF=1`) with a spinner
  window and a focused shell window; fps and present cost per pane, CPU, and
  echo latency (`+send-keys` then `+read` polling, with the `+read` round trip
  reported beside it), once with the T1952 remote-effects mode off and once on
  auto.
- A shell script under `scripts/` so it runs on a stock Mac.

## Validation criteria

- [ ] The probe runs on a console Mac session and reports "not remote" plus
      real CPU, GPU and pane numbers for a running debug build.
- [ ] `-Measure` produces a row per mode with every echo sample answered and
      the per-pane fps of the spinner.
- [ ] An acceptance script holds it to those numbers, with a negative control.
- [ ] One run from inside a real Screen Sharing session is attached.
