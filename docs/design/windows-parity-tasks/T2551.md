# T2551 - Composition step 5a: the bell border's fade on the composition path is one compositor animation declared to DirectComposition, not a UI-thread opacity step per frame

## Summary

Composition step 5a: the bell border fade on the visual path is declared to DirectComposition once (easeInOut as 8 Hermite cubics on the effect group opacity) and run by DWM; the UI thread only books the end. Oracle: comp-present E4a/E4b/E7a (0 UI steps) + scripts\bell-fade-onscreen.ps1 (advance, hold, jump; stepped A/B control).

## In plain terms

When a pane rings its bell it gets a soft yellow frame that fades in and out.
On the new drawing path that fade used to be pushed forward one step at a time
by the app itself, so a busy app made it freeze and then snap. Now the app
tells the system compositor "fade this in over 0.3 seconds" once, and Windows
plays it at the screen's own refresh rate, however busy the app is. It is the
first animation moved over this way; the pane glides follow (T2553-T2556).

## Goals

- [x] A reusable way to hand an eased fade to the compositor (the easing curve as a run of cubic pieces DirectComposition can play)
- [x] The bell frame's fade on the composition path uses it: one declaration, no per-frame work on the UI thread
- [x] The old way stays for a pane that is not on the composition path, and as a debug A/B arm
- [x] An on-screen film that scores whether the fade moves on every refresh, and can tell the two apart

## Design (technical, mine per go.md 5b)

- `comp_overlay.fitCurve` cuts any 0..1 ease into C1 Hermite cubics (value
  and slope matched at every joint); DirectComposition has no easing curves,
  only `AddCubic` polynomial segments. 8 segments keep `easeInOut` within a
  quarter of one 8-bit opacity step (unit test in `bell_math.zig`).
- `Layer.animateOpacity` builds an `IDCompositionAnimation` (device slot 25;
  AddCubic 5, End 8 per dcompanimation.h 10.0.26100) and sets it with
  `IDCompositionEffectGroup::SetOpacity(animation)` (slot 3), one commit.
- `BellBorder` on the visual path declares the fade and arms ONE timer for the
  end (the `fade done` line, hiding a frame that faded out). A retarget reads
  the current value off the curve by the clock and declares from there; a
  rebuilt tree mid-fade re-declares from the reached value. The popup path
  is unchanged (its frame is a separate window the compositor cannot animate
  as part of the pane).
- Debug seams for the oracle: `GHOZTTY_DEBUG_BELL_FADE_STALL_MS` (block the
  UI thread as the fade starts) and `GHOZTTY_DEBUG_BELL_FADE_STEPPED` (step
  the same visual the old way).
- Why not the WinRT Compositor's implicit/keyframe animations: the pane tree
  is a DirectComposition device on the renderer thread (T2466's decision), and
  a visual cannot cross devices. The pointer-driven half of T2469 (expressions)
  is where that choice gets revisited - T2556.

## Validation criteria

- [x] Unit tests: `fitCurve` tiles the duration, is continuous at every joint, reproduces a cubic (`comp_overlay.zig`); the fitted `easeInOut` stays within 0.25/255 of the exact curve (`bell_math.zig`). `floor-lane.ps1 -Lane all`.
- [x] The visual path declares each fade once and takes 0 UI-thread steps, in and out: comp-present.ps1 E4a, E4b, E7a (ALL PASS 47, background test desktop).
- [x] The popup path still steps its fade: bell-border.ps1 "the popup's fade was stepped on the UI thread" (ALL PASS 25).
- [x] On screen, through a 500 ms UI stall: `scripts\bell-fade-onscreen.ps1` ALL PASS (23) - declared arm 22 values over 175 ms = 21 refreshes, advance 1.000, max hold 1 refresh, max jump 10.3%; the stepped A/B arm froze for the stall and snapped 100% in one frame. `-NegativeControl` (every other frame dropped) goes red on declared.6/.7/.9.
- [ ] NOT a stable >= 0.98 yet on this box with the user in a fullscreen app: of six declared-arm films, 2 scored 1.000 and the rest 0.35-0.905. The comp spike's compositor glide (0.944 on 2026-10-29) scored 0.806 with holds up to 5+ refreshes in the same minute, so DWM was starving the occluded ghost window, not the animation.
