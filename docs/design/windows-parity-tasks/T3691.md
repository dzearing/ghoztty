# T3691 - Linux: a stale agent left running for live sessions shows the waiting Background Update row, as on Windows

## Summary

T3600 ported the decisions: a stale build with live sessions is left alone (stale_live_deferred). win32 also surfaces that state (T1068): a 'Background Update Ready...' menu row and a palette item (agent_upgrade.pendingFor/settlesPending, installNowText, Restart Now/Later defaulting to Later) that restarts app+agent after consent. GTK has none, so a Linux user cannot see or act on a waiting agent update. Port the pending affordance onto the GTK app menu + command palette, re-running AgentUpgrade.check first, with a test/linux acceptance on the debug GHOZTTY_AGENT_BUNDLED_VERSION hook. While there: the app-older notification's body says 'Click to update Ghoztty' but has no click action on Linux - give it one or a Linux body.

## In plain terms

After an update, the old background process that keeps Linux terminal
sessions alive is left running while sessions are open, so nothing gets
killed. Until now that wait was invisible. Now the main menu shows "Background
Update Ready…" and the command palette lists "Install Background Process
Update…" while the newer one waits. Choosing either one says waiting costs
nothing, defaults to Later, and on Restart Now swaps the process while the
windows stay open.

## Goals

- [x] While a stale agent is left alone for live sessions, the main menu shows "Background Update Ready…" and the palette lists "Install Background Process Update…"; neither shows otherwise
- [x] Choosing either re-runs the check first, then asks (Later the default, the session count named) before doing anything
- [x] Restart Now restarts the agent and rebuilds every pane in place; the row goes away
- [x] The app-older notice no longer promises a click-to-update Linux has no updater for

## Design notes

- Windows' OK relaunches the app with its agent (T1804). GTK has no app relaunch, and it does not need one: the skew path's "restart the agent, then `AgentRecovery.recover`" already rebuilds every pane in place, re-attaching what the new agent relaunches. Because of that, the Linux dialog body (`agent_upgrade_rules.installNowTextInPlace`) says the background process restarts and the windows stay. win32's text says "restarts Ghoztty", and on Linux that would be untrue.
- The row is a GMenu item on `app.install-agent-update` with `hidden-when: action-disabled`. One enabled flag drives both affordances. The palette gained an `app_action` row kind and now rebuilds each time it opens, so a state row is current. Upstream's jump rows were only refreshed on a config change, so they now refresh on open too.
