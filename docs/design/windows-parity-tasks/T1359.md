# T1359 - The machine chooser's session cards never say what a plain-shell session is running

## Summary

T545 put the agent's sampled foreground command into the +sessions roster (protocol.SessionInfo.fg_cmd). The chooser's session cards are the GUI half of that same roster and still show nothing for a plain-shell session - the common case, since argv is only set for a pane opened with an explicit --command. Show the running command on the card, win32 and mac both.

## In plain terms

When you open the machine chooser, each of your terminal sessions shows up as a
card with its folder underneath. For an ordinary shell the card never said what
was actually running in it - a long build or a Claude session looked the same as
an empty prompt. Now the card's second line names the running command while it
runs, and drops it when the shell is back at its prompt, on Windows and Mac.

## Goals

- [x] the Windows card's command line shows what is running now, else what the session was opened with
- [x] the Mac card does the same (C-API roster JSON carries `fg_cmd`; `BrowsedSession.command`)
- [x] the session's NAME is unchanged - only the subline follows what is running
