# T3689 - Linux: the app sometimes aborts on its way out (core App.deinit asserts font_grid_set is empty) - a surface outlives the quit

## Summary

Found by T3598's `test/linux/launch-handoff.sh` (2026-11-24). A debug GTK
app quitting through `handoff-quit` (T3595's `quitNow`) exited 134 instead of
0, in 3 of 3 runs of that script:

```
thread 232353 panic: reached unreachable code
std/debug.zig:559:14 in assert
src/App.zig:114:11 in deinit      assert(self.font_grid_set.count() == 0);
src/App.zig:120:16 in destroy
src/main_ghostty.zig:297:22 in main   defer app.destroy();
```

So when `main` destroys the core App, at least one surface still holds a font
grid: a surface was never deinitialized by the GTK quit path. The same abort
hit a second app the harness stopped with SIGTERM at teardown (pid 232847, and
226599 in an earlier run), so it is the GTK quit/terminate path, not the
handoff. The log shows GLib criticals just before, from windows torn down after
their tab view was gone: `adw_tab_view_get_n_pages: assertion
'ADW_IS_TAB_VIEW (self)' failed`.

It is timing/state dependent: the same verbs replayed by hand (a named
agent-hosted `+new-window`, a same-build second instance, a forwarded `-e`
window carrying a `handoff` identity, then `handoff-quit`) quit cleanly in 5 of
5 runs. The script additionally polls `+list --json` and `+version` many times
and its pane writes a heartbeat file every 200 ms.

A release build has no assert, so a user sees nothing today; but a surface
that is never deinitialized is a leaked renderer/IO thread at quit, and every
debug test that checks a clean exit is blocked on it.

Fix: find which surface escapes teardown (log surface init/deinit counts at
`terminate`; check windows destroyed after `Application.deinit` and surfaces
whose window closed while their tab view was disposed) and make the GTK
terminate path close every surface before core `App.destroy`.

## In plain terms

When the Linux app quit (for instance when you switch to a different build
of Ghoztty), a window that had just been opened could be left half torn
down, and a debug build crashed on its way out instead of exiting cleanly.
Now every window is fully closed at quit, so the app always exits cleanly,
and if a terminal ever does survive a quit again the log names it.

## Goals

- [x] find which terminal survives the quit, and what holds it
- [x] make the quit free every window's terminals whoever still holds the window
- [x] the two handoff tests demand a clean exit, not just "the app is gone"

## Root cause

`quitNow` calls `gtk_window_destroy` on each window. That drops only the
toplevel list's reference: a window anything else still holds is hidden and
unrealized but **not disposed**, so its panes stay parented and their core
surfaces (freed in GObject `finalize`) keep their font grids. The holder here
was `IpcHandlers.watchActivation`: every `--focus` window (and the handoff's
Open Window always forwards `--focus`) is referenced for a 1 s timer that logs
whether the compositor activated it. A quit inside that second left the
window alive; the run loop's final drain is non-blocking, so the timer never
fired, and core `App.deinit` asserted. The new survivor report named it:
`survivor pane=... refs=3 parent=true root=true realized=false title=/bin/sh`
- the forwarded `-e /bin/sh` window from H10.

Fix (`src/apprt/gtk/class/application.zig`): `quitNow` holds a reference
across each window's destroy and forces `g_object_run_dispose`, so every pane
is freed whatever still references the window object. That covers every
other window holder too (split-tree drags, workspaces, tab moves), not only
this timer. `Application.reportSurfaceSurvivors`, called from
`App.terminate`, logs any surface still alive after the run loop, with its
ref count and whether it still has a parent, root and realization.
