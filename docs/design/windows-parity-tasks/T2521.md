# T2521 - The viewer pane's nav bar placement costs ~1.5 ms of every window-resize pass (ViewerPane sync_cost nav_us 1450-1930 per pass at ReleaseSafe), five times the WebView2 put_Bounds beside it (T2516)

## Summary

Measured 2026-10-30: 'resize trace viewer total_us=1800 bounds_us=290 nav_us=1550' per pass on resize-sync-onscreen.ps1 -Exe zig-out-rsafe with GHOZTTY_RESIZE_TRACE=1. nav.place(width, scale) in ViewerPane's sync path is most of the viewer's share of the pass; find what it does per call (re-measuring text? moving each button HWND separately instead of in one DeferWindowPos?) and make a width-only change cheap. Validate with the same trace line: nav_us under 0.3 ms.

**Rescoped 2026-10-30 (partly fixed; the rest is T2531).** A finer trace split the bar's ~1.8 ms (ReleaseSafe, this box) into: the bar's move + forced paint ~1.3 ms (of it: `SetWindowPos` ~0.4, the glass band ~0.43, the button glyphs ~0.18, BeginPaint/EndPaint and the GDI flush ~0.3), and the address EDIT's move + paint ~0.45 ms. Tooltip sync (~0.03) and `ShowWindow` (~0.02) were never the cost. This task fixes the paint side; the two child-window moves and the paints Windows forces around them are structural and moved to T2531, which now carries the 0.3 ms target.

## In plain terms

Dragging a window's edge with a web or markdown viewer open, the viewer's address bar was repainting itself expensively on every frame of the drag - most of that work was recomputing the background gradient one pixel at a time. It now does the same drawing about a quarter faster overall, with the gradient part four times cheaper, and looks exactly the same.

## Goals

- [x] find what `nav.place` spends its time on (trace split into bar / edit / tips / glass / buttons)
- [x] make the glass band's gradient cheap without changing a pixel
- [x] stop creating a font per glyph per paint
- [x] file the structural remainder (T2531)

## Validation criteria

- [x] the bar's paint costs less: `nav_glass_us` 430 -> 110 us median, `nav_buttons_us` 180 -> 130 us; `nav_us` 1750-2060 -> 1270-1340 us median (ReleaseSafe `zig-out-rsafe`, `scripts/resize-sync-onscreen.ps1 -Drags right-shrink` and `right-grow` with `GHOZTTY_RESIZE_TRACE=1`, 32-33 passes each). The 0.3 ms target is NOT met and is carried by T2531.
- [x] the band's pixels are unchanged: `desk_palette` test "T2521: atRow is the scalar gradient, bit for bit" (both looks, three window sizes, rows above/inside/below, both x clamps and the non-multiple-of-8 tail), green under Debug and `-OReleaseFast`; the existing glass nav band pixel test in `ViewerPane.zig` (WM_PRINTCLIENT vs `glassHeadRegion`) in the win32 lane
- [x] floor lanes green (see progress log)
