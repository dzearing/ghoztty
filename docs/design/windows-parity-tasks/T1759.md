# T1759 - No on-box script drives the chooser's count capsule for a REMOTE machine, or its clearing on a failed load or an ended session (T1745 follow-up)

## Summary

T1745 added a per-machine session-count capsule to the machine chooser's list.
On the box, `test/win32/chooser-help-tooltips.ps1` section G drives only the
LOCAL row (count logged, tooltip, live push 2 -> 3, never-loaded negative
control). Three paths are unit-tested but never driven on the box:

- a REMOTE machine's count (`chooser row count key=<device-id> count=N`), e.g.
  in `chooser-sessions-remote.ps1` / the loopback remote harness;
- the capsule CLEARING when that machine's load fails
  (`chooser row count key=<device-id> cleared`: stop the remote agent and
  reselect);
- the count dropping when a session is ended from the chooser's own list (the
  optimistic kill path calls `noteRowCount`).

Also: no capture checks the capsule's pixels (only the log oracle and the
tooltip text), and `chooser_rows.zig`, which holds the capsule geometry, is
covered by the `chooser-selection` guard row rather than `chooser-help-tooltips`.

## Validation criteria

- [ ] A remote machine's count is logged with its device id and matches its listed sessions.
- [ ] Making that machine's load fail logs `cleared` for its key.
- [ ] Ending a session from the list logs the lower count.
