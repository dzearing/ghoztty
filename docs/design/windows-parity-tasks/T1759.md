# T1759 - No on-box script drives the chooser's count capsule for a REMOTE machine, or its clearing on a failed load or an ended session (T1745 follow-up)

## Summary

T1745 added a per-machine session-count capsule to the machine chooser's list.
On the box, `test/win32/chooser-help-tooltips.ps1` section G drives only the
LOCAL row (count logged, tooltip, live push 2 -> 3, never-loaded negative
control). Three paths are unit-tested but never driven on the box:

- a REMOTE machine's count (`chooser row count key=<device-id> count=N`), e.g.
  in `chooser-sessions-remote.ps1` / the loopback remote harness;
- the capsule CLEARING when that machine's load fails
  (`chooser row count key=<device-id> cleared`: stop the remote agent and
  reselect);
- the count dropping when a session is ended from the chooser's own list (the
  optimistic kill path calls `noteRowCount`).

Also: no capture checks the capsule's pixels (only the log oracle and the
tooltip text), and `chooser_rows.zig`, which holds the capsule geometry, is
covered by the `chooser-selection` guard row rather than `chooser-help-tooltips`.

## In plain terms

The machine picker shows a small number next to each computer saying how many
sessions it has. Until now only the number for THIS PC was checked by a real
run; the number for another computer, the number going down when you end a
session, and the number disappearing when that computer stops answering were
only checked in unit tests. Now a real run checks all three.

## Goals

- [x] the remote-machine harness checks the remote row's number
- [x] ...its drop when a session is ended from the list
- [x] ...its clearing when that machine's load fails
- [x] editing the count cache makes that harness due (new guard row)

## Validation criteria

- [x] A remote machine's count is logged with its device id and matches its listed sessions. (`chooser-sessions-remote.ps1` C2 + E: `key=dev-remote count=2` against `loaded 2 sessions`, both choosers; green 2026-11-21, 28/28, twice)
- [x] Making that machine's load fail logs `cleared` for its key. (E3: agent stopped + relay tripped, reselect -> `fetch failed ... state=failed` and `key=dev-remote cleared`; E3 control asserts no clear before)
- [x] Ending a session from the list logs the lower count. (E2: `key=dev-remote count=1` after the Kill)
- [x] Negative controls: never-loaded machines record/clear nothing (G2); `-NegativeControl` run records no capsule (16/16 green)

Not done here, and left as the Summary says: a pixel check of the capsule, and
moving `chooser_rows.zig`'s capsule geometry under a capsule-specific guard.
The new `chooser-sessions-remote` guard row covers `chooser_row_counts.zig`.
