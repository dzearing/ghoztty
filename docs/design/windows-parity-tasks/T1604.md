# T1604 - -AppOnly delivers a new app beside whatever agent a location already had, and never says so

## Summary

scripts\deliver-windows-build.ps1 skips resolving the staged agent stamp entirely under -AppOnly, so the per-location agent read-back (T281) is dead there. The run withholds the portable ZIP for exactly this reason ('AppOnly ships no agent', D12b) - but it leaves the LOCATION in the state it refuses to publish: a new app paired with an agent of unknown age, silently. Proposal: read the staged stamp under -AppOnly too and REPORT a location whose agent does not match it (a warning rather than a failure, since not shipping the agent is the point), with an arm in section H of test\win32\deliver-windows-build.ps1.
