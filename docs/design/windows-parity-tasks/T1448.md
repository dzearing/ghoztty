# T1448 - floor-lane's solo-confirm re-run can now go red for a filter that matched nothing, and would read as 'reproduced'

## Summary

T631 made a -Dtest-filter run that matches nothing FAIL. floor-lane.ps1's T1170 solo-confirm re-runs a red lane narrowed to the test names it scraped out of the log, one -Dtest-filter per name. When that scrape produces a name zig cannot match (a renamed test, a truncated log line, a name with characters the parser mangles), the narrowed re-run now fails on the guard rather than exiting 0 - and floor-lane would summarise that as 'alone: FAIL - reproduced', which is the opposite of what happened. The narrowed re-run should tell the guard's refusal apart from a real test failure and report 'could not narrow' instead. Found while validating T631.

## In plain terms

When a test lane fails, the floor script re-runs just the failing tests on their own to tell "the box was busy" apart from "the code is broken". If that re-run names a test the build cannot find, it now fails without running anything, and the script used to call that "reproduced - it's the code". It now says "could not narrow" instead, so nobody chases a bug that the re-run never actually saw.
