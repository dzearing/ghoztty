# T3297 - deliver-windows-build.ps1 acceptance is 64-red in lane b: the T1984 delivery lane refusal exits 6 on its sandbox targets

## Summary

Every non-DryRun/VerifyOnly call in test\win32\deliver-windows-build.ps1 delivers into a %TEMP% sandbox, yet scripts\deliver-windows-build.ps1 refuses it in lane b (Assert-LoopLaneOwnsDelivery, exit 6), so C/D/E/F/H go red there and a lane-b turn that touches the script can only clear the guard by running with GHOZTTY_LOOP_LANE=a by hand (T1604 did). Fix: let the harness scope that override to its sandboxed invocations (or teach the refusal that a target set wholly under the harness sandbox is not a delivery), keeping the real-path arms DryRun-only, and add an arm proving a lane-b run of a REAL target is still refused.
