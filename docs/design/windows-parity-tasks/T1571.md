# T1571 - The harness lane reads red after a .zig edit because -Lane all never rebuilds the app

## Summary

floor-lane.ps1 -Lane all builds the test binaries but never zig-out\bin\ghoztty.exe, so any .zig edit leaves the app binary older than its sources. The next -Lane harness run then scores build-mode-guard, persistence-flag and caller-anchor red on staleness - ten minutes to learn that a rebuild was missing, with three verdicts that name GHOZTTY_TEST_ALLOW_STALE rather than 'rebuild'. Either -Lane all should build the app, or the harness lane should say which rebuild clears it.

## In plain terms

After any change to the terminal's source code, the standing test sweep spent
ten minutes and then reported several tests as failing, when nothing was wrong
except that nobody had rebuilt the app. Now the sweep notices the app is out of
date before it starts, rebuilds it once, and only then runs - or, if the
rebuild fails, stops immediately and says which build to run.

## Goals

- [x] The harness sweep rebuilds a stale app once before any member that grades it runs
- [x] A failed rebuild (or `-NoRebuild`) stops the sweep up front and names the rebuild command
- [x] A source-only sweep never starts a build it does not need
- [x] The set of members that need the app is declared, and drift in it fails a harness

## Validation criteria

- [x] Which members grade the real exe is declared (`NeedsApp` on build-mode-guard and build-fresh-guard; caller-anchor and persistence-flag's live part left the floor in lane b's T1572 the same hour, so the rebase dropped their flags) and matches their source - `test\win32\harness-floor.ps1` I1 (an oracle that first flagged cleanslate-audit and stderr-launch-capture, both false positives: a kill-by-path and fixture text; tightened to "points at the real exe AND hands it to a gating/launching call outside a quoted line")
- [x] Stale + `-NoRebuild` refused; stale + failed rebuild refused; stale rebuilt exactly once then fresh; no app member = no check, no build - I2-I5 on a planted fixture repo
- [x] End to end: `harness-floor.ps1 -Repo <stale fixture> -Include build-mode-guard.ps1 -NoRebuild` exits 1 with `BUILD STALE - REFUSED` and the zig build line, and suite-run never produced a summary - I6
- [x] Harness ALL PASS (90), `-NegativeControl` red (exit 1)
- [x] Real tree: `harness-floor.ps1 -Include 'build-mode-guard.ps1,caller-anchor.ps1'` printed `BUILD FRESH ... (for build-mode-guard.ps1, caller-anchor.ps1)` and went ALL PASS
