# T1598 - The sibling harness audits still sweep the top level only, so lib\ can hide a violation from each of them

## Summary

T780 widened the input-desktop audit to test\win32\lib\ because a harness helper can make every script that calls it input-desktop-only while the sweep reads none of them. The scope argument is not specific to that rule: DesktopLaunchAudit enumerates $Root\*.ps1 alone, and the harness-floor family around it (exit codes, skips, verdicts, isolation, capture, body-complete, asserted-nothing) each sweeps the same top level. Ask of each one whether a lib\ helper could carry the defect it looks for - a helper that launches on the user's desktop is the obvious yes - and widen the ones where it could, with the same per-file stated-intent marker rather than a directory exclusion. Where the answer is genuinely no, say so in the header, measured, so the next reader does not have to re-derive it.
