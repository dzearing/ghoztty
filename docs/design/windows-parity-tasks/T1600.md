# T1600 - Give the keybind and input acceptance scripts a guard row so a red one cannot sit unnoticed

## Summary

T782 found kb-actions.ps1 red (T1599) only because it edited the file and re-ran it. Nothing else would have: the script has no row in scripts\guard-due.ps1, so no code change makes it DUE and no floor runs it. The same is true of several input/keybind scripts (keybinds-t01.ps1, window-title.ps1, tab-strip.ps1 have rows only in part). Add rows keyed on the win32 input/keybind sources they cover, so touching src\apprt\win32\ input handling makes the matching acceptance script due - which is the whole T783 arrangement.

## In plain terms

Some of the automated checks that press real keyboard shortcuts in Ghoztty
(new tab, split, copy/paste, rename the window) were never re-run when the code
behind those shortcuts changed, so one of them could break and stay broken
without anybody noticing. Now each of those checks is tied to the code it
tests: change that code and the loop is required to run the check again before
it can commit.

## Goals

- [x] kb-actions.ps1 has a guard row (landed by T1599)
- [x] tab-strip.ps1 has a guard row (landed since, by T1015's ChromeGeometry row)
