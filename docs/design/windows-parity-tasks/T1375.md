# T1375 - The command palette and the search bar answer to the terminal's window class, so no probe can tell them apart

## In plain terms

Nothing a user sees. This is about the test harness: the command palette and the
find bar answered to the same window class as the terminal itself, so no script
could tell which of the three it had found, and the screenshot helper refused to
photograph either popup because photographing a terminal surface returns a blank
rectangle. Giving each popup a name of its own lets the tests point at the right
window.

## Goals

- [x] Each popup carries a window class of its own
- [x] The screenshot guard keeps its teeth for the terminal surface only
- [x] Every script that found a popup by the terminal's class is repointed

## Summary

Both popups are created with App.TERMINAL_CLASS_NAME, so by class they ARE a terminal surface. Two consequences, both found while validating T563: Get-TestWindowPixels refuses to capture anything of that class (T214's rule about the GL surface returning a flat fill), so measuring the palette needs -AllowTerminalSurface, which is the hatch reserved for measuring the limit itself; and every script that waits for a popup does Wait-TestWindow -Class GhozttyTerminal, which cannot distinguish the palette from the search bar from a second terminal window. Registering GhozttyCommandPalette and GhozttySearchBar against the SAME wndproc fixes both (role is already resolved from the HWND by surface_window_role, not from the class), and it lets the capture guard keep its teeth for the surface it was written about. The cost is every acceptance script that keys on the old class name, which is why this is its own task.

## Validation criteria

- [x] The palette answers to `GhozttyCommandPalette` and the search bar to
      `GhozttySearchBar`, so a probe can name which popup it found —
      `App.registerSurfacePopupClass`, one call per name, same `surfaceWndProc`
- [x] `Get-TestWindowPixels` captures the palette with NO `-AllowTerminalSurface`
      hatch, and the T214 refusal still fires for the GL surface — the hatch is
      gone from `chrome-theme.ps1`; the guard's exact-class check on
      `GhozttyTerminal` is untouched
- [x] Every acceptance script that found a popup by `GhozttyTerminal` finds it by
      its own class, and the suites that do so are green on the box — 25 scripts
      run sequentially on the box, all green. The sweep caught two repoints the
      first pass had missed: `command-registry.ps1`'s `Find-Palette` helper and
      `viewer-panes.ps1`'s `Test-PaletteOpen`, both still doing a TOP-LEVEL
      lookup of `GhozttyTerminal`. Evidence per suite in T819's progress log
