# T3431 - Linux: Back onto a local .html page from a different folder's page re-renders the wrong file

## Summary

The GTK viewer serves a rendered .html file from ghoztty-page://page/<rel>, resolved against ONE pinned grant root per viewer (Viewer.base_dir, set on each navigate). History entries carry only <rel>, so after a.html in /x then b.html in /y typed into the address bar, Back to the /x entry requests page/<rel> against /y and shows /y's file (or a 404 card). T3412 left it because it needs two local sites in one pane's history. Fix: carry the root in the URL (e.g. a per-viewer authority id mapped to its root, ghoztty-page://<id>/<rel>) so each history entry resolves against the grant it was loaded under; keep the T601 rule that a link deeper into the site does not move the grant. Extend test/linux/viewer-nav.sh.
