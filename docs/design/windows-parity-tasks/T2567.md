# T2567 - Composition step 3d-1b: on a banded composition pane, clicks, selection, IME and menus measure from below the band

## Summary

T2558 split, slice b (input). With slice a's grid_band > 0 the pane's client y is band px below the grid's. Subtract the band where a client point goes to the core: handleMouseButton (~L4913 cursorPosCallback before the button), handleMouseMove (~L5380), cursorFromLparam / prev_cursor_client bookkeeping, and anything else decoding lparam y for the core (wheel uses no position). Points ABOVE the band (y < band) never reach the core - in slice a the banner popup covers them; T2559 routes them to the banner. Add the band where a grid point goes to the screen: positionImeWindow (~L5691, imePoint y + band), the caret/IME ClientToScreen sites, showContextMenuKeyboard's pane centre (~L5093, centre of the grid area), the link-preview bubble (~L2742, bottom of the grid area). focusFollowsMouse compares screen points, unaffected. Oracle: with GHOZTTY_COMP_PRESENT=1 and a banner, a click, a drag-selection and a wheel land on the same cells as the knob-off build (pane-banner.ps1 click rows, selection tests), and the IME candidate window sits at the cursor.

## In plain terms

On the new (still opt-in) composition drawing path, a pane with a status
banner now has its window reach up under the banner. Without this change,
clicking or selecting text in such a pane would hit a row or so lower than
where you pointed, and the input-method candidate box and the keyboard
right-click menu would open too high. Now every point is measured from where
the terminal text actually starts, so it all lands where it does on the
classic path.

## Design notes

- Two pure helpers in `banner_layout.zig`: `gridY` (client -> grid, on the way to the core) and `clientY` (grid -> client, on the way to the screen). `last_cursor_client` stays in CLIENT space - it is the "is this point news" comparison and the fallback for `getCursorPos`, which now applies the band itself on both of its answers.
- Points above the band (y < band) still reach the core as negative y, the same shape a capture-held drag past the top of a knob-off window produces; in practice the banner popup covers them (T2559 routes them to the banner).
- Debug-only log lines (`pane mouse ... cell=`, `pane ime point=`, `pane keyboard menu client=`) are the harness's oracle; the cell lookup is behind `std.log.logEnabled(.debug, ...)` so release builds never pay it.
