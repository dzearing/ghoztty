# T3064 - PA-C08/PA-C09/PA-C10: link hover selects and stringifies the whole soft-wrapped line under the renderer mutex on every cell crossed, before checking whether any link can match, and redoes it per pixel while over a link (Surface.linkAtPin)

## Summary

PA-C08..C10 (audit-1, T2964). src/Surface.zig:5623-5660 `linkAtPin` runs Screen.selectLine (src/terminal/Screen.zig:2556-2650 follows soft wraps with no cap; only hard wraps are capped by hard_wrap.max_extend = 32), then selectionString with a StringMap (one Pin per byte), then the link regexes, on the GUI thread holding renderer_state.mutex (cursorPosCallback :5878). PA-C08 (P1): cost proportional to logical line length, so a 1 MB unbroken line (minified JSON, base64) costs megabytes of string and pin map per cell crossed while IO and render are blocked. PA-C09 (P2): the hover_mods check sits inside the loop after the allocation, and the default link is ctrl-hover (src/config/Config.zig:4104-4106), so every cell crossing without ctrl allocates and frees for nothing (the Surface twin of PA-R05). PA-C10 (P2): while over a link :5918-5926 bypasses the same-cell check, so each mouse event redoes the match, two performAction calls, sets hyperlink_hover (full rebuild) and queues a render. Fix: early-return when no link's highlight matches the mods (keep the mouse_mods == null double-click path); cap the soft-wrap walk for link matching (e.g. +/-32 rows); skip re-matching while the cell is unchanged. Risk: low. Shared code: Mac half T3071. Findings: docs/design/perf-audit/audit-1/C-findings.md.

## In plain terms

Moving the mouse over terminal text made the app re-read the whole line under
the pointer, every time the pointer crossed a character, to check for links -
even when you were not holding Ctrl, so no link could ever light up. On a
pane holding one giant unbroken line (minified JSON, base64) that meant
megabytes of work per mouse twitch, with the terminal frozen while it ran.
Now a move without Ctrl does no link work at all, the check reads at most a
screenful of rows around the pointer, and resting on a link no longer redoes
the check for every pixel.

## Goals

- [x] no line read when no configured link can match the held modifiers (C09)
- [x] the soft-wrap walk for link matching stops 32 rows each side of the mouse (C08)
- [x] a pointer moving inside one cell over a link keeps it without re-matching (C10)
