# T1091 - the orphan-badge chooser test only passes when the orphan happens to sort last - Return resumes nothing from any other row

## Summary

test\win32\chooser-orphan-badge.ps1 section 3 navigates to the marked row with N Down presses from an assumed selection at index 0, then presses Return. It only passes when the orphan renders at the position the chooser already has selected: 4 runs on 2026-08-22 (two of them of the unmodified HEAD script, as a control) failed 4 of 16 assertions whenever the rendered index was 0 or 1, and passed with index 2. No 'resume session: attaching local session id=' line appears at all in the failing runs, so Return reached nothing - either the keyboard focus is not where the script assumes after 'Right', or the chooser's initial selection is not row 0. Decide which half is wrong (harness assumption vs chooser behaviour) before fixing; the same navigation shape is used by orphan-notify.ps1 section 4, which is green, so compare the two.

## In plain terms

The test that checks "pick a left-over session in the machine chooser and press Enter to bring it back" only passed when that session happened to be listed last. The navigation was fixed in T1106. This task makes the test prove it: the test now also flips the list order and requires Enter to work from the session's new position.
