# T1994 - Two loop lanes' debug builds share one debug local agent: persistence-enabled acceptance runs in lane B adopt lane A's agent (and its sessions)

## Summary

Found in T1983. GHOZTTY_PIPE_SUFFIX moves the APP pipe only; the local agent's pipe, state dir and autostart are keyed by build mode plus GHOZTTY_AGENT_INSTANCE, which debug-lineage scripts leave unset. So every debug build on the box - lane A's and lane B's - dials the same debug agent, and a lane-B persistence run adopts (or is refused by) lane A's agent built from a different tree. Fix: give each lane its own agent lineage (e.g. a per-worktree GHOZTTY_AGENT_INSTANCE set by the runner, with Register-AgentRunKeyTeardown), and extend isolation-meta so a persistence-enabled launcher without a lane-unique lineage is a finding. Check the debug state-dir assertions that read %LOCALAPPDATA%\ghoztty-debug paths.

## In plain terms

When two copies of the work loop run side by side, their tests both used the
same background session helper, so a test in the second copy could pick up the
first copy's helper - built from different code - and its sessions. Now every
test the second copy runs gets a helper of its own, and a test that cannot work
that way is stopped up front instead of quietly using the wrong one.

## Goals

- [x] Every acceptance-runner phase in a non-literal checkout (lane B) runs under its own agent lineage
- [x] A script that cannot honor a lineage is refused there, loudly, not run against lane A's agent
- [x] Lane A (the literal checkout) is unchanged byte for byte
- [x] Lineages the runner mints do not leave HKCU autostart values behind

## Design (my call - mechanism, not experience)

- Workers already had a lineage (`apw<N>-<pid>`, T1960). The gap was the phases
  that run from `-Repo` itself - main, exclusive, serial, confirm. In a checkout
  that is not the literal one, `Get-AcceptanceMainEnv` gives them
  `GHOZTTY_AGENT_INSTANCE=apm-<runnerPid>` (run-unique, so a dead run's agent is
  never adopted either). Keyed on the same `$foreign` test T1993 uses, not on
  LoopLane, so a fixture repo exercises it.
- A lineage moves the agent state dir AND the layout manifest, so the three MAIN
  patterns (hardcoded `local-agent-debug`, hardcoded `session-layout-debug`,
  dropping the lineage) mean "cannot run under a lineage" (`Unscoped`). In a
  foreign checkout such a script is a red `refused` row, never started.
  Converting the 107 such scripts is T2005; `# @lineage-safe - <why>` is the
  opt-out for fixture-text matches (applied to acceptance-parallel.ps1 itself).
- The isolation-meta extension the Summary proposed is replaced by this: the
  runner now supplies the lane-unique lineage structurally, so a per-script
  finding has nothing left to catch for runner runs. Hand runs are T2006.
- `Remove-ApLineageRunKeys` deletes both Run-value spellings for every lineage
  the runner minted (workers included - they had the T1168 leak too).
