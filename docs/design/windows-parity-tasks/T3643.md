# T3643 - Linux: a viewer pane in a minimized or suspended GTK window keeps polling git-status and animating, because its gates read only whether its widget is mapped

## Summary

T3571 made terminals follow the window's seen state (Window.isSeen: mapped, not minimized, not suspended). Viewer panes still gate only on gtk_widget_get_mapped: ViewerDiff.onPollTick spawns git every poll and an animated image keeps advancing in a window that is minimized or suspended, where the widget stays mapped (ViewerDiff.zig:329's comment says 'minimized' but the check cannot see it). Gate them on Surface.computeSeen()/Window.isSeen() too, with one catch-up on show, per docs/reference/background-windows.md rows 'git-status: pane poll' and 'Animated image'. Check whether WebKitGTK already hides the page (document.visibilityState) for a minimized toplevel before adding anything for live pages. Acceptance: extend test/linux/background-windows.sh with a git-status viewer under pane-seen --toplevel=minimized.

## In plain terms

On Linux, a pane showing live git changes kept running git every two seconds
even after you minimized its window, and an animated picture kept playing
where no one could see it - wasted battery and CPU. Now a viewer pane in a
minimized or covered window goes quiet, and the moment the window comes back
it refreshes once so what changed meanwhile shows at once.

## Goals

- [x] a `git-status:` viewer's poll skips every tick while its window is minimized or suspended
- [x] the viewer's web page is taken off screen while hidden, so WebKit pauses its animations (GIFs hold their frame)
- [x] shown again: one catch-up (git asked at once, an owed file save renders), not a replay
- [x] acceptance in `test/linux/background-windows.sh` (V1-V8), shown red without the wiring
