# T3147 - PA-V29: a viewer page that is only slow (WebView2 reports it unresponsive) is reloaded up to three times and then closed as if it had crashed

## Summary

Audit-3 (T3101), area V. viewer_process.Budget.decide (src/apprt/win32/viewer_process.zig:61-65) treats render_process_unresponsive exactly like render_process_exited: each event spends a restart, and past restart_limit the pane drops its controller (.capped -> dropController(.page_keeps_crashing), ViewerPane.zig:6543). WebView2 raises Unresponsive repeatedly while a page stays hung, so a long-running script (a big markdown render, a slow site) can be reloaded three times and then shown as a crash. FIRST confirm on the box (a page with a 10 s busy loop) how often ProcessFailed(unresponsive) fires. Fix shape: do not count unresponsive as a crash; reload only after it persists past a threshold, once. Detail: docs/design/perf-audit/audit-3/V-findings.md.
