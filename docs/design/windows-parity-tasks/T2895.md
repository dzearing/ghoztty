# T2895 - Chooser, Activity Monitor, banner and drop-highlight live-update claims have no paint-probe surface - add surfaces and measure each claim against its deleted invalidate

## Summary

Found by T1407's survey. These claims capture an already-shown popup/child
after a state change, and none of those windows has a `paint_probe.Surface`:

- `GhozttyMachineChooser`: chooser-sessions:204, chooser-session-cpu:325,
  chooser-kill-hover:276-298 (mouse-leave), chooser-link-hover:231-252,
  chooser-selection:341/372 (372 relies on the native listbox for
  `WM_UPDATEUISTATE` - no invalidate found), ipc-machine-chooser:540/560/730,
  chooser-roster-refetch, chooser-resume:332
- `GhozttyActivityMonitor`: activity-selection B/C/E/F, activity-monitor L3-L7
  focus ring, J error banner. NOTE its 1.5s sample timer invalidates on every
  adopted sample, so a counter on it is defeated the way the hero carousel
  defeats `.window` - measure the quiet first, and expect to need the sampler
  paused (or a sub-rect probe) before a count means anything.
- `GhozttyBannerOverlay`: pane-banner T377 (`setText` -> `invalidate()`, and the
  composition path posts `WM_APP_BANNER_VISUAL` instead of painting)
- `GhozttyDropHighlight`: rearrange-noop-drop ~211/234
- `GhozttyViewer` host: viewer-error-card:311 (`fail` -> `InvalidateRect`)
- `GhozttyPaneSidebar`: pane-sidebar-all-windows:788 join ring

Add a surface per window as each claim needs one (record from `WM_PAINT`
only - printclient-audit section D enforces it), measure each claim against
its deleted invalidate, and RUN every new assertion red against that deletion.

## Validation criteria

- [ ] Each listed claim marked survives-deletion / goes-red, with the build that showed it.
- [ ] Every survivor gains a probe assertion RUN red against the deletion, or is re-labelled to what it really measures.
- [ ] Touched harnesses green afterwards; guard-due rows cover any probe surface they depend on.
