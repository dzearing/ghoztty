# T3589 - Linux: a tinted pane keeps its --color tint across session restore (Leaf.tint on GTK)

## Summary

T3382 made --color / --split-color / +split --color and split inheritance tint GTK panes, but src/apprt/gtk/SessionLayout.zig captureLeaf never writes the schema's Leaf.tint (win32 T3176, Mac Leaf.tint) and restore never applies it, so a relaunch brings every pane back untinted. Write leaf.tint from Surface.backgroundTint() as #rrggbb, carry it on Surface.Restore / pending_restore, and applyBackgroundTint on the restored surface (it already defers until the core surface exists). Acceptance: a test/linux/session-restore.sh section that tints a pane, restarts the app, and reads background_tint from +list plus the pane render through hl_screenshot.

## In plain terms

On Linux you can give a pane its own background colour, but quitting or
crashing the app and opening it again brought every pane back in the default
colour, and so did the app reconnecting after its background helper
restarted. Now a coloured pane comes back in its colour every time, the way it
already does on Windows and the Mac.

## Goals

- [x] the session layout records each tinted pane's colour
- [x] a relaunch puts the colour back, whether the pane re-attaches or opens a fresh shell
- [x] an in-place agent recovery keeps the colour too (linux.md already claimed it did; it did not)

## Validation criteria

- [x] The manifest records `tint` as `#rrggbb` for tinted panes and none for an untinted one - `test/linux/session-restore.sh` RT1, PASS in WSL 2026-11-24.
- [x] After a SIGKILL relaunch `+list` reports each pane's `background_tint` again and the re-attached pane RENDERS it (99.2% of its pixels) - RT2, RT3 PASS.
- [x] A pane whose session died comes back as a fresh shell still tinted, and after an agent restart the relaunched panes keep their tints - RT4, RT5 PASS; whole script `SESSION RESTORE: ALL PASS` (41 checks).
- [x] In-place agent recovery keeps a pane's tint and leaves an untinted pane untinted - `test/linux/agent-recover.sh` A10d PASS, `AGENT RECOVER: ALL PASS` (19 checks).
- [x] Pure rules `tintToRecord` / `tintToRestore` (viewer and unreadable values refused, schema round trip) - Linux floor `LINUX FLOOR: ALL PASS` (lib, none, agentx, agent) at 62ed080d6; Windows `floor-lane.ps1 -Lane none` (the file is in `apprt/unit_tests.zig`).

Note: the first RT3 run read 0% because `unfocused-split-opacity` dims an
unfocused split, so no pixel is the raw tint (a probe showed the same before
the kill, so it was the oracle, not the restore). The test now writes the same
opacity config `cli-color.sh` uses.
