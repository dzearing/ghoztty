# T3354 - Linux: ChildStream.close does not unblock a read blocked on the child's stdout pipe (close(2) never wakes a blocked read on Linux)

## Summary

src/remote/ssh_transport.zig ChildStream.closeFn relies on closing read_fd to wake a thread blocked in posix.read on it. macOS does that; Linux does not - the reader stays blocked until the peer end closes, so test 'ChildStream: close unblocks a blocked read' hangs the Linux none lane forever (found by T3331's floor; skipped on Linux under this id). Fix: make readFn poll() on read_fd plus a wake pipe (or eventfd) that closeFn writes, so close unblocks on every POSIX host; then remove the Linux skip. Shared code - run the Mac/Windows lanes too.
