# T796 - Audit acceptance scripts for test seams that mask the shipped default

## Summary

T747's defect shipped past a green suite because every GUI section of test/win32/relay-account.ps1 sets GHOSTTY_GOOGLE_CLIENT_ID=cid-e2e. The seam is legitimate (a fake relay needs a fake id), but it meant the configuration every real user runs - no id at all - was never once exercised, so a dead button read as a fully tested feature for months. The shape generalises: any env/registry/file seam a script sets to make a flow reachable is also a statement that the UNSET case is untested. Sweep test/win32/ for the seams that turn a feature ON (GHOSTTY_*/GHOZTTY_* env sets, seeded stores, staged config) and, for each, answer whether the absent case has an arm anywhere; file what is missing. Then decide whether the rule wants enforcing the way the exit-code, skip-visibility and asserted-nothing audits are - an analyzer plus a ceiling that may only fall - or whether a one-time sweep plus a note in the harness header is proportionate.

## In plain terms

A test that has to switch a feature on before it can reach it is also saying,
quietly, that the switched-OFF version - the one that ships - was never tried.
That is how the dead "Sign in with Google" button (T747) passed a green suite
for months: every section of its test supplied a credential the real product
does not carry.

This change makes that statement out loud. Every environment switch the
acceptance suite touches and the product actually reads - 78 of them - now has
a line in a registry saying what happens when it is absent: that state is what
every other run already uses, or a named test aims at it, or it is a known hole
with an open task against it, or it cannot be reached from this machine at all
(the user's live terminal, a real network service). A new test that flips a new
switch fails until somebody writes that line, and the number of known holes can
only go down.

Two holes were found and filed: nothing ever starts the app without telling it
where the session agent lives (T1619), and nothing ever lets it look for the
`claude` CLI by itself (T1620).

## Decision: enforce, don't just sweep

The task left this open. A one-time sweep plus a header note was rejected: the
finding population here is 78 seams of which two matter, so a report is read
once and the next new seam arrives unclassified. But an UNCONDITIONAL analyzer
is worse - it cannot tell `GHOZTTY_PIPE_SUFFIX` (unset = the user's live
endpoints, which the harness is FORBIDDEN to touch) from
`GHOSTTY_GOOGLE_CLIENT_ID` (unset = a dialog the user meets daily), so it would
report all 78 and be muted. So: the ENUMERATION is mechanical, the
CLASSIFICATION is a reviewed file, and what is enforced is that the two agree -
plus a ceiling on the gaps, the same shape as the exit-code, skip-visibility,
asserted-nothing and unroll-count audits.

- [x] The sweep enumerates the seams mechanically: 78 vars are both SET by a
      `test\win32` script and READ by `src\` (101 set, 135 read) -
      `test\win32\seam-audit.ps1` section C prints the count, C2 asserts a real
      population, and section A proves on fixtures that set-but-unread,
      read-but-unset and merely-read-in-a-script are all excluded.
- [x] Every one of the 78 carries a class (`isolation` / `tuning` / `fault` /
      `non-default` / `enable`) and an unset disposition
      (`shipped-elsewhere` / `armed` / `gap` / `unreachable`) in
      `test\win32\seam-audit.registry.json` - C3/C5 ALL PASS.
- [x] An `armed` entry's arm is CHECKED, not asserted: `<script>::<marker>`
      must exist and the marker must still be in the file (C6). The three
      armed seams are T747's own (`relay-account.ps1` section 8),
      `GHOZTTY_AGENT_AUTOSTART` (`agent-autostart.ps1` section C, the
      debug-gate refusal) and `GHOZTTY_COMPOSER_SURFACE`
      (`viewer-composer.ps1`, the shipped WebView2 surface the RichEdit
      fallback would otherwise hide).
- [x] The two gaps found are filed and OPEN, and the audit fails if a gap
      names a closed or non-existent task (C7, A14, A15): T1619
      (`GHOSTTY_LOCAL_AGENT_BIN` - all 49 agent scripts override the agent
      binary, so the beside-the-exe branch every delivery takes has never run)
      and T1620 (`GHOZTTY_CLAUDE_EXE` - `findClaude`'s PATH walk has no
      coverage of any kind).
- [x] The ceiling may only fall: gaps (2) == `gapCeiling` (2); a file below its
      ceiling fails too, naming `-UpdateCeiling` (D1, D2).
- [x] A new seam cannot arrive already excused: an unregistered seam fails
      (A6, teeth T1), a stale entry fails (A7, teeth T2), a broken arm fails

- [x] NEGATIVE CONTROL: the fixture tree with a CORRECT registry produces zero
      findings (B1), so section A is not passing on an analyzer that reports
      everything.
- [x] The rule is enforced standing, not remembered: a `seam-audit` row in
      `scripts\guard-due.ps1` (covering `test\win32\*.ps1`, `lib\*.ps1` and the
      `src\` trees where seams are read) and a row in the harness floor
      (`scripts\lib\HarnessFloor.ps1`), documented in `test\win32\README.md`
