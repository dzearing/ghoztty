# T3209 - The pane sidebar's folded windows unfold after a relaunch on Windows: the session layout saves no window identity for the all-windows list, so a window's fold cannot survive (Mac paneSidebarWindowID)

## Summary

User report 2026-11-17: windows collapsed in the pane sidebar were all expanded after an upgrade relaunch. The Mac manifest saves Entry.paneSidebarWindowID ('the window's identity in the all-windows list: its fold and its place in the list's shared order', macos/Sources/Features/Remote/SessionLayoutManifest.swift ~201) alongside paneSidebarPinned/Hidden/Order; the win32 session_layout.zig saves pane_sidebar_pinned/hidden/order but no window identity and no fold. Verify how the Mac persists the fold set (shared folds keyed by window id) and port it: save each window's sidebar identity and fold additively, restore it before first paint, and prove with an acceptance check that a folded window row is still folded after a kill + relaunch with persistence on (and from a Mac manifest). Do not regress older manifests (absent = today's default).

## In plain terms

The report was that windows folded in the pane sidebar came back unfolded
after an update. On the Mac, the sidebar's "all windows" list deliberately
forgets which windows you opened: every launch starts with every window
folded. Windows already does the same thing and already remembers each
window's place in the list. What was missing was a test that relaunches the
way a user does and checks the folds, so that is what landed.

## Findings (2026-11-17)

- **The premise does not hold on either platform.** Mac does not persist
  window folds: `PaneSidebarSharedState.unfoldedWindows` is in-memory only,
  and `allWindowsIsTheDefaultScope` (macos/Tests/PaneSidebar/PaneSidebarStateTests.swift:196)
  asserts "folds and search do not persist". A launch in the all-windows
  scope starts EVERY window folded. `paneSidebarWindowID` persists the
  window's identity for the list's shared ORDER (`windowOrder` keys), not a
  fold.
- **Windows already matches that.** `PaneSidebar.loadRemembered` ->
  `shared.launchScope(remembered.all_windows)` clears `unfolded` before the
  first window (pane_sidebar_shared.zig `launchScope`, T2564). Window
  identity is the tab's persisted `uuid` (T1048), and the order file keys on
  it (`window:<tab uuid>`, pane_sidebar_window_order.zig) - proven across a
  relaunch by section 7 of `test\win32\pane-sidebar-window-order.ps1`.
- **So a folded window cannot come back unfolded**: in the all-windows
  scope every window comes back folded. The user's report reads as pane
  BLADES collapsed from the sidebar's minimize (and by gutter drags), which is
  T3208 / T3213.
- Side finding (not a bug): every test launch rewrites `pane_sidebar-debug`
  to "this window" scope (`Clear-TestWindowPlacement`), so no relaunch test
  had ever opened in the all-windows scope the user runs in. The new check
  opts out with `-KeepWindowPlacement`.
