# T3424 - The win32 and none zig test lanes are red on a Linux viewer test: viewer_scheme 'candidates: template tiers' expects /share/viewer/img/a.png and Windows builds a backslash path

## Summary

src/apprt/gtk/viewer_scheme.zig:170 (from T3410's GTK viewer, b8d2b6141) is compiled into the win32 and none test lanes on Windows, and its candidates test asserts POSIX joins ('/share/viewer/img/a.png'); on Windows the join yields a backslash path, so 'zig build test' exits 1 and test-reach-audit B1/D1 go red in the harness floor (sweep 20261122-110344, log D:\zig-build-temp\ghoztty-t1191-42080\lane.log). Fix: either gate the gtk-only tests out of non-Linux targets or make the expectations separator-neutral, then re-run both zig lanes and test-reach-audit.

## In plain terms

A test for the new Linux viewer was written with Linux-style paths
(`/share/...`), but it also runs on the Windows build machine, where paths come
out with backslashes. So the Windows test suite reported failures that were not
real bugs, and that red hid any real ones. After this, the same test passes on
Windows and Linux and still checks what it was written to check.
