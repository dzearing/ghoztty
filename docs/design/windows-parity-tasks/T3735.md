# T3735 - Choose a pane's shell: command palette 'New Tab/Window/Split with Shell' and 'Restart Pane with Shell', a + dropdown, one entry per WSL distro, and a starting folder per shell (WSL takes a Linux path, default ~)

## Summary

User request 2026-11-25: 'i have no way to choose to spawn a shell of a different type ... i need something like a way to change a pane's shell, maybe through command palette?' and 'even with wsl, im not sure how to configure the starting folder, wouldn't it be something specific to wsl'. Build a shell choice that is per pane, not only the one global Shell setting. (1) Command palette entries: 'New Tab with Shell', 'New Window with Shell', 'Split Right/Down with Shell', each opening a sub-list of the installed shells the Settings Shell menu already finds (installedShells / controls.common_shells: PowerShell 7, Windows PowerShell, cmd, Git Bash, and one entry PER installed WSL distro from 'wsl -l -q', e.g. 'WSL: Ubuntu'). (2) 'Restart Pane with Shell...' replaces the focused pane's shell in place (same pane id, same slot), with the close-confirm rule when something is running. (3) The tab strip's + button gets a dropdown of the same list (the Windows Terminal convention Windows users expect), and the window menu's New Tab gets the same submenu. (4) Starting folder is PER SHELL: a WSL pane takes a Linux path (default ~, the distro's home, launched with wsl.exe --cd ~, never the slow /mnt/c mirror of the Windows folder); a Windows shell takes a Windows path. Settings > Shell gets a 'Starting folder' field per shell, WSL's validated as a Linux path; split/tab-inherit-working-directory inherits within the same family only (a WSL split of a WSL pane keeps its Linux cwd from OSC 7; a cmd split of a WSL pane falls back to that shell's own folder). (5) The CLI gets the same: +new-window/+split --shell=wsl:Ubuntu already exists in spirit (T1665) - make the distro form work and document it in docs/claude/cli.md. Session restore must bring each pane back on ITS shell and folder. Assumptions recorded here, no decision filed: the list is the installed shells, not user-defined profiles (profiles can follow); per-distro entries. Mac half: a separate seat: mac task. Linux half: seat: linux. Acceptance: a test that opens a tab via each palette entry and asserts the pane's shell process and its cwd (WSL: pwd inside the distro equals the home), a Restart-with-Shell test that keeps the pane id, and a restore test.

**WSL in tests (CLAUDE.md: never start WSL unasked).** Nothing in the Windows floor, sweeps or the go-loop may boot WSL, so every WSL arm of these tests is opt-in (`-Wsl`, skipped with a stated reason otherwise; the precedent is the ipc-command-keepalive WSL arm, T1751). The always-run arms prove the same code path with a non-WSL shell (pwsh / Git Bash), and the WSL arm is run by hand (or by the user) before close; record that run in this file.
