# T2119 - Stacked panes acceptance: a collapsed 5-pane row stays collapsed when a pane on show closes or splits, the caret lands on a pane on show, and undo brings the row back (T2083 on-box half; needs T2084's collapse gesture)

## Summary

T2083 landed the carry-over (PaneStackState.rowsDidChange via noteRows at layout time, paneOnShow on close) with unit tests only: Windows had no way to collapse a row by hand yet, so no on-box script could build the starting state. Once T2084 wires restack to the divider/grip drag, write test/win32/stack-collapse-carry.ps1 on the test desktop: a 5-pane row, collapse to 2 on show, close one on show (strips still strips by enumerated rects; caret on a pane on show), split one on show (still collapsed), undo the close (row back as before - needs T2084's Saved-with-the-tree undo).

## Validation criteria

- [ ] A collapsed 5-pane row (2 on show): closing a pane on show leaves the
      strips as strips (enumerated pane/strip rects before and after).
- [ ] The caret after that close is on a pane on show, never a strip.
- [ ] Splitting a pane on show keeps the row collapsed.
- [ ] Undoing the close brings the row back as it was.
- [ ] Runs on the test desktop only (no focus taken from the user).
