# T3288 - The About box's new labelled rows are never pixel-checked in the light and dark themes

## Summary

T1556 gave `ConfirmDialog` an `Options.rows` band (a right-aligned label
STATIC plus a read-only value EDIT per row), and the About box now uses it.
`test\win32\ipc-version.ps1` section 3 reads every row back and asserts that
the columns line up. It never looks at a pixel, though. The value cells are
read-only EDITs, which get their color from `WM_CTLCOLORSTATIC`
(`ConfirmDialog.isRowValue` -> `p.secondary` on `p.bg`). Nothing proves they
do not paint as a white field on a dark dialog, or as the wrong text color,
in either theme.

Fix: a PrintWindow pixel probe of the About box on the test desktop, run once
with the dialog on a light panel and once on a dark one. For each value cell,
assert that its background matches the dialog's surface and that its text is
the secondary color, not the body color.

## In plain terms

The Windows About box now lists its facts as tidy rows. The automated test
checks that the rows line up, but not that they look right in both light
mode and dark mode. This adds that check.

## Validation criteria

- [ ] A pixel probe of each row's value cell matches the dialog surface in a light theme
- [ ] The same probe passes in a dark theme
- [ ] Negative control: the probe fails when the value cells fall back to the default EDIT background
