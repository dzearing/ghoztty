# T1835 - Dragging a divider on Windows floods the program with resizes and pops a size overlay: Mac now debounces resizes and shows no overlay by default

## Summary

Mac 733b03e58: termio resizes reach the program on a trailing debounce (100ms settle, 350ms cap) instead of every 25ms; a 600ms divider drag went from 35 resizes to about 4 (aDragDoesNotStormTheProgramWithResizes). resize-overlay now defaults to never. Both are shared core (src/termio/Thread.zig, src/config/Config.zig) and land with the merge. Windows owes: (1) prove a win32 divider drag and a window-edge resize deliver a handful of resizes to a ConPTY child, not dozens - and that the final size always arrives; (2) the win32 resize overlay honors the new default; (3) no regression to the T1800 / resize-flicker / drag-perf harnesses.
