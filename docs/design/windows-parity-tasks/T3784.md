# T3784 - Linux: goto_window in separate mode walks the windows in the pane sidebar's all-windows order (Mac 997b26535, win32 T3132), not GTK's toplevel list

## Summary

P2: Linux separate-mode goto_window order (found in T3649); Linux follows Mac+Windows, so not in M1. Application.gotoWindow walks gtk.Window.listToplevels; the Mac and win32 step one along the all-windows list (PaneSidebar.listOrder + pane_sidebar_window_order.stepped, already used by single mode in Workspaces.gotoWindow).

## In plain terms

On Linux, the "next window" / "previous window" shortcut jumped between
windows in the order they happened to be opened, not the order the pane
sidebar lists them in, so the keyboard and the sidebar disagreed about what
"next" means. Now the shortcut walks the sidebar's list, one entry at a time
(each tab counts, as it does on Windows), wrapping at both ends, starting
from wherever you pressed it, exactly like the Mac and Windows builds.

## Goals

- [x] separate-mode goto_window steps one along the sidebar's all-windows list from the pressing tab, wrapping
- [x] each tab of a window is its own stop, and landing on one selects it
- [x] single-window mode keeps its workspace walk untouched
- [x] an acceptance script with a negative control

## Where

- `src/apprt/gtk/Workspaces.zig` `gotoWindowSeparate`: the walk (`PaneSidebar.listOrder`, visible windows only as on the Mac, `pane_sidebar_window_order.stepped`).
- `src/apprt/gtk/class/application.zig` `Action.gotoWindow`: single mode returns the workspace walk's answer; separate mode starts from the target surface's window (an app-target action falls back to the compositor's active window). The old `listToplevels` walk and `gotoWindowMaybe` are gone.
- `src/apprt/gtk/IpcHandlers.zig` `workspaces` seam: new `stops` field (window, tab position, selected) - the test's oracle.

Design call (mechanism, not experience): the start is the window the chord came from rather than GTK's `isActive` toplevel, because a compositor may never report one active (Weston headless has no seat) and win32 T3132 starts from the pressing window too.
