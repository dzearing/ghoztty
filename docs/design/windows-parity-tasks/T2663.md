# T2663 - Lane a's watchdog opens its window as --target=main, so when another window is already named main it only focuses that window and the loop never comes back

## In plain terms

When the automatic loop died, its supervisor tried to bring it back by opening a
window called "main". If the user's own chat window already had that name, the
supervisor just brought the user's window to the front, said "done", and the
loop never restarted. Now the supervisor checks who owns the name first, and if
it is not the loop's own window it opens the loop under a name of its own.

## Summary

`go-loop-watchdog.ps1`'s last-resort re-entry ran `+new-window
--target=$WindowTarget` ('main' for lane a). Named targets are focused, not
recreated, and 'main' is the name the upgrade script gives the user's own
Claude window, so on 2026-11-03 07:01 a `-Force` re-entry focused the controller
chat, exited 0, and the lock never reached held (RECOVERY UNCONFIRMED).

Fix: `Resolve-ReentryTarget` lists windows before the re-entry. The configured
name is used when it is free or held by a window titled with this lane's
marker (`[go-loop]` / `[go-loop b]`); otherwise the re-entry opens as
`<target>-loop` (lane a: `main-loop`), a name only this function ever gives a
window - so it is trusted marked or not and a rearm focuses it instead of
stacking windows. An unreadable `+list` keeps the old behavior. The reason is
logged.
