# T1870 - Prove session-relaunch-notify arm H can go red: run it against an agent or app that withholds holder_lost

## Summary

T1793 added arm H (a pane's holder killed while attached). Every assertion passed against the fixed build, but no run has shown the arm failing against the old behavior (plain EXIT, pane closes). Add a test-only way to withhold capability.holder_lost (e.g. an env seam on the client advertisement, like GHOZTTY_RESUME_COUNT_BYTES) and a -BreakHostLost teeth switch that runs arm H with it and must score H6-H13 red.

## In plain terms

When the background process hosting one terminal pane dies, the pane now stays
open and says "Session interrupted" instead of silently vanishing. The test that
checks this has only ever been seen passing. This task makes it possible to run
that test against the old behaviour on purpose and watch it fail, so a pass
actually means something.

## Goals

- [x] a test-only switch that makes the app behave like a pre-fix build (never asks the agent for the new behaviour)
- [x] `session-relaunch-notify.ps1 -BreakHostLost` runs arm H under that switch and arm H goes red
- [x] the ordinary run stays green
