# T1744 - TTF_SUBCLASS in win32.zig is 0x0001 (really TTF_IDISHWND), so viewer nav-bar and feedback-bar tooltips may never show

## In plain terms

Hovering the buttons along the top of a viewer pane (back, forward, contents,
the diff toggles, and so on) and the send/attach buttons of the feedback
composer was supposed to show a small label explaining each one. A wrong
number in one shared definition meant Windows was never told to watch the
mouse for those buttons, so the labels were set up but never appeared. After
this lands, hovering those buttons shows their labels, the way Mac does.

## Goals

- [x] `TTF_SUBCLASS` carries commctrl.h's value (0x0010); `TTF_IDISHWND` is named in its own right
- [x] the machine chooser drops its private workaround and uses the shared constants
- [x] a win32-lane test proves a subclass tool is actually RELAYED the owner's mouse moves, and goes red against the old value

## Summary

`src/apprt/win32/win32.zig` declared `TTF_SUBCLASS = 0x0001` since T633. In
commctrl.h 0x0001 is `TTF_IDISHWND` and `TTF_SUBCLASS` is 0x0010. Both viewer
bars (`ViewerNavBar.zig`, `ViewerFeedbackBar.zig`) register rect tools with
`uFlags = w32.TTF_SUBCLASS` and `uId = 0x200 + button`, so comctl32 took each
one as a window tool keyed on a non-existent HWND and never subclassed the bar:
no mouse message reached the tooltip and no tip could show. `TTM_ADDTOOLW`
succeeded, `TTM_GETTOOLCOUNT` counted the tools and the bars logged their
rects, which is why every existing oracle (viewer-diff, viewer-feedback,
viewer-worktree read the `viewer ... tips` line) stayed green. T1633 found the
bad value and worked around it locally in `chooser_tooltip.zig`.

Fix: correct the constant, add `TTF_IDISHWND`, point the chooser at the shared
constants, and add `src/apprt/win32/tooltip_flags.zig` (listed in the win32
lane's test root): it pins the four TTF_ values to the header and, in
process, creates an owner window + tooltip, registers a rect tool exactly the
way the viewer bars do, sends ONE `WM_MOUSEMOVE` to the owner only, and
asserts `TTM_GETCURRENTTOOLW` names that tool. Only a real subclass can carry
that message to the tooltip.
