# T2046 - Switching back to a tab after the window was resized under it moves on before its panes have drawn at the new size: tabswitch pass reads timeouts=1 stale=4 of 4 under an 8ms present lag

## Summary

Found by T1035's present-lag oracle (resize-flicker.ps1 section D5, GHOZTTY_PRESENT_LAG_MS=8): on two runs out of two the cause=tabswitch pass logged waits=1 timeouts=1 stale=3 and stale=4 of 4 panes, while every other window pass under the same lag ended woken with stale=0. A hidden tab's panes take the new size only when the tab is shown, and their first frame apparently does not fit the one-frame budget - which on a vsync-throttled desktop is a frame of the previous size as the tab appears. Not yet measured at lag 0 or on the interactive desktop; start there, then find what the tab-show path does before the renderer can present (occlusion wake? renderer paused while hidden?). Section D does not assert window-pass stale today; add that assertion once fixed.
