# T2827 - The pane sidebar's card following a grid glide (T2406) is resized and repainted from the window thread on every glide tick, so a busy window thread freezes it while the declared grid glides on in the composition pane tree

## Summary

Split of T2780. PaneSidebar.gridStepped (PaneSidebar.zig ~3594) runs from Window.stackSlideTick: it reads paneSidebarFollowLag, SetWindowPos-resizes the sidebar's child window and UpdateWindow-paints it, every tick. Once T2825 declares the strips that the grid's shift moves, the grid's whole leading edge glides on the compositor through a stall and the sidebar column beside it does not, so the gutter between them opens and closes. The sidebar column has to become a declared shape too (its card's edge on the same 45 ms follower as Slide.leadingLag's card), or the column glide has to own the clock. Oracle: the sidebar arm T2825 adds to comp-glide-hold-onscreen.ps1, scoring the gutter between the sidebar card and the grid's leading card through a GHOZTTY_DEBUG_GLIDE_STALL_MS stall (constant within 2 px on every frame), -NoDeclare red.
