# T2205 - Mac: New Window on a relay window opened with an explicit --token shows 'sign in required' even though the window's own link is live

## Summary

Platform-symmetry half of T1277. Windows now opens New Window on a relay window using the bearer the parent was dialed with when the account store is empty (remote_reconnect.chooseRelayToken). The Mac's WP-B2 guard in TerminalController.newWindowInheritingRemote refuses whenever RelayAccount.hasCredentials is false, which treats a +new-remote-window --token window as an account resource. Make the guard skip a parent whose machine carries an explicit dial token (the new window shares the parent's live connection anyway), keeping the refusal for genuinely account-backed parents. Validate: signed-out Mac app, +new-remote-window --relay --device --token, then New Window -> a second connected relay window, no sign-in alert.
