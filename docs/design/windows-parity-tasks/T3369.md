# T3369 - Linux L7e: +reload reloads the GTK app config

## Summary

+reload is served by the GTK frontend: it reloads the config the way the GTK reload_config action already does, and answers what the Mac answers (success, or the config error). Acceptance: a test/linux/cli-*.sh script in the headless harness that edits a config value and observes it change.

## In plain terms

On Linux, `ghoztty +reload --config` used to answer "not served yet". Now it
re-reads your config file and every open window picks up the change at once,
exactly as on the Mac and Windows - edit a colour, run the command, see it.

## Goals

- [x] `+reload --config` runs the GTK reload_config action (hard, app-wide) and answers success
- [x] the effect is proved by a headless test that edits a config value and watches an open pane change
- [x] viewer-reload.sh R29 flipped from the "not served" sentence to success
