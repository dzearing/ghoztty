# T2105 - Stacked rows on glass have no solid cards: a tucked card is its strip alone, content hidden, and its terminal keeps its last on-show size

## Summary

Mac 89848fd59 (PaneStage/PaneLayout): stacked rows dropped PaneCard.isSolid (the 92%-opaque card so the card behind would not show through glass). A tucked card on either side of the run is drawn as its strip alone with its content hidden, and its terminal keeps the size it had when last on show - it is never resized while minimized. Windows has no stacked rows until T2082 lands; this is the glass half of that layout, which none of T2082/T2083/T2084 names. The one-resize-per-slide half is already T2082's validation. Split out of T2086.

## In plain terms

When a narrow window folds some panes of a row into thin strips at its edge,
those folded panes used to be quietly resized every time the row changed -
shrink the window and a program nobody could see redrew itself for a new size.
Now a folded pane stays exactly the size it was when you last saw it, and takes
its new size once, when you bring it back. On a see-through (glass) window
nothing of a folded pane sits behind the panes on show; only its strip shows.

## Goals

- [x] a tucked pane is drawn as its strip alone, its content hidden (already true since T2109: the layout marks every tucked card on either side of the run `is_sliver`, and the window hides its pane)
- [x] a tucked pane's terminal keeps the size it last had on show, through window resizes and row reflows
- [x] brought forward, it slides at that held size and takes its slot's size once, at the end of the slide
