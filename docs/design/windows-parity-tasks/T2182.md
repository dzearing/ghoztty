# T2182 - Ctrl+C in an .icns image pane copies nothing, though the pane now shows the icon

## Summary

Found closing T1234. The image pane now SHOWS an `.icns` by serving its widest
embedded PNG (`viewer_image.icnsBestPng`), but ctrl+C (`image_copy.copyFile`,
T1872) still decodes the FILE through WIC, which has no ICNS codec: the copy
logs `image decode: no decoder for ... hr=0x88982f50` and the clipboard is left
untouched. Mac's image pane copies the icon it shows. Fix: in `copyFile`, when
the extension routes `.icns`, decode the `icnsBestPng` slice instead (WIC from
memory - `CreateDecoderFromStream` over an `SHCreateMemStream` - or publish the
PNG bytes verbatim plus a DIB from that decode).

## Validation criteria

- [ ] `test\win32\viewer-image.ps1` K-section row: ctrl+C at the T1234 .icns pane puts a 128x128 picture on the clipboard, with the PNG format the embedded bytes verbatim.
