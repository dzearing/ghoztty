# T3664 - The Settings window takes several seconds to appear on Windows; it should open at once, as on the Mac

## Summary

User report 2026-11-24: "on windows, the settings pane takes quite a few seconds to pop open. should be opened rather instantly". Mac opens it at once.

SettingsWindow.open (src/apprt/win32/SettingsWindow.zig:321) does ALL of its work before the first ShowWindow: create() builds SettingsCatalog.defaults (the whole config schema), resolves the default file paths, opens ConfigFileStore, then reloadData(); open() then refresh()es every row before SW_SHOW. Nothing is on screen until the last of it finishes. Suspects to MEASURE first (do not guess): SettingsCatalog.defaults, reloadData (config parse / per-line validation on a scratch config?), ThemeCatalog.shared (hundreds of theme files read and parsed for the tile grid and live preview - does the first open load them eagerly even when the Appearance page is not showing?), the Sessions & Agent / Remote Machines live sections (T2686/T2687 say read without blocking - confirm they do), and the first layout/text measuring pass.

Target: the window is on screen within ~100 ms of Ctrl+, (first open, cold), and a re-open of an existing window is immediate. Approach: time each phase with the log (the 'settings: opened' line exists - add per-phase ms), then show the window first and defer or cache what is slow (theme catalog lazily on the Appearance page or on a worker, schema catalog cached across opens). Acceptance: a harness that opens Settings via the open_config action on the test desktop and asserts the window exists within a latency budget on first and second open, plus a log-timed phase breakdown recorded in this file.
