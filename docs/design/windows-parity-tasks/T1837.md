# T1837 - ipc-relay is red on two checks: a token-less relay dial says the agent is unreachable instead of not signed in, and a relay window whose agent dies is left disconnected with no way back

## Summary

Found running ipc-relay.ps1 for T1826 (reproduced twice, 2026-10-11): section 4 'error says not signed in' FAILS - a +new-remote-window --relay dial with no token now prints 'failed to reach <device> via relay ...: the agent is not running or not reachable' instead of the Mac-parity not-signed-in error; section 6 'the window is still recoverable' FAILS - after the agent is killed under a live relay window, +list reports connection {state: disconnected, self_healable: false}, so nothing will re-dial it. The T1826 merge touched nothing on the relay path (its non-mac files are CLI verbs, config, termio, renderer, viewer.css); the harness was last stamped green 2026-09-12 and its covered files had not changed since, so the regression most likely came in with yesterday's agent work (b0c7ddb72 merge, T1798 aef247988, T1800 d4bc84787) and went unseen. Bisect those, fix, and re-run ipc-relay.ps1 green. Logs: %TEMP%\h-relay2.log.

## In plain terms

The relay-window test went red in two places, and it looked like remote
windows had broken. They hadn't. The test's app was using your real
signed-in account instead of the test's own setup. A "signed out" check was
never really signed out, and a "reconnect" check got turned away by the local
test server. The test now gets its own empty account and runs on a hidden
desktop, so it stops opening windows on yours.

## Root cause

Not a product regression. `handleNewRemoteWindow` and the reconnect ladder
(`RemoteReconnect.startAttempt`) both resolve the relay credential from the
account store FIRST (`IpcHandlers.resolveToken`). The default store is
`%LOCALAPPDATA%\ghoztty\account.dat`, which is the user's real one, and the box
is now signed in (the file exists and gets renewed). So:

- section 4's "tokenless" dial carried the user's real bearer. The local
  DEV_AUTH relay 401'd it, giving `DialFailed`: "not reachable" rather than
  "not signed in".
- section 6's re-dial chose the store token over the window's dial token
  (`chooseRelayToken`, store wins because it renews), got a 401, and a 401 is
  terminal by design: `{disconnected, self_healable:false}`.

The bisect suspects named in the summary (b0c7ddb72, aef247988, d4bc84787) are
cleared. The trigger is the box's sign-in state, not code.
