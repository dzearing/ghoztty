# T1342 - A fact corrected in one doc stays wrong in the other four that repeated it, and nothing looks

## Summary

Found closing T490. On 2026-08-23 T1158 corrected a sentence in
`test\win32\lib\BuildMode.ps1` that claimed the local agent's pipe had no env
override — false since T167 — and its log entry named that sentence as
*plausibly how the soak's author concluded the pipe suffix was all that was
available*, i.e. as a direct cause of the defect that had been seeding the
user's roster with immortal pinned sessions. The correction landed in that one
file. The identical claim was sitting in FOUR more (`docs/claude/build.md`, the
header of `test\win32\lib\Isolation.ps1` where the suffix is minted, step 3 of
`go.md`, and the Details of T1023) and stayed there for twelve more days, until
a turn that happened to grep for it. Nothing in the repo asks "where else is
this written down?" when a fact changes, so the useful lifetime of a correction
is however long the person making it thinks to search.

Two shapes worth separating. The first is what T490 hit: a claim about the code
repeated in prose across docs, harness headers and task files, where the code
moved and the prose did not. The second is the one the tree already handles well
— `build-mode-guard.ps1` section G asserts that `docs/claude/build.md` and
`go.md` carry a specific warning, so those two files cannot silently lose it.
The gap is that G checks for the PRESENCE of the right sentence, never for the
persistence of a wrong one, and it only covers claims somebody thought to pin.

Directions, none of them settled: a `test\win32\doc-claims.ps1` carrying a
registry of retired claims (the phrase, the commit that made it false, and the
correction to point at) that fails the tree on any recurrence — cheap, exact,
and it grows one row per correction, which is the same shape as
`guard-due.ps1`'s coverage table; or having `parity-tasks.ps1` prompt for a
tree-wide grep of a corrected phrase at close time; or a periodic sweep that
flags prose naming an env var, function or file that no longer exists. Prefer
whichever fails LOUDLY at the moment the stale sentence is next read rather than
whichever finds the most.

## In plain terms

When we discover that something written in the docs is wrong and fix it, the
same wrong sentence is usually copied into three or four other files, and
nothing goes looking for the copies. The next person reads one of those and
believes it. That has already caused one real bug in the user's terminal, and
the fix for it left four copies of the sentence that caused it standing for
another twelve days.

## Goals

- [x] A registry of retired claims, one row per correction
- [x] A harness that fails the tree when a registered claim is written again
- [x] The rule written down where a test author reads (`docs/claude/testing.md`)

## Validation criteria

- [x] A retired claim (phrase + the commit that made it false) can be registered, and re-introducing it anywhere in the tree fails a harness - `test/win32/lib/RetiredClaims.ps1` holds the rows; `test/win32/doc-claims.ps1` section C scans every tracked text file; `-NegativeControl` plants the claim in `docs/claude/build.md` and the scan reports it (N1 red as designed, N2 restores the file)
- [x] The five T490 sentences are in that registry as the seed set, and the harness is red against the pre-T490 tree and green against today's - one row, `agent-pipe-no-env-override`, with five `Proofs` read from git (`ce943e238^` BuildMode.ps1; `63f2bab35^` build.md, Isolation.ps1, go.md, T1023.md). Section B catches all five; section C is green on today's tree (ALL PASS, 29 assertions)
- [x] The historical log (`windows-parity-log.md`) and closed task files are excluded or handled deliberately - same history line as merge-terminology: log, digests, decisions, audit/details/spec files, done/skipped tasks and open tasks' progress logs are not scanned; quoted mentions and blockquotes are allowed. Fixtures A5-A17 cover each one
- [x] A `guard-due` row, so the harness re-runs when the files it scans change - `doc-claims` row in `scripts/guard-due.ps1` (registry, harness, CLAUDE.md, go.md, docs/claude/*.md, BuildMode.ps1, Isolation.ps1); stamped green

Design choice: the registry direction, not a close-time grep prompt or a dead-name sweep. It fails loudly the next time the stale sentence is written, which the Summary asked for, and it grows one row per correction. Patterns run over normalised text (comment leaders stripped, whitespace collapsed, lower case, straight apostrophes), so a claim wrapped across comment lines is still one match.
