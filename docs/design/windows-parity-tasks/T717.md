# T717 - The ghoztty:// activation process warns with a system MessageBox, not the themed dialog every other prompt uses

## Summary

T695's URL-scheme activation runs in a short-lived process with no `App`: the
shell launches `ghoztty.exe "ghoztty://focus/x"`, it forwards a `focus` over
IPC and exits. When the link names nothing that is open, it warns with
`MessageBoxW` (`src/apprt/win32/url_scheme.zig`, `present`) — the light system
dialog T80 replaced everywhere else with `ConfirmDialog`'s dark card. The
in-app path (a banner or viewer link, where there IS an app) already uses
`ConfirmDialog`; only the external path is a system box.

`ConfirmDialog.show` takes `app: *App`, which the activation process has
nothing to hand it. The fix is either a small app-less entry point into the
same dialog class (it needs the theme colors and a message pump, not the app's
state), or posting the presentation into the running instance when there is one
— noting that a modal dialog must NOT be shown inline from the IPC handler,
which would block the serve thread until the user clicks OK.

## In plain terms

Click a Ghoztty link that points at a window you already closed and you get a
plain grey Windows warning box, not the dark dialog the rest of the app uses.
It says the right thing; it just looks like it came from a different program.

## Goals

- [x] The external `ghoztty://` warning is the app's own themed dialog
- [x] It is drawn at the display's scale, not a flat 96 DPI
- [x] The acceptance harness measures the dialog CLASS, so a relapse to the
      system box scores red
