# T2353 - Two loop lanes running the win32 test lane at once fail ViewerPane 'host floor' copy test (clipboard=null): the system clipboard is box-wide, so the lanes' clipboard tests need a box-wide lease

## Summary

Seen 2026-10-27 by lane b during T2350: `floor-lane.ps1 -Lane all` went red on
`apprt.win32.ViewerPane.test.host floor: a real controller on a real window,
on this box` at ViewerPane.zig:9711 (`copied != null`; log `copy[md]:
clipboard=null`), side by side AND alone. At that moment lane a
(D:\git\ghoztty) was running its own `zig build test -Dapp-runtime=win32`
(ghostty-test.exe pid 64072). Once that exited, the same filtered test was
green on the first try (`copy[md]: clipboard=ghoztty copied this passage`).
The clipboard is per window station, not per worktree, so lane isolation
(build roots, mirrors) does not cover it. The acceptance runner already
serialises clipboard-touching scripts within one lane; nothing serialises the
zig test lane's clipboard tests across lanes.

Fix shape: a box-wide lease (like main-intake's) held by any test that
writes the system clipboard, or by the win32 lane as a whole, so a second
lane waits instead of reading the other's clipboard. Acceptance: two
concurrent win32 lanes both green.
