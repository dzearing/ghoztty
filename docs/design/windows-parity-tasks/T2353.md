# T2353 - Two loop lanes running the win32 test lane at once fail ViewerPane 'host floor' copy test (clipboard=null): the system clipboard is box-wide, so the lanes' clipboard tests need a box-wide lease

## Summary

Seen 2026-10-27 by lane b during T2350: `floor-lane.ps1 -Lane all` went red on
`apprt.win32.ViewerPane.test.host floor: a real controller on a real window,
on this box` at ViewerPane.zig:9711 (`copied != null`; log `copy[md]:
clipboard=null`), side by side AND alone. At that moment lane a
(D:\git\ghoztty) was running its own `zig build test -Dapp-runtime=win32`
(ghostty-test.exe pid 64072). Once that exited, the same filtered test was
green on the first try (`copy[md]: clipboard=ghoztty copied this passage`).
The clipboard is per window station, not per worktree, so lane isolation
(build roots, mirrors) does not cover it. The acceptance runner already
serialises clipboard-touching scripts within one lane; nothing serialises the
zig test lane's clipboard tests across lanes.

Fix shape: a box-wide lease (like main-intake's) held by any test that
writes the system clipboard, or by the win32 lane as a whole, so a second
lane waits instead of reading the other's clipboard. Acceptance: two
concurrent win32 lanes both green.

## In plain terms

The automated tests that check copy and paste all share one clipboard on
this machine. When two test runs happened at once, one run's clipboard check
could catch the other run in the middle of using the clipboard, and it then
reported a broken Copy button that was not broken. Now every clipboard test
on the machine waits its turn for the clipboard, so a red result means a
real defect. Nobody using the terminal notices the change; it stops false
alarms in the test runs.

## Goals

- [x] One box-wide turn-taking lock, shared by every test that opens the clipboard (`clipboard_test_lock.zig`)
- [x] The clipboard_open round-trip tests take it (they opened the clipboard unlocked, one of them exclusively)
- [x] The viewer copy test's save of the user's clipboard takes it too
- [x] Proof that the lock excludes a second holder and survives a dead one

## Re-verification (2026-11-26)

The viewer copy oracle has held a session-wide named mutex since T850
(August), so two lanes' copies of THAT test already queued. What was still
unguarded: `clipboard_open.zig`'s round-trip and holder tests (the holder
test opens with a real window, which excludes every other process while it
lasts), and the copy section's initial read of the user's clipboard. The
10-27 event itself also has the T2346 shape (refusal with no window named,
gone the moment lane a's process exited), which T2346's `held_unnamed`
classification now reports as a named SKIP rather than a red. T2719 is the
open card for catching that holder live.
