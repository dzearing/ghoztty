# T1717 - A CLI value flag written with an empty value (--target=) is still forwarded in silence

## Summary

Carved out of T950. That task made the forwarding-verb allowlist check the SHAPE of each flag (value flags need '=', switches refuse one) but deliberately stopped at the presence of '=': --target= with nothing after it passes the CLI and reaches the server as an empty target. Audit each value flag in src/cli/verb_flags.zig (and +send-keys) for whether an empty value is ever meaningful (e.g. --split-command=, --working-directory=), then reject the empty form where it is not, with the same 'write it as --flag=<value>' message. P3: rarer than the no-= shape, and needs the per-flag audit first.
