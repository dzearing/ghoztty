# T1818 - Measure what Claude Code's fullscreen renderer does on a Windows pane resize, against T1763's clear-and-repaint

## Summary

T1801 turned on `CLAUDE_CODE_NO_FLICKER=1` in Windows panes by default (the
Mac's `claude-code-fullscreen`). The Mac commit's claim is that Claude's
fullscreen renderer re-lays out its own conversation on resize instead of
writing pre-wrapped rows into scrollback, which should also remove the
clear-and-repaint frames T1763 measured on the classic renderer (one Ink frame
leaves conhost as `?2026h 2J 3J ?2026l` followed by an unbracketed paint;
T1763 fixed it with the ConPTY sync hold).

Nobody has measured that on Windows. Do it: run Claude Code in a Debug pane on
the test desktop with and without the variable, resize it, and record the
ConPTY output stream per resize (the T1763 scratch probe shape) - count frames
that close a sync bracket on an empty screen, and whether the T1763 hold still
fires. If fullscreen makes the hold unnecessary for Claude, say so; do not
remove the hold (other TUIs still need it).

## Validation criteria

- [ ] Per-resize byte capture for Claude Code classic vs fullscreen on this box, numbers in the log.
- [ ] Whether the T1763 sync hold fires under fullscreen, measured.
- [ ] Runs entirely on the test desktop (never pulls focus).
