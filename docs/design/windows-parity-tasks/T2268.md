# T2268 - Windows cards glide on a fixed 380 ms curve where Mac now eases every card toward its latest target each frame (about 90% in 0.1 s, retargeted as the hand moves) (Mac a81db68f9)

## Summary

Mac PaneStageView.stepGlide: each frame k = 1 - exp(-dt / 0.045 s); every edge eases a + (b - a) * k, snapping when within 0.5 pt; a glide that catches up mid-drag RESTS until the layout moves again and ends only once the drag is over (observe isGesturing). Win32 pane_stack_slide.zig still runs T2102's fixed-duration cubic-bezier (380 ms, 200 ms gesture) from a start rect. Port the follower into the pure module (unit tests: k from dt, snap, settle, rest-while-gesturing) and drive Window.stackSlideTick from it.

## In plain terms

When panes fold into strips or come back out, Windows moved every card on a
fixed 0.38 second curve, and a drag that kept moving the layout made the cards
jump to catch up. On the Mac the cards now simply chase where they belong,
covering most of the distance in a tenth of a second and following the hand
smoothly while a drag goes on. Windows now moves them the same way.

## Goals

- [x] the glide is Mac's per-frame follower (`1 - exp(-dt / 45 ms)`, half-pixel snap), with no fixed duration
- [x] a target that moves under a drag is followed from where the card is drawn, never restarted or jumped
- [x] a glide that catches up under a drag rests (timer stopped, folded card hidden as its strip) and ends once the drag is released
- [x] the acceptance harnesses' stretched slide (`GHOZTTY_STACK_SLIDE_MS`) still slows it down for sampling
