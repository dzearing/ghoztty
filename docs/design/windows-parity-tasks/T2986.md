# T2986 - PA-W02: a resize outside the modal size loop (maximize, snap, restore, SetWindowPos) rebuilds the whole pane desk on every step, about 4 ms each (PaneDesk.zig:1127)

## Summary

PA-W02 (audit-1, T2960). The desk's live-resize canvas is only enabled from WM_ENTERSIZEMOVE (Window.zig:22473, the only non-test liveResize(true) caller); otherwise PaneDesk.zig:1127 returns the exact size and each step takes a new desk: ensureDesk re-renders and upscales the gradient, ensureComp recreates the DIB, and a full compose runs. The repo's own note (PaneDesk.zig:1102-1105) puts that at ~4 ms of a 120 Hz frame. The baseline resize phase is exactly this path (SetWindowPos every 50 ms: 13.8% CPU release, 31.0% debug); ~110 steps x 4 ms over 8 s is roughly 5% of a core (estimated). Fix: arm the canvas on any burst of size changes (a size change within N ms, or from handleResize) and drop it on a quiet timer, with the settle repaint (Window.zig:22497-22503) driven by that timer too. Risk medium: the gradient layout must still settle correctly.

## Validation criteria

- [ ] a SetWindowPos resize burst (no WM_ENTERSIZEMOVE) runs on the canvas: no ensureDesk/ensureComp per step (trace or counter)
- [ ] perf-baseline.ps1 -Phase resize: app CPU below baseline-1 (13.76% release / 30.95% debug) by more than the tolerance
- [ ] the settled desk after a burst matches the pre-change desk pixel-for-pixel (acceptance script on the test desktop)
