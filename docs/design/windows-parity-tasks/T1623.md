# T1623 - Tab tooltip sometimes ends the folder line with a stray trailing backslash

## Summary

The tooltip's folder line is the location verbatim bar the ~, so whether it ends in a backslash depends on which source answered: the OS-read live cwd can carry a trailing separator where the OSC-7 cache and a viewer location do not. Seen in tab-tooltip.ps1 arm C's oracle, where the same directory reads '~\AppData\...\tipB555\' one hover and '~\AppData\...\tipB555' the next. Nothing is WRONG, it just spells the same place two ways in a hover a user reads often. The fix is not a blanket trim: a root path is exactly the case where the separator is load-bearing ('C:\' must not become 'C:'), so trim only when a component precedes it. Where: tab_tooltip.zig tipText (pure, none-lane testable); the harness's arm C/E oracles use -like so they need no change, but the none lane should pin both the trimmed and the root case. Found while fixing T1622.
