# T3368 - Linux L7d: +rearrange rebuilds the GTK split tree from a layout

## Summary

+rearrange --layout=<json> is served by the GTK frontend: validate with the shared apprt.ipc.args.validateLayout / firstDuplicate (as win32 handleRearrange does), resolve every named pane in the active tab, and rebuild the GTK SplitTree to the layout with its ratios. Acceptance: a test/linux/cli-*.sh script in the headless harness that checks the +list tree after the rearrange.

## In plain terms

A script or agent can now tell the Linux app "lay this window's panes out
like this" in one command, the way it already can on Mac and Windows. The
panes move into place with their programs still running; a pane left out of
the new layout is closed. Before this the Linux app answered "not served yet".

## Goals

- [x] `+rearrange --layout=<json>` rebuilds the window's split tree with the given directions and ratios
- [x] the panes keep their shells, ids and names when moved
- [x] a pane the layout leaves out closes with its shell
- [x] bad layouts are refused with win32's sentences and nothing moves
- [x] with no `--target`, the caller's window is the one rearranged

## Validation criteria

All in `test/linux/cli-rearrange.sh` (headless Weston, via
`scripts\linux\wsl-run.ps1`), `CLI REARRANGE: ALL PASS` 28/28 at 947bab45a.

- [x] The tree after a rearrange is the layout, ratios included: M1 (`V30(c,H70(b,a))` read back from `+list`).
- [x] Moved panes are the same panes: M2 (same shell pids, alive), M4 (`+send-keys`/`+read` by name still drive b).
- [x] Focus: M3 (kept on the surviving focused pane), O4 (moves to the top-left pane when the focused one is left out).
- [x] An omitted pane closes with its shell: O1-O3, C2; ratio 95 clamps to 90 (O1).
- [x] Refusals leave the tree untouched: E1-E7 (no layout, bad JSON, duplicate, unknown pane, pane of another window, bad direction, unknown target).
- [x] No `--target` = the caller's window: C1 (run from rw's pane while rx is the newer window).
- [x] No panic or GTK critical: P1, P2.
- [x] No regression in the neighbouring suites (split_tree.zig changed): CLI CLOSE FOCUS, CLI WINDOWS, CLI SEND READ, IPC SERVER all ALL PASS; LINUX FLOOR ALL PASS (lib/none/agentx/agent), same run.
