# T3709 - Linux L11b5c: hovering a pane's top edge reveals a grab handle that drags the pane with rearrange mode off

## Summary

Split from T3617, which shipped the ghost card. Port the hover-revealed grab handle at the top of a pane (win32 pane_grab_handle.zig, Mac's handle): it appears when the pointer nears the pane's top edge with rearrange mode OFF, its cursor is an open hand, and dragging it starts the same pane drag the rearrange header starts (same PaneDrag source, same ghost card, same drops). Headless harness reads the handle's visibility and geometry through a debug seam; the pointer drag itself is NOT RUN headless.

## In plain terms

On Linux the only way to drag a pane somewhere else was to turn on rearrange mode first and grab the header it adds. On the Mac and on Windows you can just move the pointer to the top of any pane: a small pill with three dots fades in, darkens when you are on it, and dragging it moves the pane. Linux now does the same, with the same pill, and dragging it goes to all the same places the header drag does.

## Goals

- [x] the pointer in a pane's top band shows the grip faintly; on the grip it is solid; elsewhere it is gone
- [x] the grip is the Windows grip pixel for pixel (same rules and renderer, shared), with an open-hand cursor
- [x] no grip in rearrange mode, in a fullscreen window holding one pane, while typing has hidden the pointer, or under another drag
- [x] dragging it is the header's drag: same ghost card, drops, preview and release-over-nothing pop-out
- [x] the pane-drag seam can move the pointer over a pane and start/end a handle drag, and reads the grip back
