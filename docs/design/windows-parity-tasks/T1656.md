# T1656 - An @() wrapped around a comma-protected PS helper silently counts every result as 1, and no audit looks for it

## Summary

T853 found this shape live in scripts\test-binary-soak.ps1: three helpers used the 'return , $array' idiom while every call site wrapped the call in @(). The wrapper SURVIVES the @(), so the call site saw Count 1 whether the helper had collected nothing, one item or five - a soak in which two load workers crashed reported worker-crash=1 with both slot numbers member-enumerated into one mangled line. unroll-count-audit.ps1 already measures both halves of the trap (assertions B5/B6) and its lib deliberately drops comma-protected helpers from the index, so the INVERSE shape - an @() wrapped around such a call - is known and unaudited. Add that rule to test\win32\lib\UnrollCountAudit.ps1: a bare @(Helper ...) whose Helper is comma-protected in scope is a finding (a piped @(Helper | ...) is NOT - the pipeline re-enumerates and the count is right). Then sweep test\win32 and scripts with it and fix what it finds, either by unwrapping the call or by making the helper return plainly. A first heuristic pass over the repo listed ~40 candidate sites (agent-recovery.ps1, chooser-*.ps1, tab-tooltip.ps1, session-persistence.ps1, floor-lane.ps1 among them), but the heuristic matched comments too, so the real number is the audit's to establish.
