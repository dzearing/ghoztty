# T1914 - The Windows pane sidebar lists at most 64 panes: with more (easy in the all-windows outline), the rest never appear, even now that the list scrolls

## Summary

Found in T1878. pane_sidebar.max_items caps the roster (and the Layout's fixed arrays, tooltip text buffers and tool ids) at 64; the all-windows outline across several busy windows passes that, and the extra panes are silently missing from the list and the rail. Mac's list has no cap. Wanted: the roster grows with the panes (heap-backed layout arrays or a higher cap with a visible overflow note), with the scroll pass, tips and drop rows following.

## In plain terms

The side list of panes stopped at 64 entries. With the "all windows" view on
and several busy windows open, any pane after the 64th simply was not in the
list, and there was no hint that it was missing. Now the list holds up to 512
panes, far more than anyone runs at once, and they all show and scroll.
