# T931 - The dashboard cannot tell you the box stopped signing itself in

## Summary

T829 measures every reboot's boot-to-desktop gap into temp\go-loop-boots.jsonl and shouts once at claim time when the box waited for a human. A watcher who missed that single line has nowhere to look it up, and the standing 'needs a human' state - the Windows auto-sign-in toggle that closes the last link - is invisible on the board. Wanted: the dashboard reads the boot ledger and go-loop-boot.ps1 check, and shows total loop downtime from reboots plus a persistent banner while unattended sign-in is off.

## In plain terms

When the PC restarts and nobody signs in, the loop stops working until someone
does. That used to be announced in one terminal line, once. The dashboard now
shows an amber bar on every view whenever the PC doesn't sign itself back in,
naming the Windows setting that fixes it, and the loop card shows how much time
reboots have cost in total. While building this, the total turned out to be
wildly overcounted (46 days instead of about 2), and that is fixed too.

## Goals

- [x] The dashboard reads `go-loop-boot.ps1 check` (in the background, cached, so polling stays fast)
- [x] A standing amber bar across every view while the PC doesn't sign itself back in, with the fix
- [x] The loop card shows total reboot downtime and the last outage
- [x] The downtime total is correct: each reboot counted once

## Design notes

- **Asked, not re-derived.** The server runs `go-loop-boot.ps1 check -Json`
  asynchronously on a 10-minute TTL and serves the last answer, like
  `paneHoldsClaude` asks go-loop-lock.ps1. The same-boot rule and the link-1
  verdict live in one place. `check -Json` gained `last_boot`, `last_outage`
  and `sign_in_fix` (the fix wording, verbatim) for it.
- **Drift duplicates (found here).** `LastBootUpTime` is now-minus-uptime, so
  clock corrections slide it by seconds, and the per-second ledger key was
  re-recording the same boot: 27 rows for 7 real boots, with 7 rows for the
  2026-09-09 reboot alone. Each duplicate re-printed the BOOT OUTAGE block and
  added its gap again, so `check` reported 46d 2h of downtime when the real
  figure is 2d 0h 26m. An Explorer restart later in the same boot also
  recorded the unattended 2026-08-26 boot as a 6-day outage. A boot is now the
  same boot if it falls within `-BootToleranceMinutes` (10) of a recorded one
  or has the same shell start. Readers collapse existing duplicates onto the
  first record, and the ledger file itself is left as written.
- **Amber, not red.** The loop is not stopped, only one unattended reboot away
  from stopping, so a real block (red, T1484) still out-shouts it. Both bars
  share one sticky host and stack.
- `Fmt-Span` rounded the remainder after flooring the hours ("3d 6h 60m"), so
  it now rounds once, up front.
