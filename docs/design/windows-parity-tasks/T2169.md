# T2169 - The portable build never puts itself on PATH or offers the Claude integration, unlike a Mac app run outside /Applications

## Summary

The Desktop portable copy the user runs never adds itself to the user PATH and
never makes the first-run Claude integration offer. Both self-heals use the
`.installed_release` gate of `install_location.SelfHealGate` (T1213), which only
the MSI install folder passes.

On Mac, the CLI self-heal re-points `~/.local/bin/ghoztty` at whichever bundle
launched. It refuses only a temporary location (a mounted DMG, an App
Translocation path) and Debug builds (`CommandLineInstaller.swift`,
`AppDelegate+Setup.checkCommandLineToolOnLaunch`). A Mac app run from the
Desktop is therefore first-class.

The Windows narrowing is forced by the PATH mechanism, not chosen.
`PathInstaller` APPENDS the running dir to `HKCU\Environment\Path`. Every copy
would add an entry that nothing ever removes, and the earliest entry keeps
winning, so a later copy would not even get the CLI.

The fix:
- Make the PATH entry Ghoztty writes a single OWNED value that the last launch
  re-points. Recognise our own previous entry, e.g. by a dir holding
  `ghoztty.com`. Never touch the MSI's own Environment entry.
- Move `PathInstaller` and `AgentIntegration` to `.not_build_output`.
- Add the Windows analog of the Mac "temporary location" refusal: an exe
  Explorer extracted from a zip into `%TEMP%\Temp*_*.zip\`.
- Update the rule table in `docs/design/windows-registration-sites.md` and
  B4/B5 of `test\win32egistration-sites.ps1`.

## In plain terms

If you run Ghoztty from an unzipped folder rather than installing it, it never
makes the `ghoztty` command work in your other terminals. It also never offers
to set up Claude. A Mac copy run from anywhere does both. After this, the copy
you launched last owns the `ghoztty` command, the same as on Mac.

## Goals

- [x] The portable copy puts itself on PATH, and the last launch owns the entry.
- [x] The portable copy makes the first-run Claude offer, once (its gate is
      now `.not_build_output`; the answer file is shared by every copy).
- [x] A copy run out of a zip preview (temp extraction) registers nothing.
