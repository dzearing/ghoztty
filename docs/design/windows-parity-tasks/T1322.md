# T1322 - A task the user reported looks like every other task on the dashboard

## Summary

`user-report: true` (T1315) changes what closing a task does, but the dashboard renders nothing for it: on the Activity feed and in the task detail view a bug the user reported by hand is indistinguishable from an internal chore. Show it - a badge beside the tags, and a filter in the Tasks view - so 'what is open that a person actually asked for' is answerable at a glance instead of by grepping frontmatter.

## In plain terms

On the project dashboard, a bug you reported yourself looked exactly like
something the automation found on its own, so there was no quick way to see
"what is still open that a person actually asked for". Now those tasks carry a
red "user report" badge everywhere a task shows up, and the Tasks list has a
filter that shows only them (or only everything else).

## Goals

- [x] the dashboard data carries whether a task was reported by a user
- [x] a "user report" badge beside the tags: in-flight rows, activity cards and their detail view, the task table, the task detail view
- [x] an origin filter in the Tasks view: reported by a user / not a user report

## Validation criteria

- [x] every task file with `user-report: true` reaches the payload as `userReport: true`, one for one - `test\win32\dashboard-dom.ps1` A4 (44 files, 44 in the payload)
- [x] the badge shows on a reported in-flight task and not on an unreported card - C49, C50
- [x] the task table badges the reported row and only that one - C51
- [x] the origin filter exists and narrows both ways - C52, C53 (reported only), C54 (none reported)
- [x] the task detail dialog of a reported task shows the badge - C55
- [x] the checks can fail: with the badge disabled, C49/C51/C53/C55 go red (negative control run by hand, page restored)
