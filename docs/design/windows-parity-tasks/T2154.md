# T2154 - agent-instance-lineage's bystander check goes red when the other loop lane's own test agents exit mid-run

## Summary

Seen 2026-10-22 during T1148: FAIL bystander agents untouched (before: 8, gone: 38796 26924 20556) - the three 'gone' pids were lane B's (D:\git\ghoztty-b) acceptance agents, created 05:12:40 by lane B's own test and torn down by it while lane A's run was in flight. Get-BystanderAgentPids snapshots every ghoztty-agent.exe on the box, so another lane's short-lived TEST agents count as bystanders this script must not kill. Fix: scope bystanders to agents not owned by a test run (exclude agents whose image/command line sits under another lane's tree or temp test root), or require a 'gone' pid to have been killed by THIS run. A cross-lane false red trains the loop to re-run instead of believe a failure.

## In plain terms

When two loop lanes test on the same machine, one lane's test sometimes saw the
other lane's throwaway test helpers shut down and reported "you killed
something you should not have" - a false alarm. The check now only watches the
long-lived helpers that belong to the person using the machine, so it stays
quiet about another lane's test helpers and still catches a real kill.
