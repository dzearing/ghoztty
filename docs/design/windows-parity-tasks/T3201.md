# T3201 - PA-V06 Mac half: an idle git-status: viewer re-runs the whole listing every poll; ask one fingerprinting git status first (ViewerGit.swift)

## Summary

Windows T3038 made the git-status: viewer's 2s poll run ONE 'git status --porcelain=v2 -z --branch --untracked-files=all' and fold each named path's size+mtime into a hash, re-running the full listing (repo root, staged+unstaged name-status and numstat, ls-files, untracked line counts) only when that fingerprint moves; it also caches the repo root per pane and untracked line counts by size+mtime. Measured on Windows: an idle pane went from about 6 git processes per tick to exactly 1 (viewer-diff.ps1 section 6). Mac's ViewerGit.listingSync (macos/Sources/Features/Viewer/ViewerGit.swift) does the full listing on every diffRefreshTimer tick (ViewerView.swift:2804). Port the same short-circuit; the pure argv + porcelain path walk are in src/apprt/win32/viewer_diff.zig (statusFingerprintArgv, porcelainPaths) for reference.
