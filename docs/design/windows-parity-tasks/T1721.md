# T1721 - The session manager and its holders log nowhere on Windows, so every warning they raise is invisible

## In plain terms

The background process that keeps your terminal sessions alive, and the small
per-session helpers under it, write their warnings to a place nobody can read
on Windows. When one of them notices something went wrong — lost output, a
session it could not re-attach — the note vanishes. This gives them a log file,
so the evidence exists when a session misbehaves.

## Summary

Found while landing T970 (verified, not inferred):

- The app launches the local agent with `DETACHED_PROCESS |
  CREATE_NEW_PROCESS_GROUP` through `job_spawn.spawnEscapingJob`
  (`src/apprt/win32/LocalAgent.zig`, the `spawnEscapingJob` call), and
  `job_spawn.zig` never sets `STARTF_USESTDHANDLES` — so the agent has no
  stderr at all.
- Holders are spawned the same way (`pty_holder_child.zig`,
  `DETACHED_PROCESS | CREATE_NO_WINDOW`).
- The agent has no custom `logFn` (`src/agent_main.zig` → default `std.log`,
  i.e. stderr). The shared `%LOCALAPPDATA%\ghoztty\ghoztty.log` sink
  (`src/os/log_rotate.zig`) is written by the APP's `logFn` in
  `main_ghostty.zig`, not by the agent.
- The only place agent stderr is captured today is the dev deploy watcher
  (`scripts/ghoztty-agent-watcher.ps1` → `agent.err.log`), which is not the
  user's path.

So on a user's box `holder replay gap: N byte(s) lost`, T970's `holder dropped
N byte(s) ... not yet saved`, `adopted holder ...` and every adoption warning are
written into the void.

Mac parity: the macOS agent runs under a LaunchAgent whose stdout/stderr are
redirected to files; the Windows-native equivalent is the agent (and each
holder) appending to a bounded file under `%LOCALAPPDATA%\ghoztty\` — the
existing `log_rotate` two-generation scheme is the pattern to reuse (the agent
and holders are exactly the "several writers" it was designed for). Check the
Mac plist's actual paths before choosing names so the two platforms document
the same thing.

## Validation criteria

- [ ] An app-launched agent's `std.log` lines land in a file under the
      per-user state dir (acceptance: launch via the app in an isolated
      `LOCALAPPDATA`, provoke a known warning, read it back from the file).
- [ ] A holder's warning (e.g. T970's drop line, reproducible with the
      pty-host smoke's 4 KB ring) lands in a file too.
- [ ] The file is bounded (reuses `log_rotate`), and a Debug build still
      writes stderr as today so existing harness captures keep working.
- [ ] Floor lanes stay ALL PASS.
