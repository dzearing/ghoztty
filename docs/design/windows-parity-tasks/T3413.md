# T3413 - Linux L9d: viewer live reload, +reload, and a dead web process restarts

## Summary

File viewers watch the viewed file (atomic saves included) and re-render keeping scroll; an HTML page re-fetches from disk; +reload and Ctrl+R bypass the cache. WebKit web-process-terminated reloads the pane at most 3 times in 60 s (viewer-panes.md A dead content process).

## In plain terms

On Linux, a document open beside your terminal used to show whatever was on
disk when you opened it. Now it updates by itself when the file is saved,
without jumping back to the top; `ghoztty +reload` refreshes a pane on
demand; and if the page's engine crashes, the pane recovers on its own
instead of going blank - unless it keeps crashing, in which case it says so.

## Goals

- [x] a markdown/code pane re-renders on a save (in place and atomic), keeping the scroll
- [x] a local `.html` page reloads in place on a save, keeping the scroll; a sibling stylesheet edit needs `+reload`
- [x] `+reload` reloads a viewer pane with win32's arguments and sentences (one shared body)
- [x] a dead web process is restarted, at most 3 times a minute, then the pane says the page keeps crashing
