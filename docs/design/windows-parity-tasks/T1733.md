# T1733 - win32 caption buttons (... / minimize / maximize / close) show no tooltip, where native Windows caption buttons name themselves

## In plain terms

On Windows, resting the pointer on a window's minimize, maximize or close
button pops up its name ("Minimize", "Restore Down", ...). Ghoztty draws its
own versions of those buttons, and until now they stayed silent on hover. With
this change they name themselves in the same words Windows uses, and the "…"
menu button says "Menu (Alt)".

## Goals

- [x] One pure function decides each button's tooltip text, with unit tests
- [x] Hovering "…", minimize, maximize/restore and close shows the tip
- [x] Acceptance proves it, with negatives; pill and tab tips still pass

## Summary

T1417 gave the caption band a tooltip host (the strip's control, TipSubject). The custom-drawn '...' and the three caption slabs still show nothing on hover; Windows' own caption buttons show Minimize / Maximize / Restore Down / Close. Add a pure caption_layout tooltip(button, zoomed) text fn (none-lane tested), extend TipSubject, and extend remote-pill/caption-bar acceptance the way T1417's section 6 does (Send-TestRawMessagePair hover+timer).
