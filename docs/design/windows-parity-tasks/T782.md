# T782 - Sweep scripts/ and test/win32 for ghoztty CLI calls that put non-literal text on PowerShell's argv (the T279 hazard), as a checked audit

## In plain terms

A previous fix taught our scripts the right way to hand text to the terminal's
command line, and repaired the places that were doing it wrong. Nothing stops
the next script from doing it wrong again — and when it does, the symptom is
text that silently arrives with pieces missing. This adds the check that
notices.

## Goals

- [x] An AST analyzer that tells a hazardous argument from a safe one
- [x] An acceptance script with a `-TeethCheck` negative control
- [x] The tree at zero: every remaining site fixed or explained
- [x] A guard row, so a new call site makes the audit DUE automatically

## What was built

`test\win32\lib\ArgvHazardAudit.ps1`. It walks the AST for calls that are
BOTH a native ghoztty invocation (`& $exe ...`, a bare `ghoztty.exe`,
`Start-Process -ArgumentList`, a `cmd /c` line - never a `& .\x.ps1`, which
binds in-process and composes no command line) AND carry a free-text argument
(`--title=`, `--command=`, `--split-command=`, `--working-directory=`,
`--keys=`, `--env=`, or the positional of `+set-banner` / `+send-keys`).

The rule it applies turned out to be sharper than the one the card proposed.
"Is this interpolated" is the wrong question: what corrupts a command line is
a `"` in the value, or a `\` at its end. So each argument is judged on two
FACTS - `NoQuote` and `TailSafe` - computed bottom-up through literals,
expandable strings, `+` concatenation, `Join-Path`, and the file's own
variables. Three consequences:

- A hard-coded payload is judged too. Four of the ten defects found below are
  literal strings with an embedded `"`; the proposed "flag interpolation" rule
  would have passed every one of them.
- A literal that was given a NAME is still readable, so a test that hoists its
  banner text to `$banner` is not reported.
- A `Join-Path $env:TEMP 'leaf'` is safe with no marker: a Windows path cannot
  contain a `"`, and a literal leaf settles the tail. A BARE `$env:TEMP` is
  not - a drive root ends in the backslash that makes the closing quote read
  as escaped.

A parameter is never foldable INSIDE the function that declares it (it is
exactly what a caller composed) and never bans the same name elsewhere in the
file, which is what keeps one helper's `$banner` parameter from making every
other literal `$banner` unreadable.

Exemption: `# argv-audit: <reason>` on the call's own line or the one above
it. LINE-scoped, not file-scoped, because the hazard is per call site and a
file-wide marker would suppress every site written after it - the snapshot
problem this audit exists to end.

## What it found

Ten live sites, all of the same shape: a `powershell -Command "..."` payload
handed to `+send-keys`/`+split` with its quotes intact in the source and
STRIPPED on the way to the child. Measured with an argv oracle
(`arg[0]=<...>` per element), not inferred:

| site | what arrived |
|---|---|
| `clipboard-retry.ps1` (OSC 52 copy) | both `"` gone |
| `notification-click-focus.ps1`, `notification-click-real.ps1` (OSC 777) | both `"` gone, and a `$Body` with a space SPLIT into two arguments |
| `kb-actions.ps1` x4 (alt-screen / win32-input toggles) | both `"` gone |
| `pane-banner.ps1` x2 (OSC 7778) | both `"` gone - the site had already been worked around by building spaces with `[char]32` |
| `soak.ps1` (altscr split) | the quotes protecting a possibly-spaced path gone |

Each was kept working only by the accident that nothing after the first quote
held a space. All ten now go through `Invoke-NativeExact`. Twenty further
sites are provably safe (a pid-derived marker, a TEMP path, base64, a literal
given a name) and carry a marker saying which.

## Summary

T279 established the rule (build the command line yourself; see
`scripts\lib\NativeArgv.ps1` and the CLAUDE.md block) and converted the sites
it enumerated by hand: the loop's relaunch in `upgrade-ghoztty-windows.ps1`
and `watchdog-ghoztty-windows.ps1`, and the `Ghoz` / `Invoke-Ghoztty` helpers
in `go-loop-exec.ps1` and `go-loop-watchdog.ps1`. A hand enumeration is a
snapshot; the four sibling audits in this suite (`ExitCodeAudit`, `SkipAudit`,
`VerdictExitAudit`, `AssertedNothingAudit`, `ForegroundAudit`) exist because a
snapshot is exactly what stops holding.

The hard part is not finding native ghoztty invocations — it is telling a
HAZARDOUS argument from a safe one without producing a wall of noise. Most
interpolations here are pane ids, GUIDs, `$PID`-derived names and repo paths,
none of which can carry a `"` or end in `\`. Shape of a workable rule, to be
settled by the task:

- flag a `& $exe`/`Start-Process`/`cmd /c` ghoztty call whose argument
  interpolates a variable AND whose flag is one of the free-text carriers
  (`--title=`, `--command=`, `--working-directory=`, a `+set-banner` /
  `+send-keys` positional), rather than every interpolation;
- exempt via the stated-intent marker convention the other audits use
  (`# argv-audit: <reason>`), for a site whose text is provably an id;
- `-TeethCheck` plants a real violator in the swept directory, as
  `verdict-exit-audit.ps1` and `foreground-audit.ps1` do.

The AST is the right reader (see `VerdictExitAudit.ps1`'s reasoning): the
question "is this string interpolated" is structural, and a line-oriented
matcher cannot tell `"--title=$label"` from a comment mentioning `--title=`.
