# T3158 - Agent mirror of T3016: the agent's Mux.pumpInput re-encodes every inbound frame into an unbounded lane fifo and its Server parses it again on a second reader thread (agent/mux.zig:123-146)

## Summary

Follow-up from T3016 (P1 perf audit); agent inbound is the low-volume direction, so P2. T3016 fixed the app side (ClientMux.createConnection hands data-lane frames straight to Connection.deliverDataFrame; no data fifo, no data reader thread; Reader frees buffers past 256 KiB and sizes cobs/base64 scratch to the block). The agent's src/remote/agent/mux.zig pumpInput still parses, re-encodes into a fifo and the Server's data reader parses again; its Fifo never shrinks after a burst (PA-I19 agent half, agent/mux.zig:165-188). Input from the app is small, so the cost is mostly the extra thread per connection and the fifo's retained size. Fix the same way: deliver data-lane frames from the pump into the server's data handler, keep the close/unbind ordering safe, shrink drained buffers. Wire unchanged.
