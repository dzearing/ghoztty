# T3208 - User-made blades do not survive an upgrade relaunch: panes collapsed by a gutter drag or from the pane sidebar came back expanded after the 2026-11-16 upgrade, and no test ever makes a collapse the way a user does

## Summary

User report 2026-11-17: after upgrading to 1.55.3 (MSI install, 2026-11-16 19:25), every pane that had been collapsed into a blade, both ones folded from the pane sidebar and ones pushed to the side by dragging a gutter, came back expanded. The installed build contains T3126 (eaf1693b8) and T3177 (2ebcf125c). Gap: test\win32\session-blades.ps1 never makes a collapse - it WRITES pane_stack into the manifest between a kill and a relaunch - so nothing proves the app SAVES a collapse made by (a) a stack-grip/gutter drag or (b) the pane sidebar's minimize, nor that the upgrade path (installer stop -> new build -> restore, with session persistence on, so via agent re-attach) restores it. The user's live manifest (%LOCALAPPDATA%\ghoztty\session-layout.json) now has pane_stack rows:[] in all 3 windows, consistent with nothing currently collapsed, so it cannot tell 'never saved' from 'saved then dropped'. Do: (1) with real input (or the app's own collapse entry points called the way the gesture and the sidebar call them), collapse via each path and assert the manifest gains the row within the save debounce; (2) run the actual upgrade sequence (scripts upgrade/MSI or the same stop + relaunch) with persistence on and assert the blades come back; (3) fix whatever drops it. Mac reference: dd77885aa, a7fe3e9f8.
