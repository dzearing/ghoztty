# T1570 - The accent-registry set/restore helpers are copied per script, and a drifted copy can leave the user's accent on a test colour

## Summary

chrome-theme.ps1 and viewer-toc-emphasis.ps1 each carry their own Get-AccentRaw / ConvertTo-AccentDword / Set-Accent / Restore-Accent, comments and PS5.1 Int32 trap included, because both need to pin the accent to a known colour to measure anything about it. The duplication is not the interesting part - the RESTORE is. A copy that drifts, or a script whose finally does not run, leaves the user's desktop accent set to a test colour, and nothing about that shows up as a red test: the run goes green and the user's Windows changes colour. Move the four functions into test\win32\lib\ (ColorMath.ps1 is the natural home - it already owns the accent-adjacent derivations) so there is one implementation, and consider having the helper register the restore rather than trusting each caller's finally.
