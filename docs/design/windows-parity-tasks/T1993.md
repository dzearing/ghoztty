# T1993 - In lane B, acceptance scripts run outside the parallel pool still test lane A's build: 283 scripts default -Repo/-Exe to the literal D:\git\ghoztty, and the runner re-roots them only for pooled workers

## Summary

Found in T1983. scripts\lib\AcceptanceParallel.ps1 injects re-rooted -Repo/-Exe only for the 'parallel' class in the pool phase; main/exclusive/confirm runs start the script with no injection, so its param default (D:\git\ghoztty\zig-out\bin\ghoztty.exe) launches and grades LANE A's exe from D:\git\ghoztty-b. RepoLiteral also defaults to the runner's own repo, so in lane B the literal is not even recognised. Fix: always pass the injected parameters re-rooted at the running repo (every phase), take RepoLiteral from a fixed canonical spelling, and add an audit that a worktree run never resolves a path outside its own repo (with a negative control). T1986 (lane B bring-up) depends on this.
