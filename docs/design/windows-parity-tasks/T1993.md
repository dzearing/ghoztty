# T1993 - In lane B, acceptance scripts run outside the parallel pool still test lane A's build: 283 scripts default -Repo/-Exe to the literal D:\git\ghoztty, and the runner re-roots them only for pooled workers

## Summary

Found in T1983. scripts\lib\AcceptanceParallel.ps1 injects re-rooted -Repo/-Exe only for the 'parallel' class in the pool phase; main/exclusive/confirm runs start the script with no injection, so its param default (D:\git\ghoztty\zig-out\bin\ghoztty.exe) launches and grades LANE A's exe from D:\git\ghoztty-b. RepoLiteral also defaults to the runner's own repo, so in lane B the literal is not even recognised. Fix: always pass the injected parameters re-rooted at the running repo (every phase), take RepoLiteral from a fixed canonical spelling, and add an audit that a worktree run never resolves a path outside its own repo (with a negative control). T1986 (lane B bring-up) depends on this.

## In plain terms

A second copy of the work loop is about to run beside the first, each with its
own copy of the code. When the second copy tested its changes, most of its
tests quietly launched and graded the FIRST copy's program instead - so a
broken change could pass. Now every test the runner starts checks the copy it
was started from, and a test that cannot be pointed at the right copy is
refused loudly instead of being run against the wrong one.

## Goals

- [x] The runner passes the right program path to every test, in every phase (not only the side-by-side workers)
- [x] The runner recognises the scripts' spelling of the repo even when it runs from another folder
- [x] A test whose own text names the first copy's folder is refused in any other copy, never silently run
- [x] The tests that did name that folder in their own text no longer do
- [x] Proof that the check fails when the fix is taken away
