# T731 - Report skipped sections in the summary line of overlay-zorder, split-divider and pane-banner

## In plain terms

Three of our on-box test scripts can skip a section - a pixel probe that got an
empty capture, a hover the harness lost the race for - and still finish with a
plain "ALL PASS". Twenty-one other scripts now say how many sections they
skipped; these three are the last that do not, so a run of them can still look
greener than it was.

## Summary

T219 made the skip count ride the verdict line and put an analyzer
(`test\win32\lib\SkipAudit.ps1`) behind it. These three were left on the
shrink-only `$SkipAuditPending` list because of their site counts, not because
anything about them is different:

| script | uncounted skip sites |
|---|---|
| `overlay-zorder.ps1` | 14 |
| `split-divider.ps1` | 11 |
| `pane-banner.ps1` | 6 |

Almost all of them are pixel-probe skips - "empty capture", "no debug oracle in
the log (release build?)", "the hovered frame was never painted" - which is
exactly the family T219 exists for: they fire on a busy box, and the run says
nothing.

## Details

The conversion is mechanical and documented in `lib\SkipAudit.ps1` (canonical
shape) and CLAUDE.md:

- each site gains `$script:skipped++`;
- the verdict line interpolates
  `$(if ($script:skipped) { ", $script:skipped SKIPPED" })`;
- the script's entry is removed from `$SkipAuditPending` in
  `test\win32\lib\SkipAudit.ps1`. Leaving it there once converted FAILS
  `skip-visibility.ps1` (B2), which is what keeps the list shrinking.

Worth doing while in there: several of these sites are grouped (three `SKIP H:`
branches in one section), and counting each separately is right - the number is
sections not run, not distinct reasons.
