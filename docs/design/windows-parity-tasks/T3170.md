# T3170 - A new Mac release should file its own Windows publish request, so release-parity stops going red twice a day (T3140, T3162)

## Summary

Fork CI's release-parity job goes red whenever the Mac seat publishes `vX.Y.Z` before a matching `win-vX.Y.Z` exists. It happened twice on 2026-11-15/16 (v1.55.0 -> T3140, v1.55.1 -> T3162), and each time every validate on both lanes read CI RED until a turn noticed, filed a task and ran `daily-publish.ps1 -Request` by hand. Lane b committed T3135 under `-NoCiCheck` meanwhile.

Fix: `daily-publish.ps1` (step 6.5, lane a) should notice a Mac release newer than the newest win- release's base and file an ordinary request itself, reason `mac release vX.Y.Z has no win-vX.Y.Z`, honoured like the T1588 stranded-threshold request. The day's 3-attempt cap still applies. Lane a only (publishing).

## Validation criteria

- [ ] With a newer Mac release planted (fake gh release list), the step 6.5 run writes a request with the mac-release reason and publishes; a new section of `test/win32/daily-publish.ps1` holds it.
- [ ] With the Mac and Windows lines level, no request is written (negative control).
