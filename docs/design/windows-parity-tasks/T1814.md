# T1814 - Prove no automated run takes the foreground from a fullscreen app, then resume the soak daemon

## Summary

Carried from T1795 validation criteria 2 and 5, which need the user AWAY from the box (go.md: never pull focus; the stand-in fullscreen window would itself sit on the user's desktop). With a fullscreen stand-in window in front, run one full soak round and each declared input-desktop exception script, and assert by script that the foreground hwnd never changes; include a negative control that forces the gate off (GHOZTTY_TEST_FORCE_USER_PRESENCE=absent) and shows the steal happens. Only after that passes: soak-daemon.ps1 resume (the daemon now yields to a present user, T1795). Run only when Get-UserPresence says absent.

## In plain terms

A month ago some of our automatic test runs popped windows over the user's
fullscreen game. The fix taught every such run to notice that someone is using
the machine and stay out of the way, but nobody had watched it actually work
with a real fullscreen window in front. This puts a fullscreen window up,
runs everything that used to misbehave, and checks that the window in front
never changes. Once that holds, the background crash-hunting runs can be
switched back on.

## Goals

- [x] a repeatable check that puts a real fullscreen window in front and watches who holds the screen
- [x] every test that must use the real screen stays out of the way under it
- [ ] one full background crash-hunt round runs under it without taking the screen (moved to T2481: three rounds ran 84-135s each with no screen change, then gave way to the other lane's builds)
- [x] a control run with the check switched off shows the screen being taken, so a quiet result means something
- [x] the background crash-hunting runs switched back on
