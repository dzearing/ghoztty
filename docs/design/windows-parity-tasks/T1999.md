# T1999 - Remote panes correct their resume offset in +16/-16 pairs 9ms apart: the counted and stream positions drift and snap back on a busy pane

## Summary

Found while measuring T1956: ghoztty.log carried 313 pairs of 'resume offset corrected: counted=X stream=X-16 (delta 16)' followed ~9ms later by '(delta -16)'. adoptStreamPos's comment calls a correction rare and names only repaint/scrollback-lost injection as the cause; a symmetric 16-byte pair on a live pane says the stream-position anchor and the parsed-byte count are briefly out of step (a 16-byte frame counted before its anchor arrives, or vice versa). Find which 16 bytes, decide whether a resume taken inside the window would replay or drop them, and fix the ordering. T1956 now logs only the 1st/2nd/4th/8th... correction per pane at info with n=, so the evidence is still there.
