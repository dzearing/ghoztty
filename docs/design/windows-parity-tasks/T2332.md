# T2332 - Measure the pane sidebar's scroll-step paint cost and the 40-window all-windows list on Windows (Mac 321e61d7c's other two numbers; T1925 measured the busy sheen only)

## Summary

P2: follow-up to T1925 - the busy-sheen frame cost is fixed and measured (pane-sidebar-motion-cost.ps1); a wheel step still repaints the whole column, and the 40-window / dozen-busy-panes all-windows scenario Mac measured is unmeasured here. Measure both; fix if a scroll step costs Mac's old 31-50 ms.

## In plain terms

On the Mac, a sidebar listing forty windows with a dozen busy panes used to
stutter when scrolled and kept a CPU core busy doing nothing. This measures
the same scene on Windows. The answer: it scrolls in well under one frame and
sits idle at rest, so nothing needed fixing. What lands is the measurement
itself, re-run whenever the sidebar code changes.

## Goals

- [x] Time a wheel step's paint in Mac's scenario (40 windows, 2 panes each, every window unfolded, 12 busy)
- [x] Measure the app's CPU at rest in that scene
- [x] Fix if a step costs Mac's old 31-50 ms (not needed: 3.7-4.0 ms median, 7.7 ms worst, Debug)

## Findings

- A wheel step invalidates the whole column (`scrollTo`), so its cost is one
  full-column paint. Since this task the first paint after a step logs
  `pane sidebar scroll paint us=N full=.. mode=.. items=.. offset=..`.
- 40 windows x 2 panes, all-windows scope, search `proj` unfolding all 80
  rows (max scroll 5801 px at 125%), 12 panes busy, **Debug** build: 20 steps,
  median 3.68 / 3.95 ms, max 7.75 / 7.71 ms over two runs. Mac: 31-50 ms
  before 321e61d7c, ~8 ms after (release). Windows Debug already matches Mac's
  fixed release number.
- At rest with the dozen busy panes: 0% / 0.4% of one core, whole process,
  80 panes (Mac before: 86-99%; after: under 1%). Two earlier fixes are why:
  the sheen is the compositor's (T2801) and moves only in the window in use
  (T2909).
- Mac's third fix (drop-target frames reported on every scroll frame) has no
  Windows analog: `dropGeometry` is pulled only by a live drag, never pushed.
