# T3761 - Fifty cascaded windows of busy panes burn about 11 CPU cores: panes in windows nobody is using still draw every output chunk at full rate

## Summary

T3740 measured it (test\win32\window-count-scale.ps1 -Busy): with every window cascaded so each shows a strip, every busy pane renders at ~50 fps even though it prints only ~12 lines a second (ConPTY delivers output in small chunks and every chunk wakes a frame), and each costs ~17% of a core in its renderer thread plus ~20% in a GPU-driver thread. 50 windows = ~11 cores (release 1128%, debug 1080%); open-next-window goes 69 -> 266 ms. Covered windows already draw nothing (stacked: 54% of a core at 50). Fix: (1) a pane in a window that is not the one in use draws at a capped rate (e.g. <= 20-30 fps), and a mostly-covered window (visible client area a small sliver) lower still - the Mac rule is that work that only matters to the eye runs where someone can see it (docs/reference/background-windows.md); (2) coalesce output-driven frames to the display period instead of one frame per wakeup. Acceptance: window-count-scale.ps1 -Busy cascaded at 50 windows <= 2 cores, and the focused window still at full rate; promote the -Busy cascade case into the verdict.

## In plain terms

With dozens of windows open and a busy program (a Claude Code spinner) in
each, every window kept redrawing as fast as it could, even the ones you were
not using and could barely see. Fifty of them used about eleven processor
cores and made opening the next window slow. Now only the window you are
using redraws at full speed; the others redraw at most 20 times a second, and
the ones that only show a thin strip at most 4 times a second. What they show
is still current, just less often.

## Goals

- [x] a pane outside the window in use draws output at a capped rate (20 fps; 4 fps when under a quarter of its window shows)
- [x] the window in use is not capped, and becomes full-rate the moment it is activated
- [x] output's own cursor-blink reset no longer forces extra frames past the cap
- [x] window-count-scale.ps1 measures it in the verdict (section D) with a negative control
- [x] the Mac and Linux halves filed (T3780, T3781)
