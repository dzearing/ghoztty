# T3327 - A single acceptance harness run by hand does not wait for a test run already in flight in the same worktree (T1658 covers only acceptance-parallel and floor-lane)

## Summary

T1658 made acceptance-parallel.ps1 and floor-lane.ps1 wait on a per-worktree test-run lock, so a batch a previous turn left running behind a reset is no longer overlapped by either runner. A harness started directly (powershell -File test/win32/<x>.ps1) is still not covered: TestScore.ps1 makes it the OWNER of its own run (so the runners it launches are nested and never deadlock), but it never checks whether another run already holds the lock. Fix shape: in TestScore.ps1, when the harness is NOT nested (no live GHOZTTY_TESTRUN_OWNER), take the testrun lock itself via Enter-MachineLock -Kind testrun before claiming ownership, and report ASSERTED NOTHING (exit 2) on a timeout, the same way the timing lock does in CleanSlate. Watch the cost: 397 harnesses dot-source TestScore, some only for the scorer, and a harness that dot-sources it from a fixture repo must key on the repo it grades.

## Validation criteria

- [ ] a directly-run harness, with the lock held by a non-ancestor, prints TEST RUN LOCK WAIT and then ASSERTED NOTHING without running its body (new arm in machine-lock.ps1 section I)
- [ ] the same harness inside an acceptance-parallel worker is nested and runs at once
- [ ] acceptance-parallel due sweep green
