# T1764 - closeNeedsConfirm / ProcessTree comments still say cmd's cursor reads 'at the prompt' through a running command; T1757's 133;I makes that false for cmd - re-state which shells the process table is still needed for

## Summary

Comment accuracy only. `closeNeedsConfirm` in `src/apprt/win32/Surface.zig` and `ProcessTree.hasDescendants` explain the process-table override by saying cmd gets 133;B and never 133;C, so its cursor reads "at the prompt" through a running command. Since T1757 (6269cb9af) cmd's prompt ends in 133;I, so that is no longer true for cmd. The override itself is still right - stock PowerShell with no integration, remote shells, and a shell whose PROMPT the user replaced all still need it - so the fix is to rewrite the comments to name those cases. No behavior change.

- [ ] The comments in Surface.zig closeNeedsConfirm and ProcessTree.hasDescendants name the shells the process table is still needed for, and no longer claim cmd reads at-the-prompt mid-command.
