# T3780 - Mac: panes in a visible window that is not the one in use still draw every chunk of output at full rate; send the renderer's new pace (T3761)

## Summary

T3761 gave the shared renderer a pace message (renderer/pace.zig, Surface.paceCallback): a pane outside the window in use presents output-driven frames at most 20 fps, and 4 fps when under a quarter of its window shows; the window in use is uncapped. Windows sends it from the visibility poll. Mac renders visible background windows at full rate (docs/reference/background-windows.md: terminal frames gate only on 'can be seen'), so fifty cascaded busy windows cost the same there as they did here before T3761. Send ghostty_surface pace from WindowInUse (animates -> full; isOnScreen and WindowCoverage's uncovered share -> background/glimpse) through a new C API call, and measure it the T3740 way. T3761 also stopped the output-driven cursor-blink reset from forcing a frame past the cap; that part is shared and already on Mac.
