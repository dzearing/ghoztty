# T1774 - Check the Mac feedback composer keeps its undo history across a close and reopen, as Windows now does (T1006)

## Summary

T1006 made the Windows feedback composer keep its undo history across a close and reopen: quote a passage, type, close the pill, reopen, and Ctrl+Z takes the typing off as one step and then the quote. The Windows side assumed the Mac already behaves this way, because its composer is an NSTextView (`ViewerFeedbackBar.swift`, `allowsUndo = true`) whose undo is not scoped to the pill. That was NOT verified: the text view is built in an `NSViewRepresentable`'s `makeNSView`, so SwiftUI may rebuild it when the bar hides, and the window's undo manager may then hold actions against a text storage that no longer exists (a crash or a no-op on Cmd+Z). Check it on a Mac build: quote, type, close, reopen, Cmd+Z twice, Cmd+Shift+Z. If the history is lost, or undo misbehaves, carry the history on the model the way Windows now carries it on the bar; if sending a report does not clear the undo history, make it (an undo must never bring a filed report back).
