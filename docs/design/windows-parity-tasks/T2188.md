# T2188 - acceptance-parallel's durable-state check reads the user's own in-app update as a test leak and turns a green run red

## Summary

2026-10-23 06:35: checkout-guard, test-reach-audit and harness-floor all passed, yet the run ended ACCEPTANCE RED with state-changes=4: arp ADDED Ghoztty 1.43.5 and install CHANGED ghoztty.exe/.com/agent under %LOCALAPPDATA%\Programs\Ghoztty. That was the user's in-app updater taking win-v1.43.5 during the run (the user's screenshot shows 'Update installed'), not any script. T1230's snapshot diff cannot tell a published release landing through the updater from a test writing outside its sandbox. Attribute it: when the install/ARP delta is a version that exists as a published win-v release and the installer/updater ran (MSI log, updater state file, or the ARP DisplayVersion matching a gh release), report it as 'user update, not a test' and do not fail the run.
