# T3614 - Linux: a sized popup viewer window's page is 64px narrower than it asked for (viewer-links K24d red since the pane sidebar)

## Summary

test/linux/viewer-links.sh K24d fails deterministically: window.open(url, '', 'width=500,height=400') logs 'ready to show at 500x400 (asked 500x400)' but the popup's page measures innerWidth 436 (band 440-500). Reproduced at a3a5bb716 (before T3561) and at f91cc851d, on an idle and a loaded box. K24d was last green at 41d28bf7e (T3447); the pane sidebar (T3557/T3558) landed after it, and 64px is the width of its rail, so the likely cause is the rail being shown in a one-pane popup viewer window and taking the page's width. Decide from the Mac reference whether a popup viewer window has a sidebar at all (pane-sidebar.md); either drop it there or size the window so the CONTENT gets the asked width, as the Mac's window-features do.

## In plain terms

When a web page in a viewer opens a small sign-in style popup and asks for a
size (say 500 by 400), the Linux build made the whole window that size, so the
sidebar and the frame round the page ate into it and the page came out about
84 pixels too narrow and 160 too short. Now the window grows by what the chrome
takes, so the page itself gets the size it asked for, as on the Mac and Windows.

## Goals

- [x] A sized popup's page is the size the opener asked for, whatever the sidebar mode or pane style.
- [x] A popup that asked for no size still opens at the default.
- [x] The fit happens once and never shrinks a window, so a compositor that refuses the size cannot make it loop.

## Decision

The Mac reference does not drop the sidebar from a popup window (only the quick
terminal and hero mode hide it), so the popup keeps its sidebar and the window
is sized for the CONTENT instead. Measured, not summed: once the page has laid
out, a one-shot frame callback (`PopupFit` in `class/application.zig`) grows
the window by the page's shortfall (`viewer_links.popupFit`), so any chrome
added later (a strip, a style inset) is covered without the fit knowing of it.
win32 does the same by adding its frame with `AdjustWindowRectEx`.
