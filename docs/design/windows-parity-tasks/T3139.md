# T3139 - Previous/Next pane has no chord the Windows palette and menus can show since T3132: ctrl+alt+page_up/down became previous/next window, and the remaining ctrl+win+[ / ] binding is performable, so the reverse map (what the palette displays) has nothing for goto_split previous/next

## Summary

T3132 moved ctrl+alt+page_up/page_down (T1725's mirror of Mac Cmd-Shift-Up/Down) to goto_window, following Mac 997b26535. goto_split previous/next still works on ctrl+super+[ and ] (Config.zig non-Darwin block, putFlags performable), but performable triggers are excluded from Binding.Set.reverse, so the command palette and shortcut catalog advertise no chord for Previous/Next Pane. Mac advertises Cmd-[ / Cmd-] (non-performable). Decide the advertised Windows chord (make ctrl+super+[ / ] non-performable on Windows, or add a non-performable mirror) and check the shell does not own ctrl+win+[ (it is not a documented Windows shortcut). Test: Config.zig reverse-lookup test + palette entry shows the chord.

## In plain terms

The command palette and menus list "Previous Pane" and "Next Pane" with no
keyboard shortcut beside them, even though Ctrl+Win+[ and Ctrl+Win+] do
the job. On the Mac those rows show Cmd-[ and Cmd-]. After this lands, the
Windows rows show Win+Ctrl+[ and Win+Ctrl+], so you can learn the shortcut
from the place you would look for it.

## Goals

- [x] Ctrl+Win+[ / ] are the advertised previous/next pane chords on Windows
- [x] a unit test proves the palette/menu label reads them, and goes red without the fix

## Decision

Made ctrl+super+[ / ] non-performable on Windows only (Linux keeps
upstream's performable flag), rather than adding a second, non-performable
mirror chord. It is the Mac shape exactly: Cmd-[ / Cmd-] are
non-performable there. The one behavioural cost - with no split, the chord
is swallowed instead of reaching the program - is moot on Windows: the
Win key is not encoded into what a console program receives, and the shell
binds no Win+Ctrl+[ / ] shortcut. Every win32 surface that labels a
command (palette hint `Surface.zig` `accelTrigger`, context menu, menu bar
via `Window.zig`) reads `menu_label.accelTrigger`, so one change covers
them all.
