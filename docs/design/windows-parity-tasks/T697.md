# T697 - The persistence sweep's six-line marker window silently misses a declaration written on a function header

## Summary

T158's sweep accepts a '# persistence: <reason>' marker on the launch statement or in the SIX lines above it. agent-instance-lineage.ps1 (T167) wrote a correct, well-argued marker on the Run-Cli function header - seven lines above the Start-Process inside it - and the sweep reported the site as undeclared, i.e. as work nobody had thought about. The declaration was there; the window was one line short. Fixed in place for T663 by repeating the marker next to the statement, which is a workaround, not the rule. Options worth weighing: let a marker on the ENCLOSING function's header (or its comment block) declare every launch in that function - which is what a reader assumes it already does - or make the window a property of the comment block rather than a fixed line count. Either way the sweep should be able to say 'declared, on the function header' rather than silently not seeing it, because a false 'undeclared' is a fix applied to a site that was already correct.

## In plain terms

The suite has a check that asks every test script "do you want the previous
run's windows back, yes or no?" - a question a script has to answer or it ends
up testing someone else's leftovers. A script can answer it in a comment, and
one of them wrote that comment at the top of the helper it was explaining. The
check only looked at the six lines directly above the launch, so it read a
carefully written answer as no answer at all and reported the script as one
nobody had thought about. Now the answer counts wherever a person would
naturally write it - anywhere in the comment block, or on the function the
launch sits in - and the check says which of those it read.

## Goals

- [x] a marker on the enclosing function's header (or its comment block)
      declares every launch inside that function
- [x] the marker window is the comment BLOCK above the statement, not a fixed
      six lines
- [x] the sweep reports WHERE it read the declaration (`marker:fn:<name>`)
      instead of silently not seeing it
- [x] the same rule applies to the `# stderr:` marker, which shares the scan
- [x] the workaround this forced into `agent-instance-lineage.ps1` is removed,
      and the header marker alone still declares the site
- [x] the rule is written down in `docs/claude/testing.md`
