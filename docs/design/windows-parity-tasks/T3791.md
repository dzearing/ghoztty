# T3791 - Linux window header-bar title is too bold: use semibold (600)

## Summary

User report 2026-11-25, looking at the Linux build on the real WSLg screen: "the header font is too bold, try semibold?" The window's header-bar title (libadwaita's `.title` in the AdwHeaderBar - "Ghostty" / "~" in the 2026-11-25 screenshots, see T3783) renders at Adwaita's default bold (700). Set it to semibold (600). Same pass: any other header-bar / tab / pane-header label we style bold where the Mac uses a medium or semibold title weight - compare against the Mac's titlebar and tab title weights (docs/reference/ for the Mac's values) and list each one changed. The debug-build banner is out of scope (debug only).

Fix in the runtime CSS (src/apprt/gtk, the same place the theme CSS is built), not by a per-widget Pango override, so every window and the Settings window pick it up. Mind the existing `style.css:140` hsl() parse warning seen in the same log - fix it if it is ours.

User directive on the same report: the Linux build "really needs to be as high quality as the mac version" - see T3793 for the side-by-side pass.

## Validation criteria

- [ ] The header-bar title renders at weight 600: the GTK seat asserts the computed font weight of the title label (headless harness, via a debug seam or the style context), and fails on today's 700 (positive control).
- [ ] On-screen check on WSLg (person's command, `scripts\linux\open.ps1`): screenshot of the header bar recorded in this file next to the Mac's titlebar at the same size; weights match by eye and by stem width.
- [ ] Every other bold label in the chrome reviewed against the Mac; the list (changed / kept, with why) recorded here.
