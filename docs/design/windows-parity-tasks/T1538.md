# T1538 - A pane can be moved into another window without restarting its shell

## Summary

Split out of T1532. This is the cross-window relocation PRIMITIVE plus the drop
that uses it: dragging a pane over another Ghoztty window's panes lands it
there, and the pane that arrives is the pane that left — same process, same
scrollback, same agent session.

Nothing under `src/apprt/win32/` calls `SetParent` today, so the primitive is
new: re-parent the pane's child HWND to the destination window, transplant the
leaf between two `SplitTree(PaneView)` values owned by different `Window`s, and
hold a reference across the move so the source tree's `deinit` cannot unref the
pane to zero.

Session safety is the sharp edge. `closeSplitPane` marks the removed pane with
`setSessionCloseIntent(true)` so its agent session ENDS; a relocation must take
the same removal path with that intent left alone, or a rearrange silently kills
the session. Mac's counterpart is `PaneMoveCoordinator.finishRelocation`.

Inherited from T1530: the pane header's POP-OUT button is drawn, measured and
hit-tested, and ships disabled behind `Window.pane_pop_out_supported`. Flipping
that constant and filling the empty `.button` arm in `Window.wndProc`'s
`WM_LBUTTONDOWN` belongs to this task — a live button must land with the
session-safety rule under it, never before it.

## In plain terms

Today a pane lives in the window it was born in. If you want the same shell in a
different window you have to close it and start it again, losing whatever was on
screen. After this you can drag a pane out of one window and drop it into
another, and it keeps running — same command, same history.

## Goals

- [x] Other visible Ghoztty windows are candidates for the drag resolver, in
      z-order, so a point over another window resolves against its panes.
- [x] A relocation moves the pane's HWND and its leaf to the destination window
      without the pane being unreffed or its session closed.
- [x] The source window collapses correctly when the pane leaves (and closes if
      that was its last pane).
- [x] The pop-out header button is enabled and moves the pane to a new window.
- [x] An acceptance script proves pane HWND identity and session survival across
      the move.

## Validation criteria

- [ ] A pane dragged onto another window's pane lands there, and the child HWND
      under the destination window is the SAME handle that was under the source
      a moment before - so the process, the scrollback and the agent session
      came with it rather than being rebuilt.
- [ ] The drop is PREVIEWED over the destination window before the button comes
      up - the preview has to outrank a window its owner does not own, or the
      promise is drawn where nobody can see it.
- [ ] The window the pane left keeps its remaining panes, and they grow into
      the space.
- [ ] A window whose LAST pane is dragged away CLOSES, and the pane (and its
      session) survives the close.
- [ ] The pop-out button on a pane header opens a new window holding that pane,
      again the same handle; a window's last pane cannot pop out.
- [ ] One window owns an overlapped point: a drop over the front window's panes
      never lands in a window behind it, and a release on a window's own chrome
      is a miss rather than a new window.
- [ ] The floor stays green (`floor-lane.ps1 -Lane all`, P1-P3).
