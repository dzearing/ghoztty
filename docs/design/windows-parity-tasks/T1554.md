# T1554 - No on-box oracle proves a sign-out DETACHED the far session instead of ending it

## Summary

T713 makes relay sign-out close the account's windows with T1390's DetachPin, so the sessions keep running on the far machine. relay-account.ps1 section 7b cannot measure that: the agent's shells sit behind a PTY holder that escapes the process tree (a descendant count is always 0) and the agent's --relay mode takes no --sessions-file, so there is no roster on disk to read. The claim currently rides on remote-disconnect.ps1 proving the same pin spares a far session in the direct-TCP case. Give section 7b a real oracle - either teach --relay mode to accept --sessions-file, or add a wire probe that lists the far agent's sessions.

## In plain terms

Signing out of your relay account closes the windows that were showing another
machine's terminals, and the promise is that the work on that other machine
keeps running. Until now no test on this box actually checked that promise; it
only checked that the windows closed. Now the test asks the other machine
directly, before and after the sign-out, how many terminals it is still running.

## Goals

- [x] The machine chooser's roster line reports how many listed sessions are actually running (`live=`), not just how many are listed
- [x] relay-account.ps1 section 7b reads the far machine's running sessions before and after sign-out
- [x] The same run includes a control: a window closed with `+close` must NOT count as running, so a sign-out that killed the session would be caught
