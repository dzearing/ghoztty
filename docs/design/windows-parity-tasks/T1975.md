# T1975 - The agent never says whether it is running inside a kill-on-close job, so a field log cannot show the one condition that loses every session at once

## Summary

T1970's mechanism (an agent spawned into a nested kill-on-close job dies with it) is invisible in the agent's own log: only the APP probes its job at startup. Have the agent log its job membership and immediate-job flags at startup (and report it in a health or +sessions field), so the next 'restart lost my sessions' report carries the answer instead of needing a repro.
