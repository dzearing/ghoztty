# T2617 - Composition step 3d-3: the banner collapse glide's frozen copy becomes a visual under the banner visual, so a toggle on the composition path hides the reflow again (T2252 parity)

## Summary

T2559 put the banner card in the pane's composition tree; BannerFreeze is still a popup over the pane and would cover the card, so beginGlide is skipped when the card is a visual and the terminal reflows in view on a toggle (comp-present J9). Make the copy a comp_overlay.Layer under the banner layer (same captured pixels, offset per tick), restore the glide, and put comp-present J7/J8 back to comparing the knob-on glide with knob-off.

## In plain terms

When you collapse or expand a pane's banner, the terminal underneath used to visibly jump and re-wrap while the card moved - on the newer drawing path only. Now a still picture of the terminal slides along with the card and the real terminal swaps back in once it has settled, the same smooth motion the older path and the Mac have.
