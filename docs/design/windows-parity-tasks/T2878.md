# T2878 - Record what Chrome, Edge and Firefox 'Copy image' put on the clipboard, and confirm Ctrl+V attaches that image in a real Claude Code pane

## In plain terms

T2721 taught Ctrl+V to hand a copied picture to Claude Code when the clipboard
also carries the picture's web address. That was proven with a made-up
clipboard. This task checks the real thing: copy an image in each browser,
press Ctrl+V in a Claude Code pane, and see the image attached.

## Summary

T2721's rule (`src/apprt/win32/claude_image_paste.zig`) hands ^V to Claude when
the clipboard holds an image and its text is empty or one image address
(`http(s):`, `data:image/`, `blob:`, `file:`). It was validated by
`test/win32/clipboard-paste.ps1` sections I-L with a WinForms DataObject
(Bitmap + UnicodeText) and a renamed `claude.exe` probe.

Still unmeasured:

1. Which formats Chrome, Edge and Firefox "Copy image" actually publish
   (`Get-Clipboard -Format` / an `EnumClipboardFormats` dump). If a browser's
   text is something other than an address (alt text, a page title), the rule
   pastes it and needs widening.
2. That real Claude Code, on its `chat:imagePaste` Ctrl+V, attaches the image
   from that clipboard (it reads the image itself).

Both need a real browser's context menu and a real Claude session on the
user's desktop, which the loop must not drive (go.md: never pull focus).

## Validation criteria

- [ ] The format list for each of Chrome, Edge and Firefox is recorded here.
- [ ] In a real Claude Code pane, Ctrl+V after each browser's Copy image attaches the image.
- [ ] Any browser whose text is not an address has a follow-up filed or the rule widened.
