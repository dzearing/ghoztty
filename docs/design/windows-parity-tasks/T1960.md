# T1960 - Run due acceptance harnesses about four at a time on their own test desktops, with # @timing-sensitive scripts run alone (T1955 item 5: ~16 min to ~5)

## Summary

Due acceptance harnesses run one at a time (T1874: 21 harnesses, 13:02-13:18). They already isolate pipes and agents (Isolation.ps1, GHOZTTY_PIPE_SUFFIX) and run on background desktops, but suite-run.ps1 documents why it stays serial: scripts resolve the same zig-out and CleanSlate kills the app by ExecutablePath. Find a safe shape (per-worker zig-out copy, or a CleanSlate that only kills its own suffix), run about four at a time, and run scripts marked # @timing-sensitive alone (the T1937 mutex idea).

Split out of T1955 (P0, user 2026-10-14: 'feels like the tasks are getting slower ... selectively run things?'). The measurements and the ranked plan are in T1955.md.

## In plain terms

At the end of every task the loop re-runs the acceptance tests the change
touched, one after another - about 16 minutes. Most of them could run at the
same time, but they used to trip over each other (one test's cleanup closed
another test's app). This gives each test runner its own copy of the
workspace so four can run at once, keeps the timing-measuring tests running
alone, and re-checks anything that fails while crowded.

## Goals

- [x] One command runs the due acceptance set about four at a time
      (`scripts\acceptance-parallel.ps1 due`).
- [x] No worker can reach another worker's app (per-worker mirror of the repo).
- [x] `# @timing-sensitive` scripts and box-global ones run with nothing beside them.
- [x] A red-in-the-crowd, green-alone script is caught and named, not trusted.
- [ ] Measured on the real due set: same verdicts as serial, and the wall time.

## Design (2026-10-15)

- **Worker root = mirror of the repo**, `<repo-parent>\.<repo>-par\w<n>`: a
  junction per top-level directory, a hard link per top-level file, its own
  `zig-out` of hard links to the real build (no copy, no disk). Scripts compute
  `$repo` from `$PSScriptRoot`, so from a mirror every derived path - the exe,
  the agent, the clean-slate kill prefix, CleanSlate's under-the-repo refusal -
  is that worker's. No script needed editing for this; the ~280 scripts whose
  `[string]$Exe` parameter defaults to the literal repo path get it injected,
  re-rooted. Environment per worker: own `LOCALAPPDATA`, own
  `GHOZTTY_AGENT_INSTANCE` (the agent pipe is per-user, not per-directory, so
  this is required), own `GHOZTTY_PIPE_SUFFIX`, no `GHOZTTY_IPC_SOCKET`.
- **Classification from code (comments stripped by the tokenizer):** parallel /
  main (hardcodes unscoped `local-agent-debug` / `session-layout-debug` / the
  literal repo path; runs from the real repo, one at a time, beside the
  workers, which share nothing with it) / exclusive (clipboard, HKCU,
  installer, box-wide leak counts, process-name kills, builds, nested
  harnesses, `# @timing-sensitive`, `# @parallel-unsafe`). Suite today:
  parallel 212, main 99, exclusive 87 of 398.
- **Safety net:** every non-green pool row is re-run alone (suite-run's T1137
  rule); interference can only turn runs red, so that is the direction that
  needs the second opinion.
- Ten scripts declared `# @timing-sensitive` (perf/latency/soak/cpu):
  drag-perf, ipc-startup-latency, layout-capture-cost, pane-ingest-lag,
  profile-latency, resize-debounce, resize-flicker, send-keys-soak, soak,
  chooser-session-cpu.
- Mechanism choice recorded here (not a decision: no user-visible difference):
  mirror roots over a suite-wide `GHOZTTY_TEST_EXE` refactor - zero script
  edits, and CleanSlate's existing path-exact rules become per-worker for free.

      2's own `Stop-RepoGhoztty` (loaded from worker 2's mirror) and the
      runner's worker-2 sweep; worker 2's CleanSlate refuses worker 1's exe as
      not under its repo; worker 1's own kill takes it (positive control).
- [x] A timing-sensitive script never runs beside another one. Harness
      section D, from the fixture scripts' own clocks (D2), plus the runner's
      timeline oracle (D1) and its negative control (D12: an exclusive overlap,
      two mains at once, a reused slot all go red). Real runs: the 10 marked
      scripts all ran in the exclusive phase.
