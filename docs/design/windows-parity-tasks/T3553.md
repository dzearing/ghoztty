# T3553 - Linux L9j-6: the GTK feedback composer's draft folder and footer link (files dropped in ride along with the report)

## Summary

Mac/win32 (T645) give each composer draft a stable stem and stage it under <worktree>/temp/feedback/.staging/<stem> while composing; the footer links that folder so the user can drop logs or recordings into it, and the send publishes THAT folder (report.write's draft_stem), so the dropped files ride along. T3544 mints a fresh stem at send time and its footer is plain text. Port: keep a draft stem on the pane, report.stage on open/edit, a footer link that opens the folder (xdg-open / GtkFileLauncher), report.write(..., draft_stem), and pruneStaleStaging; headless check that a file dropped into the draft folder lands inside the published report folder.

Staging point, as built: win32's shape, not "stage on open/edit". The folder is
made when the link is clicked (and by the send), so a composer opened and
closed without a word leaves nothing behind - the same choice T645 made on
Windows.

## In plain terms

On Linux, the feedback box under a viewer pane now shows, at the bottom, the
folder the report is about to be saved in, as a link. Clicking it opens that
folder in the file manager, and anything you drop in there - a log, a crash
dump, a screen recording - is sent along with the report, the same as on Mac
and Windows. Before, the bottom line only named the project.
