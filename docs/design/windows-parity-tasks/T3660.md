# T3660 - In a WSL pane, a dropped or pasted file arrives as a C:\ path that bash cannot open

## Summary

T3581 made a paste of a copied file type its path, using the drag-and-drop rule (path_paste.zig: space-joined, double-quoted on whitespace). In a WSL pane (wsl flavor) the shell is bash and a C:\Users\... path is not a usable argument; it wants /mnt/c/Users/... (wslpath -u). Mac has no counterpart, so this is a Windows-native improvement, not parity: when the pane's shell flavor is wsl, translate each path to its /mnt/<drive>/ form (pure rule in path_paste.zig, drive letter lowercased, backslashes to slashes, single-quote any path with a shell-special character) for both drop and paste. Validation: unit tests for the translation, and a clipboard-paste.ps1 row in a wsl-flavored pane only if WSL is already running (never start WSL for it).
