# T2368 - drag-perf.ps1 measures the pane sidebar edge drag on a 4-pane window too (sidebar drag ticks= line, frame-budget verdict), beside the divider drag

## Summary

T2359 put the sidebar edge drag on the live layout path and made it print 'sidebar drag ticks=... mean_us=... verdict=' on release, measured only on pane-sidebar-resize.ps1's 2-pane window (6 ticks, mean 9.4ms, max 11.9ms). drag-perf.ps1 owns the per-tick budget verdict for divider drags on N panes; give it a sidebar-drag section on a 4-pane window so a regression in the sidebar path's tick cost is caught the way a divider's is. There is no 'before' number to compare against: the plain path recorded no cost at all.

## In plain terms

Dragging the edge of the pane list on the left resizes every terminal in the
window. A slowdown in that drag would only have been noticed by someone
feeling it, because the speed test that guards divider drags never touched
it. When this lands the same test also drags the list's edge on a window with
four terminals and fails if it gets slow.

## Goals

- [x] drag-perf.ps1 drags the expanded sidebar's edge on a 4-pane window and prints its cost line
- [x] it fails when the drag stops resizing every pane, waits more than once per move, or goes over the two-frame budget
