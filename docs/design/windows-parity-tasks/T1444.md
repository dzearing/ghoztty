# T1444 - the Windows publish never authors release notes, so What's New will go stale

## Summary

T624 put the bundled release notes and the "What's New in Ghoztty" window on
Windows. The notes themselves come from `release-notes/{client,agent}/
<version>.json`, and on the Mac side those files are authored by hand as step 2
of `.claude/commands/release.md`, before the tag is pushed.

The Windows publish has no such step. `scripts/daily-publish.ps1` decides a
version, tags HEAD and lets `release-windows.yml` build it — nothing anywhere
writes a `<version>.json` for the version it just minted. So every Windows
release ships the notes that happened to exist when the Mac line last moved,
and the window a user opens after updating tells them about work from weeks
ago rather than about the update they just took.

## In plain terms

After you update Ghoztty on Windows, "What's New" opens and describes older
releases rather than the one you just installed. The window works; nobody is
writing the notes it reads.

## Goals

- [x] The daily publish authors notes for the version it is about to tag
      (`publish-windows-tag.ps1` runs `release-notes-author.ps1`, commits the
      file through the commit guard, and tags the pushed notes commit); a
      failed author/commit tags anyway and says so — late notes beat no release.
- [x] The notes draw on the commits since the previous `win-v` tag: each
      task-closing commit subject whose task is tagged feature/fix/polish/perf/
      security, `chore(...)` excluded. A commit touching `src/remote/` goes to
      `agent/`, everything else to `client/`.
- [x] The gap is visible: `NOTES NOT SHIPPED: <why>` lands in the daily
      publish log, and the watermark records the commit actually tagged.

## Validation criteria

- [x] A run over a range with closed work produces a notes file keyed by the
      version — section S8 of `test/win32/daily-publish.ps1` (scratch repo);
      the generated shape reads as NEW in the What's New model — unit test
      "partition: a generated Windows patch release is new, the Mac line
      installed" in `src/apprt/win32/release_notes.zig`.
- [x] Nothing to say is a stated outcome — S10 writes the file with a "No
      user-visible changes" line (`NOTES NOTHING TO SAY`).
- [x] `test/win32/daily-publish.ps1` covers both, plus the dry run writing
      nothing (I5, S7), hand-written notes winning (S9) and the publish log
      naming a notes gap (T1/T2): ALL PASS, 215 assertions.

## Notes

Filed from T624. Note the version keying: a Windows release is
`win-v<mac line>.<patch>`, so the notes file name has to match what
`provenance.version` reports on the shipped build, or the split will file the
new release's own notes as "already installed".
