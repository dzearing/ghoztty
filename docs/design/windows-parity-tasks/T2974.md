# T2974 - PA-R08: a pane's render target, interop texture and swap chain only ever grow, so a pane that was once full-window or maximized keeps that much GPU memory for life

## Summary

PA-R08 (audit-1, T2959; core F7 + present finding 2). opengl/Target.zig:86 resizeInPlace keeps any larger allocation (grow_only on win32, OpenGL.zig:1334); gl_comp_present.zig:198 sharedCapacity keeps have >= need; resizeSwapInner (:658-668) ResizeBuffers only when capacity grows. Three surfaces in 256 px buckets at their high-water size: a pane once 1400x860 holds ~22-25 MB whatever its size now; one maximize on 4K pins ~150 MB per pane. In baseline-1 the three tab-root panes were full-size before their splits, so ~45 MB of the 348.8 MB is this. Fix: keep grow-only during a live resize/drag/glide (T2577/T2598 need it), then trim to the rounded-up need once the size has been stable ~1 s or at WM_EXITSIZEMOVE. Also check whether split-born panes' first frame is full-window (Surface.zig:915 creates the HWND at parent.surfaceRect()). Risk low-medium: one rebuild frame per settle, never mid-drag.
