# T1577 - tab-strip.ps1's two-tab width assertion can read a shell's transient path title

## Summary

Seen once on 2026-09-14 during a T737_NEUTERED control run: 'two tabs: each is still its own content's width (319 vs 171)' failed because the new tab's title at the instant of measurement was the cmd.exe PATH ('C:\\WINDOWS\\system32\\cmd.exe') rather than the settled cwd title ('C:\\Users\\David'). The same run passed with 171 vs 171 twice either side of it, and the code under test was identical (the neuter restores pre-T737 behaviour), so this is the harness reading a title that is still in flight rather than a defect in the strip. The fix shape is the one section 8 already uses: settle the title deliberately (send a known 'title X' and wait) before measuring, or assert against the title +list --json reports at that moment instead of an expected width.
