# T1358 - Nothing enforces the swap-then-release rule for a window's split tree

## Summary

`Window.zig` replaces a tab's split tree in six places, and every one of them
must install the new tree BEFORE releasing the old one — the window must never
be observable holding a freed tree, because a teardown can pump messages and
anything dispatched in that pump walks `tab_trees`. Three sites already say so
in a comment; the other three did it backwards until T1356, and the seventh
site (`cleanupAllSurfaces`) deinit'ed in place. Nothing checks the rule, so the
next site added gets it right or wrong by luck.

## In plain terms

A rule that four separate pieces of the window code have to follow is written
down only as a comment, and half of them were breaking it. When one of them
broke it in a place that could pump messages, the whole app died on closing a
window. Somebody should make the rule checkable instead of remembered.

## Goals

- [x] A check that fails when a tree slot is released while still installed.
- [x] It runs somewhere the loop already runs (a `none`-lane unit test over the
      AST is not available for Zig here, so most likely a small script audit in
      `test\win32\` alongside the other AST audits, plus a `guard-due` row).
- [x] A demonstration that it goes red on the pre-T1356 shape (T1133).
- [x] Fix the fifth site the first sweep found: `closeTabByIndex` freed the
      closing tab's tree and only then removed its slot.

## Where

- `src/apprt/win32/Window.zig`: `replaceTabRoot`, `replaceTabLeaf`,
  `closeSplitPane`, `splitPane`, `swapSplits`, `equalizeSplits`,
  `cleanupAllSurfaces`.
- The existing AST audits are the pattern to copy —
  `test\win32\verdict-exit-audit.ps1` reads the PowerShell AST; this one needs
  a cheaper shape (a source scan for `old_tree.deinit()` not preceded by the
  slot assignment would already have caught all three).
