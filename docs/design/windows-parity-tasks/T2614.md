# T2614 - T2610 step 3b: per-window presenter child (GhozttyPresenter class, z-ordered above terminal panes and below chrome, WS_CLIPSIBLINGS + WS_EX_TRANSPARENT + HTTRANSPARENT, window region = union of terminal pane rects) with its own thread and GL context, behind GHOZTTY_WINDOW_PRESENTER

## Summary

Builds on step 3a (gl_window_presenter.zig, gl_robust.createSharedContext). Create the presenter HWND on the UI thread when a window's first terminal pane is created and the knob chooses window_presenter (choose()); its context and compose thread live off the UI thread; the layout pass sets SetWindowRgn(bRedraw=FALSE) to the union of terminal pane rects and posts a re-compose. Compose = planPane per pane + one SwapBuffers at interval 1. Design: docs/design/win32-window-presenter.md.

## In plain terms

Each Ghoztty window is getting one drawing surface that all of its terminal
panes will show through, instead of one per pane (the per-pane surfaces leak
video memory). This step puts that surface in place: it is created with the
window, follows every split, resize and close, and lets clicks and typing pass
straight through to the pane underneath. It is switched off unless
`GHOZTTY_WINDOW_PRESENTER=1` is set. Until the next step (T2615) hands it the
panes' pictures, turning it on shows each pane as its plain background color.

## Goals

- [x] a `GhozttyPresenter` child per window, created on the UI thread with the first terminal pane when the knob chooses the presenter path
- [x] its own thread and robust GL context on the terminal pane's pixel format, ready before the pane makes its own context
- [x] z-ordered directly above the topmost terminal pane and below every other child, re-checked after every layout pass
- [x] window region = union of the visible terminal pane rects (gaps stay the parent's)
- [x] hits fall through to the pane (`HTTRANSPARENT`), panes fully covered
- [x] compose loop: wake on an event, `planPane` per pane, one swap at interval 1 (background only until 3c)
- [x] knob off and comp-knob-wins negative controls
