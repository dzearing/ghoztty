# T2614 - T2610 step 3b: per-window presenter child (GhozttyPresenter class, z-ordered above terminal panes and below chrome, WS_CLIPSIBLINGS + WS_EX_TRANSPARENT + HTTRANSPARENT, window region = union of terminal pane rects) with its own thread and GL context, behind GHOZTTY_WINDOW_PRESENTER

## Summary

Builds on step 3a (gl_window_presenter.zig, gl_robust.createSharedContext). Create the presenter HWND on the UI thread when a window's first terminal pane is created and the knob chooses window_presenter (choose()); its context and compose thread live off the UI thread; the layout pass sets SetWindowRgn(bRedraw=FALSE) to the union of terminal pane rects and posts a re-compose. Compose = planPane per pane + one SwapBuffers at interval 1. Design: docs/design/win32-window-presenter.md.
