# T1587 - The main-intake watermark's note field is one unreadable concatenated string, where a dated ledger belongs

## In plain terms

Every morning the loop checks what has landed on the Mac side and writes down
what it found. That note gets glued onto the front of the previous one, inside a
single line of a config file, so the record of the last two months is now one
enormous run-on sentence that nobody opens. The information is not lost — it is
just stored in the one shape that makes it useless.

## Summary

`docs/design/windows-parity-main-intake.json` carries the intake watermark:

```json
{ "lastEvaluated": "<sha>", "date": "YYYY-MM-DD", "note": "<every intake ever, concatenated with ' || '>" }
```

The `lastEvaluated`/`date` pair is the part the tooling reads and it is correct.
`note` is the part a human would read and it has grown past the point of being
readable — a single JSON string holding every previous intake, separated by
`||`, with no line breaks a diff or an editor can use.

The project already solved this shape once: `docs/design/windows-parity-feature-ideas.md`
is an append-only dated markdown ledger, one `## YYYY-MM-DD` section per day, and
it reads fine after a month. The same treatment applies here.

## Details

Proposed shape:

- `docs/design/windows-parity-main-intake.md` — append-only, one `## YYYY-MM-DD`
  section per intake: the sha range, commits evaluated, tasks filed (with ids),
  the sweep verdict, and the lag.
- `docs/design/windows-parity-main-intake.json` keeps `lastEvaluated` and `date`
  only. It stays the machine-readable watermark; nothing reads `note`, so
  dropping the field breaks nothing.
- The existing concatenated `note` is split back into dated sections in the same
  commit that creates the ledger, so no history is discarded.

go.md step 0.6 names the JSON file explicitly and must be updated to say where
the narrative now goes.

## Validation criteria

- [ ] `docs/design/windows-parity-main-intake.md` exists, is append-only, and
      carries one dated section per past intake recovered from the old `note`.
- [ ] The JSON file holds only `lastEvaluated` and `date`; no consumer reads
      `note` (verified by a repo-wide search for the field name).
- [ ] go.md step 0.6 names the ledger as the place the intake narrative goes.
- [ ] A subsequent daily intake writes its section to the ledger and moves the
      watermark in the same commit.
