# T1237 - The un-run-tests sweep only covers src/apprt/win32; the same silence can hide anywhere else in the tree

## Summary

T1191 proved the failure mode is real and found 4 win32 modules (16 tests) that had never executed. The oracle it built - read the compiled test binary's test-name strings, and ask the compiler instead of modelling it - generalises to any namespace, but the sweep is scoped to apprt.win32. src/os, src/remote, src/terminal and the agent lane have the same unmeasured silence. Widening it is mostly a namespace list in test\win32\lib\TestReachAudit.ps1 plus a source-directory map per namespace.

## In plain terms

A unit test can compile, look covered, and still never run, if nothing tells the
test runner to include its file. The check for that only looked at the Windows UI
folder. Now it checks the whole source tree across all three test runs this machine
does. It found one file that had slipped through (desktop detection) and now runs its
test. Every other test-bearing file is either run or skipped for a stated reason (Linux or
Mac only, or run by a separate test step), and any new file that falls through the cracks
turns the check red.
