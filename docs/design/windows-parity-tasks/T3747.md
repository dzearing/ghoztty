# T3747 - Closing a WSL pane must end its wsl.exe and ConPTY once undo-timeout passes, and a new pane must never attach to a closed pane's shell (the user's T3739 hypothesis, opt-in -Wsl arm)

## Summary

During T3739 the user guessed that closing a WSL pane does not close the shell, and that the next pane reuses it. What T3739 found is that the WINDOW is reused (T2597, pane_pool.zig), not the shell, and that fix landed. The shell side was not checked on a real WSL pane, because the loop never boots WSL. Add an opt-in -Wsl arm (the T1751 precedent) to an acceptance script: open a WSL pane with +split --shell=wsl.exe, close it, wait past --undo-timeout (CloseUndo keeps the shell alive that long, T1825), and assert that its wsl.exe and conhost and ConPTY (or its agent session, with persistence on) are gone. Then open a second WSL pane and assert it gets a fresh shell (a different PID inside the distro, and an empty scrollback). The always-run arm does the same with pwsh. Record the -Wsl run in the task file. Deps: T3739.
