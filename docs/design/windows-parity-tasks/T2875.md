# T2875 - Mac: check whether a click in a background window's pane sidebar that raises another window first orders the background window front (Windows fixed in T2863)

## Summary

T2863 found that on Windows a press on another window's header/row/tile in a BACKGROUND window's pane sidebar activated that background window on mouse-down (over the window in front) before the click raised the target on mouse-up; Windows now leaves the background window where it is for those presses (WM_MOUSEACTIVATE -> MA_NOACTIVATE). Check the Mac sidebar for the same flash: AppKit orders a clicked inactive window front on mouseDown unless the view delays ordering (shouldDelayWindowOrderingForEvent + NSApp.preventWindowOrdering). If Mac flashes the background window forward, give PaneSidebarWindowHeader / row / rail tile the same rule so both platforms behave alike; if Mac already avoids it, close with the evidence.
