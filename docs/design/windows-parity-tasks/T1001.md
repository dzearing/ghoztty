# T1001 - The pane-survives-restart guarantee is only measured against a killed manager, never a real agent upgrade

## Summary

T974 added arm M to `test\win32\session-relaunch-notify.ps1`: kill the session
manager alone and the panes must survive untouched - same process still running,
no interrupted notice, same session, still takes input. It kills the manager with
`Stop-Process`, which is the CRASH shape.

The shape this guarantee actually exists for is the T147 mandatory agent UPGRADE:
the app notices a newer agent binary, asks the running manager to stand down, the
old process exits on its own terms and a new build starts in its place. That path
has extra moving parts arm M never touches - a graceful shutdown rather than a
kill, a DIFFERENT BUILD adopting holders the previous build created, and the
handshake that decides whether it may. A holder record the new build reads
differently, or a shutdown that reaps its holders on the way out, would take every
user's panes down on the upgrade and arm M would stay green.

Add an arm (or extend `test\win32\agent-handoff.ps1`, which already drives the
real handoff) that runs arm M's assertions across a genuine upgrade: the recorded
command is the same process afterwards, no pane claims an interruption in banner
or scrollback, and the panes stay on their own sessions.

## In plain terms

Ghoztty's background session manager updates itself. When it does, nothing you
are running should notice. We now test that for the case where it CRASHES, but
not for the case where it UPDATES - which is the one that happens to everybody,
on a schedule, and the one where a new version of the program has to pick up
terminals an older version created.
