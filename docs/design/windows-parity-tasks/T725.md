# T725 - Harness guards only run when someone remembers to run them: no harness floor

## Summary

Several self-check scripts each guard a harness trap that has already cost turns - harness-exitcode-audit.ps1 (T197), build-mode-guard.ps1 (T350), persistence-flag.ps1 (T158), parity-sweep.ps1 (T152), crash-diagnostics/crash-stacks. None is in a standing lane. P1-P3 is the product floor; there is no harness floor, so each guard runs only when the turn that wrote it runs it, and every one of these traps is exactly the kind nobody remembers. They are all cheap (seconds, no GUI, no user state) - a single -Lane harness entry in floor-lane.ps1 that runs them and prints one PASS/FAIL line would make them standing.

## In plain terms

A handful of self-checks watch the test suite itself: do the tests report their
own failures honestly, do they say when they skipped something, do they run
against the right build. Nothing ever ran them on a schedule, so they only got
run when somebody thought of it - and two of them had quietly been failing for
weeks. Now they run as one command, and the tooling refuses a commit that
changed a test script without running them.

## Goals

- [x] one command runs the whole family of harness audits and prints one verdict
- [x] a member that is red against a filed task is reported but does not fail the floor, and the exception list can only shrink
- [x] the set is standing: editing any script under `test\win32\` makes it due and blocks a commit until it is green
- [x] the gate has a demonstration that it can fail (T1133)
- [x] the two audits found red are filed rather than papered over
