# T2041 - test-reach audit stayed green while mac_layout_blob.zig's tests were in no test binary: find why its binary scan counted a module the lane never ran

## Summary

Found in T1979. `src/apprt/win32/mac_layout_blob.zig` has had `test` blocks since T337, and `layout_blobs.zig` imports it, but nothing referenced it from a test container (`src/apprt.zig` lists `layout_blobs.zig` and not this file). Evidence that its tests did not run: `zig build test -Dapp-runtime=win32 -Dtest-filter=mac_layout_blob` hit the test-filter guard ("matched no tests") before T1979 added `_ = @import("apprt/win32/mac_layout_blob.zig");` to `src/apprt.zig`, and afterwards the same filter ran them and a deliberately broken assertion went red.

Yet `test/win32/test-reach-audit.ps1` (T1191) was stamped green on 2026-10-16. Its rule is exactly this case. Find out why: whether its `Get-WinModulesInTestBinary` string scan matched `apprt.win32.mac_layout_blob.test` in the binary from something other than a compiled test (debug strings, a panic message, the other test binary), whether `Resolve-WinTestBinary` read a different binary than the lane ran, or whether the filter guard misled T1979. Fix the audit so it goes red on this shape, and add the case to its section A fixtures / `-TeethCheck`.

## In plain terms

A check that makes sure every piece of code's own tests actually run looked like it had missed one module. It had not: that module's tests were running the whole time. A shortcut for running a few tests at a time gave the false impression they never ran, and its error message even suggested the shortcut that misled. The message and the testing guide now explain the trap.

## Resolution

The audit was correct. Measured on 2026-11-23 with `_ = @import("win32/mac_layout_blob.zig")` commented out of `src/apprt/unit_tests.zig`: the unfiltered win32 test binary still carried all 19 `apprt.win32.mac_layout_blob.test.*` names, and a planted `try std.testing.expect(false)` test in the file turned the full lane red at `mac_layout_blob.zig:1256`. The same tree under `-Dtest-filter=T2041` reported "matched no tests". Mechanism: a file's tests enter the binary when the file is analyzed; `mac_layout_blob.zig` is analyzed because `layout_blobs.zig`'s named tests call into it, and any filter drops those tests, so the file is never analyzed under a filter. `layout_blobs.zig` had the identical import before T1979 (`8fa92ada4^`), so T1979's "in no test binary" was a filter artifact. Nothing in the audit needed fixing; the fix is to the thing that misled: `src/build/TestFilterGuard.zig`'s failure message, a `docs/claude/testing.md` paragraph, the `unit_tests.zig` and `TestReachAudit.ps1` comments, and a correction bullet in T1979's log entry. The aggregator line stays (filterability, and independence from `layout_blobs.zig`'s tests).
