# T1982 - Timing-sensitive tests and the harness floor wait their turn when two loop lanes share the box

## In plain terms

When two copies of the work loop run on the same computer, one of them
compiling can make the other's speed tests look slow and fail for no real
reason, and two copies of the long test-checking sweep at once make both
crawl. Now the speed tests and the sweep take turns: a second one waits, says
who it is waiting for, and gives up after a fixed time instead of hanging.

## Goals

- [x] speed-measuring tests take a box-wide lock and wait their turn
- [x] only one harness-floor sweep runs on the box at a time
- [x] every wait is announced, names the holder, and is bounded
- [x] tests that do not measure time never wait

## Summary

Split from T1937 items 2 and 8. A machine-wide Global\GhozttyTimingTest mutex that scripts marked # @timing-sensitive take (perf, latency, resize-flicker, soak), plus one floor-sweep mutex so two lanes never run floor-lane -Lane harness at once. Waiting is bounded and printed, never silent. A non-timing script never waits.

## Validation criteria

- [x] A `# @timing-sensitive` script waits while another holder has the
      timing lock and says so, naming the holder and its lane; the wait is
      bounded and a timed-out run is ASSERTED NOTHING (exit 2), never run.
      `test\win32\machine-lock.ps1` sections B, C.
- [x] A script without the marker does not wait and prints nothing about the
      lock (section D); with `GHOZTTY_TIMING_LOCK=0` the B assertions would go
      red (section E, negative control).
- [x] A holder that dies does not wedge the lock (section F).
- [x] `floor-lane.ps1 -Lane harness` takes the floor lock outside its
      watchdog, tells the sweep it holds it, and on a timeout runs anyway and
      says so (section G).
- [x] Every marked script under `test\win32\` loads the hook, with a planted
      unhooked script as the teeth (section H).
