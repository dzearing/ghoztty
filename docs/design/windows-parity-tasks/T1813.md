# T1813 - The win32 unit-test lane shows its test windows on the user's screen: ghostty-test.exe opens visible banner windows on the input desktop every floor run

## Summary

Measured 2026-10-10 12:55 during floor-lane -Lane win32 with a fullscreen game (Valheim) in front: ghostty-test.exe (D:\git\ghoztty\.zig-cache\o\...\ghostty-test.exe) created 12 visible top-level windows (10 GhozttyBannerOverlay, 2 gone before their class was read; 12:55 and 12:59) on the input desktop. BannerOverlay.zig tests show their owner with SW_SHOWNOACTIVATE, so they take no focus, and a window shown that way can go on top of the non-topmost z-order, which can put it over a borderless game (inferred, not measured). Every turn runs this lane (floor-lane -Lane all), and the soak daemon's win32-releasesafe round runs the same tests, so this is the remaining route from automation to the user's screen. Fix shape: run the win32 test lane (floor-lane and the soak round) on the background test desktop (lib\TestDesktop.ps1 StartProcess with lpDesktop; children inherit it), or make every test window offscreen/hidden. Validate with a watcher that enumerates visible top-level windows owned by the test binary during a full win32 lane: zero on the input desktop.

## In plain terms

Every time the automated checks ran, the Windows test suite briefly flashed a
dozen small test windows onto your screen - even over a fullscreen game. Now
those checks run on a separate, invisible desktop, so nothing they open can
appear in front of you, and a check that ever shows a window on your screen
again is marked as failed.

## Goals

- [x] The floor runner starts every test lane on a background desktop its whole process tree inherits
- [x] The idle soak daemon's rounds land on the same background desktop
- [x] A lane whose processes show a window on the user's desktop is scored red and names the window
- [x] A harness proves all three without ever putting a window on the user's screen
