# T2394 - Frame lab live scene scorer (T2392 split): a C# GfcScorer that infers each captured frame's scene - every card's rect from the window's own edge and the chrome insets measured on a still frame at launch, not from the card's content - scores bleed per frame, records the tracked edge (window-right/bottom, divider, sidebar-edge) per frame, and keeps each failing frame's FsFindings; proved against synthetic resize frames with planted B1/B2/B3/B6

## Summary

Split out of T2392 (2026-10-28). FrameScore (T2381) scores a frame against a
FIXED scene, and FrameLabCard's `New-FrameLabCardRegion` builds a region from a
known card rect. During a live resize the card rects move every frame, so the
live scorer has to INFER each frame's scene, and must not infer it from the
card's own content - a stale-size frame (B2) is exactly one whose content
disagrees with where the pane is.

Design to build (C#, a `GfcScorer` so it runs on FrameCapture's worker):

- At launch, from a still frame: the window rect, every pane's content rect,
  the cell size, the tab-strip/sidebar/border insets and the divider positions,
  all relative to the window's edges (physical pixels).
- Per frame: locate the window's moving edge(s) independently of the cards
  (a solid backdrop behind the capture rect, or the window border colour), then
  derive each card rect = edge minus the measured insets / divider ratio, build
  the FsScene, score it (`[GhozttyFrameScore]::Score`).
- Record per frame index: failing bool, the FsFinding list, and the tracked edge
  (window-right / window-bottom / divider / sidebar-edge) for
  `Measure-FrameMotion`.
- The FrameLabInput types compile in memory (T2392 found this), so a C# type
  that needs Gli* must be compiled together with `$script:FrameLabInputSource`;
  FrameCapture/FrameScore types load from files and can be referenced.

Proof: synthetic frames rendered at a sequence of window widths with planted
B1 (magenta erase), B2 (ring inset = previous size), B3 (stretched ring) and B6
(garbage block) - each found on exactly its frame, clean frames clean, and the
tracked edge equal to the rendered one.

## Validation criteria

- [ ] Clean synthetic resize sequence scores zero findings on every frame, and the tracked edge matches the rendered edge on every frame.
- [ ] Each planted B1/B2/B3/B6 is found on exactly its frame (and a frame whose card content is the PREVIOUS size reads B2, not clean).
- [ ] The scorer keeps up: scoring a 1500x1000 frame stays under one 120 Hz refresh on this box (measured, number recorded).
