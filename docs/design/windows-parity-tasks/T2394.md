# T2394 - Frame lab live scene scorer (T2392 split): a C# GfcScorer that infers each captured frame's scene - every card's rect from the window's own edge and the chrome insets measured on a still frame at launch, not from the card's content - scores bleed per frame, records the tracked edge (window-right/bottom, divider, sidebar-edge) per frame, and keeps each failing frame's FsFindings; proved against synthetic resize frames with planted B1/B2/B3/B6

## Summary

Split out of T2392 (2026-10-28). FrameScore (T2381) scores a frame against a
FIXED scene, and FrameLabCard's `New-FrameLabCardRegion` builds a region from a
known card rect. During a live resize the card rects move every frame, so the
live scorer has to INFER each frame's scene, and must not infer it from the
card's own content - a stale-size frame (B2) is exactly one whose content
disagrees with where the pane is.

Design to build (C#, a `GfcScorer` so it runs on FrameCapture's worker):

- At launch, from a still frame: the window rect, every pane's content rect,
  the cell size, the tab-strip/sidebar/border insets and the divider positions,
  all relative to the window's edges (physical pixels).
- Per frame: locate the window's moving edge(s) independently of the cards
  (a solid backdrop behind the capture rect, or the window border colour), then
  derive each card rect = edge minus the measured insets / divider ratio, build
  the FsScene, score it (`[GhozttyFrameScore]::Score`).
- Record per frame index: failing bool, the FsFinding list, and the tracked edge
  (window-right / window-bottom / divider / sidebar-edge) for
  `Measure-FrameMotion`.
- The FrameLabInput types compile in memory (T2392 found this), so a C# type
  that needs Gli* must be compiled together with `$script:FrameLabInputSource`;
  FrameCapture/FrameScore types load from files and can be referenced.

Proof: synthetic frames rendered at a sequence of window widths with planted
B1 (magenta erase), B2 (ring inset = previous size), B3 (stretched ring) and B6
(garbage block) - each found on exactly its frame, clean frames clean, and the
tracked edge equal to the rendered one.

## In plain terms

The frame lab films every frame a window shows while you resize it. To say a
frame is wrong, it has to know what that frame should have looked like - and
while you drag, everything moves every frame. This is the part that works
that out from where the window's edges and dividers actually are, then checks
every pane's picture against it. Nothing changes for a user yet; it is what
lets the lab's first live run report real bleeding instead of guesses.

## Goals

- [x] Each frame's panes are worked out from the window edge and divider, never from what the panes show
- [x] Every frame records pass/fail, the tracked edge for the smoothness numbers, and a failing frame's findings
- [x] Runs on the capture worker as a GfcScorer
- [x] Proved on synthetic resize frames with planted defects

## What landed

- `test\win32\lib\FrameLabScene.ps1`: `GfsSceneScorer` (C#, csc-compiled and
  cached like FrameCapture). `GfsEdge` locates a moving edge on several scan
  lines (median): window-right/bottom by scanning in from a solid backdrop
  until it stops (and a scan that never crosses backdrop is NOT located), a
  divider or sidebar edge by its own colour. `GfsCard` says which edge each
  side rides on. `Calibrate()` measures the ring box, padding, cell size and
  every side's offset on a still frame and refuses one that does not score
  clean. Per frame: `RegionFor` builds what New-FrameLabCardRegion builds for
  the grid the app derives (floor((W - pads) / cell)), FrameScore scores it,
  and a `GfsRecord` keeps failing/edges/ms plus findings for failing frames.
  An unlocated anchoring edge fails the frame as `LOC`.
  `Get-FrameLabSceneMotion` hands one edge's series to Measure-FrameMotion.
- `test\win32\lib\FrameScore.ps1`: now compiled to a hashed dll in %TEMP%
  (`Import-FrameScore`, `$script:FrameScoreDll`) instead of in memory, so the
  scene scorer can reference its types; and ScoreRegion reuses the previous
  pixel's verdict on a run of one colour (9.8 ms -> 2.2 ms per 1500x1000 frame,
  verdicts unchanged: frame-score.ps1 ALL PASS 41).
- `test\win32\frame-lab-scene.ps1` (16 assertions, app-free) + guard row
  `frame-lab-scene` (covers the scene lib, FrameScore, FrameLabCard,
  FrameCapture, the harness).

## Validation criteria

- [x] Clean synthetic resize sequence scores zero findings on every frame, and the tracked edge matches the rendered edge on every frame. (frame-lab-scene.ps1 B1, B2: 17 clean frames of a 21-frame 900x600 -> 1400x840 drag, window-right / window-bottom / divider exact on all 21)
- [x] Each planted B1/B2/B3/B6 is found on exactly its frame (and a frame whose card content is the PREVIOUS size reads B2, not clean). (B3.B1/B2/B3/B6 each on exactly frames 5/8/11/14; B4: the previous-size frame reads B2 on both cards; B5: a frame with no window edge fails as LOC; B7: the same through FrameCapture's worker, failing = 5,8,11,14)
- [x] The scorer keeps up: scoring a 1500x1000 frame stays under one 120 Hz refresh on this box (measured, number recorded). (C1: p50 2.19 ms, max 4.61 ms over 20 runs, budget 8.33 ms; it was 9.78 ms before the run cache in FrameScore)
