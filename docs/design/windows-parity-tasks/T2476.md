## Summary

T2400's divider-flicker fixes (banner region order, banner ULW present, gutter clear that spares new gutters and viewers, banner pre-render) are each proven only by a probe that lives in an ignored folder: `temp/t2400/divider-black-probe.ps1` (dark frames, `-SampleEvery` frame sheets, nav-vs-page edge rows) and `temp/t2414/divider-bite-probe.ps1` (accent-bar bite on banner rows). Make them one committed acceptance script under `test/win32/` that photographs a POSTED divider drag with WGC (FrameLabDriver / FrameCapture, as the probes do) for 1, 4 and 9 panes and both divider orientations, with a banner set and an HTML viewer in the layout, and scores per frame: near-black pixels inside any pane/banner/nav, flat-config-background gutter frames, the accent-bar bite, and the viewer nav-vs-page edge mismatch (reported, not failed, until T2360: on the GDI stack the page leads every GDI pixel by 1-2 compositor frames per drag tick, see T2400's 2026-10-29 log). It captures the input desktop, so it is an `@input-desktop-exception` script: it runs only when `Get-UserPresence` reads absent, never in a sweep while the user is present (go.md, NEVER PULL FOCUS). Give it a guard-due row covering BannerOverlay.zig, the gutter clear and layoutSplits in Window.zig.
