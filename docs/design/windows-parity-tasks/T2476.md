# T2476 - Commit the WGC divider-drag flicker harness: 1, 4 and 9 panes, both divider orientations, banner set and an HTML viewer in the layout, scoring dark frames, flat-gutter frames and page-vs-chrome edge mismatches (T2400 probe made permanent)

## Summary

T2400's divider-flicker fixes (banner region order, banner ULW present, gutter clear that spares new gutters and viewers, banner pre-render) are each proven only by a probe that lives in an ignored folder: `temp/t2400/divider-black-probe.ps1` (dark frames, `-SampleEvery` frame sheets, nav-vs-page edge rows) and `temp/t2414/divider-bite-probe.ps1` (accent-bar bite on banner rows). Make them one committed acceptance script under `test/win32/` that photographs a POSTED divider drag with WGC (FrameLabDriver / FrameCapture, as the probes do) for 1, 4 and 9 panes and both divider orientations, with a banner set and an HTML viewer in the layout, and scores per frame: near-black pixels inside any pane/banner/nav, flat-config-background gutter frames, the accent-bar bite, and the viewer nav-vs-page edge mismatch (reported, not failed, until T2360: on the GDI stack the page leads every GDI pixel by 1-2 compositor frames per drag tick, see T2400's 2026-10-29 log). Each scored defect needs a negative control: `T2400_NEUTERED` (banner), `GHOZTTY_CLEAR_WHOLE_GUTTERS` (gutter clear), and T2414's pre-fix knob.

It captures the input desktop, so it is an `@input-desktop-exception` script: it runs only when `Get-UserPresence` reads absent, never in a sweep while the user is present (go.md, NEVER PULL FOCUS). Give it a guard-due row covering BannerOverlay.zig, the gutter clear and layoutSplits in Window.zig.

## In plain terms

The fixes that stopped divider drags flashing black are checked today by a throwaway script. This makes that check permanent, so a later change that brings the flicker back is caught before it ships.
