# T2985 - PA-W01: every Zig thread commits a full 16 MB stack on Windows, so each pane holds ~48 MB of stack and the parked pane threads keep ~430 MB after the panes close (reusable_thread.zig:57)

## Summary

PA-W01 (audit-1, T2960). Zig 0.15.2 std.Thread defaults stack_size to 16 MB (lib/std/Thread.zig:400) and passes it to CreateThread with dwCreationFlags 0 (:649-655), which Windows treats as the INITIAL COMMIT, not a reservation. src/os/reusable_thread.zig:57 spawns every pooled pane thread with the default SpawnConfig (renderer, io: src/Surface.zig:45-46; io-reader: src/termio/Exec.zig:36), and no stack_size override exists anywhere in src/. Estimated: 3 x 16 MB = 48 MB of the ~121 MB/pane private growth in baseline-1 cycle, and 27 parked threads x 16 MB = ~432 MB of the 825 MB the first cycle leaves behind; >=128 MB of the 323 MB idle private (IPC listeners, FrameClock, one pane). Fix: give the pools (and a shared spawn helper for the other std.Thread.spawn(.{}, ...) sites) an explicit small stack_size (64-256 KB) on Windows, or spawn with STACK_SIZE_PARAM_IS_A_RESERVATION so the PE header 16 MB reserve still grows on demand; confirm first with a one-pool A/B or VMMap. Risk low (max depth unchanged if done via reservation; a too-small explicit commit+reserve could overflow deep stacks, so prefer the reservation flag). Shared file, Windows-only effect: macOS pthread stacks are committed lazily, so no Mac half is owed.

## Validation criteria

- [ ] a VMMap or private-bytes A/B shows the per-thread stack commit before and after (one pool first)
- [ ] perf-baseline.ps1 -Phase cycle: closed private_mb drops by at least 300 MB against baseline-1 (1150.9 MB debug), and idle private (~323 MB) drops measurably
- [ ] deep-recursion paths (renderer, io parser) still pass the none and win32 lanes (floor-lane.ps1 -Lane all)
