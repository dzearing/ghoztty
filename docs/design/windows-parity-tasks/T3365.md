# T3365 - The GTK IPC server ignores the <socket>.reset rebind sentinel the CLI drops when a connect is refused

## Summary

src/os/ipc_client.zig connectWithReset drops <socket>.reset when the socket file exists but refuses, and retries with backoff; the Mac server watches for it and rebinds. src/apprt/gtk/IpcServer.zig (T3335) never looks, so a GTK app whose listener died while the app lived stays unreachable until restart. Watch the sentinel (poll it in the accept loop or a GFileMonitor), rebind, delete it; add the case to test/linux/ipc-server.sh.

## In plain terms

On Linux, if the file the `ghoztty` command uses to talk to the running app
got replaced or stopped answering while the app was still open, every command
said "no running instance" until the app was restarted. On the Mac the
command leaves a small "please reconnect" note and the app picks it up and
starts answering again. Linux now does the same, so the command recovers by
itself within a second.

## Goals

- [x] The GTK app notices `<socket>.reset` and rebinds its socket
- [x] The sentinel is removed once the path answers again, kept when it cannot be
