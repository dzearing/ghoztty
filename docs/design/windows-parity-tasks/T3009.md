# T3009 - PA-M09: renderer and termio mailboxes are destroyed without draining, so a queued change_config or pane_backdrop payload leaks at pane close (renderer/Thread.zig:233)

## Summary

PA-M09 (audit-1, T2961). src/renderer/Thread.zig:233 calls mailbox.destroy, which frees only the queue struct (src/datastruct/blocking_queue.zig:102-105); renderer Message.deinit exists and frees .change_config and .pane_backdrop payloads (src/renderer/message.zig:126-137) but is never called on messages still queued. src/termio/mailbox.zig:46-53 has the same shape. Rare (a message must land between the last drain and the stop); a leaked backdrop slice also pins one of backdrop_pool's live slots. Fix: while (mailbox.pop()) |m| m.deinit(); before destroy, and the termio equivalent (free payloads only, never execute). Risk low. Shared core: the fix serves macOS too; a seat-mac validation is filed. Baseline: docs/design/perf-audit/baseline-1.json (T2958); findings: docs/design/perf-audit/audit-1/M-findings.md.

## Validation criteria

- [ ] a unit test queues an owning message, tears the thread down, and passes under std.testing.allocator (no leak)
- [ ] none and win32 lanes green
