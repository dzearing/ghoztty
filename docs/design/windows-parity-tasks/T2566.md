# T2566 - Composition step 3d-1a: on the composition path a banner pane's window spans its whole slot, and the grid, renderer and swap chain sit below the band

## Summary

T2558 split, slice a (core geometry). Knob = gl_comp_present.enabled() read at Surface init (the present path itself is only decided on the renderer's first frame, after layout, so the knob is the only thing layout can key on). Sites: (1) Surface gets an atomic grid_band (px, 0 default) plus a helper; (2) Window.leafRect (Window.zig ~L8620): knob on + banner -> place the HWND at top (not top+inset) with height avail, and set grid_band = inset; knob off unchanged; (3) Surface.applyResize (~L4292) and updateClientSize (~L1386): height -= band, so sizeCallback gets the grid area; (4) OpenGL.surfaceSize + frameOutlivedItsWindow (src/renderer/OpenGL.zig ~L890-947): h -= band, read from rt_surface; (5) comp present: non-tree mode SetOffsetY(band) on the pane's root visual (gl_comp_present.zig Presenter.visual; add the IDCompositionVisual slot and verify it against dcomp.h) - T2467 overlay visuals hang under that root and shift with it (slice c owns them); tree mode: the Surface tree placement (~L1670) maps GetClientRect -> add band to y, subtract it from h; (6) BannerOverlay.updatePosition: popup at rect.top (not rect.top - inset) when band > 0. A WGL fallback mid-life keeps the band: surfaceSize already returns the grid size, and the blit to dst (0,0,w,h) lands in the BOTTOM w x h of the GL default framebuffer, i.e. below the band, which the banner popup covers. Oracle: pane-banner.ps1 + comp-present.ps1 green with the knob on and off; knob on, a banner pane's surface rect equals its slot rect and its grid rows equal the knob-off build's.
