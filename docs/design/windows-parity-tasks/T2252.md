# T2252 - Collapsing or expanding a pane banner on Windows resizes the terminal through the animation; Mac does one resize at the click behind a frozen copy of the last frame that glides with the card (main a81db68f9)

## Summary

Mac a81db68f9 (BannerGlide.swift, predictResizeShift/flushResize C API): banner collapse/expand never shows the terminal resizing - one resize at the click (flushed past the debounce), hidden behind a frozen copy of the last frame that glides with the card to where the content will actually land (Surface.predictResizeShift). Windows T1031/T1349 made the collapse fast and flicker-free but still resizes along the way; port the single resize + frozen-frame glide to the win32 banner animation.

## In plain terms

When you click a pane's banner to collapse or expand it, the terminal text
under it visibly jumped and re-flowed while the card slid. Now the terminal
holds a still picture of itself that slides smoothly with the card to where
the text will end up, the real resize happens once out of sight, and the live
terminal takes over in the same spot once it has redrawn - the way it looks
on the Mac.

## Goals

- [x] the grid is resized once per toggle, applied at once instead of after the resize debounce
- [x] a frozen copy of the last frame covers the pane before the resize and glides with the card by the inset change plus the grid's own row shift (`predictResizeShift`)
- [x] the copy comes down only after the card stops and the terminal has redrawn at its new size (40ms quiet), or at a 500ms cap
- [x] falls back to the old toggle when animations are off or no frame can be captured

## Design

- `banner_glide.zig` (pure, unit tested in the `none` lane): travel, eased
  offset (the card's own curve), resized height, and the release rule - Mac's
  `settleQuiet` 0.04s / `settleCap` 0.5s.
- `BannerFreeze.zig`: a layered, click-through popup owned by the terminal and
  seated directly behind the banner card, painting the captured frame (the
  renderer's own readback via `Surface.captureContent`, not an HWND capture)
  masked below the card's moving edge, pane background elsewhere.
- `BannerOverlay.toggleCollapsed` captures, predicts and shows the copy before
  the layout pass; `Surface.flush_next_resize` makes `handleResize` call the
  core `flushResize`; `present_seq` counts presented frames so "redrawn and
  quiet" is measurable. Choice recorded: the live terminal is not offset to
  meet the copy mid-glide (Mac's `lead: -1`), because the copy is only
  released after the glide ends, where both are at rest in the same place.

## Validation criteria

- [x] one frozen copy per click, travel = inset change + grid shift, grid resized exactly once and only after the copy is up, released `landed` within 180-500ms with frames presented behind it, in both directions - `test\win32\pane-banner.ps1` 6f2 T2252 assertions, ALL PASS (168) via `acceptance-parallel.ps1 run`
- [x] negative control: `T2252_NEUTERED = true` fails exactly the 6 T2252 assertions and nothing else (154 passed)
- [x] `banner_glide.zig` unit tests in the floor lanes
- [ ] NOT RUN: a by-eye look at the glide on the user's desktop (the user is present; never pull focus)
