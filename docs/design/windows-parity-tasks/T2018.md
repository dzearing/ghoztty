# T2018 - chooser-kill-hover.ps1: pointing at Kill no longer lights its fill (rest=1156, hot=427)

## Summary

chooser-kill-hover.ps1 1 FAILURE(S) (17 passed): 'pointing at Kill lights its fill (rest=1156, hot=427)'. Found in T2005 (2026-10-16): red in lane A on HEAD 161784011 with the script byte-identical to HEAD (run serially, -Width 1, alone), so it predates T2005. Logs: scratchpad aplogs3 of that turn.

## In plain terms

The automated check for the machine chooser's Kill button had been failing for five weeks, which made it look as if the button no longer lit up when you point at it. The button was fine. The check compared the button against a patch of the card next to it, and that patch had become the Show / Resume button when that button was added. The check now reads the card's colour from the card's plain left edge, so it measures the Kill button again and can again catch a real regression.

## Goals

- [x] find why the hover check reads LESS ink when hovered than at rest
- [x] fix the check, not the app, if the app is right
- [x] prove the fixed check still goes red on the defect it guards

## Validation criteria

- [x] `chooser-kill-hover.ps1` ALL PASS (18 assertions) via `acceptance-parallel.ps1 run -Scripts chooser-kill-hover.ps1 -FailFast` on a fresh debug build: rest=80 (the x glyph alone), hot=809 (the fill), after leave=80, second cycle identical.
- [x] `-NegativeControl` goes red exactly where it should: `NEGATIVE CONTROL: the Kill fill SHOULD have stuck (rest=80, after leave=80)`, 1 FAILURE(S).
- [x] no other harness takes a card-fill reference beside Kill (grep of test\win32 for the old `box.Left - $w - 4` patch).

## Root cause

Harness drift, not an app defect. `Get-CardFill` took the card's fill as the mode of a Kill-box-sized patch immediately LEFT of the Kill box. T1746 (434e0ec12) put the Show / Resume button exactly there (`chooser_sessions.zig` `withAction`: `right = kill.left - action_gap`), so the reference became the button's fill: every pixel of the Kill box differed from it at rest (rest=1156 is the whole 34x34 box at 125%) and the hover, which brightens toward the card, read as fewer. Fix: the reference is now a 4 DIP strip from the geometry's `CardX` (card left edge, clear of every mark) over the Kill box's rows.
