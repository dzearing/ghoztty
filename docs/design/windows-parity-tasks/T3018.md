# T3018 - PA-I04: the agent's session ring appends one byte at a time with a 64-bit modulo per output byte (session.zig:493-496)

## Summary

PA-I04 (audit-1, T2962). src/remote/agent/session.zig:493-496: `for (src) |b| { self.buf[widx] = b; widx = (widx + 1) % cap; }` with a runtime cap, so every output byte of every session costs a divide (several ns/byte against well under 0.1 ns for memcpy), under the store-wide lock (PA-I05). Fix: two @memcpy segments (to the end, then wrapped). Risk trivial; existing ring tests cover it. Shared agent code: Mac half filed. Findings: docs/design/perf-audit/audit-1/I-findings.md.

## In plain terms

The background service that keeps your terminal sessions alive saves every
byte of output into a rolling buffer, and it copied that output one byte at a
time with a slow division on each byte. Busy panes (a long build, a log tail)
paid that cost on every character. It now copies in at most two block moves,
so the service does less work per line of output; nothing you see changes.

## Goals

- [x] the session ring writes and reads in at most two memcpy segments (append, copyRetained, slice)
- [x] the holder's replay buffer append does the same (audit-2 PA-I18)
- [x] model tests prove the bytes are identical across every wrap point
