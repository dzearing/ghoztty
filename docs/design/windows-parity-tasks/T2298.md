# T2298 - Windows all-windows sidebar cannot close a window or a project group; Mac's window row and project header now offer an x, and every sidebar close asks nothing, takes no focus and ends the sessions (Mac 345be6b02, 7e4646bb5, 9c2ab5521)

## Summary

Mac 345be6b02: in the all-windows scope, hovering a window row or a project header puts an x where its count was (nothing shifts). A window's x closes that window (that tab, in a tab group); a project's x closes every window under it (while searching: only the matching windows it shows and counts). EVERY close from the sidebar - a pane's x (this window or another; right-click Close Pane too), a window's x, a project's x - asks nothing (no running-process confirm, no remote Close/Disconnect prompt), takes no focus (never raises/activates the window), and ENDS the panes' processes and agent sessions (CLOSE-on-free, never detach); undo still works for its window, the sessions end when it expires. A window's last pane closed from the sidebar closes the window without a confirm. The window close runs on the next loop turn so a window can close itself from its own sidebar. 7e4646bb5: header x lines up in one column with the pane rows' x. All sidebar item buttons share one style: 18pt circle, hover wash 8%->18% (on the accent pill white 20%->35%), glyph brightens to primary. Windows has the all-windows scope (T1829, PaneSidebar.zig all_windows) with window headers and project groups. NOTE for T2280: Mac's pane-row x is no longer 'the ordinary confirmed close' - it is now unconfirmed and session-ending; this task owns that semantic change. Ref: main docs/reference/pane-sidebar.md 'Closing from the sidebar'.
