## Summary

Found by T1599 while adding a guard row. `powershell -NoProfile -File test\win32\guard-due.ps1`
exits 1 with 4 failures against 96 passes, and none of them are T1599's added row:

- `A2 list excludes a script the row does not cover` - the assertion expects
  `list` not to name `test\win32\go-loop-guard.ps1`, but the real go-loop row
  covers its own harness now, so the fixture's expectation is stale.
- `C6 an uncovered file changing does not make the row due` and
  `C10 a row covering nothing here is N/A, not DUE` - both read the whole
  fixture listing, which carries a genuinely DUE `argv-hazard` row
  (`scripts/uncovered-by-any-row.ps1` changed), so the exit code they assert on
  is 1 for a reason that has nothing to do with what they measure.
- `H2 every row names a harness that exists and stamps itself` - names
  `test\win32\chooser-sessions-push.ps1`, which has NO `guard-due update` call,
  so its row (added with T710) can never be cleared. That is precisely the
  permanent-red shape H2 exists to catch, and it has been sitting red since.

The gate that watches every other harness is itself a harness nobody was
running, which is the same hole T1599 closed for kb-actions. Fix each failure
on its merits (H2 wants the stamp added to chooser-sessions-push.ps1, not the
row removed), then give test\win32\guard-due.ps1 a guard row of its own so the
table and its acceptance cannot drift apart again.
