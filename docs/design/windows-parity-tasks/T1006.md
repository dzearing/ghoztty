# T1006 - The composer forgets its undo history when the pill is closed or written to from outside

## Summary

T983 gave the web composer an undo journal for the quotes and image chips native splices in, and that journal lives on the PAGE - created when the pill opens, destroyed when it closes (D43's own renderer-cost mitigation). So a quote inserted before a close cannot be undone after a reopen, even though the text it produced is still sitting there: the buffer outlives the page and the history does not. The same edge shows up when native rewrites the buffer for any other reason - every seed that is not an insertion clears the journal deliberately, because an undo must never resurrect a report the user already sent - but what the user sees is just that Ctrl+Z stopped working, with nothing saying why. Two shapes worth weighing when this is picked up: keep the journal on the BAR (native), where it outlives the controller and can be seeded back down to a fresh page; or accept the page's lifetime and make the difference legible instead of silent. Not urgent: the common case - quote or paste, change your mind, Ctrl+Z - is covered and tested.

## In plain terms

If you quote a passage into the feedback box, close the box, and open it again later, Ctrl+Z no longer takes the quote back out - the box forgot what you did while it was closed. After this lands, the box remembers: undo works across a close and reopen, and any typing you did after the quote comes off first, as one step, before the quote itself. Sending a report still wipes the history, so undo can never bring back something you already filed.

## Goals

- [x] the undo history is kept by the app while the box is closed, and handed back when it reopens
- [x] typing done after the last quote/picture undoes as one step on the reopened box, then the quote goes
- [x] a send (or any other write from outside the box) still clears the history
- [x] Mac behaviour checked by the Mac seat - filed as T1774 (seat: mac)

## Design (the mechanism call, made here - D46: not a user decision)

Of the two shapes the summary names, the journal now lives on the BAR (native): the page posts `{t:"journal", undo, redo, after}` whenever it changes, `ViewerFeedbackBar.journal` keeps it verbatim, and `composerReady` posts it back to a fresh page right after the first seed, which `adoptJournal`s it. Chosen over "make the loss legible" because Mac's composer is an NSTextView whose undo is not scoped to a pill lifetime, so the parity experience is that the history is simply still there. `after` is where the newest journalled step left the document (plus a text+quotes key); a reopened page whose document differs from it pushes that checkpoint first, so typing the old engine knew about undoes as one run - the way a typing run is one undo on the Mac - instead of vanishing along with the quote. Every native write that is not an insertion (`composerSync`: the post-send clear, a test, anything calling `feedbackSetText`) drops the stored copy, and so does an insertion that lands with no page to journal it.
