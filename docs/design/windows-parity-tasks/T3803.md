# T3803 - Linux harnesses grep for GTK CRITICAL forms the app never writes, so their no-critical checks cannot fail

## Summary

The GTK app's glib log handler writes criticals as 'error(glib): CRITICAL: <Domain>: ...'. Nine test/linux harnesses (cli-pane-drag, cli-rearrange, gutter-bar, pane-drag-ghost, pane-pop-out, stack-glide, stack-persist, stacked-panes, url-scheme) grep for 'Gtk-CRITICAL' or '-(CRITICAL|WARNING) **', which never match that form, so they pass over real criticals (T3665 found five per window teardown in cli-undo.sh that way, now T3802). Fix: one shared hl_ helper in test/linux/lib/headless.sh that matches the real form (CRITICAL and WARNING from any domain), every harness uses it, and a negative control proves it scores a planted critical red.
