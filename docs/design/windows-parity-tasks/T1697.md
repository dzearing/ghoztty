# T1697 - The harness floor reports a stale zig-out as three RED audits instead of saying rebuild

## Summary

On 2026-09-23 (T921) floor-lane -Lane harness went 3 RED: persistence-flag, caller-anchor, build-mode-guard. All three were BuildMode stale-build refusals ('say so explicitly: GHOZTTY_TEST_ALLOW_STALE') or a stale-dependent arm (build-mode-guard F3). They passed alone after a Debug rebuild, and the floor's 'reproduced alone' line called them harness defects. Fix: the floor should check zig-out freshness once up front and either rebuild or report a single STALE BUILD verdict, not per-audit REDs.

## In plain terms

When the test build was out of date, the harness sweep used to run anyway and
report three unrelated-looking failures, sending a turn chasing defects that
were really just "rebuild first". Now the sweep checks the build once before
anything runs: it rebuilds it, or stops with one line that says to rebuild.

## Goals

- [x] a stale zig-out is settled once, before any audit runs
- [x] a stale build under -NoRebuild is one STALE verdict, not per-audit reds
