# T2504 - translucent-window.ps1 B and F read see-through 0 on the input desktop while a photo of the same build at background-opacity 0.85 shows the desktop through every pane (oracle broken, with or without GHOZTTY_PANE_LAYER)

## In plain terms

The test that checks see-through windows says the desktop never shows through, but a screenshot of the same build shows it plainly does. The test is wrong, so it can neither catch a real translucency break nor confirm a fix.

## Summary

2026-10-30 ~05:00, user away (Get-UserPresence Present=False), debug build db2584174: `test\win32\translucent-window.ps1` -> 2 FAILURE(S) (9 passed), identically with and without `GHOZTTY_PANE_LAYER=1`:

- `FAIL B: the terminal background shows the backdrop through (see-through 0 >= 30)`
- `FAIL F: toggled back, the background is translucent again (see-through 0)`

A/C/D/E/G pass (glyphs exact, caption opaque). A CopyFromScreen photo of a zig-out window at `--background-opacity=0.85` (T2502 scratch, `look-translucent\05a-three-panes.png`) shows the desktop through all three panes. Its guard was last stamped 2026-09-27 over a game (T1808), so it has likely never been verified green on a clear screen. Suspects: the WinForms backdrop is not actually behind the app window (z-order / topmost - in the same session another scratch script's topmost SetWindowPos also failed to raise a zig-out window over the installed app), or the see-through sampler's colour tolerance.

## Root cause and fix (2026-11-26, lane b)

T2342 (801963c44d, 2026-10-27) made new windows open maximized. The script's
config never set `maximize = false`, so its `SetWindowPos` hit a maximized
window. The lower-half background rect then sat outside the backdrop, on the
unchanging desktop, so B/F read exactly 0 while A/C/E passed vacuously.
That fits the dates: last green stamp 2026-09-27, T2342 2026-10-27, red
2026-10-30. `background-blur.ps1` copies the same setup and has the same
latent false red. Both scripts now set `maximize = false`, retry the
topmost promotion until `WS_EX_TOPMOST` reads back (T3609), and stop with
`SETUP FAIL` instead of measuring when the window is maximized, not
topmost, or any sampled rect is outside the backdrop. Checked so far: both
parse, both are ASCII-only, and their C# compiles. The live run has NOT RUN,
because both are `@input-desktop-exception` scripts.
