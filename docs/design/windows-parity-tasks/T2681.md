# T2681 - Settings curated rows: native controls for sliders, steppers, sizes in MB, colors, shell-integration flags, and shell/folder pickers (those rows edit their value as text today)

## Summary

Follow-up of T2585. `settings_pages.zig` carries Mac's control for every curated row, but only `toggle`, `picker` and `segmented` are drawn as controls; the rest fall back to the All Settings text field (validated, so nothing invalid is written, but not Mac's experience):

- `slider` (Dim unfocused panes - Mac shows 1 - value as a percentage -, Carousel width), `stepper` (Stack panes narrower/shorter than, with the unit), `megabytes` (Scrollback size, bytes shown as MB), `color` (Dimming color, Divider color, with the "Background"/"Automatic" unset label), `flags` (shell-integration-features as checkboxes), `shell` (an existing-executable check, Windows shell flavors), `folder` (a folder picker for working-directory), `text` keeps its placeholder.

Each control writes through `SettingsModel` like the rest; `ipc_settings` gets a way to drive each (set already covers the value path). Extend `test/win32/settings-window.ps1`.

## In plain terms

On Windows, several Settings rows - how much to dim inactive panes, the
scrollback size, cursor and divider colors, the shell to run, the folder new
windows start in, and the shell-integration features - were plain text boxes
where you had to type the raw config value. They now look and work like the
Mac's: a slider with a percentage, a number box with up/down arrows and its
unit, megabytes instead of bytes, a color swatch that opens the Windows color
picker, checkboxes, and menus that list the installed shells and offer the
Windows folder picker.

## Goals

- [x] sliders (Dim unfocused panes as 1 - opacity in %, cursor/background opacity, Carousel width) drag and write once on release
- [x] steppers (font size, padding, Stack panes narrower/shorter than) with arrows, unit and a range-checked field
- [x] Scrollback size read and typed in MB, written in bytes
- [x] color rows: a well opening the system color dialog, the unset default's name, "Use <default>" to clear it
- [x] shell-integration features as checkboxes, every flag written explicitly
- [x] Shell / Shell for scripted windows: default, installed Windows shells, Other... (checked on PATH before it is written)
- [x] Start new windows in: Home folder / Where Ghoztty was launched / the chosen folder / Choose Folder... (the Windows folder picker)

## Validation criteria

- [x] each control kind draws as its control and writes the same value text the parser accepts - settings-window.ps1 section L (28 assertions: slide/step/set/flag/color/shell/choose ops each check the config file's line), plus the painted hits per kind (slider track, color well + Use link, one checkbox per flag, both popups); screenshots of Appearance and Terminal inspected by eye (well, sliders, steppers, MB field, checkbox grid, popups)
- [x] the slider for unfocused-split-opacity shows the inverted percentage - L: default 0.7 reads 30%; a release at 0.62 writes 0.6 and reads 40%
- [x] scrollback-limit reads and writes in MB - L: default reads 10; typing 25 writes 25000000; 5000 refused with Mac's "Enter a size in megabytes, 0 to 4096"
- [x] settings-window.ps1 green with assertions per control kind - acceptance-parallel run: ALL PASS (131 assertions); settings_controls.zig unit tests 7/7

## Not done here (by design)

- Mac's font picker (`.font`) is not part of this task; the row still edits `font-family` as its list (settings_pages.zig header).
- The folder and color dialogs are modal system dialogs the seam cannot drive; the seam drives the function each dialog's result calls (`chooseValue` / `applyColor`).
