# T2078 - activity-truncated C and activity-help-tooltips E go red beside other scripts: the machine's process count crosses the Activity Monitor row cap mid-check, so the 'table was capped' badge appears in a negative control

## Summary

Found by T1114's 48-script width-4 slice (2026-10-18, run 20261018-033654). Both pass alone and fail beside other workers. activity-truncated C reads the panel's state line (Total under the row cap, so it runs the negative control), then Find-Badge sees 'The agent capped the process table; some rows are not shown.' The process count crossed the cap between the two reads because the parallel workers spawn processes. activity-help-tooltips E ('the empty badge slot and the table derive no tooltip') is the same badge turning up. Fix: decide the negative control from the SAME snapshot the badge comes from (or skip when Total is within a margin of the cap), and don't mark the scripts @parallel-unsafe, because that only hides the race.
