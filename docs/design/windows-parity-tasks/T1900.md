# T1900 - In the elevated look the Windows tab strip should start at the pane sidebar's edge with the sidebar running up beside it, one 10pt gap above the panes, and a banner's corners should be concentric with its pane's

## Summary

main 3ac40dc8b (layout half). Mac elevated style: the tab bar starts at the pane sidebar's edge, the sidebar reaches up beside the tabs (runs the window's height), the tabs sit one 10pt gap above the panes, and the DEBUG build warning is a titlebar row above both. The banner card's corner radius is max(4, paneRadius - outerMargin) so it is concentric with the elevated pane instead of the shared 14pt card radius. No parity owed for the rest of the commit: the rearrange-mode NSWindow tab-bar preference leak is AppKit persistence Windows does not have (one tab = no strip since T234, and rearrange mode's forced strip is not persisted), and the busy border is T1899. Check whether a Windows debug build shows any build warning row at all.

## In plain terms

In the default look with more than one tab, the Mac puts the tabs to the
right of the pane list on the left, and lets that list run all the way up
the side of the window beside them. On Windows the tabs ran across the full
width and the pane list started underneath them. Now Windows matches: the
list runs up the window's side, the tabs start at its edge, and the strip
of title bar above the list still drags the window. The small status card
that floats in a pane also gets tighter corners, matching the rounded pane
it sits in rather than looking like a separate rounder card.

## Goals

- [x] With glass panes and a tab strip showing, the pane sidebar starts at the window's top and its card runs up beside the tabs, its rows where they were
- [x] The tab strip starts at the sidebar's edge and follows it (rail, pinned panel, hidden)
- [x] The title-bar stretch beside the tabs still drags and double-click-maximizes the window
- [x] The tabs sit one 10 DIP gap above the panes
- [x] A banner card inside an elevated pane has Mac's concentric corner, max(4, 11 - 12) = 4 DIP
- [x] Solid panes, the flat style, one tab (no strip) and hero tabs keep the old layout

## Decisions recorded

- **Debug build warning row: none owed.** Mac moved its "debug build"
  warning strip into a titlebar row above the tabs and sidebar. Windows has
  no such row - a debug build announces itself through the T43 marker (the
  " [DEBUG]" title suffix on the window and taskbar, plus the chrome tint) -
  so there is nothing to reposition.
- **The strip's x space stays the client's.** The layout module still lays
  the run out from x = 0 in the width beside the sidebar, and the window
  shifts the results (`tab_strip_layout.shiftX`), so every hit test and
  published region follows without translating a single mouse coordinate.
- **Up beside the strip the sidebar only draws** (Mac: "the titlebar owns
  every click in that strip"): its WM_NCHITTEST answers HTTRANSPARENT there
  and the caption hit test (`caption_layout.ncHitTestBeside`) treats the
  band left of the tabs as caption, with the top resize edge intact.
- **Only with glass panes**, as on Mac (`fullSizeContentView`): without the
  desk under the chrome nothing could fill the strip left of the tabs.
