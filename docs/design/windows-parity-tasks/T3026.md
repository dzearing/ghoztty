# T3026 - PA-I12: a kernel event is created and closed for every pipe read and write on the agent link and the CLI pipe (pipe_stream.zig:251, :278; ipc_client.zig:189)

## Summary

PA-I12 (audit-1, T2962). src/remote/pipe_stream.zig:251-252 and :278-279 `const ev = try overlappedEvent(); defer W.CloseHandle(ev);` per readImpl/writeImpl; ipc_client.zig:189-195 does the same on the CLI side. Used by the app<->agent link and the agent<->holder link. Cost (arithmetic): 2 extra syscalls per I/O; at the ~8,700 frames/s burst recorded in T1464, ~35k extra syscalls/s across the holder writer and agent reader. Fix: one cached read event and one write event per Stream; reads are single-threaded and writes are serialised (client_mux out_mutex :170, agent write_mutex, single holder writer); check the HELLO-then-writer handoff and the comment at pipe_stream.zig:199-201 before relying on that. Risk low. Shared file but Windows-only code. Findings: docs/design/perf-audit/audit-1/I-findings.md.

## Validation criteria

- [ ] under a 64 MB flood on an agent-backed pane, CreateEventW calls in agent and holder are O(connections), not O(frames) (counter or ETW)
- [ ] zig build test-agent and the pipe_stream unit tests green
