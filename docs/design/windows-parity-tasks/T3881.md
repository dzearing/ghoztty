## In plain terms

The performance report said opening three document panes now costs the app
about 50 MB of memory instead of 6 MB. It does not: the measuring script
changed between the two reports and started counting a terminal tab it opens
and closes first. Measured the same way as before, the cost is about 10 MB
(release) and 6 MB (debug), within the report's tolerance. The report and the
comparison tool are corrected so the old and new numbers are compared fairly.

- [x] make `-Compare` score like against like across the definition change
- [x] correct audit-5 and the perf-audit README

## Root cause

Not a code regression. T3169 (7c44aa9eca, landed after baseline-4's
424c9e5ab - `git merge-base --is-ancestor` says it is not in baseline-4)
added a terminal CONTROL tab opened and closed between the viewer phase's
`base` and its three viewers, and kept `viewer.open.growth` as
`open - base`. In baseline-5 that tab's residue (`viewer.control.leak`:
40.0 MB, 53 handles, 11 USER, 6 threads; debug 41.4 MB) is inside the growth
number, which is the entire gap (50.4 - 40.0 = 10.4). The like-for-like
figure, `viewer.open.growth_vs_warm` (open - warm_base), is release
10.4 MB / 134 handles / 47 USER / 9 threads and debug 6.3 MB / 134 / 47 / 9,
against baseline-4's 6.0 / 132 / 45 / 10 and 8.2 / 136 / 46 / 11. Every one
is within `-Compare`'s tolerance (mb +-5, handles +-30, objects +-10,
threads +-3). No bisect was needed: the attribution block names it.

Fix: `scripts\perf-baseline.ps1 -Compare` now detects a build in `a` with no
`viewer.control` and a `b` carrying `growth_vs_warm`, scores `a`'s
`viewer.open.growth.*` against `b`'s `growth_vs_warm.*` (row tagged
`vs b.growth_vs_warm`), and prints a `DEFINITION CHANGED` line. Two post-T3169
documents still compare growth against growth.
