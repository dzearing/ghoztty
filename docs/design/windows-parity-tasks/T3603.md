# T3603 - Linux image pane copy: a phone photo's EXIF orientation may not be applied, so Ctrl+C can paste it sideways

## Summary

T3534's copy decodes the file with gdk_texture_new_from_filename, which hands back the pixels as STORED; WebKit applies the JPEG's EXIF Orientation tag when it draws the pane, so a portrait phone photo shows upright and may paste rotated. win32 fixed the same shape in T1910 (image_clipboard.Orientation + orient, pure). Verify with an oriented JPEG fixture (Orientation=6) in test/linux/viewer-image.sh: copy and read the texture back; if it comes back WxH un-swapped, read the tag (gdk_pixbuf apply_embedded_orientation, or a small pure EXIF reader feeding win32's orient) before the texture goes on the clipboard.
