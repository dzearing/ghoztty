# T1631 - The teardown sweep for an unclaimed crash does not wait for WER, so a crash in the last seconds of a run leaves no stack

## Summary

T809 gave Remove-TestDesktop a sweep for a dump one of our exes left that no launch record accounts for - the app +new-window auto-spawned, above all. It calls Find-WerCrashDump with WaitSeconds 0 on purpose: a sweep that idles per exe on every clean run would tax the 99 percent case. The cost is the other end: WER finishes writing the file a beat AFTER the process disappears, so an app that died in the last second or two of a script has its dump land just after the sweep looked, and the run that made the crash still reports nothing. The per-pid path does not have this problem (it waits 10s, and only when the exit code already says a crash). Wanted: a wait that is paid only when there is reason to think a crash happened - a ghoztty.exe that was alive earlier in the run and is gone now, or an Application Error record for one of our exes since the run started - so the common clean teardown stays free.
