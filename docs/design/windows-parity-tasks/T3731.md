# T3731 - Close-survival harnesses written before T1874 read 'the app survived' while the closed tree is still parked for undo, so they never watch the release

## Summary

T2245 found viewer-close.ps1 launching with the default 5s undo-timeout: since T1825/T1874 a closed pane/tab/window is parked and its tree released only when the undo expires, after the script had already read its survival checks. It now launches with --undo-timeout=0. Sweep test\win32 for other harnesses whose subject is a crash or leak ON CLOSE (pane-close-memory, close-overlays already sets 20s on purpose, tree/teardown/webview harnesses) and that launch without --undo-timeout, and either set it to 0 or wait past the expiry before asserting. Each converted script must show the release actually happened (a destroyed HWND or a release log line), not just survival.
