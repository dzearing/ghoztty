# T1337 - Pressing next-change at the end of a diff file stops there instead of moving to the next file

## Summary

diff.js posts diffNavOverflow when next/previous-change runs off the end of the file on screen, so the native side can open the adjacent file and continue. Nothing under src/apprt/win32 handles that message, so navigation dead-ends at every file boundary. The file tree T464 built is the list to step through.

## In plain terms

In a diff pane showing many files, pressing "next change" after the last
change in a file should carry you into the next file, the way it does on Mac.
This was filed as broken, but it already works: the fix arrived with the
change-navigation buttons themselves, before anyone re-checked this card.

- [x] previous-change at the top of a file opens the previous file, entered at its end (same commit)
