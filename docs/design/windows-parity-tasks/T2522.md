# T2522 - Pace window-edge resize steps to the compositor: once the layout pass fits in a frame, each SetWindowPos must land just after a DWM compose so the pass has a whole frame before the new frame size is shown (T2516)

## Summary

T2516's film + GHOZTTY_RESIZE_TRACE (2026-10-30) shows DWM puts a resized frame on screen at the first compose after the SetWindowPos, whatever the app has painted, and WM_SIZE arrives ~1 ms after NCCALCSIZE on the window's own thread. So a pass shorter than the frame interval still shows stale content whenever the SWP lands late in the interval. Try DwmFlush (or waiting on the frame clock) in WM_WINDOWPOSCHANGING/WM_SIZING while a live resize is on and the size changes, so the step starts right after a compose; measure with resize-sync-onscreen.ps1 (async steps) at ReleaseSafe. Only worth doing after the pass fits a frame (the desk and nav tasks filed beside this). The complete fix is all content in one composition commit (T2508-T2511).
