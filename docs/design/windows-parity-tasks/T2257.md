# T2257 - A side pane opened without focus into a row with no room is born a minimized strip on Windows; Mac features it on show and makes the caller the strip, keeping the caret (main 71da9a680 PaneStackState.featured)

## Summary

Split from T2250 (main 71da9a680). On the Mac a pane opened BESIDE the one with the caret without taking it (an agent's `+split --view`, a banner link's side pane) is FEATURED (`PaneStackState.featured`, ranked ahead of the focused pane in `ranks`): it comes on show, other panes minimize to make room, and when even that is not enough the focused pane becomes the strip and KEEPS the caret. Cleared by the next change of focus. On Windows `pane_stack_state.zig` has no featured notion, so a non-focusing split (`split_background`) into a full row is born tucked; since T2250 the `+split` reply at least says so (`; it is minimized to a strip ...`).

Port: a `featured` id on `PaneStackState` (set by `newSplitAt`/`newViewerSplitAt` when `split_background`), outranking recency in the layout provider's ranks, honoured by `bringOnShow` after the focus in `rowsDidChange`, cleared by `noteFocus` of a different pane. Mac tests to mirror: `aSidePaneOpenedWithoutFocusComesOnShow`, `aSidePaneInARowWithRoomForOneTakesItAndTheCallerKeepsTheCaret`, `aSidePaneOpenedWhileTheWindowIsCoveredIsThereWhenUncovered`; docs/claude/cli.md Stacked panes names the rule.

## In plain terms

When an agent opened a document or page beside your terminal in a window
already full of panes, the new pane showed up only as a thin strip at the edge,
so it looked like nothing had opened. Now the new pane is what comes on
show; another pane folds into a strip to make room, and your typing stays where
it was. The Mac already worked this way.

## Goals

- [x] a side pane opened without focus into a full row is on show
- [x] the pane that had the caret keeps it, even if it has to fold to a strip
- [x] the next focus change returns the row to its normal focus-history order
