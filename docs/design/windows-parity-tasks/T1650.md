# T1650 - The soak-daemon acceptance run goes red whenever the REAL soak daemon is mid-round

## Summary

test\win32\soak-daemon.ps1 section D6 asserts the box reads IDLE after a resume, and the daemon's own foreground-work detector matches any powershell running floor-lane.ps1 or a test\win32 script. The PRODUCTION idle soak daemon (marker D:\ghoztty-idle-soak) is exactly that shape, so while a real round is in flight the acceptance run reports 1 FAILURE(S) for a box condition rather than for code - measured twice on 2026-09-18 during T1649, with the busy reason naming pid 52428 running the real daemon's none-lane round. The harness should exclude the production daemon's own tree (it is recognisable by its scratch marker, the same way the daemon recognises itself) or SKIP D when a real round is running, rather than scoring red. Worth fixing alongside: Assert() in that harness prints no detail on failure, so a red line names the assertion and nothing about why - which is what turned this into a twenty-minute detour.
