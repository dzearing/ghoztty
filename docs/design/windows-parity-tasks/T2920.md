# T2920 - capture-pane of a pane in a hidden window waits out its 5s timeout and fails with 'produced no frame' instead of saying the window is hidden

## Summary

Found in T2914: a capture asked of a pane whose window is covered is never answered (the renderer presents nothing while hidden), so the debug capture-pane action burns its full 5000ms and reports 'no frame to capture', which reads like a renderer defect. hidden-new-pane.ps1 had to sleep past the visibility poll before capturing. Fix shape: the IPC handler answers at once with 'window is hidden (covered|minimized|cloaked)' when the pane's window is occluded, or serves the capture on the first frame after reveal. Test lib: test/win32/lib/PaneCapture.ps1 should surface that reason.
