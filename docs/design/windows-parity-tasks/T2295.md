## Summary

T2284 lowered the pane minimum to 225 x 125 DIP (Mac afc64dc53). These harnesses choose window widths so that a row of panes stacks at the 300 DIP minimum; at 225 the same rows fit, nothing folds, and the assertions about strips, slides and folds see nothing (run 2026-10-25 on the T2284 build):

- `stack-fold-slide.ps1` - 9 failures, F4 "at rest two panes are on show (got 3)": the fold never happens.
- `stack-collapse-drag.ps1` - 5 failures.
- `pane-stack-slide.ps1`, `pane-stack-strip.ps1` - ASSERTED NOTHING (their precondition, a stacked row, never forms).
- `pane-stack-unfold.ps1` - ASSERTED NOTHING (found 2026-10-25 in the T2285 due sweep): "s2 never folded into a strip"; the root-divider drag leaves s1 at 281 px = 225 DIP at 125%, so the row still fits. Sixth member of the same shape.
- `pane-stack-focus.ps1` - ASSERTED NOTHING (same sweep): "the 900 DIP row never settled on two on show (got 3)" - P | (s1 | (s2 | s3)) at 900 DIP fits three at 225. Seventh member.

Fix: re-derive each harness's window size from the new minimum - one `$minDip = 225` per script, the way `pane-stack-grid.ps1` was re-derived in T2284 (claim B moved 900 -> 680 DIP) - so each row stacks again for the reason it states, and run each green. The guards are acked to this task (`guard-ack`) so the floor stays enforced elsewhere meanwhile.
