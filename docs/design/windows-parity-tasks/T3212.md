# T3212 - Window mode 'same window' set in Settings is ignored until a full quit: the resident instance stays latched to the old mode and forwarded new windows open separately

## Summary

User report 2026-11-17 08:24: set window mode to same window in Settings; new windows (a Start menu / taskbar launch forwarded to the running instance) kept opening as separate windows until the app was fully quit.

Root cause: `window_mode.latch` reads `macos-window-mode` once at `App.init` (the Mac `WindowMode` latch). The win32 app stays resident when its last window closes (`quit-after-last-window-closed` is off on Windows) and nothing on screen says so, so closing every window looks like quitting but never re-read the mode. Fix: the first terminal window opened while none is open re-reads it (`App.relatchWindowModeIfIdle` -> `window_mode.relatchIdle`), and the Settings hint names that boundary.

## In plain terms

Choosing "All in one window" in Settings did nothing you could see: new windows kept opening on their own until Ghoztty was killed outright. Now, once you close your windows, the next one you open comes up in the mode you chose, and every launch after it joins that one window.
