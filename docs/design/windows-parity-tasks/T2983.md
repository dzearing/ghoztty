# T2983 - PA-R17: a recycled pane window skips SetPixelFormat, so a window parked by a helper-path pane would give a later non-helper pane a formatless device context

## Summary

PA-R17 (audit-1, T2959; correctness hazard found during the perf audit, unverified in practice). apprt/win32/Surface.zig:1019: `if (shared == null and reused == null and !on_helper) try self.setupPixelFormat();` with the comment 'A parked window already has it'. A pane whose context went current on the hidden helper (on_helper) never set a format on its own HWND; if it is parked (pane_pool) and later reused by a pane whose helper creation failed, createContext runs on a formatless DC and fails. Fix: record on the parked window whether it has a pixel format (GetPixelFormat(hdc) != 0) and set one when missing. Risk low.
