# T3755 - Session restore brings each pane back on ITS shell and folder, including a WSL distro pane at its Linux cwd (T3735)

## Summary

Child of T3735. After a relaunch (agent gone) a pane opened with --shell=wsl:<distro> or a picker comes back on that distro at its last Linux cwd, a pwsh pane on pwsh, and so on - not on the default shell. Check what session-layout.json records today for the shell/argv and extend it additively. Acceptance: a restore test (non-WSL arm always; WSL arm opt-in).

## In plain terms

You can open a pane on a particular shell - Command Prompt, PowerShell, or one Linux distro - but when Ghoztty had to start those panes over after a restart, every one of them came back on the default shell. Now each pane comes back on the shell it was opened on, in the folder it was in; a Linux pane comes back in its distro, in the Linux folder you had `cd`'d to.

## Goals

- [x] the session layout records which shell a pane was opened on (`shell` on the leaf, additive)
- [x] a pane whose session is gone reopens on that shell, in its folder
- [x] a WSL distro pane reopens in that distro at its Linux folder (`wsl --cd`), `~` when the distro never reported one
- [x] a pane on the default shell, or running a command, records nothing and restores as before
