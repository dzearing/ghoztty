# T1860 - The desktop-launch audit does not see a GUI auto-launched through cmd /c: ipc-relay.ps1 opened its windows on the user's desktop and the audit stayed green

## Summary

Found in T1837 (2026-10-11): ipc-relay.ps1's Run-Cli ran Start-Process cmd.exe -ArgumentList '/c <exe> +new-window ...', which auto-launches the app on the USER's desktop, and DesktopLaunchAudit.ps1 only recognises Start-Process or call-operator launches of the exe itself. T1837 moved ipc-relay onto Invoke-OnTestDesktop; this task teaches the audit the cmd /c shape, sweeps test/win32 for other hits, and demonstrates the new rule goes red on a planted case.

## In plain terms

Our automated tests are supposed to open their windows on a hidden
background desktop, never on top of whatever you are doing. A checker
enforces that, but it could not see one common way of starting the app, so a
test threw four windows across your screen on every run and the checker said
all was well. Now the checker sees that way too, and the three other tests it
turned up open their windows out of sight.

## Goals

- [x] the audit recognises `cmd /c "...$Exe +new-window..."` and `Start-Process cmd.exe -ArgumentList "/c ..."`
- [x] a `Run-Cli($argsLine)` wrapper is scored at the calls that pass `+new-window`, not flagged wholesale
- [x] sweep test\win32 for other hits and resolve each
- [x] a planted case proves the new rule goes red
