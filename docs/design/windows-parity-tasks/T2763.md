# T2763 - Composition step 5d-3: the banner's glide and collapse run as compositor animations of the banner visual (T2559) - offset/clip declared once - instead of a GLIDE/COLLAPSE frame-clock tick that re-renders the band

## Summary

Narrowed on claim (2026-11-07) to the GLIDE half; the card's own collapse is
T2798. The two halves are different shapes: the glide moves one bitmap (the
frozen terminal copy) by an offset, which DirectComposition can run whole;
the collapse re-renders the card every frame (moving rounded bottom edge and
shadow, body dissolve, tail fade), which needs the card split into layered
visuals before any of it can be declared.

What landed: on the composition path the frozen copy's whole glide is one
offset-Y animation of its visual (`BannerFreeze.glideOnCompositor`), fitted to
the stepped glide's own ease (`banner_glide.easeF64`, 8 Hermite cubics over
`COLLAPSE_MS`) and started on the card's clock - the part of the 180 ms the
frame capture used is cut off with `comp_overlay.tailOf`, so the copy is
exactly as far along as the card. The geometry contract the summary asked to
settle: the band the tree's root hangs at is carried apart from the glide, as
the visual's transform shift (`Layer.setShiftY`), so when the renderer moves
the root to the new band mid-glide the copy holds its place in the window
with one static set, not a step, and the declared animation is untouched. The
grid band itself never relayouts per frame (it reserves the settled height
once, T149). The glide tick is now a plain timer that only watches for the
release (terminal landed and quiet); it no longer moves anything. The popup
path (composition off) is unchanged. Nearest-neighbour sampling keeps the
copy's text on whole pixels mid-move, as the stepped path's rounding did.

## In plain terms

When you click a multi-line banner to collapse or expand it, the terminal
underneath is briefly shown as a still picture that slides to its new place
while the banner moves. That slide used to be pushed along by the app sixty
times a second, so a busy app made it stutter. Now Windows' compositor is
handed the whole slide once and plays it smoothly by itself. The banner
card's own grow/shrink is still drawn by the app; that is the next step
(T2798).
