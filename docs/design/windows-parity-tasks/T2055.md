# T2055 - Four acceptance scripts count ghoztty processes by '*zig-out*' in the command line, so the other loop lane's app inflates their counts and fails them

## Summary

Found in T2053. auto-launch-cwd.ps1 (Count-TestProcs), gui-launch-command.ps1 (Count-TestProcs), new-window-cwd.ps1 (TestProcs) and layout-blob-cross-lineage.ps1 (B1 'nothing from zig-out is still running') select processes by CommandLine -like '*zig-out*'. They kill nothing (the cleanslate audit's new cross-lane-kill rule covers kills), but with lane B running a debug app from D:\git\ghoztty-b\zig-out the counts include it and the asserts go red for a reason that is not the code. Switch them to ExecutablePath -eq the exe under test (or Get-RepoGhozttyProcess), and consider extending CleanSlateAudit to flag a cross-lane COUNT feeding an Assert.

## In plain terms

Some automated tests counted "how many copies of the terminal are running" by
looking for any copy built from a dev folder. With two work lanes on this box,
the other lane's copy was counted too, so tests failed for no real reason. One
test also shut down any matching helper program, including the other lane's.
Now each test counts and stops only the exact program it launched.
