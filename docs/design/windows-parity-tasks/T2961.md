## In plain terms

Ghoztty on Windows uses a lot of memory per pane and keeps much of it after the panes close. This task looked for where that memory goes and whether anything leaks. Nothing we allocate leaks on close. Most of what stays behind is graphics-driver memory and thread stacks, which other tasks already cover. The audit found large picture buffers that are kept at their largest size, and scrollback that is never given back. Each is now its own queued fix.
