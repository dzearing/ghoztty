# T1761 - Machine chooser's Activity button reads 'Activity' packed beside New Window; Mac shows 'See Activity' right-aligned apart from the other actions

## Summary

Mac's detail header (MachineChooserView.swift ~L560-577) puts a Spacer before seeActivityButton, labelled 'See Activity' with a chart.bar.xaxis icon, so it sits right-aligned and away from New Window/Restore All ('grouping it with the buttons that do invites misclicks'). The win32 chooser packs a button captioned 'Activity' into the same run as New Window (chooser_layout.actionRow, ACTIVITY_LABEL in src/apprt/win32/MachineChooser.zig). Found while landing T1747. Fix: caption 'See Activity' and place it at the trailing edge of the detail header, before the '...' menu; update chooser-menu.ps1 section 1b/1a row-order assertions and the actionRow packing tests.

## In plain terms

In the machine chooser, the button that opens the Activity view says just
"Activity" and sits right next to "New Window", so it is easy to click the wrong
one. On the Mac it says "See Activity" and sits on the far right, apart from
the buttons that open windows. After this, Windows looks and reads the same.

## Goals

- [x] the button reads "See Activity"
- [x] it sits at the right edge of the action row (beside the `...` menu on a remote machine), with the free space between it and New Window / Restore All
- [x] a crowded row still never overlaps or leaves the pane
