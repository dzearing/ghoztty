# T1521 - A comment-only edit to a test script makes every guard covering it due again

## In plain terms

Several of our automated checks remember "somebody ran me against the code as it
looks right now". Adding a COMMENT to a test script counts as changing it, so a
pass that only writes explanations into twenty-five scripts makes two dozen
unrelated checks say they need to be run again - hours of GUI runs that cannot
possibly discover anything, because not one executable line moved. The pressure
that creates is the problem: the cheapest way past it is the override switch,
and an override used routinely is a check nobody reads.

## Summary

`scripts\guard-due.ps1` decides a guard is due by comparing a NORMALIZED HASH of
every covered file (`Get-NormalizedFileHash`: CRLF folded, BOM dropped) against
the hash the last green run stamped. Any byte difference is a difference, so a
`# persistence: ...` line added to a script makes every guard whose `Covers`
glob includes it due.

T1012 hit this at full force: declaring the persistence intent of 49 launch
sites touched 25 files under `test\win32`, and `guard-due.ps1 check` went from
all-current to **27 DUE** - agent-autostart, holder-*, startup-failure,
install-restart, update-real-msi, suite-run and the rest - none of which could
have been affected, since apart from two flag additions (`chooser-selection.ps1`,
`remote-reconnect-relay.ps1`) every edit was a comment. The commit was made with
`-NoGuardDue` naming this task, which is exactly the habit T783 built the gate
to prevent.

## Details

The honest fix is to ask the question the stamp exists to ask: has anything that
RUNS changed? For `.ps1` that means hashing the file with comment lines and
trailing `# ...` comments removed - the suite already has that transform, in
`test\win32\lib\PersistenceSweep.ps1` (`Remove-PsLineComment`), and it is the
same normalisation the sweep uses to read launch statements.

Care is needed in three places, and each wants a demonstration in
`test\win32\gate-negatives.ps1` or a fixture in the guard's own harness:

- a `#` inside a single- or double-quoted string is not a comment, and a here-
  string's body is not code;
- a comment that is LOAD-BEARING must still count: `# cleanslate-exempt:`,
  `# persistence:`, `# stderr:` and `# preflight:` markers are read by sweeps,
  so a change to one of those lines genuinely changes what a sweep concludes.
  The cheapest correct rule is "strip comments EXCEPT the marker lines the
  sweeps read", which keeps T1012's own edits due for the sweeps that read them
  (persistence-flag, stderr-launch-capture) and current for everything else;
- `.zig`/`.md` covered files keep byte-exact hashing; this is a `.ps1` rule.

## Validation criteria

- [ ] A comment added to a `test\win32\*.ps1` leaves every guard covering it
      CURRENT, except the sweeps that read marker comments.
- [ ] A one-character change to executable text in the same file makes those
      guards DUE (the negative control - the rule must still be able to fire).
- [ ] A `#` inside a string, and a here-string body, are not treated as comments
      (fixture in the guard's own harness).
- [ ] `powershell -NoProfile -File test\win32\gate-negatives.ps1` stays ALL PASS
      with the new condition demonstrated.
