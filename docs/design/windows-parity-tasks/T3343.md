# T3343 - Linux L14: packaging and ghoztty:// registration on Linux

## Summary

Start with a tarball and an install script for WSL, then .deb/AppImage. Register the ghoztty:// scheme with a .desktop file (MimeType=x-scheme-handler/ghoztty) plus xdg-mime default. The install must never collide with a dev build's endpoints.

**Scope note (T3340, 2026-11-23):** this card owns the OS half of
docs/reference/url-scheme.md, which is registering the handler AND the
running/launched GTK app receiving `ghoztty://focus/<target>` from outside
(GApplication open / activation) and raising that pane. In-app links (viewer, banner) are
already done in T3415.

**Split (2026-11-23):** the .deb/AppImage half, and building + installing a

## In plain terms

On Linux there was no way to install Ghoztty as an app, and a `ghoztty://`
link clicked in a browser or a document went nowhere. Now the Linux build
packs into a tarball whose install script puts Ghoztty in your menu and makes
it the handler for those links; clicking one jumps to the named window or
pane, and a link to something that is gone says so instead of doing nothing.

## Goals

- [x] the desktop entry, D-Bus service and systemd unit launch the binary the build actually produces (`ghoztty`, not upstream's `ghostty`), named Ghoztty
- [x] the desktop entry registers `x-scheme-handler/ghoztty` (`ghoztty-debug` for a debug build)
- [x] a link handed to the running app over D-Bus `Open` focuses its target
- [x] a link on the `Exec` line (`ghoztty <url>`) forwards a focus and exits with win32's codes, never launching a terminal
- [x] a miss shows the shared "Can't focus" wording, one dialog per burst
- [x] a tarball (`scripts/linux/package.sh`) and an install script that installs, sets the default handler, refuses a Debug package without `--dev`, and uninstalls
- [ ] .deb / AppImage, and a release package installed end to end - T3578
