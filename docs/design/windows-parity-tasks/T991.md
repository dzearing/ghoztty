# T991 - The agent's own fixed-buffer UTF-16 readers have never been measured

## In plain terms

The background service that keeps your terminal sessions alive reads names off
Windows — this machine's name, a process's path, another session's window title
— into buffers of a fixed size. If one of those is longer than the buffer, the
service can die, and every persistent session dies with it. Nothing has ever
checked how long those names are allowed to be.

## Summary

T990 converted every fixed-buffer `std.unicode.utf16LeToUtf8` reader in
`src/apprt/win32/` onto the bounded helpers. `src/remote/agent/` was out of
that task's scope and still has the same shape in at least six places.

## Details

`std.unicode.utf16LeToUtf8` does not bounds-check its destination — its error
set covers malformed UTF-16 only — so a `catch` at one of these call sites is
not the overflow guard it reads as. Each site needs its source length compared
against what its caller passes, and converting them is cheaper than deciding
which are safe:

- `single_instance.zig:360` (a SID string into the caller's `buf`), `:371`
  (a window/mutex name), `:809` (`[..]u16` into `buf8`)
- `foreground.zig:132`, the foreground window's class/process name into
  `name_buf`
- `holder_adopt.zig:346`, a handle name into `name_buf`
- `main.zig:2305`, `GetComputerNameExW` into the caller's `out` — the same
  function T990 fixed as `ShareMachineRow.hostName`

The helper is `src/apprt/win32/utf16_text.zig` (`toUtf8Truncating` /
`toUtf8AllOrNothing` / `toUtf8Counting`), which has no OS imports and runs in
every lane. It lives under `apprt/win32/` because that is where its callers
were; the agent is a separate binary and importing across that boundary is the
first design question here — move it to a shared home (`src/os/`?) or give the
agent its own. Whichever way, ONE implementation: two copies of a bounds rule
is how the second one rots.

Pick the same semantics per site that T990 did: a name or path is
all-or-nothing (half a machine name is a different machine), a label or a log
line truncates.

## What landed

All seven fixed-destination readers in `src/remote/agent/` now go through
`utf16_text.toUtf8AllOrNothing` — every one of them reads an identity (a SID,
a user name, a host name, a pipe name, a process image path), where half a
name is a different thing. Two were measured-and-safe already (the foreground
process basename, 260 units into 780 bytes; the single-instance image probe,
1024 into 3072) and go through the helper anyway so the measurement lives in
one place. The one that was a **reachable crash** was the holder sweep
(`holder_adopt.enumeratePipes`): it read every pipe name on the box — anybody's,
up to 256 units — into 512 bytes, so any process that bound a long enough
non-ASCII pipe name took the agent and every persistent session down at its
next sweep. That decode is now the pure `holderFromEnumerated`, unit-tested
with a 260-unit CJK name.

`main.hostName` was a second copy of `enroll.hostName` that read 256 units
into 256-byte buffers; it is now an alias of the enrollment one, so the name
the HELLO advertises and the name enrollment registers cannot drift apart.

**Where the helper lives** (the design question): it stays at
`src/apprt/win32/utf16_text.zig` and the agent imports it by relative path,
the way `handoff.zig` already imports `apprt/win32/job_spawn.zig`. Moving it to
`src/os/` would have been the tidier address, but it would re-point twenty app
imports and invalidate every guard stamp that lists them, for no change in
behavior; the module doc now says both binaries depend on it, and the agent
lane runs its tests (`main.zig` test block).

Out of scope, filed: `src/renderer/gl_loader.zig:387` has the same shape in the
app's OpenGL loader (T1767).

## Goals

- [x] Every fixed-buffer UTF-16 → UTF-8 reader in `src/remote/agent/` either
      calls the bounded helper or has a measured destination and says so
- [x] One implementation of the helper, reachable from both binaries
- [x] The stale "returns 0 when it does not fit" style comments say what the
      code now does

## Validation criteria

- [x] A unit test in the agent lane converts a source longer than the
      destination and gets a bounded answer rather than a panic —
      `holderFromEnumerated` test in `holder_adopt.zig` (260-unit CJK and
      600-unit ASCII names into 512 bytes answer null; a real holder still
      matches), plus `utf16_text.zig`'s own suite now referenced from the agent
      lane's test root
- [x] A grep for `utf16LeToUtf8(` over `src/remote/agent/` returns only the
      allocating form and call sites with a measured destination — it returns
      nothing at all; every fixed-buffer site calls the helper
- [x] Floor lanes lib/none/win32/agent ALL PASS (`floor-lane.ps1 -Lane all`,
      2026-09-26), ipc-p1/p2/p3 ALL PASS, and the 14 harnesses the change made
      due green and re-stamped (holder-adopt, agent-first-answer,
      session-relaunch-notify, machine-chooser, agent-sharing-uplink,
      agent-relay-session-e2e, one-installer, window-active, printclient,
