# T1536 - A pane drag says nothing about itself: no drag cursor and no mark on the pane being moved

## Summary

T1531 landed the drag and the drop preview, but the gesture gives no feedback about its SOURCE. The cursor stays an arrow for the whole drag (nothing answers WM_SETCURSOR while rearrange_drag is live), and the pane being carried looks exactly like the panes that are staying put - so in a four-pane window, a user who looks away mid-drag cannot tell which pane is in their hand. Mac's rearrange mode marks the dragged pane and changes the cursor. Two small arms on state that already exists: a WM_SETCURSOR arm in Window.zig's wndproc keyed on rearrange_drag, and a dimmed / outlined treatment for the source pane's header while its drag is active (the header paint already knows which view it is drawing). Validation is the existing rearrange-drag.ps1 shape plus a cursor-handle assertion.
