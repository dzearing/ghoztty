# T1511 - The 79 acceptance scripts that stamp a guard move onto the shared scorer, so an unwound run stops recording the files as proven

## In plain terms

When one of our test scripts finishes cleanly it leaves a note saying "this
feature was proven against the code as it stands now", and that note is what
stops the loop being nagged to run it again. Seventy-nine of those scripts leave
the note even when the run crashed halfway - so a feature nobody actually tested
gets recorded as tested, and stays that way until somebody edits the code again.
After this lands, only a run that reached its own end leaves the note.

## Summary

T1039 gated the stamp on body completion, and it gated it in the right place:
`scripts\guard-due.ps1 update` runs as a CHILD of the harness and refuses to
write while the inherited `GHOZTTY_TEST_BODY` reads `pending`. What publishes
that variable is the dot-source of `test\win32\lib\TestScore.ps1`, so a script
that never dot-sources it publishes nothing and the child stamps
unconditionally.

T1510 measured the set and put it under a ratchet: `unarmed-stamp` in
`lib\AssertedNothingAudit.ps1`, counted by section C5 of
`test\win32\asserted-nothing.ps1`, which stood at **79** when this was filed.
This task burns that number down to zero. It is the higher-value half of the
conversion because the damage outlasts the run - a red line scrolls away, a
stamp keeps a guard quiet until the covered files change again.

## Direction

Per script, the conversion is three lines, and
`test\win32\viewer-feedback-capture.ps1` is the worked example (T1510's commit):

- dot-source `lib\TestScore.ps1` with the other libs at the top - that alone is
  what ARMS the run;
- `Complete-TestBody` as the last statement the run reaches before the stamp,
  and a top-level `try` with no `catch` either ends in it or grows a `catch`
  that SCORES the throw (`lib\BodyCompleteAudit.ps1` decides which, and it is
  already a hard-zero sweep, so a conversion that gets this wrong goes red);
- the final `if ($script:fail -eq 0) { "ALL PASS ..." } else { ... }` becomes
  one `Write-TestVerdict -Pass ... -Fail ... -Label '...'` call.

Lower C5's ceiling in `asserted-nothing.ps1` as each batch lands - never raise
it. When it reaches 0, add `unarmed-stamp` to `Get-AssertedNothingHardKinds` so
a new script cannot reintroduce one.

Batch them: each converted script must be RUN green on the box, and many of
these are GUI acceptance scripts that take minutes. Several batches, several
turns, is the shape.

## Validation criteria

- [ ] `test\win32\asserted-nothing.ps1` reports 0 `unarmed-stamp` scripts.
- [ ] `unarmed-stamp` is in `Get-AssertedNothingHardKinds`, and `-TeethCheck`
      still goes red on a synthesized violator.
- [ ] `lib\BodyCompleteAudit.ps1`'s sweep is still at zero findings over the
      whole suite - the conversion brings every one of these files into its
      scope for the first time.
- [ ] Every converted script was run on the box and ended green, with its own
      guard stamped by that run.
- [ ] The P1-P3 floor and the four zig lanes still pass.
