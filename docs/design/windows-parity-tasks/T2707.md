# T2707 - Text at the bottom of a pane shifts by a few pixels as its banner expands or collapses; Mac now starts the terminal on a whole row under the banner card

## In plain terms

When a pane's banner opens or closes, the text resting on the pane's last line
(a shell prompt, Claude's input box) can jump up or down by a few pixels each
time. The Mac just fixed that by lining the terminal up on whole rows under the
banner. This checks Windows for the same wobble and fixes it the same way.

## Summary

main intake 2026-11-04, from db09fe480 (`fix(macos): text at the bottom of a
pane holds still as its banner toggles`, `SurfaceView.swift`,
`docs/reference/banners.md`, test `BannerCollapseWindowTests`):

The grid fills from the top, so a banner inset that took part of a row moved
the last row: bottom-hugging text rested a few pixels lower or higher with each
banner height. Mac now starts the terminal on a whole row under the card.

Windows: `src/apprt/win32/BannerOverlay.zig` (`insetHeight`, `inset`,
~lines 700-830) decides how far the surface moves down. Measure the bottom
row's y with the banner expanded vs collapsed; if it differs by a non-zero
amount other than a whole number of rows, round the inset to whole cells the
way Mac does. Read the new section of `docs/reference/banners.md` on main
for the exact rule.
