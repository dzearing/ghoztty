# T1877 - The pane sidebar's all-windows scope has no search field on Windows: Mac ANDs terms over window, pane, banner and folder, Return reveals the first hit, Escape clears

## Summary

Split from T1829. Mac's all-windows scope brings a search field under the
header (7855941f7, polish e898f5a00): whitespace-separated terms, ALL of which
must appear (case- and diacritic-insensitive) in the window's title, the pane's
title, its banner line, or its directory/location (shown and full). Only windows
with a hit are listed, and nothing is folded while searching (a hit inside a
folded group would read as no hit); "No matching panes" when empty. Return
reveals the first hit, Escape clears. An open hover card stays open while the
field has the caret. Switching the scope off clears the filter. The field reads
like a native search box and does not jump on focus.

The rules are already landed and unit-tested: `pane_sidebar_outline.terms` /
`matches` (ASCII case only - diacritic folding is part of this task). What is
missing is the field itself (a child EDIT in the panel / open card header band,
Windows 11 search-box look per docs/design/win32-design-system.md), filtering
`PaneSidebar.refreshAll`'s groups and panes, and the caret-holds-the-card rule.

## In plain terms

When the sidebar shows every window, there was no way to search it: with a
dozen windows open you had to scroll and read. Now a "Search" box sits under
the sidebar's header. Type a few words and only the panes that match all of
them stay listed - by window name, pane name, banner text or folder, ignoring
capitals and accents. Enter jumps to the first match, Escape clears the box.

## Goals

- [x] a search box under the header in the all-windows view, in the pinned panel and the hover card
- [x] typing filters by every word, accents and case ignored; "No matching panes" when nothing matches
- [x] Enter jumps to the first match, Escape clears (and on an empty box hands the keyboard back)
- [x] the hover card stays open while you are typing in it
- [x] switching back to "this window only" clears the search

## Design notes

- **Painted, not a native EDIT** (mechanism call, recorded here per go.md 5b):
  the hover card is a layered popup fed by `UpdateLayeredWindow` (T1865), and
  a child control of such a window never reaches the screen. One painted
  field serves the panel and the card alike, so the two cannot drift. The
  keyboard goes to the sidebar column's own window through the loop's
  deferred focus (T48); the card never activates, which is why the column,
  not the card, holds the caret in both cases.
- Editing model is `pane_sidebar_search.zig` (insert as one line, word steps,
  Ctrl+Backspace, surrogate pairs, the scroll that keeps the caret in view);
  the fold is `pane_sidebar_outline.fold` (ASCII case, Latin-1 and Latin
  Extended-A accents, combining marks dropped - other scripts match exactly).
- Plain Ctrl chords stay in the field (Ctrl+C/Ctrl+D handed to a shell would
  interrupt or end it); Ctrl+Shift chords go on to the window's keybinds.
- Not built: text selection (no Shift+arrows, Ctrl+A) and a blinking caret.
  The field edits and pastes; it does not select. Filed as T1913 (P3).
