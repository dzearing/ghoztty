# T2000 - git-commit-guard reads a glob pathspec back as foreign paths: -Paths 'test/win32/*.stamp.json' committed only the right files and still reported T948 and refused to push

## Summary

T1956 turn: commit -Paths included 'test/win32/*.stamp.json'. git staged exactly the matching stamps, but the read-back compares committed paths against the literal -Paths strings, so every stamp was named as another session's work, the message said to reset --soft, and the push was skipped. The commit was correct and was pushed by hand. Fix: expand globs (git ls-files / pathspec match) before the read-back, or refuse a glob up front with the literal-path remedy. Add the case to section W of go-loop-guard.ps1.
