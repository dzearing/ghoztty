# T3220 - Collapsed pane sidebar rail ends up narrower than its buttons (tiles clipped), likely after an edge-drag collapse

## Summary

User report 2026-11-17 (screenshot): the collapsed pane sidebar (the rail of pane buttons, the minimized state) keeps ending up NARROWER than its own buttons - the button tiles are clipped at the rail's right edge instead of sitting fully inside it. It recurs.

Lead (ghoztty.log, 1.55.5 pid 51276): the recent collapses on this box came from `pane sidebar expanded=false cause=edge drag` (22:05:38Z) and an edge-drag re-expand at 23:39:55Z; earlier ones were header/rail buttons. Suspect the edge-drag path collapses to (or remembers) a dragged width below the rail width instead of snapping to the rail width - and start=remember then restores that width on relaunch. Check the DPI path too (rail width in DIPs vs buttons in px).

Acceptance: test/win32 script - collapse the sidebar by edge drag (several drag end-points, including past the rail width, at 100/150/200% DPI), by header button, and by relaunch with start=remember; in every case the rail width >= the button tile width + its margins (assert from logged geometry, not pixels). Compare the Mac rail's collapsed width for parity.

## In plain terms

When the pane sidebar is folded down to its thin strip of buttons, the strip sometimes looks too narrow: the buttons are cut off on the right instead of sitting inside it. The user has seen it more than once. When fixed, the folded strip always shows its buttons whole, however it was folded and whichever workspace is showing.

## Findings so far (2026-11-18)

- Screenshot: tiles cut on the right with the card's own right edge missing - about one card margin of the 78 px column is covered.
- Log (1.55.5): edge-drag collapse at 22:05:38 (glide landed at width=78, never compositor-declared), then ~25 single-window workspace switches while collapsed, then the user dragged it back out at 23:39:55 (likely to escape it).
- Repro probe on the test desktop (dpi 120, elevated, single mode, 3 workspaces, gutter-drag collapse, 6 switches): the sidebar window was 78 px every time and its paint shows the whole card. Layout math is consistent.
- So the cut is something drawn OVER the column on screen (a DWM-composed layer: the grid glide's composed desk/cards or a chrome face) or a state the probe lacked (5+ panes / a scrolled rail, translucency). PrintWindow on the background desktop cannot see either.
