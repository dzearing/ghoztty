# T3220 - Collapsed pane sidebar rail ends up narrower than its buttons (tiles clipped), likely after an edge-drag collapse

## Summary

User report 2026-11-17 (screenshot): the collapsed pane sidebar (the rail of pane buttons, the minimized state) keeps ending up NARROWER than its own buttons - the button tiles are clipped at the rail's right edge instead of sitting fully inside it. It recurs.

Lead (ghoztty.log, 1.55.5 pid 51276): the recent collapses on this box came from `pane sidebar expanded=false cause=edge drag` (22:05:38Z) and an edge-drag re-expand at 23:39:55Z; earlier ones were header/rail buttons. Suspect the edge-drag path collapses to (or remembers) a dragged width below the rail width instead of snapping to the rail width - and start=remember then restores that width on relaunch. Check the DPI path too (rail width in DIPs vs buttons in px).

Acceptance: test/win32 script - collapse the sidebar by edge drag (several drag end-points, including past the rail width, at 100/150/200% DPI), by header button, and by relaunch with start=remember; in every case the rail width >= the button tile width + its margins (assert from logged geometry, not pixels). Compare the Mac rail's collapsed width for parity.
