# T1069 - A failed agent recovery leaves the app blocked in a modal with its relaunch guard still armed

## Summary

Measured on box 2026-08-21 while re-pointing agent-upgrade.ps1 arm J at the skew path. When a destructive agent restart's re-dial fails, recoverLocalAgentInPlace returns null and the caller (handleAgentProtocolSkew, and the idle refresh's twin) calls showAgentRefreshFailed - which is a MODAL ConfirmDialog that pumps its own loop and does not return until somebody answers it. Both callers arm the T421 relaunch guard with 'defer g.disarm()', so for as long as that notice sits unanswered the guard stays ARMED and its marker file stays on disk. Consequences: the app cannot be closed cleanly during that window without the guard reading the exit as a death inside a refresh and relaunching it (masked today only because the guard often spawns degraded IN-JOB and dies with the app), the marker leaks into the next run, and the app is stuck in a modal on a path whose whole point was that the failure should be visible without being a trap. Evidence in a kept test root: 'relaunch guard: ARMED ... escape=IN-JOB (degraded)' followed by 'in-place recovery ABORTED', 'protocol-skew agent restart finished: 0 window(s) rebuilt', and no 'relaunch guard: disarmed' line at all. Likely fix: disarm the guard (and clear the marker) BEFORE raising the failure notice - the destructive window is over by then, the app has survived it, and that is exactly what the guard was watching for. Then agent-upgrade.ps1 arm J can assert the disarm and the absent marker again (it asserts only the ARM today, with a comment pointing here).

## In plain terms

When Ghoztty tries to restart its background terminal process and that restart
fails, it shows a "could not restart" notice. While that notice sat on screen,
a safety net that exists to bring the app back if it dies mid-restart stayed
switched on. So closing Ghoztty from under the notice could look like a crash
and relaunch it, and a leftover marker file carried over to the next launch.
Now the safety net switches off as soon as the restart is over, before the
notice appears.

## Goals

- [x] the relaunch guard is disarmed (marker removed) before the failure notice is raised
- [x] agent-upgrade.ps1 arm J asserts the disarm, its order, and the absent marker again

## Fix

`handleAgentProtocolSkew` (`src/apprt/win32/App.zig`) is the only caller of
`showAgentRefreshFailed`: the idle refresh's twin named in the Summary never
raises the notice, so there was one site to fix, not two. On a null
`recoverLocalAgentInPlace` it now calls `g.disarm()` and nulls the guard
before the modal, so the function's `defer` has nothing left to disarm.

two pids gone, neither started by this script): the bystander set took every
`ghoztty-agent` on the box, including per-pane `--pty-host` children, which
