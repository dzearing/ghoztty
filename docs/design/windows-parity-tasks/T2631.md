## Resolution (2026-11-06): already fixed by 3033c62d8 (T2670)

Root cause, from T2670: since T2577 (c71b37da8, 2026-10-31) the Win32 GL
render target keeps storage rounded up to 256 px and draws the frame in its
bottom-left w x h; `bg_image.f.glsl` and `cell_bg.f.glsl` used
`layout(origin_upper_left)`, so they measured each pixel from the top of the
storage. Any pane whose height was not a multiple of 256 had its glass slid
up and a flat strip along the bottom - exactly the bottom-left/bottom-right
corners this arm samples, and the pane edge it compares against the desk.
3033c62d8 measures from the frame instead, re-stamped pane-elevation green and
removed this task's guard-ack in the same commit.

Run history (`%TEMP%\ghoztty-acceptance-parallel\*\summary.json`):
