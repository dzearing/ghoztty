# T2289 - The Windows pane sidebar's rail opens on hover and has a pin; Mac's rail never opens on hover - one button, the header's first item, centred on the rail's width so it never moves, switches collapsed and expanded (Mac e77422577, dc2bbab6b; split from T2274)

## Summary

Remove the hover-open card (pane_sidebar_hover.zig + its popup) and the pin; the toggle is the header's first item, centred on the rail's 68 DIP column, and the rail's one button sits in exactly that spot (disabled when the window is too narrow for the panel). Persisted 'pinned' is read as expanded. Superseded hover follow-ups: T1908, T1997. (T1894 is NOT superseded: it is the rail's own clipped shadow, which the rail keeps; it now sits beside T2290.)

## In plain terms

The pane list down the left of a Windows window used to pop open into a
wide card whenever the pointer drifted over it, and it had a pin in the
corner to keep it open. The Mac version no longer does either: the narrow
strip stays narrow until you ask, and one button at its top opens it into
the full list and closes it again - always in the same spot, so you can
click it twice without moving the mouse. Windows now works the same way.
In a window too small for the full list, that button is dimmed and its tip
says why.
