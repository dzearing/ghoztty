# T2588 - Honor macos-pane-sidebar (remember / expanded / collapsed / hidden): how every window's sidebar starts (Mac 92ab0c9f1)

## Summary

Mac 92ab0c9f1: macos-pane-sidebar picks how the SHARED sidebar starts in every window; applied before any window is restored and on each config change but only when the value CHANGED (a reload never undoes the user's toggles); a forced value is NOT written to the remembered prefs so 'remember' still has the user's own last choice; 'hidden' keeps the remembered expanded/rail choice for when it is shown. Windows: pane_sidebar_prefs.zig + pane_sidebar_shared.zig persist and seed the shared state today; add the config-driven start with the same changed-only reapply and do-not-persist rules, unit-tested in the none lane. Keys arrive with the T2490 merge. Mac reference: docs/reference/pane-sidebar.md 'How it starts'; tests PaneSidebarSharedStateTests aForcedStartWins..., aReloadReappliesOnlyWhenTheValueChanges.

## In plain terms

The Mac lets you choose in your config how the pane sidebar starts — the
way you last left it, always open, always the narrow rail, or hidden. Windows
ignored that setting and always started the way you last left it. After this,
Windows starts every window's sidebar the way the setting says, changing the
setting while the app is open applies it at once, and your own last choice is
still remembered for when you set it back to "remember".

## Goals

- [x] `macos-pane-sidebar` decides how every window's sidebar starts, restored windows included
- [x] a reload that changes the value applies it to every open window; one that leaves it alone keeps the user's toggles
- [x] a forced start is never written to the remembered file; a toggle afterwards is
- [x] `hidden` keeps the expanded/rail choice for when the sidebar is shown
