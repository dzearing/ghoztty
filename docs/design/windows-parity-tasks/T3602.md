# T3602 - Mac: a config reload clears a --command window's wait-after-command, so the window closes when its command ends

## Summary

Windows fixed this in T1957 (Surface.sticky + App.pushConfigToSurfaces): core App.updateConfig re-derives every surface from the app config, which clears a per-surface wait-after-command set by the embedded surface options (src/apprt/embedded.zig wait_after_command / command). On Mac a reload (or any app-wide config push) after +new-remote-window --command would close that window when the command ends. Verify on the Mac build: open a --command window with a long command, reload config, let the command end; if the window closes, keep the per-surface value across the push the way T1957 does (re-derive with the surface's own value laid over the app config).
