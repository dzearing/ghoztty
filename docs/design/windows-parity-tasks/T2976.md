# T2976 - PA-R10: closing 10 panes leaves about 50 MB of GPU memory behind (107 MB vs 57.6 MB at start); find the carrier (parked pane windows, per-HWND DComp target or driver cache) and trim it

## Summary

PA-R10 (audit-1, T2959; cause unverified). baseline-1: closed.gpu_dedicated_mb 107.4 vs 57.6 at start, second_cycle_gpu_dedicated_mb 0, so a bounded plateau, not a growing leak. 49.8 MB over 9 closed panes is ~5.5 MB each, close to one 1400x900 BGRA surface. Suspect: pane_pool.zig:28 (capacity 16) parks closed pane HWNDs (Surface.zig:1554-1555) and only window destroy drains it (Window.zig:423-427); but the pool's rationale is SwapBuffers residue and composition panes never SwapBuffers, so the carrier may be the per-HWND topmost DComp target (gl_comp_present.zig:597) or driver caching. Teardown itself is complete (OpenGL.zig:517-521 -> gl_comp_present.zig:875-919). Step 1: A/B GHOZTTY_PANE_REUSE=0, GHOZTTY_COMP_PANE_TREE=1, GHOZTTY_PANE_GL_HELPER=0 with perf-baseline.ps1 -Phase cycle. Step 2: if it follows the HWND, add an idle trim that destroys parked windows after N seconds through reapSurfaceHwnd (T681); if it follows the HWND target, tree mode removes it. Also, private_mb retains ~830 MB after the first cycle (the memory auditor's area, T2961) - cross-reference.
