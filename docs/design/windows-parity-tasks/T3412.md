# T3412 - Linux L9c: viewer navigation bar and keyboard (back/forward/reload/home/reveal/address, Ctrl+R/L/F/G, zoom)

## Summary

Per docs/reference/viewer-panes.md Navigation chrome and Keyboard: a nav bar pinned open in every mode that reserves its space from the first frame; editable address (http(s), bare host completion, absolute or ~ path); real history across the file/web boundary; Home = the opened location; a reveal-in-file-manager button only while a local file is shown. Pane-scoped chords with the Linux modifier, fieldKeyAction Escape/Return precedence, no beep on keys the page ignores, every other chord falls back to the app keybindings minus terminal-only actions.

## In plain terms

A document or web page open in a pane on Linux had no browser controls: no
Back, no address bar, no way to reload or zoom from the keyboard. Now every
viewer pane has the same bar the Mac and Windows have - back, forward,
reload, home, a folder button that shows the file in the file manager, and
an address field you can type a path or a web address into - and the
browser keys (Ctrl+L, Ctrl+R, Ctrl +/-/0, Escape) work in it.

## Goals

- [x] a nav bar on every viewer pane, laid out above the page from the first frame
- [x] back / forward walk real history, across the file <-> web boundary
- [x] the address field navigates (absolute or `~` path, omnibox-completed host) and Escape reverts it
- [x] Home returns to the opened location; reveal shows only for a local file and survives a deleted one
- [x] pane chords Ctrl+R / Ctrl+L / Alt+D and Ctrl +/-/0 zoom, on the shared win32 chord tables
- [ ] find chords (Ctrl+F/G, F3): declined until T3414 brings find
- [ ] every other chord falls back to the app keybindings: filed as T3430
