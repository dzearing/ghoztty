# T3396 - An agent-backed pane opened with a multi-argument -e (ghoztty -e sh -c 'a; b') runs the words unquoted: Command.string joins argv with spaces

## Summary

`src/config/command.zig` `Command.string` joins a `.direct` argv with single
spaces and no quoting, and `src/Surface.zig` forwards that string as the
agent's `OPEN.command` whenever a pane is agent-backed (session persistence,
the default on all three platforms). So `ghoztty -e /bin/sh -c "echo a; sleep 60"`
reaches the agent as `/bin/sh -c echo a; sleep 60`: `sh -c` runs a bare `echo`
and the rest runs in the agent's own outer shell. `-e /bin/sh -c "sleep 60"`
dies at once (`sleep` with no operand).

Measured on the Linux GTK app in T3337 (2026-11-22): `+sessions` showed
`cmd=/bin/sh -c sleep 60  dead(1)`. The Mac and win32 share the core path
(`remote_command = try c.string(alloc)`), so they are expected to show the same.

Fix: forward a `.direct` argv as the OPEN argv rather than a joined string (or
shell-quote each word when it has to travel as a string), with a core unit test
over the quoting and an acceptance check per platform.

## Validation criteria

- [ ] `ghoztty -e /bin/sh -c 'echo $$ > F; sleep 60'` with session persistence on writes F and the pane stays up (Linux: a check in `test/linux/session-agent.sh`)
- [ ] a core unit test covers an argv whose words carry spaces and quotes
- [ ] the same command on win32 and the Mac runs intact (or a seat card exists for the side not validated)
