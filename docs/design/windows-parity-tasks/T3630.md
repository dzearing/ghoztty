# T3630 - Linux: prove a resize at a shell prompt never shows the prompt blank on GTK (prompt-redraw hold), and add a window-resize source to resize-pacing.sh

## Summary

T3568 measured resize pacing on GTK for a running program (divider drag, banner fold) but not the prompt half of docs/reference/terminal-resize.md: with shell integration, a resize at a prompt clears it and the renderer holds the last frame (Terminal.flags.awaiting_prompt_redraw) until the shell redraws. On GTK the GLArea presents its own framebuffer, so whether a skipped render shows the held frame or a blank/new-size buffer is unmeasured. Capture frames (capture-pane) across a resize at a bash prompt with Ghostty shell integration and assert the prompt line is never blank; also drive a window resize (gtk_window_set_default_size, as the viewer steps seam does) through the SIGWINCH counter.

## Validation criteria

- [ ] A resize at a bash prompt with shell integration never captures a frame whose prompt line is blank (capture-pane frames across the resize), with a negative control.
- [ ] A window resize reaches the SIGWINCH counter in resize-pacing.sh as paced SIGWINCHes, like the divider drag.
