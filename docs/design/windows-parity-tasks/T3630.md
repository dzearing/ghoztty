# T3630 - Linux: prove a resize at a shell prompt never shows the prompt blank on GTK (prompt-redraw hold), and add a window-resize source to resize-pacing.sh

## Summary

T3568 measured resize pacing on GTK for a running program (divider drag, banner fold) but not the prompt half of docs/reference/terminal-resize.md: with shell integration, a resize at a prompt clears it and the renderer holds the last frame (Terminal.flags.awaiting_prompt_redraw) until the shell redraws. On GTK the GLArea presents its own framebuffer, so whether a skipped render shows the held frame or a blank/new-size buffer is unmeasured. Capture frames (capture-pane) across a resize at a bash prompt with Ghostty shell integration and assert the prompt line is never blank; also drive a window resize (gtk_window_set_default_size, as the viewer steps seam does) through the SIGWINCH counter.

## In plain terms

When you resize a Linux Ghoztty window while the shell is sitting at its
prompt, the prompt must never flicker blank: the terminal keeps showing the
old picture for the instant it takes the shell to redraw its prompt at the new
width. This proves that on Linux, and also checks that dragging the window's
edge (not just the line between two panes) tells a running program about its
new size only a few times, not on every frame.

## Validation criteria

- [x] A resize at a bash prompt with shell integration never captures a frame whose prompt line is blank (capture-pane frames across the resize), with a negative control. - `test/linux/prompt-redraw.sh` ALL PASS in WSL (2026-11-25): a 16-step window storm at a green bash prompt, every resize decided `pace=now` (row=prompt, redraw=last), all 16 storm frames show the prompt, 16 holds released `by=redraw` and none `by=cap`; control C1/C2 (bash SIGSTOPped) is released `by=cap` and its frame has no green at all. `NEGATIVE=1` (bash stopped through the storm) FAILS exactly P6-P8 (frames 5-16 blank, 6 cap releases, 0 redraws).
- [x] A window resize reaches the SIGWINCH counter in resize-pacing.sh as paced SIGWINCHes, like the divider drag. - `test/linux/resize-pacing.sh` R10-R12 ALL PASS in WSL: the window edge laid out at 30 distinct widths (1280 -> 1040 px) over 794 ms and the counter saw 3 SIGWINCH (cap 4). `NEGATIVE=1` FAILS exactly R6 and R12 (8 SIGWINCH for 8 steps each).
