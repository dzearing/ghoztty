# T3060 - PA-C03: the ConPTY reader pays a quit-pipe peek, a blocking read, a top-up peek, a lock cycle and a renderer post for every ~60-110 bytes of a flood (Exec.zig read loop)

## Summary

PA-C03 (audit-1, T2964). src/termio/Exec.zig:1568-1611 + :1639: every iteration does PeekNamedPipe(quit), a blocking ReadFile, a top-up PeekNamedPipe, then processOutput (mutex, renderer notify, parse). The T62 top-up only batches bytes already waiting; T1464/T1465 measured 19-29k reads/s for 1.4-1.7 MB/s (60-73 bytes/read), the same order as baseline-1's ~28.5k context switches/s. Cost (estimated): 5-8 us per iteration, 10-16% of a core plus most of the busy context switches. Fix: (1) replace the per-read quit-pipe peek with an atomic flag set by threadExit before CancelIoEx (the 20 ms retry at :244-254 covers the race); (2) adaptive coalescing: after a non-trivial read whose top-up peeks 0, wait up to ~1 ms (high-resolution, not a 15.6 ms Sleep) or until 16 KB is pending before parsing; an isolated keystroke echo still parses at once. T1465 reverted an unconditional 1 ms wait in the holder because throughput did not move; CPU and switches were never measured, and they are the target here. Needs PA-C05 (a larger pipe) for the wait to accumulate anything. Risk: trivial for the flag, medium for coalescing (echo latency, the T62 starvation history). Windows-only code. Findings: docs/design/perf-audit/audit-1/C-findings.md.

## In plain terms

When a program pours output into a pane (a big build log, `type` of a large
file), Ghoztty handled it about 100 bytes at a time, waking up and locking the
screen ~30,000 times a second. Now it lets a flood collect for up to a
millisecond before drawing it, so the same output costs about half the CPU and
finishes a little faster. Typing still echoes instantly, because a keystroke
after a pause is never held back.

## Goals

- [x] the reader stops making a syscall per batch just to ask "should I quit?"
- [x] a flood is parsed in kilobyte batches instead of ~100-byte ones
- [x] an idle-pane keystroke echo is never delayed
- [x] the ConPTY output pipe is large enough to hold a batch (T3062, folded in)
