# T2221 - Tunnelled HTML/website viewers: page network requests go out from the remote machine over a gated web_tunnel wire (Windows + shared)

## Summary

See docs/design/remote-viewer-tunnel.md (T1297 design). Decision 3 (user decision D-filed alongside). Intercept the viewer's requests (WebView2 WebResourceRequested) and forward them as HTTP over the reserved tunnel opcode, made by the agent on the remote machine, so a remote localhost dev server previews correctly. Separate origin from local ghoztty-page so storage does not mix.

**What this task landed (the shared half, T2219's shape):** the wire and the
agent that makes the requests. A new gated capability `web_tunnel` with five
opcodes in `src/remote/protocol.zig` - `WEB_REQUEST` 0x88 / `WEB_RESPONSE`
0x89 / `WEB_READ` 0x8a / `WEB_DATA` 0x8b / `WEB_CLOSE` 0x8c - and
`src/remote/agent/web_tunnel.zig`, which performs each request on the
agent's machine. **Not the reserved `tunnel` 0x40**: that opcode is the §8
port-forward control (`{op, type, listen, dest}`), a different shape with a
different job, so reusing it would have forked its meaning (mechanism call,
recorded here, not a decision for the user). Policy, all checked before a
socket opens: only absolute `http:`/`https:` URLs with a host (never `file:`,
which is `viewer_grants.zig`'s job); no `CONNECT`/`TRACE`; header names are
tokens and values carry no CR/LF/NUL (the std client asserts on CR/LF);
hop-by-hop headers are dropped and recomputed, `Accept-Encoding` pinned to
`identity`; a redirect is answered as itself, never followed, so the page's
engine follows it through the tunnel too. Bounds: 8 MiB request body, 32 MiB
response (the local viewer's cap), 64 headers, 6 requests in flight (more are
refused `busy`, never queued), 64 MiB of held bodies, 30 s socket idle
timeout. Each request runs on its own worker thread sharing a refcounted
state with the connection, so a slow server can never reach a freed Server:
once the connection closes its answer is dropped. Nothing on the app side
calls it yet, so no user sees a change.

**Split:** T3723 (win32 WebView2 `WebResourceRequested` + own origin),
T3724 (dev-server live-reload WebSockets), T3725 (honour the agent machine's
HTTP proxy, P3), T3726 (GTK, seat: linux). Mac stays T2222.

## In plain terms

When a web page from another machine is shown in your window - say the dev
server you started on that machine - everything the page loads has to come
from that machine, or `localhost` would mean your laptop instead of the box
the server runs on. This lands the other machine's half: it can now fetch
whatever the page asks for, safely, and hand it back. Nobody sees a
difference yet; the window-side half is the next task.

## Goals

- [x] A gated, additive wire for a page's requests and their responses
- [x] The agent makes them on its own machine, under a policy checked before any socket opens
- [x] Bounded in every direction (sizes, concurrency, held bytes, silence), and a slow server cannot outlive the connection's memory
- [x] Older peers see nothing new
- [x] The remaining halves filed as their own tasks

## Validation criteria

- [x] Capability negotiates only on the intersection; the two answers are parked-on replies, the three requests are not; the biggest request body fits a frame; payloads round-trip with unknown fields tolerated - `protocol.zig` test "T2221 web_tunnel negotiates ...", agent lane (and the none/win32 lanes, whose `connection.zig` reply-dispatch walk covers every new opcode).
- [x] Policy refuses CONNECT/TRACE/non-methods, non-http(s) and host-less URLs, malformed header names, CR/LF/NUL values and bad base64, all before a socket; standard headers routed to the client's own fields so none is sent twice - `web_tunnel.zig` tests, agent lane.
- [x] Over the real agent wire against a loopback HTTP server: 200 with body and headers minus hop ones; the server saw its own Host (not the page's), `identity`, and the page's Cookie; a 1 MiB + 10 body arrives as a held piece, the rest pulled with `WEB_READ`, `WEB_CLOSE` then `WEB_READ` reads `no_body`; a 302 is returned with its Location, not followed; `file:` is `bad_url`, CONNECT `bad_method`; a closed port is `connection_refused` - `server.zig` test "T2221 WEB_REQUEST is made from the agent's machine ...", agent lane.
- [x] A peer without the capability gets no `WEB_RESPONSE` - `server.zig` test "T2221 WEB_REQUEST from a peer that did not negotiate ...", agent lane.
