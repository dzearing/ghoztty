# T2862 - After Windows relaunches Ghoztty from a crash, say so: a one-time note in the restored window naming the crash and where its report is

## Summary

T2839 lets Windows relaunch a shipping build after a crash, so the windows come back on their own. The user should still learn it happened (the Mac equivalent is the system's 'quit unexpectedly' prompt). The exit ledger (src/apprt/win32/exit_reason.zig) already records event=crash, and crash/windows.zig writes a report under %LOCALAPPDATA%\ghostty\crash. On a launch whose previous ledger entry is a crash, show a small one-time note in the first window: 'Ghoztty closed unexpectedly and was reopened' with a link that opens the crash report folder or runs +crash-report. Needs the same note on Mac? Mac already has the OS prompt; confirm no second note is needed there.

## In plain terms

Since yesterday, if Ghoztty crashes, Windows opens it again by itself and your
sessions come back. But it happened silently: the windows vanished and
reappeared with no word about why. Now the reopened app shows a small Windows
notification, "Ghoztty closed unexpectedly - It crashed a moment ago and was
reopened. Click to see the crash report." Clicking it opens the folder with
the crash report. It shows once, on the first launch after the crash.

## Goals

- [x] the first launch after a crash tells the user, once
- [x] the note says when it crashed, that the app was reopened, and what a click does
- [x] clicking the note opens the crash reports
- [x] the launch after that stays quiet, with no marker file to clean up

## Design

- **The signal is the exit ledger, not a marker.** `exit_ledger.crashBeforeLaunch`
  (pure, `src/os/exit_ledger.zig`) returns the newest `crash` record when no
  `start` follows it. `exit_reason.install` reads it in the same pass as the
  dangling-run audit, BEFORE this launch writes its own `start`, so the first
  launch after a crash sees it and every later launch finds its own `start` in
  the way. Only a `start` clears a crash: another instance's `exit` does not,
  and `unrecorded-exit` lines never do.
- **A tray balloon, not an in-window bar.** The same surface and shape as the
  T1208 "closed and reopened for an update" notice: the crash already happened
  and there is nothing to decide, so a modal is wrong and a balloon is what
  every other "this already happened" message on Windows uses. Own icon id
  (`tray_notify.crash_reopened_uid` = 7) and cleanup timer
  (`msg_timer.notif_crash_reopened` = 29); the click routes to
  `open_crash_reports`, which opens `<xdg state>\ghostty\crash` in Explorer
  (its parent when no report was written).
- **Wording** (`src/apprt/win32/crash_reopen.zig`): title "Ghoztty closed
  unexpectedly", body "It crashed {a moment ago | N minutes ago | an hour ago |
  N hours ago | N days ago | earlier} and was reopened. Click to see the crash
  report." A manual reopen days later still reads true.
- **Mac needs no second note.** macOS tells the user at the moment of the crash
  with its own "quit unexpectedly" dialog (with Reopen), so the Mac user is
  already told. This note is the Windows counterpart of that dialog, not an
  addition to it; no Mac-seat task is owed.
