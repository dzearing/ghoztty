# T2032 - Audit acceptance fixtures that chain +split --target=<window> and assume the new pane became active (T1797 made a no---focus split keep the active pane; viewer-restore.ps1 was missed)

## Summary

Since T1797 (2026-10-10) a `+split` without `--focus` leaves the tab's active pane where it was. T1797 moved seven harnesses to `--focus`; viewer-restore.ps1 was missed and sat red for weeks with a layout it never meant to build (T2015). Sweep `test\win32\` for fixtures that issue a second `+split --target=<window>` (or a window-targeted verb) after a split and expect it to land on the NEW pane. Fix each by anchoring with `--pane=<name>` (preferred: no focus side effect) and add a setup control that asserts the built layout, the way viewer-restore.ps1 D0 does.

## Validation criteria

- [ ] every fixture found is anchored explicitly or shown not to depend on the active pane
- [ ] each touched harness runs ALL PASS
