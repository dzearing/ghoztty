# T2011 - A window can drop into fullscreen with no title bar or tabs and no visible way back (Ctrl+Enter toggles it; seen over Remote Desktop)

## In plain terms

Sometimes one Ghoztty window loses its whole top bar: the tabs, the
minimize, maximize and close buttons, all gone. It fills the screen and
covers the taskbar, and there is no visible way to get the bar back. A
window in that state must always show how to leave it, and it must be hard
to enter by accident.

## Goals

- [x] Find what actually hides the chrome
- [x] F11 toggles full screen on Windows, and the menu teaches it
- [x] Entering full screen says how to leave ("Press F11 to exit full screen")
- [x] Pushing the pointer to the top edge shows an "Exit full screen" button
- [x] Leaving full screen puts the window back exactly as it was, maximized included
- [x] A display change (Remote Desktop resize/reconnect) re-fits a full-screen window
- [x] Every entry and exit is logged with what triggered it
- [x] The Ctrl+Enter question is with the user (D99)

## Summary

User report (2026-10-16), seen "a couple times now": "the chrome of the app
completely disappears (the part with the X and the max/min buttons). tab
just leaves. i can't figure out how to get it back. it's like just 1 window
out of many. but it being full screen ends up covering up the window bar.
this is on a remote connection".

Most likely cause (? INFERRED, confirm from the log): **fullscreen.** The
default binding inherited from upstream is `ctrl+enter = toggle_fullscreen`
on non-Mac platforms (`src/config/Config.zig:7380`, `ctrlOrSuper`). Ctrl+Enter
is a common keystroke inside terminals and TUIs (including Claude Code), so
it is easy to hit by accident. On Mac the binding is Cmd+Enter, which never
collides with what a terminal app expects. The user was told to press
Ctrl+Enter in that window to restore it.

Other candidates if the log shows no toggle: a Remote Desktop
reconnect/resolution change (`WM_DISPLAYCHANGE`, `WM_DPICHANGED`, or a WTS
session change) leaves the custom title bar/tab strip window hidden or sized
to zero while the frame stays maximized over the work area.

Work:

1. **Log every fullscreen entry and exit with its trigger** (keybind,
   action, IPC, display change), so the next occurrence is diagnosable.
2. **Always offer a way out:** in fullscreen, moving the pointer to the top
   edge reveals the tab strip and caption buttons (browser-style), and that
   overlay has an "exit full screen" button. On entry, show a one-time
   notice: "Full screen. Press Ctrl+Enter or F11 to exit".
3. **Add F11** as a Windows fullscreen toggle (the platform convention), on
   top of Ctrl+Enter.
4. **The accidental-entry question is a user call** (it changes a default
   key): should Ctrl+Enter keep toggling fullscreen on Windows, or pass
   through to the program, leaving F11 as the toggle? File it as a decision
   with options (per [[decision-format-preference]]), and keep the current
   binding until it is answered.
5. If the cause is the display-change path instead, re-lay out and re-show
   the title bar/tab strip on `WM_DISPLAYCHANGE`, `WM_DPICHANGED` and
   `WTS_SESSION_RECONNECT`.
6. Mac half: Mac's fullscreen already has a menu-bar reveal. Nothing is owed
   unless item 4 changes the binding on both platforms.
