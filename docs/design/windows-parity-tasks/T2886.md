# T2886 - Teach the harness floor to catch a relational assertion that leans on a value an earlier step may not have produced (the T1401 rule, mechanically)

## Summary

T1401 swept all 503 `test\win32` scripts by hand-plus-prototype for the T1392
shape - `Assert ($after -gt $before)` where `$before` may be `$null`, which
PowerShell coerces so the comparison passes for free - and fixed the three
live sites. The rule is written in `docs/claude/testing.md` beside the T794
unroll trap. Nothing stops the next script from re-introducing it.

**The judgement T1401 recorded:** a FULL check is not mechanical (whether a
helper can return `$null` is a data-flow property), but two narrow shapes are
precise enough to gate on, and both were prototyped against the whole tree:

1. **Guarded-then-compared** (precise): a variable that an earlier
   `Assert`/`Check` null-tested (`$null -ne $v`), later sitting on the VACUOUS
   side of a relational compare (right of `-gt`/`-ge`, left of `-lt`/`-le`) in
   another assertion that does not null-test it, with no `throw` /
   `Write-TestAssertedNothing` / `$null -eq $v` guard between. 4 hits on
   2026-11-10, 2 real (fixed), 2 safe because the script throws in between.
2. **Null-returning helper** (precise): the vacuous-side variable's nearest
   preceding assignment is a bare call to a repo helper with an explicit
   `return $null` (or a bare `return`). 2 hits, 1 real (fixed), 1 guarded by
   `Write-TestAssertedNothing`.

A wide version (any helper-returned variable on the vacuous side) gave 303
hits in 127 files, almost all `IndexOf`/`.Count`/`ElapsedMilliseconds` - noise,
do not ship that.

**Where it should live:** `test\win32\lib\UnrollCountAudit.ps1` already builds
the repo-wide helper index and binds a variable to its NEAREST preceding
assignment (the `unwrapped-var` kind), which is exactly what shape 2 needs. Add
a `vacuous-compare` kind there rather than a new audit, so it rides the
existing harness-floor row, guard-due row and scoped sweep. Exemption marker
in the house style (`# count-audit: <reason>` or a sibling).

## In plain terms

Some of our tests could pass without checking anything when an earlier step
failed to read a value. We fixed the ones that exist; this makes the test
floor refuse a new one instead of waiting for someone to notice.

## Validation criteria

- [ ] `UnrollCountAudit.ps1` reports a `vacuous-compare` finding for both shapes
      against fixtures, and nothing for the guarded forms (same-expression
      `$null -ne`, a `throw`/`Write-TestAssertedNothing` between).
- [ ] The current tree scores ZERO for the new kind (T1401 fixed the live sites).
- [ ] `-TeethCheck` plants each shape and the audit goes red.
- [ ] `floor-lane.ps1 -Lane harness` green with the new kind in.
