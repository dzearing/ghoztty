# T1829 - The pane sidebar's all-windows scope on Windows: every window as an outline of its panes, grouped by project, sorted, with search

## Summary

Mac all-windows scope (off by default): each window header is a parent row (chevron + the window's name - user title or its focused pane's name, never the raw title with the activity suffix) with its panes indented beneath, only this window has a selection, hairline between windows (55352e377). Windows sorted by name, stable across focus changes; '<project>: <worktree>' windows grouped under a collapsible sticky project header labeled by worktree (b4a3216cc). A search field ANDs terms over window title, pane title, banner and directory; Return reveals the first hit, Escape clears; the hover card stays open while the field has the caret; the This window / All windows switch slides in a consistent direction (7855941f7); the field reads like a native search box and does not jump on focus (e898f5a00).

**Scope as landed (the outline):** the header's all-windows toggle, the
outline (window headers with their panes indented, this window's selection
only, hairlines), Finder-order sorting, `<project>: <worktree>` grouping under
a foldable project header, folding, a click on another window's row or header
reaching that window, the rail's per-window hairlines and window-naming tile
tips, and every list following renames and closes in other windows. The rest
is split, each depending on this one:

- **T1877** (P2, M1) the search field (its term rules already landed here, in `pane_sidebar_outline`)
- **T1878** (P2, M1) scrolling, and sticky project headers (found here: the sidebar never scrolled)
- **T1879** dragging another window's row here, and this window's row onto another window's group
- **T1880** (P3) the sideways scope slide and the top-down fold reveal

## In plain terms

On a Mac, the pane sidebar can show every window at once, not just the one
you are in: each window is a heading with its panes listed under it, sorted by
name, and windows from the same project are gathered under the project's name.
Windows only ever showed the current window. Now the button beside the pin
switches the sidebar to all windows; clicking another window's pane jumps
straight to it (bringing it back if it was tucked away), clicking a window's
heading brings that window forward, and the arrows fold a window or a project
away.

## Design (win32)

- **A Mac window is a TAB here.** Mac's tabs are windows of their own, each
  with its own roster; this sidebar already lists one tab. So each tab of every
  top-level is a group, and this window's other tabs are groups beside it
  (labeled "This Tab" rather than "This Window" when the top-level is tabbed).
  Mechanism call, recorded here per go.md 5b.
- **Name** (Mac `windowTitle(of:)`): the window's title pin, else the tab's
  pinned title, else the focused pane's display title - never the raw window
  title.
- **Pure rules in `pane_sidebar_outline.zig`**, every lane: the title split
  (Mac's cases plus Windows paths), Finder order (case-folded, digit runs by
  value), outline order with case-distinct projects never interleaving, the
  line stream (project/window heads, panes, hairlines, STASHED captions,
  folds), and the search terms for T1877. `pane_sidebar.zig` lays the lines
  out (`layoutWith` / `layoutOpenWith`): heads, content indent of one chevron +
  gap per level (Mac's 12 + 5), fills full width, folded panes get no rect and
  no hit, the rail breaks on group change, and only THIS window's stash range
  is a drop target.
- **The toggle** is the icon font's TaskView glyph left of the pin; Mac reads
  on/off from a filled glyph, which the font has no twin for, so on is the
  Windows checked-toggle fill. Mac drops header buttons from the rail; so does
  this.
- **Liveness.** `Window.syncPaneSidebar` - called from every layout, focus,
  title and activity change - ends by asking every OTHER all-windows sidebar
  to refresh (`PaneSidebar.refreshScopes`, a hash compare when nothing they
  show moved); so do window close and the title/tab-title pins. A row keeps
  `*Window`/`*PaneView` only to ask about: every click re-checks
  `App.hasWindow` and `tabIndexOfPane` first, and a header finds its tab again
  by `tab_uuid`.
- **Clicks** go through `IpcHandlers.focusTarget` - the same verb as
  `ghoztty://focus` - which restores a stashed pane and selects a background
  tab. A foreign row is never a drag source yet (T1879).
