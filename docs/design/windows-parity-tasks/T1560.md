# T1560 - A task that names its own check should be able to prove itself already fixed

## Summary

T719 was fixed by T744 two days after it was filed and then sat open for 34 days. Its whole Summary was one runnable command - a sweep whose empty output IS the definition of done - and nothing ever ran it. stale-scan ranks by a later commit having NAMED the task, which cannot see a sibling task that fixed the same defect without citing it. Proposal: an optional 'verify:' line in a task's frontmatter holding a one-line command whose clean exit means the card is already satisfied, and a stale-scan pass that runs those and reports the ones that now pass. Scope it to commands that are read-only and fast (a sweep, a grep, a script with a -Check switch), never a full acceptance harness.

## In plain terms

Some task cards are finished the moment one quick command comes back clean, but nothing ever ran that command, so a card already fixed by other work could sit open for a month. A card can now carry its own check. The loop runs it when it picks the card up and every morning during triage, and says "already satisfied" the first time it passes.

## Goals

- [x] a `verify:` field holding one read-only command whose clean exit means the card is satisfied
- [x] `next` runs the picked card's check and says ALREADY SATISFIED on a pass, without ever blocking the pick
- [x] `stale-scan` (the daily triage sweep) runs every open card's check and leads with the passes
- [x] a check is held to "fast" by a timeout, and a broken check can never read as a pass
- [x] `new -Verify` writes the field at filing; `validate` names an empty one

## Validation criteria

- [x] a red check reports red, and the same check reads PASS + ALREADY SATISFIED once an unrelated change removes the defect - Y1/Y2 of `test\win32\parity-tasks-seat.ps1` (308/308 green)
- [x] the pick goes on whatever the check says; `-NoVerify` runs nothing - Y2c/Y3
- [x] stale-scan runs only open cards' checks, lists passes first, kills an overrun as TIMEOUT, and reads an erroring check red (the negative control) - Y4-Y4f
- [x] `validate` fails `verify: ""` (`BAD VERIFY`), registered as a demonstrated gate - Y6 + `test\win32\gate-negatives.ps1` (74/74)
- [x] `new -Verify` writes the line with its quoting intact - Y7
