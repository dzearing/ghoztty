# T3219 - perf-baseline.ps1's viewer phase never slides the contents card, so T3040's 'threads and GPU memory return to the pre-slide value after a card slide' has no measurement: add a compact-card slide to the phase and record app threads/GPU memory before and after

## Summary

T3040 moved the viewer contents card's slide onto the process's shared D3D11 device (T2968) and releases its DirectComposition host when each slide ends. The ViewerPane host-floor test proves the host is gone after every slide and that it drew on the shared device, but nothing MEASURES the resident cost: perf-baseline.ps1's viewer phase (T3033) opens markdown, git-status and website viewers and never narrows a markdown viewer below 720 DIP and toggles its compact card, so audit-1's PA-V08 estimate (~50 driver threads, ~12 MB GPU per viewer that slid) was never confirmed gone.

Fix: in the viewer phase, after the 'viewer open' sample, narrow the markdown viewer into compact mode, toggle its contents card in and out (CLI or posted command; no real input), let it settle, and sample app thread count and GPU memory; report the delta against the pre-slide sample in the result JSON.

## Validation criteria

- [ ] perf-baseline.ps1 -Phase viewer records a pre-slide and a post-slide sample, and the app's thread count and GPU memory delta is within noise (a few threads, < 1 MB)
- [ ] a run with GHOZTTY_COMP_SHARED_DEVICE=0 shows the delta the phase exists to catch (the negative control)
