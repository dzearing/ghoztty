# T1978 - When a restart loses every session, the windows are not rebuilt; one default window opens instead of the saved layout

## Summary

Split from T1971 validation criterion 3. Restore drops a window whose every session is gone (restoreWindowHasAttachableLeaf; T851/T590 forget it when positively adjudicated), so when T1970 loses the sessions the user gets ONE fresh window, not their 10+ windows at their sizes with fresh shells. Check what Mac does in the same case (SessionLayoutRestore: dead sessions) and match it; if Mac rebuilds the layout with fresh shells, do the same here, keeping frames, tabs and splits. Acceptance: kill the agent between save and restore (T1970 negative control); every window comes back at its frame with fresh panes.

## In plain terms

If a restart loses every session in a window, Ghoztty used to drop the
window, and you got one empty default window instead of your layout. Now
each window comes back at its saved size and place, with its tabs and
splits, and every pane opens a fresh shell in the folder it was in.

## Goals

- [x] Check what Mac does: it drops such a window too (SessionLayoutRestore T06b "all N leaf sessions POSITIVELY dead; dropping entry"), so this departs from Mac; decision D98 filed, Mac half T2003

- [x] Keep dropping windows only the agent's store remembers, and keep carrying unknown/no-agent/held windows
- [x] An acceptance script that kills the agent, removes its session file, and reads the windows back
