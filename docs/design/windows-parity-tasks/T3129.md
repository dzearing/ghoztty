# T3129 - The Debug allocator reports one leaked allocation at every clean quit: relay_suspend.launchAsync joins the relay account path at startup and never frees it (relay_suspend.zig:640)

## Summary

Found by T3005's new Debug exit report (`perf-baseline.ps1 -Build Debug -Phase cycle`, `cycle.gpa_leak_report`). At a clean quit after 10 pane open/close cycles the DebugAllocator names exactly one live allocation:

```
error(gpa): memory address 0x1f9dff20180 leaked:
std/fs/path.zig:107 joinSepMaybeZ <- join
src/remote/relay_account.zig:122 accountPath
src/remote/relay_suspend.zig:640 launchAsync
src/apprt/win32/App.zig:1223 init
```

`launchAsync` takes `relay_account.accountPath(alloc)` and uses it only for the synchronous `isSignedIn(alloc, path)`; nothing frees it. It is a fixed-size, once-per-launch leak (a few hundred bytes), so it costs nothing in practice, but it is the only thing between the Debug exit report and a clean zero, and a clean zero is what lets that report catch a real leak. Fix: `defer alloc.free(path);` after the `catch return` (the restore/reconcile/retry calls take `alloc`, not `path`). Mac shares this file, so the fix lands for both.
