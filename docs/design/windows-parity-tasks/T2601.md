# T2601 - A terminal frame at a new size during an edge drag stalls ~0.75 ms on its first synchronous GL call (any call - a glGetError probe takes it over from the uniform upload); a glFlush at draw-begin does not hide it

## Summary

T2598 step 2 split the `synced` stage (target-ready -> synced in
`src/renderer/generic.zig`) with stamps between each upload, ReleaseSafe,
CHROME+PRESENT+NOREDIR+RESIZE_TRACE, idle box. All of the new-size excess
(~0.8 ms) sat on `frame.uniforms.sync` - a ~200-byte `glBufferSubData` - and
none on the cell uploads. A `glGetError` probe placed before it took the whole
stall over (probe 1.00-1.12 ms new vs 0.26-0.28 same; the uniform upload fell
to 0.25), so it is the frame's first synchronous GL round-trip, not the
buffer. A `glFlush` at `draw-begin` (`GHOZTTY_GL_PRIME`, four alternating
arms) did not move it.

It is not plain idle time: same-size frames after a 16+ ms gap did not stall
(n=3, thin), and new-size frames drawn under 1 ms after the previous present
did not either (0.34 ms, n=9). It shows on new-size frames after a 4+ ms gap
(n=107), the gap in which the UI thread does the window's own D3D/DComp work
for the resize step. Candidates: the GL driver's command thread parked and
woken by the first sync call, or the GL context waiting on GPU work the UI
thread's resize step queued (the interop/swap chain share the device).

Do: identify the GPU/driver on the box, try the same probe with the driver's
threaded optimization off (a per-app driver profile, for the experiment only),
and look at GPUView/ETW (`xperf -on ... DX`) across one drag step for what the
render thread waits on. Each stamp on the render trace costs ~0.25 ms of its
own (the log line), so keep stamps few.

## In plain terms

During a window-edge drag the terminal loses most of a millisecond waiting
for the graphics driver before it can start each new-size picture. This finds
what it is waiting on and whether it can be avoided.

## Goals

- [ ] name what the first GL call waits on (driver thread, GPU work, or other)
- [ ] remove or hide the wait, or record why it cannot be

## Validation criteria

- [ ] resize trace: the new-size frame's first GL round-trip within ~0.2 ms of a same-size frame's, alternating A/B on one build
- [ ] floor lanes, comp-present.ps1 and comp-chrome.ps1 stay green
