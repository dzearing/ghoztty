# T903 - test\win32 hardening: convert fixed hand-rolled GHOZTTY_PIPE_SUFFIX values to per-PID Set-GhozttyTestIsolation

## In plain terms

The automated tests each talk to their own private copy of the terminal now,
but many of them name that private channel with a fixed label. If an earlier
run of the same test crashed and left its copy running, the next run can end up
talking to the leftover instead of the copy it just started — and report a
result about the wrong one. Naming the channel per-run removes that whole
failure mode.

## Summary

Filed 2026-08-16 from T680. The isolation sweep left ~90 scripts on hand-rolled
fixed suffixes (`$env:GHOZTTY_PIPE_SUFFIX = '-t318'` and the like). Those are
SAFE against the user's app — an explicit suffix outranks the pane's baked
endpoint — but a fixed name is reused by every run of that script, so a leaked
instance from a crashed earlier run answers on it and the new run drives the
leftover. `Set-GhozttyTestIsolation` (lib\Isolation.ps1) appends `$PID` and
optionally adds the throwing asserts; T680 converted the seven worst scripts
plus msi-upgrade/deliver-windows-build, and this task is the mechanical rest.

Notes for the sweep:

- Scripts that save/restore the suffix (agent-upgrade, agent-session-cap, …)
  can keep doing so; the isolation call just replaces the assignment.
- A few scripts bake the suffix into CHILD environments or fixture strings
  (e.g. hook-json writes `-hjtest` into a generated script) — those need the
  dynamic value threaded through, not a blind replace.
- `test\win32\isolation-meta.ps1` already accepts either form; nothing about
  it needs to change.

## What was actually left (2026-09-20)

The sweep this task asked for was done by **4dc012073** (2026-08-21, T352),
five days after this card was filed: it keyed every hand-rolled suffix on
`$PID` and added `isolation-meta.ps1` section C so the fixed form cannot come
back. Re-verified on 2026-09-20 — no top-level script pins one, and C1 is
green.

What that sweep did NOT cover is the OTHER endpoint knob a script can pin:
`GHOZTTY_AGENT_INSTANCE`, which keys the agent's own control pipe, state dir
and autostart entry. `holder-adopt.ps1` pinned `'t1594other'` for the foreign
holder its section D deliberately starts, so a holder leaked by an earlier run
of that script was still serving on that lineage — and "did the foreign holder
survive the sweep?" would have been answering about the leftover. That is this
task's own failure mode, one variable over, so it is what this turn closed.
