# T1677 - The floor's +list poll gives up in 20s while one +list is allowed 30s, so a single cold call can outlast the whole wait

## Summary

Found while fixing T894. All three floor scripts poll with Wait-ListMatch (TimeoutSec = 20), whose body is a +list that is itself allowed ipc_timeout.default_ms = 30000ms. On a genuinely cold box the FIRST call can therefore consume more than the whole poll deadline: the do/while runs its body once, the deadline is already past, and the function returns a stale list. Need-Listed then reports 'the fixture never appeared in +list' - one clean failure, which is the right SHAPE, but a false one, because the app was coming up fine and the poll simply had less budget than one of its own calls. The wait should be at least as long as the call it repeats (and ideally derived from it rather than a second hand-written number), or each poll call should carry a short per-call bound via GHOZTTY_IPC_TIMEOUT_MS so the poll can actually poll.
