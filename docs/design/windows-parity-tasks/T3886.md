# T3886 - The perf baseline's busy CPU seconds vary 1.5x between runs of one binary, so a single-run audit reports regressions that are not there (T3880 was one)

## Summary

T3880's same-day interleaved A/B of ONE build (424c9e5ab, ReleaseFast, busy phase, 64 MB ascii) gave cpu_s 8.89 / 10.20 / 13.36 - a 1.5x spread - while -Compare judges busy cpu_s with the 'seconds' family (rel 0.30). Baseline-4's 7.50 s was a low draw, and audit-5's 17.47 s read as a 2.3x regression that the A/B could not reproduce (head mean 11.7 vs base mean 10.8). Fix the measurement, not the threshold alone: run the busy phase N times (>=3) per build and report median + spread, or find and remove the noise source (other lanes' load, test-desktop compositor, cpu_pct vs cycles - the T3111 cycle counter may be steadier than cpu_s). The audit procedure (docs/design/perf-audit/) must then gate on the median. Evidence: docs/design/perf-audit/t3880/ab.md.
