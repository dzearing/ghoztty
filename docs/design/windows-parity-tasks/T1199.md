# T1199 - The dashboard keep-alive launcher hardcodes one clone's path, so it starts the wrong repo's dashboard (or none) anywhere else

## In plain terms

The little helper that keeps the task dashboard alive has one machine's folder
path written inside it. On any other checkout it would quietly start the wrong
dashboard, or nothing at all - and nothing would say so.

## Summary

`scripts/dashboard-keepalive.vbs` is committed with `repo = "D:\git\ghoztty"`
on line 28. It is the same defect T1192 removed from the go-loop watchdog's
launcher, which is now GENERATED next to the script it launches with that
clone's paths baked in (`go-loop-boot.ps1`'s `Write-WatchdogLauncher`, plus a
`scripts/*-launch.vbs` ignore rule). The dashboard's copy was left alone because
it was outside T1192's scope, but it carries the same wrongness and the same
silence: a VBS launched with `//B //Nologo` reports nothing to anybody.

Two ways to fix it, and the choice is a mechanism call, not a user-visible one:
generate it the way the watchdog's is generated, or make it self-locating with
`WScript.ScriptFullName` + `Scripting.FileSystemObject`. Generating keeps one
pattern in the repo; self-locating keeps the file readable in a diff. Whichever
lands, `scripts/task-dashboard.ps1:104` builds the `wscript.exe //B //Nologo`
command line and is the caller to keep in step.

## Goals

- [x] The launcher finds `task-dashboard.ps1` next to itself instead of a
      committed clone path.
- [x] A harness proves it from a temp checkout and goes red on the old shape.

## Validation criteria

- [x] No clone-specific path is committed in the keep-alive launcher.
      (section A of `test\win32\dashboard-keepalive.ps1`: no quoted drive path
      outside a comment; it locates itself from `WScript.ScriptFullName`.)
- [x] The keep-alive starts the dashboard for the repo it was installed from,
      demonstrated from a second checkout or a temp fixture. (section B: the
      launcher copied into a temp checkout beside a recording stub, started by
      `wscript //B //Nologo` the way the task does, ran THAT checkout's stub
      with `-Port 7788 -NoPane` and not a second fixture's.)
- [x] A check goes red if a hardcoded path comes back, and has been watched
      failing. (section C every run: the pre-T1199 shape aimed at a second
      fixture is flagged by A's check and starts the wrong checkout's stub;
      `-NegativeControl` ends 1 FAILURE as designed. Guard row
      `dashboard-keepalive` in `scripts\guard-due.ps1`.)
