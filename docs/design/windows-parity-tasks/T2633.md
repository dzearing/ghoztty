# T2633 - chainfold.ps1 -Live back-to-back runs SKIP ALL for 5 minutes: the presence gate counts the previous run's own injected drag as user input (FrameLabDriver discounts its own input; the chain-fold recorder does not)

## Summary

Found on T2534 2026-11-01: after one -Live run, the next run's Assert-UserAbsent read 'keyboard/mouse input 66s ago' with nobody at the box - the last input tick was the recorder's own SendInput drag (21:53:05, timeline.json written 21:53:18). Each A/B arm then costs a 300 s wait, and T2485's log already shows the same 'second run SKIP (input 97 s)'. Fix: record the recorder's last send tick and pass Get-UserPresence -IdleSecondsOverride like lib\FrameLabDriver.ps1 (Resolve-FrameLabOwnInput / Set-FrameLabOwnInput, T2395) so only input after the run's own last send counts as a human.

## In plain terms

The frame-by-frame drag test only runs when nobody is at the computer. It was
treating its own previous run's fake mouse drag as a person, so running it twice
in a row made the second run give up and wait five minutes. Now each run leaves
a note saying "that last input was mine", and the next run reads it.

## Goals

- [x] a -Live run leaves a record of its own last injected input (the own-input ledger)
- [x] the next run's presence check discounts input no later than that record, and only that
- [x] input after the record is still a person; a stale or post-reboot record is ignored
