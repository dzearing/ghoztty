# T2594 - PaneDesk test 'a bitmap over a kept section ... at every size' is flaky: 70x40 is under a quarter of the 64x48 section, so keeps() maps a new section and the handle check passes only when Windows reuses the closed handle value (red in the win32 lane on 2026-11-01)

## In plain terms

One of the automated checks for how window backgrounds are drawn failed now and then for no real reason, which made a healthy build look broken. The check now uses sizes that test what it claims to test, so it passes every time and still catches a real regression.

## Goals

- [x] the test's sizes exercise the kept-section path it names
- [x] a compile-time check keeps the sizes inside the rule

## Summary

`src/apprt/win32/PaneDesk.zig` test "a bitmap over a kept section shows what was written through the kept view, at every size" uses sizes 64x48, 70x40, 64x48 and asserts all three share the first section. `Backing.sizeFor(64*48*4)` is 64 KB, and `keeps(65536, 70*40*4 = 11200)` is false (11200 * 4 <= 65536: under a quarter), so the code correctly maps a NEW section for the second size. The `expectEqual(section, backing.section)` then passes only when the system hands back the just-closed handle's value - which it usually does, so the lane is green most runs. Seen red 2026-11-01 01:30 inside test-reach-audit's win32 lane run (`PaneDesk.zig:185`), and green on the floor lane right after.

Fix (verified green in the floor's win32 lane on 2026-11-01, then held back so T2577's turn did not make 13 PaneDesk-covered harnesses due): sizes 128x96, 140x80, 128x96 (section 128 KB; 44800 * 4 > 131072), plus `comptime std.debug.assert(Backing.keeps(Backing.sizeFor(128 * 96 * 4), 140 * 80 * 4));` so the sizes cannot drift out of the rule again.
