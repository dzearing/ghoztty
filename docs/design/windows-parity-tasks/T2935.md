# T2935 - Turn the default path's divider-drag card clip (GHOZTTY_DRAG_CARD_CLIP, T2933) on by default once a mid-drag frame on the real desktop shows the card corners intact (desk in the corners, no square or torn corner on any frame)

## Summary

T2933 built the default path's drag hold behind `GHOZTTY_DRAG_CARD_CLIP=1`.
At the start of a divider drag, each card pane's own swap-chain root visual
takes the rounded card clip (`comp_overlay.RootClip`). Then its window region
is cleared once (`Window.holdOnOwnVisual`). After each desk paint, the desk is
blitted into the pane's own DC under the four corner squares
(`paintDragCardCorners`). At drag end the region is cut again with a redraw,
and then the clip is cleared.

Measured (T2874 probe, release, 120 Hz, 3 runs per arm): region cuts went
from about 1600 to 37 a run, and worst `cards_us` from 1.2-9.8 ms to
0.65-1.6 ms. Ticks with `cards_us` over 1.5 ms went from 6 to 1.

What is NOT known is how it looks. The clip is a DirectComposition commit
and the corner fill is a GDI blit. Neither is in the window manager's
transaction with the move, so a corner could show square or torn for a
frame. PrintWindow cannot photograph the pane (T214), and the test desktop
has no CopyFromScreen. So this needs a film on the user's desktop. Also
check the banner strip's top corners when the banner is the card's top
(`setBannerCardCorner`), with no window region under it.

If it looks right: flip the default (keep `GHOZTTY_DRAG_CARD_CLIP=0` as the
escape hatch) and close T2933's first validation criterion. If a corner tears:
commit the clip before `EndDeferWindowPos`, sized to the union of the old
and new shape, as T2933's summary proposed.

## Validation criteria

- [ ] a real-desktop film of a divider drag (2-4 panes, elevated style) with the knob on: rounded corners with desk behind them on every frame
- [ ] the same with a banner on the dragged pane
- [ ] default flipped; T2874 probe shows no `cards_us` tick over 1.5 ms in 3 runs
