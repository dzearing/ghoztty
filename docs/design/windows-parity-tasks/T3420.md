# T3420 - Linux L9k: viewer panes restore with the session

## Summary

Viewer panes persist in the session manifest and restore by re-opening their file or URL (current and home location both kept); an image at best-fit; a diff pane re-runs its spec in the persisted origin directory; a missing file restores as the in-page error card.

**Re-measured 2026-11-22 after T3397:** the manifest exists (`src/apprt/gtk/SessionLayout.zig`) and already captures a viewer leaf's `kind` + `viewer_location` and re-opens it there on restore (`captureLeaf` / `ctxViewLocation`). LEFT: persist and restore `viewer_home_location` and `viewer_origin_directory` (Viewer needs accessors for both), image best-fit on restore, a diff pane re-running in its origin dir, the missing-file error card, and a `test/linux/` acceptance for all of it.

## In plain terms

On Linux, quitting or crashing Ghoztty brought your terminals back on the
next launch, but a document or web page you had open beside them came back
only half remembered: its Home button pointed at wherever you had wandered,
a git diff lost track of which repository it was showing, and scripts that
addressed the pane by id lost it. Now a viewer pane comes back exactly as on
Mac and Windows: on the page it was showing, with Home still where you
opened it, the same id and name, a picture fitted to the pane, a diff of the
same repository, and a clear "Cannot read file" card if the file was deleted
meanwhile.

## Goals

- [x] the manifest records each viewer's Home and origin directory beside its location
- [x] a restored viewer keeps its pane id, name and Home, and re-opens where it was
- [x] a diff pane re-runs in the directory it was opened from
- [x] a picture comes back at best fit; a deleted file shows the error card
- [x] a `test/linux/` acceptance proves all of it
