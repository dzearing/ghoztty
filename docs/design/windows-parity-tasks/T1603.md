# T1603 - the share's loose agent is never asked which build it is when the copy onto it fails

## Summary

In scripts\deliver-windows-build.ps1 the loose-agent branch reads the stamp back only inside the else of the copy error, so the one path that LEAVES a stale binary there - a copy that could not land - is also the one path that never asks what is there. bootstrap.ps1 and ghoztty-agent-watcher.ps1 fetch that file, so a stale one reaches boxes the delivery never touched, and the run says only 'could not be written'. The per-location branch (T785) reads the stamp regardless and should be the model. Live control: pin the destination open with FileShare.Read the way section H of test\win32\deliver-windows-build.ps1 does.

## In plain terms

When a delivery could not overwrite the copy of the background agent on the
network share (because something had it open), it said only "could not be
written" and never checked which version was left sitting there. Other
machines download that file, so an old one could spread quietly. Now the
delivery always asks the file which build it is and names a stale one.
