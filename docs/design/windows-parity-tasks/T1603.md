# T1603 - the share's loose agent is never asked which build it is when the copy onto it fails

## Summary

In scripts\deliver-windows-build.ps1 the loose-agent branch reads the stamp back only inside the else of the copy error, so the one path that LEAVES a stale binary there - a copy that could not land - is also the one path that never asks what is there. bootstrap.ps1 and ghoztty-agent-watcher.ps1 fetch that file, so a stale one reaches boxes the delivery never touched, and the run says only 'could not be written'. The per-location branch (T785) reads the stamp regardless and should be the model.
