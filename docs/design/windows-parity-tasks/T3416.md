# T3416 - Linux L9g: image viewer panes (fit, zoom, live re-decode)

## Summary

Port docs/reference/viewer-image-and-diff.md image panes onto the WebKitGTK viewer: the extension list, best-fit open, zoom chords (Ctrl+0 = 100%), double-click to fit, re-decode on save keeping zoom when dimensions match. Decode through GdkTexture/gdk-pixbuf where WebKit lacks a format.

## In plain terms

On Linux, opening a picture in a side pane used to show "Image viewer panes
are not on Linux yet". Now it shows the picture, fitted to the pane without
ever blowing a small one up; Ctrl+0 shows it at real size, Ctrl +/- zoom,
double-click flips between fitted and real size, and saving the file from
another program refreshes it in place - keeping your zoom and position when
the picture is the same size. TIFF and other formats the web engine cannot
draw are decoded by the desktop's own image loaders.

## Goals

- [x] Image panes render through the shared template (`image.js`) with win32's shared zoom rules
- [x] Host decode (GdkTexture) for TIFF/HEIF and as the retry for any raster WebKit fails on; `.icns` by its largest PNG
- [x] Missing-codec card names the Linux loader package
- [x] Reload re-decodes as a new revision; same pixel size keeps zoom + scroll (Mac `reloadFromDisk`), different size re-fits
- [x] Headless acceptance (`test/linux/viewer-image.sh`) + none-lane unit tests

## Design (recorded per go.md 5b - mechanism, Claude's call)

The Mac draws on a native `NSScrollView`; Linux follows win32 (T1183) and
draws in the template instead. GTK has no elastic, centroid-pinch scroller to
inherit any more than win32 did, while WebKit's scroll container brings
kinetic touchpad scrolling and overlay scrollbars - and the template keeps
history, the address, `+list`'s url and the error card for free. The zoom
arithmetic stays native and shared (`win32/viewer_image.zig`), so all three
platforms answer "what is 100%" identically. Host decodes run on a worker
thread (`gdk_texture_new_from_filename` is documented thread-safe) and finish
the WebKit request from the main loop.
