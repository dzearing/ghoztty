# T3652 - Linux L11k5: single-window mode on GTK - closing the workspace on show hands the window to the one shown before it, a parked one closes in place, the last closes the window, undo brings it back on show

## Summary

Closing semantics (Mac workspaceWillClose/didClose; win32 T3184, T3200): Ctrl+Shift+W, the headerbar close, +close, the sidebar x and a last pane exiting; a close that needs confirming puts a parked workspace on show first so the dialog has a window; undo of a close brings the workspace back on show; the window closing with workspaces left (not at quit) gives the next one a window. Spec: docs/reference/window-modes.md (Closing).

## In plain terms

With "All in one window" chosen on Linux, closing things now behaves like the
Mac: closing the workspace you are looking at shows the one you were in
before it, in the same window; closing a hidden one just removes it; closing
the last one closes the window. The window's own close button closes what
you are looking at, and if that needs a "Close Window?" question, a hidden
workspace is brought into view first so you see what you are closing. Before
this, closing the first workspace made a second window pop up. Undo of a
workspace close is its own card (T3790), after window-close undo (T3665).

## Design (as built)

- GTK cannot hand a GtkWindow from one `Window` object to another the way
  AppKit hands an NSWindow between controllers (and win32 an HWND, T3184).
  So when the toplevel's OWN workspace closes with others open,
  `Workspaces.retire` closes the WORKSPACE - host bookkeeping and, on show,
  the hand-off - and `Window.becomeFrame` ends what made it one (its tabs,
  undo entries, sidebar, relay record, IPC name) while its GtkWindow stays
  mapped as the frame the others are shown in. Every window walk skips a
  frame (`IpcHandlers.WindowIterator`, the session layout, the mode relatch;
  the sidebar already skips a window without a sidebar). The last
  workspace's close destroys the frame on the next idle (`dropFrameIfEmpty`).
- Every close-for-good goes through `Window.closeNow` (retire, else
  destroy): the confirmation's Close/Disconnect, `+close`, an unasked close.
- `windowCloseRequest` on the toplevel routes to the workspace on show
  (`closeRequestTarget`); everything else asks for its own close
  (`Window.requestClose`): `win.close` (Ctrl+Shift+W, the menu, the
  keybinding), a workspace's last pane going, the `close-dialog` seam.
- `askToClose` shows a parked workspace first and presents inside the
  toplevel (`dialogParent`); `openDialog` looks in the window the
  workspace's dialogs live in (`dialogHost`), so `+close` refusing over a
  dialog and the seam read the right one.
- The close hand-off runs the same adopt steps as a switch (`adopt`),
  including the T3651 desk fade.
- Seam: `workspaces` gains `toplevel_frame`, `gtk_windows`,
  `mapped_windows`; `close-dialog --op=frame` is the toplevel's close button.
