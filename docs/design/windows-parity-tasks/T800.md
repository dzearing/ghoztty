# T800 - The loop's own banner hook (ghoztty-banner.sh) is unversioned user config - vendor it into the repo

## In plain terms

The script that draws the status banner above a Claude pane used to live only
in a folder on this one machine. Nobody could review a change to it, the other
seat could not see it, and rebuilding the box would have lost it. It now ships
inside Ghoztty itself: the app writes it out when it sets up a Claude session,
so the copy on disk is the copy in the repo, and changing it is an ordinary
commit like any other.

## Summary

T745's fix landed in ~/.claude/scripts/ghoztty-banner.sh, which is not in any repo: no history, no review, invisible to the other seat, and lost on a box rebuild. That script is also the biggest single CONSUMER of the banner feature on this box, so it is where banner regressions are met first - and a fix made there cannot be cited by a commit, which is how a defect gets re-reported. Vendor it (scripts/ or a small tools/ dir) with the user's ~/.claude copy installed from it, or at minimum keep a checked-in copy the hook is diffed against, so a change to it is a commit like any other.

**Already fixed** (verified 2026-09-16, the T404 re-check path). The vendoring
this card asks for landed in two commits and went further than "a checked-in
copy to diff against" - the app installs the script:

- `f935538a7` (2026-08-01) vendored the hook on the Mac side as
  `macos/Resources/Ghoztty/hooks/ghoztty-banner.sh`, bundled with the app.
- `59388143f` (2026-08-15, T866) vendored the Windows build's copy at
  `src/apprt/win32/assets/ghoztty/hooks/ghoztty-banner.sh`, with the pristine
  upstream mirror beside it in `assets/ghoztty/upstream/hooks/` and the
  divergence (every JSON operation on `ghoztty +json` instead of jq) stated in
  the file's own header.

`src/apprt/win32/BannerScriptInstaller.zig` writes that asset to
`~/.config/ghoztty/hooks/ghoztty-banner.sh` as part of the agent integration,
so the installed hook IS the repo's bytes - measured on this box: the installed
copy and `src/apprt/win32/assets/ghoztty/hooks/ghoztty-banner.sh` are
byte-identical (24,197 bytes, `diff` clean). The old
`~/.claude/scripts/ghoztty-banner.sh` this card names is the retired plugin's
path; `claude_plugin_migration.zig` (T870) retires it, and the stale copy still
sitting on this box is a separate defect, filed as **T1624**.

No new code was written for this card. What it was owed - a check that a change
to the hook cannot land unreviewed or drift - already exists and was run green
as the closing evidence.
