# T1832 - Windows windows all share one backdrop: Mac gives each new window (and +new-window --color=random) its own random one-hue gradient

## Summary

In the elevated style, +new-window --color=random randomizes the window's gradient desk instead of tinting its terminals (fe3f7c8da); a window opened by hand (Cmd-N / New Window menu / palette) gets one by default, while programmatic, moved and restored windows keep theirs (a516200d2). Hue comes from the whole wheel (5ba797c8c); a variant is one hue lit by a soft elliptical spotlight above the top center, the base grading darker toward the bottom-trailing corner (lighter on a light theme) (a34653b2a), with a dim pool of the complementary hue in that corner (b4a3216cc). Persisted as a seed in the session manifest and derived per current theme. Explicit hex, split colors and the flat style keep the terminal tint. Windows: Ctrl+Shift+N / New Window equivalents.

## In plain terms

On a Mac, every window you open by hand now gets its own colour: one random
hue, softly lit from the top, so two windows side by side are easy to tell
apart. On Windows every window had the same blue-teal background. After this
change a window opened with Ctrl+Shift+N / New Window (or by a script asking for
`--color=random`) gets its own gradient too, keeps it after a restart, and the
terminals inside keep their normal colours.

## Goals

- [x] `+new-window --color=random` in the elevated style gives the window its own gradient and leaves the terminal untinted
- [x] A window opened by hand (New Window action, menu, palette, viewer chord; remote parent too) gets one by default
- [x] Startup, programmatic, moved and restored windows keep what they had; the machine chooser's Local row stays ocean, as on Mac
- [x] The seed persists in the session layout and a Mac blob's `deskVariant.seed` is read across; same seed = same gradient on both platforms
- [x] Flat style and explicit hex keep the old terminal tint

## Decisions recorded

- **Same generator, same draws as Mac.** `desk_palette.zig` ports Mac's
  SplitMix64 and makes the draws in Swift's argument-evaluation order, so one
  seed is one gradient on both platforms (a cross-machine restore keeps its
  look). Mechanism choice, not filed as a decision.
- **Manifest field** is `desk_variant: <u64>` (snake_case, like the rest of the
  win32 file); Mac's own spelling `deskVariant: {seed}` is read from Mac blobs.
  The Mac-side reader of win32 blobs needs the matching field (filed for the
  Mac seat).
