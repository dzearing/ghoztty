# T2811 - registration-sites.ps1 D5 flaked once (2026-11-07 17:00, green on the next run): HKCU\Software\Classes\ghoztty-debug existed after the gated launch - the key is shared by every debug build on the box, so another lane's app can write it between D4 and D5

## Summary

Seen once during T2806's due sweep: run 20261107-170053 failed only D5
(`HKCU\Software\Classes\ghoztty-debug` present after the gated launch),
while the runs before and after it (20261107-165222 apart from an unrelated
A2 row, and the next one, ALL PASS 21) were green on the same build. D2-D5
read and delete one key that EVERY debug build on the box writes when it is
not location-gated, so another lane's or worker's debug app launching
between the D4 delete and the D5 read makes this assertion fail without the
gated build having written anything.

Fix direction: make D5 attribute the key, i.e. fail only if the
`shell\open\command` value names THIS repo's build (the same test D3 uses), or
give the harness a private class-name lineage via an env seam, rather than
asserting the shared key is absent.

## Validation criteria

- [ ] D5 fails only when the key names this build (negative control: the ungated control launch still reddens it)
- [ ] registration-sites.ps1 ALL PASS with another debug build launching beside it
