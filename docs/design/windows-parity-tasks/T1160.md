# T1160 - The soak's renderer-fps bar was calibrated against the user's terminal, and needs real numbers from a full 30-minute run

## Summary

Found while fixing T1158. soak.ps1 read GHOZTTY_PERF telemetry out of the USER'S %LOCALAPPDATA%\ghoztty\ghoztty.log, because LOCALAPPDATA was not isolated - so the slice it graded mixed the soak's own app with the terminal the user was working in. Its 'median fps under load >= 20' therefore passed on the user's busy frames rather than the subject's. With the sandbox in place the population is bimodal (per-window sampling: idle windows report fps=1, rendering ones sit at the 60 cap; measured over 534 samples on a 2-minute run: median 1, p75 31, p90 60). T1158 replaced the median bar with 'p90 >= 30', which is a real floor with real margin - but 30 was chosen from ONE two-minute run, which is not how a soak threshold should be set. This task is the calibration: run the full 30-minute soak several times, look at the actual p90 distribution, and set the bar (and possibly the statistic) from that. Consider also whether the sampler should tag windows as loaded vs idle at the source, which would make the statistic meaningful instead of inferred.

**What is left (re-verified 2026-10-22):** T1147 already did the source-tagging half - every `perf` sample names its pane, and the soak grades each loaded pane against its own floor (stream 30 / altscr 15 / grow 30) instead of a pooled percentile. Those floors came from one 5-minute run on 2026-08-31. The calibration this task asks for is still owed: full 30-minute runs of the current release build, per-pane distributions recorded, floors confirmed or moved from them.

## In plain terms

The long-running stress test checks that the terminal keeps drawing smoothly while several panes pour out text. Its "smooth enough" line was set from one short run, so nobody knows whether it would catch a real slowdown or trip on a normal one. This runs the full-length test several times and sets the line from what it actually measures.

- **soak-stream: floor 30 stays.** p90 sat on the 60 cap in both runs, half an hour each; the one dip (min 19, run 2) is a single second and does not move the p90. A floor at half the cap catches a renderer that halves its throughput without tripping on a stray slow second.
- **soak-grow: not a fps subject on a full run.** Its 150k lines finish in ~13 s, after which the unfocused pane draws nothing and emits nothing; the harness already reports it "finished ... not graded". Its value is the big-scrollback `+read` latency (22-30 ms), which is graded separately.
- **soak-altscr: no data, because of a real defect.** The generator was confirmed running (new setup check) and still the pane presented no frame all run. Repro: it renders at 21-24 fps until soak-stream is split (soak-grow), then never presents again - filed as **T2163** (P1). Its floor calibration is **T2164**, deps T2163.
- **The "other" fps=1 pane** in both reports is a stray unnamed `window-1` that every cold `+new-window --target=X` auto-launch opens - filed as **T2162**.
