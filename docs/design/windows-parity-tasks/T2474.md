# T2474 - A minimized or fully covered window should give back its panes' render-target memory and redraw cleanly when shown again (Mac shrinks hidden targets to 1x1)

## Summary

Mac 1bc34a8d7 adds releaseHiddenTargets in shared src/renderer/generic.zig, gated on GraphicsAPI.presented_target_outlives_frame - Metal only (~35 MB back per occluded 1200x800 pane). The win32 build renders through OpenGL (swap_chain_count = 1), which re-presents its last target on a no-op draw, so the shared hook is deliberately off here. Translate the feature, not the mechanism: measure what a minimized / cloaked / fully covered win32 window holds per pane, and if it is material, free it on occlusion (WM_SIZE SIZE_MINIMIZED, DWM cloak, occlusion) and force a full redraw on show, proving no blank or garbage frame on restore.

## In plain terms

A Ghoztty window you minimize, or hide behind other windows, kept every
pane's drawing memory the whole time nobody could see it - about 6 MB for a
four-pane window, more for a big or maximized one. Now a hidden window gives
that memory back, and every pane redraws in full the moment the window is
shown again, so nothing on screen looks different.

## Goals

- [x] measure what a hidden window holds per pane (~6 MB of render-target storage for four panes in a 1400x900 window; grow-only renderbuffers, T2577)
- [x] free it when the WINDOW is minimized, covered or parked - never when a pane is only behind another tab (hero mode reads those)
- [x] every pane comes back fully drawn on show, no blank or stale frame
- [x] an acceptance harness that measures it and can go red

## Validation criteria

- [x] minimizing gives back the targets: dedicated GPU drops 5.0 MB of ~6 MB on each of 4 minimizes, re-taken on restore, flat across cycles - `test\win32\hidden-window-memory.ps1` A1/A2/A4 via acceptance-parallel (20261102-000705, 20261102-001212)
- [x] every pane redraws at its own size with text after every restore - same harness A3 (capture-pane reads the pane's last presented target, which the release forgets, so a pane that never redrew fails it) and A5 (16/16 release + 16/16 full-redraw log lines)
- [x] a fully covered window releases too and redraws once uncovered - same harness C1/C2
- [x] the meter can see it: `-NegativeControl` (window left on screen) turns A1/A2/A5 red; the unfixed build (7d0135e39) read 0 MB dropped and 0/16 log lines
- [x] floor lanes green: floor-lane -Lane all ALL LANES PASS (lib/none/win32/agent); scoped harness floor PASS; due sweep 54 green, 9 red, every red also red on the unmodified 7d0135e39 build or owned by an open acked task (T2438, T2628, T2431, T2380, T1854, T2518, T2631, T2362; stack-fold-slide F13 is T2501, red 2 of 3 on the base build)
