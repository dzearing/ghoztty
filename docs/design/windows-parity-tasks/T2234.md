# T2234 - +rearrange cannot be undone on Windows: Mac's Cmd+Z restores the previous layout, Windows registers no undo for it

## In plain terms

On a Mac, rearranging a window's panes (from the CLI or the rearrange mode) can be undone with Cmd+Z. On Windows the same rearrange is permanent: there is nothing to undo, so a mistaken layout has to be rebuilt by hand.

## Summary

Found by T1327 while checking the skill document's claims against the Windows build. Mac's `IPCServer.swift` registers every `+rearrange` with the undo manager under "Rearrange Layout" (`PaneMoveCoordinator.swift`), so Cmd+Z restores the previous tree. Windows' `IpcHandlers.handleRearrange` swaps the tree and re-persists it but records no undo; `close_undo.zig` only covers closes. The Windows undo chord is Ctrl+Shift+Z (`Config.zig`, T1825), so the natural shape is a rearrange entry on the same undo stack.

Until this lands the Windows install of the ghoztty skill says rearrange is not undoable (`src/apprt/win32/skill_rewrite.zig`); when it lands, change that row back to the undo wording.
