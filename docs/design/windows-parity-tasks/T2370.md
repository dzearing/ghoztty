# T2370 - The focused-pane glow's fade tick costs ~15.5 ms of a 16.4 ms frame (it repaints the whole pane desk every tick), so on the vsync frame clock it still drops ~5% of frames and holds the UI thread ~95% busy for the 250 ms fade; paint only the glow ring

## Summary

Found by T2365's harness (`test\win32\frame-clock.ps1`, 2026-10-27). With
every animation on the vsync frame clock, a do-nothing probe subscriber
lands 240/240 frames one period apart, but the focused-pane glow
(`Window.focusGlowTick`, id 0x4647) costs a mean 15.5 ms (max ~20 ms) per
tick against a 16.4 ms period. A tick that overruns the frame makes the next
vblank find the previous frame still in flight, so the glow still skips
~2.5-5% of its frames, and for the 250 ms of every fade the UI thread is
almost entirely busy painting.

Cause: `focusGlowTick` calls `repaintPaneDesk()` - a synchronous repaint of
the whole pane desk - to move a glow ring that occupies a thin band around
one or two panes (T2232 already measured ~15 ms per desk repaint).

Fix: invalidate/paint only the union of the old and new glow rings (or move
the glow onto its own layered/DComp surface, see T2360) so a tick costs well
under a millisecond.

## In plain terms

When you click from one pane to another, a soft glow slides off the old pane
and onto the new one over a quarter of a second. Ghoztty used to redraw the
whole window background for every frame of that fade, which nearly filled
each frame and made other animations beside it stutter. Now it redraws only
the thin ring where the glow actually is.

## Goals

## What landed (2026-11-05)

Re-verified first: since filing, T2574 put the fade on the compositor (one
paint per focus change on a real desktop) and T2454 made desk paints partial,
so the stepped path - the test desktop, a box without DComp, a failed glow
layer - was down to 4.4 ms a tick (measured, frame-clock.ps1, 08:04). Three
changes:

- `PaneDesk.Memo.dirty`: a glow-level change marks four thin edge bands
  (rim depth inside, glow reach outside) and the corner squares the arc
  needs, laid without overlap (`Rects.addGlowBands`), instead of each lit
  card whole plus the shadow reach. ~5.6% of the desk instead of ~half.
- `pane_elevation.paintCardsWith`: a card that misses the buffer is skipped
  before its glass tables are built, and the default sheet's table is built
  once per style in `Prepared` (`sheetLut`) - a partial compose calls the
  painter once per band.
- `PaneDesk.blitUnder`: after a changed-only paint, the desk under layered
  panes is re-blitted only where it changed.
