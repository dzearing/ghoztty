# T2488 - Composition step 2b: prove the composition swap-chain present ON SCREEN (WGC ghost capture: right way up, 0 torn/blank frames across a 9-pane glide), hold the grid during glides like Mac paneContentFreeze, then make GHOZTTY_COMP_PRESENT the default

## Summary

T2466 landed the composition present path (`src/renderer/gl_comp_present.zig`)
opt-in behind `GHOZTTY_COMP_PRESENT=1` and proved on the background test desktop
that it builds, presents, falls back and rebuilds (`test\win32\comp-present.ps1`).
What that desktop cannot show is the picture DWM composes.

**Scope of this task (rewritten 2026-10-30 when the turn split it):** the
ON-SCREEN ORACLE, and one still frame proved with it on both present paths. The
rest of the original card is split out: the 9-pane glide (T2512), the grid hold
(T2513), the default flip (T2514), and a translucent-window check (T2515).

## In plain terms

The new, smoother way of putting terminal pixels on screen could only be tested
somewhere Windows never actually draws. This adds a way to film the real screen
picture of a test window while the user keeps working - nothing pops up, nothing
takes focus - and uses it to show that a terminal looks exactly the same, right
way up, on the new path as on the old one.

## Goals

- [x] A debug-only launch knob that makes every app window a ghost (`GHOZTTY_DEBUG_GHOST`)
- [x] A whole-frame Windows.Graphics.Capture grab of another process's window
- [x] An on-screen oracle script that scores right-way-up and glyph agreement with capture-pane, both paths
- [x] A negative control that proves the oracle goes red on an upside-down picture
- [x] The remaining steps filed as their own tasks

## What landed

- `src/apprt/win32/Window.zig`: `GHOZTTY_DEBUG_GHOST` (Debug builds only; a
  release build ignores it). `=1` is the T2463 shape - layered alpha 1/255,
  click-through, tool window, never activated, bottom of the z-order. `=bottom`
  is the same WITHOUT the layered alpha: opaque, at the bottom of the z-order.
- `src/apprt/win32/wgc_capture.zig`: `Capture.grab()` reads a whole frame back
  (top row first), sharing frame acquisition with the one-row `next()`.
- `src/comp_spike_main.zig`: `ghoztty-comp-spike --grab-hwnd=<n> --out=<bmp>`
  films one frame of any window and writes a top-down BMP.
- `scripts\comp-present-onscreen.ps1`: per arm (knob on / off), a ghost app on
  the input desktop, marker lines printed, WGC grab, capture-pane of the same
  pane, then: not blank, right way up (ink in the top half, bottom third
  background), and glyph overlap with capture-pane >= 0.80 after aligning.
  `-NegativeControl` flips the grab and must go red. It lives in `scripts\`
  for the reason `comp-spike.ps1 -Live` does: it needs the input desktop.

## Findings

1. **A DComp visual under a LAYERED top-level is not in the composed picture.**
   With `GHOZTTY_DEBUG_GHOST=1` (LWA_ALPHA 1/255) the knob-on pane grabbed BLANK
   while the knob-off pane drew. Opaque (`=bottom`) both draw. So the ghost for
   the composition path is the opaque bottom one (the script's default) - it
   takes no focus, but it is visible wherever the desktop itself is uncovered.
   Real translucency is per-pixel alpha, not LWA_ALPHA (T1787), so this is not
   a user bug today; T2515 checks the translucent picture before the flip.
2. **A ghost is occluded, so the app parks its renderer after the first frame**
   (T1951): the script sets `GHOZTTY_TEST_NO_OCCLUSION=1`.
3. **The pane draws over the window's gradient backdrop**, so "ink" is scored by
   luminance rather than distance from one background colour.
