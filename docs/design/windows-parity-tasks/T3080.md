# T3080 - perf-baseline busy phase is too noisy to judge a per-frame fix: the same release binary read 27.9 s then 13.7 s app CPU for the 64 MB type (T2971)

## Summary

T2971 ran scripts\perf-baseline.ps1 -Build Release -Phase busy twice on one zig-out-release build (temp\T2971-after.json, -after2.json): cpu_s 27.89 vs 13.72, wakeups/s 43.4k vs 26.8k, resize cpu_pct 42 vs 21 - and both land outside baseline-1's tolerance in opposite directions. The audit's remaining PA-R* fixes are per-frame savings well under that noise, so the harness cannot confirm or refute any of them. Investigate the variance (other load on the box, CPU frequency, the type source, a cold vs warm file cache) and either pin it down (N repeats + median, a quiet-box precondition) or state the smallest effect the busy phase can resolve. Note the -Compare 'N of 11 metrics' count is also wrong (printed 191 of 11 against baseline-1).
