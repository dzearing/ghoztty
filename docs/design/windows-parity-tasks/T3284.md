# T3284 - Mac: the tab a pane drag rests on shows nothing while the dwell clock runs (Windows lights it since T1541)

## In plain terms

When you drag a pane onto a tab and hold still, the tab opens after half a
second. On Windows the tab now lights up while you wait, so you can see it is
about to open. On the Mac nothing changes until it opens. The Mac should show
the same "about to open" look.

## Summary

T1541 gave the Windows tab strip a `dwelling` surface: the tab button a pane
drag rests on, while the 500ms dwell clock runs, is drawn lifted past hover
with the selected tab's full rim, and goes dark when the pointer leaves it,
the dwell fires, or the drag ends. It never appears without a drag.

On Mac, `PaneDragSession.updateDwell` (macos/Sources/Features/Splits/
PaneDragSession.swift) already publishes `hoveredTab` for exactly this, but
nothing draws it - the tab bar is AppKit's native one. Translate the feature:
give the tab under `hoveredTab` a visible pressed / about-to-open state for the
life of the dwell timer (an overlay on the tab button rect, or whatever the
native tab bar allows), cleared by `cancelDwell`, `selectDwelledTab` and the
drag ending.

## Validation criteria

- [ ] Mid-dwell the tab under the drag shows a distinct state; it clears on
      leave, on fire, and on drag end.
- [ ] A plain pointer resting on a tab with no drag shows only the normal
      hover.
