# T3800 - Linux AppImage: re-check the /tmp WebKit link before each viewer, and let two users share a box

## Summary

T3658's AppRun checks /tmp/.ghoztty-appimage-webkit (the path the bundled libwebkitgtk spawns its helpers from) once at launch: it must be this user's symlink, else the launch stops. Two gaps. (1) A long-running app whose link is removed by a tmp cleaner (systemd-tmpfiles ages /tmp entries on some distros) could later spawn a web process through a link another user planted in its place. The GTK app should re-validate the link (lstat owner == getuid, readlink == /usr/lib/webkitgtk-6.0, recreate when missing) before creating a WebView in an AppImage launch, and refuse the viewer with its error card otherwise. (2) The path is fixed at build time, so a second user on the same machine is refused while the first one's link exists. Options: a per-uid path rewritten into a cached copy of libwebkitgtk on first launch, or a path under XDG_RUNTIME_DIR if one fits the 39 bytes. Validate in test/linux/package-appimage.sh.
