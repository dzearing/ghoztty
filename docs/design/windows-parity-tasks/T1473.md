# T1473 - A window opened just after the local agent dies loses persistence silently, and the agent never comes back

## In plain terms

If the background service that keeps your terminals alive dies, and you open a
new window in the second or two before Ghoztty has noticed, that window comes
up as an ordinary shell with no persistence — and Ghoztty does not start the
service again afterwards either. Nothing tells you: the window looks completely
normal, right up until you close the lid and find the session was never saved.

## Summary

Found while validating T674, on the background test desktop
(`test\win32\agent-job-escape.ps1 -TestDesktop`, about one run in four).

The shape, from the app's own captured stderr on a failing run:

1. The app is up, connected to its local agent.
2. The agent is killed out from under it.
3. Within ~1s a `+new-window` arrives. The app does NOT re-resolve its agent —
   it opens the pane on a plain local shell:
   `info(surface): local shell integration injected shell=cmd`, immediately
   followed by `warning(io_thread): error in io thread err=error.ConnectionClosed`.
4. No agent is spawned, then or later. A run 40s longer still shows none, and
   the layout syncs that follow carry `snapshot_bytes=0` — the session state is
   not being captured either.

On the runs that pass, the app has already noticed the dead connection when the
window arrives, re-resolves, and spawns a fresh agent (visible as
`in-place recovery: rebuilt N window(s) on the new agent connection`). So the
defect is the gap between the agent dying and the app noticing: a request that
lands inside it degrades to a non-persistent pane silently and permanently,
instead of waiting for (or forcing) the re-resolve.

Also note the earlier line in the same log:
`agent upgrade check: session probe failed err=error.ConnectionClosed (treating as unknown)` —
the app HAS evidence the connection is dead at that point and does not act on it.

## Where to start

- `src/apprt/win32/LocalAgent.zig` — the find-or-spawn path and whatever
  decides a surface may fall back to a local shell.
- The fallback should be a LAST resort with a warning, not a silent first
  answer while a re-resolve is still possible; and a failed session probe is a
  reason to drop the cached connection, not to shrug.

## Validation criteria

- [ ] An acceptance arm kills the agent and immediately asks for a window; the
      new pane is agent-backed (or the app says out loud that it is not)
- [ ] The app spawns a fresh agent after the old one dies, without needing a
      correctly-timed request to trigger it
- [ ] `test\win32\agent-job-escape.ps1 -TestDesktop` no longer needs the 5s
      settle T674 put between the agent kill and the window request
- [ ] Floor green
