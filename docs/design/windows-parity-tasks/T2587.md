# T2587 - Honor macos-pane-min-width / macos-pane-min-height: the configured pane minimum decides when a row stacks, live on reload (Mac 92ab0c9f1)

## Summary

Mac 92ab0c9f1 adds macos-pane-min-width (default 225, clamped 120-800 by Config.finalize) and macos-pane-min-height (125, 80-600); the minimum reaches the layout in ONE place for both the grid and the stashed-pane slots, keyboard resize and the lone-divider drag pass it to SplitTree as minimum:, and it is read on every layout pass so a reload restacks on the next one. Windows: pane_stack_layout.zig hard-codes default_minimum_width 225 / height 125 DIP (and pane_stack_grid.zig comments the same); take both from the config (the keys are shared core, arriving with the T2490 merge; Windows already honors macos-pane-style/-glass by the same name). Mac reference: docs/reference/stacked-panes.md + pane-style.md; tests aConfiguredMinimumDecidesWhenARowStacks, ConfigTests.paneMinimumSize.

## In plain terms

On Mac you can now say in your config how small a pane may get before a row of
panes starts stacking (`macos-pane-min-width` / `macos-pane-min-height`). On
Windows the setting was read but ignored: rows always stacked at 225 x 125.
After this, Windows uses the configured size too, and changing it in the config
re-lays the open windows on reload.

## Goals

- [x] The grid's stacking minimum comes from the config (default 225 x 125, clamped 120-800 x 80-600)
- [x] A config reload that changes the minimum relayouts every open window
- [x] Unit tests mirroring Mac's aConfiguredMinimumDecidesWhenARowStacks + the clamp

## Notes

- Mac also passes the minimum to `SplitTree` for keyboard resize and the lone-divider drag. Windows has no pane-size floor on those paths at all (they clamp by ratio in `split_resize`/`split_geometry`, a documented divergence since T2125), so there is nothing to thread there; the grid's stacking is where the minimum lives on Windows.
