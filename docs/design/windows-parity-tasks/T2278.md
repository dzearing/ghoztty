# T2278 - Windows sidebar icons are not coloured per pane: on Mac each pane has its own hue, its sidebar icon is drawn in it, and hovering a row or tile tints that pane's card (Mac 075d787d1, dc2bbab6b, 75dc046e3)

## Summary

Mac 075d787d1: each pane gets a hue by golden-ratio steps along its tree position; hovering a tile or row tints the pane's card in that hue (in 0.12s, out 0.2s). dc2bbab6b: the hover tint is a 10% wash with a 45% rim. 75dc046e3: only the GLYPH carries the hue (no tinted tile glass); hues are light and soft on a dark theme, deeper on a light one, so icons contrast with the sidebar; unfocused icons only slightly quieter. Windows sidebar draws monochrome icons/monograms.

## In plain terms

On Mac every pane now has its own colour in the side list of panes: its icon is
drawn in that colour, and pointing at a pane's row washes the pane itself in
the same colour, so you can see at a glance which pane a row means. On Windows
the icons were all plain grey and pointing at a row did nothing to the pane.
Now Windows does both, with the same colours and the same quick fade.

## Goals

- [x] Each pane gets Mac's hue: golden-ratio steps from 0.58 along its place in its tab's tree (stashed panes included), so a list reorder recolours nothing.
- [x] The sidebar glyph (row and rail tile) is drawn in it: light and soft on a dark theme (S 0.42, B 1), deeper on a light one (S 0.7, B 0.62); full on the focused/hovered row, 80% elsewhere.
- [x] Hovering a row or tile tints that pane: 10% wash, 2 DIP rim at 45%, following the pane's rounded card; in 0.12 s, out 0.2 s easeOut; works for terminals and viewers, and across windows in the all-windows scope.

## Design notes

- The tint is `HoverTint.zig`, the `BellBorder` shape: a per-pane layered,
  click-through popup owned by the pane's child HWND, per-pixel alpha via
  UpdateLayeredWindow, fades as `SourceConstantAlpha` on a timer. It lives on
  `PaneView` (kind-generic, so viewers tint too) and is destroyed with it.
- The hovered pane is app-wide (`App.sidebar_hover_pane`, Mac's
  `PaneSidebarHover.shared`), compared by identity only; each sidebar clears
  only the target it set, so moving between windows' sidebars never fights.
- Out of scope, filed elsewhere: the rail showing kind glyphs instead of
  monograms and the busy sheen (T2279); the hover-open card goes with T2289.
