# T1847 - The Windows pane sidebar forgets pinned and hidden across a restart: not in the session layout, and new windows only remember the last choice until the app quits

## Summary

Follow-up of T1828. Mac persists paneSidebarPinned (and hidden) per window in the session-layout manifest (additive optional fields) and remembers the last choice for new windows in UserDefaults, plus the panel width preference. T1828 keeps the new-window default in memory only (PaneSidebar.remembered). Translate: per-window fields in the win32 session layout, and a per-user preference store for the default and the width.

## In plain terms

If you pin the pane sidebar open, hide it, or drag it wider, Ghoztty forgets
that the moment you quit: the next launch is back on the narrow rail. After
this lands, new windows open the way you last left the sidebar, and windows
brought back by session restore come back exactly as each one was.

## Goals

- [x] New windows start from the last pin/hidden choice and panel width, across a restart
- [x] Each window's pin and hidden flags are saved with the session layout and restored with it
- [x] A Mac-written layout's sidebar flags come across too
