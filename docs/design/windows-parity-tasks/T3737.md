# T3737 - Linux: the command palette's 'New Tab/Window/Split Right/Split Down with Shell…' rows open the target on a shell you pick (Linux half of T3751)

## Summary

Linux half of T3735's palette piece (Windows T3751, daa060965): four palette rows, "New Tab with Shell…", "New Window with Shell…", "Split Right with Shell…" and "Split Down with Shell…". Choosing one keeps the palette open and swaps its list for the installed shells; Escape goes back to the commands; picking a shell opens that target on it, in the folder a new pane from the current one starts in, on the local agent when session persistence is on. Hidden in a remote machine's window.

Split on 2026-11-27 (the card carried four Windows tasks' worth): Restart Pane with Shell is **T3855**, the per-shell starting folder (`shell-working-directory`) is **T3856**, restore on each pane's own shell is **T3857**.

**The shell list is the Settings > Shell list, not `/etc/shells`** (assumption, recorded here, no decision filed - a mechanism choice): `settings_controls.posix_shells` (zsh, bash, fish, nu - the Mac's list) found on PATH, by absolute path, through one catalog both read (`shell_pick.catalog`, `SettingsWindow.installedShells`). A stock Ubuntu `/etc/shells` lists `/bin/bash` and `/usr/bin/bash` (one program twice), `rbash`, and `tmux`/`screen`, none of which a person means by "a different shell", and Windows' rows also read its Settings list. The pane runs `[<path>]`, exactly as `+new-window --shell=<path>` with no `--command` runs it.

## In plain terms

On Linux there was no way to open a tab, window or split on a different shell than the default one without typing a CLI command. Now the command palette has "… with Shell" rows: pick one, then pick bash, zsh, fish or nu from the shells actually installed, and the new tab, window or split comes up on that shell in the same folder you were in.
