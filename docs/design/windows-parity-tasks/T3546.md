# T3546 - Linux L9j-4: screenshots into the GTK feedback composer from the app's own render

## Summary

The composer's + button and Ctrl+Shift+S take a pane screenshot, and pasting an image inserts an [Image #N] chip with the stable-number carousel. Wayland and headless Weston have no global capture, so the picture comes from our own render: webkit_web_view_get_snapshot for the page, gtk_widget_snapshot / gsk_renderer_render_texture -> GdkTexture -> PNG for the whole pane (linux-port.md translation table). Build the capture once and share it with T3359 (the headless harness screenshot). Images land in the report's images/ folder with pixel size and byte count. Depends on L9j-2.

## In plain terms

On Linux, the feedback box under a viewer pane could only take words; a
picture pasted into it was thrown away. Now it has a `+` button (and
Ctrl+Shift+S) that snaps a picture of the page you are looking at, and a
pasted or dropped picture is kept too. Each one shows as `[Image #N]` in the
text with a small thumbnail under the box, and the report it files carries the
pictures as PNG files next to it.

## Goals

- [x] `+` and Ctrl+Shift+S take a picture of the pane from the app's own render (no global capture on Wayland)
- [x] A paste or drop in the composer attaches the picture
- [x] Each picture is an atomic `[Image #N]` chip with a stable number; deleting one takes the picture out, the rest keep their numbers
- [x] A thumbnail strip under the box mirrors the chips; clicking a thumbnail selects its chip
- [x] A send writes `images/image-N.png` beside report.json, with pixel size and bytes, linked from the body
- [x] The capture is one function (`pane_snapshot.png`) the harness screenshot (T3359) can reuse

## Decisions made here

- **What `+` captures**: the pane's PAGE (`Viewer.view`), not the nav bar or
  the composer band. The address is already in the report's `location`, and
  a picture of the composer inside its own report is noise. The Mac's `+` is
  an interactive region capture; the desktop-portal route to that on Linux is
  filed as a follow-up (see Progress log).
- **The capture route**: `gtk_widget_paintable_new` -> `GtkSnapshot` -> render
  node -> the window's GSK renderer -> `GdkTexture` -> PNG, rather than
  `webkit_web_view_get_snapshot`: one synchronous path that works for any
  widget (the harness screenshot wants the whole window), and the test proves
  the WebKit layer is in it.
