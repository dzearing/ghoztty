# T1959 - Run the four zig floor lanes in parallel with per-lane cache and prefix dirs, and prove the verdicts match a serial run on the same tree (T1955 item 4: 16-19 min to ~7-8)

## Summary

scripts\floor-lane.ps1 -Lane all runs lib, none, win32 and agent one after another. go.md:491 forbids lanes beside acceptance scripts, not lanes beside lanes. Run them in parallel, each with its own --cache-dir and --prefix (the soak daemon's T401 isolation pattern). Watch for global-cache lock stalls, which the STALL watchdog must still name.

Split out of T1955 (P0, user 2026-10-14: 'feels like the tasks are getting slower ... selectively run things?'). The measurements and the ranked plan are in T1955.md.

## In plain terms

Every turn ends by running four big test suites, one after another, which
takes 16-19 minutes. They don't depend on each other, so this runs them at the
same time and the wait becomes as long as the slowest one. The verdict is the
same as before. A suite that fails only because the others were competing for
the machine gets one more run on its own before it counts as red.

## Goals

- [x] `-Lane all` runs its lanes side by side, each with its own cache and output folder
- [x] A crash, a leaked test, or a cache repair in one lane can never touch another lane
- [x] Too little memory for all four means fewer at once, never a refusal
- [x] A lane that fails only side by side is re-run alone and reported as contention, not hidden
- [x] Real lanes: parallel and serial verdicts match on one tree, with timings recorded

## Validation criteria

- [x] Parallel and serial runs on the same tree produce the same per-lane verdicts (both run once, compared).
  Run back to back on one tree on 2026-10-15. Parallel cold, serial and parallel warm all
  scored `lib#1=PASS none#1=PASS win32#1=PASS agent#1=PASS`, exit 0, and no lane needed an alone re-run.
- [x] Wall time for both is recorded in this file.
  See "Measurements" below.
- [x] A planted red in one lane still fails -Lane all, and a stall is still reported as STALL.
  `test\win32\floor-lane-parallel.ps1`, ALL PASS (26 assertions). A red lane plus a wedged lane
  exits 2 (STALL outranks FAIL), both are re-run alone and stay red, and the token reads
  `[side by side: FAIL]`. A lane red only side by side ends green with
  `FLOOR PARALLEL CONTENTION` naming it. The same planted set run `-Serial` scores the same
  words. A too-small commit budget runs one lane at a time.

## Measurements (2026-10-15, same tree)

| run | wall | per lane (lib / none / win32 / agent) |
|---|---|---|
| serial (`-Serial`, repo `.zig-cache`) | 1232s (20.5 min) | 54 / 323 / 443 / 400 s |
| parallel, cold lane caches | 443s (7.4 min) | 49 / 304 / 435 / 380 s |
| parallel, warm lane caches | 250s (4.2 min) | 5 / 141 / 240 / 201 s |

`-j11` per lane (32 logical cores / 3 heavy lanes). Free commit at start was 81 GB, so all four ran at once.

The FIRST cold attempt, before the fixes, failed. Four cold builds each fanned out a clang
per core for the same C dependencies (glslang, oniguruma) and hit `SystemResources` /
`clang exited with code 45`. One lane's cache heal then deleted those packages from the SHARED
global cache while the others were still compiling them, so one failure became four. Fixes that
landed here: per-lane `-j` share, `-Concurrent` children never heal the global cache, and a
lane that is not green side by side is re-run alone with the final verdict.
