# T3242 - perf-baseline's idle comparison across days reads box drift as a code regression: the same 11-15 binary read 0.50-0.55% cycle CPU then and 0.69-0.74% on 11-18 (T3234) - score idle against a pinned reference exe run interleaved in the same session

## Summary

baseline-4 (11-18) read idle cpu_cycle_pct 0.90 against T3111's 0.47-0.59 (11-15) and T3234 was filed as a P1 regression. T3234 re-measured the UNCHANGED 11-15 binary (D:\git\ghoztty-t3111-base, 4c8a7cd4f ReleaseFast) interleaved with HEAD on 11-18: old 0.686/0.736, HEAD 0.716/0.748 (docs/design/perf-audit/t3234/old-*.json). Same bytes, +35% cycles: box drift (same boot, Balanced plan, 3000 MHz nominal; likely P/E-core placement or background load). Exact cycles fixed the tick problem (T3111) but not the cross-day problem.

Fix: give the idle phase (and `-Compare` on idle fields) a reference arm - a pinned ReleaseFast exe of a known commit, run interleaved in the same session (`-ReferenceExe`), and report idle as the ratio head/reference plus the raw numbers. `-Compare` against an older JSON should refuse or flag `CROSS-SESSION` for absolute idle numbers without a reference. Also note it in docs/design/perf-audit/README.md.
