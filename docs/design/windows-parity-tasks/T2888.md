# T2888 - Mac: validate the T1402 lineage rule - a debug CLI in a release Ghoztty.app pane must not drive the release app

## Summary

T1402 taught the shared CLI a lineage rule: a DEBUG client declines the
installed release's baked `$GHOZTTY_IPC_SOCKET` (`ghostty-<uid>.sock` by name),
dials its own `ghostty-debug-<uid>.sock` instead, and prints a `note:` on
stderr. The rule is `ipc_client.honouredBaked` (`src/os/ipc_client.zig`); the
POSIX path applies it in `apprt.ipc.socketPath` (`src/apprt/ipc.zig`). Windows
validated it on the box; the POSIX branch is never compiled there (`lib` builds
for a Windows target), so it needs the Mac seat's build and a hand check.

## In plain terms

On a Mac, running the repo's debug `ghoztty` from inside the real Ghoztty app
should no longer quietly drive that real app. This checks the Mac build compiles
the change and behaves the way the Windows one already does.

## Validation criteria

- [ ] `zig build -Doptimize=Debug` and `zig build test` green on the Mac seat
      (the `honouredBaked` / `releaseEndpointBasename` tests run there)
- [ ] From a pane of `/Applications/Ghoztty.app` (read-only use; nothing is
      installed or changed), `zig-out/bin/ghoztty +list` prints the `note:`
      line and answers about the debug app (or "no running instance"), never
      the release app's windows
- [ ] The release `ghoztty` run from a pane of `Ghoztty-Debug.app` still
      drives the debug app (the direction the bake exists for)
