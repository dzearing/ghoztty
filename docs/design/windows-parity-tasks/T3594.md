# T3594 - Linux: a relaunch that restores the saved layout loses its own -e command - the -e window opens a plain shell

## Summary

Found by T3398's test/linux/agent-autostart.sh (2026-11-23). After an app run is SIGTERMed (layout saved), a relaunch with '-e <script>' rebuilds the saved windows and also opens a window for -e, but the script never runs: +list shows the newest window as a plain shell titled 'Ghostty', while one RESTORED window carries the script's title ('pane5.sh') over a fresh shell ('dead relaunchable session NOT re-run (restore policy); opened a fresh shell instead'). Suspected cause: the restored surfaces are built before the -e window and the first of them consumes the config's initial-command (-e), so the -e window gets none. docs/claude/linux.md (T3397) promises 'A restored launch shows only the restored windows unless it was given -e, which still opens its own' - its command must run. Fix in src/apprt/gtk/SessionLayout.zig restore / Surface initial-command handling; add an -e-runs-its-command check to test/linux/session-restore.sh. Check Mac/Windows behavior for the same shape while there.
