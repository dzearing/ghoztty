# T3594 - Linux: a relaunch that restores the saved layout loses its own -e command - the -e window opens a plain shell

## Summary

Found by T3398's test/linux/agent-autostart.sh (2026-11-23). After an app run is SIGTERMed (layout saved), a relaunch with '-e <script>' rebuilds the saved windows and also opens a window for -e, but the script never runs: +list shows the newest window as a plain shell titled 'Ghostty', while one RESTORED window carries the script's title ('pane5.sh') over a fresh shell ('dead relaunchable session NOT re-run (restore policy); opened a fresh shell instead'). Suspected cause: the restored surfaces are built before the -e window and the first of them consumes the config's initial-command (-e), so the -e window gets none. docs/claude/linux.md (T3397) promises 'A restored launch shows only the restored windows unless it was given -e, which still opens its own' - its command must run. Fix in src/apprt/gtk/SessionLayout.zig restore / Surface initial-command handling; add an -e-runs-its-command check to test/linux/session-restore.sh. Check Mac/Windows behavior for the same shape while there.

## In plain terms

On Linux, if you start Ghoztty with a command to run (`ghoztty -e myscript`)
while it is bringing back your windows from last time, your command never ran:
you got an extra window with an empty shell, and one of the restored windows
showed your script's name over an ordinary shell. Now the restored windows come
back as they were and your command runs in its own new window, in front.

## Root cause and fix

Core `Surface.init` hands `initial-command` (`-e`) to whichever surface is
`app.first`, and a GTK surface's core is only built when its GL area realizes.
The restore built its windows before activation queued the `-e` window, so a
restored pane realized first and took the command; it re-attached its session
(or opened a fresh shell), so the command vanished, and the `-e` window then
opened the default shell. Fix (the same shape as win32's T406, translated for
GTK's realize-time init):

- `src/apprt/gtk/class/surface.zig`: a pane built by a restore (`restored`)
  nulls `initial-command` in its own config, so it can never take it whatever
  order panes realize in.
- `src/apprt/gtk/class/application.zig`: a restored launch with `-e` opens its
  window through `Action.newWindow` with the command as an explicit override
  (not `activate`'s bare `new_window`), after the restore so it is in front.
