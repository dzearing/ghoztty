# T2463 - comp spike: score frame cadence PER WINDOW with Windows.Graphics.Capture (the system-wide DComp compose clock reads 1.0 even when nothing animates, so it cannot tell gdi from comp)

## Summary

T2360 spike finding 2026-10-29: DwmGetCompositionTimingInfo counters advance per call on this build, and DComp frame stats are system-wide and saturated by the users desktop (idle mode scores advance 1.000). Capture the spike window with Windows.Graphics.Capture (CreateForWindow, free-threaded frame pool, poll TryGetNextFrame), read the blade edge x per frame, and score per-frame advance with comp_spike_stats.zig. Oracle: idle mode must score ~0 new frames, gdi ~1 in 3 at 120 Hz.

## In plain terms

To prove the new animation approach is smoother, we need a stopwatch that
watches only our test window. The old one counted every screen update on the
whole desktop, so it said "perfectly smooth" even when nothing was moving.
This adds a stopwatch that films just the test window and counts a frame only
when the sliding panel actually moved, and it runs while the user is at the
desk without showing them anything.

## Goals

- [x] Per-window capture (Windows.Graphics.Capture) in the spike, one row read back per frame, blade edge tracked
- [x] Score only frames whose edge moved, stamped with DWM's compose time
- [x] Show the oracle can tell idle, today's path and the compositor apart
- [x] A way to run it with the user present that never shows or focuses a window

## Result (2026-10-29, lane B)

New module `src/apprt/win32/wgc_capture.zig` (D3D11 device, hardware then
WARP; `CreateForWindow`; free-threaded pool; one-row `CopySubresourceRegion`
readback; slots from the 10.0.22621/26100 SDK headers). The spike prints
`WCLOCK`, `WHOLDS` (refreshes each new frame was held) and `WGLIDE`/`WSUMMARY`.
`scripts\comp-spike.ps1 -Live -CheckOracle` runs it as a ghost window.

Three things had to be found on the box:

1. **WGC rate-limits to 16 ms by default.** `IGraphicsCaptureSession5.MinUpdateInterval`
   reads 16.000 ms here. With it, the compositor path scored 0.44 (every third
   refresh) - the capture's cap, not DWM's. The module now lowers it to one
   tick and records the default.
2. **WGC refuses the background desktop.** The item reports 0x0 and
   `CreateCaptureSession` returns ERROR_INVALID_STATE (0x8007139F). The
   default (test desktop) run reports that and keeps its old lines.
3. **Off-screen placement is not a substitute.** Off every monitor a GDI window
   is never repainted (1 frame, no blade) and composition is throttled to
   ~40 Hz. What works is an on-screen **ghost**: `WS_EX_LAYERED` alpha 1/255 +
   `WS_EX_TRANSPARENT` + `HWND_BOTTOM`, never activated, tool window. DWM
   composes it, WGC captures its full-colour content, and nobody can see it.

Live ghost runs, 8 glides of 300 ms at 120 Hz:

| mode | new frames | advance_mean | holds (1/2/3/4/5+ refreshes) | max gap |
|---|---|---|---|---|
| idle | 0 | 0.000 | - | - |
| gdi | 81 | 0.281 | 1/22/15/33/2 | 52.9 ms |
| comp | 272 | 0.944 | 264/0/0/0/0 | 24.3 ms |

With a 500 ms UI stall (4 glides): gdi 0.139, max gap 160 ms; comp 0.944 on
the UI thread and on the worker thread, unchanged. comp's 0.944 rather than
1.0 is start latency: the first moved frame lands ~2 refreshes after the
declaration (the one 24 ms gap per glide); every later frame is 1 refresh.

## Validation criteria

- [x] idle scores ~0 new frames - 0 of 0 (`comp-spike.ps1 -Live -CheckOracle`, ORACLE PASS).
- [x] gdi scores about 1 in 3 at 120 Hz - advance_mean 0.281, holds mostly 2-4 refreshes (same run).
- [x] comp is told apart from gdi - 0.944, every hold 1 refresh (same run).
- [x] The check can fail: with WGC's default 16 ms interval comp scored 0.44, which `-CheckOracle` (comp >= 0.9) rejects.
- [x] Never shows or focuses a window: ghost window (alpha 1/255, click-through, bottom-most, no activation); the background-desktop run reports `capture-session ... 0x8007139f` instead of fake numbers.
