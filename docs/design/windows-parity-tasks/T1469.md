# T1469 - The hero band's terminal tile draws no border, and hero-viewer-tile.ps1 has been red about it unguarded

## Summary

Found while validating T669. test\win32\hero-viewer-tile.ps1 fails one of its 18 checks, twice in a row: 'terminal tile is painted (border stroke found, max R=11)'. The measured ring is 11 on the selected TERMINAL tile, which is exactly the band backdrop (background * 0.7 = 11,11,14), so no border stroke is being drawn around it - while the tile interior does have content (27 distinct colors). The VIEWER tile in the same run is fine (128 distinct colors, border 96), so the hero decode path is healthy and this is specifically the terminal tile's frame. Unrelated to T669: nothing in that change touches HeroCarousel or the flattening decode the hero uses. Two things to settle: whether paintTile really stopped stroking the terminal tile (a regression) or the assertion's 60 floor no longer matches a theme change, and why nothing noticed - hero-viewer-tile.ps1 has NO row in scripts\guard-due.ps1, so no turn has ever been told it went stale.

## In plain terms

In hero mode the strip of small pane previews showed a terminal preview with no frame around it, and the test that checks those previews had been failing without anyone being told. The missing frame no longer happens, and that test is now watched: whenever the preview strip's code changes, the next turn is told to re-run it.
