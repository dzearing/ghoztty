# T2333 - The rail repaints every tile's glassy rim pixel by pixel on every paint: cache the per-tile rim overlay so a scroll step or hover does not recompute it (found in T1925)

## Summary

P2: perf polish found in T1925 - paintOverlay runs Overlay.pixel over every rail tile on every paint for a tileRim that only changes with theme, size, scale and hover; cache the premultiplied DIB per (size, dark, hovered, scale) so only busy tiles compute per frame.

## In plain terms

The collapsed sidebar (the rail) draws a faint glassy edge around every tile.
It used to work that edge out again, dot by dot, for every tile on every
repaint - each scroll step, each hover - even though it never changes. Now it
is worked out once and reused, so the rail does less work while it scrolls.
Nothing looks different.

## Goals

- [x] A resting tile's rim is computed once per (size, corner, hairline, theme, hover) and reused
- [x] A busy tile (moving sheen) is still computed every paint, exactly as before
- [x] The cache is bounded and freed with the sidebar
