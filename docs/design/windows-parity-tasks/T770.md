## Summary

Found while doing T264. Both derive the caption slabs by hand instead of reading the module: close-glyph-white.ps1:101-104 (closeL = cli.Width - capW) and mouse-nc-routing.ps1:89-91 (closeL, then minL = closeL - 2*capW). Both are CORRECT today - unlike tab-strip-autohide.ps1 - so this is a latent duplicate, not a defect: three copies of one datum, which is the shape T257 spent a task deleting. Read them off Get-TestChromeMetrics (CaptionCloseLeft / CaptionMinLeft), or if a script wants the cross-check, follow T264's section 2b and assert agreement rather than leaving the copy uncompared.

## In plain terms

Nothing a user of the terminal can see is wrong here. Two of our own test
scripts each worked out where the window's close and minimize buttons sit by
redoing the arithmetic themselves, instead of asking the one place that already
knows. That is fine until the day the chrome moves: then those private copies
quietly keep testing the old place, and a real button bug passes. This makes
both scripts read the answer from the shared source, so there is one number to
change and nowhere for a stale copy to hide.
