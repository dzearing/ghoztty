# T1633 - Nothing in the machine chooser explains itself on hover except the CPU meter

## In plain terms

On the Mac, resting the pointer on almost anything in the "New Remote Window"
picker pops up a short note saying what it does. On Windows only the CPU meter
did that; every button and marker left you to guess. Now the same notes, in the
Mac's exact words, appear on every one of those controls that exists on Windows.

## Goals

- [x] Every Mac `.help()` surface that has a Windows counterpart shows Mac's
      words on hover: End, both column headers, the signed-in account, a
      machine's status dot, New Window, Restore All, Activity and "...".
- [x] One native comctl32 tooltip control for the whole dialog (never
      owner-drawn), with T812's CPU tip folded into it unchanged.
- [x] The words are derived in a pure, none-lane-tested module.
- [x] An acceptance script scores every surface it can reach, with negative
      controls, and a guard row keeps it current.
- [x] Surfaces with no Windows counterpart are recorded as n/a with the reason.

## Design decisions (made in-task)

- **One control, two kinds of tool** (`chooser_tooltip.zig`). Surfaces the
  dialog PAINTS (roster End button, CPU meter, column headers, account email +
  monogram, a machine row's status dot) share one track-mode tool the dialog
  places by hand after a `GetDoubleClickTime()` delay - T812's mechanism,
  generalized. The four real child BUTTONS (New Window, Restore All, Activity,
  "...") each get a `TTF_IDISHWND | TTF_SUBCLASS` tool on the same control, so
  comctl32 owns their delay, placement and - the part the dialog cannot see -
  dismissal when the pointer leaves a button straight out of the window. Their
  words are refreshed when the pointer enters (seen via the `WM_SETCURSOR` the
  button forwards to the dialog), so they always name the current selection.
- **Hover state is one `?chooser_help.Target`** in `MachineChooser.zig`. A
  dialog `WM_MOUSELEAVE` drops only painted-on-dialog targets (it also fires
  when the pointer enters a child); the list's own leave drops the status-dot
  target; `WM_SETCURSOR` naming anything but a help button drops a button target.
- **T812's CPU oracle lines are unchanged** (`chooser cpu tooltip row=`,
  `... dropped`, `... shown row=`); every other surface logs
  `chooser help tooltip target=<kind ...> text=<text>` at hover time and
  `chooser help tooltip dropped target=<kind ...>` when left for nothing.
- **Account help is on the email AND the monogram.** Mac puts it on the email
  text; on Windows the email is middle-truncated and the monogram is the same
  identity mark beside it, so both answer.
- **Status dot hit box** is the reserved 12 DIP status column plus the pill's
  leading padding (`chooser_help.statusColumnHit`), never the glyph column.
- `win32.zig`'s `TTF_SUBCLASS` is `0x0001`, which is really `TTF_IDISHWND`
  (commctrl.h: `TTF_SUBCLASS` = `0x0010`). This task states the correct values
  locally in `chooser_tooltip.zig` rather than changing the shared constant
  under the viewer bars that use it - see the follow-up filed from this task.

### n/a on Windows

- **Session-count badge** (Mac `countBadge`, `MachineChooserView.swift:247`):
  the win32 machine rows carry no count capsule at all, so there is nothing to
  hover. The missing badge itself is a separate parity gap (follow-up).
- **Row "Show" (bring to front) / "Resume" buttons** (Mac `:890`, `:894`): a
  win32 session card has no per-row buttons - the card itself resumes on
  double-click / Return. No control, no tooltip; not invented here.

## Summary

Mac's chooser puts help text on ten controls - the session-count badge, the New Window / Restore All / Manage buttons, the sort headers (sessionSortHelp), the Activity Monitor button, a row's Bring-to-front / Resume / End buttons, the signed-in avatar and a machine's status line. Win32 had no tooltip control at all until T812 added one for the CPU meter, so every one of those is silent. The plumbing now exists (MachineChooser's track-mode tooltip); this is the remaining nine surfaces plus their wording, and the hit tests for the ones that are owner-drawn rather than real controls.
