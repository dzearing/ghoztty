# T1557 - A cross-machine window does not say which machine it is on in +list --json

## In plain terms

When you have windows open on two different machines, a script that lists your
windows cannot tell which one is which. A person can — the pill in the title bar
names the machine — but the only way to get that name out of the app is to read
it off the screen. Anything that wants to group or label your windows by machine
has to guess from the window title.

## Summary

Mac publishes `AXGhosttyMachine` on every terminal window (the machine's display
name for a remote window, the literal `"Local"` otherwise) precisely so external
tools can group windows by machine without screenshotting the pill. Windows
publishes no accessibility attributes and, per the spec's out-of-scope rule,
never will — but the *capability* has a Windows home: `+list --json`, which
already carries the sibling fact (`connection`, T609) for exactly this reason.

Found while re-verifying T715, which asked the same question about
`AXGhosttyLinkState` and turned out to be already answered by T609. This is the
one row of that table with nothing behind it.

## Details

The value is already derived in one place and needs no new plumbing:
`Window.machineDisplayName()` (`src/apprt/win32/Window.zig:1622`) returns
`RemoteMachine.displayName()` — the same string the pill, the pill's tooltip and
the close confirmation all speak — or empty when the window has no machine
record. Shape it the way `connection` is shaped (`handleList` in
`src/apprt/win32/IpcHandlers.zig`, `List.Window` in `src/apprt/ipc/list.zig`):

- a `machine` string on a cross-machine window's entry;
- **absent** for a local window, matching `connection`'s convention on this
  platform rather than Mac's literal `"Local"` — absence is already what says
  "local" here, and two conventions in one object would be worse than either;
- additive and optional, so the golden Mac shape test (T370) and every existing
  consumer are unchanged.

Do the Mac half too, or file it `seat: mac`: Mac's `+list` has the same gap (the
name is on the AX attribute only), which is the same argument T609 made.

## Validation criteria

- [ ] `+list --json` on a cross-machine window reports the machine's display
      name — the same string the pill shows, not a second derivation
- [ ] A local window's entry carries no `machine` key at all
- [ ] The shape is additive: the T370 golden-Mac-shape test still passes with
      `machine` in the allowed-extras list
- [ ] `+list` human output names the machine too, as T609 did for the link state
