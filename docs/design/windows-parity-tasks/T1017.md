# T1017 - caption-bar.ps1 fails intermittently with a UNIFORM capture; the 2000ms retry window is too short under load

## In plain terms

The test that checks the window's title bar sometimes failed with "the picture is blank" and then passed on a re-run, even though nothing had changed. That made a healthy build look broken. Once this is done, the test gives the same answer every time, including when the machine is busy.

## Goals

- [x] Find out whether the blank-capture failure still happens
- [x] Prove the title-bar check is stable across repeated runs and under heavy CPU load

## Summary

Seen 2026-08-20 in the T306 turn: test\win32\caption-bar.ps1 failed its first run with 'Get-TestWindowPixels: the capture is UNIFORM - 3858x2118, one color over its whole interior, still uniform after 11 attempt(s) across 2000ms' and then passed cleanly on an immediate re-run (ALL PASS, 32). Nothing about the window had changed between the two runs, and no stray ghoztty was left behind. So the T303 uniform-capture guard is doing its job - it caught a blank photo instead of scoring it green - but its retry budget (11 attempts / 2000ms) is not enough for a window that has just been created on the background desktop while the box is busy, which makes a correct build read as red. Decide whether the budget should scale with load or wait on a paint signal rather than a fixed clock, and fix it once for every caller of Get-TestWindowPixels rather than in caption-bar alone. Evidence: the run happened immediately after printclient-audit.ps1 (189-file audit) on the same box.

## Validation criteria

- [x] Root cause identified, and it is not the retry budget: the failing capture was 3858x2118, a MAXIMIZED window. The old fixed 24x24 uniform-scan grid stepped 160x88 px and never put a sample row inside the 40 px caption band, so the capture read as one color whatever the timing. The re-run passed because the window was not maximized again. Fixed at the source by T1282 (f5c995bd9, 2026-09-02): `Test-TestCaptureUniform` caps the stride at 16 px (`-MaxStep`), so the band always gets sampled. The 2000 ms retry stays, because it covers a window that has not painted yet, which is a different case.
- [x] `test\win32\caption-bar.ps1` x3 back to back at HEAD bf542fb49 (fresh Debug build): ALL PASS (38 assertions) each run.
- [x] `test\win32\caption-bar.ps1` x2 with every core (32) pinned by busy-loop jobs: ALL PASS (38 assertions) both runs. No UNIFORM throw under load.
