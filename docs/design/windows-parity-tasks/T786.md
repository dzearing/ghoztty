# T786 - Hover fills still proved through held states: caption-bar, hero-mode and tab-tooltip can use the T282 hovered capture

## Summary

T282 removed the harness limit these scripts worked around, but each still asserts a hover through a stand-in: caption-bar.ps1 uses caption_pressed (a press, which survives a leave), hero-mode.ps1 reads hero hover tile= from the debug log only, and tab-tooltip.ps1 reads the derived text at hover time because the show DELAY cannot be held. Get-TestHoverCapture (test/win32/lib/HoverCapture.ps1) can now paint and capture the hovered frame directly. Convert what it covers; the tooltip's timing is a different claim and may stay as it is.

## In plain terms

Three test scripts claim to check that a control lights up when the pointer is
over it, but none of them can actually see that happen - so each proves it
sideways: one holds the mouse button down instead, one drags the divider
instead, and one reads a log line. The app can now photograph itself with a
control genuinely hovered, so those stand-ins get replaced by a picture of the
real thing. Nobody using the terminal sees a change; what changes is that a
button that stopped lighting on hover would now be caught.
