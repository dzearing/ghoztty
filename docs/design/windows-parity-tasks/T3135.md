# T3135 - New window from a session-persistence (agent-backed) Windows pane should be on screen in the key's own turn: take the parent pane's cwd as known (OSC 7 / inherited) and ask the agent only when there is none (Mac e76f7d380: 57-88 ms -> 40-63 ms key->drawn)

## Summary

Mac e76f7d380: Cmd-N from a local agent-backed window asked the agent for the parent's cwd on a background queue, built the window a turn later and presented it another turn later, laying the new workspace out twice. Windows: trace new_window/new_tab from an agent-backed pane (App.zig newWindow paths, agent cwd query) and measure key->first-frame with the existing perf tooling; if Windows also round-trips the agent for cwd or lays the new tab out twice, take the known cwd and present at once. Record before/after numbers in the card.

## In plain terms

On Mac, pressing New Window from a session-persistence window waited on a
background question to the session agent ("what directory is this pane in?")
before it could even build the window, so the window appeared a beat late.
On Windows the new window was already immediate, but every new TAB and SPLIT
in such a window asked the agent the same question and waited for the answer
on the thread that draws the UI. Now a local pane answers from its own shell,
and the agent is only asked when nothing is known here.

## Goals

- [x] Trace new window / new tab / split from a local agent-backed pane and find any agent round trip
- [x] Take the parent pane's directory as known for a local agent pane; ask the agent only when it is not
- [x] Record before/after numbers

## Findings

- **New window**: no round trip on Windows. `createWindow` -> `addTab` with no
  parent -> the core's inherited `working-directory` is forwarded to the LOCAL
  agent by `termio.Remote.openWorkingDirectory`, and the window is shown at
  once (no deferred present, no double layout). Nothing to change.
- **New tab / split**: `Window.inheritedCwd` sent a synchronous GET_CWD
  (bounded 1.5 s) on the GUI thread for EVERY local-agent tab and split, and
  `IpcHandlers` `+split` with explicit command/shell reuses it.
- **Fix**: `inherit_cwd.choose` (pure, unit-tested): a local agent pane takes
  the process read of its shell's cwd (`livePwd`, PEB) or, for a shell that
  reports OSC 7, that report; the agent is asked only when neither answers.
  A cross-machine pane always asks (a local path is meaningless there).
- **Numbers** (Debug build, same harness, `inherit cwd:` log line):
  before `source=agent us=264` (healthy local agent; up to 1500000 us against
  a busy one), after `source=reported us=2`.

## Validation criteria

- [x] Unit: `inherit_cwd.zig` tests (cross-machine always asks; local answers from live/reported; agent only when nothing known) - none lane.
- [x] Behavior: `test\win32\split-inherit-cwd.ps1` section E - the agent-backed split logs `source=reported local_agent=true` and no `source=agent`; ALL PASS (25). The pre-fix build logged `source=agent` on the same split (the harness's red state).
- [x] Agent-backed split still lands in its parent's directory (section D, unchanged assertions).
