# T1378 - Sweep the acceptance scripts for 'only while focused' claims left unasserted because the harness could not deactivate a window

## Summary

T568 gave the harness the write side of activation (Set-TestActiveWindow / Clear-TestActiveWindow), and the only script using it so far is activity-monitor.ps1's new L7. Every other place a chrome claim reads 'only while this window has the keyboard' was written under the old limit and either asserts the focus-moves-within-the-window half only, or says nothing. Sweep test/win32 for those, and land the arm each one was owed.

## In plain terms

Our hidden-desktop UI tests could not, until recently, "click away" from a
Ghoztty window, so anything that is supposed to change when you switch to
another window was taken on trust. This goes back through the tests, finds
those spots, and adds the missing check. Two land here: the quick terminal
sliding away when you click elsewhere (it had no test at all), and the
Activity Monitor's selected row dimming when its window is no longer the one
you are using.

## Goals

- [x] inventory every product site that reacts to losing activation/keyboard, against the harness that covers it
- [x] quick terminal autohide-on-blur asserted, with an autohide-off control
- [x] Activity Monitor selection emphasis asserted on deactivation, both ways and back
- [x] the remaining owed arms filed (T2883)
