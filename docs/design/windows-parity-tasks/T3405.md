# T3405 - arp-orphan, install-walkthrough, msi-upgrade and one-installer run a real msiexec without the T3394 user-install sentinel, and nothing audits that a new one carries it

## Summary

T3394 added test\win32\lib\UserInstallSentinel.ps1 (Get-PackageUserProductReach refuses a package that can act on the shipping product; Get-UserInstallSnapshot/Compare-UserInstallSnapshot + Get-UserProductInstallerEvents prove the user's install did not move) and wired it into update-real-msi and update-graceful only. Four more harnesses still run msiexec /i on a real package: arp-orphan, install-walkthrough, msi-upgrade, one-installer (grep for Start-Process msiexec / '/i'). Wire the same pre-flight before each install and the snapshot+event check in each finally, and add a harness-floor audit row that fails any test\win32 script that runs msiexec /i without loading the sentinel, so the next installer harness cannot ship without it.

## In plain terms

Some of our installer tests run the real Windows installer. One of them went wrong on 2026-11-22 and damaged the user's own installed Ghoztty. The fix for that (T3394) added a safety check, but only to two of the five tests that run the installer. This puts the same check into the other three, and adds an audit that fails if any future installer test leaves it out.

## Goals

- [x] arp-orphan, install-walkthrough and msi-upgrade refuse a package that could touch the user's Ghoztty before any install runs
- [x] each proves afterwards, on every exit path, that the user's install did not change and the installer logged nothing against it
- [x] a harness-floor audit fails any test script that runs msiexec without the sentinel
- [x] one-installer re-checked: it never runs msiexec (a read-only content check), so it owes nothing
