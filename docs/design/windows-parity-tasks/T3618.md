# T3618 - Linux L11b3: a pane released over nothing opens in a new window, and the rearrange header gets its move-to-new-window button

## Summary

Follow-up of T3564. On GTK a GtkDragSource drag-end with no drop (delete_data false, GDK_DRAG_CANCEL_NO_TARGET) is the released-over-nothing case: move the pane into a new window holding only it, same shell and pane id. The rearrange header (PaneDrag.Header) gains the right-hand button that does the same, disabled on a lone pane; a move that would empty the source window is refused. Moving a pane between windows must not end its agent session (Mac PaneMoveCoordinator.finishRelocation; session close intent). Wayland gives no global pointer position, so the new window opens where the compositor puts it.

## In plain terms

On Linux, dragging a pane and letting go somewhere that is not a pane or the
tab bar did nothing, and the pane's title bar in rearrange mode had no way to
send the pane off on its own. Now letting go over nothing - or clicking the
new button at the right of that title bar - moves the pane into a window of
its own, still running the same shell. A window's very last pane stays put
(its button is greyed out), so a drag never closes a window.

## Goals

- [x] a pane drag let go over nothing moves the pane into a new window holding only it, same shell, pid and pane id
- [x] the rearrange header carries a right-hand "move to a new window" button that does the same
- [x] the button is disabled on a window's last pane, and a release over nothing there is refused
- [x] the new window opens at the source window's size (its restored size when that one fills the screen), in rearrange mode when the drag was made in it
- [x] the agent session is not ended by the move (the same `Surface` moves; nothing frees or marks CLOSE, as T3616 established)

## Validation criteria

- [x] the pop-out rule and the new window's size are right - 2 new tests in `gtk/pane_drop_apply.zig` (`popOutAllowed`, `popOutSize`), run in the Linux floor's none lane and the Windows none lane
- [x] a release over nothing opens a new window holding only the pane, mode on, same shell still running, its window left without it - `test/linux/pane-pop-out.sh` P6-P9 (PANE POP OUT: ALL PASS, 16 checks, headless Weston)
- [x] a window's last pane: the button is disabled, a click does nothing, a release over nothing is refused, no window opens or closes - P3-P5
- [x] the button follows the tab count both ways (a lone pane may pop out once its window has a second tab, and not after) and moves the pane, same shell - P10-P12
- [x] the negative control fails: `NEGATIVE=1` (both moves aimed at a lone window's last pane) fails exactly P6, P7, P9, P11, P12 (5 failures)
- [x] no regression in the neighbouring drag suites: `cli-pane-drag.sh` ALL PASS (53), `pane-drag-ghost.sh` ALL PASS (15)
- [ ] NOT RUN: a real pointer drag released over nothing (GtkDragSource `drag-cancel` with `GDK_DRAG_CANCEL_NO_TARGET`) and a real pointer click on the button. The headless harness has no seat and Wayland has no input injection, so the seam calls the same `Header.releaseOverNothing` the cancel's idle runs, and emits the button's own `clicked`; the `drag-cancel` wiring and the `drop_seen` guard are unexercised until a seat-capable harness exists.
