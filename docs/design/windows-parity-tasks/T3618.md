# T3618 - Linux L11b3: a pane released over nothing opens in a new window, and the rearrange header gets its move-to-new-window button

## Summary

Follow-up of T3564. On GTK a GtkDragSource drag-end with no drop (delete_data false, GDK_DRAG_CANCEL_NO_TARGET) is the released-over-nothing case: move the pane into a new window holding only it, same shell and pane id. The rearrange header (PaneDrag.Header) gains the right-hand button that does the same, disabled on a lone pane; a move that would empty the source window is refused. Moving a pane between windows must not end its agent session (Mac PaneMoveCoordinator.finishRelocation; session close intent). Wayland gives no global pointer position, so the new window opens where the compositor puts it.
