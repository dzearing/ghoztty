# T3036 - PA-V04: a viewer rebuilt into a background tab starts its renderer and loads its page before anyone can see it (Window.zig:3997)

## Summary

PA-V04 (audit-1, T2963). Window.zig:3997 calls viewer.start unconditionally; setTabSurfacesVisible (Window.zig:4425-4427) says rebuilt background tabs start visible and are hidden afterwards. Session restore taking this path is inferred, not traced. Cost (estimated): one renderer (50-150 MB) and a full page load per never-shown viewer. Fix: defer start() to the first setVisible(true), keeping title from restore metadata. Risk: +read and screenshots of a never-shown viewer need start on demand; first reveal shows a load flash. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## In plain terms

When Ghoztty reopens your windows after a restart, every document or web page
sitting in a tab you are not looking at used to start a whole browser engine
and load its page right away, costing memory and time for pages nobody could
see. Now a page in a hidden tab waits: it loads the moment you switch to that
tab, and a tab you never open costs nothing.

## Goals

- [x] a viewer born into a background tab (session restore, in-place rebuild) starts no web view until it is first shown
- [x] a shown viewer comes up as before, with its address bar and chrome laid out from the start
- [x] first switch to the tab loads the page; scripts can still address the pane meanwhile

The renderer-count measurement is filed as its own task (see progress log).
