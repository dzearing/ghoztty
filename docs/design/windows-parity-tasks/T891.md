# T891 - The win32 command palette has no 'Recent' section and no alphabetical sort (Mac surfaces the 10 most recently used commands first, then sorts the rest)

## Summary

Found while landing T555. The Mac palette (`TerminalCommandPalette.swift`
`commandSections`) sorts all options with a locale-aware case-insensitive
compare (normalizing `:` so prefixed families group together), and keeps a
"Recent" section: `PaletteHistory.shared` records each command's use and the
10 most recently used surface at the top in recency order, with the rest
under "All Commands". The win32 palette (`Surface.zig`
`filterPaletteEntries`) shows registry order with user entries and the T555
jump entries appended — no sections, no sort, no history.

Shape of the fix: a pure ordering/history module (none-lane tested, the
`palette_jump.zig` pattern), a small persisted MRU (the DPAPI/state-dir
conventions do not apply — Mac uses UserDefaults; a JSON in the state dir
matches), and section headers in `paintPalette`.

## In plain terms

The command palette listed its commands in the order somebody happened to
type them into the source file, so finding one meant reading the whole list.
Now it reads like a list you can scan: everything in alphabetical order, with
the handful of commands you actually use sitting at the top under "Recent" -
and it remembers them after you close the app, the same way the Mac palette
does.

## Goals

- [x] Alphabetical order, with Mac's `:`-family grouping
- [x] A "Recent" section: the ten most recently used, in recency order
- [x] The recents survive a relaunch
- [x] Headers are labels, not rows you can land on or click

## Validation criteria

- [x] Entries are sorted alphabetically (case-insensitive) when there is no
      filter, matching the Mac normalization of `:`-prefixed titles -
      `palette_order.titleOrder` tests in the none lane, and arm O1 of
      `test\win32\palette-order.ps1` on the box (Enter on the "new " filter
      runs *New Remote Window*, which only alphabetical order puts first)
- [x] Executing a command records it; the next palette open lists up to 10
      recent commands first, in recency order, under a "Recent" header -
      arms O2/O3 (the store names the command that ran; a seeded history
      makes *New Tab* win the same keystrokes)
- [x] The MRU survives an app relaunch - arm O3 seeds the store BEFORE the
      relaunch and arm O4 reads the fresher stamp back after it
- [x] Pure ordering/history logic unit-tested in the none lane; behavior
      covered by an on-box acceptance script; floor stays green
