# T1788 - Wire background-blur to the documented Win11 acrylic backdrop (DWMSBT_TRANSIENTWINDOW) once the window carries per-pixel alpha

## Summary

T1016's call: on Windows 11 background-blur should use DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE=3), the documented successor to the undocumented SetWindowCompositionAttribute accent blur. Measured on the box: acrylic blurs WHATEVER is behind the window, other windows included (a red/white checker came through as a smooth pink, high-frequency energy 0.00), which is what Mac's CGSSetWindowBackgroundBlurRadius shows; Mica (type 2) samples only the wallpaper (the checker vanished, pale wallpaper colour) and is therefore NOT a translation of background-blur. Keep the accent policy as the fallback below Windows 11 22H2, where the backdrop attribute does not exist (probe the HRESULT, fall back on failure). Mac takes a radius (background-blur = N) and acrylic's is fixed; record that gap in the design system. Compare the acrylic look against Mac side by side; if Windows' acrylic tint and noise read visibly different from Mac's plain blur, file a decision (experience gap) rather than picking silently. Probe to re-measure: scripts\blur-backdrop-probe.ps1.

## In plain terms

On a Mac, `background-blur` makes whatever sits behind a see-through terminal
window look frosted. On Windows the setting did nothing. With this change
Windows 11 uses its own frosted-glass material (acrylic) behind the window,
and older Windows falls back to the blur it already had.

## Goals

- [x] background-blur asks Windows 11 for the acrylic backdrop, never Mica
- [x] older Windows (no backdrop attribute) falls back to the accent blur
- [ ] a config reload turns the blur on and off on open windows (wired in
      `onConfigChange`; measured only by background-blur.ps1 B/E, NOT RUN)
- [ ] the blurred composite is measured on screen (T1808, needs the user away)
