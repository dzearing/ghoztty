# T993 - Nothing makes anyone re-run the paste acceptance script after the paste code changes

## Summary

test\win32\clipboard-paste.ps1 is the only harness that proves ctrl+v and shift+insert actually paste (and fall through to the pane when the clipboard holds no text), but it has no row in scripts\guard-due.ps1 - so an edit to the paste path leaves it unrun and nothing says so. T947 touched that very path and the gate stayed silent; the fix's paste half rode on a source guard rather than on the behavior script. Add a clipboard-paste row covering the paste read and the key-binding path it exercises. It runs on the background test desktop, so it is gateable without taking the user's foreground.

## In plain terms

There is a test that proves Ctrl+V and Shift+Insert really paste into the
terminal, and that they pass the key through to programs like Claude Code when
the clipboard holds a picture instead of text. Nothing reminded anyone to run
that test after the paste code changed, so a paste regression could ship
unnoticed. Now changing the paste code makes the test "due", and a commit is
refused until it has been run green again.
