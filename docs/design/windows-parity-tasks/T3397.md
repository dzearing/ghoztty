# T3397 - Linux L8b: relaunching the GTK app re-attaches the panes the agent kept - session-layout manifest, restore and relaunch policy

## Summary

T3337 made GTK panes agent-hosted and made a quit detach them, but nothing brings them back: the Linux app writes no session-layout manifest and restores nothing at launch, so after a quit or crash the sessions run on unseen in the agent. Port the manifest write (window/tab/split layout, ratios, titles, session ids, quit-time snapshot) and the launch-time restore that ATTACHes each session (docs/reference/session-persistence.md, What a relaunch restores), including session-relaunch restore/rerun/prompt after an agent restart. Also prove a real quit (not a kill) detaches: the T3337 acceptance only covers SIGKILL and user close.

## In plain terms

On Linux, if Ghoztty crashed, was killed or was quit, your shells kept running
in the background but the next launch showed one blank window and left them
out of sight. Now the next launch brings your windows back the way they were -
the same splits at the same sizes, the same pane names - with each pane
reconnected to the very shell it had, screen and all. A pane whose shell ended
meanwhile comes back as a new shell in its place; a window you closed stays
closed.

## Goals

- [x] the running app keeps a layout file current (windows, tabs, splits, ratios, names, pane ids, session ids)
- [x] a relaunch rebuilds the layout and re-attaches each pane to its own session
- [x] a quit (SIGTERM, what a logout sends) detaches and snapshots each pane's screen
- [x] a pane whose session is gone comes back as a fresh shell in its place; after an agent restart, as a relaunched shell
- [x] a closed window never comes back; a second instance never restores or writes
- [ ] window size and tab titles (T3549)

## Validation criteria

- [x] the restored pane's screen still shows what it printed before the crash (R8b)
- [x] SIGTERM quits, every session stays alive (detached), and the quit's write carries every pane's screen snapshot (R10-R13)
