# T807 - A correct verdict line reads as unreported: SkipAudit never examines a scorer call that carries no string literal, so Write-TestVerdict -Skipped alone cannot credit a skip count

## In plain terms

The test suite has a rule: if a test script skipped part of its work, the one
line at the end - the line anybody actually reads - has to say so. An automated
audit enforces that rule across every script. It turns out the audit was not
looking at most scripts' final line at all, because of how that line is written:
it passes only variables and no quoted text, and the audit skipped over any line
without quoted text before it got that far. So a script that reported its skips
perfectly could still be flagged as hiding them, and - worse - a script that
really was hiding them could pass unnoticed. After this, the audit reads the
final line either way.

## Goals

- [x] the audit examines a scorer verdict call that carries no string literal
- [x] a correct `-Skipped` call credits the skip count instead of reading as `unreported`
- [x] a scorer call missing `-Skipped` is reported as `unreported`
- [x] both shapes are pinned by fixtures in the acceptance script

## Summary

**Defect.** `Get-SkipAuditFindings` (`test\win32\lib\SkipAudit.ps1`) opened each
logical line with

```powershell
$literals = @(Get-SkipStringLiterals $line)
if ($literals.Count -eq 0) { continue }
```

and only *below* that bail did it test the line for
`Write-Test(Verdict|AssertedNothing)` - the T271 rule that a script on the shared
scorer has no `ALL PASS` literal of its own, so the CALL is its verdict line. But
the canonical call has no string literal EITHER; every argument is a variable:

```powershell
Write-TestVerdict -Pass $script:pass -Fail $script:fail -Skipped $script:skipped
```

Most of `test\win32\` scores itself that way, so for most of the suite the audit
never examined the verdict line at all.

**Two symmetric wrongs, both reproduced against the real suite:**

- *False positive.* `build-fresh-guard.ps1` counts both its skip sites and passes
  `-Skipped $script:skipped`. The sweep still reported it `unreported`, on the
  strength of the only `ALL PASS` literal in the file - fixture text inside an
  array at L238, plus an `-notmatch 'ALL PASS'` assertion about another tool's
  output. A correct verdict line read as a violation.
- *False negative, which is the more serious half.* A scorer call MISSING
  `-Skipped` registered no verdict line at all, and `unreported` is only raised
  when `$verdictLines.Count -gt 0`. So the finding this whole file exists to
  raise could not be raised against the commonest shape in the suite.
  `update-apply.ps1` was sitting in that hole.

**Fix.** Hoist the scorer-call test above the no-literals bail; the `ALL PASS`
literal scan stays below it. `$isAssert`/`$isOperand` still gate it, and both are
false by construction on a literal-free line.

**Effect on the sweep** (`test\win32\`, 24 findings before and after): 14
violating scripts become 13 - `build-fresh-guard.ps1` leaves as the false
positive it was, and `update-apply.ps1` gains the `unreported` finding it was
owed. `skip-visibility.ps1` section B stays red for the pre-existing unconverted
13, which is the state `HARNESS_FLOOR_PENDING` already tracks under T1123; this
task does not convert them.

## Validation criteria

- [x] a literal-free `Write-TestVerdict ... -Skipped $script:skipped` with a counted site is clean - `skip-visibility.ps1` A15, modelled on `build-fresh-guard.ps1`'s real shape
- [x] a literal-free `Write-TestVerdict` WITHOUT `-Skipped` and a counted site is `unreported` - A16
- [x] that finding points at the scorer call, not at line 1 - A17
- [x] section A is otherwise unchanged (A1-A14 all pass)
- [x] the sweep drops `build-fresh-guard.ps1` and gains `update-apply.ps1` L463
- [x] harness floor lane green (or PENDING against its filed task), zig floor lanes green
