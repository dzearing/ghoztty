# T3596 - Linux L8d-2: +stash and +restore move a pane out of its GTK window's layout and back

## Summary

Split from T3399. GTK answers +stash/+restore with 'not served'. Port win32's ipc_stash.zig (Mac handleStash refusal strings byte for byte) onto the GTK split tree: a stashed pane keeps its shell, is listed stashed:true in +list, and comes back with +restore (--focus opts in). Needs the GTK pane sidebar to show the stashed pane (T3557). Acceptance test/linux/cli-stash.sh.

## In plain terms

On Linux, `ghoztty +stash` and `+restore` answered "not served yet". Now a
pane can be tucked out of its window's layout - its program keeps running and
scripts can still type into it and read it - and brought back to exactly the
spot it left, from the command line, the Ctrl+Shift+M key or its (dimmed) row
in the pane sidebar, the way the Mac and Windows apps already work.

## Goals

- [x] `+stash` takes a pane out of the layout, keeps it in the tree and its shell running; `+list` says `stashed: true`
- [x] `+restore` puts it back in its own slot; focus moves only with `--focus`
- [x] Mac's refusals: no target, not found, a window, the last pane on screen, the Quick Terminal
- [x] a window always shows a pane: closing the last one on screen brings the top of the stash back
- [x] the sidebar keeps a dimmed row for a stashed pane, and a click restores it
- [x] `stash_pane` (Ctrl+Shift+M) and `restore_stashed_pane` keybinds
- [x] what is left (relaunch, resize/equalize/swap/drops, Alt-click exchange) filed as T3667
