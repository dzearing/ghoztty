# T2881 - Mac: a launch restore with several saved windows brings back the last-focused window first and the rest one at a time behind it (D102, the Mac half of T1163)

## Summary

The Mac half of T1163 (decision D102, resolved by the user 2026-10-26: "last-focused window first, the rest a moment later, one at a time"). Windows landed it in T1163; this seat cannot build or validate Swift, so it is filed `seat: mac` per the platform-symmetry rule.

Today `SessionLayoutRestore.presentRestoredSessionWindows` (macos/Sources/Features/Remote/SessionLayoutRestore.swift) rebuilds every entry in one loop, in manifest order, then `NSApp.activate`.

What Windows does, to mirror:

- **Record focus.** Every window records `last_focused_ms` (ms since the epoch, the moment it was last activated) in its manifest entry / layout blob. Windows: `Window.last_activated_ms`, stamped on `WM_ACTIVATE`, written by `captureWindow`; a rebuilt window carries its saved stamp forward (`restore_pacing.carriedStamp`) so an untouched relaunch keeps the order. Mac: stamp on `windowDidBecomeKey`, persist as an additive field (spelling `lastFocusedMs` in the Mac blob; the win32 Mac-blob reader `mac_layout_blob.zig` should learn to read it too).
- **Order.** Most recent stamp first; unstamped entries keep their listed order after every stamped one (`restore_pacing.order`). A tab group moves as one unit, led by its newest member.
- **Pace.** Build the first window synchronously and make it key; then build one more every 200 ms (`restore_pacing.interval_ms`), each ordered BEHIND the first (`orderBack`/`order(.below, relativeTo:)`, never `makeKeyAndOrderFront`). Pending entries must not be dropped from the manifest by a save that runs while they wait.
- Log lines the Windows harness keys on: `restored the last-focused window '<id>'; N more follow one every 200ms` and `paced window '<id>' i/N at +<ms>ms`.

## Validation criteria

- [ ] With 4 saved windows, the last-focused one is restored first and key; the other 3 follow one at a time, each at least ~150 ms after the previous (Mac acceptance, the shape of `test/win32/restore-paced.ps1` sections C/D)
- [ ] Focusing a different window and relaunching makes THAT one lead (negative control)
- [ ] Crash recovery from the agent's layout blobs (no manifest) is still paced
- [ ] No saved window is lost: the manifest holds every window after the paced restore
