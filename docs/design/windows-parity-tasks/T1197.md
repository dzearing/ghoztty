# T1197 - Agent soak tests leave HKCU Run autostart entries behind on the box

## Summary

T1188's first cleanup inventory found four GhozttyAgent-soak-<pid> HKCU Run values from 2026-08-23 still armed, each pointing at a zig-out-release ghoztty-agent.exe with a --port-file under a sandbox temp dir that no longer exists. A soak test registered a real logon autostart on the user's machine and never removed it. Fix the soak harness to unregister what it registers (and to sweep pre-existing GhozttyAgent-soak-* values on entry), and add an assertion that the Run key is unchanged across a soak run. Found by scripts\ghoztty-cleanup.ps1 inventory.

## In plain terms

Running the test suite used to add startup programs to this machine: four
leftover "start the Ghoztty agent at sign-in" entries from one morning of soak
runs, each pointing at a test folder that no longer existed. This card turned
out to describe the same four entries as T1168, which had already fixed it, so
the work here was checking that the fix holds and closing the duplicate.

## Goals

- [x] confirm whether the leak is still real on today's code
- [x] prove on the box that a test run leaves the sign-in list untouched
- [x] close the duplicate against the commit that actually fixed it

## Validation criteria

- [x] The HKCU Run key on the box holds no `GhozttyAgent-<suffix>` value
  (read 2026-10-22: only the user's `GhozttyAgent` plus non-Ghoztty entries).
- [x] A sandboxed run unregisters what it registers, even when it dies half way
  — `test\win32\harness-process-leak.ps1` registry sections (armed child leaves
  nothing, bare child leaks: the teeth), run through
  `acceptance-parallel.ps1 run -Scripts harness-process-leak.ps1`: ALL PASS (42
  assertions), 2026-10-22.
- [x] Pre-existing leftovers are swept on entry — `Reset-GhozttyTestState`
  (`test\win32\lib\CleanSlate.ps1`) calls `Remove-LeakedAgentRunValue`, and the
  same harness asserts the sweep and its refusal to touch the user's own name.
- [x] The Run key is asserted clean after a run — R14 of the same harness is the
  box-wide "no leaked agent autostart entry" check.

## What was done

Already fixed; no new code. T1197 was filed on 2026-08-30 from the T1188
cleanup inventory, and it names the very four `GhozttyAgent-soak-*` values from
2026-08-23 that T1168 was filed for. Two later commits closed it:

- `c26754bc5` (T1168, 2026-08-31) — the teardown is armed at the one place a
  sandbox lineage is minted (`Set-GhozttyTestIsolation -ReleaseSandbox` →
  `Register-AgentRunKeyTeardown`), the clean slate sweeps leftovers on entry,
  and `harness-process-leak.ps1` gives it teeth. This is the commit this task is
  closed against.
- `3072ad6c8` (T1146, 2026-08-31) — a release build running out of a source
  checkout (the soak's `zig-out-release`) no longer writes the Run value at all,
  so the soak's write never happens in the first place.
