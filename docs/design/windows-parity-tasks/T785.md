# T785 - deliver-windows-build.ps1's per-location agent stamp check has no live negative control

## Summary

T281 verified the agent in every mirrored location, but the MISMATCH branch there is only covered by the pure comparator plus the upgrade script's live control (section E of upgrade-staleness.ps1). Forcing 'copied fine but is the wrong build' in that sandbox needs a seam: the copy always overwrites the destination before the verify runs, so a stale binary cannot be seeded. A -TestStaleAgent style hook (or a staging swap between copy and verify) would give the branch teeth the way section E has them.

## In plain terms

When a new build is copied out to the Desktop portable and the network share, a
helper program called the agent goes with it. The delivery already re-reads that
program afterwards and asks it which build it is - but nothing had ever seen
that question answered WRONG, so nobody knew the check worked. Now a run
deliberately leaves an older agent in one location where the copy cannot replace
it, and the delivery has to catch it and say so.

## Goals

- [x] construct a genuinely stale agent in a delivered location, live, with no
      test-only hook in the delivery script
- [x] prove the delivery names both stamps and fails over it
- [x] prove the same failed copy with the CURRENT agent pinned does NOT trip the
      stamp check, so the verdict belongs to the read-back
- [x] cover the third outcome too (a file under that name which is not a program)
- [x] give the audit's cross-location agent comparison the same live control

## Validation criteria

- [x] a delivered location holding another build's agent FAILS the delivery,
      naming the stale stamp, the staged stamp and the location - H6/H7 of
      `test\win32\deliver-windows-build.ps1`, green on this box
- [x] the negative control is a REAL agent binary of another build (the debug
      tree's `20260915-b8d0770cc` against the staged `20260914-70b16cc2d`), not a
      fabricated stamp - H2/H8
- [x] the positive twin isolates the branch: the same pinned-file copy failure
      with the STAGED agent's bytes leaves the stamp check clear - H11/H12
- [x] the not-a-program branch is caught off the PE header, without launching it
      - H13/H14
- [x] the audit half fails on locations whose agents disagree and passes once

      measure the check and not the sandbox
