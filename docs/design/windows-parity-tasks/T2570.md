# T2570 - Composition step 5c-1: in pane-tree mode a pane's visual takes its card's shape - cut to what a sliding card shows and rounded to the card's corners - instead of the whole client rect, so a folding pane never draws at full size over its neighbour

## Summary

Split of T2554. Surface.syncTreeVisual clips the pane's tree visual to the child window's whole client rect (comp_tree.placement), but the window path shapes the child with SetWindowRgn: Window.applyCardRegions cuts a sliding card to pane_stack_slide.clip (PaneView.card_region_cut, T2187/T2287) and rounds the elevated style's card corners (createCardRegion). A region does not clip a DComp visual on a topmost=TRUE target, so in GHOZTTY_COMP_PANE_TREE mode a pane going into its strip draws at full size over the pane sliding in, and elevated panes lose their rounded corners. Fix: carry the plan's cut as the visual's clip rect (offset into the visual's own pixels) and the card radius as an IDCompositionRectangleClip, set where applyCardRegions sets the region. Oracle: scripts\comp-present-onscreen.ps1 tree arm with a stack fold stretched by GHOZTTY_STACK_SLIDE_MS, WGC grab mid-fold matches the on arm at the strip edge; elevated corners match at rest; -NegativeControl red.

## In plain terms

In the new drawing mode, each terminal is drawn by the compositor instead of by its own window, and the compositor ignored the shapes the old path cut the panes to. So the rounded corners of the card-style panes came out square, and a pane folding away into its strip would draw at full size over the pane sliding in next to it. With this change the compositor cuts each pane to the same shape the window has.

## Goals

- [x] A pane's tree visual takes its card's shape: the slide cut, or the elevated card's rounded rect (top corners square under a header or banner)
- [x] Elevated corners are round on screen in pane-tree mode, and flat ones stay square
- [ ] Mid-fold, the pane going into its strip is cut on screen (needs an idle box: the fold is a posted divider drag, which captures the mouse)

## Design

`Window.applyCardRegions` computes each pane's region plan as before and now also hands it to `Surface.setTreeShape` as a `comp_tree.Shape` - BEFORE the T2593 deferral, because the region only carries input for a tree pane while the visual has to follow the shape live. `Surface.syncTreeVisual` turns placement + band + shape into a `comp_tree.Clip` (pure, unit-tested), and `Host.panePlace` sets it: a plain rect through `SetClip(D2D_RECT_F)`, a rounded one through an `IDCompositionRectangleClip` (device slot 24, visual `SetClip(IDCompositionClip*)` slot 13, setters at the float slots 4..26 - checked against the 22621 SDK `dcomp.h`) that the surface keeps and releases with the visual. The clip covers the banner band too, since the region did.
