# T2549 - With GHOZTTY_COMP_CHROME=1 a window-edge grow shows the flat background in the strip the window grew into (15-24 frames per right-grow drag, 0-1 with the knob off): the caption visual widens a compose before the desk does

## Summary

Found filming T2546. The caption rides the compositor at the new width while the desk visual is still at the old one, so the newly exposed strip shows the window surface's flat fill (scripts\resize-sync-onscreen.ps1 check right-grow.4: 24 and 15 frames knob on, 1 and 0 off). Must be gone before the knob is defaulted; 4e (no redirection surface) may remove it outright - re-film after 4e before building a separate fix.

## In plain terms

With the window's drawing on the new compositor path, dragging the window's
edge outward used to show a thin plain-coloured band along the edge on every
step, where the background belonged. Re-filmed on 2026-11-02, that band is
gone: work landed between the old film and today already fixed it. The film
did show two other problems, now filed separately.

## Finding (2026-11-02, HEAD 18627a0d4)

The 2026-10-31 film's trace (`%TEMP%\t2577-film-2`) explains the old symptom:
each grow step's frame change came ~14 ms before the desk was committed at
the new size, so the first compose at every new width showed a 12 px strip
past the desk's clip (`right-grow/f0004`, `f0006` ...).

Re-filmed with `scripts\resize-sync-onscreen.ps1 -Exe zig-out-rsafe\bin\ghoztty.exe`
(ReleaseSafe, `GHOZTTY_COMP_CHROME=1`, `GHOZTTY_RESIZE_TRACE=1`), four
right-grow and four left-grow runs: **no frame shows the 12 px strip**.
left-grow scores `flat_background=0` on every run (it was 32-39). What
right-grow still counts as flat is not the desk strip:

- **a 5-6 px column past the viewer page** on 3-6 frames a drag (the page a
  step short of the frame), filed as **T2654**;
- **the terminal card solid black**, on some knob-on runs and on EVERY frame
  with the knob off (51 of 51), a default-path regression filed as **T2653**
  (P1, M1).

Most likely fixed by da5b55af6 (T2578: a growing edge drag lays the inside out
ahead of the frame) and 10dacd87c (T2577: panes move without the system's
redraw), both landed after the 18:18 film; not bisected, because the strip no
longer reproduces at all and there was nothing to fix in code.

**Tried and reverted:** extending the desk visual's clip to the drag's canvas
(`PaneDesk.live`), so a frame that outruns the desk would show desk rather
than fill. A/B'd in the same build (two runs per arm): no difference in
either drag, so it was not kept.
