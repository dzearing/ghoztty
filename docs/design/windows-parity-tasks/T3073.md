# T3073 - next does not re-queue a blocked task whose trigger is a date or a count of closed tasks, so the perf re-audit cadence (T3072) needs someone to remember it

## Summary

T3072 (perf audit-2) is due 7 days after audit-1 or after 10 PA tasks close, whichever is first. The tracker has no way to say that: blocked(...) parks come back only on an idle box (parity-tasks.ps1 ~:1445). Add a re-queue for a date and a closed-count, and prove it in parity-tasks-seat.ps1.

Shape (suggested, the implementer's call): two optional frontmatter fields on
a `blocked(...)` task, `requeue-after: "YYYY-MM-DD"` and
`requeue-when-closed: { count: 10, of: [T...] }` (or a simpler list form),
read by `next` beside the idle re-queue: when either holds, `next -Claim`
flips the task to `todo` and journals which trigger fired, the same way the
idle path does. `validate` should reject a malformed date or an id that does
not exist. Then set both fields on T3072 (2026-11-21; the PA task ids from
`docs/design/perf-audit/audit-1.md`), and have audit-N tasks filed by each
re-audit carry them.

## In plain terms

The performance review is meant to repeat every week or so. Right now the
task list cannot hold a "come back on this date" note, so the repeat happens
only if somebody remembers. This makes the task list bring it back on its own.
