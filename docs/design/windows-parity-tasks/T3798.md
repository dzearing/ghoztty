# T3798 - window-count-scale.ps1 D1 (50 cascaded busy windows <= two cores) flips red on a quiet change: the same build read 154% and 230% against a 200% line

## Summary

On 2026-11-26 (T2328) D1 read 230% then 154% on the same build, and the pre-change build read 191.9% then 173.8% - a reading spread of about 75 points straddling the 200% budget, with the box at 40% load from other lanes. C1 swung 61.6-92.8% the same way. A change that never touches the measured path (T2328's debug-only glide oracle) turned the guard red once and green on re-run. Make D1 measure something stable (e.g. CPU per window over a longer window, or report the box's own load and widen or refuse under it) so a red means the windows got costlier.
