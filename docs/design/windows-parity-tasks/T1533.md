# T1533 - remote-disconnect.ps1 section F picks the wrong cmd.exe as the pane shell and cannot go busy

## Summary

Reproducible on 2026-09-13 over 3cb9dacfe+: sections A-E of test\win32\remote-disconnect.ps1 ALL PASS and section F dies in SETUP with 'F: something is running under the local shell (0 descendants)'. The typing is NOT the problem - the app log shows the pane title become 'C:\WINDOWS\system32\cmd.exe - PING  -N 100 127.0.0.1', so ping really ran. What fails is the pid the section is watching: it takes the FIRST cmd/powershell/pwsh in Get-DescendantPids of the app pid and calls that the pane shell, and the app has more than one such descendant (the job-escape shell hop is one), so Get-DescendantPids of the pid it chose is legitimately empty while ping runs under a different one. Fix: ask the app which shell the pane owns (Get-PaneShellPids, the way the other harnesses do) instead of pattern-matching the process table. Two identical runs failed identically, so this is not the T400 flake shape. Until it is fixed the remote-disconnect guard row stays due and gets excused.
