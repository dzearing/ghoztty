# T1912 - Splitting a pane can crash a debug build: the raised-card painter clamps against an empty card rect (pane_elevation.paintCards, from T1856)

## Summary

viewer-panes.ps1 (run 2026-10-13 11:04 during T1872) crashed the debug GUI: STATUS_BREAKPOINT from reachedUnreachable <- assert <- std.math.clamp <- pane_elevation.paintCards <- paintPaneDesk <- layoutSplits <- insertPaneAsSplit. Root cause: line ~626, 'std.math.clamp(c.left + edge, x0, x1)' (added by 847c931e2, T1856) asserts x0 <= x1, but x0 = max(c.left, 0) and x1 = min(c.right, wi) cross whenever a card lies wholly outside the buffer (a transient layout mid-split, or a zero-width card). Release builds compile the assert out, so users are not crashing, but every debug acceptance run that splits under the raised-card look can die. Fix: skip a card whose clipped rect is empty (x1 <= x0 or y1 <= y0) before the row loop in the fill pass, and audit the other clamps in paintCards for the same shape. Validation: a pane_elevation unit test with a card wholly right of / left of the buffer and a zero-width card, then viewer-panes.ps1 back to ALL PASS (it was 17 FAILURE(S), all downstream of the crash).

## In plain terms

Splitting a pane in a developer (debug) build could crash the whole window,
because the code that paints the raised "card" look around each pane tripped
over a pane that was momentarily off-screen or zero-wide. Released builds did
not crash, but every automated test that split a pane could die. Now an
off-screen pane is simply skipped when painting.
