# T1904 - After an update, the installed agent hook scripts (~/.config/ghoztty/hooks) keep their old text until someone opens Agent Integrations and clicks Update, so a fix to the hook (T1823's help text) never reaches the agents running in the terminal; both platforms

## Summary

Found in T1901: the installed ghoztty-banner.sh was dated 2026-09-14 three releases after T1823 fixed its help text, so every Claude session still got the old instruction. BannerScriptInstaller.state() reports .outdated and the dialog shows 'Update available' (same on Mac), but nothing applied it.

**Re-verified 2026-11-23: partly fixed in passing.** Since T2806 (Windows, 964fd7702) and 2c9432071 (Mac) every launch's plugin settle refreshes an OUTDATED Claude integration, and the banner scripts are a component of it - so a Claude-only user now converges. What was LEFT: that refresh runs only through the Claude integration, so the shared scripts stayed stale when (a) Claude was not the agent set up (Copilot hooks reference the same scripts), (b) the user answered Keep Plugin with a live plugin, (c) a plugin registration was still `.unknown`, or (d) on Windows, any first-run offer was pending (the launch check returns before the settle). This task closes that: `BannerScriptInstaller.refreshIfOutdated` runs on its own at every launch, on both seats.

**Silent, not surfaced** (mechanism call, not filed as a decision): the files carry Ghoztty's ownership marker, the user already set them up, and the outcome is indistinguishable from pressing Update - the dialog just reads installed afterwards. A never-installed pair is not created, and an unmarked (user's own) file is never touched.

## In plain terms

When Ghoztty updates, the little helper scripts it put in your home folder for AI agents now update too, the next time Ghoztty starts. Before, they kept the old version until you opened Agent Integrations and clicked Update, so fixes to them never reached the agents you were running.
