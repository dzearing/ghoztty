# T3029 - PA-I15: after a session's shell exits, its holder and conhost (~50-65 MB) stay alive until the pane is closed, because the agent keeps the link open (pty_holder_child.zig:493)

## Summary

PA-I15 (audit-1, T2962; inferred, not traced end to end). After EXIT the agent reader stops reading but leaves the link open (pty_holder_child.zig:493 `if (self.handleFrame(frame)) break; // EXIT: stop reading`); the holder only finishes when the owner disconnects (pty_host.zig:281-293) and never closes the HPCON before then; markExited (session.zig:~1026) leaves the child installed and terminate runs only on removal (:~1423). Cost (estimated): ~50-65 MB per exited-but-bound pane (~15 MB once PA-I01 lands) for as long as it stays bound; how long that is in practice was not measured. Fix (agent-only, works with old holders): after EXIT and the final ACK, close the holder stream so its existing exit-delivered path ends. Risk low: tryWait/lost read `exited` first (:698). First step: measure how long an exited pane keeps its holder. Findings: docs/design/perf-audit/audit-1/I-findings.md.

## Validation criteria

- [ ] measured: an exited shell's holder and conhost pids are gone within 5 s of EXIT while the pane stays open
- [ ] the exit banner and close-on-exit acceptance still green
