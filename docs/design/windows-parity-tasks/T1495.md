# T1495 - Convert the chooser-* and agent-* acceptance suites onto their own agent lineage (T691 tranche 3)

## In plain terms

The same conversion as the session suites, for the agent and machine-chooser
scripts. These are the ones that need a live roster, so they are the batch
most likely to have been quietly measuring nothing: without a lineage of its
own a sandbox could not start an agent at all, and the app falls back to
non-persistent panes silently. Expect some assertions to change, and read each
change rather than accepting it.

## Details

The conversion is three lines per script, and T691 landed the machinery plus
`test\win32\session-open.ps1` and `test\win32\session-close.ps1` as the worked
examples - diff either one to see the whole shape:

1. `[void](Set-GhozttyTestAgentLineage -Tag '<suite>')` immediately after the
   `lib\CleanSlate.ps1` dot-source, with `lib\TestDesktop.ps1` dot-sourced
   beside it (the scoped kill asks it which `ghoztty.exe` pids are ours, and
   REFUSES rather than widening if it cannot be asked).
2. `-ScopeToLineage` on every `Stop-RepoGhoztty` / `Reset-GhozttyTestState`.
3. `Get-GhozttyAgentStateDir -Root $tmp` in place of every hardcoded
   `ghoztty\local-agent-debug`, which no longer names this run's dir.

Read each converted suite's result rather than accepting it: a suite that was
silently non-persistent all along (no agent could start, so the app fell back to
exec panes) starts actually exercising persistence here, and its assertions may
change. That is the point. `session-open.ps1`'s explicit "the pane really is
agent-backed (port.json written)" assert is the shape a converted suite carries.
