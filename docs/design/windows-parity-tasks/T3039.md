# T3039 - PA-V07: opening a file in a diff viewer copies its patch about four times on the GUI thread and keeps 8 MB per pane (ViewerPane.zig:2296)

## Summary

PA-V07 (audit-1, T2963). setDiffFileCall (ViewerPane.zig:2296-2309, viewer_diff.zig:640-658) builds an unsized UTF-8 list that executeScript then widens; probe.patch (cap 8 MB, ViewerDiffProbe.zig:47) has one reader (ViewerPane.zig:2278) yet lives until the next patch or close. Cost (estimated from the cap): ~32-40 MB transient at the cap, 8 MB retained. Fix: build UTF-16 directly with a presize, as callUtf16 does (viewer_content.zig:785-797); free the patch after the push. Risk: low. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## In plain terms

Opening a changed file in a diff viewer made several full copies of that file's changes in memory at once, on the thread that draws the window, and then kept one copy around for as long as the pane stayed open. For a big change that was tens of megabytes of churn and 8 MB held per pane. Now the change is written once, straight into the form the viewer page needs, and dropped as soon as the page has it.

## Goals

- [x] build the `setDiffFile` script straight into UTF-16 with one presized buffer
- [x] free the patch bytes once the page has them
- [x] keep the narrow (UTF-8) form and the wide form provably identical
