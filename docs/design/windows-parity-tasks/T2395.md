# T2395 - Frame lab matrix driver (T2392 split): frame-lab.ps1 launches the FrameLabCard scene per matrix cell (panes 1/4/9, theme, sidebar; a DPI cell the monitor is not already at is Blocked, never a display-scaling change), reads back the physical geometry the gestures need, wires the live scorer into Invoke-FrameLabCell, writes the results JSON + HTML report, and produces one live verdict per pointer interaction

## Summary

Split out of T2392 (2026-10-28). With the live scorer (T2394) and the two
live probes T2392 landed in `test\win32\frame-lab.ps1`, build the rest of the
original T2392 driver:

- **Launch** per matrix cell: the debug `zig-out` build with `lib\lab-card.ps1`
  in every pane (panes 1/4/9 via `+split`, theme flat/elevated/glass, sidebar
  expanded/rail/hidden), positioned on the input desktop (this is a declared
  input-desktop exception, so it also needs an `@user-desktop-launch` line in
  `lib\TestDesktop.ps1`), geometry read back in physical pixels (window rect,
  work area, caption point, divider, sidebar edge), closed after.
- **DPI**: a cell whose DPI is not the monitor's current one is `Blocked`, never
  run by changing the user's display scaling.
- **Score**: the T2394 scorer as the GfcScorer; bleed per non-superseded frame,
  tracked edge into `Measure-FrameMotion`, `Test-FrameMotionTargets` for misses;
  return `Frames` (Index, Png, FsFindings) for the report.
- **Output**: `New-FrameLabResults` -> `Write-FrameLabResults`
  (`Test-FrameLabResults` gates it) and `New-FrameLabReportHtml -PngRoot`.
- Presence-gated like the rest of frame-lab.ps1 (`Assert-UserAbsent`).

## Validation criteria

- [ ] One live cell per pointer interaction (frame-right, frame-bottom, frame-corner, caption-dblclick, aero-snap, divider, sidebar-edge) produced a verdict with its numbers; T2373's baseline then follows as T2373's own step.
- [ ] The results JSON passes `Test-FrameLabResults` and the HTML report renders the worst frames outlined.
- [ ] A cell at a DPI the monitor is not at reads Blocked, and the display scaling was never touched.
- [ ] (from T2397) With `Show-FrameLabBackdrop` up behind the launched app, `New-FrameLabCellScene` calibrates on the real still frame for a 1-pane and a 2-pane cell, and the measured cell size and padding equal the config the lab launched with.
- [ ] (from T2397) A live frame-right drag with the backdrop up locates window-right on every scored frame (no LOC), and `Get-FrameLabSceneScore` feeds its series to Measure-FrameMotion.

Wiring notes from T2397: the driver's `Scene` hook is `New-FrameLabCellSceneSpec` + a still frame (a short capture with `-KeepFrames 1`, wrapped as an FsFrame) + `New-FrameLabCellScene`; its Scorer arrives as StartCapture's third argument and the whole answer as Score's fifth, where `Get-FrameLabSceneScore -Delta $scene.Delta` is the Score. Launch must supply `Geometry.Panes` (Name, Index, content rect) and, for those cells, `Divider`/`Sidebar`.
