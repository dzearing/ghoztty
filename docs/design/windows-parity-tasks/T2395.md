- **Launch** per matrix cell: the debug `zig-out` build with `lib\lab-card.ps1`

  tracked edge into `Measure-FrameMotion`, `Test-FrameMotionTargets` for misses;
  return `Frames` (Index, Png, FsFindings) for the report.
- **Output**: `New-FrameLabResults` -> `Write-FrameLabResults`
  (`Test-FrameLabResults` gates it) and `New-FrameLabReportHtml -PngRoot`.
- Presence-gated like the rest of frame-lab.ps1 (`Assert-UserAbsent`).

## In plain terms

The frame lab is the tool that will measure whether resizing and dragging in
Ghoztty looks smooth or janky. Every piece of it existed, but nothing yet
opened the real app, laid out panes, dragged, and wrote up the answer. This
task is that driver: run `frame-lab.ps1` on an idle box and it opens the
debug build once per scenario, performs each drag, and writes a results file
and a readable HTML report.

Launch must supply `Geometry.Panes` (Name, Index, content rect) and, for those cells, `Divider`/`Sidebar`.
