# T3133 - Closing a just-opened Windows shell never asks 'are you sure?' even before its first prompt (Mac 8c6987575 shared core: Surface.fresh_default_shell + user_input_sent); prove every Windows input path (keys, IME commit, paste, drag-drop text, +send-keys) marks input sent

## Summary

Mac 8c6987575 adds fresh_default_shell/user_input_sent to src/Surface.zig; needsConfirmQuit returns false for a default shell with no input unless confirm-close-surface=always. It arrives on Windows with the merge of main, but the flag is only set from keyCallback, writePtyRaw, writePtyBracketed and completeClipboardPaste. Windows has its own text paths (IME composition commit, WM_CHAR fallbacks, drag-drop of paths/text, the composer/send paths) that may write the pty without going through those: audit Surface.zig/App.zig callers of queueIo/textCallback, and verify a ConPTY agent-backed pane (remoteBackend session_id null, re-attached session asks). Acceptance: new tab then immediate Ctrl+Shift+W closes with no dialog; type a char then close -> asks; restored session -> asks; confirm-close-surface=always -> asks. Window.zig ~21966 is the Windows confirm site.

## In plain terms

Opening a new Windows tab and closing it straight away could still ask "are you sure?" if the shell was still starting up, which is what the Mac stopped doing today. And the other half was quietly broken: typing into a fresh tab did not count as typing on Windows, because Windows sends most keys over its own route. Now a tab you never touched closes without a question, and one you typed into still asks when something is running.

## Goals

- [x] An untouched new tab closes without the dialog, even while its shell is still busy starting up
- [x] Typing a character, an IME commit, an injected character or `+send-keys` counts as input, so the close asks again
- [x] `confirm-close-surface = always` still asks (unchanged path, covered by section D)

## Validation criteria

- [x] Untouched fresh shell made busy without input (a child parented to the shell) closes on ctrl+w with no dialog - close-confirm-idle.ps1 F/fresh-exec and G/fresh-agent 'untouched' (ALL PASS 79).
- [x] One typed character (no Enter) brings the dialog back - F and G 'typed'; also the in-section control proving that state confirms without the fresh rule.
- [x] One `+send-keys` character brings the dialog back - F 'send-keys'.
