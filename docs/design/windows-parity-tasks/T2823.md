# T2823 - Frame lab: measure the geometry the maximize-button and blade-glide trigger plans need (T2784 follow-up): the live launcher never sets Geometry.MaximizeButton or Sidebar.Toggle/OtherEdgeX, so both cells are Blocked in the live matrix

## Summary

T2784 made the frame lab's live driver fire trigger cells, but two of the six
plans need geometry the launcher (`New-FrameLabLiveDriver`'s Launch in
`test\win32\lib\FrameLabDriver.ps1`) never measures, so `Get-FrameLabTrigger`
would throw on them:

- **maximize-button** needs `Geometry.MaximizeButton` (`@{ X; Y }`, physical
  screen px). `+list --json`'s `chrome` object reports the tab strip's
  regions in client coordinates (cli.md, T231); check whether it carries the
  caption buttons, or add them there, rather than modelling the button's
  position in the harness.
- **blade-glide** needs `Geometry.Sidebar.Toggle` (the collapse/expand
  control) and `Sidebar.OtherEdgeX` (where the sidebar edge sits in the other
  mode - rail vs expanded). The other edge can be measured the way the
  maximized still is: toggle, settle, read the `GhozttyPaneSidebar` rect,
  toggle back.

Until then `Get-FrameLabLiveMatrix` marks both cells Blocked naming this task
(`$script:FrameLabLiveTriggerGaps`); remove each entry as its geometry lands.

## Validation criteria

- [ ] Launch sets `Geometry.MaximizeButton` and the sidebar `Toggle`/`OtherEdgeX`; pure checks in `frame-lab.ps1` section A cover how they are derived.
- [ ] `$script:FrameLabLiveTriggerGaps` is empty and A19 expects both interactions to run.
- [ ] A `-Live` run of each cell reads pass or fail (NOT RUN while the user is present - input-desktop exception).
