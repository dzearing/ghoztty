# T1481 - fork-ci windows-cross fails installing msitools, so every push reads red

## In plain terms

The build machine cannot finish a Windows build any more: it dies while
installing the tool that packages the installer, before it ever compiles
anything. Nothing is wrong with the code, but every push now reports a failure,
which means the one signal that says "the branch builds" says nothing at all.

## Goals

- [ ] fork-ci's windows-cross job goes green again on an unchanged commit
- [ ] The packaging step cannot take the whole job down with it when its
      dependency source moves

## Summary

`Fork CI` run 34384937910 (commit `886dc6f1e`, 2026-09-09) failed in
**windows-cross**, at the step **"Build and install msitools 0.106 (wixl,
msiinfo, msibuild)"**, with `Process completed with exit code 100` — the apt
exit code, i.e. the package fetch/build failed on the runner. The compile step
after it ("Build Windows release artifacts") never ran, and `release-parity`
passed, so **no Zig code is implicated**: the job dies before it builds.

This matters beyond one red run. `parity-tasks.ps1 validate` FAILS on a red CI
verdict (T1219) and `go-loop-exec.ps1 claim` reports it, so as long as this step
is broken every turn's close has to reach for `-NoCiCheck` — which is exactly
the hatch that is supposed to be rare and explainable. A permanently-excused
gate is not a gate.

Two things to decide while fixing it: whether msitools should be pinned/cached
(or fetched from a prebuilt artifact) rather than built from source on every
run, and whether the packaging step belongs in the same job as the cross
compile at all — the compile is the signal the loop actually gates on, and it
is currently hostage to a packaging dependency.
