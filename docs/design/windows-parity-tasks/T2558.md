# T2558 - Composition step 3d-1: on the composition path a pane's window spans its banner band - the grid, renderer, mouse, IME and in-pane overlays all measure from below the band, so the banner can live inside the pane's own picture

## Summary

T2493 split, part 1 (geometry). The pane's DComp tree is clipped to the surface HWND, and the banner band (T101) sits OUTSIDE it: the layout moves the owner HWND down by the inset and BannerOverlay.updatePosition puts a popup at rect.top - inset. So no child visual of the pane can draw the banner today. On the comp path (GHOZTTY_COMP_PRESENT=1) with a banner, the layout must stop offsetting the owner: the surface spans the whole slot and carves the band off its top, the way applyResize already carves the scrollbar off its right. Sites to move (Surface.zig, 2026-10-31 survey): applyResize/sizeCallback height (subtract band), OpenGL.surfaceSize (reads GetClientRect - renderer must size to the grid area), gl_comp_present (content visual offset (0, band); swap chain at grid size), handleMouseButton/Move/Wheel y (L4766, L5305, L4686/4864/4895: subtract band; y<band goes to the banner, part 2), GetClientRect users L1371/L3456/L3893/L5020, ClientToScreen IME/caret L2667/L5060/L5333, in-pane overlays positioned off the surface rect (scrollbar, bell border, dim, search bar, palette, key-state pill), Window layout's inset offset, pane_clip. The knob-off (WGL) path keeps today's geometry. Oracle: pane-banner.ps1 + comp-present.ps1 green with the knob on and off; with the knob on a banner pane's surface rect equals its slot rect and its grid rows equal the knob-off build's; clicks/selection/wheel land on the same cells both ways.
