# T1497 - The machine chooser's row-pill probes go red when another chooser script ran just before it

## Summary

In the T694 sweep (`temp\suite-runs\t694`), `ipc-machine-chooser.ps1` ran
straight after `chooser-menu.ps1` and scored

    MACHINE-CHOOSER ACCEPTANCE: 4 FAILURE(S) (73 passed)

The four are all row-pill pixel probes:

- `unfocused list: the selected row still draws a neutral pill (r 255 vs gutter 255)`
- `focused list: the fill steps up to the emphasized wash (r 255 -> 255)`
- `focused list: the accent is on the indicator mark (max b-r = 0 in the mark band)`
- `the row's text starts at the composed text column (first bright column at 0, text_x = 85)`

The runner's alone re-run (T1137) then scored the same script **ALL PASS**, so
this is order-dependence in the harness, not a rendering regression. Every
probe that depends on the fake relay directory and its port passed in both
runs, so it is not T694's conversion either.

Two notes that should shorten the hunt. The capture itself is real in the red
run (`the chooser capture holds real content (64 distinct colors)` passes), and
every reading is a NULL one - r equal to the gutter, `b-r = 0`, first bright
column at 0 - which is the signature of probing the right window at the wrong
moment or the wrong rectangle, not of a window that painted the wrong colors.

## In plain terms

One of the machine-chooser tests fails when another chooser test ran just
before it, and passes when it runs by itself. Nothing is wrong with the
terminal; the test is reading the picture at the wrong moment. Until it is
fixed, every full sweep reports a failure that is not real, and a real one
could hide behind it.

## Goals

- [ ] Reproduce it deliberately: `chooser-menu.ps1` then `ipc-machine-chooser.ps1`.
- [ ] Name what the first script leaves behind that the second reads.
- [ ] The pair passes back to back, and the script still fails when the product is wrong.

## Details

Reproduce with the runner, which is what found it:

```
powershell -NoProfile -File scripts\suite-run.ps1 -Order 'chooser-menu.ps1,ipc-machine-chooser.ps1'
```

Evidence from the run that found it: `temp\suite-runs\t694\ipc-machine-chooser.log`
(the red), and the `[alone: PASS - NOT reproduced]` note in that run's
`summary.json`.

## Validation criteria

- [ ] `chooser-menu.ps1` followed by `ipc-machine-chooser.ps1` is ALL PASS, run twice.
- [ ] The fix is in the harness, not in the chooser's drawing code (or, if the
      product is at fault after all, this task says so and hands off to a
      product task).
- [ ] A negative control still fails the four probes when the pill is actually
      wrong, so the fix did not simply stop asserting.
