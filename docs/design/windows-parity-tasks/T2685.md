# T2685 - agent server test 'FLOW pause halts streaming; resume continues from buffered offset' fails in the win32 floor lane ([tripwire] untripped point=read) and passes alone

## Summary

Seen 2026-11-04 02:14 during T2676 (which touches only the Settings window): `floor-lane.ps1 -Lane win32` went red twice in a row, side by side and then alone (whole lane, log floor-lane-win32-20261104-021414-075.log) on `remote.agent.server.test.FLOW pause halts streaming; resume continues from buffered offset` with `[tripwire] (warn): untripped point=read`, 7541/7617 passed, 1 failed. Run by itself (`zig build test -Dapp-runtime=win32 -Dtest-filter='FLOW pause'`) it passed 3 of 3. The same tripwire shape as T2563 (PaneDesk): a test waits for a read that does not arrive under full-lane load. Find the timing assumption in src/remote/agent/server.zig:6638 and make the wait bounded on the event, not the clock.

## In plain terms

One of the automated checks for session persistence failed now and then when
the whole test suite ran at once, and passed when run alone. Nothing was wrong
with the terminal: when a paused pane resumes, the agent sometimes sends the
missed output and the new output as one piece instead of two. The check now
looks at the text in order, not at how it was split into pieces, so it stops
blocking every turn's test run.

## Root cause

The failing run's log has `expected PAUSED, instead found PAUSEDLIVE` at
offset 0. `handleFlow(.resume)` enqueues the catch-up DATA (offset 0) under the
store lock, and the test then feeds `LIVE` (offset 6). When the writer thread
has not drained the queue in between (a loaded floor lane), T1464's
`coalesceRun` merges the two contiguous DATA frames into one. That is the
writer's documented backlog behaviour. The bytes, the offsets and the order are
all correct. The test was the one T1464 missed when it moved the others to
`drainLiveData`: it read one frame per write. The `[tripwire] untripped
point=read` line is a warning from an unrelated test's teardown, not the cause.
