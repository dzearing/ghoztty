# T772 - agent-upgrade.ps1 has no -Release mode: the agent-refresh decision is only ever tested in the debug lineage

## In plain terms

Ghoztty decides on its own when to replace the background process that keeps
your terminals alive across app restarts — silently when nothing is running,
and with a confirmation dialog when something is. That decision is checked by an
automated test, but only against a developer build. The build you actually run
has never been through it. Nothing is known to be wrong; it is simply untested
in the shipping configuration, which is where an "only in release" defect would
live.

## Goals

- [x] A `-Release` switch that measures the agent-refresh decision in the
      lineage the user's own Ghoztty is in.
- [x] Staleness that is real in that lineage: two agent binaries, different
      stamps, no test hook anywhere in the decision.
- [x] The arms that cannot exist there say so and are counted, instead of
      quietly not running.
- [x] The user's terminal is provably untouched by such a run.

## Summary

`test/win32/agent-upgrade.ps1` (T147, plus T229's arm H) measures the whole
agent-refresh policy by outcome. Every arm runs against the DEBUG build.

T269 removed the blocker that made a release-lineage run impossible — with
`GHOZTTY_AGENT_INSTANCE` + `GHOZTTY_PIPE_SUFFIX` + a redirected `LOCALAPPDATA`,
release binaries run beside the user's own agent and leave it alone (measured;
`agent-instance-lineage.ps1 -Release`). What T269 deliberately did NOT do is
convert this script, because its staleness INPUT does not exist in a release
build.

## What makes this its own task

Arms C, D, E, H and I fake staleness with `GHOZTTY_AGENT_BUNDLED_VERSION`, and
arms J/K fake a protocol skew with `GHOZTTY_AGENT_PROTO_VERSION`. Both hooks are
**debug-only on purpose** (`LocalAgent.bundledVersion`, `protoVersionOverride`):
a stray env var must never be able to kill a user's agent or cut their app off
from its own sessions. So a release-mode run needs a genuinely stale world
rather than a faked one:

- Build the agent twice, `-Dagent-version=<old>` and the real stamp, both
  ReleaseFast — two real binaries with different stamps.
- Let the app SPAWN the old one first (`GHOSTTY_LOCAL_AGENT_BIN=<old>`), so it
  is recorded in `port.json`; then relaunch the app with the bundled path
  pointing at the NEW binary. Running != bundled, with no test hook anywhere:
  exactly the shape a real upgrade produces.
- The protocol-skew arms (J/K) have no release-mode equivalent at all and should
  SKIP with a named reason rather than pretend.

Two more differences a release run has to absorb: the app's decision log is the
`%LOCALAPPDATA%\ghoztty\ghoztty.log` file rather than stderr (one appended file
for the whole run, so each arm needs an offset instead of its own capture), and
the state dir is `local-agent`, not `local-agent-debug`.

## Validation criteria

The first criterion was written before T1056 and named an arm that no longer
exists: a stale BUILD raises no dialog at all any more, and the mandatory
confirmation is reserved for a protocol skew (arms I/J). Rewritten to the policy
the code actually has, which is the same question asked of the release lineage.

- [x] `agent-upgrade.ps1 -Release` reaches every staleness arm against a
      GENUINELY stale agent - a second ReleaseFast binary stamped
      `-Dagent-version=20200101-t772old`, running while the app ships the current
      one - and they pass: C (left strictly alone), E (adopted silently once
      idle, new pid), H (restored busy layout, untouched), L (draining), M (the
      agent replaces itself and the session comes across). Verified:
      `AGENT-UPGRADE (RELEASE LINEAGE): ALL PASS (88 assertions, 4 SKIPPED)`.
- [x] Arms with no release equivalent (I/J/K/N - all four need the debug-only
      `GHOZTTY_AGENT_PROTO_VERSION`) SKIP with a stated reason and are counted in
      the verdict line. Verified: the four SKIP lines above the verdict.
- [x] The user's own agent and their `GhozttyAgent` autostart value are measured
      before and after and are untouched (the bystander pattern T269 landed) -
      asserts P1/P2/P3, and the three isolating knobs are set through
      `Set-GhozttyTestIsolation -ReleaseSandbox`, which `-Allow` then verifies.
- [x] The debug run of the same script is unchanged: `AGENT-UPGRADE: ALL PASS
      (147 assertions)`.
