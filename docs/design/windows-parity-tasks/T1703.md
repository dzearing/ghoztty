# T1703 - Re-point viewer-feedback-alpha.ps1 onto the web composer, and split the other five harnesses into their own tasks

## In plain terms

Our automated tests for the feedback box still typed into an old, hidden text box instead of the real one people use. This task moves the first test (the one that checks see-through pictures show correctly) onto the real box, and splits the remaining five tests into their own tasks so each can be moved carefully. Nothing changes for users.

## Summary

Originally "re-point all six viewer-feedback harnesses" (split out of T937). Six scripts of 450-1100 lines each, with arms that do not map one-to-one onto a web page, is more than one context, so per the context rule it was split: this task moves viewer-feedback-alpha.ps1 and grows the DevTools driver with what it needed; T1706 (viewer-feedback.ps1), T1707 (-capture), T1708 (-carousel), T1709 (-images) and T1710 (-utf16) carry the rest, and T1704 (delete the fallback) now depends on all of them.

## Outcome

- **viewer-feedback-alpha.ps1 runs on the web composer.** It no longer pins `GHOZTTY_COMPOSER_SURFACE=richedit` and asserts `composer surface=web`. The half-transparent PNG goes in through the page instead of the OS clipboard plus a Ctrl+V into the RichEdit. The carousel pixel oracle is unchanged, because the carousel is the band's own GDI paint on either surface.
- **Driver: `Send-CdpComposerImage`** (`test\win32\lib\WebViewCdp.ps1`) pastes a picture by dispatching a `ClipboardEvent` carrying a `File` into the page's own paste listener. That is the same shape the ViewerPane.zig host floor test uses, and from the engine's delivery onward it is the path a real paste takes (decode, size check, base64, `image` message to the host).
- **Found and handled: two apps share one browser process.** Each arm launches its own app on the same user-data folder, so the second app joins the first app's WebView2 browser process. A port armed for the second app never opens, and its composer appears on the FIRST port beside the first arm's page. The first run failed exactly there (`no endpoint answered` on the dark arm). The fix is one port per script plus `Find-CdpComposer -Exclude <sessions already used>`, and the lib header now documents it.
