# T1504 - The GUI postmortem calls a deliberately terminated test GUI a crash

## Summary

test\win32\reset-context.ps1 ends its run with 'GUI POSTMORTEM ... verdict: CRASHED - 0xFFFFFFFF unnamed NTSTATUS' over a GUI that the harness itself killed at teardown (Stop-RepoGhoztty terminates it, so the exit code is -1 by construction). The run is ALL PASS, and the block prints a crash report with a stderr tail and a 'no WER record found' line under it - which is the exact shape of a REAL crash report, so the one that matters will read as more of the same. Observed 2026-09-12 on the T1502 run. The postmortem should know which pids the harness terminated on purpose and stay quiet about those, or say TERMINATED BY THE HARNESS rather than CRASHED.

## In plain terms

When a test finished and shut its own copy of the terminal down on purpose,
the crash reporter used to print a full "this app CRASHED" report anyway. That
false alarm looked exactly like a real crash report, so a real one would have
been easy to miss. It no longer happens: a terminal the test stopped itself is
not reported, and one that dies on its own still is.

## Goals

- [x] a GUI the harness kills on purpose is not reported as CRASHED
- [x] a GUI that dies on its own (including an exit of -1) is still reported
- [x] reset-context.ps1, the run this was observed on, finishes green with no postmortem block

## Resolution

Already fixed at the source by **T2058** (`c8607b32a`, 2026-10-17), before
this task was picked up: `Stop-RepoGhoztty` (`test\win32\lib\CleanSlate.ps1`)
now calls `Set-GhozttyHarnessLaunchKilled` (`test\win32\lib\AgentLineage.ps1`)
for every pid it stops, and `Write-TestDesktopPostmortems` skips a record
marked `Killed`. reset-context.ps1 stops its app through exactly that helper
(line 389, `-AppOnly`) and tears down through `Remove-TestDesktop`, which marks
its own kills, so both of its kill paths are covered. T1467 (`f2aac9901`)
later removed the last hand-rolled copy of the marking. T1363 keeps the other
direction honest: an app that exits -1 by itself is still a crash. No code
changed in this task; the validation below is what it was owed.
