# T1504 - The GUI postmortem calls a deliberately terminated test GUI a crash

## Summary

test\win32\reset-context.ps1 ends its run with 'GUI POSTMORTEM ... verdict: CRASHED - 0xFFFFFFFF unnamed NTSTATUS' over a GUI that the harness itself killed at teardown (Stop-RepoGhoztty terminates it, so the exit code is -1 by construction). The run is ALL PASS, and the block prints a crash report with a stderr tail and a 'no WER record found' line under it - which is the exact shape of a REAL crash report, so the one that matters will read as more of the same. Observed 2026-09-12 on the T1502 run. The postmortem should know which pids the harness terminated on purpose and stay quiet about those, or say TERMINATED BY THE HARNESS rather than CRASHED.
