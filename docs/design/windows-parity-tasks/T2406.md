# T2406 - Windows pane sidebar collapse/expand (button or edge drag) glides as ONE motion with the grid: the card follows the grid's glide frame by frame with the gutter held, panel and rail crossfade at their own sizes, and no blade jitters (Mac 7e2d0a9da)

## Summary

Mac main 7e2d0a9da reworked collapse/expand: the sidebar card's edge tracks the grid's drawn leading edge every grid step less the gutter (no two easings drifting apart); mid-glide the panel (at its width) and rail (at its rail width) are both drawn left-aligned, clipped by the card, opacities by progress - nothing re-lays out to the card width so nothing wraps; the edge-drag bar sits on the card's drawn edge every step; the sidebar host never resizes/moves; the grid holds cards until the stage has actually moved/been laid out at the new size (no stepping toward a layout not yet applied - right-hand blades jittered); every card incl. strips tweens rect to rect. Windows: builds on T2401 (sidebar slide-out). Port the one-motion behavior to the win32 sidebar + pane stage glide and prove it with frame sampling (frame-lab / pane-sidebar glide scripts): gutter constant per frame, no far-right blade movement during an edge drag, no wrap in the panel mid-glide. Ref docs/reference/pane-sidebar.md on main ('Collapse/expand glides - one motion').

## In plain terms

Collapsing or expanding the left sidebar should look like one motion: the
sidebar's edge and the panes beside it move together, with the same gap
between them the whole way, and the sidebar's contents fade between the
narrow rail and the full panel without squashing or re-wrapping. On Windows
the two moved on different timings. Now the sidebar follows the panes.

## Goals

- [x] The card's edge follows the grid's drawn leading edge every grid step, less the gutter (`Slide.leadingLag` -> `transition.followWidth`, `PaneSidebar.gridStepped` from `Window.stackSlideTick`)
- [x] Panel and rail crossfade at their own sizes, opacity by how far the card is between the two widths (`followProgress`; both frames were already drawn at their own widths, cut by the card)
- [x] The drag's bar sits on the card's drawn edge: flat, painted on the composed frame at the drawn width; elevated, the gutter (`sidebarEdgeGutter`) shifted by the same lag, repainted each step
- [x] The grid never jumps toward a layout mid-glide: a width change from the edge drag retargets the glide instead of ending it
- [x] The host never resizes or moves: n/a on Windows - the column HWND only ever changes width with SWP_NOMOVE (Mac's swing came from SwiftUI animating the host's frame)
- [ ] Strips tween rect to rect - already so on Windows since T2287 (`cardOf` moves every edge of a strip card); not re-measured here

## Validation criteria

- [x] Gutter held mid-glide, expand and collapse - `pane-sidebar-glide.ps1` sections 2/3, ALL PASS 40; negative control 0 of 6 held (see T2401).
- [x] Edge drag glides to the end under a pointer flood - section 5, 168/170 and 166/166 steps painted.
- [ ] Far-right blade holds still under an edge drag (Mac `theSidebarsEdgeDraggedByTheMouse`) - not sampled; T2392's live matrix is the on-desktop home for it.
