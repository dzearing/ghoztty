# T2913 - Git-status diff viewers and animated images pause in hidden windows on Windows: no polling or GIF frames while covered or minimized, one catch-up when shown (port of Mac 68a8344f0, split from T2909)

## Summary

Part (5) of the Mac 68a8344f0 port, split from T2909. Mac: ViewerView.startWatchingDiff skips the git-status: poll while the window cannot be seen and refreshes once when shown; ViewerImageView.advanceFrame stops an animated image on its frame and goes on when shown. Windows: the git-status poll lives around ViewerPane.zig / viewer_diff.zig / ViewerDiffProbe.zig, GIF playback in the viewer image path (gdiplus_decode.zig). Gate both on the window being seen (Window.occluded / minimized; ViewerPane.setVisible already gets hidden state from applyOcclusion), with one catch-up on reveal. Live web pages need nothing (WebView2 throttles occluded pages itself). Acceptance: a covered git-status viewer runs no git while covered and shows a change made meanwhile within a poll of being revealed; a covered GIF stops advancing.

## In plain terms

A "what changed in my repo" pane kept running git every two seconds even
when its window was minimized or buried under other windows, and pages in
viewer panes could keep animating where nobody could see them. Now a hidden
pane does nothing: no git runs and no frames are drawn, and the moment the
window shows again the list is brought up to date at once, including
anything that changed meanwhile.

## Goals

- [x] a `git-status:` pane skips its poll while its window is minimized or covered (or its tab is not showing)
- [x] one catch-up listing the moment the pane shows again
- [x] animated content (GIFs, page animation) in a hidden viewer pane stops drawing and goes on when shown

## Design

- `src/apprt/win32/hidden_poll.zig` (pure, every lane): `Gate.tick(shown)`
  skips and remembers a hidden tick; `Gate.reveal()` says whether one
  catch-up is owed; `reset()` drops a debt when the poll is re-armed for a new
  location.
- `ViewerPane`: the `diff_timer_id` tick gates on `self.visible`, which
  `Window.applyOcclusion` / `setActiveTabVisible` already drive for
  minimized, covered, cloaked and locked windows and for background tabs (a
  stricter "hidden" than Mac's window-level check; the catch-up makes it
  free). `setVisible(true)` pays the debt with `refreshDiff` (the explicit,
  queueing ask, so a reveal is never dropped behind a busy worker).
- GIFs need no code: the viewer draws images in WebView2 (`viewer_image.route`
  is `.browser` for gif), and a hidden pane's controller is already set
  `IsVisible = false`, which stops the page's frame clock. Verified, not
  assumed: the harness's page counts requestAnimationFrame callbacks (the
  clock GIF playback runs on) and the count holds at 0 while hidden. A
  `viewer pane <id>: page paused (hidden)` debug line names the transition.

## Validation criteria

- [x] a covered or minimized git-status viewer runs no git: `test/win32/hidden-viewer.ps1` B1 (minimized, 0 git runs in 6 s) and C1 (covered, 0 in 5 s), counted from the app's GIT_TRACE file; shown control A1 = 18 runs in 5 s
- [x] a change made while hidden is shown within a poll of reveal: B4, listed 493 ms after restore, via the logged catch-up
- [x] a hidden page stops drawing (GIF clock): B3/C3 0 frames while hidden, A2/B5 ~600 frames per 5 s shown
- [x] the gate can fail: `-NegativeControl` (window never minimized) reads B1 18 git runs and B3 730 frames, 2 FAILURES
- [x] pure gate unit-tested in `hidden_poll.zig` (every lane); floor lanes - see progress log
