# T3131 - Hero mode on Windows matches Mac 997b26535: hides the pane sidebar while on (per tab), turns on over a single pane, and the carousel starts 130 px wide via new macos-hero-carousel-width (ratio now optional and wins when set; divider drag down to 5%)

## Summary

Mac 997b26535 (HeroModeState/HeroModeView, Ghostty.Config): hero mode hides the window's sidebar while on without touching the shared hide/show flag, is allowed over one pane, and sizes the carousel from macos-hero-carousel-width (u32 points, default 130, clamp 80-600) unless macos-hero-carousel-ratio (now ?f64, default null) is set. Windows reads the ratio as f64 at Window.zig ~4931 and ~23019, hero_math.zig, App.zig ~3876 and the Settings slider (settings_pages.zig ~265, key must become Carousel width = macos-hero-carousel-width). The merge of main changes the type, so the merge task needs at least the compile fix; this task carries the behavior: width in DIPs scaled by DPI, sidebar hidden per tab during hero, single-pane hero, divider min 5%. Mirror HeroCarouselRatioTests in a unit test and an acceptance script.

## In plain terms

Hero mode (one big pane with a strip of thumbnails beside it) now behaves the
way it does on the Mac: the thumbnail strip starts narrow (130 px) instead of
taking a quarter of the window, the pane list on the left gets out of the way
while hero mode is on, and you can turn hero mode on even with only one pane.

## Goals

- [x] carousel starts at `macos-hero-carousel-width` (130 DIPs, DPI-scaled, 80-600), `macos-hero-carousel-ratio` wins when set
- [x] a divider drag may narrow the carousel to 5% (not snapped back to 10%)
- [x] hero mode turns on over a single pane, and stays on when a tab drops to one pane
- [x] the pane sidebar steps aside while the active tab is in hero mode (per tab; shared hide/show flag untouched)
- [x] Settings' Carousel width is the `macos-hero-carousel-width` stepper
- [x] unit tests mirror `HeroCarouselRatioTests`; acceptance covers it on the box
