# T1610 - Every keepalive acceptance run ends with a CRASHED verdict, so a real crash there would read as normal

## Summary

Every run of test\win32\ipc-command-keepalive.ps1 ends with the GUI postmortem reporting `CRASHED - 0xFFFFFFFF unnamed NTSTATUS`, with no WER record and no dump. Measured on an untouched HEAD build (dd9ec8e6b) on 2026-09-16 as well as on a working-tree build, so it is standing, not a one-off. 0xFFFFFFFF is the exit code a TerminateProcess(-1) leaves behind rather than a real exception status, so the likely reading is that the harness teardown (Reset-GhozttyTestState / Remove-TestDesktop) is killing the app and the postmortem is scoring that kill as a crash - but "likely" is the problem: this file prints a CRASHED verdict on every green run, which is exactly how a REAL crash in that window would be read as normal and ignored. Establish which it is. If the app is being terminated on purpose, the postmortem must recognise the harness's own kill and say so; if the app is really dying, catch it with scripts\crash-catch.ps1 and fix it.
