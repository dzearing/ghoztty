# T2007 - Three acceptance scripts that default -Repo to D:\git\ghoztty load neither BuildMode.ps1 nor TestScore.ps1, so the T1996 checkout guard never sees them: parity-tasks-split-deps, release-artifacts, website-windows-download

## Summary

Found in T1996. The checkout guard (test/win32/lib/CheckoutGuard.ps1) rides BuildMode.ps1 and TestScore.ps1, which reach 282 of the 285 scripts that spell the literal. These three load neither, so run bare from lane B they still read lane A's checkout via their -Repo default. Fix: have each dot-source lib/CheckoutGuard.ps1 (or TestScore.ps1) after its param block, then re-run each harness to re-stamp its guard row (release-artifacts needs its non-Docker sections green).

## In plain terms

A test script started by hand from the second working copy could quietly
check the first copy's files instead of its own, and report that as a pass.
After this, every such script either checks its own copy or refuses to run
and says which value to pass, and a test catches any new script that slips
past.
