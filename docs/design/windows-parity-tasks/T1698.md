# T1698 - After the session manager restarts, a re-run pane no longer shows the 'session restarted' line (session-relaunch.ps1 A10/A11 red since 2026-09-02)

## Summary

test\win32\session-relaunch.ps1 arm A (session-relaunch=rerun, agent killed and restarted) fails A10 and A11 deterministically (2 of 2 runs on 2026-09-23 at 22e2b386e, debug zig-out app+agent): the SAME session id comes back alive (A9), input reaches the new child (A12), the pre-kill marker is in the pane, but the '--- session restarted ---' divider is not - the DIAG read shows the old screen, blank lines, then the fresh cmd banner. Arm B (prompt/keystroke relaunch, T923/T1264's B7) is green. Last recorded green was 29b5040be (2026-09-02). The harness has NO guard-due row (the 'session-relaunch' guard row runs session-relaunch-notify.ps1 instead), so nothing re-ran it across the ~20 agent/Remote commits since; candidates include da0d5e35b (T752 cwd restart), 83b4d19ba (T1594), df889ab87 (repaint label), 15a4d3520 (T691). Fix the regression AND give session-relaunch.ps1 a guard row so it cannot rot silently again.

## In plain terms

With "re-run my sessions" turned on, a pane that comes back after the background
session manager restarts is supposed to show its old output, then a dim
"--- session restarted ---" line, then the fresh shell. The line (and the last
prompt above it) was being wiped out the moment the window finished laying out
its panes, so the old output and the new shell ran together with a few blank
lines between. Now the line stays.

## Root cause

Not geometry, though it looked like it. The replayed history of a cmd.exe pane
ends at the dead shell's prompt, and cmd's shell integration (T512) marks a
prompt's start and end but never "a command's output starts here". So after the
replay the terminal still believed it was inside the dead shell's prompt, and
wrote the divider and the new shell's banner as if they were typed input. When a
split then settled the pane's width, Ghostty did what it does for a prompt on
resize: cleared the whole prompt region so the shell could redraw it - from the
dead prompt down, divider included. Measured with screen dumps taken inside the
live app around the park, the width reflow and the resize: the park and the
history guard were both correct, and the resize itself imported nothing.

The fix closes that prompt region: `replay_mode_reset` - the reset the agent
splices in right after the divider, before the new child's first byte - now ends
with OSC 133;D ("command finished"), which returns the terminal to plain output
and moves nothing. It lives in the shared core (`src/termio/Remote.zig`), so the
Mac seat's remote panes get it with no Swift change. The same reset is what the
`restore` policy writes behind its restored screen, so that path is covered too.
