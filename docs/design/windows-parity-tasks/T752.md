# T752 - a restored or fresh-swapped remote pane opens in the agent's default directory, because the manifest records no working directory

## In plain terms

When a pane's shell has to be started over — the machine rebooted, the agent
restarted, you clicked Reconnect — the new shell comes up in the home directory
instead of the folder you were working in. Everything else about the pane comes
back: its place in the layout, its title, its banner, its name. The one thing
that decides whether the pane is immediately useful is the directory, and that
is the thing that does not.

## Goals

- [x] The manifest records each terminal pane's working directory.
- [x] A pane that has to open a fresh shell comes up in it — launch restore,
      in-place recovery, and the reconnect swap alike.
- [x] A directory that has since been deleted still gives the user a pane.
- [x] A manifest written by an older build restores exactly as it does today.

## Summary

Found while building T611's fresh-session swap (2026-08-11). The session-layout
manifest's `Leaf` (`src/apprt/win32/session_layout.zig`) records
`session_id`, `title`, `ipc_name`, `pane_id`, `banner`, `kind`, the viewer
locations and the screen snapshot — and **no working directory**. So
`restoreAttachOverride` has nothing to put in `Overrides.remote
.working_directory`, and every path that OPENs rather than ATTACHes gets the
agent's default:

- the launch-time restore of a leaf whose recorded session is gone,
- the local-agent in-place recovery of the same,
- T611's manual fresh-session swap of a cross-machine window.

`+list --json` already reports each pane's `working_directory`, so the value is
available at capture time; what is missing is the field, the capture, and the
restore. Note the value is REMOTE-native for a cross-machine pane — a path from
the other machine — which is exactly what the agent OPEN wants, but means the
field must never be reused as a local path.

Worth deciding while implementing: what to do when the recorded directory no
longer exists on the machine the pane comes back on. The session-relaunch path
already answers this for its own case (fall back to `%USERPROFILE%` rather than
failing the pane) and this should match it rather than invent a second rule.

### How each was verified

- **Criteria 1 + 2** — `test\win32\remote-reconnect-fresh.ps1` arm D (new): the
  window is opened in a directory of the test's choosing, the agent is dropped
  and Reconnect clicked, and both fresh panes are asked where they are by the
  SHELL (a bare `cd`) rather than by reading our own cache back. 15/15 green.
  Its teeth were demonstrated rather than assumed: with `captureLeaf` stubbed to
  record nothing, D1 and D2 — and only D1 and D2 — went red, with the panes in
  `D:\git\ghoztty`, the agent's inherited directory. That is the reported defect
  reproduced on demand.

  One honest deviation from criterion 2 as written: the arm does not `cd`
  mid-session before the drop. A CROSS-MACHINE pane gets no shell integration
  from us, so a remote `cmd.exe` never reports OSC 7 and there is no local pid to
  read — a `cd` there tells the app nothing, which is a real gap and is now
  **T1583** (sample the cwd agent-side and push it as `META{cwd}`). What arm D
  proves is the half that is this task's: the recorded directory is captured,
  carried, and spent on the fresh OPEN.
- **Criterion 3** — the agent's `resolveSpawnCwd` (T230) already answers this
  and has its own unit tests in `src/remote/agent/pty_child.zig` ("a missing
  directory falls back to home, never to failure"); the local exec path's
  `access` check drops an unreachable cwd and inherits. The restore side adds
  no second rule, which is what the card asked for.
- **Criterion 4** — `session_layout.zig`: "a pre-working-directory manifest still
  loads, with a null directory", plus the open-path rule's own null case in
  `App.zig`.
- **Criterion 5** — `floor-lane.ps1 -Lane all`: lib / none / win32 / agent all
  PASS. `-Lane harness` PASS (stamped). The nine acceptance harnesses
  `guard-due` named for these files all exit 0.
