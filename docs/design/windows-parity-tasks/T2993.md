# T2993 - PA-W09: every elevated chrome paint reads the light/dark theme from the registry three times (system_colors.zig:151, Window.zig:1619)

## Summary

PA-W09 (audit-1, T2960). chromePalette (Window.zig:1616-1620) calls systemUsesLightTheme() unconditionally; system_colors.zig:146-153 usesLightTheme does RegOpenKeyExW + RegQueryValueExW + RegCloseKey (readDword, :423-438) with no cache. Called from the caption (:18649), strip (:19248) and desk (:14256) paths: three registry round-trips and three chrome_theme.resolve contrast searches per paint. The comment at Window.zig:1611-1613 (no registry per paint) is true only for the accent. Fix: cache the bool beside cached_accent, drop it in system_colors.invalidate() (WM_SETTINGCHANGE already calls it), and memoize the palette on (base, accent) as panelPalette does (:173-184). Risk low: make sure every invalidation source drops it.

## Validation criteria

- [ ] no registry read per paint (unit test on the cache, or trace)
- [ ] switching Windows light/dark still re-themes the chrome live (theme acceptance green)
