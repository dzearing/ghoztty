# T2535 - Chain-fold oracle misreads the near-full-monitor window: (b) counts a terminal text column's left edge as a rim (run49: 93 rims at x1708-1716) and a GPU-overlay toast as novel colour (run48 f82-87 #446600), and (d) is blind on 35 frames because WGC hands over fewer frames at ~3700 px wide

## Summary

Found scoring T2485 run48/run49 (first complete near-full-monitor captures, -QueueGB 16, zero queue drops). The rim check needs the same text exclusion the normal window got, the novel-colour check should ignore pixels outside the panes' union or a known overlay rect, and (d) needs a measure that holds when WGC delivers below the refresh rate at this size (recorder reported gaps=170/146). Until then the near-full verdict on b/d is not trustworthy; a (black) still is. Close when run48/run49 re-score with zero rims/novel from those causes and d reports a measured verdict, with synthetic sections added for each.

## In plain terms

The automated judge that watches a recording of the "drag one divider across
six panes" scenario frame by frame was wrong about the big, nearly
full-screen window. It reported a glowing border that was really the edge of
the purple divider. It reported a strange colour that was really a graphics
driver's pop-up ("Press Alt+Z"). And it could not say whether the window kept
up with the mouse, because the screen recorder delivers fewer frames at that
size. Now it ignores the first two and gives a real answer on the third, so a
red result on the big window means the app, not the judge.

## What was wrong (root causes, measured on the frames)

- **"Text edge" rims were the accent's edge.** run49 f215: x1708 = `564174`
  beside the accent `A94DC1` at x1709-1713. The accent-edge exclusion only
  engaged for a steady colour absent from the FIRST frame; on run49 the
  divider was already lit under the pointer on the press frame (f74
  x689-693 = `A94DC1`), so the exclusion never switched on. Now a steady
  colour missing from either end qualifies (one in both ends is background).
- **The novel colour was NVIDIA's "Press Alt+Z" toast** at x3208-3731
  y179-362, over pane 6 (inside the panes' union, so a union mask would not
  have helped). Recognised by its brand bar (an unbroken saturated-green run
  >= 60 px tall, <= 16 px wide), extended right across its dark panel; the
  rect is sticky and only the colour checks skip it.
- **run48 f90 #AA44BB**: the grabbed accent one step off for one frame (that
  run's press frame had no accent yet). One step from a drag-steady colour now
  counts as a blend, like one step from an end state.
- **Black strips were double-counted as rims** (all 32 of run49's full-height
  rims = its 32 black findings). A rim inside a black finding's columns on the
  same frame is the black check's.
- **(d) blind 35**: at ~3700 px WGC hands over a frame every 2-3 refreshes, so
  nearly every span had a hole. A holed span is now settled by evidence: still
  frames that prove the picture did not change for > 16.7 ms (a gap, source
  `screen`), else the app's `stack trace batch ... end=` stamps (`app.log` in
  the run dir, or `<run>-stderr.log`): batches never > 16.7 ms apart =
  Resolved, wider = a gap (source `app`). Only what neither can settle stays
  Blind.
