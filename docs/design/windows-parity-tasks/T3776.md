# T3776 - Nobody has measured a release-mode session agent's memory over many pane open/close cycles on Linux

## Summary

T3646 proved the Debug agent's per-session private-memory climb (~27-45 KB) is DebugAllocator page pinning, not a leak: its live heap stays flat. Users run a release agent on std.heap.smp_allocator, whose private memory over 50+ open/close cycles has never been measured. Add a mode to test/linux/pane-close-memory.sh (or a sibling) that runs a release-built agent beside the Debug app without colliding with the debug agent's state dir, and assert the agent's private memory is flat after warm-up.
