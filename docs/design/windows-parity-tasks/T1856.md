# T1856 - An elevated window's divider drag repaints the whole desk every mouse move: 17.9ms paint per move in Debug against 169us for the flat line (drag-perf)

## Summary

T1831's PaneDesk.paint copies the cached desk, rasterises every card's shadow ring and BitBlts the whole content area on every layout pass. drag-perf measured 17,938us of paint per move with the default elevated style against 169us flat (Debug): still under the 33ms two-frame budget, but about 100x. Options: blit only the union of the cards' old and new shadow rings plus the moved gap; cache each card's shadow sprite per size; skip the memcpy by compositing straight into the window DC's clip. Measure Release too.

## In plain terms

Dragging the line between two panes under the default raised-card look made
the app redraw every pixel of the window's background, shadows and card
edges the slow way on every mouse move, so the drag felt sticky. The drawing
now does the same job with a fraction of the arithmetic, producing exactly
the same picture, so the drag keeps up better. Anyone who resizes panes
notices.

## Details

What the paint was doing: `pane_elevation.paintCards` evaluated
`roundRectDistance` and `erfc` (an `exp`) for every pixel of every card's
shadow reach (37px at 150%, both layers) and every glow pixel, and the
default glass card ran `glassMix` (three float mixes and table walks) on
every interior pixel, about the whole window.

What it does now:

- **Separable distance (`Frame`).** The rounded-rect distance is a function
  of a horizontal term (x only) and a vertical term (y only) and couples them
  only in the four corner squares. Off the corners it is the distance to one
  straight edge, so a shadow's/glow's alpha is computed once per column
  (table) and once per row (scalar). `roundRectDistance` itself is now
  written through `Frame`, so the table values are the per-pixel values to
  the bit.
- **Solid interior** is a row `@memset`.
- **Glass interior** is `GlassLut`: four byte-indexed lookups per pixel
  (three channel mixes and the coverage), built once per paint.
- The old rasteriser is kept in the test section as `refPaintCards`, the
  oracle the fast one is held to.

Not done (would change pixels or needs more machinery): skipping the card
interior the child window covers anyway, dirty-rect blits, and caching shadow
sprites per size (a drag changes the size every move, so the cache would miss
exactly when it matters).
