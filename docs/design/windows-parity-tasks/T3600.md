# T3600 - Linux L8f: a stale (older-build) local agent is refreshed, and a protocol-skewed one gets the mandatory-update notice, on GTK

## Summary

T3400 brought in-place recovery when the local agent dies or its link stays down. What it left out is win32's other two LocalAgent behaviours: when the running agent is an OLDER build than the app (agent_upgrade.zig: drain, restart onto the new binary, rebuild panes in place through the same AgentRecovery path) and when the HELLO handshake reports protocol skew (the mandatory-update notice instead of a silent exec fallback). Port both onto src/apprt/gtk/LocalAgent.zig + AgentRecovery.zig, with a test/linux acceptance that plants an older agent build.

## In plain terms

The background process that keeps Linux terminal sessions alive outlives the
app, so after an update an old copy can keep running for days. Now the app
notices: when nothing is running in it, the old copy is swapped for the new one
quietly and the windows carry on; when sessions are running it is left alone
until they close. And when the old copy is too old to talk to at all, the app
asks before restarting it instead of silently losing session persistence - or,
if the app itself is the old side, says so and touches nothing.

## Goals

- [x] An older agent build with nothing live is restarted onto the bundled build and its panes rebuilt in place, asking nobody
- [x] An older agent build with live sessions is never restarted for it (T1056); the check runs again when the last window closes
- [x] A protocol skew where the agent is older shows the mandatory-update dialog (Later is the default); Restart brings session persistence back
- [x] A protocol skew where the app is older notifies the user and never stops the agent
- [x] A pid read from `port.json` is verified to be the agent before it is signalled
