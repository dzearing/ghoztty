# T2900 - Machine chooser: dial the per-row load probes and draw the reading (T1440 part 2)

## In plain terms

Ctrl+Shift+N lists the machines you can open a window on, and no row says
how busy its machine is. This is the half that makes the rows actually show
it: each visible machine's row grows a live `CPU 12% · 3.2 GB / 16.0 GB`
after its hostname while the picker is open, and a machine that cannot be
reached keeps its plain line instead of a number that is not true.

## Summary

Split out of T1440 at the context boundary. T1440 landed the pure model in
`src/apprt/win32/chooser_load.zig` (none lane, 15 tests): the subline text
(Mac's `tcpSublineText` format, appended to the hostname), `plan` (which
visible rows get one of the 8 probes, the selected machine excluded), and
`Backoff` (per-MACHINE retry memory that survives filter keystrokes). This
task is everything with a socket or a pixel in it.

### What to build

- **Probe set** (`chooser_load_conn.zig`, modeled on `activity_probe_conn.zig`):
  fixed slots held by value in the chooser, `(chooser id, serial, gen)` landing
  rule, dial on a detached thread, result posted to the APP's message-only
  window and routed by chooser id (as `SessionCpuProbe`/`onSessionCpu` do —
  the chooser has no message window of its own and is short-lived), subscribe
  with `Connection.subscribeMetrics(chooser_load.interval_ms, ...)`, and
  unsubscribe-before-free teardown. Failures go into `chooser_load.Backoff`,
  not the slot.
- **Selected machine**: its reading rides the pooled connection
  (`warmRemoteConnection` / `onPoolChange`) via a second metrics subscriber —
  the stream multiplexes since T1632 — and is retargeted with the meter and
  roster in `retargetStreams`.
- **Local row**: an in-process `remote_metrics.Sampler`, discarding the first
  (baseline) sample, like `ActivityMonitor.sampleLocalCard`.
- **Sync on a tick + on filter change**: `chooser_load.plan(visibleIds,
  selectedOrNull, ...)`, retire slots no longer wanted, retire quiet links
  (`chooser_load.isStale`), dial what is due (`Backoff.due`).
- **Paint**: `rowText` passes the reading through `chooser_load.subline` into
  the row's subtitle (scratch buffer per row; the row painter already
  ellipsizes). Invalidate only rows whose text changed.
- **Teardown** in `destroyState`: stop every probe, bump gen, so in-flight
  dials free their connection when they land.

## Validation criteria

- [ ] A chooser row for a reachable machine shows a live CPU/mem reading.
- [ ] A machine that refuses the dial shows its plain subtitle, not a spinner
      that never resolves, and is not re-dialed in a tight loop (log shows the
      backoff deadline; typing in the filter does not reset it).
- [ ] The SELECTED machine gets its reading without a second connection to it.
- [ ] Closing the chooser with dials still in flight frees every connection —
      asserted on the socket count, as `activity-monitor-remote.ps1` H7 does.
- [ ] Both `zig build test` lanes plus `zig build test-agent` green; P1-P3 ALL
      PASS; a new acceptance harness for the above has a guard-due row.
- [ ] Mac twin T1441 still open or done - platform symmetry noted in the log.
