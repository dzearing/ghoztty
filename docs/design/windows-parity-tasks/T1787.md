# T1787 - background-opacity fades the text with the background and turns background-blur into a no-op: the window is whole-window LWA_ALPHA, not per-pixel alpha

## Summary

T1016 measured it: every translucent ghoztty window is WS_EX_LAYERED + SetLayeredWindowAttributes(LWA_ALPHA), which fades the WHOLE window uniformly - glyphs, cursor and chrome as well as the background - where Mac's background-opacity makes only the background translucent and keeps text fully opaque. The same layering defeats every DWM blur: over a sharp checker the high-frequency energy under the window is 12.62 with no blur, 12.66 with the shipped accent blur, 12.62 with the Win11 acrylic and Mica backdrops - nothing blurs (the accent only lightens the view). A non-layered window with per-pixel alpha 0 in the client blurs under the same probe (1.13 accent, 0.00 acrylic). The fix is a per-pixel-alpha present path: the renderer clears to background at background-opacity with premultiplied alpha into a surface DWM composes by alpha (candidates: WGL pixel format with alpha plus DwmEnableBlurBehindWindow with an empty region on the top-level, or a DXGI/DirectComposition swapchain), chrome painted alpha-correct, and no LWA_ALPHA. Unblocks the background-blur follow-up.

## In plain terms

With a see-through background turned on, Ghoztty on Windows used to fade the
whole window evenly - the text went see-through along with the background,
and so did the title bar and tabs. On a Mac only the background is see-through;
the text stays solid and readable. Now Windows does the same: the desktop shows
through the background, and the text, cursor, title bar, tabs and viewer bars
stay solid.

## Goals

- [x] The terminal background is see-through at `background-opacity`; glyphs and the cursor are fully opaque
- [x] The caption band, tab strip, split dividers and pane headers stay opaque (GDI chrome made alpha-correct)
- [x] GDI child windows of the top-level (viewer host and everything in it, the tab-rename box) stay opaque
- [x] `toggle_background_opacity` still switches a window opaque and back, and a new window still inherits it
- [x] An acceptance harness that reads DWM's composite and fails on the old mechanism

## Design (the calls made)

- **Mechanism: `DwmEnableBlurBehindWindow` with an EMPTY region** on the
  top-level, plus `PFD_SUPPORT_COMPOSITION` on the panes' WGL pixel format. The
  renderer already writes premultiplied alpha (`load_color` in
  `shaders/glsl/common.glsl`), so the panes needed no renderer change. Measured
  first with a probe before anything else was built: the GL child windows ARE
  composed by their alpha this way. The DXGI/DirectComposition swapchain
  alternative would have rebuilt the present path for no observable gain.
- **Chrome is opaque, not translucent.** Under LWA_ALPHA the caption and tab
  strip faded with everything else; now they are solid. Mac's native titlebar
  is an opaque system material, and the design system's contrast floor (T306:
  chrome text >= 4.5:1) cannot hold over an arbitrary desktop showing through.
  A mechanism call under the 2026-08-14 directive, recorded here.
- **One wrapper, not an edit per painter.** `paintAlphaCorrect` paints the
  chrome into a 32bpp buffer pre-filled with a marker, makes every pixel a
  painter touched opaque and every untouched pixel transparent
  (`chrome_alpha.zig`, unit-tested), and lays it down with a source-over
  `AlphaBlend`. Source-over matters: the first cut blitted the whole clip box,
  and the post-layout divider pass then erased the caption (caught by the
  harness, assertion D).
- **GDI children: an opaque layered child** (`Window.composeOpaqueLayer`,
  `WS_EX_LAYERED` + constant alpha 255, Windows 8+). Applied to the viewer
  host - which covers the nav bar, find bar, TOC, feedback bar and the cards in
  one bit - and to the inline tab-rename EDIT.
- The toggle state moved from "is the window WS_EX_LAYERED" to
  `Window.translucent`, read by the toggle, `new_window`'s inheritance and
  `isForcedOpaque`. Disabling blur-behind must NOT pass a region (DWM answers
  E_INVALIDARG - measured, it left the window translucent).
