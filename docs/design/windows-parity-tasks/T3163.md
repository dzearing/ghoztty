# T3163 - A pane that moves to another window (or a parked workspace that comes back) keeps its banner's terminal inset: check the win32 banner layout does not reset on reparent and leave the text under the card (Mac 199403483)

## Summary

Mac 199403483 (v1.55.1): the banner card's onDisappear reset its height/inset/reveal whenever the pane left the hierarchy, so a parked workspace or a pane moved to another window came back at the same banner height without re-firing the height preference, and the terminal was laid out under the translucent card. Fix: reset only when the banner is CLEARED. Windows: verify the same on pane drag-to-another-window (pane_drop) today, and on workspace switch once single-window mode (T3136) lands; if win32 BannerOverlay/Surface resets the inset on reparent, key the reset to the banner clear instead. Mac test: SingleWindowModeTests.aBannerStillHoldsTheTerminalBelowItAfterASwitch; doc: docs/reference/banners.md.
