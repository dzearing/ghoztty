# T1800 - Per-pane input writer on Windows (from main 7e78aacf4)

## In plain terms

Pasting a very large block of text into one Windows terminal pane used to
freeze typing in every other pane for several seconds, because all panes'
keystrokes went through one shared line that waited for the slow pane. Now each
pane has its own line, so a busy pane only slows itself.

## Scope (re-cut 2026-10-10)

This task was filed as the whole Windows proof of Mac commit 7e78aacf4. It was
split at claim time (one task per context): the piece that was explicitly
POSIX-only - per-child input writer threads - lands here; the reboot/re-attach
acceptance port (exact history, no answered queries, no stray modes, live
prompt, real size, survives resize) is **T1817**.

## Summary

Mac commit 7e78aacf4 (merged 39d2471b8, 2026-10-07). The Mac first reproduced
the failures with `scripts/e2e/session-persistence.py --reboot-tui` (14
failing assertions on 1.37). The causes it fixed are nearly all in shared
code:

- Reboot replayed the RAW ring, so queries were answered into the new shell
  and keyboard modes stayed on. The agent now keeps a content-only HISTORY
  per session (`grid_snapshot` scrollback, `<id>.hist`) and replays that.
- The client inbound ring dropped the rest of any frame over 256 KiB. It now
  overflows per channel, and FLOW resume sends the paused output.
- One non-reading pty blocked every pane's input; the fix is per-child
  writer threads. The new test begins `if (is_windows) return
  error.SkipZigTest; // POSIX writer thread only`, so Windows needs its own
  answer: one blocked ConPTY input pipe must not stall other panes.
- The remote IO mailbox overflowed on big replays (`drainRing` now yields).
- Panes opened at the 49x17 placeholder; they now wait for the real size.
- Offset inflation froze panes after app restarts (additive
  `Attached.replay_len` plus a discard-watermark clamp).
- The recorded cwd is now the shell's live cwd; orphan snapshots are swept;
  extended VT modes are reset; restored rows keep soft wraps and OSC 133
  marks, so a resize no longer blanks restored output.

`src/remote/protocol.zig` changed, so T1796's merge must respect the
app<->agent compatibility rules in docs/claude/sessions.md.

## Validation criteria

- [x] A pane whose ConPTY input is not being read does not stall typing in
      another pane of the same agent. Measured first: inline `WriteFile` to the
      ConPTY input pipe ran at ~1.7 MB/s with a non-reading child (1 MiB 0.6 s,
      8 MiB 4.9 s on the shared thread). With the writer thread, the unit test
      `PtyChild: a child that never reads stdin cannot block the writer — or
      terminate` (now enabled on Windows, 8 MiB, < 2 s bound) passes; a negative
      control proved the test runs on Windows rather than skipping.
- [x] Tearing a pane down with input still queued completes (same test, < 5 s):
      `Pty.closeConsole` now also closes the input pipe's read end so a writer
      parked mid-write gets BROKEN_PIPE.
- [ ] Moved to T1817: the `--reboot-tui` port (exact history, no answered
      queries, no stray modes, live prompt, real size, resize).
- [x] `floor-lane.ps1 -Lane all` green (see progress log).
