# T1402 - A repo-built ghoztty CLI run inside a pane of the installed release talks to the USER's app

## Summary

`zig-out\bin\ghoztty.exe +list --json`, run from a shell inside a pane of the
INSTALLED release, answers about the installed release: same for `+read`,
`+send-keys`, `+close`. The debug build derives the `ghoztty-debug-<user>` pipe
(T350's endpoint isolation), but every pane exports `GHOZTTY_IPC_SOCKET`, and
that per-pane override outranks the derivation — so the dev binary dials the
user's app because of where it was launched from, not what it is.

Found while working T1396: the first `+list` of a freshly launched dev instance
reported `"mode":"ReleaseFast"` and `"exe":"...\\Programs\\Ghoztty\\ghoztty.exe"`,
i.e. the user's terminal, with the loop's own windows in the tree. Clearing the
variable made the same command answer about the dev build.

## In plain terms

The developer build's command line, run from inside the terminal you are using,
quietly drives the terminal you are using instead of the copy under test. Every
answer it gives is about the wrong app, and nothing says so.

## Details

- The override is deliberate and load-bearing for instance addressability
  (`docs/claude/cli.md`) — a pane's tools must reach the app that owns the pane.
  What is missing is the LINEAGE check: a debug-lineage client honouring a
  release-lineage endpoint (or the reverse) is never what anybody meant.
- Candidate shapes: refuse (with the one-line remedy) when the inherited
  endpoint's lineage does not match the client's own build mode; or have the
  test isolation helper clear it, which only helps scripts that remember to.
  The refusal is the one that cannot be forgotten.
- `Set-GhozttyTestIsolation` and `test\win32\lib\BuildMode.ps1` are the existing
  places this rule would live for the harness side.

## Resolution

**Redirect with a note, not a refusal.** The bake exists for the opposite
direction — the release `ghoztty` on `$PATH` run from a DEBUG app's pane must
reach that debug app (`src/apprt/ipc.zig` header, `docs/claude/cli.md`), so a
symmetric lineage refusal would break the case the override was built for. A
debug client now declines exactly one baked value, the installed release's own
endpoint (`ghoztty-<USERNAME>` pipe / `ghostty-<uid>.sock`, compared by name),
derives its own instead, and says so on stderr (stdout stays the JSON answer).
Every other bake — another debug instance, a suffixed sandbox — is honoured.
Rule: `ipc_client.honouredBaked`; applied in `ipc_client.clientEndpointPath`
(Windows) and `apprt.ipc.socketPath` (POSIX), so the Mac CLI gets the same
behaviour.
