# T3411 - Linux L9b: viewer panes live in the split tree - +new-window/+split --view, +list view:, terminal verbs refuse

## Summary

Retype the GTK split tree leaf from Surface to a terminal-or-viewer pane (the win32 PaneView shape, T90a) so a viewer resizes, focuses, zooms, closes and persists through the same code paths. Serve --view on +new-window and +split (relative paths against --working-directory else the caller cwd; git-*: never path-resolved; about:blank = blank browser pane), +list view: prefix and JSON type viewer + url (current location), +read/+send-keys/+set-state/+set-banner fail with ...is a viewer pane, not a terminal, +close never prompts. Replace the view_not_yet sentence in IpcHandlers.zig.

## In plain terms

On Linux, asking Ghoztty to show a file or web page beside your terminal
(`ghoztty +split --view=README.md`) used to answer "not served yet". Now it
opens the document in a pane right in the window, the same as on Mac and
Windows: it splits, resizes, focuses and closes like any other pane, scripts
can see it in `+list`, and commands meant for terminals politely refuse it.

## Goals

- [x] `+split --view` and `+new-window --view` open a viewer pane in the split tree
- [x] relative paths resolve against the caller's directory; `git-*:` specs, URLs and `about:blank` pass through
- [x] `+list` shows the pane as a viewer with its current location (`view:` in the text form)
- [x] `+read` / `+send-keys` refuse a viewer with the shared sentence
- [x] `+close` closes a viewer with no confirmation
- [x] `--name` is reused for the same view and refused for another
