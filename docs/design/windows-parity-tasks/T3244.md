# T3244 - The release session agent's base memory doubled (9.3 -> 17.7 MB) and each session holder grew 12.5 -> 17.8 MB when release agents moved to smp_allocator (T3017): measure the retained per-thread caches and decide the allocator per process

## Summary

Split from T3235 (which took the idle-CPU half). baseline-4 release: agent base private_mb 9.3 -> 17.7 and per-session child private 12.5 -> 17.8 MB; Debug unchanged (9.8 / 12.45), and Debug still uses DebugAllocator, which points at 674561478 (T3017: release agents use std.heap.smp_allocator, which keeps per-thread free lists and never returns them). Measure before choosing: private bytes of an idle agent and an idle holder under smp_allocator vs c_allocator (msvcrt/ucrt heap, thread-safe, returns memory) vs the old DebugAllocator, with the T3017 throughput number (relay-throughput / pane-ingest-ab) beside each. A holder serves one session with few threads and may not need smp at all. Keep T3017's ingest win; report the memory/throughput pair in the task. Validate with perf-baseline -Build Release -Phase agent (base and per_session_child_private_mb) and the T3017 throughput harness.
