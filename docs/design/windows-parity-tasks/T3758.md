# T3758 - An explicit bash command (-e bash --rcfile X, command = bash --rcfile X) gets no shell integration on an agent-hosted pane: it rides OPEN.command under the default shell and the injection lands on that outer shell

## Summary

Found by T3630 in WSL: a GTK pane launched with -e bash --rcfile <file> logs 'local shell integration injected shell=bash via argv rewrite (2 args)' yet the pane never sees an OSC 133 mark (resize pace=debounce content=output row=none on an idle prompt). Surface.zig forwards a non-bare explicit command as OPEN.command and computes the integration for the inherited SHELL (the outer shell the agent wraps the command in), so the inner bash - the one the user asked for - is unintegrated. Upstream Ghostty's exec path integrates it (shell_integration.setupBash handles --rcfile/--init-file). Shared core (src/Surface.zig), so Mac and Windows agent panes have the same gap. Manually sourcing ghostty.bash in that rcfile works (pace=now, released by=redraw). Fix direction: when the explicit command's argv[0] is a shell setup() can integrate, run setup() on the whole command and forward the rewritten argv as OPEN.argv instead of OPEN.command - the T514 bare-shell rule extended to a shell with arguments.
