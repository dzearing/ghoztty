# T3149 - PA-C19: the Windows font index is built on whichever thread asks first, so with font-family set the first window waits 60-75 ms on the GUI thread, and a rebuild after a font install runs under the grid lock

## Summary

Audit-3 (T3101), area C, verified at d0d874326. WindowsFontIndex.candidates (src/font/WindowsFontIndex.zig:118-126) takes the index mutex and calls currentLocked, which builds or rebuilds the snapshot synchronously (:152-166). The prewarm does not cover the first query, so with font-family set SharedGridSet (src/font/SharedGridSet.zig:180, :195) waits for a full build on the GUI thread (60-75 ms warm per T3011, against 8.4 ms before; cold-cache unmeasured), and after a font install the rebuild happens inside the grid's exclusive lock. Fix: start the build at app start on a worker and have the first query wait only on what is left; rebuild off-lock and swap. Detail: docs/design/perf-audit/audit-3/C-findings.md.
