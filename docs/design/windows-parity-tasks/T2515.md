# T2515 - A composition-present pane must still look right on a translucent window (background-opacity < 1): the terminal background shows the desktop through and glyphs stay opaque, same as the WGL path

## Summary

Found in T2488: a DComp swap-chain visual under a LAYERED (LWA_ALPHA) top-level is absent from the composed picture - the pane read blank in the WGC grab while the WGL path drew the same frame (grabs of 2026-10-30, `GHOZTTY_DEBUG_GHOST=1`). Today's translucency is per-pixel alpha, not LWA_ALPHA (`Window.setTranslucent`, T1787), so this is not a live user bug; but nothing has checked that the swap chain's alpha mode composes the same see-through picture (background shows the desktop, glyphs opaque) as the WGL path. Check it on screen with the T2488 oracle before the default flips.

## In plain terms

With the new, smoother way of drawing terminal panes switched on, a
see-through window (background opacity below 100%) was not see-through at all
inside its panes: the terminal background came out solid. Now the desktop shows
through the background exactly as it does on the old drawing path, the text
stays solid, and switching the window opaque and back, or changing the opacity
in the config while the window is open, gives the same picture on both paths.

## Goals

- [x] The new drawing path composes a translucent window's panes by their alpha (premultiplied swap chain)
- [x] Toggling the window opaque shows a solid background on the new path, as on the old
- [x] A config reload that makes an opaque window translucent rebuilds the pane's swap chain so it turns see-through too
- [x] The on-screen oracle measures real alpha and proves all three, and can go red

## What landed

- `src/renderer/gl_comp_present.zig`: `Presenter.init(..., premultiplied)`;
  `alphaMode` (PREMULTIPLIED for a translucent window, IGNORE otherwise, so an
  opaque window's pane is still never blended), `forceOpaqueAlpha`,
  `needsAlphaRebuild`, with unit tests.
- `src/apprt/win32/Surface.zig`: `window_translucent` (atomic mirror of the
  window's mode for the renderer thread), set at init, by every layout pass
  (covers a pane moved to another window) and by `setWindowTranslucent`, which
  kicks a frame on a change. Composition panes no longer take an own layer
  (T2499): see Findings 2.
- `src/apprt/win32/Window.zig`: `setTranslucent` tells every pane.
- `src/renderer/OpenGL.zig`: the chain is made premultiplied when the window
  is translucent; an IGNORE chain under a window that turned translucent is
  rebuilt (`composition swap chain rebuilt: the window turned translucent`);
  a premultiplied chain under a window toggled opaque has its frame's alpha
  cleared to 1 after the blit (the picture the WGL window shows when it stops
  honouring alpha).
- `scripts\comp-present-onscreen.ps1`: `-Opacity`, raw-BMP alpha scoring
  (System.Drawing drops a 32bpp BMP's alpha, so the first probe read 255 on
  both paths), a toggle check per arm (bare F9 POSTED to the pane), the
  `reload`/`reloadoff` arms, and cross-path comparisons A3/A4. `-Arms on,off`
  through `-File` now splits on commas.

## Findings

1. **Measured defect, before the fix**: background-opacity 0.8, WGC grab raw
   alpha: WGL pane background mostly 204 (see-through), composition pane
   mostly 255 (solid). The swap chain was `DXGI_ALPHA_MODE_IGNORE`.
2. **A pane born in an opaque window took its own layer (T2499)**, and after
   a reload to 0.8 the dropped layer still sat under the composition visual:
   background alpha 224 where WGL reads 204 (it survived a toggle pair and a
   window resize; `GHOZTTY_PANE_LAYER=0` gave 204.1). A composition pane never
   presents into its window, so the layer bought nothing there - the same
   reason the window-presenter path already skipped it. If the composition
   chain fails and the pane falls back to WGL, it runs without its own layer
   (T2499's memory saving only, no picture change).
3. **Never post a Send-TestKeys chord on the input desktop**: its
   AttachThreadInput + SetFocus made the ghost the foreground window in the
   first run (`.F` caught it). A bare key posted with PostMessage reaches the
   keybind without moving the foreground.
4. The `tree` arm's split checks (tree.split-left.8, tree.10, tree.14) are
   red at opacity 1 exactly as T2625 records; unrelated to this change.
