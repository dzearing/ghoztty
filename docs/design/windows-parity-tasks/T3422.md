# T3422 - Linux viewer reads its document and serves every scheme request on the GTK main thread; move both off it (win32's T3224 shape)

## Summary

Viewer.zig (T3410) reads a markdown/code file with readUtf8 and answers each ghoztty-viewer:// / ghoztty-page:// request with a blocking readToEndAlloc, all on the GTK main thread. A large file (up to content.max_file_bytes) or a slow disk stalls the terminal beside it. win32 moved the document read to a worker in T3224; do the same here (GTask or a thread + glib.idleAdd for the read; webkit_uri_scheme_request_finish may be called after the handler returns, so serve requests asynchronously too). Validate with a test/linux probe that a multi-MB document renders while a +send-keys round trip to the terminal pane stays fast.
