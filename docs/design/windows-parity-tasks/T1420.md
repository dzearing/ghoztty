# T1420 - A relay machine's Activity panel shows its raw device id when opened from the window, its friendly name when opened from the carousel

## Summary

T1419 made both entry points name a machine by its identity, which is right for a direct host (host:port tells two agents apart) but leaves a relay machine titled by its raw device id when the panel is opened from the window's palette or pill. The carousel's card for a directory-listed relay machine carries the friendly name the directory knows, so switching to that card retitles the same panel. A window's RemoteMachine.relay record holds base/device/token and no name, so the window cannot supply one - the panel would have to adopt the directory's name once the machine list lands, and retitle itself. Mac titles the window from machine.name, so the friendly name is the target. Not covered by activity-monitor-remote.ps1, which is TCP-only.

## In plain terms

Opening the Activity panel for a machine reached through your account showed
an unreadable device id in its title, while picking the same machine's card in
the panel's carousel showed its friendly name - one machine, two names. Now the
panel uses the friendly name from either entry point, and a panel opened before
the name was known picks it up as soon as the machine list arrives.

## Goals

- [x] A relay window's panel opens titled by the friendly name the window knows (T1418's record)
- [x] The carousel's card for a relay window is labeled by that same name
- [x] A panel already open under the device id retitles itself when a listing names the machine
- [x] Direct-host panels keep their host:port identity (T1419 unchanged)

## Re-verification

Still real at claim: `Window.activityPanelSource` returned `.name = id` for
relay machines, though T1418 had since given `RemoteMachine.relay` a `name`
field - the window CAN now supply the name, which the Summary said it could not.

## Fix

- `Window.activityPanelSource`: relay -> `relayLabel(displayName(), id)` (name
  when it fits the panel buffer whole, else the id); tcp stays the id.
- `activity_machines.refreshWindowMachines`: a relay window's card is labeled
  the same way.
- `activity_machines.sourceRename`/`adoptSourceNames`: on any landed listing
  (`Window.adoptRelayNames` - the panel's own fetch and the chooser's alike),
  a panel whose machine the listing names adopts the name, retitles, and
  rebuilds its cards. Only the name moves; the registry key stays the id.
