# T1732 - Every MSI we ship has its shared strings under-counted, so any tool that edits one can silently blank another row

## In plain terms

The installer package is fine for installing. But its internal string table
keeps a count of how many places use each piece of text, and the tool that
builds it (wixl) counts too low. Any program that later edits the package -
our own test tooling included - can make a piece of text vanish from a row that
still needed it. So far that has only ever hurt tests, four times.

## Summary

wixl under-counts shared strings in the package's string pool. Windows Installer
only notices when something edits the database: a cell rewrite drops a count to
zero, the entry is freed, and every OTHER cell that shared it now reads empty or
as a different string. It has now arrived through four doors:

- T1209: `-ProductVersion` in `scripts\msi-test-identity.ps1` freed a shared entry.
- T1301: rewriting `Shortcut.Name` blanked `C_StartMenuShortcut`'s ComponentId.
- T1730: deleting rows to patch the prompt authoring - "Database string pool is
  corrupted" at CreateShortcuts. Worked around by pinning strings in a scratch
  table first.
- T1368 (this filing): `install-walkthrough.ps1 -TeethUnarmedRepair` updated the
  Condition of SetRepairMode/SetRepairModeFlags; that freed the condition string
  MaintenancePrompt still used, so the prompt ran unconditionally - inside `/qn`
  upgrades and uninstalls, hanging them. A second attempt that also wrote the
  prompt's condition back found `REINSTALL` itself reused. The control now edits
  only the integer `Sequence` column and reads the prompt's condition back.
  Separately, `msi-test-identity.ps1` refuses a source package that has already
  been through a COM `Commit()` ("did not converge" / "could not hold the
  identity cells").

Each caller has grown its own workaround. The fix belongs at the source: have
`build-msi.sh` (or a post-step) emit a pool whose refcounts match the cells, so
the shipped package is safe to edit and the per-tool workarounds can go.

## Validation criteria

- [ ] The package verifier in `build-msi.sh` counts every string's references
      across all tables and fails when a pool count is lower than the cell count.
- [ ] A shipped package, edited through the COM API (one row's Condition
      changed), keeps every other cell byte-for-byte.
- [ ] `msi-test-identity.ps1` rewrites a source package that has been through a
      COM `Commit()` cleanly.
