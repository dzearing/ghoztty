# T1201 - The website harness reads a stale local origin/gh-pages and reports it as mirror drift

## Summary

Section F of test\win32\website-windows-download.ps1 compares the in-repo mirror against 'git show origin/gh-pages:index.html' - the LOCAL remote-tracking ref. Right after a release publishes a new gh-pages commit, that ref is stale, and the harness reports 'FAIL F1 mirror != deployed gh-pages index.html (the mirror has drifted twice before; sync it)'. The mirror had not drifted; the local ref had. T1179's turn spent a diff and a line-ending hunt on it before running 'git fetch origin gh-pages' and getting ALL PASS. Fix: fetch the ref in the harness (network is already a precondition of section E), or, if the fetch fails, say 'origin/gh-pages is stale/unfetched' instead of accusing the mirror. A check that names the wrong culprit is worse than a skip.

## In plain terms

The website test compares the copy of the download page in the repo with the
one actually published. It read the published page from this machine's last
download of it, so right after a release it accused the repo copy of being
wrong when it was the local download that was out of date. Now it asks GitHub
whether its download is current first, and when it is not, it says so instead
of blaming the page.

## Goals

- [x] the F8 mirror verdict is never given against a local `origin/gh-pages` that is behind origin
- [x] a drift reported against a ref that cannot be confirmed current names the ref, not the mirror
- [x] the freshness probe itself is proven current/stale/unknown on a fixture

## Re-verification (2026-10-22)

Partly fixed already: T1088 (180eb1e5d) moved section F onto
`site-mirror.py`, so a stamps-only lag behind a stale ref now passes. What was
LEFT: F8 still ran `check --no-fetch` against whatever the local ref held, so a
page *edit* pushed to gh-pages (or one synced into the mirror ahead of the
clone's fetch) still read `MIRROR DRIFT` and failed on the mirror's account.

Fix: `Get-GhPagesFreshness` in the harness asks `git ls-remote origin
refs/heads/gh-pages` (read-only, `GIT_TERMINAL_PROMPT=0`) and compares it with
the local ref. Stale -> F8 SKIPs naming both shas and the fetch to run;
drift + unconfirmable ref -> SKIP naming the ref; current -> verdict as before.
Kept read-only rather than fetching, per the section's existing contract.
