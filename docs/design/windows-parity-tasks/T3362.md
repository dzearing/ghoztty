# T3362 - No capture checks the machine chooser's per-machine count capsule pixels; its geometry in chooser_rows.zig is guarded only by chooser-selection (T1759 follow-up)

## Summary

Left over from T1759. The machine chooser's per-row session-count capsule
(T1745) is verified on box only through its change-only log oracle
(`chooser row count key=... count=N|cleared`, in `chooser-help-tooltips.ps1`
section G for Local and `chooser-sessions-remote.ps1` C2/E2/E3 for a remote
machine) and its tooltip text. Nothing captures the row and checks that a
capsule is actually painted where `chooser_rows.countBadge` says, that it
vanishes on `cleared`, or that a zero count draws none.

The capsule geometry lives in `src/apprt/win32/chooser_rows.zig`, which is in
the `chooser-selection` guard row's Covers (pixel probes of the selection
pill), not in a capsule-aware harness.

Fix: a PrintWindow capture of the list on the test desktop (the chooser rows
are owner-drawn, so this is the only read-back), probing the capsule box at
the row's right edge for the count-text contrast against the row fill, with a
negative control on a never-loaded row.

## Validation criteria

- [ ] A loaded remote row shows a painted capsule in the box `countBadge` computes; a never-loaded row shows none.
- [ ] After `cleared`, the capsule is gone from the same probe.
- [ ] The harness that probes it covers `chooser_rows.zig` in its guard row.
