Found by T2642's turn, 2026-11-02 ~07:30-08:00, idle box (Get-UserPresence Present=False, idle 6,500 s+). `test\win32\divider-flicker.ps1 -Live -Panes 1 -Orientation vertical` on a Debug build of HEAD 575a88723 (worktree `D:\git\ghoztty-t2642base`, no T2642 change) fails La: `dark=249..260` of ~300 scored frames, in BOTH the viewer layout and T2414's `-NoViewer` scene. The T2642 build reads the same, so it is not T2642's change.

T2476's own live run at 03:14 today (Debug at 3cdf6d4b8 + T2476) read **dark 0 in all 6 cells**. Between that tree and 575a88723 sit 2d064eb24 (T2573, composition-tree hero slide), 367101943 (T2476 itself, adds the GHOZTTY_OVERLAYS_AFTER_BANDS knob) and 39ddff25c (T2500, window-close handle leak). Note too that the near terminal's whole body photographs black (#000) in these runs, pressed frame included, while its configured background is #2a3a50: check first whether the terminal is rendering at all, since a pane that never presents would read as a constant dark block plus a strip wherever it grows. Bisect with the harness (each cell ~1 min, `-Exe` takes any build).

Frames: `temp\divider-flicker\20261102-07*` (fixed and base runs, `frames\f*-fail.png`).

## In plain terms

While you drag the line between two panes, a thin black stripe one drag-step wide shows beside the line on almost every frame. It was gone this morning and is back now.

## Finding (2026-11-02, lane b)

**No commit brought it back: every red run was taken on an occluded display.** Each cell's `app-stderr.log` under `D:\git\ghoztty\temp\divider-flicker\` was read: all 22 red-era runs (07:25-09:33, builds 575a88723 and f2213441d) log `warning(frame_clock): compositor clock wait failed (c01e0006); falling back to a timer`, and none of the 23 green-era runs (02:53-03:42, a22f3f258) do. 0xC01E0006 is STATUS_GRAPHICS_PRESENT_OCCLUDED (`ntstatus.h`): DWM reports the output occluded - monitor asleep after 6,500 s idle, session locked, or a screen saver. A terminal whose presents are occluded never shows a frame, which is exactly the "near terminal photographs #000, pressed frame included" note above, and a black strip one drag step wide is that unpainted terminal growing. The src diff a22f3f258..575a88723 was read too: T2573 (hero slide only, behind the composition-tree flag), T2476 (an env knob, default off), T2500 (handle closes) and T2490 (Mac-only config keys, a win32 no-op action) - none touches terminal presentation.

Fix landed here: the harness no longer scores such a run. `Get-DividerFlickerOccluded` (`test\win32\lib\DividerFlickerScore.ps1`) finds the app's own occluded line, and a live cell carrying it is SKIPPED by name (so it never stamps either); section E of the synthetic run proves the detector, including on a log the app still holds open, and pins the FrameClock.zig format string it matches. Replayed against the 45 real logs it splits them exactly as above.

Filed: T2649 (FrameClock never returns to the compositor clock after one OCCLUDED - product, P2), T2650 (share the gate with every live WGC harness; re-read T2620/T2631, which report the same all-black signature - P1).
