# T788 - NeuterAudit: enforce that every *_NEUTERED flag has a live consumer and a shipped-value pin

## In plain terms

Some of our tests are only trustworthy because a switch in the source can turn
the fix off and make them go red. Twice now a switch has quietly stopped doing
that — it was still there, still documented, but nothing in the drawing code
was listening to it, so the test that "proved itself" proved nothing. This adds
an automatic check so the next one is caught the day it happens instead of
months later.

## Summary

T209 found two `*_NEUTERED` flags that claimed more than they covered. T283
swept all eight and found two more problems of the same shape:

- `icon_button.universalHover()` was exported, documented and unit-tested with
  **no consumer on any paint path** — T282 moved its call sites onto
  `lightsFill(glyph)` and left the predicate behind, kept alive only by the
  test that pinned it. Deleted in T283.
- Five of the eight flags (`T202`, `T249`, `T123`, `T377`, `T149`) had **no
  shipped-value pin**, so a flag left `true` by an experiment would have
  shipped and gone red only in an acceptance script somebody remembered to run.
  T283 added pins by hand.

Both are properties, not facts, and the repo already knows how to hold a
property: `ExitCodeAudit`, `SkipAudit`, `VerdictExitAudit`,
`AssertedNothingAudit`, `ForegroundAudit`. This is the sixth of that family.

## What to do

An analyzer that enumerates every `*_NEUTERED` declaration under `src/` and
enforces, at zero:

- **`no-consumer`** — the flag (or a predicate that reads it) is referenced
  only inside `test` blocks and its own declaration. The reference graph is
  one hop: flag → predicate → call site, which is what
  `glyphCentered`/`universalHover` needed and a plain grep for the flag name
  cannot answer.
- **`unpinned`** — no `testing.expect(!<FLAG>)` (or equivalent) anywhere in the
  module, so nothing fails when a neutered build is committed.
- **`no-claim`** — the declaration carries no doc comment naming the script it
  guards. The claim list IS the control's contract (T283 finding 3), so a flag
  with no claim cannot be audited at all.

Same conventions as its siblings: a stated-intent `// neuter-audit: <reason>`
exemption marker, and a `-TeethCheck` that plants a real violator of each kind
in the swept tree and requires the sweep to find it.

Consider also whether the "measured split" belongs in the analyzer's reach —
T283 had to read five task files to learn when each flag was last measured. A
`/// measured YYYY-MM-DD: N FAILED / M passed` line in the doc comment, checked
for presence and age against the guarded script's mtime, would make a stale
claim visible without a human remembering to look.
