# T2204 - desktop-launch audit misses camelCase exe variables like $testExe, so update-real-msi opened windows on the user's screen unflagged

## Summary

`Test-DesktopLaunchAuditGhozttyRef` (`test\win32\lib\DesktopLaunchAudit.ps1`)
decides whether a variable names the ghoztty exe with
`(?i)(^|[^a-z])exe(path|)$`. Under `(?i)` the character before `exe` must be a
non-letter, so in practice only a bare `$Exe` / `$exePath` / `$script:exe` /
`$my_exe` matches; `$testExe` and `$AppExe` do not (the comment beside the
rule claims `$AppExe` is covered). `test\win32\update-real-msi.ps1` launched the installed
throwaway product three times as `Start-Process -FilePath $testExe` on the
caller's desktop - every run put a terminal window on the user's screen - and
the audit was green with no `@user-desktop-launch` declaration. Found and fixed
for that one script in T1269 (it now launches through `Start-OnTestDesktop`).

Fix the rule rather than the names: treat a camelCase `...Exe` / `...ExePath`
suffix (case-sensitive capital E after a lowercase letter, plus the existing
bare forms) as an exe reference, then re-run the sweep and declare or migrate
whatever it newly finds. Expect hits on `$agentExe` sites (headless - the agent
opens no window, so the rule may need to exclude names that resolve to
`ghoztty-agent.exe`, or those sites get declared) and on non-ghoztty helpers
like `$sleepExe` / `$leakExe` (cmd/timeout - the audit must not call those app
launches; check how the site classifier scores them before widening).

## In plain terms

A check exists to stop tests from opening windows on the user's screen, but it
only recognises a few spellings of "the app's path". One test spelled it
differently and opened windows on every run without the check noticing.

## Validation criteria

- [ ] A negative control: a fixture script that launches `Start-Process -FilePath $testExe` is reported `undeclared` by the audit
- [ ] The widened rule produces no false findings on headless/non-ghoztty launches (agent, cmd, timeout), or each is declared with a reason
- [ ] The desktop-launch sweep is at zero findings after the change
