# T1743 - Mac +new-window/+split must answer only once the new pane's session_id is readable (T1612 contract)

## In plain terms

On Windows, a script that opens a window or a split can ask straight away
which persistent session the new pane belongs to and get the answer. The Mac
should behave the same way, so scripts written against one platform work on
the other.

## Summary

T1612 settled the contract on win32: `+new-window` and `+split` hold their
reply until each new pane's agent OPEN has settled (bound or failed), bounded
at 3 s, so one `+list --json` straight after the verb carries `session_id`.
Documented in `docs/claude/cli.md` beside `session_id`.

The Mac server does not report `session_id` yet (T553). Once it does, its
`handleNewWindow` / `handleSplit` must hold the same contract, or the CLI
surface diverges: a Mac script would read no id on the first query where a
Windows one reads it. Translate the mechanism, not the code: hold the IPC
reply (off the main thread) until the new surface's session is bound, with the
same bound and the same early exit on a failed OPEN.

## Validation criteria

- [ ] On macOS, `+new-window` followed by ONE `+list --json` (no poll) reports
      the new pane's `session_id`, over a cold start (app and agent not running).
- [ ] Same for `+split`.
- [ ] A failed OPEN / unreachable agent does not hold the verb past the bound.
