# T1113 - context-menu-real-input.ps1 cannot take the foreground and never runs a single assertion

## In plain terms

One of the checks could not get the app's window to the front, so it gave up before testing anything. It counts as a failure, but the more important part is that nobody is checking that behaviour at all right now.

## Summary

`test\win32\context-menu-real-input.ps1` failed at setup in the T1094 sweep, in 5.8 seconds:

```
SETUP FAIL (plain): could not take the foreground (a fullscreen app or an input lock owns it)
```

No assertion ran. The script's whole subject - the context menu under REAL input rather than synthesised messages - is currently unmeasured, and has been for as long as this has been failing.

The message names its own two suspects. On this box both are live possibilities: the suite now runs scripts on a background test desktop where the notion of 'the foreground' is different, and there is prior history of a system service holding a foreground lock that no amount of correct code can beat.

Attribute before fixing - see [[T1100]].
