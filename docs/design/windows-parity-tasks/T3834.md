# T3834 - A strip click's glide waits 14-20 ms for its first frame-clock tick behind the click pass's follow-on work, so on the shipping path it first moves 30-44 ms after the click: get the first tick in within one refresh

## Summary

Measured by T2480 (scripts\comp-glide-hold-onscreen.ps1 -Arms on -Clicks 8 -SlideMs 400, 120 Hz, 2026-11-26): on the shipping composition-present path a strip click's glide first moves on screen 30 ms p50 / 38-44 ms p95 after the button-up (3.6 / 4.6-5.3 refreshes). The glide is armed 1-3 ms after the click, but its first frame-clock tick lands 14-20 ms after arming: the click pass's follow-on work (deferred focus, paints, strip-face pictures, pane snapshot readbacks) runs ahead of the posted WM_APP_FRAME. Profile what runs between 'stack glide armed' and 'stack glide first tick' (GHOZTTY_STACK_TRACE's between-tick breakdown) and get the first tick in within one refresh of the arm - run it from the click pass itself, or move the follow-on work behind it. Oracle: that command's START LATENCY line, p95 <= 2 refreshes (16.7 ms).
