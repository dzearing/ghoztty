# T1981 - Two loop lanes never get the same task or the same new task id: a claim ledger shared by every worktree on the box

## In plain terms

The user wants two task loops running at once. Each loop works in its own copy
of the repo, so neither can see that the other has already picked up a task or
used a task number. This adds one shared notebook on the machine, which both
loops check before taking a task or a number. Once it lands, two loops can never
work the same task or file two tasks under the same number.

## Goals

- [x] Shared ledger outside every worktree, written under a named mutex
- [x] `next -Claim` skips (and never resumes) a task another live lane holds
- [x] `new` allocates ids past the ledger's high-water mark
- [x] Claims expire after a TTL, and a restarted lane reclaims its own task
- [x] Race tests with negative controls

## Summary

Split from T1937 items 1 and 7. A ledger outside the worktrees (%LOCALAPPDATA%\ghoztty\loop-ledger.json, under a named mutex) records which lane holds which task and the highest id handed out. next -Claim skips (and never RESUMEs) a task another live lane holds; new allocates past the ledger high-water mark. Claims expire with the holder's heartbeat. Scripted race test with a negative control.

## Validation criteria

- [x] Two `next -Claim` processes released together from identical copies of the
      queue, one per lane, claim DIFFERENT tasks every iteration
      (test/win32/parity-tasks-lanes.ps1 section A). Negative control B: with
      the ledger off, the same race collides.
- [x] Two simultaneous `new` calls, one per lane, get different ids (section C).
      Negative control C4: with the ledger off, they collide.
- [x] An in-progress task held by another live lane is not resumed; once the
      claim is past the TTL it is (section D, plus the TTL env override D11).
- [x] `set-status done` releases the claim. A corrupt ledger is backed up and
      replaced with a warning. A held lock fails after a bounded wait and
      names the mutex. Fixture (`-TaskDir`) runs never write the real ledger
      (section E). Lanes harness: ALL PASS (33 assertions).
- [x] Existing harnesses still green: parity-tasks-seat (209),
      parity-tasks-split-deps, gate-negatives (58; the new HELD BY OTHER LANE /
