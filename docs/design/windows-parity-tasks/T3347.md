# T3347 - Confirm on a real 8-worker -LoadKind build soak that T1718's -j cap keeps the workers compiling (no worker-fail, no load-degraded) instead of failing inside a minute

## Summary

T1718 capped each build worker at -j(processors/(workers+1)) and made failed worker builds report as worker-fail/load-degraded; fixtures prove the reporting, only a real loaded soak proves the cap is enough on this 32-core/64 GB box. Run: test-binary-soak.ps1 -Lane agent -Runs 1 -LoadWorkers 8 -LoadKind build -NoCatch -Label t1718-cap (background task, stdout to a file). Pass = summary carries worker-fail=0 and no load-degraded, and the worker logs hold no OutOfMemory / LLVM out of memory. If still degraded, lower the default divisor or add a memory-based cap.
