# T3357 - acceptance scripts run from a Ghoztty cmd pane hand the loop's integration PROMPT (OSC 7 included) to their loopback agent, so their 'shell reports no OSC 7' fixtures are not

## Summary

Found by T1741. This loop's own shell carries PROMPT=$E]133;A$E\$E]7;kitty-shell-cwd://localhost/$P$E\$P$G$E]133;I$E\ (the T512 cmd integration), and every acceptance script inherits it. A loopback ghoztty-agent started from such a script hands it to every cmd.exe it spawns, so the 'other machine' reports its own directory by OSC 7. remote-cwd-follow.ps1 measured it: with the inherited PROMPT, a cd reached +list in under a second through OSC 7 and the agent's META{cwd} push was never exercised; with PROMPT cleared it took 6-10 s, through the push. remote-cwd-follow.ps1 and remote-reconnect-fresh.ps1 now clear it. Others that assume a bare cmd.exe (remote-inherit.ps1 says 'cmd.exe has no OSC 7, so there is no local cwd-inherit path to confuse the result') still inherit it. Fix in one place: drop PROMPT in lib\CleanSlate.ps1 the way it already drops GHOZTTY_IPC_SOCKET, after auditing which scripts rely on it, and add an audit row so a new fixture cannot regress.
