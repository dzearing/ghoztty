## Summary

session-relaunch-notify.ps1 H14 sends 'exit' + Enter to the respawned shell of a pane whose holder was killed (section H, T1793) and waits 25s for the pane to leave +list. Until T1656 the check was vacuous: All-Leaves returns with the comma idiom and was piped bare into ForEach-Object { [string]$_.id }, so $ids was ONE space-joined string, never -contains the pane id, and H14 passed the instant two panes existed. With the call parenthesised (T1656) the per-id list is real and H14 is red on 2 of 2 runs (2026-11-21, lane b): the pane is still listed after 25s. First decide whether this is the product (an exit from a host-lost respawned shell is not treated as a pane exit, e.g. the respawn path never re-arms the close-on-exit wiring) or the test (keys sent before the fresh prompt is reading, or the respawned shell is a different flavor that needs a different exit). Read the pane after the send to tell which. Guard session-relaunch is acked to this task.
