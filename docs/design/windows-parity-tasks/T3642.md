# T3642 - A macOS ReleaseSafe dev build is not isolated from the user's installed Ghoztty: it builds as Xcode ReleaseLocal with the release bundle id, so its app and agent use the user's agent dir, LaunchAgent label and guard

## Summary

Found by T2051. GhosttyXcodebuild.zig maps ReleaseSafe/ReleaseSmall/ReleaseFast all to the Xcode ReleaseLocal config, whose PRODUCT_BUNDLE_IDENTIFIER is com.dzearing.ghoztty (the release id; only Debug carries .debug). LocalAgentManager.Paths picks local-agent vs local-agent-debug and the LaunchAgent label by that bundle id, so a 'zig build -Doptimize=ReleaseSafe' app on Mac reads and writes the user's ~/.config/ghoztty/local-agent and LaunchAgent, while build_config.is_debug calls the same build debug. T2051 deliberately kept the Mac agent's baked is_debug Debug-only (agentIsDebug in src/build/GhosttyAgent.zig) so the guard stays with the directory the Swift app hands it. Fix on the Mac seat: give ReleaseSafe its own isolated lineage (e.g. a .debug-suffixed bundle id for a ReleaseSafe ReleaseLocal build, or key Paths on the zig build mode), then flip agentIsDebug's macOS ReleaseSafe arm to true and the restating test in src/remote/agent/main.zig with it.
