# T3334 - Linux L5: move the IPC verb handlers into shared code so the GTK frontend serves the same handlers as win32

## Summary

src/apprt/win32/IpcHandlers.zig is 2793 lines with only 7 w32 calls; the shared helpers already live in src/apprt/ipc/. Extract the frontend-independent logic behind a small interface (find surface/window, split, close, read, send keys, set banner/state) that win32 and GTK each implement. This changes the Windows side, so validate it on Windows too: ipc-p1/p2/p3 ALL PASS before and after, unchanged.

## In plain terms

Ghoztty's command line talks to the running app over a local socket, and the
code that answers it only existed inside the Windows app. The Linux app needs
to answer the very same commands the very same way. This moves the part of
that answering code that has nothing to do with Windows into a shared place,
so the Linux app plugs into it and cannot quietly leave a command out: if it
does not answer one, it does not build. Nothing changes for a Windows user.

Scope as landed: the shared layer is the request format, which words map to
which command, the reply wording, and the router. The bodies of each command
still talk to Windows windows directly; moving those behind a shared model is
T3361.
