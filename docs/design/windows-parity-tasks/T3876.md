# T3876 - The agent's freeUnlinked walks the session table with no lock held, so a concurrent add or remove can make it read a freed session

## Summary

The agent's SessionTable.freeUnlinked (src/remote/agent/session.zig:1504-1511, from 749cc744df, T3646) logs heap_stats with self.liveCount() and self.deadCount() with no session lock held. liveCount (:1288-1295) iterates by_id and dereferences every session pointer (sp.*.alive), so a concurrent insert that rehashes the map, or a concurrent remove that frees a session, makes it read freed memory in the shipped agent, which owns the user's live sessions. The arguments are evaluated in every build mode. Found by audit-5's area-I auditor (T3316), read at HEAD. Fix: take the counts under the lock (or keep atomic counters) and log after release.
