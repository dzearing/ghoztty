# T2622 - Window presenter path: a pane the presenter is not composing (hidden tab, folded stack) waits 2x20ms per frame for a take that never comes, drops the frame, and shows its stale pending frame when shown again

## Summary

OpenGL.presAcquire: a pane absent from WindowPresenter.sync's rects is never taken, so acquire() stays null. Fix shape: the presenter tells a link it is not composed (or takes and discards its pending frame), and the pane redraws on show. Off by default until T2610 step 5.

## In plain terms

With the (still opt-in) single-surface window presenter, a terminal that is
not on screen - a background tab, a folded stack, a pane past the presenter's
limit - used to stall for about 40 ms on every frame it drew, waiting for a
hand-off that never came, and then threw the frame away. When the pane came
back it could show the picture from before it was hidden. Now such a pane
draws its new frame straight over the one nobody took, never waits, and
whatever it shows when it comes back is the newest thing it drew.

## Goals

- [x] a pane the presenter is not composing never waits for a take
- [x] its newest frame, not a pre-hide one, is what the presenter takes when it composes the pane again
- [x] it asks for no compose (no window swap for a frame nobody takes)

## Validation criteria

- [x] `SlotPair.reclaim` gives the renderer back only the untaken pending slot, never the held one, and the next take is the newest frame - unit tests "SlotPair: reclaim ..." and "SlotPair: a frame taken before the reclaim ..." in `src/renderer/gl_window_presenter.zig` (none lane).
- [x] On the box, a pane left out of the compose (debug hook `GHOZTTY_PRESENTER_UNCOMPOSED=last`) redraws in place frame after frame with zero dropped frames - `test\win32\window-presenter.ps1` H2-H5 (reclaims=16, 0 drop lines), 54/54.
- [x] Negative control: composed panes never take that path - same harness, F11 (0 reclaim lines).

## Fix

- `gl_window_presenter.SlotPair.reclaim`: the renderer takes back its own
  pending slot when nothing will take it. Safe without the presenter: it only
  reads the held slot, and a pending slot is never the held one.
- `WindowPresenter.PaneLink.composed`: every `sync` marks each link in or out
  of the compose, before it requests the compose.
- `OpenGL.presAcquire`: an uncomposed link reclaims instead of waiting 2x20 ms;
  `presPublish` skips the compose request for it. Reclaims and drops are
  counted and logged at powers of two (`pane renderer ... reclaims= drops=`).
