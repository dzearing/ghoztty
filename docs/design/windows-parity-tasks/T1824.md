# T1824 - win32 test lane intermittently exits non-zero with no failing test named and no runner summary

## Summary

Seen during T1820 (2026-10-11 01:14): `scripts\floor-lane.ps1 -Lane all` scored
win32#1=FAIL in 278s with `alone: unknown: no test named in the log`. The lane
log (`%TEMP%\floor-lane-win32-20261011-011440-716.log`, 350 lines) ends
mid-stream on an ordinary `Invalid timestamp in cache entry` warning with no
test-runner summary, i.e. the test binary or the build runner died without
reporting a failing test. The same tree passed the lane alone 10 minutes later
(183s). The lane ran right after the none lane and before agent, inside
`-Lane all`, with nothing else running on the box. Find what ended the process
(crash-catch.ps1 over a looped run, or the runner's exit code) and either fix
it or make floor-lane name the death (exit code / NTSTATUS) instead of
"unknown".

## In plain terms

Sometimes the automated test run fails without saying which test broke, and
the report could only shrug ("unknown"). Now it says how the test process
actually ended - an ordinary failure, a crash, a Ctrl+C-style kill, or the
machine running out of memory - so the next person knows where to look
instead of re-running and hoping.

## Goals

- [x] the floor names the lane process's full exit status when a red lane names no test
- [x] the same wording reaches the FLOOR FAILURE DETAIL block and the summary's `[alone: ...]` token
- [x] the original death is not chased further on purpose: it has not recurred in 42 days, and the next occurrence now names its own status, which is the evidence a new task would need
