# T3786 - Linux L11k3b: single-window mode on GTK - a terminal made while its workspace is parked (+new-window without --focus, +split into a parked workspace) starts its shell at once, not on first show

## Summary

GTK starts the core surface on the GL area's first resize, which only a drawn (mapped) widget emits, and a parked workspace's content is out of every window; so a born-parked pane has no shell, +send-keys does nothing and its grid is 0x0 until shown (T3648/T3650 progress logs). Mac starts the terminal while parked (aWorkspaceParkedFromBirthStaysQuiet: it runs, it just does not draw). Needs a GL context for the renderer's init without mapping: e.g. park content inside the toplevel as a child-invisible widget and realize its GL areas, then init from the T3650 allocation. T3653 (the CLI) depends on it.
