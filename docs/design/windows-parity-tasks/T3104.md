# T3104 - Stashed panes and panes behind a zoomed pane keep rendering every frame on Windows: tell them they are hidden, and never draw a hidden surface from any thread (Mac e15077861, 6bd6fe7fb)

## Summary

Mac e15077861: a terminal is visible only if its window is on show, it is not stashed, and nothing is zoomed over it - re-evaluated on occlusion changes and every tree change (covers a pane created while its window is covered). 6bd6fe7fb (shared renderer): a hidden surface draws nothing even when a non-render-thread caller asks. On Windows: verify what +stash and split zoom do to the hidden panes (setVisible/occlusion signal into the renderer), wire them as hidden, and audit any WM_PAINT/resize path that draws a hidden surface directly and would re-take released targets. Validation: zoom a pane over busy siblings and stash a busy pane - the hidden ones stop presenting (frame counter flat) and release targets; unzoom/restore shows current content with no blank frame.
