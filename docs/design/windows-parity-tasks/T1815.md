# T1815 - A crashed lane's cdb re-run still launches the test binary on the user's desktop: CrashCatch.ps1 starts cdb with Start-Process from floor-lane (input desktop), so its test windows can reach the screen

## Summary

T1813 moved every floor lane and soak round onto the background desktop GhozttyLaneDesktop (scripts/lib/LaneDesktop.ps1). One launch path was left: when a lane's test binary crashes, floor-lane's Invoke-LaneCrashCatch -> scripts/lib/CrashCatch.ps1 re-runs that binary under cdb with `Start-Process ... -RedirectStandardOutput -NoNewWindow`, from floor-lane's own process, which is on the INPUT desktop. The re-run executes the same tests, so a crashed win32 lane can still show its banner windows on the user's screen. Fix: launch cdb through Start-LaneProcess (cmd /c with > and 2> redirection, as soak-daemon does), keeping the timeout/kill semantics. Validate with the crash-databreak / floor-lane-compiler-crash style harness driving a planted crash and asserting the cdb child's desktop is GhozttyLaneDesktop.

## Validation criteria

- [ ] A planted crashing lane's cdb re-run (and the test binary under it) runs on GhozttyLaneDesktop, measured from inside the child.
- [ ] crash-first-chance / crash-databreak harnesses stay green.
