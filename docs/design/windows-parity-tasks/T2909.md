# T2909 - Background windows go quiet on Windows too: busy border and sidebar sheen animate only in the active on-screen window, hidden panes skip frame building, hidden titles held, polling/GIF paused (port of Mac 68a8344f0)

## Summary

Port of Mac 68a8344f0 (perf(macos): stop background windows doing work nobody can see; 16 background windows ~21% -> ~4.7% CPU on Mac). The shared-core half arrives with the merge: src/renderer/Thread.zig now skips updateFrame while flags.visible is false and rebuilds once on show (frame_stale) - so on Windows the win32 apprt must report a covered/minimized/fully-occluded window as not visible, or the core saving never fires. The win32 half to build: (1) a WindowCoverage equivalent deciding hidden from the window list (minimized, cloaked on another virtual desktop, fully covered by other top-level windows - Mac found occlusionState lies for a window exactly behind another of its frame), feeding surface visibility; (2) busy border + sidebar busy sheen animate only in the foreground on-screen window; (3) window title changes held while hidden (<=5s) but +list reads the held title immediately; (4) a terminal added to a hidden window starts hidden; (5) git-status polling for diff viewers and GIF playback pause while hidden and catch up on show. Reference: docs/reference/background-windows.md and macos/Sources/Helpers/WindowInUse.swift after the merge. Measure CPU with N background windows before/after.
