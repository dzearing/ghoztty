# T3187 - Single-window mode: a relaunch brings every window back as a workspace with the one that was in front on show, and a manifest from either mode restores in the other

## Summary

Session restore in single mode: each manifest window entry becomes a workspace at the shared frame, the frontmost entry restored last so it is on show (T3137 adds the field); tab-group siblings become workspaces of their own; a single-mode manifest read in separate mode is windows at one frame, frontmost on top. Agent wire contract unchanged. Child of T3136 (split 2026-11-16). Design (T3136 Details): ONE shared top-level HWND; every workspace keeps its own Window controller; the workspace on show owns the HWND (GWLP_USERDATA, chrome, sidebar), a parked Window has hwnd=null and its pane child HWNDs are reparented (adoptPane-style SetParent, Window.zig:7278) under a hidden park host so they survive the shared HWND closing. Spec: docs/reference/window-modes.md. Acceptance goes in test/win32/single-window-mode.ps1 (one section per child).

## In plain terms

With "All in one window" on, quitting and reopening Ghoztty has to bring back
every workspace inside the one window, with the one you were looking at still
on screen - and a saved session has to come back sensibly if you switch the
setting between launches. Before this, the workspaces you were not looking at
were saved without a window size, and the one marked "in front" could be a
workspace you had switched away from.

## Goals

- [x] the manifest records every parked workspace at the shared window's frame
- [x] the workspace on show is the one marked frontmost, however it got there
- [x] a single-mode relaunch rebuilds every entry as a workspace of one window, the frontmost on show, the rest parked
- [x] a saved window's tabs come back as workspaces of their own
- [x] the same manifest read in separate mode is windows at one frame, the frontmost on top

## Decisions made here (mechanism, not filed)

- **Tabs become workspaces** (revised after T3182 landed mid-turn: a
  single-mode workspace has no tabs and no strip). A saved window with
  several tabs - a separate-mode window, or a Mac tab group that
  `mac_layout_blob` folds into one window's tabs - comes back as a workspace
  per tab (`session_layout.tabAsWindow`, `App.restoreWindowShown`): the
  active tab first, keeping the window's layout key, name, title pin,
  gradient, focus stamp and front mark, then each other tab as a fresh
  workspace parked behind it. A cross-machine window (one dialed connection)
  is still built whole. The first version of this commit kept tabs as tabs,
  which T3182 would have left unreachable.
- **Launch restore builds front first and parks the rest** (`restore_pacing.order`
  already sorts the frontmost first); in single mode every window after the
  first is built `background`, so it parks behind the one on show instead of
  switching to itself - paced or not, launch pass or deferred pass
  (`App.restoreParksBehindShown`). Restore All keeps its frontmost-last order,
  which ends on the right workspace through a hand-off per window.

- [x] a single-mode relaunch: 3 workspaces, `swm-h2` on show, 1 HWND, 2 parked, one window at the saved frame - I2
- [x] the same manifest in separate mode: 3 windows at one frame, `swm-h2` on top - I3 (top window reads `SWM-H2-FRONT`)
- [x] unit: `markFrontmostOnShow` (on-show beats stamps; null / out-of-range fall back) and `tabAsWindow` (identity stays with the active tab) - `session_layout.zig`
- [x] a window saved with two tabs in separate mode comes back in single mode as two workspaces, one tab each, its active tab on show with the window's name - I4 (4 workspaces, all `tabs=1`, active `swm-h2`)
- [x] floor lanes (lib, none, win32, agent)
