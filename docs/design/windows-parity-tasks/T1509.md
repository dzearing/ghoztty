# T1509 - A CLI verb that meets a half-open IPC pipe prints a nonsense number instead of what went wrong

## Summary

`IPC response has invalid length: 1768842863` is the four bytes `invo` read as a
u32 - the client decoded a plain-text reply as a length prefix and said so in the
one vocabulary nobody can act on

## In plain terms

When the app answers a command with something the CLI was not expecting, the CLI
prints a ten-digit number. There is nothing a person can do with that: it does
not say what went wrong, whether to retry, or that the app is still starting up.

## Goals

- [ ] A reply the client cannot frame reports what it actually received (the
      leading bytes as text when they are printable, the byte count otherwise)
      and what state that suggests
- [ ] The message says whether retrying is reasonable, the way the T755 timeout
      message does

## Details

Observed twice on 2026-09-12, both times against a cold-started app:

```
ghoztty +new-window --target=p1win ...
exit: 1 after 365ms
stderr: IPC response has invalid length: 1768842863
```

`1768842863` is `0x696E766F`, i.e. the ASCII `invo` - the first four bytes of an
un-framed message beginning "inv…" (an earlier occurrence decoded to `data`). So
the client read a payload where a length prefix was due. Whether that is the app
writing an unframed reply, or a reply landing in a pipe the client had already
begun reading, is the first thing to establish.

Either way the MESSAGE is wrong independently of the cause: the number is a
decoded fragment of the very text that would have explained it. T755 set the
house standard here for the timeout case - name what was waited on, and name the
way out - and this path never got the same treatment.

Both sightings were on a cold auto-launch, which is the same window
`ipc_timeout.auto_launch_ms` exists for; a re-run passed immediately. So this is
also a flake source for `ipc-p1.ps1` section 1.

## Validation criteria

- [ ] A unit test over the framing error path asserts the message quotes the
      received bytes rather than their integer value
- [ ] `test\win32\ipc-p1.ps1` ALL PASS
- [ ] The `none` lane green
