# T2916 - A background probe dial against a wedged local agent holds its only pipe instance, so in-place recovery waits 10s for the pipe - and the agent's heartbeat is ~20s stale after a suspend

## Summary

Found while validating T1473 (agent-recovery.ps1 section I). Two facts measured on the box: (1) when a worker-thread probe dial (orphan check, session roster: LocalAgent.dialProbe) reaches a SUSPENDED agent first, it takes the pipe's only instance and the GUI-thread recovery re-dial then spends the full 10s PIPE_BUSY budget (pipe_stream default_busy_budget_ms) before ConnectionRefused - 10s of blocked GUI thread. (2) the agent's heartbeat file was 17-22s old at the start of section I although the interval is 10s: after the H-section suspend/resume the heartbeat thread does not appear to beat promptly. Together they push a merely-wedged agent past the 45s takeover age, so a challenger replaces it. The harness now starts I on a fresh beat (T1473); this task is the product side: bound or skip the PIPE_BUSY wait on recovery's dial when a probe is in flight, and make the heartbeat write promptly after a resume.
