# T1088 - The site mirror goes stale on every release and only a red test notices

## Summary

relay/deploy/ghpages/index.html is a mirror of the deployed gh-pages page, but a release updates gh-pages and nothing syncs back, so the mirror drifts and section F of test/win32/website-windows-download.ps1 goes red. Found three releases behind (v1.31.0 vs v1.34.0) during T353 and hand-synced. Third recurrence. Make the sync mechanical: either the release workflow commits the rewritten page back to the branch it was built from, or a script/step syncs the mirror and a harness run reports the drift as an action rather than a failure to hand-fix.

## In plain terms

The website's download page has a copy in the repo, and every release changes the live page's version numbers without updating the copy. A test then went red over a difference nobody needed to fix, and someone had to copy the page back by hand. Now a small tool tells "only the version numbers moved" (normal, refreshed with one command) apart from "the page text itself differs" (a real problem), and only the second fails the test.

## Goals

- [x] a tool that classifies mirror vs live as ok / version stamps only / content drift
- [x] a one-command, refusal-guarded sync for the release runbook
- [x] the website test passes on stamp lag and still fails on content drift
- [x] the real mirror re-synced
