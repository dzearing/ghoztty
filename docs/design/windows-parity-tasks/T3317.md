# T3317 - Activity Monitor's Ghoztty-only view can adopt an unrelated process whose parent pid Windows recycled to the app or one of its children

## Summary

markSpawned (src/apprt/win32/activity_rows.zig) walks the tree by ppid alone. On Windows a dead parent's pid is reissued quickly, so an orphan whose dead parent's pid now belongs to the app (or to anything in its tree) is counted as ours and shown with Show all off. The usual guard is to reject a child created before its claimed parent, but remote_protocol.Proc carries no start time, so it needs an additive wire field (agent HELLO capability) plus the sampler change. Not observed in practice: found while investigating T1615, which no longer reproduces. T1615's Write-TestStrayPingReport labels this case RECYCLED(parent younger) if it is ever seen.
