# T3588 - Linux: +split --focus and a --focus on an existing target say in the reply when the compositor may decline, like +new-window --focus

## Summary

T3381 made +new-window --focus on GTK carry the note '--focus: Ghoztty is not the active app, so the compositor may keep the window behind ...' when no window of the app is active, but +split --focus and the idempotent --focus of an existing --target/--name go through the shared verb bodies in src/apprt/ipc/verbs.zig (split, alreadyThere), which have no hook for a frontend note, so on Linux they only log the outcome. Add an optional F.focusNote hook (@hasDecl, so win32 is untouched) and append it to those replies; extend W21b of test/linux/cli-windows.sh.
