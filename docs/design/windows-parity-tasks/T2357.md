# T2357 - The Windows sidebar draws the Mac's icon set

## Summary

User report 2026-10-27: "Whats going on with the icons, they don't match the
mac icons."

Root cause (audit 2026-10-27): the Mac pane sidebar does NOT use SF Symbols
for its main icons. `macos/Sources/Features/PaneSidebar/PaneSidebarSymbol.swift`
(lines 3-8 say why: the mock's lighter, rounder strokes, SF Symbols rejected)
draws its own 16-unit paths with round caps at 1.25-1.4 stroke:
`.sidebar(expanded:)` (46-49, 88-90), `.windows(filled:)` (34-45, 85-87),
`.plus` (50-52), `.terminal` (53-58), `.document` (59-67), `.globe` (68-72),
`.diff` (73-77). Windows draws every sidebar icon from Segoe Fluent Icons
(`src/apprt/win32/PaneSidebar.zig:198-218`), per win32-design-system.md §4
"Glyphs" (system icon font first). Two icon families, so even the "equivalent"
icons do not look alike.

Specific mismatches on top of that:

- diff pane -> Windows `else => glyph_code` (`PaneSidebar.zig:1513`); Mac
  `.diff` (`PaneSidebarRow.swift:416`)
- code / html panes -> Windows `</>` 0xE943; Mac `.document`
  (`PaneSidebarRow.swift:415`)
- all-windows toggle -> Windows TaskView 0xE7C4 + checked fill
  (`PaneSidebar.zig:3695-3713`, stale `macwindow.on.rectangle` comment); Mac
  two stacked windows, front one filled when on
- collapse/expand -> Windows OpenPane/ClosePane 0xE8A0/0xE89F
  (`PaneSidebar.zig:3376`); Mac ONE shape, sidebar filled when expanded
- search clear -> Windows bare Cancel x (`PaneSidebar.zig:3670`); Mac
  `xmark.circle.fill` (`PaneSidebarView.swift:764`)

## Decision (recorded, per the 2026-10-25 directive "features and visuals
should port as well as they can")

Where the Mac draws its own icon, Windows draws the SAME path (antialiased:
D2D or GDI+, scaled from the 16-unit box, round caps, the Mac stroke widths).
Where the Mac uses an SF Symbol, the closest Fluent glyph stays acceptable.
Amend win32-design-system.md §4 to say so, so the next sidebar icon is not
re-derived from the font.

## Goals

- [ ] a Windows `sidebar_symbol` module that draws Mac's PaneSidebarSymbol
      set from the same coordinates (pure geometry unit-tested; one painter)
- [ ] rows, rail tiles and the header use it; kind mapping matches
      `PaneSidebarRow.swift:404-416` exactly (diff -> diff, code/html ->
      document)
- [ ] search clear is an x in a filled disc
- [ ] design-system §4 amended; the stale comment at PaneSidebar.zig:3695 fixed

## Validation criteria

- [ ] on-box screenshot of rail + expanded sidebar beside the Mac reference
