# T3106 - Every banner, tree or sidebar change re-encodes and rewrites the whole session layout on the UI thread on Windows: write it off the UI thread, latest state wins, flushed at quit (Mac 2a4388ee4)

## Summary

Mac 2a4388ee4: the session layout manifest re-encoded every window (screen snapshots included) and rewrote the file on the main thread on every banner change; now written on a background queue, latest-wins, flushed when quit begins and at termination; one session-id retry loop per entry instead of one per trigger (3.6 ms -> 0.6 ms of main thread per banner change, 22 panes). On Windows: measure what a +set-banner costs the UI thread in session-layout.json writes, and move the write off it with the same latest-wins + flush-at-quit contract. Validation: UI-thread time per banner change measured before/after on a many-pane session; a quit right after a banner change still persists it.
