# T3027 - PA-I13: cold agent start sleeps in 100 ms steps on the GUI thread, and the upgrade check spawns ghoztty-agent --version synchronously (LocalAgent.zig:1140, :590)

## Summary

PA-I13 (audit-1, T2962). src/apprt/win32/LocalAgent.zig:1139-1149 findOrSpawn loops `std.Thread.sleep(poll_interval_ms)` (100 ms) for up to 2 s, so first-window latency rounds up to the next 100 ms (~50 ms average) while the GUI thread only pumps IPC. LocalAgent.zig:590 std.process.Child.run of `ghoztty-agent --version`, called from App.zig:6347, is a process create and wait once per app run (duration not measured; GUI-thread caller inferred, not traced). Fix: WaitNamedPipeW (or a named ready event) with the remaining deadline; run the version probe on a worker or cache the stamp keyed by the binary's mtime and size. Risk low.
