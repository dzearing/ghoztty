# T2260 - Main intake runs several times a day, not once at the morning digest, so Mac changes reach the Windows queue within hours

## Summary

User directive 2026-10-25: "we should be checking main maybe a few times a
day for mac updates so that updates stream with a very low latency."

Today the main intake (go.md step 0.6, "daily for now", user 2026-08-07:
"reduce the lag ... to virtually hours rather than days") is part of the
morning-owner block (`scripts\morning-owner.ps1`, steps 0.5-0.7) and runs
once a day. A Mac commit that lands at 09:00 is not even read until 05:00
the next day, and its merge task (T2249-style) and port tasks queue behind
that.

## Goals

- [ ] intake is its own due-check, independent of the digest: due when
      `origin/main` has moved past the watermark AND at least N hours
      (default 4) have passed since the last intake - checked at every task
      boundary in either lane, so the effective latency is hours
- [ ] exactly one lane runs it at a time (box-wide lock, the T1982 pattern),
      and the watermark commit never conflicts with the other lane's
      (morning-owner's T2115 lesson)
- [ ] an intake that finds Mac commits also files/refreshes the merge task
      (like T2249) at P1, so the code merge follows within the same day
- [ ] the intake note keeps its per-run entry (date AND time now), and the
      digest reports how many intakes ran and the worst Mac-commit -> filed
      latency of the day
- [ ] go.md step 0.6 is rewritten to say this; "daily for now" is gone

## Validation criteria

- [ ] acceptance script under `test\win32\` drives the due-check: not due when
      main has not moved; not due inside the N-hour window; due after it;
      a second lane is refused while the lock is held - with a positive
      control
- [ ] a live run on the box: an intake fires mid-day from a task boundary
      and moves the watermark (cite the commit)
