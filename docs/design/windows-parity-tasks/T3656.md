# T3656 - On Linux, SIGTERM never quits a GTK app running with quit-after-last-window-closed = false: it logs 'received SIGTERM, quitting' and stays up, and a second SIGTERM is ignored

## Summary

Found by T3573's window-mode.sh: the app (pid alive 10+ min) logged 'received SIGTERM, quitting' (handleSigterm -> quitNow, application.zig) but never exited with quit-after-last-window-closed = false, and the harness's second SIGTERM did nothing because handleSigterm returns SOURCE_REMOVE (GLib keeps the signal routed to a removed source). A logout or systemctl stop would leave a resident app running. Expected: SIGTERM quits whatever the quit-after-last-window-closed setting (Mac applicationWillTerminate). Repro: test/linux/window-mode.sh without its KILL fallback (kill -TERM the first app after W5b; it never exits). window-mode.sh currently kills that app with SIGKILL after the TERM and names this task.

## In plain terms

On Linux (under WSL), asking Ghoztty to quit from outside (a logout, a
`systemctl stop`, `kill`) sometimes left it running forever: it said it was
quitting and then froze while closing its windows. Now a quit that stalls
for 8 seconds after the layout is saved ends the process anyway, so the
app always goes away and the next launch brings everything back.

## Root cause

Not the SIGTERM handler and not quit-after-last-window-closed. gdb on a
stuck app (one run in three of window-mode.sh) shows the main thread inside
`quitNow`'s window destroy: `gtk_widget_unrealize -> gdk_gl_texture_release
-> libgallium (Mesa d3d12, WSLg's GPU driver) -> futex wait` that never
wakes. The second SIGTERM looked "ignored" only because the first handler
never returned. A driver hang cannot be fixed from here, so `quitNow` arms a
backstop (`armQuitBackstop`, application.zig) after `SessionLayout.finishForQuit`
and `RelayWindows.syncForQuit`: a detached thread that `_exit(0)`s 8s later
and logs `quit backstop: ...`. Nothing is lost - the agent detaches every
session on the broken pipe, as for a crash (docs/claude/sessions.md). No
parity owed: macOS and win32 have no GTK/Mesa teardown; this is a Linux-only
guard.
