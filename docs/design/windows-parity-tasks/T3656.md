# T3656 - On Linux, SIGTERM never quits a GTK app running with quit-after-last-window-closed = false: it logs 'received SIGTERM, quitting' and stays up, and a second SIGTERM is ignored

## Summary

Found by T3573's window-mode.sh: the app (pid alive 10+ min) logged 'received SIGTERM, quitting' (handleSigterm -> quitNow, application.zig) but never exited with quit-after-last-window-closed = false, and the harness's second SIGTERM did nothing because handleSigterm returns SOURCE_REMOVE (GLib keeps the signal routed to a removed source). A logout or systemctl stop would leave a resident app running. Expected: SIGTERM quits whatever the quit-after-last-window-closed setting (Mac applicationWillTerminate). Repro: test/linux/window-mode.sh without its KILL fallback (kill -TERM the first app after W5b; it never exits). window-mode.sh currently kills that app with SIGKILL after the TERM and names this task.
