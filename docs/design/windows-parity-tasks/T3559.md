# T3559 - Linux: the pane banner collapses to its title row on click, and the interactive banner editor (Ctrl+R) on GTK

## Summary

T3339 landed the GTK banner card (PaneBanner.zig) without two Mac behaviors from docs/reference/banners.md: clicking the card collapses it to its title row (ephemeral, reset on clear; the terminal resized once, not per animation frame), and prompt_banner - the multi-line Set Pane Banner editor (Return newline, Ctrl+Return saves, Escape cancels) - which application.zig still logs as not ported.

## In plain terms

On Linux a long pane banner could not be folded away, and there was no way to
type a banner from the keyboard - only a script could set one. Now a click on
the banner (or its little arrow) folds it down to its first line and gives
the terminal the space back, and Ctrl+Shift+B opens a small editor with the
banner's text in it, the same as Windows.

## Goals

- [x] A click on a multi-line card, or on its chevron, folds it to its title row and back; a one-line card does not fold
- [x] The terminal gets its rows back when the card folds, and is resized once per click
- [x] A new text keeps the fold; a cleared banner comes back expanded
- [x] Ctrl+Shift+B opens the Set Pane Banner editor filled with the banner (Windows' chord; plain Ctrl+R stays the shell's)
- [x] Return is a newline, Ctrl+Return saves, Escape cancels, a blank save clears; one editor at a time

## Design

- **Collapse.** `pane_banner_rules.collapsible` is win32's rule (a line under
  the first). Folded, the card draws `collapsedBlocks`: the first block cut to
  one row (a heading/line ellipsized to one line, a list's first item, a
  table's header or first row). No animation: the card is rebuilt at its new
  height and GTK lays the pane out once, which is the Mac's "the user never
  sees the terminal resize" without its frozen-frame machinery (parity is
  behavior, linux-port.md). The card's click release is queued to an idle so a
  link (`activate-link`) or the chevron (`clicked`), both decided later, can
  take the click instead of folding the card.
- **Editor.** An `AdwAlertDialog` (Cancel / Save) with a monospace wrapping
  `GtkTextView`, so it looks like every other libadwaita prompt; the key
  handler sits in the capture phase so Ctrl+Return never reaches the view's
  own Return. Saves go through `Surface.setPaneBanner`, the `+set-banner` /
  OSC 7778 path.
- **Chord.** Ctrl+Shift+B in the Linux default bindings, same reason as
  Windows (Config.zig comment): plain Ctrl+R is reverse history search.
