# T2775 - comp-present-onscreen.ps1's default (on) arm never shrinks a pane, so a stretched frame after a split or a window narrowing on the default composition path is invisible to every on-screen oracle (T2625 was caught only by the tree arm)

## Summary

T2625's stretch (a `SetSourceSize` rectangle stretched over a larger bucketed
buffer) hit every composition pane that shrinks, but only the tree arm splits,
so the default per-pane visual - the path composition present now ships on by
default (087055a50) - was never filmed after a shrink. Add a split (or a
`+rearrange`/window narrowing) to the `on` arm and score the shrunk pane's
glyph match and position the way `tree.split-left.8` / `tree.10` do.
Negative control: run it with `sourceTransform` forced to identity (a debug
seam) and it must go red.

## Validation criteria

- [ ] the on arm splits (or narrows) and scores the shrunk pane: glyph match >= 0.80 at its own spot
- [ ] with a debug seam forcing the source transform to identity, that check goes red
