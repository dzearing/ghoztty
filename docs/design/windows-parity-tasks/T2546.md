## In plain terms

When you drag a window's edge, for one frame the window has its new size but
what is inside it is still drawn at the old size. This task films that drag
with the window's title bar moved onto the new drawing path, to see whether
that alone fixes it. It does not, so the next step (T2548) goes deeper.

## Goals

- [x] film the four edge drags with the knob off and on, same build, twice each
- [x] say whether chrome on the compositor removes the out-of-step frame
- [x] file step 4e if it does not (T2548), plus anything new the film shows (T2549)

## Findings (2026-10-31)

`scripts\resize-sync-onscreen.ps1 -Exe zig-out-rsafe\bin\ghoztty.exe`,
ReleaseSafe at `565f6d44b`, `GHOZTTY_RESIZE_TRACE=1`, ghost window (never
activates). Bad frames per drag (right-shrink / right-grow / left-shrink /
left-grow, of 62-68 frames), two runs each:

| knob | run 1 | run 2 | flat-background frames (right-grow) |
|---|---|---|---|
| off | 30 / 60 / 30 / 63 | 30 / 61 / 31 / 62 | 1, 0 |
| `GHOZTTY_COMP_CHROME=1` | 37 / 48 / 39 / 48 | 33 / 47 / 54 / 53 | **24, 15** |

**Verdict: chrome on the compositor does not remove the out-of-step frame.**
What it changes is which surfaces disagree:

- **Shrink.** Off, the page is ahead of its own address bar
  (`pageL=733/barL=738`). On, page and bar agree, but both are still at the
  previous step's layout under the new frame (`gap=9 right=2`, about one
  frame per step, the same count as before). Every surface now moves
  together, and the whole client moves a compose behind the window's size.
  That is the redirection surface: DWM resizes it and shows the new frame at
  the first compose, whatever has been committed by then.
- **Grow.** Fewer bad frames than off (about 48 against 61), but a new shape:
  the caption visual is at the new width while the desk is not, so the strip
  the window grew into shows the window surface's flat fill (frame
  `right-grow/f0004`: caption buttons at the new right edge, a dark strip
  beside the viewer card). Filed as T2549.

Next: **T2548 (step 4e)**. Remove the redirection surface once the last GDI
pixels are off it (T2544/T2545), sequence the visual-tree commit with the size
change, and re-film. T2516 now waits on T2548 and T2549 as well.
