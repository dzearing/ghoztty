# T1838 - A stashed pane comes back on screen after a Windows restart: the session manifest does not record the stash (Mac per-leaf stashIndex)

## Summary

T1827 brought pane stashing to Windows, but the stash is not written to the
session layout manifest, so after an app restart (or a session restore onto the
agent) every stashed pane comes back ON SCREEN. Mac records a per-leaf
`stashIndex` (0 = top of the stash) in `SessionLayoutManifest` and rebuilds the
stash on restore with `withStash(stashedIDs(...))` (main 597a193cc).

Port: add an optional `stash_index` to `session_layout.Leaf` (snake_case like
every other win32 manifest field; additive, absent = not stashed, so an older
app ignores it), write it at capture from `pane_stash.stashIndex`, and on
restore mark the restored leaves in stash order (highest index first, so the
top ends up most recent) then `pane_stash.normalize` the tree. A pane stashed
at launch must still get its real slot size (`Window.placeStashedNode` already
does this on the first layout pass - assert it, that is the c6826b79a case).
Never touch session close intent on the way (Mac PaneStashSessionSafetyTests).

## Validation criteria

- [ ] capture writes `stash_index` for stashed leaves only (unit test on the capture path)
- [ ] restore re-stashes in the recorded order, top of stash preserved
- [ ] a restore whose stash would hide every pane leaves one visible (normalize)
- [ ] a pane stashed at launch is sized to its real slot, not a placeholder (acceptance: extend test/win32/ipc-stash.ps1 or a session-restore script)
- [ ] no session is marked close-on-free by a stash round trip
