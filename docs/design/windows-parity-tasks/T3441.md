# T3441 - release-windows.yml still lets setup-zig save the Zig cache after a cancelled or failed run, the T3440 poisoning shape on the release path

## Summary

T3440 found that mlugg/setup-zig's post step saves .zig-cache unconditionally, so a run cancelled mid-compile hands a half-written glslang.lib to every later run (fork-ci windows-cross was red for hours over it). fork-ci now restores/saves with actions/cache and saves only after a green compile. release-windows.yml (line ~85, mlugg/setup-zig@v2 with default use-cache) has the same exposure on its own setup-zig-cache-v2-<job> chain: one cancelled or failed tag build would poison the next release build. Apply the same shape (use-cache: false, actions/cache/restore before the build, actions/cache/save after it) and add a release-artifacts.ps1 assertion like E14.
