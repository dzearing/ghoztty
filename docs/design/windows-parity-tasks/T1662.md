# T1662 - A red zig lane reports an unrelated stderr line as the failure reason, so the real cause is never in the kept output

## Summary

When a zig test fails, the build runner prints 'error: <test> failed: <text>' where the text is whatever stderr happened to arrive at that moment - and every test in the binary shares one stderr. floor-lane.ps1's FLOOR FAILURE DETAIL keeps the first six 'error:' lines, so that misattributed line is what survives into the kept output, while the REAL cause (the error return trace naming the same test) carries no 'error:' prefix and is dropped. T1645 is what this cost: four turns and five progress-log entries chased '[tripwire] (warn): untripped point=read' - a line emitted by src/tripwire.zig's own PASSING test - while the actual failure, error.WaitForTimeout at ViewerPane.zig:8237, sat in the same logs unread. Remedy: when Get-LaneFailureDetail sees 'error: <name> failed:', pull the stack-trace frames that name that test out of the same log and print those under it.

## In plain terms

When the test suite goes red, the few lines we keep to explain why can name the
wrong thing entirely. All the tests in one binary share a single output stream,
so the failure line picks up whatever text happened to be printed at that
moment - often a harmless note from a test that PASSED. The real reason is
further down and does not look like an error, so our filter throws it away.
The result is a red run whose kept output points at an innocent line, which is
how one defect cost four turns of chasing.

## Goals

- [ ] A failure summary keeps the lines that name the failing test, not the
      lines that happen to match `error:`
- [ ] The 2026-09-18 T1645 logs, replayed through the fixed formatter, surface
      `error.WaitForTimeout at ViewerPane.zig:8237` rather than
      `[tripwire] (warn): untripped point=read`

## Validation criteria

- [ ] Given a captured lane log in which `error: <test> failed:` carries text
      from a different test, `Get-LaneFailureDetail` prints the error return
      trace frames that name the failing test underneath it.
- [ ] A lane log with no such misattribution is formatted exactly as it is
      today (no regression in the ordinary case).
- [ ] A negative control proves the new section can be absent: a log with no
      frames for the named test says so rather than printing nothing.
