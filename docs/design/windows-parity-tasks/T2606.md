# T2606 - The opt-in composition present (GHOZTTY_COMP_PRESENT=1) strands ~48 MB of GPU memory per closed window with plain panes - 3 split cycles 58.8 -> 202.2 MB dedicated

## In plain terms

Terminal panes are drawn through a newer graphics path by default, and closing
a window on it left some graphics memory behind every time - about 1 MB a
window on average, growing without limit over a day of opening and closing
windows. After this fix, closing a window with one or two terminals gives that
memory back.

## Goals

- [x] find what keeps the closed pane's graphics memory alive
- [x] release it when the window closes
- [x] the split-shape memory check passes

## Summary

Found while bisecting T2599 (2026-11-01, lane b, debug, RTX 4090). Per-step
GPU probe (`GHOZTTY_PANE_LAYER=0`, `GHOZTTY_COMP_PRESENT=1`, a window with a
right split, `+close` the window, `--undo-timeout=0`), GPU dedicated MB:

- start 58.8; cycle 1 open 105.2, split 136.5, close 106.6
- cycle 2 open 153.0, split 184.3, close 154.4
- cycle 3 open 200.7, split 232.1, close 202.2

So ~47.8 MB a closed window stays behind, and even the anchor window costs
~26 MB more than on the SwapBuffers path. T2499 measured 4-5 MB per closed
PANE on this path; the per-WINDOW strand is far bigger. Likely the
presenter's interop device / shared textures (`gl_comp_present.zig`,
`OpenGL.zig` `self.comp`) are not released when the window closes, or the
DComp visual tree holds them. Measure with the same probe (one terminal,
then two) and `window-close-memory.ps1 -Shape split` with the knob set.

## Validation criteria

- [x] `window-close-memory.ps1 -Shape split` with `GHOZTTY_COMP_PRESENT=1` and `GHOZTTY_PANE_LAYER=0`: A8 <= 1 MB a closed window - 2026-11-07 debug, `-Cycles 20 -Report --undo-timeout=0`: ALL PASS, A8 0.99 MB, and GPU dedicated flat at 77.4 MB from cycle 8 to 20 (fill, not slope)
- [x] single shape no longer climbs - 2026-11-07 debug, 20 cycles: 73.4 -> 76.4 (one step, then flat), A8 0.47; before the fix 40 cycles went 64.3 -> 106.4 linearly in 3 MB steps
- [x] unit test: `comp_overlay` test "the last holder of a tree commits after the root goes and before the device does (T2606)" (`zig test src/renderer/comp_overlay.zig`, 10/10)
- Out of scope, filed as T2785 - the full (default) shape: 30 cycles still climb 69.9 -> 89.4 in 1.5 MB steps (A8 1.06); viewer shape alone passes (0.59)
