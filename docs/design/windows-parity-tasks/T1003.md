# T1003 - After a late restore the empty terminal the launch opened is still sitting there

## Summary

When the launch restores nothing it opens one blank terminal; T976's deferred pass then rebuilds the real windows around it, so the user ends up with an extra empty window they did not ask for. T976 deliberately left it alone - closing a pane the user may already have typed into is worse than an extra window - but the polished behaviour is to close it when it is still PRISTINE (one pane, nothing typed, no child output, no viewer) at the moment the deferred restore succeeds. Needs a pristine test that cannot be fooled by a shell prompt banner, and an acceptance arm that types into the blank window first and proves it is kept.

## In plain terms

If Ghoztty starts before its background helper is ready, it shows one empty terminal and then, a few seconds later, brings back the windows you had open. Until now that empty terminal stayed behind as an extra window nobody asked for. Now it closes by itself when the real windows come back, unless you already typed into it, split it, added a tab or opened a viewer in it. In that case it stays.

## Goals

- [x] the launch remembers its blank stand-in window only while the late restore is still pending
- [x] "untouched" means nothing was ever sent to its shell (keys, paste, mouse, `+send-keys`), not "nothing appeared", because every shell prints a prompt on its own
- [x] once the late restore has rebuilt at least one window, an untouched stand-in closes and one that was used is kept
- [x] acceptance covers both arms, and the used arm is the control

## Design

- `termio.Termio.input_written` (shared core, an atomic bool) is set in `queueMessage` for every `write_*` message. Every input path goes through that queue: core key/paste/mouse encoding, the win32 IPC `+send-keys` and the IME/char `writeWin32InputSequence`. Program output, focus and colour-scheme reports are separate message kinds and never set it, so a prompt banner cannot make the window look used.
- `restore_placeholder.zig` holds the decision as a pure function: close only when the deferred pass restored something AND the window is alive, has one tab, one initialized terminal pane (no viewer) and no input. It is unit-tested in both lanes.
- `App.restore_placeholder_window` is set in `run` only when the blank startup window opens while `restore_retry_armed` is set, so a launch-command window never qualifies. It is cleared on stand-down, when the retries run out, when the window is destroyed (`Window.zig` removal path) and after the deferred pass decides. The close is a real `Window.close()`, so the pane's shell/session ends with it.
- Mac seat: macOS has no deferred pass at all. `SessionLayoutRestore.restoreSessionLayoutWindows` gives up with "local agent unreachable; keeping N manifest entries for next launch". The Mac half of T976 and this task is filed as T1724 (seat mac); the `input_written` flag it needs is already in the shared core.
