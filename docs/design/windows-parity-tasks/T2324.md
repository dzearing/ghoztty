# T2324 - Windows pane sidebar's this-window list starts with the window's own header (name, fold chevron, hover + and x) with its panes indented under it; in the rail the header is its + alone in a slot the header's exact height

## Summary

Mac e94a9737e (main intake 2026-10-26): the Panes list is held by this window's header exactly as in All windows (no 'This Window' tag), so this window has a + too; the rail shows only the + in a slot of PaneSidebarWindowHeader.height so collapse/expand moves no icon. Mac ref: docs/reference/pane-sidebar.md, macos/Sources/Features/PaneSidebar/PaneSidebarView.swift. Builds on the + buttons task.

## In plain terms

The pane sidebar's list of this window's panes used to start straight with
the panes. Now, as on Mac, it starts with the window itself: its name, a fold
arrow, and on hover a + (new pane) and an x (close window), with the panes
tucked in under it. When the sidebar is collapsed to icons, that header shrinks
to just its +, in a slot exactly as tall, so collapsing or expanding the
sidebar never makes a pane's icon jump.

- [x] the header's + and the rail's + split the focused pane the last manual way; the chevron folds the panes and tray away; the x closes the window
