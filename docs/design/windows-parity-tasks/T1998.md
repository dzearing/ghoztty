# T1998 - Every CLI invocation writes a 9-line startup banner into the shared ghoztty.log: on this box it is ~75% of the log (3363 CLI runs in a day = ~30k lines)

## Summary

Found while measuring T1956. In the last 40k lines of %LOCALAPPDATA%\ghoztty\ghoztty.log, 'executing CLI action', os_locale setlocale, renderer=, libxev backend, font_backend, harfbuzz, runtime=, version and build-optimize lines each appear 3363 times - one block per +read/+list/+set-banner call (agents and the banner hook call the CLI constantly). Viewer/remote lines were 6.8k by comparison. A CLI action should not log the GUI's startup banner at info into the app's log (or should not open the shared log at all below warn). Check both platforms: if the Mac CLI writes the same banner to its log, fix it there too. Validate: count lines per +list call before/after; error lines from a failing CLI action still reach the log.

## In plain terms

Every time a script or an AI agent asked the terminal a quick question
(list the windows, read a pane, update a status banner), the terminal wrote
nine lines of "here is my version and build" into its diagnostic log. That
happens thousands of times a day, so most of the log was this boilerplate,
and the lines that explain a crash were pushed out of it within hours. Now
those quick calls write nothing unless something actually goes wrong.

## Goals

- [x] a `+verb` CLI call writes no info line into the shared `ghoztty.log`
- [x] warnings and errors from a CLI call still land
- [x] a CLI call that becomes the app (no instance running) still logs the app's banner
- [x] an opt-in (`GHOZTTY_CLI_LOG=info`) puts a CLI call's info lines back for diagnosing the CLI itself
- [x] Mac checked

## Validation criteria

- [x] Lines per `+list` call: 9 before, 0 after - measured on a ReleaseFast `zig-out-release` exe in a sandboxed LOCALAPPDATA (by-hand probe, then `test\win32\log-append.ps1` section T, T1: "+list without the opt-in wrote 0 line(s) (was 9 with it)"). "Before" is also the user's real log: in the last 40k lines each banner line appeared once per CLI call.
- [x] A failing CLI call's warning/error lines still reach the log, and none of its info lines do - `log-append.ps1` T2-T5 (`+validate-config` on a bad config: 1 warning/error line with or without the opt-in, 0 info by default).
- [x] The sink sections (L1-L9 append/prefix, R1-R10 rotation, C1-C7 concurrent rotation) still pass with the opt-in as their line source - `log-append.ps1` ALL PASS (36 assertions).
- [x] The gate is pure, with unit tests in every lane - `src\os\log_gate.zig` (5 tests; `zig test` alone, then `floor-lane.ps1 -Lane all` lib/none/win32/agent PASS).
- [x] Mac: no change owed. The file sink is Windows-only (`logFn`'s `windows_file` block); the Mac CLI logs to unified logging, where info lines are memory-only by default and never go into a file Ghoztty owns. The banner-only refactor in `global.zig` is shared and unchanged in behaviour there (the re-log on master promotion is comptime-gated to Windows release).
- [x] Seam registered - `GHOZTTY_CLI_LOG` in `test\win32\seam-audit.registry.json`, armed by log-append T1 (`seam-audit.ps1` ALL PASS).
