# T3646 - The session agent's private memory grows about 40-50 KB for every pane session opened and closed

## Summary

Measured by test/linux/pane-close-memory.sh (T3572) on the Linux debug agent: over 30 split open/close cycles the agent's private memory (smaps_rollup Private_*) climbed 10616 -> 11836 KB, roughly linearly (~40-50 KB per closed session), while its child processes, and the app's threads and fds, all came back. Under the harness's 1 MB per-pane budget, but a linear climb is the shape of retained per-session state (ring, emulator, session table entry, log buffers) rather than allocator warm-up, which flattens. Find what a closed session leaves behind in src/remote/agent (the code is shared, so check the Windows agent the same way, e.g. pane-close-memory.ps1's descendant column) and free it; acceptance: 50+ cycles with the agent's growth flat after warm-up.
