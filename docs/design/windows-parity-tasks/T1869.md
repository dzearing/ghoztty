# T1869 - LaneLeak's self-spawned-test-binary walk (scripts\lib\LaneLeak.ps1 ~l.340-388) still links processes by parent pid alone, so a stranger under a reused pid can be read as a self-spawn and its CPU dropped from lane progress (T1867 rule not applied there)

## Summary

Found while closing T1867. The function that finds test binaries spawned by test binaries (T933) in scripts\lib\LaneLeak.ps1 builds parent->children by ParentProcessId alone, both for the upward "is an ancestor a test binary" walk and for the downward "everything under each root" walk. Pids are recycled and ParentProcessId is never rewritten, so a process older than the member it names can be linked in: its CPU is then dropped from lane progress (a stall read as a wedge, or the reverse). Read path only - nothing is killed through it. Fix: the T1840/T1867 rule (a child must be no older than the parent it names; skip when either CreationDate is missing), ideally by reusing Get-ProcessFamily from scripts\lib\ProcessFamily.ps1. Validation: a synthetic-row arm in test\win32\floor-lane-leak-sweep.ps1 with an undated negative control.

## Validation criteria

- [ ] floor-lane-leak-sweep.ps1 gains an arm: an older process naming a test binary's pid is not treated as a self-spawn; negative control with undated rows still links it
- [ ] lane-leak-sweep guard row green
