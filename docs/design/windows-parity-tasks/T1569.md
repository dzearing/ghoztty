# T1569 - Both portable install locations hold a Debug ghoztty.exe beside a release ghoztty.com

## In plain terms

The portable copy of Ghoztty on the Desktop, and the one on the network share,
are both currently broken in the same way: the main program is a debug build
(it opens a console window) and the little launcher next to it is from a
different, older build. Anybody who runs those copies gets something nobody
meant to ship. Nothing has noticed for weeks.

## Summary

T727's audit was run for the first time on 2026-09-14 and immediately scored the
state it was written for:

```
D:\Users\David\Desktop\Ghoztty-portable-x64\Ghoztty\ghoztty.exe has PE subsystem 3, expected 2
D:\Users\David\Desktop\Ghoztty-portable-x64\Ghoztty ships ghoztty.exe +f1d06293e beside ghoztty.com +db68549df
\\homeassistant\share\ghoztty-windows\Ghoztty-portable-x64\Ghoztty\ghoztty.exe has PE subsystem 3, expected 2
\\homeassistant\share\ghoztty-windows\Ghoztty-portable-x64\Ghoztty ships ghoztty.exe +f1d06293e beside ghoztty.com +db68549df
\\homeassistant\share\ghoztty-windows\ghoztty-agent.exe reports 20260810-60bb1e9c9 but the portables have 20260908-fc2e17ac4
```

PE subsystem 3 is console: a Debug build. So both portable locations carry a
debug `ghoztty.exe` (+f1d06293e) beside a `ghoztty.com` from +db68549df, which
is precisely the 2026-08-10 shape, and the share's loose agent is a month older
than the one in the portable directories beside it.

The fix is a delivery, not an edit: build a real release staging prefix and run
`scripts\deliver-windows-build.ps1` against it, which refuses a Debug staging
prefix up front and verifies every file it writes. Nothing here touches the
user's installed Ghoztty (D85) — these are install locations 2 and 3, which the
loop owns.

Reproduce, at any time, with:

```
powershell -NoProfile -File scripts\deliver-windows-build.ps1 -VerifyOnly
```

## Validation criteria

- [ ] A release staging prefix exists and `deliver-windows-build.ps1` accepts it
      (a Debug one is refused at the door).
- [ ] `deliver-windows-build.ps1 -VerifyOnly` exits 0 afterwards, with every
      location agreeing on one commit.
- [ ] The share's loose `ghoztty-agent.exe` matches the agent in the portable
      directories.
- [ ] `go-loop-health.ps1` reports `deliver=ok`.
