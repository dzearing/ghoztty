# T2238 - The test-reach audit passed while chrome_reposition.zig's tests were never compiled into the win32 lane

## Summary

Found in T1348: -Dtest-filter=chrome_reposition matched nothing, so T1392's five tests and any new ones ran nowhere, yet test-reach (stamped green 2026-10-24, chrome_reposition.zig in its stamp) reported no finding. Get-WinModulesInTestBinary scans for apprt.win32.<mod>.test - find why the module read as present (or was exempted), fix the oracle, and add a TeethCheck case for a win32 module imported only by other modules (not by win32.zig's test block). T1348 added the missing import line, so reproduce against the parent commit.

## In plain terms

A check that is supposed to catch unit tests that never run was suspected of
missing one. It was not: the tests did run all along, and the suspicion came
from a quirk of running a filtered subset. Nothing changes for users; the
misleading code comment is corrected.

## Goals

- [x] find why test-reach read chrome_reposition as present
- [x] decide whether the oracle needs fixing (it does not)
- [x] correct the record the false premise left behind

## Outcome

**No oracle defect.** Built the win32 test lane at `1c4c99f69` (the parent of
T1348's `86224b6b3`, before `win32.zig` named `chrome_reposition.zig`) in a
detached worktree and scanned the binary: all five
`apprt.win32.chrome_reposition.test.*` names are present (261 modules). Then
planted `try testing.expect(false)` in `height-only resize counts too` at that
same parent and rebuilt: the unfiltered lane went **red** on exactly that test
(`6895/6968 passed, 1 failed`). So the tests ran through the five overlays that
import the module - the T2041 shape already written up in
`docs/claude/testing.md` ("A filter drops those named tests") - and T1348's
"matched nothing" was the `-Dtest-filter` artifact, not absence. The oracle
answered correctly; the requested TeethCheck case for "a module reached only
through other modules" would assert a module IS present, which section B's
B3/B4 already do over every such module in the real tree.

Changed: the comment over the import in `src/apprt/win32.zig` (it claimed the
tests "ran nowhere") and the trap paragraph in `docs/claude/testing.md` now
names T1348 as the second instance.
