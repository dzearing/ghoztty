# T1843 - Busy panes do not shimmer in the Windows pane sidebar, a stashed question does not pulse, and a bell on a stashed pane leaves no dot

## Summary

Follow-up of T1828. Mac: busy = the icon/monogram drawn as a dim base with a brighter band sweeping across (~1.1s sweep, ~0.3s rest, plain under reduced motion - SPI_GETCLIENTAREAANIMATION on Windows); needs_input on a STASHED row pulses gently; a bell on a stashed pane shows a dot until it is restored. T1828 paints static badges: an accent dot for busy and the accent question disc.

## In plain terms

The pane list down the side of a window is supposed to tell you at a glance
which panes are working, which are waiting on you, and which beeped while
you had them tucked away. On Windows it showed a small static dot for
"working" and nothing for a beep. Now a working pane's icon has a light
sweeping across it, a pane with a question has a softly breathing ring round
its badge, and a tucked-away pane that beeped keeps a dot until you look at
it - the way the Mac app does. A beep is also silent by default now, as on
Mac (it only flashes the taskbar when the window is in the background).

## Goals

- [x] busy marks shimmer (rail monogram and panel row icon), with no busy dot
- [x] the question badge breathes in panel rows and window headers; the rail's corner "?" holds still (Mac)
- [x] a stashed pane whose bell rang shows a dot (row and rail tile) until it is focused or typed into
- [x] the motion clock runs only while something moves, stops itself, and honors "Animation effects" off
- [x] `ring_bell` honors bell-features `system` (beep, off by default) and `attention` (taskbar flash)

## Design

- `pane_sidebar_motion.zig` (pure, every lane): Mac's `PaneSidebarShimmer`
  numbers (1.4 s period, 0.8 sweep, band 3x the mark, base 0.3, stops
  0.35/0.5/0.65) and the question ring (0 -> 0.22, 1.2 s each way, eased);
  `Marks.moving(motion)` is the only gate on the clock.
- GDI has no gradient mask for text, so a busy mark is drawn in vertical
  one-pixel slices, each in the band's color at that x mixed over what the
  mark sits on; runs of one color are one draw.
- One window timer per sidebar surface (id 3 on its own hwnd, not msg_hwnd):
  every paint tallies what it drew and arms the timer if anything moves; a
  tick repaints while the last paint moved and the window is visible and not
  minimized, else kills itself. So the clock can never outlive the marks.
- `Surface.bell` (Mac `SurfaceView.bell`): set by `ring_bell` whatever
  `bell-features` says, cleared on WM_SETFOCUS and on any key press;
  `setBell` re-syncs the sidebar only when it moves.
- Reduced motion = `App.clientAreaAnimationsEnabled()` (SPI_GETCLIENTAREAANIMATION),
  read per paint and per tick: busy marks are drawn plain in full ink, no ring.

- [x] shimmer/pulse timing and the clock gate: unit tests in `pane_sidebar_motion.zig` (none + win32 lanes, floor-lane all)
- [x] busy starts the clock and the rail really moves (6 of 8 WM_PRINTCLIENT frames distinct): `test\win32\pane-sidebar-activity.ps1` section 1
- [x] idle stops the clock (`motion off` logged) and the rail holds still: section 2
- [x] the rail's corner "?" starts no clock and holds still: section 3
- [x] the pinned panel's question badge breathes (8 of 8 distinct): section 4
- [x] a BEL in a stashed pane: tally bell=1, the picture gains the dot, the dot holds still; focused once, re-stashing brings no dot back: section 5

- [x] frames inspected by eye: band crossing "dav", ring round the "?", dot on the stashed row
