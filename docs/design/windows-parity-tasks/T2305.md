# T2305 - The Windows pane sidebar's all-windows outline never shows this window's empty tray: Mac keeps the dashed 'Drag a pane here to stash it' well in this window's group at rest and adds the tray header during a drag (Mac 543489bca tray(); split from T2276)

## Summary

Mac `PaneSidebarView.tray()` (origin/main, 543489bca): in the all-windows
scope, THIS window's group always ends in `PaneSidebarEmptyStashSlot` when it
has nothing stashed, and its divider + STASHED caption appear while a drag is
live (`isThisWindow && (dragSession.isDragging || !showsAllWindows)`). Other
windows' groups show a tray only when it holds something.

Windows: T2276 made the single-window roster lay the empty tray out at rest
(`pane_sidebar.addEmptyTray`), but `addEmptyTray` returns early for the
outline (`if (l.outline) return;`) and `pane_sidebar_outline.buildLines`
pushes a `.stashed_caption` line only for a group that has stashed panes. So
in the all-windows view there is no visible stash target at all - the whole
sidebar is still a stash drop, but nothing says so.

Fix: give the own group an empty-tray line (a well; plus the rule and caption
while `drag_active`) in `buildLines`, lay it out in `layoutLines` into
`drop_slot`, and keep `dropGeometry`'s `slot` pointing at it.

Priority P2: the drop already works in the outline; this is the affordance.

## Validation criteria

- [ ] Unit: the outline's own group with nothing stashed lays out a well after its last row; another window's empty group lays out none; with a drag live the own group gets the rule + caption
- [ ] Acceptance: `pane-sidebar-all-windows.ps1` - the outline line names the well in this window's group at rest
