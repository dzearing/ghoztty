# T1762 - Every command palette title ending in an ellipsis paints blank (Change Pane/Tab/Window Title..., Check for Updates...)

## Summary

Seen in T1754's O10d capture (%TEMP%\ghoztty-palette-order-o10d-*.png): rows for the four registry commands whose names end in U+2026 draw no title at all, only their keybind hint. Root cause (Surface.zig paintPaletteInto, since e0118f682): 'while (name_len > 0 and entry_name[name_len - 1] & 0xC0 == 0x80) name_len -= 1;' strips trailing continuation bytes UNCONDITIONALLY, not only when the @min truncation cut a codepoint - so the complete 3-byte ellipsis E2 80 A6 is cut to a lone E2, utf8ToUtf16Le errors, 'catch 0' paints an empty string. Fix: back up to a codepoint boundary only when name_len < entry_name.len (or back up to the last lead byte and keep the codepoint if it fits), extract it as a pure helper with a none-lane test (ellipsis intact, truncated multi-byte dropped), and add a palette-order.ps1 pixel arm that the filtered row for 'Change Window Title' paints text. Check the other DrawText call sites using the same idiom (grep '& 0xC0 == 0x80').

## In plain terms

In the command palette, the commands whose names end in "..." (Change Window
Title..., Change Tab Title..., Change Pane Title..., Check for Updates...)
showed up as empty rows with only a shortcut on the right. After this they
show their names like every other row.
