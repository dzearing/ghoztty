# T1516 - The session-layout cost harness scores a different failure every run, so nobody can tell a real regression from box load

## Summary

test\win32\layout-capture-cost.ps1 is RED at HEAD on this box and red DIFFERENTLY each run: run 1 failed G4 (the forced refresh did not run the bounded pass, mode was not fresh) and G5 (1 of 1 panes advanced, 6 flooded); run 2, minutes later, passed both and failed G3 instead (17.45 ms against a 16.67 ms frame budget). A wall-clock budget measured on a box that is also building and running GUI acceptance scripts cannot separate a real regression from contention, and the G section's mode assertions look load-sensitive the same way. Either the budget needs a headroom factor and a re-measure policy, or the section needs to measure CPU rather than wall time. Found while converting the script for T1511 batch 4; that conversion was written and REVERTED rather than shipped unproven, because a red run cannot re-stamp the guard.
