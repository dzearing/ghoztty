# T3171 - Both seats write release-notes/client/<version>.json for the same version: win-v1.55.1 and Mac v1.55.1 collided at the T3164 merge, and one side's notes must be dropped

## Summary

Both seats mint the same version numbers (Mac `v1.55.1`, Windows `win-v1.55.1`) and both write `release-notes/client/1.55.1.json`: the Mac by hand at release step 2 (8d239f6fc), Windows through `release-notes-author.ps1` at publish (2218a6816). Whichever lands second sees `NOTES EXIST` and stays silent (1.55.0 shipped Mac notes on Windows that way), or, when both landed first on their own branch, the merge is an add/add conflict. At the T3164 merge the Windows side was kept: it is what win-v1.55.1 actually embeds, and the Mac item describes single-window mode, which Windows does not have yet (T3136).

After the cutover there is one trunk and one file per version, so this has to be designed rather than resolved by hand each time. Options to weigh (mechanism - this seat's call): per-platform directories (`release-notes/client-win/`) read by the win32 What's New and the Windows author; or one shared file with per-item `platforms` and both renderers filtering. Whichever is chosen, the Mac seat's release command and `GhosttyReleaseNotes.zig` must agree - file the `seat: mac` half if Swift changes.

## Validation criteria

- [ ] A Mac release and a Windows publish of the same version no longer touch the same file (or merge without conflict), proven by a fixture in `test/win32/` that writes both and merges.
- [ ] The Windows What's New for a version shows the Windows notes, not the Mac's, when both exist.
