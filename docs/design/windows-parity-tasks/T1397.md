# T1397 - resize-flicker has no coverage at 200% DPI or across a monitor change

## Summary

T1393 closed the non-modal whole-window resize paths (maximize, restore, snap, title-bar double-click) and proved them with the new 'window resize cause=.. sync=..' oracle - but only at this box's DPI (120) on a single monitor. A DPI change and a monitor move both resize every pane through the same layout pass, and neither is exercised by resize-flicker.ps1. Extend section D to drive a WM_DPICHANGED and a cross-monitor move where the harness can reach them, and say plainly in the script what it cannot.

## In plain terms

Moving a terminal window to a screen with a different zoom level, or dragging it
onto the other monitor, resizes every pane at once - the same kind of resize that
used to make the text blink to a blank background. The flicker test never tried
either move, so a regression there would have shipped unseen. Now it does both,
and says in the script what it still cannot reach.

## Goals

- [x] the flicker test changes the window's DPI (in place, and mid-drag) and checks every pane waited for a frame
- [x] the flicker test drags the window onto the second monitor and back, and maximizes it there
- [x] the script states plainly what a test cannot reach (a real OS-sent DPI change)

## Validation criteria

- [x] DPI change reaches the handler and resizes panes through a guarded pass - `test\win32\resize-flicker.ps1` D6a/D6b: `the DPI handler ran for every scale flip (4 of 4, 120 <-> 180 dpi)`, `a DPI change resized the panes (causes: dpi, ...)`, `every whole-window resize waits for a frame in every pane`, stale=0 (ALL PASS, 31 assertions, 2026-11-10)
- [x] cross-monitor drag lands on monitor 2 at Windows' suggested size, and maximize fills that monitor - D6b/D6c: `left=3880 width=1770` and `left=3831 width=3858, work area x=3840` (same run)
- [x] the debug hook's packed suggested size unpacks correctly - unit test `testSuggestedSize unpacks width and height and treats zero as keep` (Window.zig), win32 lane
- [x] what cannot be reached is written at D6 in the script: an OS-originated WM_DPICHANGED (refused cross-process; this box's monitors share one scale), its timing at the majority-area crossing, and the non-client re-measure
