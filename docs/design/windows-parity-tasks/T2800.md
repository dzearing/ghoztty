# T2800 - Live run on an idle box: the viewer contents card's compositor slide (T2764) must advance on every refresh at UI stalls of 0, 50 and 500 ms, and hand back to its window with no blank or doubled frame - a toc-slide-onscreen film adapted from bell-fade-onscreen.ps1, stepped arm (GHOZTTY_DEBUG_TOC_SLIDE_STEPPED) as control, stall via GHOZTTY_DEBUG_TOC_SLIDE_STALL_MS

## Summary

T2764 moved the narrow viewer's contents-card slide onto DirectComposition
(`viewer_toc_comp.zig`, declared once as `viewer_toc_layout.slidePlan`). Its
host-floor test proves the PATH (compositor=true, declared=2, failures=0, the
card window hidden mid-slide), but not what the screen shows: that needs the
real desktop (CopyFromScreen), which the loop's off-desktop harness cannot
reach. Write `test/win32/toc-slide-onscreen.ps1` from `bell-fade-onscreen.ps1`:
open a narrow viewer, toggle the contents card, sample the card's left edge
every refresh, with the UI thread held by `GHOZTTY_DEBUG_TOC_SLIDE_STALL_MS`
at 0/50/500 ms.

## Validation criteria

- [ ] the card's x advances on every sampled refresh across the 150 ms slide at all three stalls (compositor arm)
- [ ] the stepped arm (`GHOZTTY_DEBUG_TOC_SLIDE_STEPPED=1`) freezes for the stall at 50/500 ms - the control proving the film can score red
- [ ] the hand-back at the end of a slide in shows no blank or doubled frame (the window is up before the visual comes down)
- [ ] run on an idle box only - this is a real-desktop film, never sweep-run while the user is present
