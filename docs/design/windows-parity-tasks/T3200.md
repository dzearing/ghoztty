# T3200 - Single-window mode: undo of a workspace close brings it back on show (today a workspace close in single mode skips the undo window)

## Summary

T3184 closes single-mode workspaces with no undo (Window.close / closeTabByIndex skip close_undo.parkWindow for a managed workspace, because parking hides the shared HWND). Mac: undo of a close brings the workspace back on show (docs/reference/window-modes.md Closing). Needs a CloseUndo shape that parks a workspace controller (panes under the park host, no HWND) and restores it via App.showWorkspace.

## In plain terms

With "All in one window" on, closing a workspace by mistake could not be
taken back: Ctrl+Shift+Z did nothing, and its shell was gone at once. Now the
closed workspace waits for the undo time (5 seconds by default) with its shell
still running; pressing undo puts it straight back on show in the same window,
exactly as it was. Mac does the same.

## Goals

- [x] closing a workspace (on show or parked) leaves it waiting for an undo, while the window goes on to the next one at once
- [x] undo brings it back on show in the same window, same shell
- [x] when the undo runs out, the close happens for real
- [x] a closed workspace whose shell exits while it waits closes for real

## Validation criteria

- [x] Closing the workspace on show hands the window on and the closed one waits (seam `closed_for_undo=1`) - single-window-mode.ps1 L1
- [x] Ctrl+Shift+Z puts it back on show in the shared HWND, same shell (scrollback mark still there via +read), the other parked - L2
- [x] A parked workspace's close undoes onto show too - L3
- [x] The undo expiring closes it for real (seam 0, +read no longer reaches it, a later undo brings nothing back) - L4
- [x] Earlier close sections (C1-C4, incl. a parked workspace's last shell exiting) still pass with undo on by default - single-window-mode.ps1 ALL PASS 248 (acceptance-parallel run 20261117-060024)
- [ ] The "last shell exits while waiting" path (Window.removeTabSlot -> expireParkedWindow) is code-read only: no harness drives a shell exit inside a closed-for-undo workspace (covered by the same timer expiry K4 proves)
