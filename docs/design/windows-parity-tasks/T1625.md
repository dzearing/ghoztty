# T1625 - Run the resume-offset arms against a real POSIX agent, not the quiet-attach emulation

## Summary

T804 measured the `repaint_data` (0x15) labelling against a peer that does not
repaint after an attach - the case the opcode exists for - and found the
labelling inert until T804 fixed it. But the peer it measured against is an
EMULATION: `GHOSTTY_AGENT_QUIET_ATTACH=1` makes the Windows agent record an
attaching client's geometry and leave the child alone, so ConPTY stops
repainting behind the injection. That reproduces the property, not the platform.

The real article is a POSIX agent, where a quiet child answers `TIOCSWINSZ` with
silence for free and nothing about the attach is emulated. The Windows seat
cannot host one - this box may not start WSL, by standing user directive - so
this is the Mac seat's run: point a window at a POSIX `ghoztty-agent` with
`+new-remote-window`, kill and re-attach three times, and require
`requested == head` with `repaint_data` negotiated, then an overshoot with
`GHOSTTY_AGENT_SUPPRESS_CAPS=repaint_data`. Arms D and E of
`test\win32\session-resume-offset.ps1` are the shape to mirror.

## In plain terms

The check that proves a reconnecting terminal remembers its place was run
against a stand-in for a session on another machine, because this machine cannot
host the real thing. Run it against the real thing once, so the stand-in is
confirmed to stand for it.

## Goals

- [ ] The D/E pair runs against a genuine POSIX agent and comes out the same way.
- [ ] Any difference between the emulation and the real peer is recorded, or the
      harness note claiming they are equivalent is confirmed accurate.

## Validation criteria

- [ ] `requested == head` across three re-attaches to a POSIX agent with
      `repaint_data` negotiated.
- [ ] The same run with `GHOSTTY_AGENT_SUPPRESS_CAPS=repaint_data` overshoots
      and is clamped on every cycle after the first.
