# T1329 - The packaging guard can only be satisfied by Docker on this box, so the MSI half of release-artifacts.ps1 is permanently skipped

## Summary

test\win32\release-artifacts.ps1 section B needs the msitools-local Docker image to assert the FILEVERSION rule has one live definition, and Docker Desktop is deliberately kept down on this box. So the run reports ALL PASS (1 skipped) and the release-artifacts-packaging guard goes DUE and stays DUE - it is DUE right now for a build-msi.sh change. guard-due.ps1 stamp-ci exists as a hatch but has to be driven by hand, and the log records three occasions this month where the hatch meant 'red for a task in the queue' rather than 'cannot run here' (T1165). Make the Linux runner run the wixl-dependent assertions, where wixl is native, and have the green CI run satisfy the guard, so the check is performed rather than skipped.

## In plain terms

One check on the installer's version numbering could only run inside a Docker
container, and Docker is never started on this machine, so the check was
skipped on every run and nobody here ever saw its answer. It turns out the
check never needed Docker at all; it now runs every time.

## Goals

- [x] B1 (the FILEVERSION single-source assertion) runs on a Docker-less box
- [x] the green CI run satisfies the packaging guard (already true since T1236 - verified, not rebuilt)
- [x] the packaging stamp still cannot be earned by a run that proved nothing about wixl

## Findings (2026-10-24 re-verification)

- **Half the task was already done.** T1189 made the packaging row advisory and
  T1236 made the claim stamp it from fork-ci's green `windows-cross` run (which
  really compiles the MSI with native wixl). `guard-due.ps1 check -Guard
  release-artifacts-packaging` read `GUARD CURRENT ... stamped 2026-10-22 from
  CI run 39876234322`.
- **The premise of the other half was wrong.** B1 is not a wixl assertion:
  `build-msi.sh --print-file-version` prints and exits *before* the script looks
  for wixl/msiinfo. It needed bash, never Docker. Run through Git Bash with
  `TZ=UTC` it prints `26.10.24.7`, matching the UTC expectation.
- So nothing in `release-artifacts.ps1` ever compiled the MSI - the Docker run
  of B1 was not the compile proof its stamp comment claimed. The comment now
  says so, and names fork-ci as the compile proof.

## Fix

`test\win32\release-artifacts.ps1` B1 now runs through Git Bash (pinned to UTC,
the same reason the image route compared UTC), with the image as fallback;
SKIP only when neither exists. `-RequireDocker` keeps its meaning (image route
or FAIL), and the packaging stamp is still written locally only by that run -
a bash run of the same question is no more evidence about wixl, so it does not
vouch for the row (G11 of `test\win32\guard-due.ps1` still holds).
