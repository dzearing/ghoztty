# T3337 - Linux L8: session persistence - agent-hosted panes, restore and re-attach, systemd user autostart

## Summary

Port docs/reference/session-persistence.md. Agent autostart is a systemd --user unit (WSL needs [boot] systemd=true in /etc/wsl.conf), XDG autostart .desktop when systemd is off. The app<->agent wire protocol rules in docs/claude/sessions.md apply unchanged (HELLO capability detection, additive only).

**Split 2026-11-22 (one context could not hold all of L8).** This card is the
first slice: the GTK app hosts every new pane in the local agent (find or
spawn over the Mac's 0600 Unix socket), a user close ends a session and a
quit or crash leaves it running. The rest is its own cards: T3397 (relaunch
re-attaches; the layout manifest), T3398 (systemd --user / XDG autostart),
T3399 (+stash, +restore, +new-remote-window, handoff quit), T3400 (in-place
recovery when the agent dies under a running app).

## In plain terms

On Linux, closing or crashing the terminal used to kill every shell in it.
Now each pane's shell runs inside a small background helper (the same one the
Mac and Windows apps use), so a crash or a kill leaves the shells running and
`ghoztty +sessions` still lists them. Closing a pane yourself still ends it.
Getting those surviving shells back into windows on the next launch is the
follow-up card.

## Goals

- [x] the GTK app finds or starts `ghoztty-agent` and opens new panes in it

- [x] `session-persistence = false` keeps the plain pty
