# T1970 - Restarting the app on Windows almost always loses every session, though only the UI restarted and the agent should keep them

## In plain terms

Restarting Ghoztty should only restart the window. Your terminals live in
the background agent and should come straight back. On the user's Windows
machines they almost never do: after a restart, every pane comes back
empty.

## Summary

User report (2026-10-15): "on windows, when we restart the app, almost
always none of the sessions are reloaded, despite expecting that a reboot
shouldn't reset the agent if only the interface has changed. and, when they
reset, 1. the window sizes are all small and not restored, 2. the
environment variables aren't loaded so path isn't working. I have to open a
new pane for path to be loaded!!!!!" Symptoms 1 and 2 are T1971 and T1972.

On MAXIMUSHOME (this repo's box) restores are clean. The log for the
2026-10-14 23:31 and 2026-10-15 02:57 restarts shows
`session-restore: restored 2 window(s)`,
`attached 3 pane(s); 0 live agent session(s) unattached` and
`agent upgrade check: stale, but the agent is replacing itself without
losing any session (standing down)`, and the Sep 25 agents are still
alive. So the failure depends on the machine or the restart path. The most
likely machine is the user's no-GPU Windows 365 Cloud PC (dzearing1).

**Step 1 is evidence from a failing machine.** Ask the user (or their agent
on dzearing1) for `%LOCALAPPDATA%\ghoztty\ghoztty.log*` lines matching
`session-restore|agent upgrade check|relaunch|restart manager|agent.*(exit|died|replac|kill)`
around a failed restart, plus the `ghoztty-agent.exe` process start times
before and after a restart.

Suspects to rule in or out with that evidence:

- **The install kills the agent.** Restart Manager closes `ghoztty-agent.exe`
  because its image is in use. Every apply path (T1934 auto-apply,
  `update_apply`, the manual MSI) must sideline the agent image first, as
  `update_apply.sidelineName` intends. A user double-clicking the MSI
  sidelines nothing.
- **The agent restarts for a version skew it does not need to.** Check the
  HELLO/compat decision and the "replacing itself" handoff.
- **The relaunched app cannot find the live agent.** It runs from the
  msiexec/Restart Manager context, so a different `USERNAME` derivation or
  pipe name (`ipc_client.endpointPath`) would make it miss the agent.
- **The layout manifest is missing or rejected on that box**
  (`session-layout.json` age, or restore suppressed by the focus ping-pong
  mitigation).
- **Persistence is off there.**

## Validation criteria

- [ ] The cause is named with evidence from a machine where it fails.
- [ ] Acceptance (test desktop, dev install): N panes with scrollback
      markers, restarted via (a) Restart Ghoztty, (b) the T1934
      auto-apply, (c) a manual `msiexec /i` of a newer MSI, and (d) closing
      and relaunching the app. Every pane comes back attached to the SAME
      agent session id with its marker, and the agent pid is unchanged in
      (a), (b) and (d). A negative control that kills the agent fails it.
- [ ] Mac: check the same four paths on the mac seat, and file a
      `seat: mac` task if any of them loses sessions there.
