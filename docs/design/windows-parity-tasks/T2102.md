# T2102 - Stacked panes: the carousel slide - cards glide to their new slots when a strip comes forward, and each terminal resizes once, when the slide ends

## Summary

Mac slides on Core Animation so no terminal resizes mid-slide. Windows: animate the cards' visuals (DWM thumbnail / snapshot bitmap of each moving pane, or SetWindowPos of child HWNDs whose sizes do not change - pane_stack_layout keeps slot sizes equal so a moving card is not resized) and resize a ConPTY at most once per slide (count it from the size log in the acceptance). Ties to T2086 (a slide resizes each terminal once).

## In plain terms

When several panes share a row too narrow to show them all, the extra panes
tuck in as strips at the edge. Clicking one used to make the row jump to the
new arrangement in a single frame. Now the panes glide into their new places,
the way they do on Mac, and the programs inside them are not resized while
they move.

## Goals

- [x] cards on show glide to their new slots on Mac's curve (0.38 s, cubic-bezier 0.2/0.8/0.2/1) when a stack's run changes
- [x] a card that keeps its size is only moved: no terminal resize mid-slide
- [x] a card whose size changes holds its old size and resizes once, when the slide ends
- [x] a second change mid-slide starts from where the cards are on screen
- [x] Animation effects off / Remote Desktop: no slide (instant, as before)

## Validation criteria

- [x] the clicked pane passes through many intermediate positions (S1 of `test\win32\pane-stack-slide.ps1`: 47 positions over a stretched 2 s slide, flat; elevated likewise)
- [x] no pane window changes size more than once over the slide (S2: worst 1, a 1 px rounding change landing at 1935 ms of 2000 - the one end-of-slide resize)
- [x] the T2109 result holds at rest: clicked pane on show, focused, two on show (S3)
- [x] negative control: a 0 ms slide fails S1 (0 positions on the way)
- [x] pure logic unit-tested in `pane_stack_slide.zig` (curve, plan, size hold, mid-slide restart, resize-is-not-a-slide)
