# T756 - tab-strip.ps1's T204 close-click arm is intermittent: one run went red on a correct build, the next was ALL PASS

## In plain terms

One of the automated UI checks fails now and then on a build with nothing
wrong with it. A test that cries wolf is worse than no test: the next person
spends a context chasing a defect that is not there.

## Summary

OBSERVED 2026-08-11 during T528. Two back-to-back runs of
`test\win32\tab-strip.ps1` against the SAME binary:

```
run 1: FAIL  T204: a click at the close button's PAINTED center closes that tab (3 -> 3 tabs)
       1 FAILED / 63 passed
run 2: ALL PASS (64 assertions, 1 SKIPPED)
```

Nothing was rebuilt between them. T528's change to that area was a COLOR only
(`close_hover_color` now reads `pal.danger_ink`), and the arm is about a click
landing, so the two are unrelated - which is precisely why the flake matters:
it landed in the same run as a chrome change and had to be ruled out by hand.

Note the second run also reported `1 SKIPPED` where the first reported none, so
the two runs did not take the same path through the script; that difference is
probably the thread to pull.

Likely shape: the synthesized click races the tab's own layout/paint (T249's
ratchet re-fits widths asynchronously), so the "PAINTED center" the script
computed is stale by the time the click is posted. Fix by re-reading the
geometry immediately before the click and/or gating on a settled layout, not by
sleeping longer.

## Validation criteria

- [x] The arm's trigger is derived from geometry read at click time, or the
      script waits on an observable settled state rather than a fixed sleep.
      DONE: the click point is re-derived from the last tab's right edge read
      immediately before the click, and only once two consecutive captures
      agree on that edge (an observable settled run, not a longer sleep). A run
      that never falls still scores red instead of being clicked at anyway.
- [x] 10 consecutive runs of `tab-strip.ps1` on this box are ALL PASS.
      DONE: 10/10 `ALL PASS (78 assertions)`. Two earlier sweeps over the same
      build are the evidence that this took three fixes rather than one: the
      first was 10/10 on the T204 arm with 2 runs red on a DIFFERENT stale-
      geometry arm, the second 8/10 with one of those reds cascading into
      `1 -> 1 tabs`.
- [x] The arm still FAILS against a build with the close hit-rect deliberately
      broken (teeth check), so the de-flaking did not just weaken it.
      DONE: `close_left` in `Window.zig`'s strip click handler shifted +40px,
      rebuilt Debug, `tab-strip.ps1` -> `FAIL ... (3 -> 3 tabs; target=...
      still-open=...)`, exit 1. Patch reverted and rebuilt clean.
- [x] The flake's own mechanism is reproducible on demand, and the pre-T756 arm
      fails on it. DONE: `GHOZTTY_T756_PERTURB=1` adds a tab so the run re-fits
      between the pixel read and the click; with `GHOZTTY_T756_STALE=1` (the
      carried point, i.e. the old arm) the run FAILS, without it ALL PASS.
