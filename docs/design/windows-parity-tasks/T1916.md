# T1916 - The viewer nav bar stays a solid band on a glass pane; Mac's chrome bar is a material the sheet shows through

## Summary

Mac WebChromeBar uses glassEffect / ultraThinMaterial, so on a glass pane the sheet reads through the nav bar. Windows ViewerNavBar paints opaque bar_rgb, and cardColors reports it as an opaque head band. Follow T1884's rearrange-header treatment (pane_elevation.glassHeadMix, head_glass on the card) so the bar is the chrome colour as a material over the sheet. Follow-up of T1885.

## In plain terms

With glass panes on, a markdown or diff viewer's page already shows the
window's colour gradient through it, but the address bar across the top sat on
a solid grey strip. Now that strip is a frosted layer too: mostly the bar's own
colour, with the gradient's light still showing through, the way the Mac bar
looks and the way the pane header in rearrange mode already does here.

## Goals

- [x] on a glass pane the nav bar paints the chrome colour as a material over its slice of the desk
- [x] the card's rounded top corners round the bar are drawn the same way, so they meet it without a seam
- [x] a new desk slice (a divider drag, a resize) repaints the bar, not only the page under it
- [x] off glass the bar is the solid band it was

## Validation criteria

- [x] On glass the bar's top row is `glassHeadMix` of the desk at each pixel (left edge, middle, right edge) and is not the solid band colour - live host-floor test, win32 lane (`-Filter 'host floor: a real controller'`), photographed through the bar's WM_PRINTCLIENT
- [x] `cardColors().head_glass` is true on glass and false off it - same test
- [x] Off glass the bar's top row is the solid `bar_rgb` again - same test
- [x] `glassHeadRegion` equals `glassHeadMix` pixel for pixel and varies across the desk - pane_elevation unit test (none lane)
- [ ] NOT RUN: the material composited on a real on-screen window - on-screen runs are off while the user is present; tracked with the rest of the glass on-screen check in T1915
