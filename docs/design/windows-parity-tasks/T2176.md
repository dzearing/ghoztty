# T2176 - 39 acceptance scripts redirect ghoztty stderr under ErrorActionPreference Stop, so the CLI's 'Waiting for Ghoztty to answer' note kills the run with no verdict

## Summary

Found in T1215: under $ErrorActionPreference='Stop', PowerShell 5.1 makes any stderr line from a native call with 2>$null or 2>&1 terminating, and the CLI prints 'Waiting for Ghoztty to answer ...' on stderr whenever the app is slow - on its way to succeeding. soak.ps1's 30-minute run died on it at teardown after every assertion passed, skipping its cleanup. soak.ps1 now wraps those calls in Invoke-Tolerant (with a SelfTest negative control). 39 scripts in test/win32 have the same shape (grep: EAP Stop + '& $exe ... 2>$null|2>&1'; worst: pane-hwnd-reap, menu-bar, font-inherit, tab-strip, scrollback-narrow, resize-flicker). Move Invoke-Tolerant to a shared lib and either convert the sites or add a harness-floor audit that flags an unwrapped redirected ghoztty call under Stop.
