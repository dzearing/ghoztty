# T3895 - Does an idle Ghoztty's private memory keep climbing past the first hour (T2669 saw +10 MB in hour one, flat in the next 30 min), and which OS thread pool starts its ~15 new threads an hour?

## Summary

T2669's one-hour idle sample (scripts\idle-thread-growth.ps1, release 0f48474fa3, RTX 4090) saw private bytes 204.6 -> 214.8 MB in the terminal span (slope 7 MB/h, a +4 MB step near minute 20, then ~2.4 MB/h) and FLAT (-0.7 MB/h) over the following 30 min viewer span. Thread creation was 15/h then 12/h, all ntdll start addresses (OS thread-pool workers), which at T2644's 64 KB each bounds the NVIDIA driver cost at ~1 MB/h, so the hour-one rise is not threads. Run the sampler for 8 h (-Minutes 480 -ViewerMinutes 0) to tell bounded fill from a slow leak; if it climbs, attribute it (perf-baseline committed-memory split) and name the pool behind the ntdll workers (cdb bp on ntdll!TppWorkerThread with stacks), then decide whether a persistent worker is the fix.
