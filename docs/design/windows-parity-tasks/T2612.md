# T2612 - Mac half of +agent-setup (T2605): bake GHOZTTY_AGENT_SETUP into every Mac pane's environment and wire +agent-setup --install=<agent> to the Swift AgentIntegrationService (it prints 'not wired in this build yet' on macOS today)

## Summary

Platform symmetry for a P0 user report: the Windows half shipped in T2605.

`ghoztty +agent-setup` is in the shared CLI (`src/cli/agent_setup.zig`), so
the pointer README and `--skill[=<file>]` already work on macOS (they print
the bundled bytes from `src/apprt/win32/assets/ghoztty/skills/ghoztty`,
byte-identical to `macos/Resources/Ghoztty/skills`, without the Windows
rewrite). Two halves are left for the Mac seat:

1. **Pane env**: Windows bakes `GHOZTTY_AGENT_SETUP=ghoztty +agent-setup`
   through the surface config `env` seam (`src/apprt/win32/Surface.zig`, next
   to `GHOZTTY_PANE_ID`). Mac should inject the same pair through
   `surface_cfg.environmentVariables`, where it bakes `GHOZTTY_PANE_ID`, so it
   reaches agent-backed and relaunched panes too. Constant names:
   `agent_setup.pane_env` / `pane_env_value`.
2. **`--install=<claude|copilot>`**: on macOS `install()` in
   `src/cli/agent_setup.zig` prints `--install is not wired in this build yet`
   and exits 1. Wire it to the same install the Swift "Set Up Agent
   Integrations..." flow performs (`AgentIntegrationService`): either an IPC
   action the Swift app answers, or a Zig install over `$HOME` with the Mac
   wording. Same outcomes and exit codes as Windows (installed / already up to
   date / upgraded at 0; not installed, plugin present, failed at 1).

## Validation criteria

- [ ] a Mac pane's `env` shows `GHOZTTY_AGENT_SETUP=ghoztty +agent-setup` (agent-backed and exec panes)
- [ ] `ghoztty +agent-setup --install=claude` into a sandbox home installs the skill + hooks, second run reads "already up to date"
- [ ] `+agent-setup --skill` on Mac prints the Mac wording of SKILL.md
