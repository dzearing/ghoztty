# T810 - The Activity Monitor and Restore All still dial their own per-machine connections instead of borrowing the pool's

## Summary

T461 made one warm connection per machine the rule for the chooser's roster and Kill, but two other remote surfaces still open their own: ActivityMonitor.dialWorker dials the relay per panel (falling back to borrowing a WINDOW's connection via activity_borrow), and RestoreAllRelay gives every rebuilt window its own dial. Both pay the upgrade+auth cost the pool removes, and neither can host a subscription. Convert them onto App.machine_pool leases; the win32 detail to preserve is that a rebuilt remote WINDOW must still own its transport (it frees it on close), so Restore All's per-window dial is not simply a pool borrow.

## In plain terms

When you press "Restore All" on another machine in the machine chooser, Ghoztty
used to open a brand new connection to that machine just to ask it which windows
it has — even though the chooser you pressed the button in was already holding a
connection to that exact machine open. On a real network that is a whole extra
round trip of handshaking before the first window can come back. Now it asks
over the link that is already there, so the windows arrive sooner. Each window
that comes back still gets its own connection, because closing a window has to
be able to hang up without taking its neighbours down with it.

And if your relay session has expired by the time you press it, you now get told
that — "Session expired — sign in again above" — instead of being told the
machine had nothing saved.

## Goals

- [x] the layout pull rides the chooser's already-warm pooled connection
- [x] a machine the pool has nothing for still dials its own pull, unchanged
- [x] per-window transports stay per-window (T336's ownership rule)
- [x] a restore where every window's dial failed says WHY instead of reading as
      an empty machine
