# T2069 - agent-stamp-inputs reads a 13-input cache manifest instead of the agent build's: Find-Manifest takes the newest .zig-cache\h file that merely names remote\agent\main.zig (B3/C1 red)

## Summary

Found by T1068 (2026-10-17): editing `src/apprt/win32/agent_upgrade.zig` made the `agent-stamp-inputs` guard due, and the harness is red both beside other scripts and alone: `B3 the manifest is a real agent build (hundreds of inputs) inputs: 13`, plus `C1 src/os/main.zig / src/terminal/main.zig / src/apprt/win32/job_spawn.zig is a compiled input of the agent`. Nothing in T1068 touches the agent build.

`scripts/agent-stamp-inputs.ps1` `Find-Manifest` takes the NEWEST `.zig-cache\h\*.txt` that contains the string `remote/agent\main.zig`. Some other cached step now also names that path in a small manifest (13 inputs) and is written after the agent compile, so it wins. Its last green stamp is 2026-09-16 (c8b87873e).

Fix: choose the manifest by content, not by recency. Either take the largest matching manifest, or the one whose input count passes the B3 bar. Better, have `-Build` record which manifest the agent compile step wrote. Then re-run the harness green and stamp it.

Also seen in the same sweep: the first parallel attempt threw `'ghoztty-agent.exe' is held open by a running process; moved it aside as 'ghoztty-agent.exe.old-1'`. That is a parallel-run collision on zig-out, so check whether the harness should be `@parallel-unsafe`.
