# T1714 - The web feedback composer grows with its text but never shrinks, and an emptied box still holds a newline

## In plain terms

When you type several lines into a viewer's feedback box, the box grows. On Windows it then stayed that tall after you deleted lines, or after you made the window wider again, until you closed and reopened it. Clearing the box also left an invisible line break in the text you were about to send. After this fix the box shrinks back as soon as the text gets shorter, and a cleared box is really empty.

## Summary

Found by T1706 re-pointing viewer-feedback.ps1 onto the web composer. `composer.js` `lineCount()` measured `el.scrollHeight` in place. That value is never less than the box's own height, and the host sizes the box from the previous count, so the count could go up but never down. And `walk()` read a trailing `<br>` after text as a real newline: `a\nb<br>` is what a deleted last line leaves, and a lone `<br>` is what Ctrl+A, Delete leaves. The buffer then held a break the user could not see.

Fix (`src/viewer/composer.js`):

- `lineCount()` sets the box to `height: auto` for the read, takes `scrollHeight`, then restores the height and the scroll position. It all happens in one task, so nothing paints in between.
- `walk()` treats the box's last node, when it is a `<br>`, as the caret placeholder, always. A trailing `<br>` at the end of a block never starts a line of its own. An Enter at the end (`a<br><br>`, or `a\n` plus `<br>`) still reads as `a\n`, exactly as before.

The test driver's read (`$script:CdpComposerRead` in `test\win32\lib\WebViewCdp.ps1`) mirrors the rule.

No Mac half is owed: `composer.js` is the page behind the win32 composer only (embedded by `viewer_feedback_page.zig`). The Mac composer is a native text view, and a native text view shrinks by itself.

Not in scope: T1705. That is the text-node form of the placeholder (`"hello\n\n"`), which is a different shape.

## Goals

- [x] The pill gives its height back when lines are deleted
- [x] The pill gives its height back when the pane is widened again
- [x] A box emptied with Ctrl+A, Delete reads as empty, not as a newline

## Validation criteria

- [x] `test\win32\viewer-feedback.ps1` arm D: six Backspaces take `three` and its line away. The page reads `one\ntwo` and the band shrinks from 129 to 106 px (with the page following it). ALL PASS (107) on 2026-09-23.
- [x] Arm I: after narrowing, the pane widens back and the band returns to its wrapped height. Ctrl+A, Delete reads back `''`.
- [x] Negative control: runs 2 and 3, on the page before this fix, went red on exactly these arms. The box read `"one\ntwo<br>"`, with scrollHeight 56 px (3 lines) for every document shape, including an empty one. That is the in-place floor this fix removes.
- [x] `test\win32\viewer-composer.ps1`: ALL PASS (41). Its Enter/undo/reopen round trip is unchanged by the new placeholder rule.
