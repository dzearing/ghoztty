# T2818 - On-screen oracle for T2777: in the composition pane tree a WGC film of a fold or an unfold contains the strip face (the T2561 blind spot) - score the folding/opening card in comp-glide-hold-onscreen.ps1's tree arm instead of reporting it unscored, GHOZTTY_FACE_COMP=0 as its negative control

## Summary

T2777 moved a folding (or opening) card's face into the window's own composition tree when `GHOZTTY_COMP_PANE_TREE` is on, but `scripts\comp-glide-hold-onscreen.ps1`'s TREE arm still treated both faces as the T2561 blind spot - reported, never scored - so the claim "a window capture of a fold now contains the face" had only off-screen evidence. The TREE arm now scores both faces from the WGC film: **tree.18** the folding card is on film at 2+ places and its left edge travels at least half its width toward the strip before it leaves the film; **tree.19** the opening card is on film at 2+ places before it settles. `-NoFaceComp` sets `GHOZTTY_FACE_COMP=0` (faces back on their popups) and both go red. The tear check (.8) no longer judges a fading card's faintest frame (first frame of an opening card, last of a folding one): with the face on film from content_alpha's first step, that frame's block sits on the colour threshold along its edge (green f14 right 159..168, 1 run in 3).

The ON/OFF arms still cannot see the popup face; that half stays T2561.

## In plain terms

When a pane folds into its side strip, or opens out of one, the card that
slides is now checked in a real screen recording of the window, not just from
the app's own log. The test proves the sliding card is actually visible the
whole way in the new drawing mode, and proves the check would catch it if the
card went missing.

## Goals

- [x] the tree arm scores the opening card's face from the film
- [x] `-NoFaceComp` negative control turns both red
