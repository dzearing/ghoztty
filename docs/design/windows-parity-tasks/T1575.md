# T1575 - A test block outside src/build/ that no test root reaches is still invisible

## In plain terms

Some checks in this codebase may never run. A test written next to a file that
nothing else pulls in is compiled into no test binary at all, so it reads as
coverage in review and can never go red. We just closed that hole for one
directory; this is the question of whether it is open anywhere else.

## Goals

- [x] Measure: how many files under `src/` carry `test` blocks that no test
      root reaches - zero missing (789 test-bearing modules, 736 in a lane, 53
      exempt with reasons)
- [x] If the answer is not zero, wire each one in (or record why it cannot be)
      - nothing left to wire; T1237 wired the one it found (`os\desktop.zig`)
- [x] Keep the answer at zero with a standing check, the way
      `src/build/BuildTestSweep.zig` does for its directory -
      `test\win32\test-reach-audit.ps1` section D, a daily harness-floor member

## Resolution (2026-11-20): already fixed by T1237, commit b0fe38e5e

T1237 (2026-10-23) built exactly this check, five weeks after this card was
filed, without naming it: `test\win32\test-reach-audit.ps1` section D reads the
test names compiled into the win32, none and agent test binaries (the compiler
is the oracle, not a model of Zig's reachability rules) and requires every
`src\**\*.zig` with a test block to appear in some lane's binary or under a
written exemption in `test\win32\lib\TestReachAudit.ps1`. An exemption a lane
does run is red too, and section C plants unreferenced test files under
`src\apprt\win32\`, `src\os\` and `src\remote\agent\` and requires the sweep to
name them. It runs daily as a `harness-floor` member.

Why it is the compiled binary and not an import graph: this turn's own textual
`@import` sweep (from `src/main.zig`, `src/agent_main.zig`,
`src/build/build_test.zig`, `src/lib_vt.zig`) reached 1058 of 1116 files and
named only 2 orphans, but an import that is never referenced pulls in no tests
(T1177 measured this on `startup_error.zig`), so a text graph overstates
coverage. The 2 files it named, `comp_spike_main.zig` and
`remote_test_client_main.zig`, are exe roots that the audit already exempts by
name with a reason.

## Summary

T736 made the src/build/ aggregator enforced: BuildTestSweep walks that directory and fails the test step on a test block no step imports. The same dead-coverage shape is possible anywhere else a file is not reachable from a test root - the main test binary roots at src/main.zig, the agent lane at src/agent_main.zig, and a module nothing imports carries assertions that read as coverage and cannot fail. Worth measuring before building: sweep src/ for files with top-level test blocks that no root reaches, and see whether the answer is zero (in which case this becomes a standing check like BuildTestSweep) or a list (in which case it is also a batch of work).
