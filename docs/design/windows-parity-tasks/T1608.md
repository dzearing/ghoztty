# T1608 - Nothing proves on-box that the machine chooser reports an unreachable machine during a wedge instead of spinning

## Summary

T1589 fixed the decision (a wedged link no longer carries the chooser's requests) and the none lane proves the policy, but the user-visible half - opening the chooser during a wedge and getting an answer rather than a spinner - has no on-box oracle. agent-recovery.ps1 already suspends the agent and waits for the link to go down (section K), so the wedge is already built; what is missing is a section that drives the chooser in that state and asserts it resolves.

## In plain terms

When the background helper that keeps your sessions alive stops answering, the
machine list should tell you right away that this machine can't be reached,
not sit on a loading spinner. An earlier fix made it do that, but nothing ever
opened the machine list during such a stall to check. Now a test does: it
freezes the helper, opens the list, and requires an answer within a few
seconds - and then, with the helper running again, requires the same list to
load normally.

## Goals

- [x] An on-box test opens the machine chooser while the local agent is wedged
      and requires the session roster to reach a verdict quickly
- [x] The verdict is "unreachable", not a roster read from somewhere else
- [x] A positive control: the same chooser loads the roster once the wedge ends
- [x] Proven to have teeth against the pre-T1589 gate
