# T2194 - A second click on the update balloon while 'Install and Restart?' is open stacks a second dialog on top of the first

## Summary

offerUpdate (App.zig) never checks update_prompt_open, so a WM_APP_TRAY balloon click dispatched inside ConfirmDialog's nested pump re-enters it and opens dialog B over dialog A. Pressing Install in B arms the applier and quits; A then unwinds as a cancel and logs 'user deferred' after the arm. Observed by T1242's harness (an accidental two-click run). Fix: when update_prompt_open, bring the open dialog forward instead of opening another; assert it in test\win32\update-consent.ps1 (two posted clicks -> exactly one GhozttyConfirmDialog).
