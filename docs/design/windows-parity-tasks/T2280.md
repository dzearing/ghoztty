# T2280 - Windows sidebar still has trash mode and a needs-input question badge; Mac removed both - a hovered row offers stash/restore and an ordinary confirmed, undoable close (x) instead (Mac dc2bbab6b, 2924ea5cc)

## Summary

Mac dc2bbab6b: hovering an expanded row offers -/restore and x; x is the ordinary confirmed, undoable close. Trash mode (header button, red unconfirmed kill, Escape to leave, killPane) is REMOVED. 2924ea5cc: the question state is gone from the sidebar entirely - row badge, tile rim, window header badge and the pulse ring - because it did not reach the sidebar reliably and was wrong as often as right. Windows has T1845 trash mode (PaneSidebar tool_trash, App.leaveSidebarTrash, CloseUndo quick-kill) and the question chip; remove them and add the hover close/stash. The CloseUndo trash path goes with it.

## In plain terms

The pane list down the left of a Windows window had a "trash mode": a
button that turned every row into a red kill switch with no confirmation
and no way back, plus a little "question" badge that was meant to say a
pane was waiting for an answer but was wrong as often as right. The Mac
version dropped both. Now, as on the Mac, pointing at a pane's row shows
two small buttons at its end - put it away (or bring it back), and close
it. Close asks nothing, but it can be undone like any other close. The
question badge is simply gone.

## Goals

- [x] Trash mode is gone: header button, red caption, red row wash, tile corner x, Escape handling, the CloseUndo kill path
- [x] A hovered row of this window offers stash/restore, then an x that closes the pane with no confirmation, undoably
- [x] The question state is gone from the sidebar: row chip, rail tile disc, window header badge, breathing ring
- [x] The all-windows toggle sits alone at the header's trailing edge

## Decisions taken

- **The x closes without asking, undoably** (Mac 345be6b02, per the
  2026-10-26 intake note): `Window.paneSidebarCloseNow` is `closeSplitPane`
  - no running-process confirm, no remote Disconnect prompt - and the close
  is parked for undo like any other, the sessions ending (CLOSE, never
  detach) when the undo expires. A window's last pane parks the window.
- **Another window's row (all-windows scope) offers no buttons yet.** Mac
  HEAD gives it an x alone, but that close must take no focus, and
  `closeSplitPane` hands focus to the next pane - which would raise that
  other window. T2298 owns the foreign x together with the window and
  project x and the no-focus close; until then the row is Mac's dc2bbab6b
  shape (foreign rows had no buttons). The foreign stash button Windows had
  is gone too: Mac never offered one.
- **Right-click Close Pane stays the interactive close** here; T2298 moves
  it to the same unconfirmed close as the x.
