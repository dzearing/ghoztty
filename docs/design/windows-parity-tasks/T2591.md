# T2591 - Windows has no keyboard shortcut guide: Mac's searchable shortcuts window (Help menu, Cmd+/, palette) lists the live config's bindings with plain names, custom badges, key search, click-to-run and a printable cheat sheet

## Summary

Mac 1b7ebbcc8 (2026-10-31) added a keyboard shortcut guide: a searchable window of the EFFECTIVE keybindings (defaults merged with the live config's overrides and unbinds, via the new shared ghostty_config_keybinds_json in src/config/keybind_list.zig and ghostty_input_action_keys), curated plain-language names/descriptions/categories per action tag (with a test that fails when an action has no curated entry), CUSTOM/GLOBAL/TABLE/BUILT-IN badges, families collapsed (Ctrl+1..8), key-combo search in any modifier order, keyboard navigation, click-to-run for safe actions, a printable cheat sheet, and live reload on config change. Opened by Help > Keyboard Shortcuts, the new app-scoped show_keyboard_shortcuts action (Mac default Cmd+/), or the command palette ('Show Keyboard Shortcuts'). Windows needs the native equivalent: handle the show_keyboard_shortcuts apprt action in the win32 frontend, a Windows default chord (Ctrl+/ unless taken; record the choice), a window built to the win32 design system, the same curation table shared or ported, and the palette entry (comes free from src/input/command.zig after the merge). Spec: docs/reference/keyboard-shortcuts.md on origin/main. Needs T2490 first (the shared core arrives with the merge).

## In plain terms

On a Mac you can open a window that lists every keyboard shortcut Ghoztty has, in plain words, searchable by name or by key, with your own changes marked. Windows had no such window, so the only way to learn a shortcut was to spot it in a menu or read the config. Now Help > Keyboard Shortcuts, Ctrl+Shift+/ or the command palette opens the same guide on Windows, built from your real settings.

## Goals

- [x] A guide window built from the live config, compared against the defaults (CUSTOM, unbound-in-your-config, GLOBAL, TABLE, BUILT-IN)
- [x] Plain-language names for every action, enforced at compile time (exhaustive switch over the action list)
- [x] Search by words or by key combo in any modifier order; categories with live counts; Show unbound actions (remembered)
- [x] Keyboard: Up/Down select while typing, Enter runs, Esc clears the search, then the selection, then closes
- [x] Run a safe action in the terminal window it was opened from; destructive ones are never offered
- [x] Printable cheat sheet and Open Config File
- [x] Opened by Help > Keyboard Shortcuts, Ctrl+Shift+/ (default) and the palette's Show Keyboard Shortcuts
- [x] Rebuilt live when the config reloads

## Decisions recorded (mechanism, not filed)

- **Chord: Ctrl+Shift+/.** Mac's Cmd+/ carried the way the Windows defaults carry Cmd chords here (Cmd -> Ctrl+Shift, as stash_pane and toggle_pane_sidebar do). Plain Ctrl+/ is NOT taken: it is the ^_ undo every readline/emacs user presses, and the plain-ctrl mirror list in Config.zig deliberately leaves shell keys alone.
- **Native GDI window, not WebView2**, following WhatsNewWindow: one per process, reused; design-system metrics live in the pure `shortcut_guide_layout.zig`, asserted at 1.0/1.25/1.5/2.0.
- **The search field is painted, not an EDIT child**, so the window routes every key itself (Mac does the same with a local key monitor).
- **Families also collapse rows with several bindings** when they share the whole modifier list: Windows binds each tab twice (Ctrl+N and Alt+N), which Mac never does, and without this Go to Tab was eight rows.
- **Rows draw up to three bindings, then "+N"**; every binding is in the cheat sheet.
- **Cheat sheet = an HTML page that opens its own print dialog** in the default browser (Save as PDF there), written to %TEMP%.
