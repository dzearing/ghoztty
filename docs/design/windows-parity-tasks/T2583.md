# T2583 - Surgical config-file writer and store for the Settings window: one edit per action, comments/includes/CRLF/BOM survive byte for byte (Mac 92103f39d)

## Summary

Mac 92103f39d adds ConfigFileText.swift (pure text edits: set rewrites the LAST line for a key in place; reset removes every line incl. the bare flag form; setList keeps the longest in-order matching run; setKeyed for keybind-by-trigger / palette-by-index / env-by-name) and ConfigFileStore.swift (every write re-reads the file first; undo only if the file still holds what Settings wrote; validate the new lines with Ghostty's own parser on a scratch config before writing; backups before the first change per app session, newest 10 kept; write through symlinks; atomic; refuse non-UTF-8), plus src/config/schema_json.zig + ghostty_config_schema_json (shared core, arrives with the T2490 merge). Windows: port the writer and store to Zig as pure logic with none-lane unit tests mirroring ConfigFileTextTests/ConfigFileStoreTests (401 lines of cases), backups under %LOCALAPPDATA%, the schema read straight from schema_json.zig (no C API needed). Must write the dev build's own file (dep). Mac reference: docs/reference/settings.md 'Rules' and 'Repeatable keys'.

## In plain terms

On the Mac, Settings changes one line of your config file per change and leaves the rest of the file alone. That means your comments, includes, line endings and odd formatting all stay. Windows has no Settings window yet, and this is the piece underneath it: the code that reads and rewrites the config file that carefully. Nobody sees it on its own. The Settings window (T2584) is what they will see, and it can't safely write anything without this.

## Goals

- [x] `ConfigFileText.zig`: a pure text editor over the config file: set / remove / setList / setKeyed / add, with every untouched byte kept
- [x] `ConfigFileStore.zig`: reads the file again before every write, writes through symlinks, writes atomically, backs up once per session (newest 10 kept), refuses non-UTF-8 files, and restores from a backup
- [x] Both covered by none-lane unit tests that mirror Mac's ConfigFileTextTests / ConfigFileStoreTests
- [x] The scope this port left out (undo only if unchanged, parsing the new line on a scratch config first) filed as T2664; T2584 now depends on it

## Validation criteria

- [x] Unit tests for the text editor and the store pass: `zig test src\apprt\win32\ConfigFileStore.zig` gives 65 passed, 1 skipped (the skip is managed_file's posix-only symlink case), 0 failed. Real NTFS symlink cases are included.
- [x] Wired into the none lane via `src/apprt/unit_tests.zig`. `floor-lane.ps1 -Lane all`: lib, none, win32 and agent all PASS (2026-11-03).
- [x] CRLF, BOM, mixed line endings and a missing trailing newline survive edits byte for byte (`ConfigFileText: CRLF files stay CRLF` / `mixed endings` / `BOM is preserved`; `ConfigFileStore: CRLF and BOM survive a store write byte for byte`).
- [x] A failed edit writes nothing and makes no backup (`ConfigFileStore: an invalid value is refused before anything is written`, `refuses non-UTF-8 files and leaves them alone`).
