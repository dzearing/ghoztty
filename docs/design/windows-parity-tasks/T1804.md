# T1804 - Command palette has no way to restart Ghoztty or its background agent

## In plain terms

There is no menu or palette command to restart Ghoztty. Restarting the app,
or the background process that keeps sessions alive, currently means killing
processes by hand. Add palette commands that do it safely, and say plainly
what happens to your open terminals.

## Goals

- [x] "Restart Ghoztty" in the palette and the File menu: relaunches the app, and every pane comes back attached to the same running session
- [x] "Restart Ghoztty and Background Sessions": asks first, says how many sessions end, Cancel is the default
- [x] Only this build's background process is ever stopped; any other copy is left alone
- [x] The relaunched app says it restarted, and whether the sessions kept running
- [x] Mac task T1805 carries the exact names and wording to match

## Summary

User report (2026-10-10): "there is no command in the pallete to restart
ghoztty (and the agent process)". Verified: neither platform has one. On Mac,
the only restart flow is the forced-upgrade alert
(`macos/Sources/Features/Remote/LocalAgentManager.swift` `makeUpgradeAlert`).
On Windows, the only restart flows are the update path and the agent-restart
dialog (T625). The Mac half is T1805. Both land as the same commands with the
same names and wording.

Two commands, because they cost the user very different things:

1. **Restart Ghoztty.** Relaunch the app only. With session persistence on,
   every pane re-attaches to its still-running agent session, and the windows
   come back through the existing session-layout restore. Nothing is lost, so
   no confirmation is needed beyond a single "restarting" cue. With
   persistence off, confirm first, because the shells will die. Use the
   relaunch pattern the updater already has (wait for the old process to
   exit, then start the new one). The new process must not take the
   foreground while the user is in another app (T1795/T1797). Relaunching
   from the palette is a deliberate act, so focusing the restored windows is
   right; that is the one exception.
2. **Restart Ghoztty and background sessions.** Also restart
   `ghoztty-agent`. That ends every live session, so reuse the wording and
   safety of the mandatory-update alert: name the session count, make the
   safe choice the default, and never let Enter destroy work.

Rules that bind the implementation:

- Stop the agent by **ExecutablePath**, never by image name. The installed
  release's agent owns the user's live sessions, and a debug build must never
  touch it (CLAUDE.md non-negotiables; `docs/claude/build.md` recipe).
- The agent restart goes through the app<->agent protocol as a graceful
  shutdown request if one exists (check the HELLO capabilities). An older
  agent without it falls back to process termination of its own executable
  path (`docs/claude/sessions.md` compatibility contract).
- The CLI surface stays symmetric. If a `+restart` verb is added, it lands
  on both platforms with the same name and flags, or it is not added.

## Known limits

- The relaunch starts the app with no arguments, as the updater's does. A
  window opened with `-e <cmd>` comes back through the saved layout, not by
  re-running the command line.
- The protocol has no graceful agent shutdown, so the background-sessions
  restart stops the agent by process termination, after the identity check.
