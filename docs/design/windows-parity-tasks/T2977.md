# T2977 - PA-R11: an unchanged frame is re-presented through two full-frame GPU copies on the composition path, up to twice a second per pane

## Summary

PA-R11 (audit-1, T2959). generic.zig:1907 calls presentLastTarget when !needs_redraw; OpenGL.zig:1558-1566 returns early only on the window-presenter path (T2615), so the composition path replays BlitFramebuffer target->interop texture (OpenGL.zig:1397), CopyResource to the back buffer (gl_comp_present.zig:839/844) and Present(1,0) (:851), although a flip-model chain keeps its last frame on screen. The comment's reason (apprt swapping buffers) is SwapBuffers-only. Measured busy gpu_engine_pct is only 1.0-1.6% on a 4090; matters on integrated GPUs and many panes. Fix: early-return on the composition path once a frame has been presented (signalFrameDrawn must still fire; resize-wait and planted-frame cases keep presenting). Longer term render the final pass into the interop FBO directly. Risk low for the early return.

- [ ] idle with 10 panes: presents per second per pane fall to ~0 (renderer trace) and resize-wait/frame-lab harnesses stay green
- [ ] perf-baseline.ps1 -Phase busy gpu_engine_pct not worse
