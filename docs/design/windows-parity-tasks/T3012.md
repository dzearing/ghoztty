# T3012 - PA-M12: Window.onDestroy and Window.deinit are drifted twins - onDestroy (the +close path) never stops the composition drag thread or cancels the rename, banner and machine-chooser dialogs (Window.zig:2476)

## Summary

PA-M12 (audit-1, T2961). Window.deinit (src/apprt/win32/Window.zig:2476-2484) calls compDragThreadStop and cancels rename_dialog, banner_dialog and machine_chooser; onDestroy (:21927-22015) does neither (it destroys sidebar and grab_handle, which deinit does not). Unverified: whether those dialogs free their own state when their owner HWND is destroyed (a lead, not a proven leak). Fix: one shared teardown function both paths call, plus a test that closes a window by +close with each dialog open. Risk low. Baseline: docs/design/perf-audit/baseline-1.json (T2958); findings: docs/design/perf-audit/audit-1/M-findings.md.

## Validation criteria

- [ ] closing a window via +close with each dialog open leaves no dialog HWND and no growth in private_mb/USER objects (measured)
- [ ] a single teardown function is the only place those resources are released
