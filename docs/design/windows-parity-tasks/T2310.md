# T2310 - Each new Windows split comes out a shade lighter than its parent; Mac now gives every pane in a window the same glass - a split inherits the parent's --color tint unchanged, or none (Mac 157b08c48)

## Summary

Mac 157b08c48 removed BaseTerminalController.shiftedTint from newSplit: splits used to lighten 5% per generation 'for depth', which compounded so each new pane came out brighter. Now a split inherits a --color tint unchanged, or none (ref: main docs/reference/pane-style.md 'Every pane in a window is the same glass'). Windows still carries the shift: Window.zig ~10309 (Mac newSplit parity comment) and color_math.zig shiftedTint (+ its two unit tests, which go with it). Remove the shift so a split's tint equals its parent's; keep unit coverage that a split inherits the exact tint.

## In plain terms

On Windows, every time you split a pane the new one came out slightly lighter
than the one it came from, and splitting again made it lighter still. The Mac
stopped doing that: every pane in a window now has the same background. After
this change a split on Windows keeps exactly the colour of the pane it came
from, and a pane you never coloured makes splits you never coloured.

## Goals

- [x] A split of a `--color` pane has exactly the parent's tint (and the same readable text colours)
- [x] A split of an uncoloured pane stays uncoloured
- [x] The old 5%-lighter shift is gone from the code, with unit coverage that a split inherits the exact tint
