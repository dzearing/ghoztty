# T3155 - A shell picked in Settings still asks before closing a just-opened tab on Windows: command = pwsh counts as an explicit command, so Surface.fresh_default_shell is false for every pane of a user who chose a shell (Mac's agent-backed rule treats a configured command as the default shell)

## Summary

Found in T3133. src/Surface.zig init sets fresh_default_shell for an agent-backed pane as `session_id == null and !(command != null and (wait-after-command or (local_shell_integration and command_explicit)))` (the T3138 merge adaptation). The Windows Settings 'Shell' row (settings_pages.zig ~295) writes `command = <shell>` to the config, which `Config.finalize` records as `_command-explicit = true`, so for any user who picked a shell in Settings no pane is ever 'fresh' and the T3133 rule (close a just-opened, untyped shell without asking) never applies. On Mac the agent-backed rule ignores a configured command unless wait-after-command is set, so a configured shell is still the default shell there.

Impact is limited by T41: an idle shell with no descendants already closes silently on Windows. What is lost is the startup window (pid not known yet, or a profile helper still running), where the close asks.

Fix direction: distinguish 'the config names my shell' (the `command` key / Settings) from 'run this command' (`-e`, `initial-command`, `+new-window --command`): only the latter should clear fresh_default_shell. Check how +new-window --command reaches the surface on Windows (IpcHandlers.zig ~229, command-shell wrap) so it stays explicit.

## Validation criteria

- [ ] close-confirm-idle.ps1 F/G 'untouched' passes with `--command=pwsh.exe` (or cmd.exe) on the launch line.
- [ ] A `+new-window --command=...` pane still confirms while busy.
