# T3864 - PA-R28 (= PA-M23): pooled D3D11 devices are never released once created, and each pane past a device's interop limit pays a refused open first

## Summary

From audit-5 (T3316), areas R and M. gl_comp_present.zig:421 (pool_max 8), :440-469 (acquireAt keeps the cache reference for the life of the process), :712-723 (each pane walks the pool from device 0 and pays a refused interop open per full device). Each extra device is about 54 driver threads and tens of MB (quoted from T2968); bounded at 7 extra. Introduced by 459de62840 (T3746), by design. Fix: release a pooled device when its last pane goes, and start a new pane at the last device that accepted an open. Detail: audit-5/R-findings.md and M-findings.md.
