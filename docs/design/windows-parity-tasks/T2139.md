# T2139 - pane-sidebar-actions.ps1 'still four on screen' / 'five on screen' fail: five panes in a 1400 DIP window with the pinned sidebar no longer all show (stacked-row rule, T2108)

## Summary

Red on 2026-10-21 against 57c01f8c3 (before T2125) and after. The script counts visible pane HWNDs after a stash/restore; with the 300 DIP minimum a five-pane row in ~1160 DIP of grid stacks, so the count is of what is on show, not what exists. Decide what the assertion means now (panes in the tree vs on show) and resize or recount.

## In plain terms

The test that checks right-click actions in the pane sidebar was failing even
though the actions themselves work. It opened five panes in a window too narrow
for five at the new minimum pane width, so the app (correctly) tucked some of
them away and the test's "five on screen" count came up short. The test window
is now wide enough for all five, so the count means what it was written to
mean again.

## Goals

- [x] Decide what "on screen" means: panes in the grid, all on show - so size
      the window so the row does not stack, rather than counting tucked panes
- [x] Fail at setup, with a clear message, if a future layout change stacks
      the row again

## Validation criteria

- [x] `acceptance-parallel.ps1 run -Scripts pane-sidebar-actions.ps1`: ALL
      PASS (40 assertions) at 125% DPI, with the window at 1850 DIP (was red
      2 FAILURE(S) at 1400 DIP, same build, same run).
- [x] New setup check "all five panes on show beside the pinned sidebar"
      passes, so steps 3/4's counts measure the grid, not the stacking.
- [x] Negative control `-NegativeControl` still FAILS (9 failures).

## Resolution

Widened the test window from 1400 to 1850 DIP: 240 DIP sidebar + 5 x 300 DIP
panes + gutters/chrome fits with ~100 DIP slack and still fits a 1920-wide
screen at 100%. The assertion keeps its meaning (visible pane HWNDs = panes in
the grid), which only holds while the row is not stacked - hence the new setup
check. T2136 and T2144 were the same defect and are closed as duplicates.

Found on the way: the scoped harness floor's `click-coord-audit` was red on
any sweep including this script (its E1 blind control counted the script's own
`At` wrapper sites against an 80% whole-tree ratio: 72%). I fixed it here too,
but lane a landed the same fix first in T2134 (3a67970c0: wrapper-forwarded
sites leave the denominator), so at rebase this commit took theirs and kept only
the pane-sidebar-actions change.
