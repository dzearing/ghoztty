# T1540 - agent-handoff.ps1 unwinds mid-body in a suite sweep but passes when run alone

## Summary

Seen in the T1535 sweep (`temp\suite-t1535`, 2026-09-13): 28 of 29 scripts
green, and `agent-handoff.ps1` scored `nothing` - `AGENT-HANDOFF: RUN DID NOT
FINISH (17 assertions passed)`. Re-run alone by the suite's confirm pass it
scored PASS, so the suite's own verdict is "harness/isolation, not the
product".

The stderr says exactly where it unwinds - `agent-handoff.ps1:457`:

```
Copy-Item : The process cannot access the file
'...\ghoztty-agent-handoff-7384\agentdir\ghoztty-agent.exe.bak' because it is
being used by another process.
```

So the script swaps the agent binary while a previous process still holds the
`.bak` open. Alone there is enough slack for that handle to close; behind 7
other scripts there is not. The fix is a bounded wait (or a retry) on the
handle being released before the copy, and a named assertion if it never is -
never a bare `Copy-Item` whose failure aborts the body with everything past it
unmeasured.

Worth noting the machinery worked: nothing was stamped (`STAMP REFUSED ...
GHOZTTY_TEST_BODY=pending`), so the guard stayed due rather than recording a
green run that did not happen.

## In plain terms

One of the automated tests gives up half way through when it runs as part of a
big batch, because it tries to overwrite a file another program still has open.
On its own it works. Nothing is wrong with the terminal - the test needs to wait
for the file to be free.

## Goals

- [ ] Reproduce by running `agent-handoff.ps1` behind the same neighbours.
- [ ] Wait for the handle (bounded) instead of copying blind.
- [ ] A failure to get the file names itself as an assertion rather than
      unwinding the body.

## Validation criteria

- [ ] `agent-handoff.ps1` green on its own AND in a sweep that runs it after
      the scripts it followed here.
