# T1540 - agent-handoff.ps1 unwinds mid-body in a suite sweep but passes when run alone

## Summary

Seen in the T1535 sweep (`temp\suite-t1535`, 2026-09-13): 28 of 29 scripts
green, and `agent-handoff.ps1` scored `nothing` - `AGENT-HANDOFF: RUN DID NOT
FINISH (17 assertions passed)`. Re-run alone by the suite's confirm pass it
scored PASS, so the suite's own verdict is "harness/isolation, not the
product".

The stderr says exactly where it unwinds - `agent-handoff.ps1:457`:

```
Copy-Item : The process cannot access the file
'...\ghoztty-agent-handoff-7384\agentdir\ghoztty-agent.exe.bak' because it is
being used by another process.
```

So the script swaps the agent binary while a previous process still holds the
`.bak` open. Alone there is enough slack for that handle to close; behind 7
other scripts there is not. The fix is a bounded wait (or a retry) on the
handle being released before the copy, and a named assertion if it never is -
never a bare `Copy-Item` whose failure aborts the body with everything past it
unmeasured.

Worth noting the machinery worked: nothing was stamped (`STAMP REFUSED ...
GHOZTTY_TEST_BODY=pending`), so the guard stayed due rather than recording a
green run that did not happen.

## In plain terms

One of the automated tests gives up half way through when it runs as part of a
big batch, because it tries to overwrite a file another program still has open.
On its own it works. Nothing is wrong with the terminal - the test needs to wait
for the file to be free.

## Goals

- [x] Reproduce the collision. The original sweep's neighbour ordering is not
      recoverable and the race is load-dependent, so the collision was
      reproduced directly instead: a second process holds the `.bak` open with
      `FileShare.None`, which is the exact error the sweep printed.
- [x] Wait for the handle (bounded) instead of copying blind:
      `Set-AgentFixture` / `Set-CanonicalAgent` first wait (30s) for every
      process running from the per-run agent dir to be gone, then retry the
      copy/remove for up to 30s. All five fixture writes (B, D x2, E x2) go
      through them, including the canonical `Remove-Item` that used to be
      `-ErrorAction SilentlyContinue` (a silent failure there would leave the
      newer build in place and make the next arm hand off before its baseline).
- [x] A failure to get the file names itself as an assertion (B0b, D0, D2b,
      E0, E4b) carrying the error text, rather than unwinding the body.

## Validation criteria

- [x] `agent-handoff.ps1` green on its own: `acceptance-parallel.ps1 run
      -Scripts agent-handoff.ps1` -> `AGENT-HANDOFF: ALL PASS (42 assertions)`,
      guard re-stamped.
- [x] The contended case, which a sweep only hits by luck: a scratch probe
      extracts the helpers from the script's AST and drives them against a file
      held `FileShare.None` - held 3s: waits 2.6s and succeeds (both the `.bak`
      copy and the canonical copy); held 45s: returns `copy to .bak: The process
      cannot access the file ... being used by another process` without
      throwing. `T1540 HELPER: ALL PASS`. The pre-fix bare `Copy-Item` throws in
      the first case, which is the unwind the sweep recorded.
- [x] Harness floor (scoped) green and stamped; `unwired-hook-audit.ps1` ALL
      PASS (13); `guard-due.ps1 check` clean.
- Not re-run: the 29-script T1535 sweep itself. The script is now `[exclusive]`
  in `acceptance-parallel.ps1`, so it no longer shares the box in a sweep; the
  helper probe above is the deterministic stand-in.
