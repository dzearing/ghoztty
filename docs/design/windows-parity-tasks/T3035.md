# T3035 - PA-V03: a viewer in a background tab or minimized window keeps its whole renderer: it is paused but never suspended or memory-trimmed (ViewerPane.zig:1834)

## Summary

PA-V03 (audit-1, T2963). ViewerPane.setVisible (ViewerPane.zig:1834-1849) only calls put_IsVisible and ShowWindow; no ICoreWebView2_3 (TrySuspend/Resume) or ICoreWebView2_19 (MemoryUsageTargetLevel) exists in src/apprt/win32. Cost (estimated): 50-150 MB renderer heap per hidden viewer plus page timers on live pages. Fix: add both vtable slots; on hide set MemoryUsageTargetLevel=Low, then TrySuspend after ~30 s; restore Normal on show. Risk: IPC verbs and captures against a suspended page must Resume first; needs a runtime-version fallback. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## In plain terms

A document or web page open in a background tab, or in a minimized window,
used to stop drawing but otherwise stay fully alive: its memory stayed
allocated and a live website's timers kept running. Now such a page is asked
to shed memory the moment it is hidden, and is put to sleep entirely once it
has stayed hidden for 30 seconds. It wakes by itself when you look at it
again, or when an agent reloads it, so nothing that drives a hidden pane has
to wait.

## Goals

- [x] a hidden viewer lowers its renderer's memory target at once
- [x] a viewer hidden for 30 s has its page suspended (script and timers frozen)
- [x] showing the pane, or reloading / scripting / capturing it while hidden, wakes it first
- [x] older WebView2 runtimes without these interfaces keep the T2913 pause and nothing else
- [ ] a measured memory saving (not visible to the current baseline: T3174)
