# T3880 - Baseline-5 regression: printing 64 MB costs the release app about twice the CPU it did at baseline-4 (7.5 s -> 15.8-17.5 s), and takes longer (26 s -> 33-39 s)

## Summary

Found by audit-5 (T3316). perf-baseline.ps1 busy phase, release, at 5eaac0760a: cpu_s 7.50 -> 17.47 (baseline-5) and 15.77 (repeat, -Build Release -Phase busy,viewer, temp run); cpu_pct 28.8 -> 53.6 / 40.8; wall_s 26.0 -> 32.6 / 38.6. Debug cpu_s 13.1 -> 18.4. The app's own counters did NOT move: reads/s, batches/s, queue_render/s, renderer wakeups ~118/s, fps 119, and attributed Mcycles/s (1298 -> 1294) and wakeups/s are all within tolerance - so the extra cost is spread over a longer span rather than a hotter loop, or sits outside the attributed threads. FIRST STEP (T3242/T3234 lesson): run the baseline-4 binary (424c9e5ab, rebuilt ReleaseFast) on the same day to rule out box drift and concurrent lane load; only then bisect 424c9e5ab..5eaac0760a (candidates: T3761 pace 7ce6815435, T3746 device pool 459de62840, T2622 presenter 79307bd67b). Filed P1, not P0, under the same exception as audit-4 (the controller put the single-window port ahead of perf work). Data: docs/design/perf-audit/baseline-5.json, audit-5.md.
