# T1652 - The ViewerPane host-floor test goes red in a full floor run but passes alone, so a green floor needs a re-run

## Summary

Found under **T848**. `scripts\floor-lane.ps1 -Lane all` ended `FLOOR NOT GREEN`
on the agent lane:

```
lane agent: error: 'apprt.win32.ViewerPane.test.host floor: a real controller on a real window, on this box' failed:
FLOOR SUMMARY: lib#1=PASS none#1=PASS win32#1=PASS agent#1=FAIL
  [alone: PASS alone - NOT reproduced -> harness/timing, not the product]
```

The solo confirm pass (T1170) re-ran it by itself and it passed, and a hand
re-run of the whole agent lane minutes later was `LANE agent PASS in 198s`.
Nothing in the T848 change could reach it - that change is PowerShell only and
this is a Zig test - so the lane is red for the state of the box rather than the
state of the code.

That is the T1170 shape, and the confirm pass names it correctly. What it does
not do is make the floor usable: the standing gate is "all four lanes green",
so every full run that trips this costs a re-run, and a real regression in this
test would be indistinguishable from the flake for as long as the habit is to
re-run and move on.

## In plain terms

One browser-pane test fails when the whole test suite is running at once, but
passes when it runs by itself. So a clean test run sometimes reports a failure
that is not real, and the fix is to run it again - which is exactly the habit
that lets a genuine failure slip past.

## Goals

- [ ] The full `-Lane all` run is green on an unchanged tree over several
      consecutive runs, without a hand re-run
- [ ] Whatever the fix is, a genuinely broken ViewerPane host still turns the
      lane red - the flake is removed, not the assertion
