# T1654 - The viewer host-floor test now fails ALONE on a 30s waitFor timeout in the git-status diff section

## Summary

Found on the T849 turn (2026-09-18), running the standing floor over a tree whose
only changes were PowerShell and Markdown - no Zig at all, so the test binary
could not have been altered by that work.

`floor-lane.ps1 -Lane all`: **lib PASS (87s), none PASS (337s), win32 FAIL
(543s), agent FAIL (500s)**, both on the same test:

```
apprt.win32.ViewerPane.test 'host floor: a real controller on a real window, on this box'
```

The wrapper's own solo confirm then re-ran that single test under
`-Dtest-filter` on an otherwise idle box and **reproduced it in both lanes**:
`solo confirm: FAIL alone - REPRODUCED. This is the code, not the box.`

That is what separates this from [[T1645]]. T1645's signature is
`[tripwire] (warn): untripped point=read`, it appears when a live WebView2
controller is starved by a busy box, and its solo confirms have historically
come back `PASS alone - NOT reproduced`. This one is a different assertion, in a
different part of the test, and it does not need a busy box:

```
[viewer_pane] (warn): waitFor: nothing satisfied the wait; pane still for 30011ms (bound 30s), 35881ms total
[viewer_pane] (warn): waitFor: state=ready mode=diff page_loaded=true diff_pushed=true
                      controller=true failure=false callbacks=256 title=Working tree
                      location=git-status: diff{repo=...\.zig-cache\tmp\BLvfR6sZeICRAo_6
                      files=2 patch=true busy=true}
D:\git\ghoztty\src\apprt\win32\ViewerPane.zig:9342:5  in waitFor -> error.WaitForTimeout
D:\git\ghoztty\src\apprt\win32\ViewerPane.zig:8764:13 in test.host floor: ...
```

So the pane IS ready, the diff HAS been pushed, the controller IS live, 256
callbacks have run - and the wait still expires. The `busy=true` in the diff
state is the thing to look at first: the section is the git-status diff view,
and a wait that never sees `busy` clear is a very different defect from a
controller that never starts.

## In plain terms

One of the automated checks that drives a real viewer window has started
failing every time, in the part that shows a git diff. Nothing about the viewer
changed - it just waits thirty seconds for the diff to finish loading and then
gives up. Until it is fixed, every piece of work on this machine finishes with
two red test lanes that have nothing to do with the work.

## Goals

- [ ] The win32 and agent lanes go green on an unchanged tree
- [ ] Whatever the wait was missing, the test says so when it expires rather
      than printing a state dump a reader has to interpret

## Details

Where to start:

- `src/apprt/win32/ViewerPane.zig:8764` is the failing wait; `:9342` is
  `waitFor` itself. The predicate that never came true is the first thing to
  name - the log dumps the state but not the condition.
- `busy=true` on a `git-status` diff with `files=2 patch=true` suggests the
  diff's own busy flag is never cleared, or is cleared on a path this fixture
  does not reach. Compare against the same section's earlier passes.
- It is NOT load: the solo confirm is a single filtered test on an idle box and
  it still fails, in two independently built lanes.
- Bisect is cheap here because the tree has not changed: the last known green
  win32 lane was the T846 turn (2026-09-18, commit 5e04fcc19 era), so the
  window is small.
