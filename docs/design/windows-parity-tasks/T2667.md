# T2667 - The Windows keyboard shortcut guide forgets its size and position: Mac autosaves the guide's frame (ShortcutGuideWindow) and reopens it where you left it; Windows opens it centred at 880x640 every time

## Summary

Follow-up to T2591. Mac's ShortcutGuideController autosaves its NSWindow frame as ShortcutGuideWindow. The win32 guide (src/apprt/win32/ShortcutGuideWindow.zig) centres on its owner at the default size on every open. Persist the placement (window_placement.zig / window_memory.zig are the existing seams) and restore it, clamped to a visible monitor.

## In plain terms

The keyboard shortcut guide (Help > Keyboard Shortcuts) always opened in the middle of the terminal at the same size, however you had moved or stretched it last time. On the Mac it reopens exactly where you left it. Now Windows does too: drag or resize it, close it, and the next time it opens it is back in that spot at that size - and if the monitor it was on is gone, it opens on one you can see.

## Goals

- [x] The guide remembers its position and size when a move or resize ends, and when it closes
- [x] It reopens at that frame, rescaled when the monitor's scale changed
- [x] A frame on a monitor that is gone opens centred on the nearest one; a corrupt file opens at the default
- [x] A debug build keeps its own file, so tests never move the user's guide
