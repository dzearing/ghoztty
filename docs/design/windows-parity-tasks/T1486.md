# T1486 - The loop's own pane says nothing when the loop is blocked; only the dashboard does

## Summary

T1484 put a bar on the dashboard when the loop is stopped by a usage limit. The terminal window actually running the loop still shows nothing - +set-banner is right there, and a user looking at the loop pane itself (the most likely place they look) learns nothing. Give the loop pane a sticky banner carrying the same reason and reset time, raised and cleared by the same watchdog record the dashboard reads.

What is LEFT (re-verified 2026-11-14): T2097 already banners the loop pane
for a blocker only the user can clear (an expired login). A usage limit with a
known reset goes through T1485's `hold` branch instead, which neither banners
the pane nor stamps the `recovery_blocked*` fields - so since T1485 landed the
dashboard's T1484 bar cannot show a quota hold either.

## In plain terms

When the AI service's usage limit stops the loop, its own terminal window
just sits there looking idle, and since this morning's change the dashboard's
"blocked" bar does not appear either. After this, the window shows a banner
saying the loop is paused for the usage limit and roughly when it picks up
again, and the dashboard bar is back.
