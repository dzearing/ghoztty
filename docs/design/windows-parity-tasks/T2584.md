# T2584 - Settings read model on Windows: the schema catalog, the files Ghostty loads in order, which later include overrides a key, and the All Settings filter (Mac 9287de0ff)

## Summary

Originally the whole Mac 9287de0ff Settings window: Cmd-, / Preferences / the
open_config action open a Settings window instead of the file; a searchable
sidebar of pages; every row shows the key's docs, a changed-from-default dot
and a reset; bad values are shown inline and never written; changes apply
live; a key set by a later config-file include is read-only with an Open link;
Advanced -> All Settings lists every schema key automatically. Mac reference:
`docs/reference/settings.md`.

**Split on 2026-11-03** (too big for one context): this task is now the read
model the window is built on, the win32 port of Mac `ConfigSchema.swift` and
the reading half of `SettingsModel.swift`. The window shell (sidebar, search,
generic row, All Settings, open_config wiring) is **T2675**; the rest of
Advanced (file path, includes, backups/Restore, the change toast) is
**T2676**; the curated pages stay **T2585**.

What landed here:

- `src/apprt/win32/SettingsCatalog.zig`: the schema from
  `src/config/schema_json.zig` (Windows links the core, so it calls
  `allocJson` directly instead of Mac's C entry point): `defaults()` is the
  catalog (docs + defaults), `describe()` the live config's effective values,
  `summary()` a row's one-line subtitle.
- `src/apprt/win32/SettingsSources.zig`: the files Ghostty loads in Windows'
  order (XDG legacy, XDG, a dev build's `config-debug.ghostty`, then
  `config-file` includes breadth-first, relative to the including file, `?`
  optional; no `~` expansion, as Ghostty on Windows); `overriding` /
  `overridingKeyed` / `overrideMessage` (Mac's text); the `Reader`
  (`value` / `values` read from the file before the reload lands,
  `isModified`, `matches`, `allSettings(.all | .changed, query)`).
- `SettingsModel.sources`: `set` and `setKeyed` refuse a key (or keybind
  trigger, after normalization) that a later file sets, with the row note,
  and write nothing.

## In plain terms

On the Mac, pressing Cmd-comma opens a Settings window. On Windows the same
key still opens the raw config file in a text editor. This piece is the part
of the Windows Settings window that works out what to show: every setting
with its description and default, what your config files actually set, and
which settings another config file you include will override. Nobody sees it
on its own; the window that uses it is the next task.

## Goals

- [x] The schema catalog: every config key with its docs, default and kind, with no hand-kept list
- [x] The load order: default files then includes, exactly as Ghostty on Windows reads them
- [x] Override detection for plain keys and keybind triggers, with Mac's wording, enforced by the write model
- [x] The row reads (value, values, changed) and the All Settings filter and search
- [x] The window, the Advanced page and the curated pages filed as their own tasks (T2675, T2676, T2585)
