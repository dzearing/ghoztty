# T3115 - A win32 viewer pane whose WebView2 browser process exits shows an error card instead of coming back: re-create the environment and controller in place

## Summary

T3107 handles ProcessFailed BROWSER_PROCESS_EXITED by closing the dead controller and showing the error card (The viewer's browser process stopped / Reopen this pane). Every viewer pane in the app shares one environment (webview2.Host caches env in .ready), so recovering in place means: Host drops its dead env and goes back to .idle, then each affected pane re-runs start() (handlers reset, location kept). Mac has no equivalent event (WebKit has no browser process), so this is Windows-only robustness beyond parity. Validation: kill the msedgewebview2 browser process of a test pane (pid via get_BrowserProcessId) - the pane renders its document again. Follow-up of T3107.
