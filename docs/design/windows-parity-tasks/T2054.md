# T2054 - GUI postmortem calls exit 0xFFFFFFFF a CRASH: it is TerminateProcess(-1), i.e. Stop-Process/.NET Kill from outside, and saying so would have named T2053's cause on day one

## Summary

ConvertTo-GuiExitVerdict (test\win32\lib\GuiPostmortem.ps1) treats any high-bit exit code as an NTSTATUS crash, so a process killed by Stop-Process prints 'CRASHED - 0xFFFFFFFF unnamed NTSTATUS' and a hunt for a crash follows (T2053: it was lane A's agent-upgrade.ps1 teardown). Give -1 its own verdict: 'killed from outside (exit -1 = TerminateProcess by Stop-Process/.NET Process.Kill) - look for a script that kills by name/command line', and list which ghoztty-killing scripts were running at the time if cheap (acceptance-parallel run dirs). Deliberate script teardowns that kill their own pids should not print a postmortem at all, or should be marked as theirs.
