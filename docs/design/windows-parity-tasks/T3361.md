# T3361 - Linux L5b: move the per-verb bodies (target lookup, split, close, read, send-keys, set-banner/state, the +list tree walk) behind a shared frontend model so GTK reuses win32's logic instead of rewriting it

## Summary

T3334 moved the server's frontend-independent layer into src/apprt/ipc/server.zig (request shape, action table, reply builders, a dispatcher that refuses to compile a frontend missing a verb). The verb BODIES were still per frontend, and T3336 had already hand-copied +send-keys/+read from win32 into GTK. This task builds the shared-body layer and moves the first verbs through it:

- `src/apprt/ipc/verbs.zig`: the +read and +send-keys bodies (argument handling, the per-state failure sentences, reply shape, the ConPTY LF rule) over a small model a frontend supplies: a `Terminal` handle (writeRaw / writeBracketed / pasteIsBracketed / dumpScreen), `replyAllocator`, `lookupTerminal` -> `Lookup{ready, not_found, gone, viewer, not_started}`, `input_line_ends` (.pty / .conpty) and an optional `notFoundResponse` (win32's T2250 ambiguity sentence). Unit-tested over a fake in the none lane.
- `src/apprt/ipc/core_terminal.zig`: that `Terminal` over the shared core Surface both frontends host.
- `src/apprt/ipc/pane_id.zig` (moved from win32/; GTK imported it from there) and `src/apprt/ipc/build_identity.zig` (provenance's comptime half, which GTK duplicated).

Scoped (rescoped 2026-11-21): the remaining verbs move in T3374 (+close/+focus, +set-banner/+set-state) and T3375 (+split/+new-window/+rename policy and the +list tree walk).

One deliberate behaviour alignment: win32's flat (unsegmented) +send-keys path queued its write past the core Surface's read-only check; through the shared body it uses `writePtyRaw`, as the segmented path and the Mac (`surfaceModel.writePtyRaw`) always did.

## In plain terms

The Windows and Linux apps each had their own copy of the code that answers "type this into that pane" and "show me what that pane says". Now there is one copy both apps use, so a script gets the same answers and the same error messages from either, and a fix made for one platform fixes both. Nothing a user sees changes.
