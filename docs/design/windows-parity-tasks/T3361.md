# T3361 - Linux L5b: move the per-verb bodies (target lookup, split, close, read, send-keys, set-banner/state, the +list tree walk) behind a shared frontend model so GTK reuses win32's logic instead of rewriting it

## Summary

T3334 moved the server's frontend-independent layer into src/apprt/ipc/server.zig: request shape, action table, reply builders and a comptime dispatcher that refuses to compile a frontend missing a verb. The verb BODIES are still in src/apprt/win32/IpcHandlers.zig and talk to App/Window/PaneView/SplitTree directly. Define a small model interface (find window/pane by id or name in the caller's window, list windows/tabs/panes, split a pane, close, read screen text, queue input, set banner/state) that win32 implements over its types and GTK over its own, then move each verb's argument handling and reply wording into shared code a verb at a time. Validate every step on Windows: ipc-p1/p2/p3 ALL PASS before and after, unchanged (baseline 2026-11-21: 26/20/19 assertions). T3336 (GTK verbs) builds on whatever has moved.
