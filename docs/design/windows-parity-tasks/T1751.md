# T1751 - ipc-command-keepalive arms C (git-bash) and I (wsl) flake: '+send-keys runs in the pane afterwards' misses on some runs

## In plain terms

A test that checks "a pane opened with a command stays usable afterwards" sometimes
said the pane was dead when it was fine, for the Git Bash and WSL shells. It was
reading the screen too early. It now waits for the shell's actual answer, and it no
longer starts WSL on its own just to find out whether WSL is there.

## Goals

- [x] the ALIVE probe waits for its output line, not for its own echo
- [x] a probe typed while the posix login shell is still starting is re-sent once
- [x] the WSL arm (and ipc-remote.ps1 3b) no longer boots WSL to decide whether to run

## Summary

Seen during the T1665 turn (2026-09-25): `test/win32/ipc-command-keepalive.ps1` failed `I wsl +send-keys runs in the pane afterwards` on one run (old build) and both `C git-bash` and `I wsl` on the next (new build), then went ALL PASS on the next run with no change to the code those arms exercise (the agent-backed `--command` path). The marker assert passed each time, so the command ran; what missed is the ALIVE probe typed afterwards. Suspect: the posix shells' `exec <shell> -li` restart is still starting when the probe is typed, so the keys land before the login shell reads input, or the 25s wait is short for a cold wsl. Investigate by capturing the pane tail on failure (arm K's `Test-PaneIsPowerShell` already prints one) and waiting for a prompt before sending the probe.

## Root cause and fix (2026-11-21)

- **The wait matched the probe's own echo.** `Test-KeepAlive` waited for
  `ALIVE<marker>\s*[\r\n]`, which the echoed command line (`$ echo ALIVE<marker>`
  then newline) satisfies the moment the keys are echoed. On a shell slower to
  answer than to echo (git-bash, wsl) the tail was read before the output line
  existed, counted one hit, and FAILed over a live pane. The wait is now for the
  OUTPUT line alone: `(?m)^\s*ALIVE<marker>\s*$`, which the command line (it has
  `echo ` before the probe) can never match.
- **The type-ahead window.** The posix rows `exec <shell> -li` after the command,
  so the probe can land during the handover. If half the wait passes with no
  answer the probe is typed once more; only a shell that RAN the echo prints the
  bare line, so the retry cannot make a dead pane pass. The pane tail is printed
  on a failure.
- **Found on the way: the WSL arm booted WSL.** Arm I (and `ipc-remote.ps1` 3b,
  which copied it) gated on `wsl.exe -e /bin/true`, which starts the WSL2 VM -
  against CLAUDE.md's "Never start WSL unasked". New `scripts/lib/WslState.ps1`
  reads the distro table (`wsl -l -v`, starts nothing) and both arms run only when
  the default distro is already Running, SKIPping with the reason otherwise.
