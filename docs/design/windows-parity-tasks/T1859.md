# T1859 - A debug build reads and renews the user's REAL relay account (%LOCALAPPDATA%\ghoztty\account.dat): build-mode endpoint isolation does not cover the account store

## Summary

Found in T1837 (2026-10-11): ipc-relay's debug app resolved the user's signed-in relay token from the default account store, dialed a local test relay with it, and two sections went red. Pipes and state dirs are derived from build mode (T350) but relay_account.accountPath() is not, so any debug run without GHOSTTY_ACCOUNT_STORE (harness or by-hand) reads the user's credential and may RENEW (rewrite) it under the installed app. Decide by code whether a debug lineage should get its own store (e.g. account-debug.dat) and/or whether Set-GhozttyTestIsolation should default GHOSTTY_ACCOUNT_STORE to the run's temp dir; sweep the relay/chooser harnesses that do not set it (cli-unknown-flag, ipc-remote fixed in T1837).
