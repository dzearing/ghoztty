# T3342 - Linux L13: a parity intake sweep for the Linux seat

## Summary

parity-sweep.ps1 excludes src/apprt/gtk as owing Windows nothing, which stays right for the Windows seat. The Linux seat needs its own view: Mac commits since the Linux baseline with no seat: linux task citing them. Do not change the Windows sweep's output.

## In plain terms

The Mac version gets features first and Linux copies them, but nothing told
the Linux work queue when the Mac side changed: the existing check only asks
"has Windows written this down?". Now the Linux loop runs its own check every
turn, and a Mac change that no Linux task mentions shows up as a hole to fill,
so Mac features cannot quietly skip the Linux build.

## Goals

- [x] `parity-sweep.ps1 -Seat linux`: Mac commits since the Linux watermark that no `seat: linux`/`any` task cites (Windows tasks, the log, digests and decisions do not count)
- [x] `-Record [-Note]` moves the Linux watermark only over a clean range that starts at the watermark; `-Note` cites no-parity-owed shas and counts in the same run
- [x] the Linux baseline is recorded (`docs/design/windows-parity-linux-intake.json`, `9c0e90622` = origin/main, already merged; earlier Mac behavior reaches Linux through the docs/reference intake, T3340)
- [x] the Windows sweep's output is unchanged
- [x] the lane-L turn runs it (go.md lane L overrides; linux-port.md Sweep/intake row)

## Design notes

- Same watch paths as the Windows sweep (macos/ + src/ minus both non-Mac
  frontends): Linux follows the Mac, so a win32-only commit owes it nothing
  just as a gtk-only one owes Windows nothing.
- `seat: any` counts: an any-seat task is one the Linux loop's `next` hands out.
- The Linux watermark is its own file, never the Windows intake's: the two
  seats move at different speeds, and the Windows sweep ignores it, so a
  Linux "no parity owed" judgement never quiets the Windows gate.
- Record refuses exit 1 over unmapped commits and exit 2 over a gap (range
  start is not the watermark) or a non-range.
