# T3185 - Single-window mode: the CLI sees no difference - +list lists every workspace (on show first, focused), and every verb reaches a parked workspace without showing it

## Summary

+list: one entry per workspace, on-show first and focused, parked title kept (Mac 9b05b54a4), stable id the same parked or shown; --target names resolve to parked workspaces; +close/--force, +split, +read, +send-keys, +set-state, +set-banner, +stash/+restore address a parked workspace without showing it; --focus and ghoztty://focus switch. IpcRegistry/IpcHandlers enumerate controllers, never visible HWNDs. Child of T3136 (split 2026-11-16). Design (T3136 Details): ONE shared top-level HWND; every workspace keeps its own Window controller; the workspace on show owns the HWND (GWLP_USERDATA, chrome, sidebar), a parked Window has hwnd=null and its pane child HWNDs are reparented (adoptPane-style SetParent, Window.zig:7278) under a hidden park host so they survive the shared HWND closing. Spec: docs/reference/window-modes.md. Acceptance goes in test/win32/single-window-mode.ps1 (one section per child).

## In plain terms

With "All in one window" turned on, the windows you are not looking at were invisible to scripts: asking Ghoztty for its list of windows only named the one on screen. Now every workspace shows up in the list with its title, the hidden ones can be split, typed into, read, labelled and tidied without jumping onto the screen, and asking to focus one switches the window to it.
