# T1617 - The 151 remaining unwrapped counts in test and script sources are worked down to zero

## In plain terms

Lots of our automated checks count things - windows, panes, rows - and compare
the numbers. When the thing being counted turns out to be a single item,
PowerShell hands back nothing to count, both sides of the comparison are
nothing, and the check passes no matter what the product did. T794 added the
sweep that finds these and stopped new ones arriving; this is the work of going
through the 151 that were already there, file by file, so that every one of
those checks can actually fail.

## Summary

T794 landed `test\win32\unroll-count-audit.ps1` (analyzer:
`lib\UnrollCountAudit.ps1`), fixed the 46 sites in the harness-floor audits and
their libs, and recorded the rest as a per-file baseline in
`test\win32\unroll-count-audit.baseline.json` - 151 sites across 35 files,
measured 2026-09-16. The ratchet refuses a file that gains a site, so nothing
new arrives; what is left is the existing population.

The fix itself is one `@()` at the point of use:

```powershell
$before = (Get-TestWindows -ProcessId $g.Pid).Count      # vacuous for one window
$before = @(Get-TestWindows -ProcessId $g.Pid).Count     # counts

$rows = Get-Rows ; $n = $rows.Count                       # vacuous for one row
$rows = @(Get-Rows) ; $n = $rows.Count                    # counts
```

A helper that returns `, @(...)` is NOT one of these - the comma keeps the
array whole and the count is already right, so wrapping such a call breaks it
(`@(CommaTwo).Count` answers 1). The analyzer knows the difference; the first
mechanical pass did not, and turned four green audits red before the floor
caught it.

What is NOT mechanical is criterion 3 of T794: a site that was vacuous may have
been hiding a real failure, so a file's assertions have to be RE-RUN after the
wrap and any new red investigated rather than re-wrapped away. That is why this
is a task per file family rather than one sweep: the biggest holders are GUI
acceptance scripts (`resize-flicker.ps1` 33, `banner-resize-repaint.ps1` 10,
`agent-recovery.ps1` 9, `build-locked-artifact.ps1` 9, `upgrade-no-fork.ps1` 9,
`split-divider.ps1` 8) whose runs need the app and the
test desktop.

Work it down in slices, and lower the baseline in the same commit that fixes a
file (`unroll-count-audit.ps1 -UpdateBaseline`) - the ratchet fails a file that
is BELOW its baseline precisely so the record cannot drift from the tree.

## Validation criteria

- [ ] the baseline is empty (or holds only sites carrying a stated
      `# count-audit: <reason>` exemption) and
      `test\win32\unroll-count-audit.ps1` is green
- [ ] every file whose sites were wrapped has had its own acceptance run since,
      and any assertion that went red as a result is named with what it turned
      out to be - a real defect, a fixture drift, or a wrong expectation
- [ ] no site was silenced with an exemption marker that does not state a real
      reason
