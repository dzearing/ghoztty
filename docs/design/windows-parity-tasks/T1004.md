# T1004 - Nothing sweeps the suite for the empty-collection unroll that killed a floor run

## Summary

T982/T1000 died on it (an empty ArrayList return unrolls to null and a Mandatory parameter refuses null), T974 died on its mirror image (a 'return ,$ids' nests inside the caller's @() so .Count reads 1 forever). Both were found by accident, weeks apart, in scripts nobody suspected. A static audit over scripts\*.ps1, scripts\lib\*.ps1 and test\win32\*.ps1 could name the class: a [Parameter(Mandatory)] parameter that accepts a collection but carries no [AllowNull()], and a 'return ,' whose call sites wrap in @(). Model it on the existing meta-audits (isolation-meta, verdict-exit, stderr-capture) - AST-based, its own guard row, a -TeethCheck that plants a violator.

## In plain terms

Two PowerShell quirks have each silently broken a test run: a list that comes back
empty turning into "nothing" and crashing the next step, and a list wrapped twice so
that counting it always says 1 no matter what is in it. Both were found by accident.
The existing unroll audit now looks for both shapes across every script, the 27
places that had them are fixed, and a new one fails the audit.
