# T2191 - floor-lane parallel says CONTENTION (the box, not the code) when the source changed between the side-by-side run and the solo re-run

## Summary

On 2026-10-23 (T2169) win32 and agent failed side by side on a real GPA leak in install_location tests; the leak was fixed before the solo re-runs, which passed, and the summary printed FLOOR PARALLEL CONTENTION ... the box, not the code. A solo re-run must compare the tree it builds against the one the side-by-side run built (e.g. git diff hash / newest source mtime) and, when they differ, say SOURCE CHANGED instead of blaming contention - otherwise a genuine code defect gets reported as box flakiness.

## In plain terms

When the test floor runs its four lanes at once and one goes red, it re-runs that
lane alone; if the re-run passes, it used to say "the box was too busy, not the
code". But if somebody fixed the code in between, the red was a real bug and the
floor was hiding it. Now it checks whether the code changed between the two runs
and says so instead of blaming the box.

## Goals

- [x] each side-by-side run and each solo re-run records a fingerprint of the build inputs as it starts
- [x] a red-then-green lane over changed sources prints `FLOOR PARALLEL SOURCE CHANGED`, not `CONTENTION`
- [x] the summary token and the lane's `====` line carry the change (`[side by side: FAIL, source changed]`, `a -> b`)
- [x] a fingerprint that cannot be taken claims neither (`FLOOR PARALLEL RERUN UNEXPLAINED`)

## Design

`scripts\lib\FloorSource.ps1`: `Get-FloorSourceFingerprint` hashes HEAD + `git diff HEAD --binary`
over the build inputs (`src pkg include vendor build.zig build.zig.zon`) + every untracked,
non-ignored file under them by content (139 ms on this tree). Tracker docs and test scripts
are deliberately excluded: the other lane commits them all the time and none can turn a zig
lane red, so counting them would say "source changed" on every run. `Get-FloorRerunCause`
is the pure verdict (contention / source-changed / unknown). The exit code is unchanged:
the solo run's verdict is still final, since it tested the tree as it now stands; what
changes is what the summary claims about the side-by-side red.
`GHOZTTY_FLOOR_SOURCE_FAKE` lets the harness change "the source" from inside a planted lane.

## Validation criteria

- [x] a planted lane that goes red AND changes the source on its first run comes out exit 0 with `FLOOR PARALLEL SOURCE CHANGED: none` and no CONTENTION line - `test\win32\floor-lane-parallel.ps1` (T2191 arms), ALL PASS 40 assertions via `acceptance-parallel run`
- [x] the existing flaky-lane arm (unchanged source) still says CONTENTION and no SOURCE CHANGED - same run
- [x] the fingerprint moves for a tracked edit, a new untracked source, an edit to that file, and a commit; holds still for a docs edit; is `$null` outside a repo - same run, over a throwaway git repo
- [x] negative control by construction: without the wiring the source-change arm prints CONTENTION, which its `-notmatch 'CONTENTION'` clause fails
