# T2161 - Ctrl+Enter toggles full screen on Windows, so apps like Claude Code never receive Ctrl+Enter

## Summary

User report 2026-10-22: Ctrl+Enter toggles full screen on Windows (src/config/Config.zig:7380, inherited from upstream's ctrlOrSuper(enter) - Cmd+Enter on Mac, which never reaches a terminal app, but Ctrl+Enter on Windows, which apps like Claude Code use). The keystroke should reach the app. User suggested Ctrl+Shift+Enter instead, BUT that is already toggle_split_zoom (Config.zig:7389, ctrlOrSuper(shift+enter)) - so the fix has to settle both: e.g. drop the Ctrl+Enter default on Windows and keep F11 (already bound at Config.zig:7468, and already what the menu and full-screen notice teach), or move split zoom elsewhere. Check the test at Config.zig:11176 that asserts the legacy Ctrl+Enter binding, the menu/notice text, and docs/claude keybind docs; Mac keeps Cmd+Enter (no collision there), and record the Windows-only difference as the native translation of a Cmd chord.

## In plain terms

Pressing Ctrl+Enter in a Ghoztty window on Windows threw the whole window into
full screen instead of passing the key to the program running in it, so
Claude Code (and anything else that uses Ctrl+Enter) never saw it. After this,
Ctrl+Enter goes to the program, and F11 - the usual Windows full-screen key,
already shown in the menu and the on-screen notice - is how you go full
screen. Mac is unchanged (Cmd+Enter never collided with anything there).
