# T1726 - Test fixtures write into the real publish and watchdog logs, poisoning postmortems

## Summary

Acceptance scripts append to the REAL supervision logs, so a postmortem reads fixture events as the loop's history. Seen 2026-09-24 in %TEMP%\ghoztty-daily-publish.log: "05:45:21 REQUESTED: T1: the installer dies silently" and "05:45:23 REQUEST FAILED: could not write ...\ghoztty-gate-negatives-7ed77f6b\not-a-dir\req" (test\win32\gate-negatives.ps1 fixtures). Seen 2026-09-23 05:48 in %TEMP%\ghoztty-go-loop-watchdog.log: "forced: re-entry requested ... LAUNCH-APP FAILED: could not start ...\gz-stop-d9db75ff\no-such-ghoztty.exe" (a go-loop-guard fixture) - the start-go controller first read it as a failed real recovery. Fix: every script that logs (daily-publish.ps1, go-loop-watchdog.ps1, and any other %TEMP%\ghoztty-*.log writer) takes its log path from a seam the harness redirects into the fixture dir, and a sweep asserts no test run grows a real log.
