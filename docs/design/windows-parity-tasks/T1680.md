# T1680 - Section B of job-escape-startup flakes: the jailed app writes nothing at all, so four assertions and C2 go red together

## Summary

Observed 2026-09-20 in three of seven consecutive runs (and reproduced with the pre-T902 HEAD copy of the script, so it predates that change). B1 passes - the WMI/session-0 launcher does start the app and writes app.pid - and then app.err.txt is ZERO BYTES for the rest of the run, so B2 (detected the job), B3 (respawned), B4, B5 and C2 all fail together. The app is not at fault: a standalone replication of B's exact shape (WMI-created launcher, jailed in a 0x2000 job, GHOZTTY_PANE_ID set, no agent instance) logs the full probe/escape trail and exits 0 every time, and sections E/F/G - which launch apps into jobs the same way - are green in the same runs. Suspect the launcher's Start-Process -RedirectStandardError never attaching in the session-0 launcher, or the app forwarding to an instance this run cannot see and exiting before its first log line. Next step: have the launcher record the app's exit code (the standalone repro does) and the reason it exited, so a red B says which of the two it was instead of only that the file is empty.
