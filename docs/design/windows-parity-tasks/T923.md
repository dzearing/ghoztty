# T923 - The press-any-key relaunch says nothing about having restarted the session

## Summary

test\win32\session-relaunch.ps1 B7 fails: under session-relaunch=prompt, pressing a key does respawn the session (B6 and B8 both pass - the id goes alive and input reaches the new child) but the '--- session restarted ---' divider performAwaitedRelaunch writes is not in the pane afterwards. Almost certainly the same erase T230/T423 fixed for the restore notice: the divider is written, then the respawned shell's ConPTY startup repaint (ESC[H ESC[2J) blanks the line before anyone sees it. The restore path survives that by folding its notice above the viewport with Termio.armNoticeFold; performAwaitedRelaunch does not arm the fold. Pre-existing - found running the harness for T823, whose rename touched no logic on this path (arm A, the rerun path, is fully green).

## In plain terms

When a pane's shell had ended and you pressed a key to start it again, the new
shell appeared with no marker between the old output and the new, so you could
not tell it was a fresh shell. That line now appears. It was fixed on
2026-09-02 as part of another task, and this card just confirms the fix.

## Resolution

Already fixed by **29b5040be** (T1264, 2026-09-02): `appendRestartDivider`
became idempotent and runs on every relaunch, and the viewer parks the
replayed screen into scrollback at `RELAUNCHED.replay_bytes` so the respawned
shell's repaint cannot erase it. No new code from this card.

The same runs found arm A (the automatic `rerun` relaunch after an agent
restart) RED on A10/A11 - the divider is missing on that path again. That is a
regression since 29b5040be, not this card's defect: filed as **T1698**, which
also notes that `session-relaunch.ps1` has no guard-due row, which is why it
went unnoticed.
