# T818 - A diff pane's git calls have no timeout on Windows, so a wedged git would hang the pane's teardown

## In plain terms

When a diff pane asks git what changed, it waits for git to answer. If git
never answers — a credential helper waiting on something, a filesystem that
has stopped responding — the pane waits forever, and closing that pane (or
quitting Ghoztty) waits with it, because the close has to collect the worker
before it can free what the worker is writing into. Nothing recovers; the app
has to be killed.

## Goals

- [x] A bounded wait on every `git` invocation a diff pane makes, after which
      the pane reports that git did not answer rather than hanging
- [x] Closing a pane whose git is wedged still closes it — the worker the
      teardown joins now always returns, because the child it is reading is
      terminated at the deadline

## Evidence

`src/apprt/win32/git_run.zig`'s `captureAlloc` reads the child's stdout to EOF
with no deadline, and `ViewerDiffProbe.deinit` JOINS the worker (it must — the
worker writes into a `Job` the deinit then frees). Mac's `ViewerProcess.run`
has the deadline this lacks: a 15 s `DispatchWorkItem` that calls
`process.terminate()`.

What is already in place, and why this is P2 rather than P1: `captureAlloc`
sets `GIT_TERMINAL_PROMPT=0` and `GIT_OPTIONAL_LOCKS=0`, which are the two
documented ways a read-only `git diff` blocks indefinitely. No hang has been
observed on this box.

The shape to port is a watchdog thread (or a `WaitForSingleObject` on the
child's handle with a timeout, then `TerminateProcess`) — with the same
"stdout is drained to EOF" property `captureAlloc` documents, since a
terminate that leaves a full pipe still deadlocks the reader.

## What landed

`git_run.zig` grew a `Deadline` — a watchdog thread per spawn that
`TerminateProcess`es the child if the capture has not finished within
`default_deadline_ms` (15 s, Mac's number). Terminating closes the child's end
of the pipe, so the blocked reader sees EOF and unwinds through the ordinary
path; nothing reaches into the reader's state. The watchdog is JOINED before
`child.wait()`, because the wait closes the handle the watchdog holds — that
ordering is the one invariant here, and it is written down where the struct is.

Both entry points are covered, not just the diff one: `capture` and
`captureAlloc` each delegate to a `…Deadline` variant, so every `git` the
viewer runs is bounded and no caller had to change.

The answer reaches the user as its own sentence. `Output.timed_out` rides back
with `ok = false`, `ViewerDiffProbe` turns it into a new
`viewer_diff.Failure.git_timed_out`, and the card says **"git did not answer"**
with "Reload to try again" — rather than borrowing `git_failed`'s "check the
revision names", which is advice about a revspec that is not wrong.

`git_run.zig` is now listed in `win32.zig`'s test block. It was imported and
compiled before, which is exactly the shape that lane list exists to catch: its
tests ran nowhere.

## Validation criteria

- [x] A unit test in the win32 lane: a child that never exits is given up on
      within the deadline and the capture returns — three tests in
      `git_run.zig` (the alloc form reports `timed_out` and `!ok` and returns
      well inside the bound; the fixed-buffer form returns at all; and a
      NEGATIVE control, a child that exits on its own under a 10 s deadline,
      which must come back `!timed_out` and `ok`). Green in the win32 lane.
- [x] The timeout test can actually fail: inverting its `timed_out` assertion
      made `zig build test -Dapp-runtime=win32` go red naming that test, and
      restoring it made it green — a deadline nobody has watched fire is
      indistinguishable from one that cannot.
- [x] `test/win32/viewer-diff.ps1` ALL PASS (65 assertions) — the deadline does
      not turn a cold `git diff` into a failure. First run of the pair failed
      one T817 assertion and passed it on an immediate re-run over the same
      build; that flake is filed as T1642, and it is not this change (nothing
      here touches diff navigation).
- [x] Floor: `floor-lane.ps1 -Lane all` — lib PASS, none PASS, win32 PASS;
      agent FAILED UNDER LOAD on the known T678 WebView2 host-floor test and
