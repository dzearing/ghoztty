# T3293 - A light panel with an app icon and the tab title sometimes paints into the tab strip's leading slot, partly under the active tab

## Summary

Found while fixing T1591 (2026-11-20). With `--window-show-tab-bar=always` and one tab, a synchronous `PrintWindow` of the window on the background test desktop shows the tab strip's leading slot (window x 0 to ~86 px at 160% scale, left of the active tab) in one of two states, and a single launch can flip between them a second or two after it shows:

- a dark rounded empty square (the expected leading slot), or
- a light grey panel carrying the app's icon and the start of the tab title (`C:\Users...`), clipped by the active tab's left edge. It looks like an inactive, classic-themed tab or caption drawn beneath the strip.

Measured with a probe capturing every 700 ms across three launches: lit pixels over the strip went 479 -> 1650 mid-launch in two of three. Because the active tab clips it, it seems to be painted by the strip itself (or a child window under it), not by another top-level window. Unknown: whether the input desktop shows it too, and what the panel is (a hidden or ghost tab, the sidebar toggle's hover art, a drag ghost).

title-font.ps1 used to sample that slot, and the flip scored a ~1000-column raster diff between two launches of the same font; since T1591 its signature starts past the slot. Re-measure the slot geometry there (`$lead` in title-font.ps1) if this fix changes it.

Next step: reproduce on the test desktop (launch, `Get-TestWindowPixels -Sync` every 700 ms, crop x 0-520 y 0-70), then find which paint path draws it.
