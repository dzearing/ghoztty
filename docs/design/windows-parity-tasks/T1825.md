# T1825 - Closing a pane or tab cannot be undone on Windows: Mac's undo (Cmd+Z within undo-timeout) brings the pane back with its session still running; Windows ends the session at once

## Summary

Found by T1791. On Mac, closing a split or tab registers an undo with the
window's NSUndoManager (`BaseTerminalController.swift`, `undoExpiration` =
the `undo-timeout` config). Within that window Cmd+Z brings the pane back, and
for a session-persistence pane the agent session stays alive and bound until the
undo expires. That is why Mac's chooser needed its `actionable` filter.

On Windows, `App.zig` lists `.undo` / `.redo` as macOS-only NSUndoManager
actions, and `+close` on a persistent pane ends its agent session at once
(T1791's chooser-sessions.ps1 section 3b printed `lingering attached: False`).
An accidental close is unrecoverable here.

Work: a Windows undo stack for close (pane, tab, window) honouring
`undo-timeout` that defers the agent CLOSE until the undo expires and
re-attaches the session on undo. Which key carries it is an experience call:
Ctrl+Z belongs to the shell on Windows, so Mac's Cmd+Z does not map 1:1.

## Validation criteria

- [ ] Closing a split and pressing the undo binding within `undo-timeout` brings the pane back in the same place, with its shell process still running (same pid).
- [ ] After `undo-timeout` passes, the session is ended at the agent (`+sessions` stops listing it).
- [ ] The chooser shows no Resume row for a closed pane during the undo window (T1791's filter, now exercised for real by chooser-sessions.ps1 3b).
