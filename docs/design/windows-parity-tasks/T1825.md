# T1825 - Closing a pane or tab cannot be undone on Windows: Mac's undo (Cmd+Z within undo-timeout) brings the pane back with its session still running; Windows ends the session at once

## Summary

Found by T1791. On Mac, closing a split or tab registers an undo with the
window's NSUndoManager (`BaseTerminalController.swift`, `undoExpiration` =
the `undo-timeout` config). Within that window Cmd+Z brings the pane back, and
for a session-persistence pane the agent session stays alive and bound until the
undo expires. That is why Mac's chooser needed its `actionable` filter.

On Windows, `App.zig` lists `.undo` / `.redo` as macOS-only NSUndoManager
actions, and `+close` on a persistent pane ends its agent session at once
(T1791's chooser-sessions.ps1 section 3b printed `lingering attached: False`).
An accidental close is unrecoverable here.

Work: a Windows undo stack for close (pane, tab, window) honouring
`undo-timeout` that defers the agent CLOSE until the undo expires and
re-attaches the session on undo. Which key carries it is an experience call:
Ctrl+Z belongs to the shell on Windows, so Mac's Cmd+Z does not map 1:1.

Scope as built: pane and tab closes (including Close Other Tabs / Close Tabs
to the Right, which undo as one group). A whole WINDOW close - and the last
tab's close, which closes its window - still ends at once; that half is
**T1874**. Mac's undo of non-close actions (new split/tab/window, pane moves)
is **T1875**. The key choice is decision **D95** (assumed Ctrl+Shift+Z /
Ctrl+Shift+Y).

## In plain terms

Closing a pane or tab by mistake on Windows used to throw away whatever was
running in it. Now, for five seconds (the `undo-timeout` setting), pressing
Ctrl+Shift+Z brings it straight back in the same spot with the program still
running; Ctrl+Shift+Y closes it again. Edit > Undo Close does the same from the
menu. If you do nothing, the close happens for real once the time is up.

## Goals

- [x] A closed split comes back in the same place with its shell still running
- [x] A closed tab comes back as a tab, title and colour intact
- [x] Redo closes it again; the undo window honours `undo-timeout` (0 = off)
- [x] Agent sessions are only ended when the undo expires (or the window/app goes away)
- [x] Undo/Redo reachable from the keyboard, the Edit menu and the command palette

## Design

- `close_undo.zig` (pure, every lane): an expiring per-window LIFO with groups,
  and the re-insertion `Anchor` - the closed leaf's sibling subtree by leaf
  set plus the parent split's layout/ratio/side, so a restore reproduces the
  layout exactly when nothing changed and still lands beside a surviving
  neighbour when something did.
- `CloseUndo.zig`: a close PARKS instead of freeing - the pane keeps one
  reference (a tab keeps its whole tree), its HWND is hidden, and nothing below
  it notices, so the shell, the ConPTY and the agent attachment all survive.
  Expiry (one `msg_hwnd` timer, `msg_timer.close_undo`) finalizes exactly as an
  immediate close used to: CLOSE intent, then the last unref. A window closing
  or the app quitting finalizes its own entries first, while the HWNDs they
  hide under still exist. A parked pane whose shell exits is let go at once.
- Mechanism calls made here (not experience decisions): parking rather than
  detach-and-reattach (works for local, agent, remote and viewer panes alike,
  and keeps the same pid by construction); IPC `+close` is undoable too, as on
  Mac (T1791's chooser test expects the lingering session); the chord is not
  forwarded from a focused viewer pane, whose page owns Ctrl+Shift+Z as its own
  redo - the Edit menu still works there.
