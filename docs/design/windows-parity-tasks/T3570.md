# T3570 - Linux L11h: the keyboard shortcut guide on GTK - show_keyboard_shortcuts opens a searchable guide built from the live keybinds

## Summary

Port docs/reference/keyboard-shortcuts.md: Help menu entry, the show_keyboard_shortcuts action (Linux default chord to match the platform convention, e.g. Ctrl+Shift+/ or Ctrl+?, recorded in the card) and the command palette entry open one guide window; data comes from the live keybind table (ghostty_config_keybinds_json / input action keys), filtered through the same curation layer; triggers drawn as keycaps; search and keyboard navigation; it reuses the Settings catalog. win32 counterparts: ShortcutGuideWindow.zig, shortcut_catalog.zig, shortcut_guide_layout.zig. GTK4 has GtkShortcutsWindow, but the content and curation must be ours.

## In plain terms

On Linux, the "show keyboard shortcuts" key did nothing - the app only
logged that it was not implemented. Now Ctrl+Shift+/ (GTK's own Ctrl+?),
"Keyboard Shortcuts" in the main menu, or the command palette opens a
Keyboard Shortcuts window like the Mac's and Windows': every shortcut you
actually have, by category, with its keys drawn as keycaps, a search that
takes words or keys ("ctrl shift p"), and a Run button for the safe ones.
Rebind something in your config and the window shows it as you reload.
