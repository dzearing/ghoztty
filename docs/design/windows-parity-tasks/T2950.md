# T2950 - 4K fold glide: one laid tick still costs 17-18 ms in 2-3 of 10 drags on the release (place ~11 ms + paint ~6 ms), so T2462's no-frame-over-16.7-ms clause misses by under 1 ms

## Summary

On published win-v1.54.17 (3efaca80b, carries T2942+T2946), 10 consecutive 4K drag-glide runs (3800x2100, travel 2600, step 24, release sandbox, ring trace; temp\t2462-soak17-4k.txt): glide-line max_us 15.6/17.1/17.4/12.2/15.8/13.0/13.4/14.1/15.9/15.1 ms, so 2 runs have a tick over 16.7. The worst-gap tick of run 2: place_us=10631 paint_us=6430 layout_us=1628 cards_us=1058, desk_full=false, owner=tick, gap 25.0 ms. T2946's own 10-run soak shows the same (max 16.9 and 17.9 ms in 2 runs) - its '0 over in 7394 ticks' read only the ticks the trace ring kept (see the measurement task filed beside this). Other-process CPU 0.8-1.9 cores per run (an idle-soak zig test and lane B were running), so re-measure with the box quiet before assuming it is the app's alone. Bring the heaviest laid tick under 16.7 ms with margin.

## In plain terms

Dragging a divider on a 4K screen until panes fold into strips mostly ran smoothly, but now and then one frame took a little longer than a 60 Hz screen allows, which shows as a small hitch. The cause: every frame copied the same patch of the window to the screen twice. Now it copies it once, so each frame's paint is about a quarter cheaper and the slow frames stop.

## Root cause

On the user's default window (with a redirection surface), each laid glide tick paints the desk twice: the vacated-strip paint, clipped to the box the moved panes left, and the band paint after it through an unclipped DC. Since T2732 the first one blits only what changed plus the window's invalid box. But it recorded EVERYTHING it blitted as still owed (`PaneDesk.carry`), and it never validated the box it had just made current. So the band paint blitted all of it a second time, plus `GetUpdateRect`'s box: the whole column the moved panes exposed, about 600 x 2023 px at 4K. A memo hit with `area=0` spent 4-6 ms in that blit on a quiet box (`stack trace bandpaint ... upd=2597,54,3199,2077 ... desk_out=40000-60000` QPC ticks), and 30-40 ms under load.

## Fix

- `PaneDesk.clip_box` + `Memo.Rects.minus`: a paint clipped to a box owes only what it blitted OUTSIDE that box.
- `clearVacatedPaneStrips` passes its box as `clip_box` and `ValidateRect`s the box after the paint, so the band paint's invalid box is what lies outside it (now `upd=0,0,0,0`).
- `GHOZTTY_VACATED_BOX_OWED=1` puts the old double blit back, for an A/B in one binary.
- `stack trace bandpaint` line: the band paint's invalid box going in, its desk phases, hit, why and area.
