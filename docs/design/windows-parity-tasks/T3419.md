# T3419 - Linux L9j: the GTK viewer's feedback button - which git worktree a pane's content belongs to

## Summary

Re-scoped 2026-11-22 when claimed: the whole of docs/reference/viewer-feedback.md is about ten thousand lines on win32, so it is split. THIS card is the first slice, the provenance and the button: a GTK viewer pane works out which git worktree its content belongs to (Mac strategy D - the viewed file's own directory; for an `http://localhost:PORT` page the listening process's working directory, read from `/proc/net/tcp{,6}` + `/proc/<pid>/fd` + `/proc/<pid>/cwd`, Linux's lsof; else the pane's `--working-directory`), resolves it to a repo root with `git rev-parse --show-toplevel` off the UI thread, caches it per (location, origin) for 15 s, re-resolves on every navigation, and shows an icon-only feedback button at the trailing end of the nav bar only while there is a worktree, tooltip `Send feedback to <root>`. Clicking it logs that the composer is T3544's.

The rest is filed: T3544 (composer + report folder), T3545 (quoting), T3546 (screenshots from the app's own render, sharing the capture with T3359).

## In plain terms

On Mac and Windows, a viewer pane showing something that lives in a git checkout grows a small feedback button in its toolbar, so you can file a note against that repo. On Linux the button did not exist. After this, it appears on Linux under the same rule - only when the page belongs to a checkout - and its tooltip says which one; the note-writing box it opens is the next card.
