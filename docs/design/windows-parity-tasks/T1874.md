# T1874 - Closing a whole window cannot be undone on Windows: Mac's undo brings back a closed window (and Close All Windows) with its tabs and sessions; Windows ends them at once

## Summary

T1825 made pane and tab closes undoable (parked for undo-timeout, restored with Ctrl+Shift+Z). A WINDOW close still finalizes immediately: Window.close() calls close_undo.finalizeWindow and ends every session. Mac registers 'Close Window' / 'Close All Windows' undos (TerminalController.registerUndoForCloseWindow). Closing the last tab of a window is the same case (removeTabSlot posts WM_CLOSE). Needs: park the window's tab trees (re-parent pane HWNDs to a hidden parking window, or hide the window itself and drop it from IPC/+list), restore as a new window at the old frame, and decide what the last window's close does when quitting is pending.

## In plain terms

Closing a whole Ghoztty window by mistake on Windows used to end everything
running in it. Now, for the `undo-timeout` (5 seconds by default), pressing
Ctrl+Shift+Z in any other Ghoztty window brings the closed window back where it
was, with all its tabs and programs still running. Closing the last tab of a
window counts the same way. The one exception is your very last window - see
decision D97.

## Goals

- [x] A closed window comes back at the same place and size, with the same tabs and running shells
- [x] Undo reaches it from any other window (and the Edit menu / palette)
- [x] Closing a window's last tab is undoable the same way
- [x] Redo closes it again; when the undo expires the window really closes and its sessions end
- [x] While waiting it is gone from `+list`, IPC targeting, the sidebars and the saved layout
- [x] The last window, Close All Windows, sign-out and the launch placeholder still close at once

## Design

- A closed window is PARKED whole: `ShowWindow(SW_HIDE)`, out of
  `App.windows` (so every list, `+list`, IPC lookup, sidebar scope and layout
  capture sees it gone), `closing` raised (input dropped), its renderers
  parked. Nothing inside it changes, so shells, ConPTYs and agent attachments
  all survive, exactly like a parked tab (T1825).
- Its entry is owned by a shared key (`shared_owner`), because the window it
  would be scoped to is the one that closed: `close_undo.Stack.popForEither`
  lets every window's undo reach it, in recency order with that window's own
  closes - Mac's app-wide undo manager ordering.
- IPC names pointing at the window or its panes are saved
  (`IpcRegistry.save`) and re-registered on undo, since the registry prunes
  targets that leave the live set.
- `Window.close` = park-or-`closeNow`; `closeNow` is the old immediate close,
  run by expiry, by programmatic closes (sign-out, the restore placeholder)
  and when a parked window is closed again (its last shell exited).
- Not parked: the last window (nowhere left to press undo - D97), the quick
  terminal, a window with nothing running, and Close All Windows (bypassed:
  its last window cannot park, so the rest would only wait to end).
- App quit finalizes parked windows right after the final layout write,
  while the window list and agent link their teardown reads are still up.

## Validation criteria

- [x] A second window closed with `+close` is hidden (HWND alive), leaves `+list`, and its shell keeps running; Ctrl+Shift+Z in the FIRST window brings it back visible, same HWND, same frame, same pid, its `--target` name listed. - `test\win32\close-undo.ps1` section 4w.
- [x] Redo (Ctrl+Shift+Y) closes it again with the shell alive; undo brings it back again. - close-undo.ps1 4w.
- [x] Closing the window's last pane parks the whole window; undo restores it with the same pane and pid. - close-undo.ps1 4x.
- [x] On expiry the HWND is destroyed and the shell exits; the other window is untouched. - close-undo.ps1 4y.
- [x] Agent-backed: the closed window's session stays alive+attached during the undo, and the agent ends it after expiry. - close-undo.ps1 section 8.
- [x] `undo-timeout=0` closes windows at once. - `close-undo.ps1 -NegativeControl` fails 24 assertions (8 of them window ones), as it must.
- [x] Pure parts unit-tested: `popForEither` (close_undo.zig) and `IpcRegistry.save` round trip.
