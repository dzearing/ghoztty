# T1590 - A config reload does all of its window work three times over

## Summary

Measured in T765: one reload_config chord runs the whole per-window rebuild THREE times - applyChromeTheme, applyBackgroundBlur, updateDimOverlays, refreshAllDividerBands, createTabFont/createPillFont (two HFONTs deleted and recreated each pass), invalidateTabBar and tabTipReset, once per pass. The fan-out is one app-level config_change plus one per surface, so it scales with pane count: a window with six panes rebuilds its chrome seven times for one keypress. Decide whether the per-surface config_change should reach the app-level handler at all, or whether onConfigChange should coalesce.

## In plain terms

Reloading your config (Ctrl+Shift+,) redrew each window's title bar, tabs,
dividers and fonts once for the app and once more for every pane - six panes
meant seven full redraws for one keypress. Now it happens once per window.
It also stops one pane's light/dark theme switch from quietly becoming the
whole app's config.

## Goals

- [x] the app-scoped `config_change` alone does the window-wide rebuild
- [x] a surface-scoped `config_change` no longer overwrites the app config
- [x] an acceptance assertion that counts the passes and fails on the old shape

## Decision

Mechanism call, not a user decision: the per-surface notification stops at the
apprt (`.surface => return true` in `App.zig`'s `config_change` arm) rather
than coalescing inside `Window.onConfigChange`. Every step of the rebuild reads
`self.app.config`, which only the app-scoped call changes, and the core's
`App.updateConfig` always ends with that call after the surfaces. A
surface-only soft reload (conditional color-scheme state) changes no app
config, so it owes the chrome nothing - and the old arm cloned that surface's
DERIVED config into `self.config`, a latent correctness bug. Mac's
`configChange` makes the same app/surface split.

## Validation criteria

- [x] one reload of a two-pane window rebuilds the window once - `split-divider.ps1` run 1, new assertion `one reload rebuilt the window once (update-region lines=1, app-wide passes=1, panes=2)`, ALL PASS (99 assertions) via `acceptance-parallel.ps1 run -Scripts split-divider.ps1`
- [x] the assertion fails on the old behavior - negative control: surface arm changed to fall through, rebuilt, re-run: `FAIL ... (update-region lines=3, app-wide passes=3, panes=2)`; fix restored
- [x] the live divider re-color still works and the reload leaves no dirty region - same run, the T252/T765 assertions green
- [x] floor lanes - `floor-lane.ps1 -Lane all`: lib/none/win32/agent PASS
