# T3148 - PA-I21: while a viewer is behind, the agent's writer thread refills up to 4 MiB from the rings under the store lock, stalling every session's output

## Summary

Audit-3 (T3101), area I, verified at d0d874326. catchUpLocked (src/remote/agent/server.zig:2584-2630) runs on the per-connection writer thread under the store lock and refills the DATA lane in catch_up_chunk pieces up to the 4 MiB room, each piece with a per-byte modulo ring read, three copies and two allocations. All sessions' output appends wait on the same lock for the whole pass. Fix: copy one piece per lock hold (drop and re-take between pieces), reuse one buffer, and read the ring with two memcpy spans (shares the PA-I04 ring fix, T3018). Detail: docs/design/perf-audit/audit-3/I-findings.md.
