# T2201 - upgrade-no-fork.ps1 auto-launches its sandbox copy of the app on the user's desktop (Run-Sandbox +new-window)

## Summary

Found by T1267's widened desktop-launch sweep. `test\win32\upgrade-no-fork.ps1`
copies the repo build into a sandbox install (`$sandboxExe = Join-Path
$installDir 'ghoztty.exe'`) and drives it through `Run-Sandbox`, a `cmd /c`
wrapper. Section B calls `Run-Sandbox "+new-window --target=main ..."` from
cold, which auto-launches the sandbox app on the CALLER's desktop - the user's
screen. The audit never saw it because `$sandboxExe` does not match the old
`exe` suffix rule (`x` precedes `exe`), and the script owns no test desktop.

Fix: route the sandbox launches through the harness (`Invoke-OnTestDesktop`,
or a `Start-OnTestDesktop` of `cmd.exe` so the inherited desktop carries the
auto-launch), then delete its `@user-desktop-launch` entry in
`lib\TestDesktop.ps1` - the sweep fails a stale declaration, so the entry
cannot outlive the migration.

## Validation criteria

- [ ] upgrade-no-fork.ps1 ALL PASS run on the test desktop, with no repo ghoztty window on the interactive desktop during the run
- [ ] its `pending migration (T2201)` declaration is removed and desktop-launch-audit.ps1 stays ALL PASS
