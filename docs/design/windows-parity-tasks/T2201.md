# T2201 - upgrade-no-fork.ps1 auto-launches its sandbox copy of the app on the user's desktop (Run-Sandbox +new-window)

## Summary

Found by T1267's widened desktop-launch sweep. `test\win32\upgrade-no-fork.ps1`
copies the repo build into a sandbox install (`$sandboxExe = Join-Path
$installDir 'ghoztty.exe'`) and drives it through `Run-Sandbox`, a `cmd /c`
wrapper. Section B calls `Run-Sandbox "+new-window --target=main ..."` from
cold, which auto-launches the sandbox app on the CALLER's desktop - the user's
screen. The audit never saw it because `$sandboxExe` does not match the old
`exe` suffix rule (`x` precedes `exe`), and the script owns no test desktop.

Fix: route the sandbox launches through the harness (`Invoke-OnTestDesktop`,
or a `Start-OnTestDesktop` of `cmd.exe` so the inherited desktop carries the
auto-launch), then delete its `@user-desktop-launch` entry in
`lib\TestDesktop.ps1` - the sweep fails a stale declaration, so the entry
cannot outlive the migration.

## In plain terms

One of the upgrade tests opened a copy of the terminal on the user's own screen
every time it ran, which pulled focus from whatever they were doing. It now
runs that copy on a hidden background desktop, the way the other tests do.

## Goals

- [x] every sandbox CLI call (`Run-Sandbox`) runs on the test desktop through `Invoke-OnTestDesktop`
- [x] the upgrade script itself runs there too, so the app it kills and relaunches comes back on the test desktop
- [x] the `@user-desktop-launch` pending-migration entry is gone

## Validation criteria

- [x] upgrade-no-fork.ps1 ALL PASS run on the test desktop, with no repo ghoztty window on the interactive desktop during the run: ALL PASS (131 assertions), three times. A watcher on the user's `Default` desktop (`EnumWindows`, scanning every sandbox `ghoztty.exe` pid, with a positive control that saw 32 windows of the user's own Ghoztty) found **no** app window (`GhozttyWindow` or any other ghoztty class) from any of the 10 sandbox processes. A probe of the same helper path (`Invoke-OnTestDesktop +new-window`) confirmed that an auto-launched app has zero windows on `Default`. The one residue is not an app window: a `PseudoConsoleWindow` attributed to each app the UPGRADE SCRIPT relaunches, which is the Debug console-subsystem exe's new console being handed to Windows Terminal. That is a separate mechanism in `scripts\upgrade-ghoztty-windows.ps1`, filed as T3694.
- [x] its `pending migration (T2201)` declaration is removed and desktop-launch-audit.ps1 stays ALL PASS: removed from `lib\TestDesktop.ps1`; `desktop-launch-audit.ps1` ALL PASS (66), E1 no undeclared launch site, E2 no stale declaration.
