# T3723 - Win32 remote web viewer: WebView2 WebResourceRequested sends a remote page's requests through WEB_REQUEST, on its own origin

## Summary

T2221 landed the agent half of decision 3 (the web_tunnel capability, WEB_REQUEST..WEB_CLOSE 0x88-0x8c, src/remote/agent/web_tunnel.zig). The win32 viewer still never calls it. For a viewer bound to a remote session: register a WebResourceRequested filter for a page served on a dedicated virtual host (not ghoztty-page, so storage and cookies never mix with local pages), send each request as WEB_REQUEST through the session's agent Connection (rpcCall parks on web_response/web_data), pull held bodies with WEB_READ and WEB_CLOSE them, and hand WebView2 a response with status, reason and headers. Against an agent without web_tunnel the pane says the page has no network rather than loading it from this machine. Acceptance over a loopback agent serving a localhost page with a relative script and a redirect.
