# T1713 - Test runs of go-loop-exec resume write forced re-entries into the REAL watchdog log (resume forwards -LockPath/-StopPath/-StatePath but not -LogPath/-TaskDir)

## Summary

Found during T1711 (2026-09-23). `%TEMP%\ghoztty-go-loop-watchdog.log` holds lines no real watchdog wrote: `16:37:52 forced: re-entry ... last pane=PANE-H (closed) ... fake-ghoztty-app-gone.cmd`, `16:41:17 ... LAUNCH-APP FAILED: could not start ...\gz-stop-21001914
o-such-ghoztty.exe`, and `16:44:26 forced ... nudge live session in pane 492C135B-... remaining=479`. These came from go-loop-guard and go-loop-resume. Their `Dog-Run` passes `-LogPath`, but `go-loop-exec.ps1 resume` (scripts\go-loop-exec.ps1, the `$dogArgs` block) forwards only `-LockPath/-StopPath/-StatePath/-GhozttyExe`. So a hermetic test that goes through `Exec-Run resume` gets a watchdog logging to the real log and counting the real task dir (`remaining=479`). Nothing was typed into a real pane: 492C135B is the test's own isolated app pane. But a reader of the real log sees a forced nudge into an unknown pane, which cost this turn a detour. The log is also what `go-loop-health` and incident write-ups read.

Fix: add `-LogPath` and `-TaskDir` params to go-loop-exec.ps1 and forward them in `resume`, with the history ledger path too if it is not already derived from the lock dir. Then pass them from the test harnesses' `Exec-Run`.

## Validation criteria

- [ ] A go-loop-resume + go-loop-guard run adds ZERO lines to %TEMP%\ghoztty-go-loop-watchdog.log (line count before/after, asserted in the harness)
- [ ] The forced tick in the test reports the fixture task count, not the real queue's
