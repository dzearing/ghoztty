# T2938 - +close --force on Windows: close with no confirmation and no undo window, and a +close left waiting on a close confirmation fails instead of reporting success (Mac 4b558ab8f)

## Summary

Mac 4b558ab8f (main, 2026-11-12): +close now runs the close before replying, and a close left waiting on a 'Close Terminal?' confirmation FAILS with 'waiting on a close confirmation' instead of answering success (scripted windows piled up off screen). New +close --force dismisses any confirmation, closes with undo disabled, marks every pane's agent session to END and frees each pane's core at once, so the process exits now; a window target closes its whole tab group; older apps ignore the flag. Port both halves to the win32 IPC close handler (close-confirm dialog + close-undo window + agent session end), document --force in src/cli/close.zig + docs/claude/cli.md, and cover it with an acceptance script (close-confirm / close-undo harnesses are the neighbours). Reference: docs/reference/cli-commands.md '+close' on main, macos/Tests/IPC/CloseWindowTests.swift.
