# T1025 - Nothing notices a DUPLICATED log entry, which is the price union merge trades a conflict for

## Summary

T957 put docs/design/windows-parity-log.md and windows-parity-feature-ideas.md under git's union merge driver, so a two-seat collision now merges silently instead of conflicting. That is the right trade - the conflict was always resolved by keeping both entries - but union is not free: a rebase that replays a commit whose entry is already in the file, or a hand edit to an old entry made on both seats, produces the SAME entry twice and nothing anywhere is obliged to notice. A conflict at least stopped somebody. Add a duplicate-entry check to parity-tasks.ps1 validate (or a small sweep it calls): for each union-merged ledger, flag two entries with the same date+task id, or two identical lines longer than N characters. Cheap, and it restores the 'somebody looks at it' half that the driver removed.

## In plain terms

Two shared history files are merged automatically so the two machines never
have to stop and resolve a clash in them. The catch is that an automatic merge
can quietly leave the same entry in the file twice, and nothing would ever say
so. After this lands, the check that runs before every commit points at the
doubled entry by file and line.

## Goals

- [x] a scanner that finds a doubled entry, a heading reused over a different body, and a line repeated inside one entry
- [x] it checks whichever ledgers `.gitattributes` puts under `merge=union`, so a new ledger is covered from the day it joins
- [x] `parity-tasks.ps1 validate` fails on it, under its own headline
- [x] a real union merge is shown producing exactly the duplicate it catches

## Validation criteria

- [x] The scanner finds each of its three findings in both entry shapes the log uses (dated bullets and `##` headings), and stays quiet on the two legitimate repeats measured in the live log: one task with several entries on one day, and a floor sentence recurring across entries. Verified by `test/win32/ledger-dupes.ps1` section A.
- [x] The ledger set is read from `.gitattributes` (`.md` + `merge=union`), skipping commented lines, non-union files and `.gitignore`. An empty set is exit 2, never a silent CLEAN. Verified by section B.
- [x] The live ledgers are clean: 1292 entries in 2 ledgers, about 1 second. Verified by section C.
- [x] A real `git merge` under `merge=union` exits 0 and leaves one entry doubled, and the scanner reports it. Two seats holding the same two entries in opposite order are enough. Verified by section D.
- [x] `validate` is driven red through its relay as `DUPLICATED LEDGER ENTRY` with the ledger and line, and falls quiet once the copy is removed. Verified by section E. The label is registered as a gate in `test/win32/gate-negatives.ps1` (58/58).
- [x] `-NegativeControl` doubles the last entry of a copy of the live log and scores exactly 1 failure.
