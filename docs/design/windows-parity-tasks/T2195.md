# T2195 - The applier-sandbox harnesses re-point the dev ghoztty-debug:// link handler at a temp directory they then delete

## Summary

update-apply, update-auto-apply and update-failure-visible all end with the applier relaunching ghoztty.exe out of New-ApplierSandbox's temp dir, and a Debug build registers HKCU\Software\Classes\ghoztty-debug wherever it runs - so after any of them the dev build's links open a deleted exe until the next zig-out launch re-registers. T1242 hit it in update-consent.ps1 and set GHOZTTY_URL_SCHEME=off there. Fix once in lib\ApplierSandbox.ps1 (New-ApplierSandbox sets GHOZTTY_URL_SCHEME=off for the run, restored on teardown), re-run the three harnesses, and assert the registration is unchanged after a run.
