# T1499 - The cache heal names a torn package it cannot delete, so every lane re-runs into the same failure

## Summary

On 2026-09-12 all four floor lanes died with 'failed to check cache: ...\p\<hash>\fonts\ttf\JetBrainsMono-Regular.ttf file_hash FileNotFound'. Get-TornCacheEntry DID find the package - the lane printed 'healed 0 torn cache entr(y/ies)', a line that only prints when it found one - and Invoke-CacheHeal's delete then threw: the package held AppleDouble sidecars ('._.', '._fonts', '._AUTHORS.txt'), and a file literally named '._.' defeats both the PowerShell delete cmdlet and the cmd.exe recursive-directory command (both resolve that name to the directory itself and report it missing, then refuse the non-empty parent). Only [System.IO.File]::Delete over a '\\?\' path removed it, by hand, after four red lanes. So the heal reports FAILED, returns 0, re-runs the lane once, and the box stays red until a human who knows the trick shows up - which is the whole failure the heal exists to prevent. Fix: give Invoke-CacheHeal a delete that survives these names ('\\?\'-prefixed IO, or a robocopy mirror-from-empty purge), and prove it with a negative control that plants a '._.' file inside a fake package dir. Check the same delete path in build-cache.ps1 clear. Second, smaller finding from the same hour: once the partial delete had removed '._fonts', build-cache.ps1 check reported the cache CLEAN while the package was still broken - the orphan-sidecar heuristic only fires on '._X' with no 'X', so a package missing a whole subtree and no sidecar is invisible to it.

## In plain terms

When a downloaded dependency lands on disk half-extracted, every build on the
box fails at once, and the repair that is supposed to happen by itself could
not: it tried to delete the broken folder, one file inside it had a name
Windows' ordinary delete cannot address, and so the folder stayed and every
retry hit the same wall. The only way out was somebody who knew the trick
deleting it by hand. Now the repair uses a delete that cannot be beaten by a
filename, and if it somehow still cannot finish it leaves a note behind so the
next health check says "broken" instead of "fine".

## Goals

- [x] the automatic heal deletes a torn package whose contents include a
      file named `._.`
- [x] the whole-cache clear (`build-cache clear`) takes the same delete
- [x] a heal that cannot finish is visible to the next `build-cache check`
      instead of reading as a healthy cache
- [x] the harness plants a real `._.` file, so the hard case is actually
      covered rather than apparently covered
