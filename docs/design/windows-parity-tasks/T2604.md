# T2604 - Claude Code installed AFTER Ghoztty never gets the Ghoztty skill: the first-run agent offer is one global accepted/declined bit, so accepting it for Copilot burns it for Claude forever. Offer per agent, once, the first time each agent is detected (launch probe AND when a pane starts that agent), and name the palette entry so 'skill', 'claude', 'copilot', 'plugin' all find it

## In plain terms

If you set up Ghoztty's skill for one coding agent (say Copilot) and install
another one later (Claude Code), Ghoztty never offered to set up the new one,
and searching the command palette for "skill" found nothing. Now each agent
is offered setup once, the first time Ghoztty sees it: at the next launch, or
as soon as you open a new pane after installing it. The palette's
"Set Up Agent Integrations…" row is found by "skill", "claude", "copilot",
"plugin" and "hooks".

## Goals

- [x] the offer is answered per agent, so a later agent is still offered once
- [x] a box answered by an older build is carried over without re-asking what it decided
- [x] a new pane re-checks, so an agent installed mid-session is offered without a relaunch
- [x] the palette finds the setup by the words people search for
- [x] the Mac half is filed (T2613)

## Summary

`AgentIntegration.zig`'s offer (T870) wrote ONE answer (`claude_setup`)
after the first prompt and never prompted again, so an agent installed after
it was never offered. Fix:

- **Per-agent answers** in `<state dir>\agent_offer_<agent>`; the rule is the
  pure `agent_offer.zig` (`decide`). An agent already set up (installed,
  outdated, or plugin-managed) is recorded accepted and never asked; an
  undetected one is never offered and never spent; the prompt names, and
  spends, only the still-unanswered detected agents.
- **The old answer is folded in once** (`agent_offer_migrated` marker):
  "declined" stands for the agents detected at that launch; "accepted" decides
  nothing (an agent not set up was either unticked or not installed yet, which
  cannot be told apart, so it is asked once more rather than never - the
  user's exact case). `claude_setup` is still written, so an older build run
  afterwards finds the offer answered.
- **Re-check on a new terminal pane** (`recheckSoon`, called from
  `Surface.init`): spaced 60 s from the last check, off-thread, cheap file
  reads first, never raises the plugin-migration offer. Chosen over watching
  the pane's title or process: Claude Code titles the pane with the
  conversation's topic, and an npm-installed agent runs as `node.exe`, so
  neither names the agent; an installer's PATH edit is only seen by a new
  shell anyway, which is a new pane.
- **Palette keywords** on "Set Up Agent Integrations…": skill skills claude
  copilot plugin hooks banner install integration. A second "Install Ghoztty
  skill for Claude Code" row was NOT added: the keywords make the one row
  findable, and a second row would open the same window.

Point 2 of the report (the old public plugin repo) is archived and its
discovery story is T2605; point 3 is T2605.
