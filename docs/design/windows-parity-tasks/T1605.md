# T1605 - The app exits 0xFFFFFFFF after its own close button, so every caption-bar run ends on a CRASHED postmortem

## Summary

caption-bar.ps1 ends ALL PASS and exit 0, but its GUI postmortem reports 'CRASHED - 0xFFFFFFFF unnamed NTSTATUS' for the app it closed. Reproduced on 2026-09-16 against b9d0971eb WITHOUT the T786 edit, so it is not that change. The stderr tail ends on a complete line after a clean surface teardown (GL context cleaned up, DC released, 'surface deinit: complete'), so the process is getting all the way through shutdown and then returning -1 rather than 0. 0xFFFFFFFF is not an NTSTATUS, so ConvertTo-GuiExitVerdict names it 'unnamed' - structurally a crash because the high bit is set. Either the exit path returns -1 (a wParam or a std.process.exit default) and should return 0, or something is terminating it. Until it is one or the other, every GUI script that closes a window teaches its reader to ignore the postmortem block, which is the one thing that block must not become.
