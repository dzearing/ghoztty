# T3249 - Mac half of T3239: check whether programs run in an agent-held pane get a background QoS clamp under launchd, and opt them out if so

## Summary

T3239 found that on Windows the programs a user runs in an agent-held (persisted) pane were put in efficiency mode by the OS classifier, because nothing in their process tree owns a window: a 7.7 MB burst took 11-16 s against ~5.5 s in a local pane, and an opt-out on the holder alone did not reach them (not inherited). Fixed on Windows by opting out every process that joins the PTY job (JOB_OBJECT_MSG_NEW_PROCESS -> SetProcessInformation(ProcessPowerThrottling)). The macOS agent runs as a LaunchAgent; launchd's ProcessType and the inherited task QoS / darwin role may clamp the shell and its children the same way (Background/Utility QoS, E-cores on Apple silicon, I/O throttling). Do: measure a big output burst in an agent-held pane against a local one on Mac debug and release builds (the pane-ingest-ab shape), read the QoS of the shell and its children, and if they are clamped give the PTY children the interactive class (posix_spawnattr_set_qos_class_np, PRIO_DARWIN_BG off, or ProcessType Interactive for the agent, whichever is the right lever). Record the measurement either way.
