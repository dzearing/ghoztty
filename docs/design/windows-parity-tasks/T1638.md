# T1638 - the ctrl_handler slot is read without a lock and has no draining clear

## Summary

T814 gave the three PUSHED handler slots (metrics, session_cpu, sessions) a draining unsubscribe. The fourth slot, ctrl_handler, was left as it was and is weaker in two ways: controlReaderLoop reads it with NO lock at all (if (self.ctrl_handler) |handler|), where the push slots are read under write_mutex; and there is no clearControlHandler at all, so a caller that wants to free the ctx it registered has no call that promises no handler is in flight. Today every ctrl_handler ctx outlives its Connection, so nothing is broken - this is the same latent shape T814 fixed, one slot along. Fix: read it under write_mutex with pushEnter/pushLeave like the others, add clearControlHandler that nulls and drains, and point setControlHandler's doc comment at it.
