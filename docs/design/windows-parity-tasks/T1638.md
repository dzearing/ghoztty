# T1638 - the ctrl_handler slot is read without a lock and has no draining clear

## Summary

T814 gave the three PUSHED handler slots (metrics, session_cpu, sessions) a draining unsubscribe. The fourth slot, ctrl_handler, was left as it was and is weaker in two ways: controlReaderLoop reads it with NO lock at all (if (self.ctrl_handler) |handler|), where the push slots are read under write_mutex; and there is no clearControlHandler at all, so a caller that wants to free the ctx it registered has no call that promises no handler is in flight. Today every ctrl_handler ctx outlives its Connection, so nothing is broken - this is the same latent shape T814 fixed, one slot along. Fix: read it under write_mutex with pushEnter/pushLeave like the others, add clearControlHandler that nulls and drains, and point setControlHandler's doc comment at it.

## In plain terms

The part of Ghoztty that talks to its background session agent hands every
control message to a registered listener. Nothing let a listener be removed
safely: the slot was read without a lock, and there was no "remove and wait"
call, so code that wanted to tear its listener down could free it while a
message was still being handled. Nothing crashes today (every listener lives as
long as the connection), so no user notices; this closes the gap before
anything starts relying on it.

## Goals

- [x] the control reader reads the handler and its ctx under `write_mutex`, counted as an in-flight dispatch
- [x] `clearControlHandler` nulls the slot and drains a running dispatch (and does not wait on itself)
- [x] `setControlHandler` publishes handler and ctx together and points at the clear

## Validation criteria

- [x] a clear issued while the handler is running returns only after it finishes - `remote.connection.test.T1638: clearControlHandler waits for a handler that is already running`, none lane (`-Dtest-filter=T1638`, dump confirmed both T1638 tests matched)
- [x] negative control: with `drainPush(.control)` commented out that test FAILS (`rec.finished` false), restored it passes
- [x] a handler that clears itself on the reader thread does not deadlock - `T1638: a control handler may clear itself without deadlocking`
