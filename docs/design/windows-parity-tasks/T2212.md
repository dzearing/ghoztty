# T2212 - Whole-capture pixel helpers default to the whole window, the region T1115 showed chrome alone can satisfy

## Summary

Get-TestBrightness, Get-TestDistinctColors and Get-TestCaptureContent (lib\TestDesktop.ps1) and HoverCapture Changed score the whole capture unless the caller passes a rect. Every current caller is a lenient gate or passes a window that IS the subject (T1281 inventory), but the default invites the T1115 shape. Make the region an explicit argument (or name the whole-capture default in each helper's contract) and update callers. TestDesktop.ps1 is a shared library, so this forces a full harness sweep. Found by the T1281 inventory.

## In plain terms

The test helpers that ask "does this screenshot have real content in it?" used
to look at the whole window unless told otherwise. The window's own frame (title
bar, tabs, borders) is busy enough to pass that question even when the part a
test cares about is blank, so a test could pass while the thing it checks was
broken. Now every test has to say which region it means, or say outright that
it means the whole window.

## Goals

- [x] Get-TestBrightness, Get-TestDistinctColors, Get-TestCaptureContent take `-Rect` or `-Whole`, and throw on neither / both
