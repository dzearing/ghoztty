# T2973 - PA-R07: each new glyph re-uploads the whole font atlas texture in every pane that shares the font, and the atlas never shrinks

## Summary

PA-R07 (audit-1, T2959). font/Atlas.zig:274 bumps `modified` on every set; generic.zig:2005-2020 then calls syncAtlasTexture, which replaceRegion()s the entire atlas (generic.zig:3906) in every pane on its next draw. Growth doubles with no shrink path (Atlas.zig:366 clear does not reclaim). Cost estimated: 256 KB (R8) or 1 MB (BGRA) per new glyph per pane at 512^2, 4/16 MB at 2048^2. Fix: track a dirty rectangle in Atlas and upload only that (sharing the texture across panes is PA-R03). Risk low. Shared code: Mac half filed with the shared-renderer Mac task.

## In plain terms

Every time a pane draws a character it has never drawn before (a new CJK
ideograph, an emoji), the whole font picture the GPU keeps was sent again -
up to several megabytes - for every pane using that font. Output full of new
characters therefore got slower the more panes were open. After this, only
the strip of the picture that actually changed is sent.

## Goals

- [x] the atlas remembers which rows each recent change touched
- [x] a pane uploads only the rows changed since it last synced, falling back to a full upload when it has never synced, the texture was recreated, or the gap is wider than the history
- [x] measured: CJK-heavy output costs less GPU than before (two A/B pairs, below)

## Not in scope

- The atlas still never shrinks (Atlas.clear does not reclaim memory) - that is a memory question, not an upload one; sharing one texture across panes is PA-R03.

## Validation criteria

- [x] a unit test asserts Atlas reports a dirty rect covering only the glyph region set since the last sync - four `dirty rows:` tests in src/font/Atlas.zig (single set, union + mid-sync consumer, gap wider than the log, grow/clear = whole atlas); none lane green via floor-lane -Lane all
- [x] perf-baseline.ps1 -Phase busy with a CJK/emoji-heavy file shows less GPU upload time than baseline - added `-BusyText cjk` (40-ideograph UTF-8 lines walking U+4E00..U+9FFF, typed under chcp 65001).
