# T1525 - Rearrange mode: drag a pane by its header into another split, tab or window

## In plain terms

On the Mac you can now turn on "rearrange mode": every pane grows a small header
you can grab, and you drag panes around — into a different split, onto another
tab, or into a different window entirely — with a highlight showing where the
pane will land. Windows has no equivalent, so moving a pane means closing it and
opening a new one somewhere else.

## Summary

Mac's implementation (`macos/Sources/Features/Splits/`: `PaneDragSession`,
`PaneDragSource`, `PaneDropFeedbackView`, `PaneDropResolver`, `PaneHeaderView`,
`PaneMoveCoordinator`, `RearrangeModeState`, plus `SplitTree` rearrange support)
is the reference for the behavior, not for the mechanism — the Windows build
gets a win32-native drag, per the platform-symmetry rule. The drop resolution
logic (which edge of which pane a drop lands on, and what the resulting tree is)
is the part worth porting as shared, testable logic: Mac covers it with
`PaneDropResolverTests` / `SplitTreeRearrangeTests`.

## Goals

- [ ] Rearrange mode gives every pane a grab header.
- [ ] A pane can be dragged to another position within the same split tree.
- [ ] A pane can be dragged onto another tab.
- [ ] A pane can be dragged into another window.
- [ ] A drop target is previewed before the mouse is released.

## Validation criteria

- [ ] Unit tests in the `none` lane cover drop resolution and the resulting split tree.
- [ ] An acceptance script in `test/win32/` performs a real drag and asserts the pane moved.
- [ ] Both zig test lanes, `test-agent` and the `lib` build stay green.
