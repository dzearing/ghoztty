# T2326 - Prove T2320 on real releases: the next two win-v releases published on one day install over each other through the in-app updater (msiexec 0, ARP Version rises)

## Summary

T2320 changed the MSI ProductVersion to yy.m.dNNN with a clock-derived within-day number; its on-box two-MSI upgrade was NOT RUN (wixl is Docker-only here). When two releases land on one UTC day, read back: both releases' MSI ProductVersion (msiinfo / Get-MsiProperty) rising, the in-app update from the first to the second exiting 0 in ghoztty.log, and HKCU Uninstall Version rising (scripts\arp-version-check.ps1).

## In plain terms

When two Windows updates come out on the same day, the second one used to be
refused by Windows Installer, so people stayed on the morning's build. This
checks, on the user's own machine and on real published releases, that the
second update of a day now installs over the first.

## Goals

- [x] read the version Windows Installer compares from real same-day release MSIs
- [x] read the in-app updater's own record of installing one same-day release over another
- [x] read back what Windows registered after the second install

## Validation criteria

- [x] **Same-day releases carry rising ProductVersions** - downloaded the published MSIs with `gh release download` to scratch and read the Property table read-only (WindowsInstaller COM, `OpenDatabase` mode 0; nothing installed). 2026-11-02 UTC: win-v1.52.6 `26.11.2558` < win-v1.52.7 `26.11.2578`. 2026-11-03 UTC: win-v1.52.8 `26.11.3497` < win-v1.52.9 `26.11.3514`. All four share UpgradeCode `{5EB02044-7F06-498B-B7A9-7EFD65486CFB}` with distinct ProductCodes, and ARPDISPLAYVERSION is the release number.
- [x] **The in-app updater installed the second over the first and msiexec exited 0** - `%LOCALAPPDATA%\ghoztty\ghoztty.log`: 2026-11-03T16:45:57Z auto-install win-v1.52.8 -> `msiexec succeeded` 16:46:17Z, relaunch; 17:47:17Z auto-install win-v1.52.9 (same UTC day) -> `msiexec succeeded` 17:47:59Z, relaunch pid 8152. 2026-11-02 shows a four-release same-day chain 1.52.4 -> 1.52.5 -> 1.52.6 -> 1.52.7, every one `msiexec succeeded`.
- [x] **Windows registered the newer version** - `scripts\arp-version-check.ps1` (read-only) on the user's install: product `{D1A16C05-...}` registry Version `26.11.3514` = package ProductVersion, display `1.52.9`, unfused; the 1.52.8 product `{1BED4CFD-...}` has no cached package any more, i.e. the major upgrade removed it. `ghoztty.com +version` reads `1.52.9+72a471b21`.
- [x] **Side finding, already tracked**: the same run lists 45 `Ghoztty` products, 44 of them orphan listed HKCU entries (one per update since 1.43.4) with no cached package, so arp-version-check exits 1. That is T2327 (filed at 8 entries); journaled the growth there rather than filing a duplicate.
