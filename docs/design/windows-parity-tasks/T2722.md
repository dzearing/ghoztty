# T2722 - Check every default Claude Code chord reaches a Claude-style raw-mode reader on Windows with the bytes macOS sends (T2693 found Ctrl+Enter/Shift+Enter flattened; nothing sweeps the rest)

## Summary

T2693 showed a whole class: Claude Code reads VT bytes and picks key forms by terminal (kitty / modifyOtherKeys on `ghostty`), and ConPTY's Win32 Input Mode can flatten a chord before it arrives. The fix covered modified Enter/Tab/Backspace/Escape. Nothing checks the rest of Claude Code's default bindings (Ctrl+letter chords, Alt+letter, Shift+Tab, Ctrl+Left/Right, Escape twice, Ctrl+X Ctrl+S, Alt+V image paste - see T2694).

Extend `test\win32\kitty-key-bridge.ps1` (or a sibling) with a table: for each default chord, the bytes a macOS Ghoztty writes under kitty flags 1 + modifyOtherKeys 2, and assert the Windows reader receives an equivalent the program decodes the same (same key + modifier bits; Ctrl+letter as C0 is acceptable where Claude Code treats both alike). Read the binding list from Claude Code's own defaults, not memory. File each mismatch as its own task.

## Validation criteria

- [ ] a table-driven arm sends every default chord and records what arrives
- [ ] each chord either matches the macOS decoding or has its own filed task
