# T3350 - Linux: under WSLg the app renders on llvmpipe (software) unless GALLIUM_DRIVER=d3d12 is set; pick the GPU by default

## Summary

Measured 2026-11-21 (T3330): glxinfo -B and the GTK app both report llvmpipe by default; with GALLIUM_DRIVER=d3d12 both report D3D12 (NVIDIA GeForce RTX 4090) and the app loads OpenGL 4.6. /dev/dxg and /usr/lib/wsl/lib exist. A user launching ghoztty in WSL gets a slow software renderer (and the low_power path treats it as software). Fix: at startup on Linux, when /dev/dxg exists and GALLIUM_DRIVER / MESA_LOADER_DRIVER_OVERRIDE are unset, set GALLIUM_DRIVER=d3d12 before GTK creates its GL context (and do not leak it into child shells), or document why not. Validate with test/linux/gtk-smoke.sh minus its own GALLIUM_DRIVER export: the app log's 'loaded OpenGL' line names D3D12.

## In plain terms

On Windows' Linux subsystem the Linux build of Ghoztty drew everything with the
CPU, because the graphics library there does not pick the real graphics card on
its own. It now asks for the card itself, so the terminal renders on the GPU
out of the box, and that choice stays private to the app: the shells it opens
see the same environment they always did, and a user who picked a driver
themselves keeps theirs.

## Goals

- [x] the app renders on the GPU under WSLg with nothing exported
- [x] the override never reaches a shell, the agent, or WebKit's web processes
- [x] a driver the user chose (GALLIUM_DRIVER, MESA_LOADER_DRIVER_OVERRIDE, LIBGL_ALWAYS_SOFTWARE) wins
- [x] the test harness stops exporting the variable to the app, so every GUI test runs the default path
