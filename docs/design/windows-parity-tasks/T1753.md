# T1753 - Palette shows Ghostty default commands that do nothing on Windows; Mac hides unsupported ones (isSupported)

## Summary

Follow-up of T1752. Mac's terminalOptions filters command-palette-entry commands through Ghostty.Command.isSupported, so a default whose action the Mac apprt does not perform never shows. The win32 palette now shows every config entry except defaults the registry covers (commands.coversDefault), so any remaining default whose action the win32 apprt does not implement (a macOS-only action, e.g. secure input or a mac-only toggle) is a row that does nothing when run. Enumerate the survivors of coversDefault, check each against what the win32 apprt actually performs, and hide the unsupported ones with a none-lane test naming each. Validation: none-lane test over the survivor list; an on-box palette-order arm that filters to one known-unsupported default and asserts no row.

## In plain terms

The command palette listed some commands that do nothing on Windows, such as
"Undo", "Redo" and "Toggle Secure Input" (Mac-only features). Choosing one
closed the palette and nothing happened. Now they are not listed, the same way
Mac hides the commands it cannot run.

## Goals

- [x] name every palette action the Windows app acknowledges but does not perform
- [x] hide config palette entries running one of them (defaults and the user's own, as Mac does)
- [x] keep actions Mac hides but Windows performs (window decorations, tab overview) listed

## Validation criteria

- [x] none lane: `isSupported` hides exactly the six defaults named in the test (Redo, Show On-Screen Keyboard, Show the GTK Inspector, Toggle Inspector, Toggle Secure Input, Undo), and every unsupported action has a default - `scripts\floor-lane.ps1 -Lane all` none + win32 lanes PASS
- [x] on box: `test\win32\palette-order.ps1` O9 - a supported config entry runs (control), the same entry with `undo` is absent, and "Toggle Secure Input" is absent - ALL PASS (53); negative control (filter line removed, `zig-out-neg1753`) FAILS O9b and O9c exactly, O9a still passes
- [x] floor: `scripts\floor-lane.ps1 -Lane all` green (lib/none/win32/agent PASS), harness lane PASS, ipc-p1/p2/p3 ALL PASS, close-confirm-idle/remote-disconnect/menu-bar/kb-actions ALL PASS

## Design note

The unsupported set is an explicit list in `commands.zig`
(`unsupported_actions`), mirroring Mac's `Ghostty.Command.unsupportedActionKeys`.
It is the actions App.performAction acknowledges with `return true` and no
effect: `toggle_secure_input`, `undo`, `redo`, `show_gtk_inspector`,
`show_on_screen_keyboard`, `inspector`. Mac's own list differs where the
frontends do: win32 performs `toggle_window_decorations` and
`toggle_tab_overview` (hero mode), so those stay. The filter applies to user
entries too, matching Mac, which filters its whole list.
