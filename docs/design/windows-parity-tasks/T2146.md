# T2146 - acceptance-parallel's RED summary names only a script's .log, but Assert helpers that use WriteErrorLine send the FAIL line to the sibling .err.log: drag-perf read '1 FAILURE(S)' with no failing assertion in sight

## Summary

Found in T2134 (2026-10-21). drag-perf.ps1's Assert writes FAIL via $host.UI.WriteErrorLine, which the runner captures to NN-<script>.err.log. The RED line printed only the .log path, which carries 11 PASS lines and a bare '1 FAILURE(S)' verdict. Fix: print the .err.log path in the RED block when it is non-empty, or quote its FAIL lines inline.

## In plain terms

When a test script fails under the parallel test runner, the runner's summary
pointed at the script's output file. Some scripts report their failures on the
error stream, which is saved to a different file, so the summary showed only
"1 failure" with no hint of what had failed. Now the summary names the error
file too and prints the failing lines right under the red row.

## Goals

- [x] a red row names the `.err.log` whenever it holds anything
- [x] up to three FAIL lines from each log are quoted inline under the row
- [x] `summary.json` carries each run's `ErrLog` path

- [x] the existing log-path check (F12) still passes - same run
