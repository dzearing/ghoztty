# T3333 - Linux L4: Linux build/test doc and a headless Wayland test harness so Linux GUI tests never touch the user's screen

## Summary

Write docs/claude/linux.md (build, launch, crash diagnostics, the apt line, the interop PATH trap: inside WSL a bare `ghoztty` can resolve to the Windows ghoztty.exe and drive the user's terminal - scripts must name the Linux binary by full path). Add test/linux/lib with a harness that starts a nested headless compositor (weston --backend=headless or sway headless) and runs the app inside it - the Linux analog of TestDesktop.ps1. Add the routing row to CLAUDE.md.

## In plain terms

Linux test runs on this box happen inside WSL, and WSL's normal display puts any
Linux window straight onto the user's Windows desktop and gives it focus. This
task gives every Linux GUI test one shared, invisible stand-in display, which
refuses to start the app at all if it could still reach the real screen, and
writes down how to build, test and debug the Linux build.
