# T2296 - Unticking Share this machine should remove this PC from your account, so other devices stop listing it as offline (D100)

## In plain terms

Today, unticking "Share this machine" on Windows stops the PC serving but
leaves it registered, so your other computers list it as an offline machine
you cannot open. You chose (D100) that unticking should take the PC off your
account entirely, the way signing out does on a Mac, so no dead entry is left
behind.

## Summary

D100 (resolved 2026-10-26T05:59:57Z, option o1 "Untick removes this PC from
your account (Recommended)") overturns what T1965 assumed. T1965 made the
sharing choice tri-state (`sharing.Choice`: absent = follow enrollment,
explicit on/off respected) with `decide(choice, has_credential)` shared by the
agent reconciler and the chooser checkbox; an explicit off keeps the
credential and parks the uplink, which is the listed-but-dark state.

To build: unticking must deregister the machine from the relay account (the
same effect as the sign-out path that deletes `relay.env`), and re-ticking must
re-enroll (which now needs the sign-in step again, the con D100 accepted).
Re-check the D101 guest path (T2099: a non-owner's tick is refused and
explained) still holds, and whether an explicit "off" in sharing.json still has
any meaning once untick == sign-out.

Mac: no counterpart change - Mac has no checkbox; leaving there is signing out.

## Validation criteria

- [ ] Unticking removes the PC from the account: the relay no longer lists it for another device (share-machine.ps1 new section).
- [ ] Re-ticking walks the sign-in and the PC is listed and reachable again.
- [ ] A guest's tick on someone else's shared PC is still refused with the D101 explanation.
- [ ] agent-sharing-uplink.ps1 and share-machine.ps1 ALL PASS.
