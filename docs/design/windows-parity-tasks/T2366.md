# T2366 - A new window's terminal gets the caret, not the sidebar's all-windows search field (Mac 470526d63)

## Summary

Mac main 470526d63: with the shared sidebar showing all windows, a newly ordered-in window (Cmd-N, the sidebar + buttons, a restore) handed the caret to the sidebar's all-windows search field instead of the terminal. Mac removed the search field from the key-view loop so it only takes focus when clicked. Windows: verify that a new window opened by Ctrl+Shift+N / the sidebar + buttons / session restore puts keyboard focus in the terminal (src/apprt/win32/pane_sidebar_search.zig owns the search EDIT), and that the search field never takes focus except by click (or its explicit shortcut). Fix if it does; add an acceptance check either way. Reference: docs/reference/pane-sidebar.md on main.

## In plain terms

On the Mac, when the sidebar listed every window, opening a new window put
the typing cursor in the sidebar's search box, so the first keys you typed
went into the search box instead of the terminal. Windows never had this bug:
a new window's frame passes focus straight to its terminal, and the search box
only takes the keyboard when you click it. This task adds a test that keeps it
that way.

## Goals

- [x] Confirm whether a new window on Windows hands the caret to the search field (it does not)
- [x] An acceptance check that a new window's terminal holds the keyboard, both on open and after re-activation, and that a click still focuses the field
- [x] Prove the check fails when the defect is planted

## Validation criteria

- [x] With the sidebar showing all windows and the caret already in window A's search field, a `+new-window` window's keyboard focus is in its `GhozttyTerminal`, on open and after switching away and back. Verified by section 6c of `test\win32\pane-sidebar-all-windows.ps1`, run with `acceptance-parallel.ps1 run -Scripts pane-sidebar-all-windows.ps1 -FailFast`: ALL PASS (109 assertions), 2026-10-28.
- [x] The new window's search field never logs `search focus=true` until it is clicked, and the click still focuses it. Same run.
- [x] Teeth: a planted defect (frame `WM_SETFOCUS` forwards to the sidebar when it shows all windows and is expanded) turns 6c red, with 7 failures in 6c, both in a worker and alone. The plant was then removed.
