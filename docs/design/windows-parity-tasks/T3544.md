# T3544 - Linux L9j-2: the GTK viewer's feedback composer and the report folder it files

## Summary

T3419 put the worktree-attributed feedback button on the GTK viewer's nav bar; clicking it only logs. Port the composer (docs/reference/viewer-feedback.md): a pill under the nav bar hosting the shared src/viewer/composer.js in a second WebKitWebView (win32's D43 shape, ViewerFeedbackWeb.zig), Enter = newline, Ctrl+Enter sends, Escape closes, contents survive close/reopen; on send write <worktree>/temp/feedback/new/<stamp>-<suffix>/report.json via staging + one atomic rename, using win32's pure viewer_feedback_report.zig (source, worktree path/name/branch/commit, app, paneID, viewport, selection), then the Filed confirmation. Headless: steps-seam verbs to type/send and a test that reads the filed report.json.

## In plain terms

On Linux, the feedback button on a viewer pane used to do nothing. Now it
opens a small text box under the address bar: type what is wrong, press
Ctrl+Enter, and a report (what you wrote, which file or page you were on,
what you had selected, and the exact git branch and commit) is filed into
that repository's `temp/feedback/new/` folder for an agent to pick up.
