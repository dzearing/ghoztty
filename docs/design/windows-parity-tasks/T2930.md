# T2930 - A pane thumbnail capture is still a synchronous GPU readback on the pane's renderer thread (1-1.6 ms after the present, up to 8 ms), so it delays that pane's NEXT frame - an opening card mid-drag, or a hero pane being typed into

## Summary

T2873 moved heroSnapshot after the swap, which took it out of the layout pass's frame wait (long waits 8/5/8/7 -> 0 a run). The readback itself is unchanged: glReadPixels straight into the caller's buffer. A PBO + fence read collected on the next frame (or a GPU-side downscale for hero thumbnails) would take it off the renderer's critical path entirely. Measure first with the glide probe's unfold and hero typing; the snap's own cost is easy to stamp around heroSnapshot.
