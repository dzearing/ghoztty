# T1550 - A green acceptance run ends with a false CRASHED postmortem for every app the script killed itself

## Summary

Scripts that tear down with Stop-RepoGhoztty (chooser-session-cpu.ps1, chooser-sessions-push.ps1 and every other harness with that finally block) kill the app outside the test desktop's own bookkeeping, so Remove-TestDesktop's died-on-its-own report (T527) never sees the Killed flag and prints 'GUI POSTMORTEM ... verdict: CRASHED - 0xFFFFFFFF' for a process the script terminated on purpose. A real crash and a deliberate kill therefore read identically at the end of a PASS run, which is exactly what T527 exists to prevent. The fix is to mark those launches killed (or to let the desktop teardown kill its own launches first), never to soften the verdict. Found while landing T710.

## In plain terms

When a test closes the terminal it started on purpose, the test log ended with a
"this app CRASHED" report anyway, even though every check passed. That makes a
real crash impossible to spot at the end of a run. Now a deliberate stop is never
reported as a crash, and an app that really dies on its own still is.

## Goals

- [x] Every way a test script stops its own app is recognised as deliberate, without editing each script
- [x] An app that dies on its own is still reported, including one that exits 0xFFFFFFFF

## Fix

T2058 marked the launch record "killed" inside `Stop-RepoGhoztty`, but about
seventy scripts stop the app they launched with a bare `Stop-Process -Id
$app.Pid` (caption-bar.ps1 does it to drop its windowless first instance), and
those still read as `CRASHED - 0xFFFFFFFF`. `lib\TestDesktop.ps1` now defines
`Stop-Process` as the exact generated proxy of the cmdlet: before forwarding to
`Microsoft.PowerShell.Management\Stop-Process`, it marks the harness launch
record for each pid being stopped (`Set-TestLaunchKilled`). Only a record whose
process is still running is marked, so a launch that already died on its own -
or whose pid was recycled - keeps its report. Mechanism choice (one proxy over
seventy per-script edits) was mine: the next script that stops its app needs to
know nothing.
