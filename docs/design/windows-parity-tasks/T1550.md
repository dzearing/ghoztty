# T1550 - A green acceptance run ends with a false CRASHED postmortem for every app the script killed itself

## Summary

Scripts that tear down with Stop-RepoGhoztty (chooser-session-cpu.ps1, chooser-sessions-push.ps1 and every other harness with that finally block) kill the app outside the test desktop's own bookkeeping, so Remove-TestDesktop's died-on-its-own report (T527) never sees the Killed flag and prints 'GUI POSTMORTEM ... verdict: CRASHED - 0xFFFFFFFF' for a process the script terminated on purpose. A real crash and a deliberate kill therefore read identically at the end of a PASS run, which is exactly what T527 exists to prevent. The fix is to mark those launches killed (or to let the desktop teardown kill its own launches first), never to soften the verdict. Found while landing T710.
