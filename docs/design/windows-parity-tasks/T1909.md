# T1909 - Ctrl+C at an image pane also puts the FILE on the clipboard, so a paste into Explorer makes a copy (Mac writes the file URL beside the picture)

## Summary

Mac's ViewerImageSurface.copy writes the NSImage AND the file URL (main 1d513083a), so pasting into Finder or a terminal gets the file. T1872 landed the picture half on Windows (PNG + CF_DIBV5). The file half is CF_HDROP plus 'Preferred DropEffect' = copy. Check first which readers prefer a file drop over a bitmap when both are present (Outlook, Teams, Word, Slack, Chromium pages) - if any turns an inline picture paste into an attachment, that is an experience gap to file as a decision rather than to ship. Validation: viewer-image.ps1 section K reads CF_HDROP back as the viewed path, and the K1/K2 picture asserts stay green.

## In plain terms

Pressing Ctrl+C on a picture open in Ghoztty copied the picture, but not the
file. Pasting into File Explorer did nothing. Now the file goes on the clipboard
too, the way the Mac version does it, so pasting into an Explorer folder makes a
copy of the file. Pasting into Paint, Word or a chat window still pastes the
picture.

## Goals

- [x] ctrl+C at an image pane puts the viewed file on the clipboard as a file drop (`CF_HDROP`)
- [x] the drop is marked COPY (`Preferred DropEffect`), so Explorer never reads it as a move
- [x] the picture formats stay first, so readers that take the first format they know still paste the picture
- [x] a path that cannot be named (not absolute) still copies the picture, without the file

## Decision record (no decision filed)

The summary asked whether any reader would turn an inline paste into an
attachment once a file is present. That is the same tradeoff Mac accepts:
`ViewerImageSurface.copy` writes both an NSImage and the file URL. On Windows,
the formats go on in a fixed order: PNG, CF_DIBV5, then CF_HDROP. A reader that
walks the formats and takes the first one it knows meets the picture first.
Explorer reads no bitmap at all, so it is the one reader that takes the file.
I could not test this against Office, Teams or a Chromium page on this box:
none is installed here, and pasting into one would take the user's focus. That
hand check is T3582. Pasting the file's path into a terminal pane, which Mac
also does, is T3581.
