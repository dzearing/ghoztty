# T1068 - Nothing tells you a background-process update is waiting, now that Ghoztty stops asking

## In plain terms

Ghoztty keeps your terminal sessions alive in a background process. When an
update brings a newer version of that process while sessions are open, Ghoztty
now (rightly) waits for a quiet moment instead of asking to close everything —
but nothing told you an update was waiting, and on a machine whose windows
never all close it could wait forever. Now the window menu shows a quiet
"Background Update Ready…" row; choosing it explains that waiting costs nothing
and offers to install it right away, which you have to confirm.

## Summary

T1056 removed the dialog that used to appear when the agent (the background process that keeps sessions alive) was older than the app: it offered to end every live session for a binary refresh, which is not a trade worth offering. The newer build is now adopted silently at the next quiet moment. The consequence is that a pending agent update is completely invisible - on a box whose last window never closes and whose agent is a pre-T907 generation (no self-handoff), it can wait indefinitely with nobody able to see it or take it deliberately. Mac has the same gap. Wanted: a non-modal, non-destructive way to see it and act on it - the agent's own '+sessions --agent' already reports handoff state (unsupported/ready/draining), so the missing half is a user-facing surface (a quiet notice, a menu item, or a line in the connection pill) that says an update is ready and installs when your sessions close, plus a deliberate 'install it now' that is opt-in rather than offered. Must never become the old dialog by another name: nothing that interrupts, and nothing that ends a session without the user having gone looking for it.

## What landed (Windows)

- `agent_upgrade.zig`: pure `Pending` (`when_idle` / `draining`), `pendingFor`
  (only `stale_live_deferred` and `stale_handoff_draining` leave an update
  waiting; `stale_handoff` is already under way), `settlesPending` (skew and
  unknown-bundled checks never clear a row a real check put up), and the copy
  (`installNowText` leads with "nothing you have open is interrupted" before it
  names the sessions that end).
- `App.refreshLocalAgentIfStale` sets/clears `agent_update_pending` from the
  decision it already logs, and logs `agent update affordance: shown (...)` /
  `cleared` on each change.
- The window menu grows **Background Update Ready…** under the app-update row
  while pending — no dot on the button, because the wait costs nothing.
  The palette lists **Install Background Process Update…** under the same
  condition (not pinned, not emphasized).
- Choosing either runs `App.offerAgentUpdate`: re-check first (an idle agent
  is refreshed silently and the row retires, no dialog), else a dialog —
  Restart Now / Later, default Later — whose OK is the T1804 "Restart Ghoztty
  and Background Sessions" restart, not asked a second time.

Mechanism choice (mine, not a decision): a menu row rather than a tray balloon
or a line in the connection pill. A balloon interrupts, which is the thing this
task must not do; the pill is a remote-connection surface. The menu row mirrors
the T1673 app-update row the user already knows.

Mac half: **T2068** (`seat: mac`).
