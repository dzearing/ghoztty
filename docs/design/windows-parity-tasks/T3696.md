## Summary

2026-11-24, lane l (T3606 turn): scripts/linux/floor.sh lane agent failed rc=1 with 2855/2895 passed, 1 failed - 'remote.ssh_transport.test.spawnChannel: pipes carry a real HELLO handshake (fake agent, no ssh)' (the keepalive integration test's stderr was a session_meta warning beside it). Reproduce in a loop (FLOOR_LANES=agent, or zig build test-agent -Dtest-filter=spawnChannel N times) and find whether the fake-agent handshake races or times out under box load.

**Re-aimed 2026-11-26.** The spawnChannel test never failed. Zig's `while executing test '<name>'` prefix (`lib/std/Build/Step/Run.zig:1370`) names the LAST test the binary ran, whatever failed; the failing test is the one on the `'<name>' failed:` line (Run.zig:1615-1628), which was `remote.agent.keepalive.test.integration: server heartbeat pings keep the link alive (no false stale)`. That test asserted no stale over 600ms with `stale_after_ms = 150`, and `lastRxMillis` is wall clock, so any 150ms gap (reader thread starved under the full floor, or a WSL2 time-sync clock step) failed it with nothing wrong.

## In plain terms

One of the background tests for the remote-agent connection sometimes failed on the Linux test run even though nothing was broken: it allowed only a sixth of a second of silence, and a busy or briefly paused machine can be that slow. The test now allows a full second, which still catches the real bug it guards. The error report had also named the wrong test, which is why this card originally pointed at a different one.
