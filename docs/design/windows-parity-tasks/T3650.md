# T3650 - Linux L11k3: single-window mode on GTK - a parked workspace is laid out at the shared window's size, again 0.3s after a resize settles and at once on a tree change, so a switch never changes its grid

## Summary

Parked content keeps the size and scale the shared window has (Mac prepareParkedContent / windowDidResize / layoutParkedContent; win32 T3193, resize_settle_ms in workspace_host.zig). Measure: +list rows/cols of a parked workspace's pane equal what it shows with after a switch, across a resize. Spec: docs/reference/window-modes.md (Size).

## In plain terms

In single-window mode the app shows one window, and every other "window" is a
workspace waiting behind it. Until now a waiting workspace never heard about
the window being resized or about a split made inside it, so when you switched
to it its terminals suddenly jumped to a new size (and a program running there
saw the resize only then). Now a waiting workspace follows the window's size
while it waits, so switching to it shows exactly the grid it already had.

## Goals

- [x] a parked workspace is laid out at the shared window's size when it parks
- [x] 0.3s after a resize of the window settles, every parked workspace is laid out at the new size, and its running terminals take the new grid while parked
- [x] a tree change in a parked workspace (a split, a close) lays it out at once
- [x] a switch to a parked workspace never changes its grid
- [ ] a terminal made while parked starts at once - split to T3786 (it starts on first show today)
