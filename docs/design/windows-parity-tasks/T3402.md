# T3402 - win32: an -e argument containing a space splits into several words on the way to the local agent

## Summary

T3396 fixed this for POSIX agents only (`Command.posixShellString`). On Windows
`src/Surface.zig` still forwards `Command.string`, a plain space join, and the
agent runs it through its per-shell convention (`cmd /c`, `pwsh -Command`), so
an `-e` argument holding a space (a path under `Program Files`, a pwsh script
block) arrives as several words. Needs Windows quoting by the
`CommandLineToArgvW` rules, or the T468 `command_argv` route for a verbatim
argv. Related but distinct: T1666 (a `direct:` value in the CONFIG cannot
spell a space at all) - that one is the parser, this one is the hand-off to
the agent.

## Validation criteria

- [ ] `ghoztty -e` with an argument containing a space runs intact in an agent-backed pane (a check in `test/win32/`)
- [ ] a unit test covers the Windows quoting of argv words with spaces and quotes
