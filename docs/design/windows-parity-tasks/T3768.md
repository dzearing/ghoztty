# T3768 - The tab strip shows a chevron beside + that drops down the shell list, so the dropdown is visible without knowing to right-click (Windows Terminal split button) (T3753 follow-up)

## Summary

T3753 put the shell list on a right-click of the tab strip's + and in File > New Tab. Windows Terminal shows the same list behind a visible chevron (a split button: + opens the default shell, the chevron beside it drops the list), and a right-click is undiscoverable. Add the chevron to the strip: tab_strip_layout gets a rect after new_tab (the T232 gap tests re-measured), icon_button a chevron glyph from the design system, hover/pressed states, the hit test, and stripRegions/+list chrome publishing it; a left-click on it calls Window.openNewTabShellMenu. Follows docs/design/win32-design-system.md. Acceptance: new-tab-shell.ps1 grows a section that left-clicks the published chevron rect and reads the same rows; tab-strip.ps1 / menu-bar.ps1 geometry rows re-measured.

## In plain terms

Choosing which shell a new tab opens on (PowerShell, Command Prompt, Git Bash,
a WSL distro) was hidden behind a right-click on the tab strip's "+", which
nobody would think to try. Now a small down-arrow sits right beside the "+",
the way Windows Terminal does it: click "+" for your usual shell, click the
arrow to pick a different one.

## Goals

- [x] a chevron button beside "+" on every local window's tab strip, the same size and row as "+"
- [x] a left click on it drops the same shell list the right-click shows
- [x] it lights on hover and stays lit (pressed) while its list is open
- [x] "+" itself still opens a tab at once, and a right-click on either still opens the list
- [x] scripts can find it: `+list --json` chrome publishes `new_tab_menu`
- [x] remote windows (whose shells are not this PC's) show no chevron

## Design choices

- **Same 28 DIP square as "+"**, not a narrow WT-style half: design system
  section 2.1 says every icon button in one cluster paints the same square.
  The `chevron_down` glyph (12 x 6 DIP) the banner already uses.
- **Painted gap = the two hit pads** (`split_gap = 2 * hit_pad`), so the two
  hit boxes abut: no dead pixel between them and no overlap. `pad_sm` would
  overlap by a pixel at 125% (`round(2.5) * 2 = 6 > round(5) = 5`).
- The pair travels together; `group_gap` is now measured from the chevron to
  the menu button, and the tab run gives up one square plus the split gap.
- While the shell list is open the "≡" no longer lights as if its own menu
  were open (it keyed off the shared `menu_open`); the chevron lights instead.
