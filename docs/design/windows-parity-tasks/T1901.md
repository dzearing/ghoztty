## In plain terms

Another "How do you want to open this file?" box popped up on the user's
screen at 2:32 this morning while the loop was working. Same cause as last
time: Claude ran the banner-update script from PowerShell, which cannot run it,
so Windows asked the user what to do with it. The earlier fix only changed the
instructions Claude reads, and those come from the installed copy of the
script, which had not been updated. Now the repo itself refuses that kind of
command before it runs and tells Claude to use bash instead, whichever
instructions it was given.

## Resolution

Root cause (verified from transcript 0803a03f, tool call at
2026-10-13T09:32:46.901Z = 02:32:46 local, picker created 02:32:47): the T1895
turn's PowerShell-tool call
`... note T1895 ... | Out-Null; ~/.config/ghoztty/hooks/ghoztty-banner.sh 2>$null; powershell ... guard-due.ps1 check ...`.
Same shape as T1823. T1823's fix (help text "from the Bash tool, never from
PowerShell") shipped in win-v1.39.2+, but the text the model receives is
generated by the INSTALLED `~/.config/ghoztty/hooks/ghoztty-banner.sh`, which
is dated 2026-09-14 and still carries the old help: the integration reports
"Update available" (same as Mac) and nothing refreshes it until someone
clicks Update. This session's own prompt hook still carried the old line.

Fix: a project-level Claude Code PreToolUse hook (`.claude/settings.json`,
matcher `PowerShell`) running `scripts\hooks\deny-sh-from-powershell.ps1`. It
parses the command with PowerShell's own parser and denies one that launches a
`.sh` (command name ends in `.sh`, Start-Process/Invoke-Item on a `.sh`, or
either inside a nested `powershell -Command`); `bash x.sh` and `.sh` as an
argument pass. Fail-open on any error. ~0.26 s per call. The deny reason
names the remedy (the Bash tool), so the model retries correctly.

Mac: no change owed - the PowerShell tool exists only on Windows, so the
matcher never fires on the Mac seat, and a `.sh` runs natively there (T1823).

The pickers (pid 26580, pid 60680) are left for the user to dismiss.

Filed T1904: installed hook scripts never refresh after an update (both
platforms), which is why the T1823 wording never reached a session.
