# T3296 - The persistence and stderr launch sweeps read only the top level, so a lib\ helper that starts the app undeclared would hide from both

## Summary

T1598 measured lib\ for PersistenceSweep (persistence-flag.ps1 and stderr-launch-capture.ps1): two launch sites today, FrameLabDriver.ps1 (declared, captures stderr) and TestDesktop.ps1's Start-OnTestDesktop forwarding the caller's argv. Nothing hides there now, but a new helper that Start-Process'es the app with no persistence flag would make every caller a violator unseen. Widen Get-GhozttyLaunchSites to lib\*.ps1 once it recognises the forwarding shape (a launch whose argv is a parameter of the enclosing function is the caller's to declare, as DesktopLaunchAudit's Resolve-DesktopLaunchAuditParamSites does), keyed lib\<name>, with teeth.
