## In plain terms

The automated check for "bring back another machine's windows" was failing,
which made a working feature look broken. Two things were wrong with the
test itself, not the app: it was dialing a stale address for the test's own
session service, and it still expected a restored window to keep the other
machine's internal name, which an earlier fix deliberately changed to match
the Mac. The check now passes and tests the current behavior.

## Root cause

1. `Get-LocalAgentPipeName` (`test/win32/lib/PipeBridge.ps1`) built
   `ghoztty-agent-debug-<user>` and ignored `GHOZTTY_AGENT_INSTANCE`. The
   parallel runner gives every script a lineage (`apm-<pid>`), so the agent
   listened on `ghoztty-agent-debug-apm-<pid>-<user>`; the pipe bridge dialed
   a pipe nobody served, and every relay dial died at `HandshakeTimeout` -
   the 21-failure shape. The helper now mirrors `LocalAgent.pipeName`
   (`-Instance` overrides). Its four other callers inherit the fix.
2. The remaining 5 failures (the original report) asserted that the rebuilt
   window keeps the ipc name `t336-multi`. T1883 (d812773c8) made a
   cross-machine restore mint a FRESH local name on purpose (Mac parity;
   `session_layout.adoptableName`). The product rebuilt the window correctly
   as `window-3`, 3 panes, user-set title intact; J and K then looked for
   `t336-multi` and found nothing. The script now picks the rebuilt window as
   the widest new window, asserts it took a `window-N` name, and aims J/K at
   that name. It also lists every window on a miss.
