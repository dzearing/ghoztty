# T2975 - PA-R09: panes on a background tab keep all their GPU surfaces even with hero mode off, and a hidden window keeps each pane's interop texture and back buffers

## Summary

PA-R09 (audit-1, T2959). OpenGL.zig:1536-1544 releases targets only when the whole WINDOW is hidden (T2474), and generic.zig:1261-1263 then shrinks only the GL target; Presenter.texture and the two back buffers survive. A tab switch (Window.zig:4785-4790) hides the panes without any release, by design for hero mode's carousel, even when hero mode is off. Cost estimated: ~16-19 MB per full-size pane survives a window hide; ~22-25 MB per background-tab pane. Fix: on window hide also destroyShared() (begin() rebuilds it when texture == null, gl_comp_present.zig:771-778); keep back buffers for DWM thumbnails. For background-tab panes with hero off, release target + shared texture and shrink the chain; reveal already waits for a frame (carried_hidden). Note: the '1x1' release actually allocates 256x256 (Target.zig bucket). Risk medium: one texture create + ResizeBuffers on tab switch; blank-on-reveal hazard if the reveal wait is bypassed. Mac shrinks occluded targets to 1x1; confirm whether Mac background tabs count as occluded (Mac seat).

## In plain terms

Every terminal pane keeps a few screen-sized pictures in graphics memory so it
can draw. A pane on a tab you are not looking at kept all of them, forever, and
a minimized window kept one of them too. Now a pane on a background tab hands
that memory back the moment its tab goes behind, and gets it back when you
switch to it - the same thing a minimized window already did - and a minimized
window gives back about twice as much as before.

## Goals

- [x] a pane on a background tab gives back its render targets (as a hidden window's do)
- [x] a released pane also frees the composition path's staging texture
- [x] the tab comes back drawn, and hero mode is unaffected
- [ ] shrink the swap chain too - filed as T3091 (kept on purpose: its last image is what a reveal shows)

## Validation criteria

- [x] background-tab release, and redraw on return - `test\win32\hidden-window-memory.ps1` new section T: T1 4/4 panes release when a second tab opens, T3 4/4 redraw in full on return, T4 every pane captures with text (acceptance-parallel, green 16/16, 2026-11-14)
- [x] a minimize gives back more - same run, A1: smallest drop 11 MB per 4-pane window (was 5.0 MB on 2026-11-02; the difference is the staging texture)
- [x] hero carousel harness green with hero mode on - hero-mode.ps1 ALL PASS (90), hero-nav.ps1 ALL PASS (48)
- [ ] perf-baseline.ps1 -Phase cycle with 3 tabs: NOT RUN this turn; the 3-tab dedicated-memory delta mixes the new tab's own pane (section T reports 122.3 -> 140.9 MB on opening a tab), so the release is scored by T1 + A1 instead
- [x] no blank frame on reveal - by construction: the swap chain keeps its last image, so a revealed pane shows the old frame until the redraw lands (T4 captures text after return); the chain shrink that would put this at risk is T3091, which owns the pixel oracle

## Design note

Hero mode was the reason T2474 left background tabs alone, and it does not
need them: the carousel keeps every leaf of ITS OWN tab renderer-visible
(`Window` hero layout, `setVisible(true)` per leaf) and snapshots only the
active tab (`heroSnapTick`). A pane hidden by zoom or a stash still keeps its
target. Follow-ups: T3091 (swap chain), T3092 (window-presenter slot
textures), T3093 (Mac seat: are background tabs occluded there?).
