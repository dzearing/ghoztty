## The split (2026-11-22)

Re-measured at pickup: 4,639 lines (3,291 at the T1013 split), code ends at
~3,800, then ~840 lines of tests. Unlike MachineChooser.zig or Surface.zig
the file is NOT a file-as-struct: everything lives inside one nested
`pub const BannerOverlay = struct { ... }` (lines ~279-3667, indented four
spaces), and `scripts/split-plane.py` only moves column-0 decls. So the
first child, **T3523**, de-nests it (`const BannerOverlay = @This();`, plus
`pub const BannerOverlay = @This();` so the three importers - App.zig,
Surface.zig, Window.zig - keep `@import("BannerOverlay.zig").BannerOverlay`
unchanged), and every plane depends on it. That is a mechanism call, made
here rather than by extending the tool for one file: after the de-nest the
owner looks like every other split owner and the proven tooling applies
unchanged.

The imports, file-level helpers (wrapWidth, Prepared, PrepKey), the field
block and create/destroy/setText/refreshForCwd/setColors/placeChange stay in
the owner, as do registerClassOnce and bannerWndProc. Each child names its
range by FIRST and LAST function, because line numbers drift as siblings
land. The existing `banner_*.zig` files are pure models, so the new planes
are named `banner_overlay_*.zig`.
