# T1514 - The cleanup-screen harness can never re-stamp its guard on this box, so any edit to it stays permanently due

## Summary

test\win32\ghoztty-cleanup.ps1 section H5 skips with 'the ghost entry is not registered on this box', and a run with a skipped section deliberately does not stamp. The consequence is that the ghoztty-cleanup guard goes DUE on any edit to the script and can never be cleared here: the conversion for T1511 was made and reverted for exactly that reason. Either make H5 answerable without the real ARP ghost entry (a fixture, or an explicit 'not present' assertion that is itself a check), or make the guard's stamp rule tolerate that one box-state skip and say so. Found by T1511 batch 1.
