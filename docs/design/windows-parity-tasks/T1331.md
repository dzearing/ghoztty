# T1331 - The agent test binary compiles and runs the whole win32 app suite: os/open.zig drags apprt.zig into every test root

## In plain terms

The automated check suite for the background session daemon does not just check
the daemon: it compiles and runs the entire terminal application's checks too —
window chrome, the document viewer, the machine chooser, all of it. That is why
that suite takes minutes instead of seconds, why it can start a hidden browser
process on the machine while it runs, and why a change to a button's layout can
make the daemon's suite go red.

## Goals

- [x] `ghoztty-agent-test.exe` no longer contains `ViewerPane` / `EBWebView`
- [x] The agent lane's test count drops to the agent's own tests (7014 -> 2773;
      the "~600" guess predates the agent growing since 2026-09-04)
- [x] The win32 unit tests it stops carrying still run in the `none` and `win32`
      lanes — counts before/after per lane, so nothing silently stops running
- [x] The agent lane's wall time drops accordingly

## Summary

The second half of T434, kept separate because the fix is a shared-core change
that moves what every test lane compiles, not an agent-lane edit.

**The import path, established 2026-09-04** (T434 asked for it and could not find
it by reading `remote/agent/main.zig`'s imports, which reach no `apprt`):

```
src/agent_main.zig
  -> src/remote/agent/main.zig ... -> (anything) -> src/os/main.zig
       -> src/os/open.zig:5   const apprt = @import("../apprt.zig")
            -> src/apprt.zig  test { ... 112 x  _ = @import("apprt/win32/<file>.zig") }
```

`src/apprt.zig`'s test block is the deliberate aggregator (T59a) that makes the
pure win32 unit tests run in the `none` lane as well as `win32`. Anything that
reaches `apprt.zig` therefore carries all 112 of them plus everything they
import — and `src/os/main.zig` re-exports `open.zig`, so essentially every file
in `src/` reaches it. `open.zig` needs exactly one type from there
(`apprt.action.OpenUrl.Kind`), and importing `../apprt/action.zig` directly does
not help: `action.zig` imports `../apprt.zig` itself.

Measured on the agent lane, 2026-09-04: `ghoztty-agent-test.exe` is 103 MB and
runs **5443** tests; a filtered probe (`-Dtest-filter="scales with DPI"`) runs 90
win32 layout tests inside it. The agent's own aggregator lists 13 files.

`_ = runtime` in that same test block is a second edge: the agent exe is built
with the global `-Dapp-runtime`, which is `win32` on this box, so even an
otherwise-clean `apprt.zig` would pull the win32 runtime's tests in.

## Where to look

- `src/apprt.zig` — the `test {}` block (line ~56) and its 112 `_ = @import` lines
- `src/os/open.zig:5` — the edge that makes `apprt.zig` universally reachable
- `src/apprt/action.zig` — imports `../apprt.zig`, so it is not a shortcut
- `build.zig` — the `test_step` roots, to keep the moved tests running in
  `none` + `win32`

## What landed

- `src/apprt.zig`'s 178-line aggregator, plus `_ = runtime/action/ipc/structs`,
  moved to `src/apprt/unit_tests.zig`, imported only by `main_ghostty.zig`'s
  test block. `apprt.zig` keeps `_ = Runtime` (a std-only leaf).
- `src/os/open.zig` names `OpenUrl.Kind` through the new leaf
  `src/apprt/open_url_kind.zig`; `action.zig` re-exports it as
  `OpenUrl.Kind`, so every other caller is unchanged.
- `src/build_config.zig` takes `Runtime` from `apprt/runtime.zig` directly.

## Direction (as filed)

Move the win32 unit-test aggregation out of `apprt.zig` into a test-only root
(e.g. `src/apprt/win32/unit_tests.zig`) that only the app's test roots import,
and give `open.zig` a way to name `OpenUrl.Kind` without importing `apprt.zig`.
Both halves are needed: the aggregator is the bulk, `_ = runtime` is the rest.
