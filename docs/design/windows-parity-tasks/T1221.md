# T1221 - The portable copies are still fed from the repo

## In plain terms

The rule you set is that a terminal should only ever run something that was
actually published. That is now true of the app you installed. It is not yet
true of the two other copies on this box: the portable folder on the Desktop and
the copy on the network share - the one whose ZIP is what somebody would
download. Both are still filled straight from a repo build.

## What has to change

`scripts\deliver-windows-build.ps1` copies a staging prefix into the Desktop
portable, the share's portable, the share's loose `ghoztty-agent.exe` and the
downloadable ZIP, and verifies every byte of it. None of that is wrong; the
question is what it should be fed. Two shapes:

- **Published-only, like the install**: the portable locations are refreshed
  from a published release's artifacts, so every copy on this box describes real
  released bytes. The share's ZIP in particular is a thing people download -
  arguably the strongest case of all for this.
- **Dev-explicit**: the portables stay a dev convenience, and they are LABELLED
  as such (the debug/dev marker the app already has) so nobody mistakes one for
  the product.

The choice has a user-visible consequence (what the share's download is), so it
may be worth a decision rather than a quiet call.

Note the current state: nothing delivers to these automatically any more.
`launch-upgrade.ps1` was the only caller, and the loop stopped running it when
T1218 retired the morning swap. So this is about settling the rule before the
next hand-run delivery, not about stopping an ongoing bleed.

## Goals

- [x] Settle the rule: the portable locations take PUBLISHED releases only (D85 applied to the other two copies)
- [x] Make the rule a refusal, not a paragraph
- [x] Give the portables a way to receive a release (`-FromRelease`)
- [x] Make the daily audit notice an unpublished build sitting there

## Decision

Published-only, not dev-explicit. This is the experience the user already
chose in D85 ("the terminal should only ever run something that was actually
published"), and the share's zip - the thing a stranger downloads - is the
strongest case for it, so it is not filed as a new decision.
