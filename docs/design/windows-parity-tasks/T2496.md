# T2496 - Blades on a translucent window: the strip names are still alpha-blended in their own pass after the desk blit, so they can blink out under load the way T2485 D3 did on an opaque one

## In plain terms

On a see-through (background-opacity below 1) window, the names on folded
pane strips were painted in a second step after the rest of the desk, so
under load the strip could show up for a frame without its name. Now the
names go to the screen in the same step as the strip they sit on.

## Goals

- [x] On a translucent window drawn through GDI, the strip names reach the window in the desk's own blit (whole and changed-only)
- [x] The window's separate strip-name pass no longer runs there
- [ ] On-screen dropout measurement on a background-opacity < 1 config (needs the input desktop: NOT RUN, user present)

## Summary

Re-verified 2026-11-26 against the code: **partly fixed**. T2541 already laid
the names into `out` for the compositor path (`toSink` -> `layNamesOut`), but
`PaneDesk.layNames` still returned false on a translucent window with no sink,
which is the GDI path a translucent window takes whenever its desk is not on
the compositor (a header band or hero split over the desk, or no live
compositor). There `paintStackStrips` drew the names into
`paintAlphaCorrect`'s buffer and alpha-blended them after the desk had already
gone to the window: the T2485 D3 two-pass gap.

Fix (`src/apprt/win32/PaneDesk.zig`): `layNames` marks the names for `out` on
every translucent paint; `blit` lays them into `out` after the whole-desk
rebuild; the changed-only path (`blitRect` per rect, now `blitShown`) rebuilds
every rect into `out` first, lays the names once, then BitBlts the rects. So
the names go out in the same BitBlt as their bands, and `names_laid` makes the
window's own pass skip them in the elevated style, as on an opaque window.
