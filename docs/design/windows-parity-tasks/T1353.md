# T1353 - A redirect skip naming a task id that does not exist silently satisfies its dependents

## Summary

T518 made skipped(duplicate/obsolete/superseded -> X) deps resolve through X. Get-OpenDeps ignores an id with no task file (the long-standing rule), so a TYPO in the redirect target - skipped(duplicate of T9999), or a digit dropped - resolves to nothing and satisfies every dependent, which is exactly the misroute T518 closed, re-opened by a slip of the keyboard. validate already has DANGLING DEP for the same shape in a deps: list; the redirect target has no equivalent. Add a validate check (and/or a set-status refusal) that a redirect status naming an id must name one that exists. Watch the false-positive side: the FIRST id in the status is the target, and prose after it routinely names other tasks, so only the target is in scope. Small, and it protects a correctness rule that has no other backstop.

## In plain terms

When a task is closed as a duplicate of another one, anything waiting on it now waits on the other task instead. A typo in that other task's number used to make the wait silently disappear, so work could be started before what it depends on was done. The tracker's check now refuses a duplicate pointer to a task that does not exist.
