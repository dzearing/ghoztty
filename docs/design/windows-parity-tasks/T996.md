# T996 - Nothing enumerates which acceptance harnesses have no guard-due row, so the coverage gap is found one harness at a time

## Summary

T884, T967, T972, T981, T993 and now T963's verdict-exit row were each filed separately for the same shape: an acceptance harness in test\win32 that no row in scripts\guard-due.ps1 covers, so editing the code it scores obliges nobody to re-run it and the harness can sit red at HEAD unnoticed (verdict-exit-audit did exactly that until T883 ran it by hand). Nothing lists the uncovered ones, so each is found by accident. Wanted: an enumeration - every top-level test\win32\*.ps1 against the Name/Script set in guard-due.ps1's table - with a stated-intent exemption for harnesses that genuinely need none, so the remaining gap is a number somebody can read rather than a series of surprises.

## In plain terms

Every test script is supposed to be re-run when the code it checks changes, but
that reminder only exists for scripts somebody registered. Nothing said which
ones were never registered, so each gap was found by accident. Now one command
prints how many test scripts have no reminder (126 of 352 today) and names them.

## Goals

- [x] one command lists every top-level test\win32 harness with no guard-due row
- [x] harness-floor members and stated exemptions are counted separately, not as gaps
- [x] an exemption that stopped being true (script gone, or it has a row now) is reported
- [x] the number is read somewhere on a schedule (daily triage, go.md step 0.6)
- [x] the remaining gap is a filed task (T1768)

## Validation criteria
