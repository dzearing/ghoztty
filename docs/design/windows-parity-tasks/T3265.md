# T3265 - On-box acceptance arm: a pane whose session another window takes shows the notice and its typing never reaches the shell

## In plain terms

When two windows show the same terminal session, the newer one wins and the
older one now says "Session opened elsewhere" and stops typing into it
(T1506). That is proven by unit tests of each half, but nothing yet drives the
real app to show the whole thing working together.

## Summary

T1506 added the `session_taken` capability (per-channel `DETACHED{taken}` to
the losing viewer), the agent-side input fence (`Server.takenFromUsLocked`),
and the pane notice (`session_notice.taken_notice`, `termio/Remote.zig`
`rd.taken`). Write an acceptance arm in `test/win32/` (on the test desktop,
never the input desktop) that:

1. opens a session-backed pane in window A;
2. resumes the SAME session from a second window B (chooser resume, or the
   remote arm that keeps `.attachable`);
3. asserts window A's pane text (`+read`) carries "Session opened elsewhere";
4. `+send-keys` a marker into A's pane and asserts it never appears in B's
   pane, while a marker sent to B does.

Add a guard-due row covering `src/remote/agent/server.zig` bindLocked and
`src/termio/Remote.zig` for it.

## Validation criteria

- [ ] The arm is red against a build with the T1506 notice removed (negative
      control) and green on HEAD.
- [ ] Runs on the test desktop; no window takes the user's focus.
