# T3037 - PA-V05: every save re-reads, re-sends and re-renders the whole document, even when the viewer is hidden or the file did not change (ViewerPane.zig:7545)

## Summary

PA-V05 (audit-1, T2963). WM_APP_VIEWER_RELOAD arms the 100 ms debounce (ViewerPane.zig:7461-7463) and the timer calls reloadContent(.file_changed) (:7545-7553) with no visibility check, unlike the diff poll (:7541). Read and escape run on the GUI thread (:4527-4566; 32 MB cap viewer_content.zig:1341); the page re-renders everything (src/viewer/viewer.js:54-63, shared). Cost (estimated from the copies): ~3x file size transient per save plus a full renderer parse, unbounded while a writer keeps saving. Fix: skip when size+mtime unchanged; while hidden record the reload as owed and pay it once on show (the diff_poll_gate pattern, :1844). Page-side incremental render is the Mac half (T3057). Risk: a hidden pane read over IPC is stale until shown. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## Validation criteria

- [ ] perf-baseline.ps1 viewer phase (PA-V01): a hidden markdown viewer whose file is rewritten 10x/s for 30 s shows ~0 app and renderer CPU
- [ ] showing it afterwards displays the latest content (acceptance)
- [ ] an unchanged touch does not re-render (log line count)
