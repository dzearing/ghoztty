# T2087 - A Windows viewer\u0027s Ctrl+D splits again (as Mac\u0027s Cmd+D now does); the address bar stays on Ctrl+L and Alt+D

## In plain terms

In a viewer pane, Ctrl+D should split the pane, as it does everywhere
else. The address bar stays on Ctrl+L and Alt+D, the keys every Windows
browser uses.

## Summary

Mac 89848fd59: "Viewer address bar is Cmd-L (Cmd-D splits again, also from
a window of only viewers)".

Windows today: `viewer_accel.zig:392` maps Ctrl+D and Alt+D to
`focus_address`, with the comment "ctrl+d mirrors Mac's Cmd+D", the rule
Mac just dropped. Change: Ctrl+D falls through to the app's split binding
(whatever new_split is bound to on Windows), and Ctrl+L and Alt+D keep
focusing the address bar. That includes a window of only viewers.

## Validation criteria

- [x] Unit test: `paneChord(0x44, ctrl)` is no longer `focus_address`;
      Ctrl+L and Alt+D still are (viewer_accel.zig "paneChord: exact-modifier
      chords only"; floor-lane `-Lane all`).
- [x] Acceptance: in a viewer-only window, the split binding splits
      (viewer-window-chords.ps1 S7, ALL PASS 52), and Ctrl+L focuses the
      address bar while Ctrl+D from a viewer splits (viewer-panes.ps1 11d,

## Goals

- [x] Ctrl+D in a viewer splits right, a window of only viewers included
