# T2518 - window-close-memory.ps1 A1 sits on its 1 MB budget: 1.02 MB per closed window in the width-4 parallel sweep, 0.97 MB alone (2026-10-30) - either a real ~1 MB per-window leak the budget barely hides, or load noise; measure the spread and fix the leak or the budget

## In plain terms

Two of our memory-leak tests kept failing and passing on the same code,
depending on how busy the computer was. There was no real leak behind it. The
tests did a sum that a single burst of graphics-driver memory could tip over
the limit. They now use a measure that a real leak still trips but a one-off
burst does not. A leak still fails them, and a busy machine no longer does.

## Goals

- [x] Re-verify what the 1 MB a window was. It was a real leak (NVIDIA driver, T2644, fixed by thread pools) plus a one-time driver fill (T2782, adaptive warm-up). After those two fixes, reds came mostly under load and passed when run alone.
- [x] Measure the spread: one settled sample per cycle
- [x] Replace the estimator in both meters (window-close and pane-close)
- [x] Prove the negative controls still go red

## Summary

**The defect was in the estimator, not the app.** A1 and A8 judged
`(end - baseline) / cycles` from two single samples. Settled samples taken
after every cycle (2026-11-26, alone, 20 cycles) swing by about 1.5 MB from one
cycle to the next. They also hold step events: a heap trim read 292.1 -> 281.8
-> 287.3 -> 293.3 MB, and the driver's bounded upload-pool fill lands as
+4 MB steps. Over ten cycles, two steps add 0.8 MB a window to the mean
whether anything leaks or not. That is the 0.97-1.53 MB straddle in the log
below. A 20-cycle solo run read a 0.11 MB mean. A 10-cycle solo run read a
1.26 MB mean, which is red under the old rule, with deltas
`4.2 0.0 1.3 -0.7 1.6 -0.1 0.3 1.9 -0.4 4.5`.

**Fix (test-only):** `Get-LeakRate` in `test/win32/lib/ProcessMemory.ps1`
returns the **median** of the consecutive per-cycle deltas plus the old mean.
Both `window-close-memory.ps1` and `pane-close-memory.ps1` now take a settled
sample after every measured cycle. They assert the median against the 1 MB
budget (A1/A8) and hold the mean to a 3 MB gross ceiling (A1b/A8b). The
ceiling catches a leak that lands on only some cycles, which has a median of
0. A leak grows every cycle, so it moves the median by its full size. Each run
also prints its deltas, so a red run shows which shape it is.
