# T2830 - comp-present.ps1 B proves a fallen-back pane draws only from the renderer's own target: nothing checks the pane WINDOW shows those pixels after its context moved off the hidden helper (T2788)

## In plain terms

When a pane's normal fast drawing path fails and it falls back to the older
one, the test only checks that the pane drew text into its own memory, not
that the text actually shows on screen. Since T2788 that fallback also
moves the pane's drawing context, so it is worth seeing the pixels.

## Summary

T2788 put a composition-path pane's GL context on a hidden helper window and
made `Surface.adoptPaneDrawable` move it onto the pane window when the pane
drops to SwapBuffers. `comp-present.ps1` B6/B7 assert the move happened (log)
and B4/L assert the pane still draws (`capture-pane`, which reads the
renderer's own target). Neither reads the pane WINDOW's composed pixels, so a
SwapBuffers that went to the wrong drawable would still pass. Add a capture of
the pane window after the fallback (a DWM/WGC capture of the top-level, or
PrintWindow with PW_RENDERFULLCONTENT, on the background test desktop - not
CopyFromScreen) and assert non-background text pixels inside the pane rect,
with a negative control (the same capture before any output is drawn).

## Validation criteria

- [ ] B and L each assert the pane window's composed pixels show text after the fallback
- [ ] a negative control proves the capture can read an empty pane as empty
