# T1709 - Re-point viewer-feedback-images.ps1 from the RichEdit fallback to the web composer

## Summary

viewer-feedback-images.ps1 reads chips out of the RichEdit, Backspaces them away and types 'look at these'. Move all three onto the web page; pictures go in with Send-CdpComposerImage. Split out of T1703, which landed the pattern on viewer-feedback-alpha.ps1: arm ONE DevTools port per script with Enable-WebViewCdp before the first launch, open the composer, Find-CdpComposer (pass -Exclude for pages an earlier app used), then type with Send-CdpComposerText / Send-CdpKey, paste pictures with Send-CdpComposerImage, and read back with Get-/Wait-CdpComposerText (test\win32\lib\WebViewCdp.ps1). Chords NATIVE owns (Ctrl+Enter, Esc) still go through the band's window messages. Assert Wait-ComposerSurface 'web' instead of pinning 'richedit'. When done the script no longer calls Set-ComposerSurface 'richedit' or reads a RichEdit50W, which is what T1704 needs before it deletes the fallback.

## In plain terms

The test that checks pasting pictures into the feedback box was still testing an old, hidden version of the box that users never see. It now tests the real one, so a picture-paste bug in the box people actually use would turn it red. Nothing changes for users; it clears the way to delete the old hidden box.
