# T3730 - ghoztty-agent.exe leaves no crash report on Windows - it installs no crash filter and no panic hook, so a dying agent takes every live session with nothing written

## Summary

T1355 and T2244 give the app (ghoztty.exe) a crash report for faults and panics. The session agent (src/agent_main.zig, src/remote/agent/) never calls crash.init and has no root panic handler, so an agent that faults or panics on Windows exits (code 3 for a release panic) and only the app's exit ledger, at best, notices the sessions vanished. Wire crash/windows.zig into the agent root the same way (init at startup, pub const panic in agent_main.zig), naming the process in the report, and grow an agent case in test\win32\crash-report.ps1 or a sibling harness. Check what the Mac agent does on SIGABRT/SIGSEGV first: if it has no Sentry either, this is a two-seat gap and needs a seat: mac twin.
