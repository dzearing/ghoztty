# T1882 - Mac's reader of Windows-captured layouts ignores desk_variant: a Windows window's own gradient comes back as the ocean when restored on a Mac

## Summary

T1832 made a Windows window carry its own gradient as a seed, persisted in the
win32 session layout as `"desk_variant": <u64>` on the window object (the win32
blob is snake_case; Mac's own entries spell it `deskVariant: {"seed": N}`).
Windows already reads Mac's spelling (`mac_layout_blob.zig` `deskSeed`). Mac's
reader of win32-lineage blobs (the T622 path that already converts
`primary_screen_height`) needs the mirror: read `desk_variant` and set the
restored controller's `deskVariant = PaneDeskVariant(seed:)`. The palette
derivation is identical on both platforms (same SplitMix64, same draw order),
so the restored Mac window shows the same gradient the Windows one had.

A seed is usually above Int64.max: decode it as UInt64 (a JSON number that does
not fit Int64), and treat 0/absent/malformed as no variant.

## Validation criteria

- [ ] Unit (PaneDeskTests or the win32-blob reader tests): a win32 blob with `desk_variant` restores that seed; one without restores the ocean; a seed past Int64 round-trips exactly.
