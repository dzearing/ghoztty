# T3721 - wsl-run.ps1 -KeepRunning has no way back: a turn that kept the VM up for several steps cannot shut down the VM it booted, and vmIdleTimeout=-1 holds the memory forever

## Summary

T3622's turn ran pane-style.sh three times and a harness sweep with -KeepRunning to skip repeated boots. Afterwards a plain wsl-run call leaves the VM alone, because a VM already running counts as somebody else's (vmWasIdle is computed per call), and nothing records that THIS lane booted it. Only wsl-run may call wsl.exe, so the turn had no sanctioned way to give the memory back, and Ubuntu is also the user's own distro, so a bare --terminate could kill their sessions. Fix: when -KeepRunning boots an idle VM, write a lease under temp\ (pid, time, distro); add a -Release switch that terminates and shuts down only when that lease exists and the VM is still the one it recorded; have go-loop-exec claim and the turn end report a lease still held. Acceptance: test\linux\wsl-run-guard.ps1 sections for the lease and -Release refusing without one (never boots WSL).
