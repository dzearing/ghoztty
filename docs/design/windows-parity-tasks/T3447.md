# T3447 - Linux: a popup that stays in Ghoztty (Ctrl-click, bare window.open, non-web scheme) is adopted as its own viewer window with window.opener intact and the size it asked for

## Summary

T3415 routes viewer popups on Linux: to the browser by default, a Ctrl-click off-site through the link scheme, a ghoztty:// link in process. The popups that must stay in Ghoztty are not adopted yet: a Ctrl-clicked same-site popup opens a fresh viewer window at its URL (no window.opener, so window.close() and postMessage back to the opener do not work, and the requested width/height is ignored), and a bare window.open() or a non-web scheme does not open at all (window.open returns null). Mac and win32 adopt the popup's own web view (WebKit's create signal must return a web view made with related-view, shown on ready-to-show and closed on close) in a viewer window sized from webkit_window_properties. Needs Surface/Window plumbing to host a pre-made Viewer.

## In plain terms

On Linux, when a page in a Ghoztty viewer opened a pop-up window that should stay inside Ghoztty (a sign-in box, a "print preview", a blank window a page fills itself), either nothing opened at all or a disconnected copy opened that could not talk back to the page or close itself. Now the pop-up opens as its own Ghoztty window, still connected to the page that opened it, at the size the page asked for, and it closes when the page tells it to - the same as on Mac and Windows.

## Goals

- [x] A pop-up that stays in Ghoztty becomes a viewer window of its own, still connected to its opener
- [x] A blank `window.open()` gives the page a window it can write into
- [x] The window opens at the size the page asked for, clamped like Windows
- [x] The page closing the pop-up closes its window

## Validation criteria

- [x] A Ctrl-clicked same-site `target="_blank"` link opens a viewer window whose page sees `window.opener`, and `window.close()` in it closes that window (headless: probe + `+list`). — `test/linux/viewer-links.sh` K24 (a Ctrl-clicked `_blank` into the page's folder is adopted), K24f (a Ctrl-clicked same-site `_blank` on a website is adopted, `+list` shows its window), K24a (the popup's page reaches its opener by `postMessage`, which needs a real `window.opener`), K24e (`window.close()` inside it: `+list` two.html windows 3 -> 2), WSL, at 41d28bf7e.
- [x] A bare `window.open()` gets a window the opener can write into. — K24c: the opener `document.write`s `<h1>Written</h1>` into the returned window and reads it back, and `w.opener === window`.
- [x] `window.open(url, "", "width=500,height=400")` opens at that size (clamped like win32's `viewer_popup.requestedSize`). — K24d: the popup's page measures `innerWidth` 500; the log says `ready to show at 500x400 (asked 500x400)`, and the unsized popups get the default. The clamp is `viewer_links.popupSize` (none-lane test).
