# T2356 - Check for Updates does nothing

## Summary

User report 2026-10-27 (~17:25 local), on win-v1.48.1 (0ef9c932a, installed
app pid 2880): "i click check for updates. nothing happens." / "no feedback,
hnothing."

`%LOCALAPPDATA%\ghoztty\ghoztty.log` for pid 2880 has ONLY the hourly
`update check (automatic): up to date` lines. A manual check always logs
`update check (manual): ...` (`App.zig` updateCheckThread, ~10433/10446) and
then posts feedback (`postUpdateFeedback`, which T1565 routes to a dialog
rather than the tray balloon). Neither happened, so the click is lost BEFORE
`App.startUpdateCheck(.manual)`.

Path: menu bar `Check for &Updates…` (`menu_bar.zig:259`) / palette row
(`commands.zig:370`) -> `Surface.performCommand` (`Surface.zig:3436`) ->
`.binding` -> `core_surface.performBindingAction(.check_for_updates)` ->
core `App.zig:514` -> `rt_app.performAction(.app, .check_for_updates)` ->
win32 `App.zig:9614`.

Silent drop candidates, in order of suspicion (unverified):

1. `performCommand` starts with `if (!self.core_surface_ready) return;` - no
   log. If the menu's WM_COMMAND is routed to a surface that is not ready (or
   to none: focus in the pane sidebar, a viewer pane, the stash tray), the
   app-scoped action dies there. An app-scoped action should not need a
   terminal surface at all.
2. The WM_COMMAND for the menu bar item is not mapped to `performCommand`
   for this id (check the Window.zig menu handler).

Not yet known: whether the user used the menu bar, the window menu, or the
palette - test all three.

## Goals

- [ ] every route to Check for Updates reaches `startUpdateCheck(.manual)`,
      whatever has focus (terminal, viewer, sidebar, no pane)
- [ ] app-scoped commands never depend on `core_surface_ready`; a drop for
      any other reason logs a warning naming the command
- [ ] the user always sees an answer (up to date / available / failed) via
      the T1565 dialog - verify on THIS box, where Windows notifications are
      off system-wide

## Validation criteria

- [ ] acceptance on the test desktop: trigger Check for Updates from the menu

      least the user's route
