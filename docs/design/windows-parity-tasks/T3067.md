# T3067 - PA-C13/PA-C14: a shaping cache miss holds the font grid's exclusive lock across the HarfBuzz call, and the run iterator fills the HarfBuzz buffer before the cache is consulted (shaper/harfbuzz.zig)

## Summary

PA-C13 + PA-C14 (audit-1, T2964). PA-C13: src/font/shaper/harfbuzz.zig:134-148 and src/font/shaper/Cache.zig:67-78 hold the SharedGrid write lock for the whole hb_shape of a miss, serializing every pane on that grid; scrolling output misses on most rows. PA-C14: src/font/shaper/run.zig:75, :306-310 and harfbuzz.zig:265-298 do hb_buf.add + codepoints.append per cell and reset + guessSegmentProperties per run even when the cache then hits, plus a shared-lock getIndex per cell (SharedGrid.zig:165-169). Cost (estimated): 0.1-0.3 ms per full 120x40 rebuild, multiplied by PA-C01 and PA-R01. Fix: shape under the face's own ft_mutex instead of the grid write lock; fill the HarfBuzz buffer lazily on a miss. Risk: medium (FreeType thread-safety, the run hook contract). Shared file; the HarfBuzz path is Windows and Linux only, the Mac uses CoreText, so no Mac half. Findings: docs/design/perf-audit/audit-1/C-findings.md.
