# T3632 - Linux L11g3: the GTK Settings window edits list and keyed settings - font-family, font-feature, keybind, palette, env - with setList/setKeyed, not read-only text

## Summary

T3569's All Settings showed a repeatable key (font-family, keybind, palette, env, ...) as a disabled comma-joined field, and T3631's curated list rows (Font, Font features) the same. Port Mac's `ListControl` over win32's shared `SettingsModel.setList`: the user's file's values as removable chips plus an "add a value" field, on the curated list rows and on every All Settings list row, with Mac's "In effect:" line under the latter. setList keeps the longest matching run of lines (their comments stay). Seam ops add / remove as win32 `ipc_settings.zig` names them (plus list-add / list-remove for a curated row); extend test/linux/settings-window.sh.

Re-scoped on 2026-11-25 against the Mac code: Mac's Settings UI never calls `setKeyed` (its only consumer will be the Keyboard page's binding editor, not yet built on Mac) - keybind / palette / env entries go through `ListControl` and `setList` there too, which is what this card ports. The keyed path stays in the shared model for that editor.

## In plain terms

On Linux, settings that hold a list - extra fonts, font features, key
bindings, colour palette entries, environment variables - used to show as a
greyed-out line you could not change. Now each value is a small tag with an
x to remove it, and a box beside them adds a new one, exactly like the Mac.
A value the terminal would not understand is refused with the reason, and
nothing in your config file changes.

## Goals
