# T1372 - Acceptance oracles still sleep a flat interval for a repaint and pick their click target out of a fixed box

## Summary

T561 removed both bets from activity-monitor.ps1 section J: it now derives the painted band from the capture, clicks the glyph's centroid, and waits for the condition while recording the latency (135-141ms observed against a 600ms budget). The same two shapes - a Start-Sleep between a posted click and a pixel assert, and a hand-written search box whose bounds are a guess at where a control is - are spread across test/win32. Sweep for them and convert the ones that gate on a painted result; each is a flake nobody can read when it fires.

## In plain terms

Some of the automated checks click something, wait a fixed fraction of a second,
then take a picture and check it. On a busy machine the picture can be taken
before the app has redrawn, so a working feature is reported as broken, and the
report gives no clue why. After this change those checks wait until the screen
actually shows the result (with a deadline), and they say how long it took.

## Goals

- [x] every "click/key, fixed sleep, capture" site that gates on a painted result waits for the result instead (six sites, table below)
- [x] one shared wait helper rather than a hand-rolled loop per script (`test\win32\lib\PaintWait.ps1` `Wait-TestPaint`)
- [x] the "click target found in a guessed box" shape checked for across the suite (none left outside T561's own fix)
