# T711 - The Windows machine chooser has no warm/seeded device list: it opens empty and blocks on the network

## Summary

Mac persists the device list and seeds the chooser instantly (66012e2ee), warms it with a quiet refresh at launch (b0028112a), presents cache-seeded rows as 'checking' (55dd70978), and polls the directory live while the chooser is open (27e639ae6). The win32 chooser fetches on open with nothing cached, so Ctrl+Shift+N shows an empty list until the relay answers and never updates while it is open. Found by the T684 sweep.

## In plain terms

Press ctrl+shift+n to open a window on another machine and the list of your
machines is empty until the network answers - every single time, because
nothing was remembered from the last time you looked, and the dialog asked for
the list while you were waiting on it. On a slow or dead connection that is a
dialog that just sits there. And once it is open the list is a photograph: a
machine that comes online, gets renamed, or is removed does not show up until
you close the dialog and open it again.

After this, the chooser opens instantly on the machines it remembers from last
time, each one marked as being checked until the live answer confirms it, and
it keeps itself up to date while it is open.

## Goals

- [x] the chooser opens on remembered machines, without waiting for the relay
- [x] a remembered row reads as "checking", never as a confident online/offline
- [x] the remembered list is per-account and is dropped on sign-out or a 401
- [x] the app warms the list in the background at launch
- [x] an open chooser re-asks every 5s: renames, removals and presence land live
- [x] a transient failure keeps the list that is on screen and stays quiet
- [x] the selection stays on the machine it was on when a refresh changes rows
