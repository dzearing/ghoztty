# T2919 - The visibility poll reads a window hidden with SW_HIDE (a close-undo park) as visible, so a layout pass in a parked window wakes its panes

## Summary

Found in T2914. occlusion.windowHidden checks IsIconic, cloaked and coverage, never IsWindowVisible on the target itself, so a close-undo-parked window (SW_HIDE) reads .visible and Window.occluded stays false. CloseUndo hides the panes once on park, but any layout pass while parked (an IPC verb, a config reload) marks them visible again with no poll to undo it. Fix shape: windowHidden returns a hidden state for !IsWindowVisible - but a window created hidden and shown later must then be revealed at show time (refreshOcclusion on WM_SHOWWINDOW), or a new window would come up blank for a poll interval. Acceptance: extend test/win32/hidden-new-pane.ps1.
