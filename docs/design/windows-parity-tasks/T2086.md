# T2086 - Glass panes on Windows: unfocused panes are the more see-through ones, stacked and hero panes are glass, and a slide resizes each terminal once

## In plain terms

With glass panes on, the panes you are not using should be the more
see-through ones, so your eye goes to the focused pane. On Windows today
every pane uses the same heavy 40% sheet. Hero mode and stacked panes
should be glass too, and a pane sliding into view should resize its
terminal once, not seven times.

## Summary

Mac 89848fd59 (`feat(macos): glass panes - unfocused panes see-through,
stacks and hero glass, one resize per slide`):

- Unfocused glass panes get a thinner sheet (15% tint vs 40%). The whole
  terminal (text and sheet) fades by `unfocused-split-opacity`. The
  background-colored wash is not drawn on glass, because it made unfocused
  panes the MORE opaque ones. Viewers get the thinner sheet only.
- Stacked rows have no solid cards: a tucked card is drawn as its strip
  alone, with its content hidden, and its terminal keeps its last on-show
  size.
- A resizing slide resizes each terminal once, together, after the slide.
  Focus fades animate opacity only (an animated frame had caused 7
  terminal resizes per strip click).
- Hero mode uses the same glass card as a focused pane.
- (The viewer key changes in the same commit are T2087. The command
  palette over a viewer already exists on Windows, `viewer_accel.zig:341`,
  so nothing is owed there.)

Windows today: `pane_elevation.zig:224` `GLASS_TINT = 0.4` for every pane.
The unfocused dim is the separate DimOverlay wash. That is exactly the
combination Mac removed on glass.

Windows translation: a focus-dependent tint (0.15 unfocused, 0.40 focused,
faded on T1834's focus-fade timeline). On glass, unfocused panes fade by
`unfocused-split-opacity` instead of getting the DimOverlay wash, which
fits T1809's rule (viewers never dim) because viewers just get the thinner
sheet. The hero card uses the focused glass. The stacked-row and slide
parts ride on T2082.

## Validation criteria

- [ ] Pixel oracle (PrintWindow capture, test desktop): the backdrop
      contributes more to an unfocused glass pane's background pixels than
      to the focused one's (measured), and no DimOverlay window exists for
      a glass pane. A negative control at the old tint fails.
- [ ] A viewer pane gets the thin sheet and no dim (T1809 still holds).
- [ ] Hero mode's card matches a focused pane's glass (same tint value
      logged).
- [ ] Each terminal gets one resize per slide (counted; with T2082).
