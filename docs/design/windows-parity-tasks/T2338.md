# T2338 - Windows all-windows sidebar: dragging a window row into a project group or out of one retitles the window (<project>: <name> / <name>, pinned) and outlines the group it would join, as on Mac

## Summary

Mac 379a352ef. A window drag reads the whole list as rows (group headers, their windows, lone windows; PaneSidebarCrossDrop) and every row slides on its own; right under a header or between a group's windows joins that group; past a group's last row the upper half joins, lower half lands after it at top level. Joining outlines the group header (PaneSidebarJoinHighlight). Dropped in another group: renamed '<project>: <name>'; dropped out: '<name>', pinned like Change Window Title. Grabbed open, it folds to its row under the pointer. Distinct from T1879 (moving PANES between windows). Mac ref: docs/reference/pane-sidebar.md 'A window drags anywhere in the list'; tests PaneSidebarCrossDropTests, PaneSidebarSyncWindowTests.dragMovesAWindowIntoAndOutOfAGroup.

## In plain terms

On Mac you can drag a window in the sidebar into a project group, or out of one, and the window is renamed to match. Windows cannot. After this, dragging a window onto a group on Windows moves it there, with the group outlined while you hover it.

## Goals

- [ ] A window drag reads the whole list as rows and can land in or out of any group
- [ ] The target group's header is outlined while the drop would join it
- [ ] Dropped into a group the window is retitled '<project>: <name>', out of one '<name>', pinned

## Validation criteria

- [ ] Unit tests for the cross-group drop resolver (join vs after-the-group halves)
- [ ] On-box acceptance: drag into a group and back out, titles read back via +list
- [ ] -NegativeControl goes red
