# T2423 - Starting a drag in the Windows pane sidebar repaints only the window in use, not every window's sidebar (Mac 6bd2962eb: a 0.4-1.3s stall with 20 windows)

## Summary

Mac main 6bd2962eb: starting an item drag used to redraw every window's sidebar (0.4-1.3s stall with 20 windows); now only the window in use redraws. Windows: measure drag-start latency with many windows open (the shared sidebar from T2336 broadcasts state to every window); make a drag start touch only the source window's sidebar and catch the others up after; add a timing check. Also from the same commit: a stale sidebar catches up WITHOUT animating. Ref PaneSidebarItemDrag.swift / PaneSidebarSyncWindowTests.swift in 6bd2962eb.

## In plain terms

On the Mac, picking up a window in the sidebar's all-windows list used to
freeze for up to a second when many windows were open, because every window
redrew its sidebar at once. On Windows the other windows already wait until you
switch to them before redrawing, so a drag starts at once. This task measures
that, and adds a check so it stays that way.

## Goals

- [x] A drag start says how long the lift took and how many other windows it redrew
- [x] A twelve-window test proves only the window in use redraws, fast
- [x] A window left behind catches up, without a glide, when it is next activated

## Validation criteria

- [x] The lift redraws only the window in use: section 10 of
      `test\win32\pane-sidebar-window-order.ps1` (twelve windows) reads
      `item drag lifted us=999 redrawn=1 others_redrawn=0 others=11 others_behind=11`
      - ALL PASS (74), 2026-10-28.
- [x] It is fast: the same line, 1 ms on a Debug build (bound 80 ms; Mac's
      stall was 0.4-1.3 s with 20 windows).
- [x] Another window, activated, catches up then (same section); `catchUp`
      takes the shared state and refreshes with no glide or cross-fade (it
      never calls `startTransition`), so Mac's "catches up without animating"
      already holds - verified by reading `catchUp`/`refresh`.
- [x] Negative control: `-NegativeControl` activates no other window, and the
      catch-up check goes red (7 failures, the expected two sections).
- [x] Floor: `floor-lane.ps1 -Lane all` ALL LANES PASS.
