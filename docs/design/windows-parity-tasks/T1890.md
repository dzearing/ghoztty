# T1890 - A bell on Windows ignores bell-features audio, title and border: no sound file, no bell in the title, no border flash

## In plain terms

On a Mac, a terminal that beeps can play a sound file you chose and puts a
little bell in front of the window title until you look at it. On Windows it
did neither. Now both happen. The third option, a yellow frame around the
pane, is split out to T1919.

## Goals

- [x] `audio`: a bell plays `bell-audio-path` at `bell-audio-volume`
- [x] `title`: the window caption (and taskbar / Alt-Tab text) and the tab's label lead with the bell emoji while the pane the tab is titled after has an unacknowledged bell
- [x] the glyph clears when the pane is looked at (focus or a key), as on Mac
- [x] `border` filed as its own task (T1919) - it needs a new overlay window

## Summary

T1843 made ring_bell honor bell-features system (MessageBeep, now off by default as on Mac) and attention (taskbar flash). Mac also honors: audio (bell-audio-path at bell-audio-volume), title (a bell glyph prefixed to the window title while the focused surface's bell is set - BaseTerminalController.computeTitle), and border (SurfaceView BellBorderOverlay). The pane's bell flag now exists on the win32 Surface (Surface.bell, cleared on focus/key), so title and border can key off it.

**Scope as landed (2026-10-13):** `audio` and `title`. `border` is T1919.

## What changed

- `src/apprt/win32/bell_math.zig` (new, pure, unit-tested in every lane): the
  title prefix (U+1F514 + space, Mac's exact string) and its gate, the
  0..1 -> 0..1000 MCI volume mapping (clamped, NaN -> 0.5), and the MCI
  command strings.
- `src/apprt/win32/bell_audio.zig` (new): plays the file through MCI's
  `mpegvideo` (DirectShow) device - any format Windows has a codec for, async,
  and the only MCI device that honours a volume. `PlaySoundW` was rejected:
  wav-only and no volume, so `bell-audio-volume` would mean nothing. winmm is
  resolved at run time from System32 (`LoadLibraryExW` +
  `LOAD_LIBRARY_SEARCH_SYSTEM32`, the T1251 gl_loader pattern) so the app takes
  no load-time dependency for an opt-in feature. The device stays open per
  path; a path that cannot open is logged once, not per ring. Closed at
  `App.terminate`.
- `App.zig` `ring_bell`: `audio` plays alongside `system`, as Mac does.
- `Window.zig`: `tabBellPrefix(i)` keys the glyph on the tab's focused pane
  (Mac reads the bell of the surface it titles after); `updateWindowTitle`
  leads with it - over a pinned title too, as Mac's `computeTitle` does; the
  tab strip measures and paints it as a separate run so the title's animated
  spinner cell (T60) still starts the title. `onPaneBellChanged` re-titles and
  repaints the strip; `Surface.setBell` calls it instead of the bare sidebar
  sync.
