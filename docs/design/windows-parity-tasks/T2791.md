# T2791 - Harnesses split with --target=<pane name> where they mean the exact pane (drag-glide p4, pane-sidebar-motion-cost s2, pane-sidebar-rename a2): --target splits that pane's window's ACTIVE pane, so their layouts are not the ones their comments describe (T2753 shape)

## Summary

T2753 found `close-overlays.ps1` splitting `--target=c2` and expecting the
new pane beside c2. By contract (both platforms, `docs/claude/cli.md`
`+split`), `--target=<pane>` resolves to the pane's window and splits that
window's active pane; CLI splits open in the background, so the active pane
is usually the window's first one. A grep for `+split --target=<a name an
earlier +split --name= created>` finds:

- `test/win32/drag-glide.ps1:209` (`--target=p4 ... --name=p5`)
- `test/win32/pane-sidebar-motion-cost.ps1:141` (`--target=s2 ... --name=s3`)
- `test/win32/pane-sidebar-rename.ps1:383` (`--target=a2`, a viewer beside a2)
- possibly `pane-sidebar-scroll.ps1:192` (`--target=p1`, check whether p1 is a window)

For each: read what layout the script means, switch to `--pane=` where it
means the exact pane, and re-run it green. Where the window's active pane is
what it means, leave it and say so in a comment.

## Validation criteria

- [ ] each listed script either uses `--pane=` for an exact-pane split or carries a comment saying the active pane is intended
- [ ] each changed script runs green
