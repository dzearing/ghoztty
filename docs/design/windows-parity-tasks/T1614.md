# T1614 - window-active-audit is not in the harness floor family, so -Lane harness leaves it DUE and every turn pays for a second run

## Summary

guard-due.ps1 carries window-active-audit and printclient-audit side by side: same shape (a source-scanning audit, no GUI), same 237-file Covers list over src/apprt/win32/, adjacent registry entries. printclient-audit.ps1 is a member of scripts/lib/HarnessFloor.ps1; window-active-audit.ps1 is not. Consequence, measured on the T790 turn: floor-lane -Lane all plus -Lane harness ran green and re-stamped 384 files, and window-active-audit was still DUE afterwards because the only thing that touched it was a doc-comment edit to MachineChooser.zig and activity_rows.zig - so validate refused the commit until it was run standalone. Any turn that touches a win32 source file pays the same tax. Either add it to the family (it costs what printclient-audit costs, and the family is exactly the set of standing source scans) or write down why it is deliberately outside, because right now the asymmetry reads as an oversight rather than a decision.

## In plain terms

One of the standing source checks was left out of the group that runs them all
together, so after every change to the Windows app it had to be run a second
time by hand before the change could be saved. It now runs with the rest.
