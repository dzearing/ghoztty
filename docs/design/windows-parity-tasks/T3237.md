# T3237 - The agent's pipe stream creates and closes a kernel event for every single read and write (pipe_stream.zig:202) - ~0.85 s of agent CPU per 64 MB flood; cache one per stream per direction

## Summary

Profiled in T3159: src/remote/pipe_stream.zig:202 overlappedEvent() creates a fresh manual-reset event for EVERY overlapped ReadFile/WriteFile and closes it after (readImpl :251, writeImpl :278). In a 64 MB flood that is ~0.6 s of holder CPU (NtCreateEvent 0.45 s + NtClose 0.14 s on the writer thread) and ~0.25 s of daemon CPU (serverRead and serverWrite both pay it). Fix: one cached event per stream per direction (reads are single-reader per stream; writes may race, so take the cached write event with an atomic swap and fall back to a fresh one when it is in use), reset before each op. The comment's reason for per-call events (concurrent read+write must not share a wait state) is preserved by keeping read and write events separate. Check the same pattern in src/os/ipc_client.zig:189 and src/apprt/win32/ipc_pipe_io.zig:80. Windows-only code (named pipes); the Mac socket path has no per-op event. Measure with perf-baseline.ps1 -Build Release -Phase busy -BusyPersistence -SampleAgent.
