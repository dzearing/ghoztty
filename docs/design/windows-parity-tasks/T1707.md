# T1707 - Re-point viewer-feedback-capture.ps1 from the RichEdit fallback to the web composer

## Summary

viewer-feedback-capture.ps1 reads the RichEdit's text as its chip oracle and types 'this bit here' into it around the capture flow. Re-point the chip oracle to Get-CdpComposerText (chips read as their [Image #N] label) and the typing to Send-CdpComposerText. Split out of T1703, which landed the pattern on viewer-feedback-alpha.ps1: arm ONE DevTools port per script with Enable-WebViewCdp before the first launch, open the composer, Find-CdpComposer (pass -Exclude for pages an earlier app used), then type with Send-CdpComposerText / Send-CdpKey, paste pictures with Send-CdpComposerImage, and read back with Get-/Wait-CdpComposerText (test\win32\lib\WebViewCdp.ps1). Chords NATIVE owns (Ctrl+Enter, Esc) still go through the band's window messages. Assert Wait-ComposerSurface 'web' instead of pinning 'richedit'. When done the script no longer calls Set-ComposerSurface 'richedit' or reads a RichEdit50W, which is what T1704 needs before it deletes the fallback.

## In plain terms

The test that checks the feedback box's screenshot button was still driving an old,
hidden version of the text box that users never see. It now drives the real one, so
a break in the box people actually use shows up here, and the old hidden box can be
deleted without losing this test.

- [x] Nothing in it depends on the RichEdit fallback any more, so T1704 can delete it
