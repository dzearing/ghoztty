# T1166 - A script's suite-timeout declaration can stop parsing without anyone being told

## Summary

soak.ps1 lost its 2400s declaration to a CRLF rewrite (ce943e238) and was silently back to being killed at 600s and scored a stall - the exact defect T1125 fixed. T1137 made the regex CRLF-tolerant, but the shape of the failure stands: a declaration that does not parse is indistinguishable from no declaration at all. The runner should say so - a script whose text contains 'suite-timeout-sec' and whose declaration did not parse gets a named warning in the run header and in 'list', instead of quietly inheriting the global cap.

## In plain terms

A test script can say "I need longer than the usual time limit". If that line
had a typo, the test runner quietly ignored it and killed the test early, and
the result looked like the app had hung. Now the runner prints a warning naming
the script and the line it could not read. One shipping test had exactly this
typo and has been fixed.

## Goals

- [x] a declaration that tried and did not parse is named in `suite-run.ps1 list`
- [x] ...and in the run header of `suite-run.ps1` and `acceptance-parallel.ps1`
- [x] the shipping suite carries no unparseable declaration (agent-lineage-suites.ps1 fixed)

## Validation criteria

- [x] `Get-ScriptTimeoutProblem` reports a missing-colon declaration with its line, and stays silent for a good one, a here-string mention and no declaration - A12 of `test\win32\acceptance-parallel.ps1` (ALL PASS, 74)
- [x] `suite-run.ps1 list` prints the WARNING under the garbled script only - N15/N16 of `test\win32\suite-run.ps1` (ALL PASS, 134)
- [x] the run header prints it - N17 (`-DryRun` header)
- [x] no shipping `test\win32` script carries one, and agent-lineage-suites.ps1 now reads as declaring 900s - N18
- [ ] the `acceptance-parallel.ps1` queue-time WARNING is emitted via Out-Host and not captured by a harness; verified by reading only (the function behind it is A12's subject)

## Design notes

An "attempt" is a line comment that OPENS with the key, spelled loosely
(`(?i)^\s*#\s*suite[-_ ]?timeout`), so case slips, `_` and a missing `-sec`
are caught. Block comments and strings that mention the key are not attempts -
the same comment-token rule T1960 gave the reader, so suite-run.ps1's own
fixture here-strings never warn. The fallback to the run's cap is unchanged
(N11); only the silence is gone.
