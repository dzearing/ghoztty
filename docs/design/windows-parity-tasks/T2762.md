# T2762 - Composition step 5d-2: the hover tint's fade is a compositor opacity animation - the tint first becomes a child visual of the pane (comp_overlay.Layer, like BellBorder) instead of a WS_EX_LAYERED popup

## Summary

HoverTint.zig is still a layered popup stepped on FrameClock; move it onto the pane's composition tree (visual path + popup fallback, the BellBorder shape), then declare its fade with Layer.animateOpacity. Oracle: T2552-style film with stall seam and stepped control.

## In plain terms

When you point at a pane's row in the sidebar, that pane glows faintly in
its colour and the glow fades out again when you move away. That fade was
timed by the app itself, so a busy moment could make it stutter or stall.
Now Windows plays the fade, so it stays smooth however busy the app is, and
the glow is part of the pane's own picture instead of a separate floating
window laid over it.

## Goals

- [x] the tint is a child visual of a terminal pane on the composition path (the default), with the popup kept for a banner pane, a viewer pane and a SwapBuffers pane
- [x] its fade in (0.12 s) and fade out (0.2 s), both easeOut, are each declared to the compositor in one call, with one end timer for the bookkeeping
- [x] a fade retargeted halfway, or one running when the renderer rebuilds its tree, carries on from the value it had reached
- [x] debug seams for the oracle: `GHOZTTY_DEBUG_HOVER_TINT_FADE_STEPPED` (the A/B arm) and `GHOZTTY_DEBUG_HOVER_TINT_FADE_STALL_MS`
- [ ] the on-screen film at UI stalls of 0/50/500 ms -> T2797 (needs CopyFromScreen on the real desktop, which this loop cannot run)

## Design

The BellBorder shape (T2467/T2469), not the DimOverlay one, because the tint
has per-pixel alpha (rim plus wash, rounded card) and a timed fade. The
popup HWND stays as the timer host on both paths. `wantVisual` takes the
visual only when the pane has a composition slot AND no banner band
(`Surface.grid_band == 0`). The tint covers the whole pane window, band
included, and the pane's visual starts below the band, so a banner pane keeps
the popup (the same call DimOverlay made in T2491). Like every other overlay
the layer attaches at the back (T2617), so it sits under the unfocused-split
dim, which matches Mac, where the dim is the last layer of the pane. The
curve is `pane_hue.easeOut` fitted by `comp_overlay.fitCurve`. The duration
is `pane_hue.fadeMs` (direction-dependent, fixed regardless of distance, as
SwiftUI retargets).
