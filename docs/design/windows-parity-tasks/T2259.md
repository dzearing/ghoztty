# T2259 - A wsl pane's prompt has not been proven to reflow live on resize: prompt-reflow.ps1 covers cmd and Windows PowerShell only, since starting WSL is the user's call

## Summary

T2251 proved Mac a81db68f9's live prompt reflow on Windows for cmd and Windows
PowerShell, local and agent-backed (`test\win32\prompt-reflow.ps1`), and found
that conhost's post-resize paint ends cmd's `133;I` input region - fixed with
the ConPTY prompt-row pacing rule (`Termio.conptyPromptRow`). A wsl pane was
not run: WSL's bash integration marks its prompt with `133;B` (open input,
like PowerShell), so it should take Mac's path, but its prompt arrives through
wsl.exe inside the ConPTY and nobody has watched it. Starting WSL is the user's
call on this box (it once took 28 GB), so this waits for a box where WSL is
already up, or the user's go-ahead.

Add a section E to `prompt-reflow.ps1` with `--command=wsl.exe`, SKIPPED (not
failed) when no distro is running.

## Validation criteria

- [ ] With WSL already running, a divider drag and a window resize over a wsl bash prompt are decided live, never released by the cap, and the prompt is still there afterwards (`prompt-reflow.ps1` section E).
- [ ] With WSL not running, section E reports SKIP with the reason and never starts WSL.
