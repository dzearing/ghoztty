# T3388 - A release build launched inside a test sandbox can auto-update and run msiexec against the user's real installed Ghoztty

## Summary

path-selfheal.ps1 section J launched a zig-out-release copy from the sandbox's LOCALAPPDATA\Programs\Ghoztty. A release build treats that folder as the installed release, so its automatic update check ran with the default download policy, staged Ghoztty-1.56.7-x64.msi under the sandbox and ran msiexec. msiexec is per-user product state, not sandboxed by LOCALAPPDATA: on 2026-11-22 05:42:01 it reconfigured the user's real product (MsiInstaller 1035), and the install-prepare custom action renamed the real %LOCALAPPDATA%\Programs\Ghoztty\ghoztty-agent.exe aside (ghoztty.log win32_install_prepare, pid 49092) with no fresh copy written back, so the user's install had no agent exe until it was restored by hand from the .old-1795354921 sideline. path-selfheal J now passes --auto-update=off (T1768 turn). Remaining: make Set-GhozttyTestIsolation -ReleaseSandbox itself disable updates (env or config) so no release-sandbox harness can reach msiexec, add an audit that flags release launches without it, and consider whether an app running outside the real install dir should ever apply an MSI that targets it.

## In plain terms

A test that ran a copy of the released app inside a throwaway folder let that
copy check for updates, and the installer it ran treated the user's real
Ghoztty as the thing to update, leaving it missing a file. After this, every
test sandbox switches automatic updates off, and the test helpers refuse to
start a release copy that has not done so.

## Goals

- [x] the app honors a `GHOZTTY_AUTO_UPDATE=off` switch that overrides the `auto-update` config (a harness's own test feed still wins)
- [x] `Set-GhozttyTestIsolation -ReleaseSandbox` sets the switch
- [x] the release-sandbox gate (`Get-GhozttyReleaseSandboxGaps`, behind every `-Allow`/`-AllowReleaseBuild` launch) refuses a release launch without it
- [x] follow-ups filed: the app-side "never apply an MSI that targets another folder" (T3393), and the update-* harnesses that run real msiexec on purpose (T3394)
