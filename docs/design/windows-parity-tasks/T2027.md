# T2027 - Two loop lanes stamping the same harness collide: a stamp.json both lanes committed conflicts on the commit guard's pull --rebase, and a dirty stamp blocks the pull outright

## Summary

Seen closing T1986: lane B committed argv-hazard-audit, harness-floor and unroll-count-audit stamps while lane A held uncommitted stamps for the same three harnesses. git pull --rebase refuses any dirty tree, and two commits that each rewrite one stamp.json conflict on rebase (stamps are JSON, not merge=union). Lane A got through only by restoring its three stamps to HEAD by hand and letting lane B's fresher stamps stand. Fix options: a merge driver for *.stamp.json that keeps the newer stamp, or stamps written outside the tracked tree per lane. Validation: a two-clone harness where both lanes stamp the same guard and commit, and the second commit through git-commit-guard.ps1 pushes without a conflict (with a negative control without the fix).

## In plain terms

Two copies of the work loop now run side by side, and both record "this test
passed against this code" in the same small files. When both changed the same
file, the second one to save its work got stuck and needed a person to sort it
out. Now the newer record simply wins, and a record that was not saved yet is
set aside and put back, so neither loop gets stuck.

## Goals

- [x] Two lanes committing the same stamp no longer conflict: the newer stamp is kept whole
- [x] A stamp left uncommitted no longer blocks the guard's pull --rebase
- [x] Anything that is not a stamp is still never moved by the guard

## Fix

- `test/win32/*.stamp.json merge=ghoztty-stamp` in `.gitattributes`; the
  driver is `scripts/stamp-merge.ps1` (rule in `scripts/lib/StampMerge.ps1`):
  keep the stamp with the newer `generated`, tie keeps ours, and an unreadable
  side falls back to `git merge-file` so it is still a marked conflict.
- `git-commit-guard.ps1 install` registers `merge.ghoztty-stamp.driver` in
  local config (the claim re-runs install every turn). A clone without it (the
  Mac seat) gets git's text merge, as before.
- `Invoke-PushWithRebase`: when the only dirty tracked files are guard stamps,
  they are parked in memory, reset to HEAD, the rebase runs, and each comes back
  only if it is newer than the pulled one. A dirty non-stamp file disables the
  parking entirely (the no-autostash rule stands). A rebase that stops leaves
  the parked stamps in `<gitdir>/ghoztty-parked-stamps/`.
- Design choice (mechanism, not a decision): newer-wins over per-lane stamps
  outside the tree, because guard-due re-checks the kept stamp's hashes against
  disk, so a wrong pick reads DUE and costs one re-run, never a false green.
