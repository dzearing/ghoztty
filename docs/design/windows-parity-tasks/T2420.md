# T2420 - pane-sidebar-glide.ps1 section 2's gutter-held oracle flakes: 4 of 6 mid-glide samples within 2 px (gaps 0,3,0,0,3,1) on a due sweep, ALL PASS alone

## In plain terms

The test that checks the sidebar's edge moves together with the panes beside it
sometimes failed on a busy machine even though nothing was wrong: it measured
the two edges at slightly different moments, while they were moving. It now
measures them together, so it fails only when the edges really drift apart.

## Goals

- [x] the gutter oracle reads the column and the pane with no motion between the reads
- [x] green under sweep-like load, where it used to flake
- [x] a column on its own easing (tens of px off) would still fail it

## Summary

`Get-GutterSamples` (test/win32/pane-sidebar-glide.ps1) took each sample as two
`Get-TestChildWindows` enumerations - one for the column, one for the pane - so
the glide moved between the two reads, and under a sweep's load that was the
3 px "gap" (gaps 0,3,0,0,3,1 / 3,3,2,0,3,1 vs 0 at rest). Fix: resolve both
hwnds once and read the rects by handle (`Get-TestWindowRect`, GetWindowRect)
back to back, with the column read on both sides of the pane read. The app
moves the grid first and the column after it in the same step
(`PaneSidebar.gridStepped`), so a read landing inside the step sees grid-new /
column-old; the second column read sees it caught up. The threshold (2 px, 5 of
6) is unchanged, so a column on its own easing - tens of px off on both reads -
still fails.
