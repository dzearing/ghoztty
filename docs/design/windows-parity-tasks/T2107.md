# T2107 - Stacked panes: a pure adapter turns the win32 split tree into pane_stack_layout nodes (stash-aware, index for index) and the engine's DIP result into pixel pane rects, strip tabs and divider gutters

## Summary

First slice of T2101 (split 2026-10-20). pane_stack_grid.zig: build engine Nodes from SplitTree(View) index for index, a split with a wholly stashed side resolving to its visible child so Divider.node still names a real split; scale DIPs<->px by the window DPI; return pane px rects, tucked/sliver flags, strip tab rects and divider gutters. Unit-tested in the none lane.

## In plain terms

The new stacked-panes layout works in its own units and its own picture of
the panes. The window speaks pixels and keeps its panes in a split tree. This
is the translator between the two, tested on its own, so the next step can
switch the window over to it without guessing at the arithmetic.

## Goals

- [x] The window's split tree becomes the layout's input, node for node, so a
      divider the layout reports names the real split a drag must move
- [x] A stashed pane gets no slot: the split holding it folds into its other
      side, the same rule the window's layout already follows
- [x] Layout answers come back as pixel rects at any DPI, with neighbouring
      panes sharing their edges exactly and the grid ending on its own edge
- [x] Hit tests the window will need: which divider gutter, which strip
      (topmost wins where strips overlap)
