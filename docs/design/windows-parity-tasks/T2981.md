# T2981 - PA-R15: pane GL pixel format asks for a 24-bit depth and 8-bit stencil buffer the renderer never uses, costing ~5 MB per pane on machines without composition interop

## Summary

PA-R15 (audit-1, T2959). apprt/win32/Surface.zig:1735 PFD_DOUBLEBUFFER and :1751-1752 cDepthBits = 24, cStencilBits = 8. The renderer draws to an offscreen RBO and blits colour only. On the default path the format sits on a 1x1 helper (free); on the SwapBuffers fallback (no WGL_NV_DX_interop2: Mesa, some Intel/AMD, RDP) every pane carries a pane-sized D24S8 buffer, ~5 MB at 1400x900, on the machines with the least VRAM. Fix: cDepthBits = 0, cStencilBits = 0 (wglChoosePixelFormatARB for a strict pick). Risk low.
