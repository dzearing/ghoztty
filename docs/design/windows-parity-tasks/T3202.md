# T3202 - Pane popups are owned by the TOP-LEVEL window, not the pane: a parked workspace's banner/dim/badge popups die with the shared window when it closes under them, and a pane dragged to another window keeps popups owned by the window it left

## Summary

Found in T3192. Windows makes a child window's top-level ancestor the owner of a WS_POPUP created against it (win32.zig seatedAboveOwner already compares GW_OWNER against the root), so every pane overlay (Surface.overlay_fields, link preview, search, palette, hover tint, strip face) is owned by the window it was created in - contrary to the comment on Window.adoptPane. Single-window mode: a workspace that surrendered the shared HWND keeps popups owned by it; when the shared window is destroyed under parked workspaces (App.forgetWorkspace -> promoteToOwnWindow) Windows destroys those popups and the Surface holds dead HWNDs (banner never comes back; hide/show on a dead handle). Birth-parked panes' popups are owned by the park host. Cross-window rearrange (T1538 adoptPane) has the same shape when the source window then closes. Verify first with GetWindow(GW_OWNER) on a moved pane's banner; fix by re-owning (SetWindowLongPtrW GWLP_HWNDPARENT to the new top-level) wherever a pane changes top-level: adoptPane, Window.reparentPane (surrender/adopt/promote). Acceptance: single-window-mode.ps1 (close the shared window with a bannered parked workspace, show it, banner back) + a rearrange-window-drop arm.
