# T3202 - Pane popups are owned by the TOP-LEVEL window, not the pane: a parked workspace's banner/dim/badge popups die with the shared window when it closes under them, and a pane dragged to another window keeps popups owned by the window it left

## Summary

Found in T3192. Windows makes a child window's top-level ancestor the owner of a WS_POPUP created against it (win32.zig seatedAboveOwner already compares GW_OWNER against the root), so every pane overlay (Surface.overlay_fields, link preview, search, palette, hover tint, strip face) is owned by the window it was created in - contrary to the comment on Window.adoptPane. Single-window mode: a workspace that surrendered the shared HWND keeps popups owned by it; when the shared window is destroyed under parked workspaces (App.forgetWorkspace -> promoteToOwnWindow) Windows destroys those popups and the Surface holds dead HWNDs (banner never comes back; hide/show on a dead handle). Birth-parked panes' popups are owned by the park host. Cross-window rearrange (T1538 adoptPane) has the same shape when the source window then closes. Verify first with GetWindow(GW_OWNER) on a moved pane's banner; fix by re-owning (SetWindowLongPtrW GWLP_HWNDPARENT to the new top-level) wherever a pane changes top-level: adoptPane, Window.reparentPane (surrender/adopt/promote). Acceptance: single-window-mode.ps1 (close the shared window with a bannered parked workspace, show it, banner back) + a rearrange-window-drop arm.

## In plain terms

A pane's floating extras - its banner, dim wash, badges, link preview - were
tied to the window the pane was born in, not to the pane. Move the pane to
another window (drag it out, or switch workspaces in single-window mode) and
then close the window it came from, and those extras were destroyed with it:
the pane's banner never came back. Now they move with the pane.

## Goals

- [x] every popup a pane owns is handed to the pane's new window whenever the pane changes window
- [x] a banner survives the window its pane left closing
- [x] a debug seam can tell when a popup is owned by the wrong window

## Validation criteria

- [x] Cross-window move: the popped-out pane's banner popup is owned by the new window, and survives the old window closing - `rearrange-window-drop.ps1` RUN 3 (T3202 arm), green 2026-11-17.
- [x] Single-window mode: no pane popup is owned by a window its pane is not in, on show (E2) or parked (E4) - `single-window-mode.ps1` via the `workspaces` seam's `popups_misowned`, green 2026-11-17.
- [x] The checks can fail: a build with the re-own disabled (`zig-out-t3202neg`, `-ExePath`) fails exactly those three assertions (E2 misowned=3, E4 swm-b=3, D new=0 old=1).
- [x] Floor: `floor-lane.ps1 -Lane all` ALL LANES PASS; due sweep 53 green, 8 red all acked to open tasks (T2300, T2921, T2690, T2820, T2884, T2905, T2692).

## Not tested

The promote path (shared window destroyed under parked workspaces, `App.forgetWorkspace` -> `promoteToOwnWindow`) has no driver: every ordinary close hands the window on rather than destroying it. It goes through the same `reparentPane`, which the E2/E4 arms exercise.
