# T3711 - The app serves a remote session's forwarded +verbs under the remote-origin scope policy (app_ipc dispatcher, win32)

## Summary

Third slice of T2217 (docs/design/remote-viewer-tunnel.md decisions 2 and 4). The app serves APP_REQUEST frames: Connection (src/remote/connection.zig) advertises capability.app_ipc, hands each APP_REQUEST to the window that shows the session, and the win32 IPC server runs request through apprt/ipc/server.zig dispatch under the remote-origin policy in src/apprt/ipc/remote_origin.zig: origin = the connection's machine key (never a request field); caller pane forced to the local pane bound to session_id (forcedCallerPane), replacing Request.caller_pane and any --caller-pane= arg; scope(verb): .refused verbs answer refusedMessage; .own_target lookups treat a target outside targetInScope as NOT FOUND (no existence leak); .own_list filters +list to the origin's panes; .creates_remote makes +split/+new-window without --view open a pane on the SAME remote machine with its per-host default shell (a remote can never spawn a local shell), and a --view creates a viewer owned by the origin. Reply with APP_RESPONSE{response} (or error when no pane is bound: unbound_session_message). Fix docs/claude/cli.md's 'a remote pane's IPC still belongs to the local app' line to describe the real path. Unit tests for the policy enforcement in the win32 lane; end-to-end acceptance is T2225 (loopback agent). The GTK frontend's half is a seat: linux follow-up.
