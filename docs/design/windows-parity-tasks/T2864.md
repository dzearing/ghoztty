# T2864 - Mac: check whether a launch with a startup command plus a session restore can rebuild the command's own window as a crash orphan (Windows T2842)

## Summary

Windows T2842 (2026-11-08): a launch with `--initial-command` opens its window
BEFORE launch restore (T406). The restore's message pumps let that window's
layout sync mirror it into the agent's layout store, the agent pull read it
back as a "crash orphan", and reconcile adopted it. The rebuild put up a second
window with a fresh shell under the SAME pane id, so every `--target=<id>` was
ambiguous. The Windows fix makes the launch pass skip every offered window that
is already on screen (`session_layout.appendNotShownHere`, by layout key or by
session id), the same filter the deferred pass applied.

Mac seat: check whether `SessionLayoutManifest` reconcile/adopt on a launch
that carries a startup command (`-e` / `initial-command` / `command`) can read
back the launch window's own blob from the agent. Do this especially when the
manifest has regressed after a crash, since then the union holds orphans and
the pull happens after the first window exists. If it can, apply the
same already-on-screen filter. If it cannot, record why and close.

## Validation criteria

- [ ] a Mac launch with a startup command over a crash-regressed manifest shows the command window once, with every pane id unique in `+list --json`
