# T3568 - Linux L11f: terminal resize pacing on GTK - one paced SIGWINCH per divider drag or animation, and no prompt-redraw flash

## Summary

Port docs/reference/terminal-resize.md. The debounce (src/termio/Thread.zig Coalesce, 100ms settle / 350ms cap) and Termio.resizePace are shared core; the GTK work is to make every GTK resize source (GtkPaned drag, window resize, banner collapse, stacked-pane glides) go through them rather than resizing the surface on every frame, and to honour the renderer prompt-redraw hold. Acceptance: a CLI-driven test in test/linux/ that counts SIGWINCH reaching a child during a scripted resize and checks it is one, not one per frame.

## In plain terms

When you drag the line between two panes on Linux, the program running in the
pane (Claude Code, an editor) should be told about the new size a few times,
not on every frame of the drag - each "your size changed" makes it repaint the
whole screen. This checks that Linux behaves that way, and that folding a
banner tells the program exactly once.

## Goals

- [x] Confirm every GTK resize source goes through the shared debounce (it does: `glareaResize` -> `Surface.sizeCallback` -> the IO thread's `Coalesce`; nothing on GTK resizes the PTY directly)
- [x] A Linux acceptance that counts SIGWINCH during a scripted divider drag and a banner fold, with a negative control
- [ ] The prompt-redraw hold seen on GTK frames, and a window-resize source in the test -> T3630

## Validation criteria

- [x] A 30-frame divider drag reaches the program paced - `test/linux/resize-pacing.sh` R3-R6 in WSL: the pane was laid out at 31 distinct widths (593 -> 833 px) over 848ms and the counter saw 3 SIGWINCH (cap 4, at most one per 3 frames).
- [x] A banner fold and an unfold are one SIGWINCH each, with the rows given back and restored (R7/R8: 17 -> 22 -> 17 rows).
- [x] The core paced them as a running program's (R9: `resize pace=debounce` on the app log).
- [x] The oracle can fail: `NEGATIVE=1` (8 steps 250ms apart) FAILS R6 alone - 8 SIGWINCH for 8 frames - `RESIZE PACING: 1 FAILURE(S)`.
- [ ] No prompt-redraw flash on GTK: not measured here; filed as T3630 (needs shell integration + frame capture across a resize at a prompt).
