# T3335 - Linux L6: GTK IPC server on a 0600 Unix socket at the same endpoint derivation as the Mac

## Summary

The client already resolves a Unix socket on non-Windows (apprt.ipc.socketPath). Add the server side to the GTK app: one derivation shared with the client so they cannot drift, mode 0600, $XDG_RUNTIME_DIR preferred, debug vs release names distinct, $GHOZTTY_IPC_SOCKET per pane honored. Acceptance: ghoztty +list from inside the debug app's pane answers from that app and never from an installed one.

## In plain terms

The `ghoztty` command line drives a running app by talking to it over a
private local socket. The Linux app never opened that socket, so every
command from a Linux shell said "no running instance". Now the Linux app
opens it - only its own user can connect - and every terminal pane it opens
remembers which app it belongs to, so a command typed inside a pane always
drives that app and never some other copy of Ghoztty. `+list` and
`+version` answer today; the other commands say plainly that they are not
on Linux yet (T3336) instead of failing silently.

## Goals

- [x] One socket derivation for the server and every client: `ipc_client.endpointPath` (`$XDG_RUNTIME_DIR` first on Linux, `$TMPDIR` on the Mac, one `/` always)
- [x] GTK app serves it at mode 0600, debug and release names distinct, a live socket never stolen, a stale one replaced
- [x] Each pane baked with `$GHOZTTY_IPC_SOCKET` (this app's) and a UUID `$GHOZTTY_PANE_ID`; an inherited value is dropped
- [x] `+list` (windows, tabs, split tree, pane id/title/cwd/pid/tty, build) and `+version` served; `--tty` works
- [x] Every other verb answers "not served by the Linux app yet (T3336)"
