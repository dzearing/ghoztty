# T3132 - Ctrl+Shift+Up/Down (Mac Cmd-Shift-Up/Down, 997b26535/675ad0b8d) walks windows in the pane sidebar's all-windows order, wrapping, and goto_window previous/next follows that order; hero mode still takes the chord for its panes; a viewer pane must not take the chord from a focused terminal

## Summary

Mac 997b26535 rebinds super+shift+up/down from jump_to_prompt to goto_window previous/next and makes goto_window walk the sidebar's all-windows list order (pane_sidebar_window_order + outline order on Windows), wrapping. Windows binds ctrl+shift+up/down to jump_to_prompt (Config.zig ~7102, the non-Darwin block) and App.zig ~9637 goto_window walks tabs/windows in its own order. Decide the Windows chord by the experience test (go.md 5b): the Mac chord is the platform's prompt-jump chord too, so the faithful translation is ctrl+shift+up/down -> goto_window; record the call. Also port the viewer fix: Mac viewers were offered every key equivalent in the window and swallowed the chord; check viewer_accel routing so a WebView2 viewer only handles it when focused, and swallows it in hero mode. docs/reference/window-modes.md documents the order.
