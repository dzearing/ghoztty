# T760 - A non-persistent terminal split inherits the app-global focused surface rather than the pane it was split off

## Summary

Found while fixing T538. `+split --pane=X` (or a keybind split) in a window
running **plain ConPTY panes** — `session-persistence = off`, and every pane in
a build or config where the agent is not in play — passes no working directory
of its own, so the new pane's cwd comes from the core's `newConfig` +
`Surface.init`'s T185 live-pwd override, both of which read
**`app.core_app.focusedSurface()`**: an app-GLOBAL value. Split a pane in a
window that does not currently hold focus and the new terminal opens in the
FOCUSED window's directory instead of next to the pane it was split off.

The default (persistence on) path does not have this hole: `newSplitAt` →
`buildRemoteInherit(at.surface())` queries the split PARENT's live cwd and
sends it with the agent OPEN. So the two backends disagree about what a split
inherits, which is the real defect — the parent pane is the right answer for
both.

Evidence trail: `test/win32/viewer-panes.ps1` section 11's fallback assertion
failed for a whole month because the window it splits in is not the one that
holds focus (T538); the same mechanism is what a terminal-parent split rides
when there is no agent.

## In plain terms

With session persistence turned off, splitting a terminal in a window you are
not currently clicked into opens the new pane in some other window's folder
instead of the one right next to it.

## Where

- `src/apprt/win32/Window.zig` `newSplitAt` (the `else` leg where no baton and
  no `buildRemoteInherit` applies), and `viewerSplitFallbackCwd`, which already
  does the live-pwd read for the viewer case
- `src/apprt/win32/Surface.zig` ~600-620 (`newConfig` + the T185 override)
- `src/apprt/surface.zig` `newConfig` (the app-global read; shared core, so the
  fix belongs on the win32 side rather than in it)
