# T765 - A config reload repaints the whole client area and nobody knows what asks for it

## Summary

T252 measured that a config reload invalidates the split-divider bands even with every divider repaint compiled out, so a pixel assertion taken after a reload can pass on a build whose subject was deleted. Ruled out by measurement: the DWM chrome calls (applyChromeTheme/applyBackgroundBlur), updateDimOverlays, DarkMode.apply, and a relayout (layoutSplits does not run - its GetDC pass would have painted the new color and did not). Find the real invalidator, decide whether the repaint is wanted, and check whether any other acceptance assertion after a config reload is leaning on it.

## In plain terms

Nothing a user can see changes here. When you reload the terminal's settings,
somebody had written down that the whole window gets redrawn for reasons nobody
could name — and an unexplained redraw is either wasted work or a bug waiting to
be found. Measured: it does not happen. The redraw belongs to our own test
tooling, which secretly repaints a window every time it photographs one. That
matters well beyond this one case: it means a whole family of our tests have
been proving less than they claim, and this writes down which ones and what to
do instead.
