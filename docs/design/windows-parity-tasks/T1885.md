# T1885 - Viewer panes stay opaque in the glass style: Mac's markdown/diff viewer pages go transparent (pane-glass class) so the tinted sheet is the page background

## Summary

Follow-up of T1833 (main 8174d96fc: viewer.css html.pane-glass, ViewerView toggles the class; websites and HTML pages keep their own background). The shared CSS is already on this branch; the Windows viewer (WebView2 child of ViewerPane) never sets the class and its host paints an opaque background. Needs the WebView2 DefaultBackgroundColor made transparent for template pages and the viewer host to paint the glass mix of its desk slice behind it (a viewer HWND, like a terminal, cannot see the parent desk). Validate with a markdown viewer in a glass window: page background varies with the desk; a website keeps its own.

## In plain terms

With glass panes on (the default), a terminal pane shows the window's colour
gradient faintly through its background, but a markdown, code, diff or image
viewer pane sat on a solid dark or white page. Now those viewer pages are
see-through too, so a viewer beside a terminal reads as the same sheet of
glass. Websites and opened `.html` files keep their own background, as on Mac.

## Goals

- [x] the window hands each viewer pane its slice of the desk, as it does a terminal
- [x] the viewer host paints the glass sheet over that slice, under the web view too
- [x] the web view paints nothing under our own pages on glass, and the template drops its background (`pane-glass`)
- [x] a website or `.html` page keeps its own background
- [x] the page's light/dark follows the sheet it sits on, not the OS, so ink stays readable

## Validation criteria

- [x] On glass a markdown page's class and computed backgrounds are `true|rgba(0, 0, 0, 0)|rgba(0, 0, 0, 0)|rgba(0, 0, 0, 0)` - live WebView2 host-floor test (win32 lane), same oracle as Mac's PaneSidebarWindowTests
- [x] The web view's DefaultBackgroundColor reads back alpha 0 on glass and 255 off it - same test
- [x] The host paints exactly `glassSheetRegion` of its slice (corners and centre compared), and the sheet varies across the pane - same test, painting into a DIB
- [x] The browser's `Chrome_WidgetWin_0` child is never cut out of the under-page paint; our own `Ghoztty*` children are - same test
- [x] Off glass the class goes, the page is opaque again and the OS scheme is back - same test
- [x] Websites/html keep their own background; the scheme follows the sheet on glass - viewer_glass.zig unit tests (none lane)
- [ ] NOT RUN: the sheet actually composites through a real on-screen window. Off-desktop surfaces cannot be read back (measured: a hidden parent's paint+read through one DC returns black), and on-screen runs are off while the user is present - follow-up T1915 (nav bar material: T1916)
