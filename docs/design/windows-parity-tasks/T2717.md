# T2717 - An idle loop turn waits for background due sweeps that are no longer running, until the 180m backstop (about 1.5-2h lost per stall)

## Summary

Twice in 4 hours a loop lane sat idle for ~1.5-2h inside one turn, held only by the watchdog's 180m backstop. Lane b, T2704, turn 27: idle from before 21:55 until after 22:12 on 2026-11-04. Lane a, T2705, turn 33: idle from about 00:30 until after 02:12 on 2026-11-05.

The two cases look the same:
- The pane shows 4-6 "still running in background" lines for overlapping duplicate due sweeps (several named "Run all due harnesses without fail-fast"), then "Compacted while idle".
- The watchdog logs session=idle bg=1/2, so T1711's background-wait arm keeps it healthy.
- In lane a's case at 02:12, NO harness process existed. Lane a's claude (pid 25104) process tree held only Claude Code's long-lived PowerShell tool hosts: no acceptance-parallel, no guard-due, no test/win32 runner.

So the tasks the transcript counts as pending were not running. Either they had already exited without a notification reaching the idle session, or the count includes tasks the session already consumed. A turn that relaunches the same sweep several times adds to the count and to the box load.

Fix direction:
1. Get-LoopPendingBackgroundTasks (scripts/loop-session.ps1) should confirm a pending task still has a live process (or an output file still growing) before it lets T1711 waive the stall. Otherwise a dead wait counts until the 180m backstop.
2. go.md should tell the loop to run ONE due sweep and wait for it, never to relaunch a sweep that is still running.
