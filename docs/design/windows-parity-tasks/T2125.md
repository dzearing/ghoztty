# T2125 - Stacked panes: every resize handle answers only in the gaps between panes, strips get gaps too, and the flat style gets a 6pt gutter

## Summary

Split from T2084 (Mac 2811a3043 gutter-only resizers). Restrict split_resize.zig hit-testing (dividers, stack grips, run-edge grip, sidebar edge) to gutter rects only, give strips gutters, and change Window.stackGapDip's flat-style value from 2 DIP to 6 (T2108 note). Validation: a none-lane test enumerating points inside cards (no hit) and inside gutters (hit), plus an acceptance that the cursor/hit answer matches.

## In plain terms

Grabbing the line between two panes used to work from a few pixels inside
either pane, so a click near a pane's edge could start a resize instead of
landing in the terminal. Now every resize handle - the line between panes,
the handle between stacked cards, the side panel's edge - only answers in
the gap between things. The gap in the default (flat) look is a little wider
(6 DIP, as on Mac) so there is something to grab, with the same thin line
down its middle.

## Goals

- [x] Dividers and stack grips take the mouse in their gutter and nowhere else; panes no longer fall through for them
- [x] The flat gutter is 6 DIP with the 2 DIP line centred in it; strips and cards get the same gutter
- [x] The pane sidebar's rail/card edge grip lies inside the card, never over a pane
- [x] Divider drags and resize keys still hold every other boundary on its pixel with the wider gutter
