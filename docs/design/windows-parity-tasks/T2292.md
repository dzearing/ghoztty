# T2292 - git-commit-guard leaves a half-finished rebase when its push-reject pull --rebase hits a transient index.lock: the commit is made, the guard exits 6 with 'Another git process seems to be running', the message file is deleted, and the tree sits mid-rebase with a stale CHERRY_PICK_HEAD

## Summary

Seen 2026-10-25 22:12 on lane b while lane A was committing: the next guard call then failed with 'cannot do a partial commit during a cherry-pick' and rebase --continue could not find rebase-merge/message. The guard should retry the pull on an index.lock, and on any failure mid-rebase either finish or abort it and say which, never exit with the repo mid-rebase. Recovered by hand: git commit -F + rebase --continue + push.
