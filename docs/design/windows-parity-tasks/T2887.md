# T2887 - gate-negatives section F writes its fake publish request (REQUESTED: T1: the installer dies silently / REQUEST FAILED ...not-a-dir) into the REAL %TEMP%\ghoztty-daily-publish.log - 110 such lines since 2026-10-11

## Summary

Found writing the 2026-11-10 digest. `%TEMP%\ghoztty-daily-publish.log` is the
live publish log the digest and `go-loop-health.ps1` read, and it carries 110
lines like:

    2026-11-10 01:41:43 REQUESTED: T1: the installer dies silently - the next task-boundary publish ships it ...
    2026-11-10 01:41:45 REQUEST FAILED: could not write C:\Users\David\AppData\Local\Temp\ghoztty-gate-negatives-c8ad4883\not-a-dir\req ...

The first dates from 2026-10-11. They come from `test\win32\gate-negatives.ps1`
section F (the UNSHIPPED USER REPORT demonstration, T1315), which points the
request PATH at a sandbox but leaves the LOG path at its default. No real request
file was written (`daily-publish.ps1 -Check` reads NOT DUE), so nothing shipped
by mistake. But a reader of the live log sees a request for a "T1" that never
existed, plus a write failure, interleaved with real publishes. Same shape as
T1713 (go-loop-exec resume writing into the real watchdog log).

Fix: give `daily-publish.ps1`'s request path a log override (or derive the log
from the sandboxed state dir), and have section F pass it. Then add an assertion
to section F that the live log's length is unchanged across the section.

## Validation criteria

- [ ] `gate-negatives.ps1` section F leaves `%TEMP%\ghoztty-daily-publish.log` byte-identical (asserted in the section itself)
- [ ] section F still demonstrates the UNSHIPPED USER REPORT gate red and green
