# T3616 - Linux L11b4: dragging a pane into ANOTHER window splits, swaps or inserts there, the cross-window half of the one drop resolver

## Summary

Follow-up of T3564. Each window's split tree already has a GtkDropTargetAsync for the private pane mime type, and the compositor delivers the drop to the window under the pointer, so a drop in another window reaches that window's SplitTree.dropPaneAt. Teach it a dragged pane that lives in a different tree: SplitTree.moveTo / swapWith / insertAtTopLevel / insertInGap across the two trees, install both, and keep the moved pane's agent session alive (Mac finishRelocation).

**Corrected while building (2026-11-24):** the filing said to *refuse* a move
that would empty the source window, after `docs/reference/pane-rearrange.md`.
The Mac code says otherwise and wins: `PaneMoveCoordinator.allows` has let a
window's last pane join an EXISTING window since fd7385c42 ("pop a pane out,
change your mind, drag it back"), and the emptied window closes. That is what
landed; the stale doc is T3707.

## In plain terms

On Linux a pane could be dragged around inside its own window but not into
another one: dropping it on a different window did nothing. Now a pane
dragged onto another window's pane splits beside it or swaps places with it,
and dropped on that window's tab bar it becomes a tab there. Its shell keeps
running throughout, the window it lands in comes forward in rearrange mode if
you were rearranging, and a window you drag the last pane out of simply
closes, because everything in it moved.

## Goals

- [x] a drop on another window's pane finds the dragged pane app-wide and splits, swaps, spans an edge or fills a gap there
- [x] a drop on another window's tab bar makes a new tab there at that index
- [x] a window's last pane may join another window; its tab closes, and its window with no tab left, with no confirmation
- [x] the moved panes keep their shells, pids and sessions; a Disconnect pin does not follow them
- [x] the mode follows the pane: a drag made in rearrange mode leaves the window it lands in rearrangeable, and that window comes forward
- [x] the tab dwell works on another window's bar, so a drop can land in any of its tabs
