# T2172 - profile-latency.ps1 auto-launches a startup window beside its prof window

## In plain terms

The latency profile starts a fresh terminal and opens its test window, but the
terminal also opens its own default window first. That extra, idle window's
frame-rate samples get mixed into the profile's numbers, and the script may
even pick the wrong window to type into.

## Summary

Same shape T1214 fixed in `test\win32\soak.ps1` (2026-10-22): `+new-window
--target=prof` with no instance running auto-launches the app, which opens its
own STARTUP window (auto-named `window-1`) before taking the `+new-window`. A
3-minute soak on 2026-10-22 showed it directly: `startup roster: closing what
the auto-launch opened beside the soak window: window-1 (1 pane)`.

In `test\win32\profile-latency.ps1` two things follow:

- the `perf ... fps=` parse (`Read-PerfSlice`, around line 260) pools every
  pane, so the startup window's idle pane drags the idle/storm fps medians
  toward 1;
- `[ProfDrv]::FindTop([uint32]$proc.Id)` finds A top-level window of the
  process, which with two windows may be the startup one rather than `prof`,
  so the injected keys and the focus go to a pane nobody measures.

Fix: close the startup window right after the launch, read the roster back to
prove it is gone, and assert the instance holds only `prof` - the soak's
`Get-StrayWindows` / `Format-StrayWindows` / `Get-WindowLeaves` are the
helpers; lift them into `test\win32\lib\` (both callers) rather than copying.

Not run on the loop box: the script asserts the `real-input` + `foreground`
capabilities (`-Interactive`), so it is a run the user has to be present for.

## Where

- `test/win32/profile-latency.ps1` - the `+new-window --target=prof` launch, `FindTop`, the perf parse
- `test/win32/soak.ps1` - the helpers to lift into a lib

## Validation criteria

- [ ] profile-latency's report names the startup window it closed and asserts the instance holds only `prof`
- [ ] the perf parse counts only the `prof` pane's samples
- [ ] soak.ps1 -SelfTest still green after the helpers move to a lib
