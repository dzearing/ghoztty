# T2303 - Dragging a Windows pane sidebar row up or down does not reorder the list: add the sidebar_order drop target (two lists split at the stash boundary), apply it (grid pane: list only; stashed: restore at that place; other window: join there), and make a row drag a list drag clamped to its own sidebar - T2275 part 2

## Summary

Mac e77422577 PaneDropTarget.sidebarOrder + PaneMoveCoordinator; 0a547522d PaneDragSession.isListDrag/listTarget: the pointer is clamped to the source sidebar (x = mid, y inside) before resolving, so a release over the grid or past the window lands the row level with the pointer and never moves the pane out. Index = rows of that list, dragged one aside, whose middle is above the pointer, measured as laid out (not as slid). Windows today: anywhere on the sidebar means stash (pane_drop.zig resolve/resolveBlade, tests 'anywhere on the sidebar means stash').

## In plain terms

Dragging a pane's row up or down the Windows pane sidebar did nothing useful:
anywhere on the sidebar meant "stash it", so a row could not be put in a new
place in the list, and a row dragged out over the grid could move the pane
somewhere else entirely. Now the sidebar is two lists, like on Mac: drop a row
among the panes and it takes that place in the list (the grid stays as it is);
drop it below the hairline and it is stashed; drag a stashed row up into the
list and it comes back to the screen at that place. A row drag stays in its
own sidebar wherever the mouse goes.

## Goals

- [x] the drop resolver knows the sidebar's two lists (the new list-place target, split at the tray's hairline)
- [x] a list drop applies: grid pane = list only; stashed pane = restore then place; another tab/window's pane = join, then place
- [x] a row's drag is a LIST drag, held to its own sidebar (release over the grid or another window lands it level with the pointer)
- [x] the list place is previewed as a caret on the sidebar

## Validation criteria

- [x] Resolver: above the tray a drop places in the list at the right index, below it stashes, a stashed pane dragged above comes back into the list, a strip on the list joins it, and a list drag is held to its own sidebar (Mac PaneDropResolverSidebarTests ported, y flipped) - `zig test src/apprt/win32/pane_drop.zig` 63/63, plus `drop_highlight.zig` 91/91 for the caret
