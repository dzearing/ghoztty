# T2004 - A harness that stops its own app with Stop-RepoGhoztty gets a CRASHED 0xFFFFFFFF postmortem for it: the kill never marks the test desktop's launch record

## Summary

Seen in agent-job-report.ps1 (T1975): Stop-RepoGhoztty kills test-desktop launches without setting their launch record's Killed flag, so Remove-TestDesktop's Write-TestDesktopPostmortems reports each deliberate kill as 'CRASHED - 0xFFFFFFFF' and dumps the app's whole stderr (~500 KB of log) into the run output, green or red. agent-job-report works around it by marking live launches Killed before its own Stop-RepoGhoztty call. Fix it once: Stop-RepoGhoztty (lib\CleanSlate.ps1) should mark any record in GhozttyTestDesktopLaunches whose pid it kills. A record already dead before the kill must stay unmarked so a real crash still reports. Then drop the per-script workaround.
