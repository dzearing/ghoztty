# T3777 - The Windows close-memory harness cannot see the session agent's live heap, so it cannot tell an agent leak from allocator overhead

## Summary

T3646 added src/remote/agent/heap_stats.zig: a Debug agent counts the bytes its DebugAllocator has handed out and logs 'heap: session created|freed: live_bytes=N ...' (scope heap, debug level) per session; test/linux/pane-close-memory.sh M6 asserts it per closed pane <= 1 KB. On Windows agent_log.logFn keeps debug lines off agent.log and the detached agent has no stderr, so test/win32/pane-close-memory.ps1 cannot read it. Route the heap line where the Windows harness can read it (e.g. agent.log at info level in Debug builds only) and add the same live-heap check to pane-close-memory.ps1.
