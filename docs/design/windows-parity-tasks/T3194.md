# T3194 - Single-window mode: every path that opens a window opens a workspace (Ctrl+Shift+N, menus, sidebar +, +new-window, drag-out, undo close) with Mac focus policy, and the adopt turn carets the focused pane before first layout

## Summary

Child of T3181 (split 2026-11-16; P0 by user directive via T3136). Spec docs/reference/window-modes.md; decisions come from src/apprt/win32/workspace_host.zig. Acceptance: a section of test/win32/single-window-mode.ps1.

## In plain terms

With "All in one window" chosen, every way of opening a new window - the New Window key, the New Window button, a pane dragged or popped out of its window, a script - should open it inside the one window, and when you switch to it the cursor should already be in the pane you were last using there. Opening already went to the one window; the cursor now lands in the right pane before anything is drawn, so a switch never briefly shows the wrong pane.

## Goals

- [x] Audit every open path: each reaches `App.presentWorkspace` (createWindow's tail, the pop-out's commit) with the Mac focus policy (manual / --focus on show, programmatic parked)
- [x] The adopt turn puts the caret on the workspace's focused pane (`caretPaneOnShow`, never a folded strip) before its first layout
- [x] Acceptance section G in `test/win32/single-window-mode.ps1`
- [x] Undo of a workspace close: owned by T3200 (already filed); blade replay on a switch: T3204
