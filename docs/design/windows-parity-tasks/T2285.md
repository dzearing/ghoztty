# T2285 - Double-clicking a Windows split divider resets only that one split to 50/50; Mac now evens out every pane in that divider's direction and leaves the other direction alone (Mac 6362115c8)

## In plain terms

Double-clicking the line between two panes is meant to even the panes out.
On Windows it only split the two panes either side of that line, so three
panes side by side came out half, quarter, quarter. Now, as on a Mac, every
pane in that line's direction gets the same size, and sizes running the other
way stay as you set them.

## Goals

- [x] A double-click on any divider evens every pane across dividers running its way
- [x] The other direction's sizes are left alone
- [x] Hidden (stashed) panes keep their slots, the same way Equalize Splits treats them

## Summary

Mac 6362115c8: double-clicking a divider used to run equalize_splits, resetting every split ratio both ways (a pane made narrow came back wide when a horizontal divider was double-clicked). Now it evens out panes only in the divider's direction (SplitTree change + tests). Windows Window.zig WM_LBUTTONDBLCLK sets that one split to 0.5 (resizeInPlace(hit.handle, 0.5)), which for three panes in a row gives 50/25/25, not thirds. Match Mac: equalize every split of the divider's orientation so panes in that direction come out equal, leaving the other orientation's ratios untouched; unit-test the tree op in the none lane.

## Validation criteria

- [x] Tree op: `SplitTree.equalizeOnly` evens only the given layout and keeps the other (Mac's `equalizedInOneDirectionKeepsTheOther` case: A | (B / C) at 0.2/0.8), and gives A | B | C thirds - none-lane unit tests, green; a planted wrong expectation went red (negative control).
- [x] On the box: three panes made uneven by a drag (624/684/948 px) come out 752/752/752 after a double-click on the second divider, and again after a double-click on the first - `test\win32\split-divider.ps1` T2285 asserts, ALL PASS (97). The old 0.5-only code would read 624/816/816.
- [x] Floor lanes and due harnesses green (see progress log).
