# T3844 - suite-run.ps1 still starts @input-desktop-exception scripts (serial AND -Jobs): T3839 gated only the acceptance-parallel.ps1 CLI

## Summary

T3839 (9c40f6f651) made scripts\acceptance-parallel.ps1 drop every script on test\win32\lib\TestDesktop.ps1's @input-desktop-exception list before anything starts (NOT RUN, not red), through scripts\lib\InputDesktopExceptions.ps1. The gate sits in the CLI, not in scripts\lib\AcceptanceParallel.ps1's Invoke-AcceptanceRun, so scripts\suite-run.ps1 - its -Jobs path (which calls Invoke-AcceptanceRun directly) and its serial loop (Get-SuiteRows, around line 270) - never consults the list: a whole-suite run still launches translucent-window.ps1, frame-lab.ps1, background-blur.ps1 and the rest on the input desktop. Fix: have Get-SuiteRows use Get-InputDesktopExceptions / Get-InputDesktopExceptionFor and score those rows skip with the same NOT RUN line unless an explicit user opt-in is passed; add a section to test\win32\suite-run.ps1 with a planted fixture named after a listed script (both paths) and a positive control. (A version gating Invoke-AcceptanceRun itself was written in T3843 and dropped as a duplicate; it is on local branch T3843-backup.)

## In plain terms

A few test scripts only work by taking over the real screen. The loop is never
supposed to start those while someone is using the machine. Yesterday's fix
taught the routine test sweep to skip them, but the "run the whole suite" tool
had its own way of starting scripts and still launched them. Now it skips them
too, says by name why, and does not count them as failures. A person who
wants to run them anyway, while nobody is at the box, has to ask for that
explicitly.

## Goals

- [x] a whole-suite run (serial) never starts a script on the TestDesktop.ps1 exception list

- [x] such a script is reported `skip` with "NOT RUN (input-desktop-exception)" and its declared reason, never red
- [x] a '-Live only' entry (divider-flicker.ps1) still runs its default, synthetic run
