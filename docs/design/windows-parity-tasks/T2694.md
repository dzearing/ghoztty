# T2694 - Ctrl+V with a screenshot on the clipboard does not attach it in Claude Code on Windows (Claude binds image paste to Alt+V there); make Ctrl+V attach images out of the box

## In plain terms

On Windows, taking a screenshot and pressing Ctrl+V in Claude Code did
nothing. Claude Code only attaches an image there with Alt+V, while on a Mac
it is Ctrl+V. Once this lands, setting up Ghoztty's Claude integration (the
first-run offer, Set Up Agent Integrations..., or `ghoztty +agent-setup
--install=claude`) also teaches Claude Code that Ctrl+V attaches the image, so
it works the way Mac users expect. If you already bound Ctrl+V to something
yourself, Ghoztty leaves your binding alone.

## Goals

- [x] Installing the Claude integration binds Chat `ctrl+v` to `chat:imagePaste` in `~/.claude/keybindings.json`
- [x] A Ctrl+V binding the user already has (any action, or an explicit unbind) is never overwritten or removed
- [x] Uninstall removes only the binding Ghoztty added
- [x] An integration installed before this reads "Update available", and Update adds the binding
- [x] Ghoztty does NOT rewrite Ctrl+V for other programs in a pane
- [x] The image + text clipboard case is filed separately (T2721)

## Summary

**Cause.** Claude Code binds `chat:imagePaste` to `ctrl+v` on macOS and to
`alt+v` on Windows. Ghoztty already passes ^V through to the pane when the
clipboard holds no text (T154), so with a screenshot on the clipboard the key
reached Claude and Claude had nothing bound to it.

**Fix.** There is a new Claude-only integration component,
`src/apprt/win32/ClaudeKeybinding.zig`, wired into `RuntimeIntegration.make`
between skills and hooks (hooks stay last for the banner refcount). It merges
`{"context":"Chat","bindings":{"ctrl+v":"chat:imagePaste"}}` into the user's
`~/.claude/keybindings.json`, into the existing Chat block when there is one.
The file belongs to the user, the same way `settings.json` does:
- Any Chat `ctrl+v` entry that is already there (including `null`) counts as
  installed and is never touched.
- The binding Ghoztty adds is recorded in a sidecar,
  `keybindings.json.ghoztty-owned`. Uninstall removes the binding only when
  that sidecar exists and the binding still says `chat:imagePaste`.
- A keybindings file that is not mergeable JSON is left alone and counts as
  installed. Refusing would fail the whole Claude install over a file Claude
  itself reports.

In `RuntimeIntegration.state`, a missing keybinding on its own reads as
`outdated`, not `not_installed`. Integrations already in the field therefore
show "Update available" and do not look unset-up, which would also have
re-armed the first-run offer through `decideOffer`. Like skills and hooks,
the binding is gated on the old external plugin.

**Mac half.** No Mac change is owed. Claude Code on macOS already binds Ctrl+V
to image paste, so the Mac user already has this experience, and this change
brings Windows in line with it.

**Not done here.** When the clipboard holds an image AND text (some browsers'
Copy Image), Ghoztty's own paste wins and the text goes in instead. That is
filed as T2721.
