# T2990 - PA-W06: the Activity Monitor creates a new OS thread every 1.5 s sample, and on the NVIDIA driver each one strands ~64 KB (activity_sample.zig:151)

## Summary

PA-W06 (audit-1, T2960). activity_sample.zig:151 does std.Thread.spawn(.{}, sampleWorker, ...) per sample (joined at :145), driven at trend_gauge.zig:30 sample_interval_ms = 1500 while the panel is open and observable. worker_pool.zig:3-5 (T2644) records that every thread created while a GL context is alive costs ~64 KB the NVIDIA driver never returns: 2400 threads/hour ~ 150 MB/hour with the panel open (estimated), plus a transient 16 MB commit per spawn (PA-W01). Fix: run the sampler on worker_pool.spawn or a single long-lived worker parked on an event. Risk low.

## Validation criteria

- [ ] the sampler no longer creates a thread per sample (thread count flat across 60 s with the panel open)
- [ ] Activity Monitor acceptance stays green
