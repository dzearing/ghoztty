# T1749 - The agent pushes a roster change only to the connection that made it, so a remote chooser never hears about sessions other clients start or end

## Summary

server.zig markRosterDirty flags only SELF (the per-connection Server). A session created, closed, relaunched or exited over connection B never pushes to a sessions_sub on connection A. Locally invisible (every local pane shares the one warm connection); remotely the chooser's pooled connection never sees a +new-remote-window session until a refetch. Found by T1636's H section (a session started after the swap was not pushed; it did appear on the next selection). Shared agent code: affects Mac's SessionBrowserProbe push too. Fix: a store-level roster generation/notify that every subscribed Server's pump observes; acceptance = chooser-conn-pool.ps1 open a second remote window and assert a push.

## In plain terms

When you browse a remote machine in the machine chooser, its session list is
meant to update live. It only did so for changes made over the chooser's own
link: open a second remote window onto that machine and the list stayed one
session short until you clicked away and back. Now any change to a machine's
sessions - from any window, or a shell simply exiting - shows up in every open
list straight away, on Windows and Mac alike.

## Goals

- [x] a roster change reaches every subscribed connection, not just the one that made it
- [x] changes no connection made (an unattached shell exiting, the idle reaper, a window dropping) push too
- [x] a connection leaving can never be notified after it is freed

## Fix

`SessionStore` now owns an intrusive list of roster listeners
(`addRosterListener` / `removeRosterListener` / `notifyRosterChanged`, own
mutex; lock order `store.mutex` -> listeners -> each Server's `roster_mutex`).
A `Server` links its `roster_listener` on `SESSIONS_SUB`, unlinks it on
`SESSIONS_UNSUB` and first thing in `stopRosterPump`, and `destroy` asserts it
is unlinked. `markRosterDirty` broadcasts through the store. The store itself
now notifies on an exit in `onChildOutput` (bound or not), `reapIdle`,
`reapUnboundTombstone` and the vanished-child sweep; `detachAll` notifies when a
dropping connection had sessions bound (attached -> detached). Wire protocol
unchanged - same frame, sent more often - so no capability bump.
