# T2650 - Every WGC live harness scores frames taken on an occluded display: share divider-flicker's 0xC01E0006 app-log gate (T2645) and re-read T2620's all-black strip face and T2631's solid-black glass pane against it

## Summary

T2645 (2026-11-02) showed that a WGC capture taken while the display is occluded (asleep, locked) photographs terminals that never presented as solid black, and divider-flicker read that as a P0 regression in every cell. The app says so in its own log: FrameClock writes `compositor clock wait failed (c01e0006)` once at startup. divider-flicker now SKIPS such a cell by name (`Get-DividerFlickerOccluded` in `test\win32\lib\DividerFlickerScore.ps1`, section E of `test\win32\divider-flicker.ps1`).

Other live WGC harnesses have no such gate, and two open reds carry the same signature: T2620 (stack-fold-slide F13, the strip face reads all-black 000000) and T2631 (pane-elevation glass arm, a glass pane photographs solid black). Do: move the gate into a shared lib (FrameCapture or UserPresence, with its guard-due LIB COVERAGE row), call it from every harness that captures the real app's pixels, and re-read the T2620/T2631 run logs for the line - close either as box state if its red runs were all occluded.

## In plain terms

Several screen-recording tests can mistake a sleeping monitor for a broken app, because a sleeping screen photographs as black. One test now knows to set those runs aside; the others still need it, and two open bugs that report black pictures should be rechecked in case they were only a sleeping screen.

## Goals

- [x] one shared reader of the app's "display occluded" log line, in its own test lib
- [x] every harness that films or grabs the real app's composed pixels calls it
- [x] T2620 and T2631 rechecked against it

## What landed

- **`test\win32\lib\OccludedDisplay.ps1`** (new; its own lib rather than FrameCapture or UserPresence: several callers load neither, and UserPresence's Add-Type is a cost the probes do not need). `Get-OccludedDisplayLine` (the moved reader), `Get-OccludedDisplaySkip -What` (the one SKIP sentence every per-cell caller prints), `Exit-IfOccludedDisplay -Root` (whole-run `SKIP ALL`, exit 0, for probes that score arms against each other), `Test-OccludedDisplaySource` (FrameClock still logs the matched prefix). `Get-DividerFlickerOccluded` is gone from DividerFlickerScore.ps1.
- **Callers, 15 in all.** Per cell/drag: divider-flicker -Live, divider-ghost -Live, resize-sync-onscreen (all three moved over), chainfold -Live (new: reads the recorder's `app.log`), frame-lab live (new: the live driver now keeps each cell's stderr as `app.log` and offers an optional `Occluded` hook that `Invoke-FrameLabCell` turns into a `skipped` verdict). Whole run: bell-fade, comp-chrome, comp-desk, comp-flat, comp-glide-hold, comp-overlay, comp-present, comp-present-glide, divider-drag and hero-glide `*-onscreen` probes call `Exit-IfOccludedDisplay -Root $OutDir` before their verdict.
- **Found on the way: divider-flicker E3 was red on HEAD.** T2724 (today) reworded FrameClock's line to add the period and the retry, and E3 matched the old literal with its closing quote. Nothing made the guard due, because FrameClock.zig was not in its covers. E3 now checks the format string's fixed prefix, and the divider-flicker row covers `OccludedDisplay.ps1` and `FrameClock.zig`. The -live rows cover the new lib too (divider-ghost-live swaps DividerFlickerScore for it).
- **Out of scope on purpose:** PrintWindow / WM_PRINT photographs (stack-fold-slide, pane-elevation). They read the window's own paint rather than what DWM composed, so a sleeping display does not blacken them.
