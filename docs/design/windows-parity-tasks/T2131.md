# T2131 - Stacked panes: during the carousel slide, the cards going behind the run and their strips jump to their places instead of sliding with the rest

## Summary

PARTLY FIXED by T2186: a card going behind the run now slides to its tucked place (shown until the slide ends) on every slide, click or drag. What is LEFT: the strips. Every strip is still painted by the window at its final place from the first frame, so a strip of a card that stays tucked but moves along the edge (a run change shifting the stack's strips) jumps, and a departing card's strip is hidden under the sliding card only because the card covers it. On Mac a strip is part of its card and slides with it. Make paintStackStrips read a mid-slide rect for each strip (a strip of a card in the slide follows `stackSlideRect`; a strip whose tucked card moved but is not in the slide needs its own from/to). Acceptance: extend test\win32\pane-stack-slide.ps1 with a strip-position sample mid-slide (pixel probes are dead on the test desktop, so expose the strip rects - e.g. a debug IPC field - rather than reading pixels).

## In plain terms

When you click a folded-away pane in a stack of panes, the row slides along
like a carousel. The thin folded edges ("strips") of panes that stay folded
used to snap to their new spots on the first frame while everything else
slid. They now slide too. A later fix (T2417) made that change. This task adds
the test that proves it.

## Goals

- [x] Confirm whether the strip jump still happens (it does not: T2417's `StripGlide` covers it on every glide, run changes included)
- [x] Land the acceptance check the card asked for: a mid-slide strip sample in `pane-stack-slide.ps1`

## Validation criteria

- [x] A strip that stays a strip through a strip-click run change is drawn at 2+ rects mid-slide: `test\win32\pane-stack-slide.ps1` S7, via `acceptance-parallel.ps1 run`, ALL PASS (18 assertions; P's strip drawn at 16 rects).
- [x] The check can fail: `pane-stack-slide.ps1 -NegativeControl` (0 ms slide) gives S7 FAIL with 0 rects, alongside S1's FAIL.

## Resolution

ALREADY FIXED by T2417 (c5b6ee6da): `pane_stack_slide.plan` gives every strip
that stays a strip and whose rect changed a `StripGlide` (`moveStrip`), on
every glide, run changes included. `shownStrip` → `shownStripTab` /
`paintStackStrips` paint it at its eased rect. The departing card's strip
was already covered by the strip-face work (T2288/T2307/T2825). The original
click in pane-stack-slide.ps1 swaps the whole run ({P,s1} → {s2,s3}), so no
strip stays tucked there. S7 adds a second click (s1's strip, from s2|s3)
in which P stays tucked and its strip changes rect. It reads the T2417
`stack strip glide` log oracle instead of a debug IPC field: same evidence,
no new surface.
