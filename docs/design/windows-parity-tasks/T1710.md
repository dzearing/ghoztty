# T1710 - Re-point or retire viewer-feedback-utf16.ps1 (RichEdit UTF-16 caret arithmetic) now the composer is a web page

## Summary

viewer-feedback-utf16.ps1 is ABOUT the RichEdit's UTF-16 caret arithmetic (EM_GETSEL, surrogate pairs beside chips). The web surface reports its caret in UTF-16 code units through the page's snapshot (viewer_feedback_page.zig ImageSpan), so either re-point the arms at the page (type astral text, paste, Backspace, read the document and the host's buffer back) or retire the script and name the in-process test that covers the same arithmetic. Split out of T1703, which landed the pattern on viewer-feedback-alpha.ps1: arm ONE DevTools port per script with Enable-WebViewCdp before the first launch, open the composer, Find-CdpComposer (pass -Exclude for pages an earlier app used), then type with Send-CdpComposerText / Send-CdpKey, paste pictures with Send-CdpComposerImage, and read back with Get-/Wait-CdpComposerText (test\win32\lib\WebViewCdp.ps1). Chords NATIVE owns (Ctrl+Enter, Esc) still go through the band's window messages. Assert Wait-ComposerSurface 'web' instead of pinning 'richedit'. When done the script no longer calls Set-ComposerSurface 'richedit' or reads a RichEdit50W, which is what T1704 needs before it deletes the fallback.

## Validation criteria

- [ ] The script no longer asks for the RichEdit fallback and asserts the composer opened on the web surface
- [ ] Every editing arm drives the web page (or is retired with its replacement coverage named)
- [ ] The script runs ALL PASS on the box
