# T2637 - Shared GPU memory grows ~2 MB on some minimize/restore cycles of a 4-pane window, with or without the T2474 target release (hidden-window-memory.ps1 table)

## Summary

## In plain terms

Each time a Ghoztty window with several panes is minimized and brought back,
the graphics memory it holds sometimes grows by about 2 MB and never comes
back. One cycle is nothing; a day of minimizing a terminal adds up.

## Summary

Found by T2474's `test\win32\hidden-window-memory.ps1` (one window, four
default-layered terminal panes, 1400x900, debug build). Its table shows the
process's SHARED GPU usage stepping +2.0 MB on two of four minimize/restore
cycles (39.1 -> 45.1 MB) both on HEAD 7d0135e39 BEFORE the T2474 release
existed and after it, so it is not the release. Dedicated memory is flat
across cycles once T2474 lands. T2599 measured a +3.0 MB DEDICATED re-pay per
minimize/restore for PLAIN panes (`GHOZTTY_PANE_LAYER=0`); this is the default
layered path and the shared heap, so it may be the same redirection-surface
re-creation charged to a different heap, or a separate one. First step: run
the harness with `-Cycles 10` and a never-split window to see whether the step
is per-cycle, per-pane or bounded; then compare against T2599's
`test\zig-repro\t2599-wgl-multichild` repro.
