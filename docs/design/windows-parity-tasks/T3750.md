# T3750 - The shell list the pickers offer: Git Bash beside PowerShell 7, Windows PowerShell and cmd, and one 'WSL: <distro>' entry per installed distro (T3735)

## Summary

Child of T3735. One catalog function every picker reads: settings_controls.common_shells (found on PATH) plus Git Bash (found at its install path) plus one entry per wsl_distros.listInstalled distro, spec wsl:<name>, label 'WSL: <name>'. Settings > Shell lists the same entries; what a distro entry writes to the command key must actually launch that distro (check how Config parses a command with arguments on Windows before choosing the written form). Unit tests for the catalog; gui-launch-command H-style check that a distro pick reaches the next window (opt-in -Wsl arm).

## In plain terms

Settings > Shell used to offer PowerShell, cmd and one plain "WSL" entry that
opened whichever Linux distro was the default, in a slow Windows-drive folder.
Now it also offers Git Bash when it is installed, and one "WSL: Ubuntu"-style
entry for each Linux distro you have, each opening in that distro's home
folder. Picking any of them makes the next window, tab and split open that
shell. The per-pane pickers that come next (command palette, the + button)
read this same list.

## Goals

- [x] one list every picker reads: the found common shells, Git Bash, one `WSL: <distro>` per installed distro (`settings_controls.shellCatalog`, `SettingsWindow.installedShells`)
- [x] Settings > Shell lists it; the default-shell row writes a command line, the scripted row the `--shell` spelling (`wsl:<distro>`)
- [x] what a distro entry writes (`wsl.exe -d <distro> --cd ~`) launches that distro as `wsl.exe` itself, not under a hidden `cmd /c`
- [x] what the Git Bash entry writes (its quoted path) launches with session persistence on AND off
- [x] `wsl:<distro>` is refused on the default-shell row (that key takes a command line) and when the distro is not installed
