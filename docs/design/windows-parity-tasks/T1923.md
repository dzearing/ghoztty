# T1923 - A glass viewer pane re-evaluates the desk gradient for every one of its pixels on every paint, so a divider drag beside a viewer pays it each mouse move

## Summary

`ViewerPane.paintGlass` calls `pane_elevation.glassSheetRegion`, which runs
`Palette.at` (the full gradient math) for EVERY pixel of the viewer's client
area, at full resolution, on every WM_PAINT - and `Window.syncGlassBackdrops`
hands the viewer a new spec (so it invalidates) on every divider-drag move that
resizes it. T1907 measured the terminal's quarter-resolution slice at 4.7ms for a
1250x1350 pane in Debug; the viewer's full-resolution sheet is ~16x the texels.
Fix shape: give the viewer the same crop T1907 gave the terminal - read the
pixels out of the window's cached desk (`PaneDesk.backdrop`) and apply the
GlassLut mix - or cache the sheet per (rect, desk gen, tint) inside the viewer.
The spec is stored and painted later, so it cannot carry a borrowed pixel slice;
the viewer has to reach the window's desk at paint time or own a copy.
Measure with drag-perf extended to put a viewer pane in the grid (it has none).

## Validation criteria

- [ ] a divider drag beside a glass viewer no longer evaluates the gradient per pixel (timed before/after)
- [ ] the viewer's sheet still meets the desk round its card without a seam (unit test against the analytic sheet)
