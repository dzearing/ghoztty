# T1923 - A glass viewer pane re-evaluates the desk gradient for every one of its pixels on every paint, so a divider drag beside a viewer pays it each mouse move

## Summary

`ViewerPane.paintGlass` calls `pane_elevation.glassSheetRegion`, which runs
`Palette.at` (the full gradient math) for EVERY pixel of the viewer's client
area, at full resolution, on every WM_PAINT - and `Window.syncGlassBackdrops`
hands the viewer a new spec (so it invalidates) on every divider-drag move that
resizes it. T1907 measured the terminal's quarter-resolution slice at 4.7ms for a
1250x1350 pane in Debug; the viewer's full-resolution sheet is ~16x the texels.
Fix shape: give the viewer the same crop T1907 gave the terminal - read the
pixels out of the window's cached desk (`PaneDesk.backdrop`) and apply the
GlassLut mix - or cache the sheet per (rect, desk gen, tint) inside the viewer.
The spec is stored and painted later, so it cannot carry a borrowed pixel slice;
the viewer has to reach the window's desk at paint time or own a copy.
Measure with drag-perf extended to put a viewer pane in the grid (it has none).

## In plain terms

With the glass look on, a document or web viewer pane redrew its see-through
background by working out the desk's colour gradient from scratch for every
pixel, every time it repainted. Dragging a divider next to one repaints it on
every mouse move, so the drag felt heavier with a viewer open. Now the viewer
copies the background out of the picture the window has already drawn, which
is several times cheaper and matches the window's own pixels exactly.

## Goals

- [x] the viewer's glass sheet is read out of the window's rendered desk when that desk holds the viewer
- [x] the gradient is evaluated only when there is no such desk (a test pane, before the first desk paint)
- [x] the sheet matches the desk pixels the window paints round the card, so no seam appears

## Validation criteria

- [x] a divider drag beside a glass viewer no longer evaluates the gradient per pixel (timed before/after) - unit test `T1923: a glass viewer's sheet read out of the window's desk...` (PaneDesk.zig, win32 lane) times both on an 880x940 viewer region in Debug, single thread: evaluated 6645us, from the desk 1437us (4.6x), and asserts the desk read is the cheaper; the paint itself runs that read across the sheet worker pool. `ViewerPane.glass_cost.desk_paints` counts the paints that took it. A live drag timing with a viewer in drag-perf's grid is T3599.
- [x] the viewer's sheet still meets the desk round its card without a seam (unit test against the analytic sheet) - same test: every pixel equals `sheetMix` of the window's desk pixel under it (the bitmap the card rims are painted on), and stays within 3 levels of the evaluated sheet; the pooled path is byte-identical to the serial one; a region off the desk returns false and writes nothing. viewer-panes.ps1 ALL PASS (205), pane-elevation.ps1 ALL PASS (152).
