# T3385 - Check that a fast-exiting command's 'Process exited' notice survives under session persistence (agent-hosted ConPTY), the T3383 race on the remote path

## Summary

T3383 fixed a race on the LOCAL ConPTY path (src/termio/Exec.zig): conhost's first paint (erase + blank frame) can land after a ~10ms child exits, and the exit notice was printed before it and erased. ipc-child-exited.ps1 runs with --session-persistence=false, so the default path - the agent hosts the ConPTY and frames EXIT after the session's final DATA (src/termio/Remote.zig ~2872) - is not exercised. Whether the agent's pty host waits for conhost's first paint before sending EXIT is unverified. Add an arm to ipc-child-exited.ps1 with persistence on (cmd /c exit 0 and exit 3, +read shows the notice / diagnostic); if red, apply src/termio/conpty_exit_gate.zig's paint-seen rule in the agent's pty host before it frames EXIT.
