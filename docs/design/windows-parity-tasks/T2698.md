# T2698 - Settings: 'Start new windows in' (and likely Shell) show the changed dot while unset, because finalize resolves their live value away from the schema default

## Summary

Found while validating T2681 (screenshot of the Terminal page after `working-directory` was reset): the "Start new windows in" row carries the accent changed-dot and the sidebar counts it, although the user's file does not set the key.

`SettingsSources.Reader.isModified` returns true when the effective value differs from the schema default, and the effective value comes from the FINALIZED config: `Config.finalize` resolves `working-directory` to the home path (and fills `command` with `cmd.exe` on Windows), so both read as changed with nothing in the file. Check Mac's `isModified` for the same comparison (it reads the same finalized schema) - if Mac shows the dot too, fix both seats; if not, match Mac's rule.

Likely fix: for keys finalize resolves, compare against the pre-finalize value, or treat "not set in any loaded file" as unmodified for them.

## Validation criteria

- [ ] with an empty config, Terminal's Shell and Start new windows in rows show no changed dot and the page count excludes them
- [ ] settings-window.ps1 asserts `modified=false` for both keys when unset
