# T3041 - PA-V09: on glass, every viewer paint allocates and renders a full-window bitmap, even under an opaque web page (ViewerPane.zig:7112)

## Summary

PA-V09 (audit-1, T2963). paintGlass (ViewerPane.zig:7112-7130) creates and destroys a full-client 32bpp DIB and renders the whole sheet on every WM_PAINT, also under an opaque website page (paintUnderPage :7154-7174 ignores the update rect). Cost (computed): 5 MB per paint at 1400x900, 33 MB at 4K, on every resize step and backdrop change (setGlassBackdrop :5215). Fix: a grow-only DIB (as ViewerNavBar.ensureBack), clip to the update rect, skip the controller rect under an opaque page. Risk: stale pixels while the page arrives (T1885). Findings: docs/design/perf-audit/audit-1/V-findings.md.

## In plain terms

On a see-through (glass) window, every time a viewer pane redrew itself -
including every step of dragging a window edge - it built a brand-new
picture the size of the whole pane, drew the frosted background into all of
it, copied it to the screen and threw it away. It did that even behind a web
page that completely hides the background. Now the pane keeps one picture
and reuses it, redraws only the part that actually changed, and skips the
part a web page covers. Nothing looks different; resizing a window with a
viewer in it does less work and churns far less memory.

## Goals

- [x] the glass sheet's pixels are reused across paints instead of allocated per paint
- [x] an ordinary partial repaint lays the sheet only over its dirty rect
- [x] under a ready, opaque web page the sheet under the page is skipped
- [x] any change to the sheet itself (new slice, resize, page turning opaque/see-through, page moving) still repaints the whole client, so no stale pixels (T1885's risk)
- [x] the buffer is given back off glass, when the pane's snapshots are released, and at teardown

## Design

- The buffer is a plain heap `[]u32` blitted with `StretchDIBits`, not a kept
  DIB section: no GDI object to hold, and the rendered region is always
  contiguous at its own width, so a grow-only buffer needs no stride juggling.
  Grown with 25% headroom; `glass_cost.allocs` counts the grows.
- `paintUnderPage` takes the update rect (read with `GetUpdateRect` before
  `BeginPaint`). Whether a host's update region reaches under a child window
  is never relied on: `glass_full_due` forces a whole-client paint whenever
  the sheet itself changed, so the clip only ever trims an ordinary repaint.
- `WM_PRINTCLIENT` (pixel probes) still paints the whole client, page area
  included - a photograph has no web view on top.
