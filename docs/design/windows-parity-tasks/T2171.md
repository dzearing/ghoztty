# T2171 - The command palette no longer opens the Agent Integrations window on the test desktop: claude-integration.ps1 cases 4 and 6 red, last green 2026-09-19

## Summary

`test\win32\claude-integration.ps1` is red with 2 failures (56 assertions
passed). It failed the same way run alone and beside other scripts, on
2026-10-22 during the T1213 turn (lane b):

- `palette opens the Agent Integrations window` (case 4, line 368).
  `Invoke-PaletteAgentSetup` reports the flow injectable, but no
  `GhozttyAgentIntegrations` window appears within 10 s.
- `the management window opens with no agents installed` (line 563), same
  wait.

The harness was last stamped green on 2026-09-19 (b6b6f2b79). The dialog's
class name is unchanged and `AgentIntegrationsDialog.zig` has had no commit
since. The first-run cases in the same run all PASS, and they are the only
path T1213 touched (`setupEnabled`, bypassed by the `force` seam here). So this
broke somewhere in the month between, most likely in palette dispatch or how
the action reaches the dialog on the background test desktop.

Bisect from b6b6f2b79 with the harness, fix the cause, and re-stamp. The guard
is acked to this task until then.

## In plain terms

Picking "Agent Integrations" from the command palette may no longer open the
window where you set up Claude. At minimum, the automated test that proves it
does is failing, and has gone unnoticed for a month.

## Goals

- [x] Find what broke the palette path in claude-integration.ps1
- [x] Make the harness green and re-stamp its guard
- [x] File the user-visible ranking issue it exposed (T2173)

## Validation criteria

- [x] claude-integration.ps1 ALL PASS, run alone on the test desktop
  (`acceptance-parallel.ps1 run -Scripts claude-integration.ps1 -FailFast`,
  2026-10-22: ALL PASS, 87 assertions; guard re-stamped, ack released).
- [x] The cause named, with the commit that introduced it: 375846ed6 (T1804,
  2026-10-10) gave "Restart Ghoztty and Background Sessions" the keywords
  `relaunch reopen agent`. The palette lists matches alphabetically, so the
  harness's bare `agent` query put that row above "Set Up Agent
  Integrations…" and Enter took it. The dialog, dispatch and test desktop were
  never at fault.

## Resolution

The harness now types `set up agent`, which matches the one row it means. The
product side - a keyword-only match outranking a title match, which a user
typing "agent" meets too - is Windows-only (Mac filters titles, no keywords)
and is filed as T2173.
