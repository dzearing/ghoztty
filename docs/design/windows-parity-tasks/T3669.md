# T3669 - Linux L8d-6: per-host shell and cwd defaults apply to GTK remote windows, tabs and splits

## Summary

Split from T3668 part 3. win32 openDialedWindow and buildRemoteInherit consult host_defaults.lookup (T174): a new remote window takes the host's default shell and cwd, and a tab/split on that machine takes the default SHELL only (cwd inherits from the parent). The GTK frontend never reads host defaults, so a remote window, tab or split always opens the agent's default shell. Wire host_defaults into ipc_remote_window.finishWindow/fromFocused and window.remoteTabInherit/split_tree.newSplitAt. Acceptance: test/linux/cli-remote-window.sh with a host-defaults file naming a shell.

## In plain terms

On Linux, the per-machine Host Settings (a default shell and starting folder
for each remote machine) were saved but never used: a remote window always
opened the machine's own default shell. Now a new remote window opens in the
machine's chosen shell and folder, and a new tab or split on it uses the chosen
shell while staying in the folder it was opened from - the same as the Mac and
Windows.

## Goals

- [x] A new remote window takes the machine's stored shell and cwd (an explicit flag wins; a relay window brought back at relaunch is untouched)
- [x] A tab or split on the machine takes the stored shell only and keeps its parent's remote cwd
- [x] An acceptance section proves each, with a negative control
