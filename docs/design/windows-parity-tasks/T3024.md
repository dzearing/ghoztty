# T3024 - PA-I10: +new-window and +split wait for the new pane's session by posting to the GUI thread every 15 ms for up to 3 s (IpcServer.zig:396-409)

## Summary

PA-I10 (audit-1, T2962). src/apprt/win32/IpcServer.zig:396-409 PostMessageW(WM_APP_IPC) a session check, waits, then sleeps IpcSessionAwait.poll_ms (15, ipc_session_await.zig:37) up to budget_ms (3000, :34). Cost (arithmetic): ~67 GUI wakeups/s, up to 200 per +new-window/+split with persistence on, and reply latency quantised to 15 ms. Fix: have the surface's session-bind completion signal an event the listener waits on with the remaining budget as timeout. Risk low. Findings: docs/design/perf-audit/audit-1/I-findings.md.
