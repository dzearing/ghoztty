# T1639 - The process sampler stops at 512 processes, so a busy machine's own sessions fall out of the snapshot

## Summary

Found by the T815 turn's standing floor, 2026-09-17: `zig build test-agent` FAILED
and reproduced under the solo-confirm re-run, on two tests that have not been
touched since 2026-08-15 -
`ProcSampler: a genuinely busy thread reports a plausible per-core cpu_pct`
(`src/remote/agent/proc.zig:997`, `try testing.expect(mine != null)`) and
`ProcSampler: enumerates own pid with a name; second sample yields cpu_pct >= 0`
(`:1107`, `try testing.expect(found)`). Both assert the same thing: the sampler
finds its OWN pid in the snapshot it just took. It no longer does.

`default_limit` is 512 (`proc.zig:33`) and `sampleWindows` walks the
`CreateToolhelp32Snapshot` list in the order the OS hands it back, stopping dead
at the cap (`:263`, `if (out.items.len >= cap) { truncated = true; break; }`).
`(Get-Process).Count` on this box answered **498** while the lane was red, and
`Get-Process` does not see every protected/system process - so the real count is
over the cap and the snapshot is being cut before it reaches the test binary.

This is not only a test problem. The rows that survive truncation are whichever
ones the snapshot happened to list first, NOT the busiest or the ones that belong
to us: on a machine with a few hundred processes the chooser's CPU column and the
session panel can silently omit a session that IS running. A cap is the right
idea (a pathological host must not balloon a snapshot); ordering the cut by
something meaningful, and never dropping our own lineage, is what is missing.

## In plain terms

On a machine that is running a lot of programs, the panel that shows what your
sessions are doing can quietly leave some of them out - not because they stopped,
but because the list it reads gets cut off partway through and whatever is past
the cut is invisible. Right now that even hides the app's own processes.

## Goals

- [ ] our own lineage is never the part that gets cut
- [ ] the cut, when one is needed, drops the least interesting rows rather than an arbitrary tail
- [ ] the truncation is visible to the caller instead of silent
- [ ] both ProcSampler tests pass on a box with more processes than the cap

## Validation criteria

- [ ] `powershell -NoProfile -File scripts\floor-lane.ps1 -Lane agent` green on this
      box while it is carrying 500+ processes (the state that produced the red).
- [ ] a unit test pins the rule directly: a sampler with a cap SMALLER than the
      live process count still returns the current pid.
- [ ] the chooser's CPU column still shows a session on a box over the cap.
