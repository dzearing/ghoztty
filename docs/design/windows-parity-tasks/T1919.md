# T1919 - A bell on Windows never draws the bell-features border: Mac strokes a yellow frame around the rung pane until it is looked at

## In plain terms

If you turn on the `border` bell option, a Mac pane that beeps gets a soft
yellow frame around it until you look at it. On Windows nothing appears.

## Summary

Split out of T1890, which landed `audio` and `title`. Mac draws
`SurfaceView.BellBorderOverlay` while `bell-features` has `border` and the
surface's `bell` is set: a 3pt stroke of rgb(1.0, 0.8, 0.0) at 50% opacity
around the surface's edges, no hit testing, faded in and out over 0.3s
(easeInOut). The win32 Surface already carries the flag (`Surface.bell`, set
by `ring_bell`, cleared on focus and on a key) and tells the window when it
moves (`Window.onPaneBellChanged`, T1890), so this is the drawing half only.

The shape that fits the existing chrome: a click-through layered popup owned
by the surface HWND, placed the way `DimOverlay` is (same layout/move/z-order
heal path in `Window.updateDimOverlays`, same `matchOwnerRegion` clip for an
elevated pane's rounded card). A hollow frame needs either per-pixel alpha
(UpdateLayeredWindow, the Scrollbar path) or a colour-keyed interior with
LWA_ALPHA for the 50%. The fade is a timer stepping the alpha.

## Validation criteria

- [ ] a BEL in a pane with `bell-features = border` shows a yellow frame of the scaled 3px width around exactly that pane (pixel probe on the test desktop)
- [ ] the frame goes away when the pane is focused or gets a key
- [ ] no frame without the feature; no frame on a viewer pane
- [ ] the frame follows the pane through a resize, a divider drag and a window move
