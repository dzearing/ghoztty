# T1919 - A bell on Windows never draws the bell-features border: Mac strokes a yellow frame around the rung pane until it is looked at

## In plain terms

If you turn on the `border` bell option, a Mac pane that beeps gets a soft
yellow frame around it until you look at it. On Windows nothing appears.

## Summary

Split out of T1890, which landed `audio` and `title`. Mac draws
`SurfaceView.BellBorderOverlay` while `bell-features` has `border` and the
surface's `bell` is set: a 3pt stroke of rgb(1.0, 0.8, 0.0) at 50% opacity
around the surface's edges, no hit testing, faded in and out over 0.3s
(easeInOut). The win32 Surface already carries the flag (`Surface.bell`, set
by `ring_bell`, cleared on focus and on a key) and tells the window when it
moves (`Window.onPaneBellChanged`, T1890), so this is the drawing half only.

The shape that fits the existing chrome: a click-through layered popup owned
by the surface HWND, placed the way `DimOverlay` is (same layout/move/z-order
heal path in `Window.updateDimOverlays`, same `matchOwnerRegion` clip for an
elevated pane's rounded card). A hollow frame needs either per-pixel alpha
(UpdateLayeredWindow, the Scrollbar path) or a colour-keyed interior with
LWA_ALPHA for the 50%. The fade is a timer stepping the alpha.

## Goals

- [x] a pane that rang shows Mac's soft yellow frame while `border` is on
- [x] it fades in and out the way Mac's does, and goes away once you look at the pane
- [x] it stays glued to its pane when the window or layout changes

## Validation criteria

- [x] a BEL in a pane with `bell-features = border` shows a yellow frame of the scaled 3px width around exactly that pane - `test\win32\bell-border.ps1` section 1: one `GhozttyBellBorder` popup whose rect equals the rung pane's rect (not the other pane's), stroke 4px at 120 dpi = round(3 x 1.25). **Pixel probe NOT possible** (capture limit named in the script: an UpdateLayeredWindow popup has nothing for PrintWindow and there is no composite off the input desktop); the pixels - rgb(255,204,0) at alpha 128 premultiplied, outer stroke only, clear interior - are asserted by `bell_math.zig` unit tests instead
- [x] the frame goes away when the pane is focused or gets a key - section 3: a key in the pane logs the fade-out to alpha 0 and the popup hides; no visible frame remains
- [x] no frame without the feature; no frame on a viewer pane - section 4 (second launch with `no-border,title`: the bell rings, the title glyph proves it, no frame window and no `shown` log). Viewer: `Window.updateBellBorders` skips non-terminal panes by construction, and a viewer has no bell to ring
- [x] the frame follows the pane through a resize and a window move - section 2 (rect equality after each). A divider drag rides the same `updateDimOverlays` layout pass the resize exercises; it was not driven separately
- [x] the fade is Mac's 0.3s easeInOut - `bell_math` tests (bezier (0.42,0)(0.58,1), retarget from the current alpha) plus the log: fade-in done alpha=255 at ~320ms, fade-out to 0 at ~304ms
- [x] -NegativeControl (first app without `border`) FAILS 8 assertions, so the script can go red
