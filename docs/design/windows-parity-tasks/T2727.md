## Summary

Split from T2398 (2026-11-05), which built the window-moving scenes.
`New-FrameLabCellSceneSpec` (`test\win32\lib\FrameLabLiveScene.ps1`) still
marks these four Unsupported, so their cells read `incomplete`:

- **banner** tracks `pane-top`: the banner pushes one pane's top down. A
  candidate edge: scan UPWARD in the pane's left padding column (theme
  background, not a card colour) until the padding colour stops - refused at
  calibration when the chrome above the pane is the same colour. The target
  pane comes from the trigger plan's target (`Get-FrameLabTrigger`).
- **hero, tab-switch, split-close** change the pane set mid-run, so one
  calibrated scene cannot describe every frame. Likely shape: one calibrated
  state per pane set (a still frame of each, taken by the scene hook the way

  best kept, with a frame that matches no state failing.
- The live driver's `Fire` hook still answers skipped for every trigger cell
  (`FrameLabDriver.ps1`); maximize-button's scene exists since T2398 but is
  only exercised once triggers are driven.

Reuse T2398's pieces: `GfsEdge.Open`/carried scans, `CalibrateMaximized`'s
second-still pattern, and the synthetic world in
`test\win32\frame-lab-live-scene.ps1` (section G).

## In plain terms

The frame lab photographs the app frame by frame during an interaction and
checks every frame looked right. Four interactions could not be checked at
all: showing a banner above a pane, the hero (zoom one pane) toggle,
switching tabs, and splitting then closing a pane - their cells always read
"incomplete". Now each has a scene the checker understands, so once the live
driver fires them (T2784) they get a real pass or fail.

## Goals

- [x] hero / tab-switch / split-close: score each frame against every pane set the run shows
- [x] refuse (never pass) a scene that cannot be read, and fail a run whose interaction never happened

## Design (as built)

- `pane-top` edge (`FrameLabLiveScene.ps1`): on the `Geometry.Target` pane, scanned UP its left padding column (new `GfsEdge.Until` without a backdrop) from near the pane's bottom; the scan's three columns are spread over the padding width measured on the still. Refused when the chrome above the pane is the padding colour.
- Pane-set states (`FrameLabScene.ps1`): `GfsSceneScorer.States` holds one calibrated scorer per other pane set; `ScoreFrame` scores against its own scene, then each state, keeps the first that passes (else the closest), and records `GfsRecord.State`. Edges recorded are always the base scorer's. `New-FrameLabCellScene -States @(@{Name;Geometry;Still})`; `Get-FrameLabSceneScore -ExpectStates` (driver passes it) makes a run with no other-pane-set frame a miss.
- Live: the driver's `Fire` still answers skipped; firing the plan and taking per-state stills (with a card in the split pane, and `Geometry.Target` for banner) is T2784.
