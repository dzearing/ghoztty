# T3634 - Linux: a Settings write keeps the config file's permissions and names its backup in local time, as the Mac does

## Summary

Found building T3569. The shared ConfigFileStore writes atomically through managed_file.writeAtomicNoFollow, whose non-Windows path renames a fresh temp file over the config, so on Linux the file takes the umask's mode instead of keeping its own (Mac rule: writes keep the file's permissions; a 0600 config must stay 0600). And ConfigFileStore.localNow is UTC off Windows, so a Linux backup is named config-debug.ghostty.<yyyyMMdd-HHmmss> in UTC where the Mac and Windows use local time. Fix both in the shared store with a Linux test (mode 0600 survives a set; the backup stamp matches the local clock).
