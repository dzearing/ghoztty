# T960 - Re-run the divergence inventory monthly so the cost of not merging upstream stays visible

## Summary

D80's option 'merge upstream later in one pass' carries a mitigation that has to exist or the option silently loses its safety net: re-run scripts/divergence-inventory.ps1 on a schedule so the growing gap is measured rather than assumed. Today the inventory is a one-off snapshot (2026-08-16) and nothing re-runs it, so 'the risk set is 131 files' will quietly become false and nobody will notice. Wire it into the daily triage (go.md step 0.6) as a monthly job, or into the digest, and have it report the delta since the last run - risk-set growth, new upstream commits, and whether the Zig-0.16 boundary has moved. Cheap, and it is the only thing that keeps docs/design/windows-parity-upstream-pull-plan.md honest over time.

## In plain terms

We keep a list of the files both we and the original Ghostty project have
changed - the places a future pull from Ghostty could go wrong. That list was
made once, in August, and nothing ever refreshed it, so its numbers were
quietly going stale. Now it is re-made once a month as part of the daily
housekeeping, and each refresh says what changed since the last one.

## Goals

- [x] The inventory remembers every run (a history file beside the report)
- [x] Each run reports what moved since the last: files joining/leaving the
      risk set, new upstream commits, fork point, both sides' minimum Zig
      version
- [x] A cheap "is it due?" question the daily triage can ask (`-Check`)
- [x] go.md step 0.6 asks it daily and runs the inventory when due
- [x] The first monthly run happened (2026-09-24) and is committed

## Validation criteria

- [x] A second inventory run reports the delta against the first: joined
      paths, new upstream commit count, and a `minimum_zig_version` move.
      **How verified:** `test\win32\divergence-inventory.ps1` section D (D1-D6)
      against a synthetic repo where upstream gains two commits (adds a path
      we also added, bumps the zon). ALL PASS (33 assertions). The first
      draft of the fixture accidentally committed the history file away and
      D2-D6 went red, so the section demonstrably fails when the history is
      missing.
- [x] `-Check` is DUE at exactly 30 days, CURRENT at 29, DUE with no record,
      and writes nothing. **How verified:** section E (E1-E5).
- [x] A report written before the history existed serves as the baseline, so
      the first real run had a delta. **How verified:** section F (F1-F4), and
      live: `-Check` read the 2026-08-16 report as `DUE ... 39d ago`, the run
      reported `DELTA since 2026-08-16: risk set 131 -> 145 (+15 -1), upstream
      +683 commits, fork point unchanged`, and `-Check` then said
      `CURRENT ... next due in 30d`.
- [x] The loop's instructions ask for it. **How verified:** go.md step 0.6
      "Monthly upstream divergence" bullet; the upstream-pull plan's state
      section points at the delta section (`upstream-remote` and
      `merge-terminology` harnesses re-run green after that edit).
