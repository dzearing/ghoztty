# T2850 - Fake relay/bridge Start-Job workers outlive the test that started them: 62 orphans with a 127.0.0.1 socket each accumulated 2026-11-03..08; find the harness and why the worker does not exit with its parent

## Summary

Found during T2805 (2026-11-08). The box held 62 orphaned Start-Job workers
(`powershell.exe -Version 5.1 -s -NoLogo -NoProfile`, parent process gone), one
created every hour or two from 2026-11-03 08:19 to 2026-11-08 22:30, each owning
a 127.0.0.1 TCP socket (some `Listen`) and using no CPU (one thread in
ExecutionDelay, the rest waiting). The socket points at the job-based fake
servers in `test/win32/lib/`: `FakeRelay.ps1`, `FakeAgentRelay.ps1`,
`PipeBridge.ps1` (all `Start-Job` + a `while ($true)` Pending()-poll loop, stopped
only by `Stop-*`). Their inherited handles wedged loop turns' tool hosts (T2805),
and T2805's watchdog now reaps any orphaned job worker every tick, so this no
longer stalls the loop - but every leak is still a process, a socket and a held
handle until the next tick.

Open questions:
1. WHICH harness leaks them (a test killed mid-run by acceptance-parallel's
   timeout skips its `finally`/`Stop-*`; or a harness that never calls `Stop-*`).
   The `created` times line up with due sweeps ~30 min in.
2. WHY the worker survives its parent. A plain `Start-Job { Start-Sleep 900 }`
   whose parent is killed exits with it (measured while writing T2805's
   fixture); these did not. Likely their stdin pipe's write end was inherited by
   a sibling (two jobs started by one script), so EOF never arrives - and their
   poll loop is no longer running either (0 CPU).

Fix direction: each job loop checks its parent pid (passed in at Start-Job
time) every pass and exits when it is gone; the harness that leaks gets its
cleanup in a `finally`.

## Validation criteria

- [ ] the leaking harness is named, with the evidence
- [ ] a fake-server job whose starting script is killed exits within a few seconds (acceptance arm that kills the parent and polls)
- [ ] a full due sweep leaves no orphaned `-s -NoLogo -NoProfile` worker behind (the watchdog log shows no `reaped` line for a day)
