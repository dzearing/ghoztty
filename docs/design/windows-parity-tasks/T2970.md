# T2970 - PA-R04: a focused pane wakes and redraws every 600 ms even when its cursor does not blink or is hidden, because the frame-change hash uses the raw blink phase

## Summary

PA-R04 (audit-1, T2959). Thread.zig:902-903 flips cursor_blink_visible and notifies on every tick while focused (armed at Thread.zig:475 regardless of whether the cursor blinks); generic.zig:1664 hashes the raw phase into frame_changed, so a steady, hidden (most TUIs) or off-screen cursor still produces a full updateFrame, buffer upload, gl.finish and present of identical pixels 1.67 times a second; generic.zig:3137 sets cells_rebuilt unconditionally. renderer/cursor.zig:64 shows the phase only matters when cursor.blinking. Fix: hash the result of cursorStyle(...) instead of the raw phase; only arm the timer while the cursor is visible, blinking and focused. Risk low; the 500 ms safety present still backstops. Shared code: Mac half filed with the shared-renderer Mac task.

## In plain terms

The pane you are typing in kept repainting itself about twice a second even
when nothing on it could change: a cursor that does not blink, or one a
full-screen program has hidden, was still "blinked" on a timer, and each blink
redrew and re-showed the whole screen. After this, a pane whose cursor cannot
blink stays completely still until something actually changes, and a blinking
cursor blinks exactly as before. Nobody sees a difference on screen; laptops
and busy boxes see less idle CPU/GPU work.

## Goals

- [x] the frame-change check only counts the blink phase when it can change the pixels
- [x] the blink timer stops while the cursor cannot blink, and restarts when a program turns blinking back on
- [x] a unit test pins "can the phase show" to the cursor-style rules
- [x] an acceptance harness counts the presented frames for blinking, hidden and steady cursors

## Validation criteria

- [x] presents per second with a steady cursor, and with a cursor a TUI hid, read 0 in a focused pane (renderer's own GHOZTTY_PERF frame counter) - `test\win32\cursor-blink-redraw.ps1` B/C: 0 perf lines in 6 s each on the fix; NEGATIVE CONTROL on the pre-fix release build (zig-out-release, +107cfa871): 5 lines each (fps=1), B and C red. The perf-baseline idle phase was not used: its pane is a cmd prompt whose cursor blinks, so it cannot see this fix; the dedicated harness measures the exact case instead.
- [x] a blinking cursor still blinks - same harness A (5 lines/6 s, before) and D (5 lines/6 s after a steady phase stopped the timer: it restarts), green on fix and pre-fix alike.
- [x] none lane unit test - `cursor: blinkMatters is false exactly when the phase cannot change the style` (every combination of blinking/visible/password/focused/preedit checked against `style()`), plus `cursorBlinkWanted` in Thread.zig; floor-lane -Lane all: lib/none/win32/agent PASS.
