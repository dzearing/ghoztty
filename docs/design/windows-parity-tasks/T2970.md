# T2970 - PA-R04: a focused pane wakes and redraws every 600 ms even when its cursor does not blink or is hidden, because the frame-change hash uses the raw blink phase

## Summary

PA-R04 (audit-1, T2959). Thread.zig:902-903 flips cursor_blink_visible and notifies on every tick while focused (armed at Thread.zig:475 regardless of whether the cursor blinks); generic.zig:1664 hashes the raw phase into frame_changed, so a steady, hidden (most TUIs) or off-screen cursor still produces a full updateFrame, buffer upload, gl.finish and present of identical pixels 1.67 times a second; generic.zig:3137 sets cells_rebuilt unconditionally. renderer/cursor.zig:64 shows the phase only matters when cursor.blinking. Fix: hash the result of cursorStyle(...) instead of the raw phase; only arm the timer while the cursor is visible, blinking and focused. Risk low; the 500 ms safety present still backstops. Shared code: Mac half filed with the shared-renderer Mac task.

## Validation criteria

- [ ] perf-baseline.ps1 -Phase idle: wakeups_per_s falls against baseline-1 (release 163.9) with a TUI that hides the cursor focused, and presents per second at idle with a steady cursor read 0 (renderer trace)
- [ ] a blinking cursor still blinks (acceptance harness covering cursor blink green)
- [ ] none lane unit test: frame_changed is false across a blink tick when cursor.blinking is false
