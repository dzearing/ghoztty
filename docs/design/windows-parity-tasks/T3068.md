# T3068 - PA-C15: the agent drain path parses 1 KiB per lock cycle and render post, and its priority yield can never run, so a waiting key or renderer can lose the mutex for a whole 512 KB wake (Remote.drainRing)

## Summary

PA-C15 (audit-1, T2964). src/termio/Remote.zig:2590 `slice_bytes = 1024`; drainRing pops at most 1 KiB (:2620-2650) and passes it to feedSliced, whose SliceIter (max_parse_slice = 4 KiB, :2231) returns it whole, so `if (it.rest.len > 0)` at :2276-2279 is never true and yieldToPriorityWaiters never runs; between lock cycles there is only an atomic load, a ring pop and a memcpy (the re-lock pattern renderer/State.zig:18-36 exists to stop). Each slice also runs queueRender and clock reads (Termio.zig:1192-1205): a 2 MB re-attach replay is 2,048 lock cycles and posts. Cost (computed at T1464's 0.06-0.07 us/byte): a priority waiter can lose for ~31-37 ms per 512-slice wake in ReleaseFast, seconds in Debug. Fix: call yieldToPriorityWaiters between drainRing iterations and delete the dead inner slicing (comments at :2219-2230, :2628 are stale); slice by mailbox pressure (grow to 4-16 KiB while underPressure() is clear) instead of a fixed 1 KiB. Risk: medium; the 1 KiB bound was chosen against mailbox overflow during Claude replays (:2614-2619). Ghoztty code used by both platforms' agent path: Mac half T3071. Findings: docs/design/perf-audit/audit-1/C-findings.md.

## In plain terms

When a pane is flooded with output (a big build log, or a session being restored), the thread that paints the output keeps grabbing the pane's lock back faster than anything else can get in. There was a "let the waiting key go first" handoff for exactly this, but on the default (agent-backed) panes it never actually ran. After this fix, a keystroke or the screen repaint that is waiting gets the lock between every 1 KiB of output.

## Goals

- [x] the priority handoff runs between every drain slice on agent-backed panes
- [x] zero cost when nobody is waiting (one atomic check)
- [x] a unit test that fails if the handoff becomes unreachable again
- [x] the throughput half (bigger slices, fewer lock cycles) filed as T3228
