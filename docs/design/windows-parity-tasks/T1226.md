# T1226 - Nothing on the box can create a background session with no reader, so the sweep that saves them is only proven on paper

## Summary

Filed while closing T1162. The vanished-child sweep (`SessionStore.sweepVanishedChildren`) exists because a background session whose shell exits with NO reader attached is never noticed - that is the field state the user hit, six sessions listed as running against dead pids for a day. The sweep is unit-tested against a synthetic process table, and `test\win32\session-vanished.ps1` covers the user-visible outcome end to end. What is missing is a box-level state that ONLY the sweep can rescue.

Measured, not assumed: `session-vanished.ps1` was run against the same build with `GHOZTTY_AGENT_VANISH_SWEEP=0` and section D still passed. Killing a holder from outside tears the session down through the holder-loss path, which reaches the same answer by a different mechanism - so an inverted assertion there would have been a control in name only, and it was removed rather than kept green.

So: find (or build) a way to reach "session alive, shell gone, nothing reading" from a script. The agent-handoff path is the likeliest route - an agent that inherits a session record whose holder is already gone while the shell is not - and `sessions.json` seeding (the shape `agent-session-cap.ps1` uses) is the other candidate. Once such a state is constructible, add it as a section to `session-vanished.ps1` with the sweep's off switch as its negative control, and the sweep finally has a box-level proof rather than a paper one.

## In plain terms

There is a safety net in the background service that closes out sessions whose program has quietly died. We can prove it works in isolation, and we can prove the end result the user sees is right - but on a real machine we cannot yet set up the exact broken situation the safety net was built for, so nothing on the box actually exercises it. This is about building that situation so a future change cannot remove the net without anything going red.

## Goals

- [x] Build the "shell gone, nobody can answer" state on a real box
- [x] Prove the sweep, and only the sweep, rescues it (sweep-off control)

## Validation criteria

- [x] A script can put the agent into "session alive, shell exited, no reader" without patching the build. - `New-NoReaderSession` in `test\win32\session-vanished.ps1`: detach, SUSPEND the session's holder (its shell's parent) with NtSuspendProcess, kill the shell. The holder is alive with its pipe open, so it is neither exited nor lost and `reapExited` gets no answer; asserted premises include "the suspended holder is still alive".
- [x] `test\win32\session-vanished.ps1` grows a section over that state whose negative control (`GHOZTTY_AGENT_VANISH_SWEEP=0`) genuinely fails, so the section is attributable to the sweep. - Section F runs the state with the sweep OFF and asserts the session is STILL reported running after 25 s (PASS: with the sweep off, nothing else notices). Section G runs it with the sweep ON: closed out within 90 s, and G2 proves the roster query still answers, so the drop is not a wedge. `acceptance-parallel run -Scripts session-vanished.ps1`: ALL PASS (39 assertions), twice.
- [x] The harness's "WHAT THIS SCRIPT DOES NOT PROVE" block is updated or removed to match what it then proves. - Now "WHAT D DOES NOT PROVE". It keeps the 2026-08-31 measurement for section D and names F/G as the sweep's box-level proof.
