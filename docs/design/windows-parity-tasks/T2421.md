# T2421 - Windows all-windows sidebar lists ungrouped windows (no '<project>: ' prefix) ABOVE every project group, so folding a group hides all of it, and a drag keeps an item to its side of that line (Mac 6bd2962eb)

## Summary

Mac main 6bd2962eb: windows without a '<project>: ' title prefix now list above every group, so a folded group no longer seems to leave members behind below it; window/group drags keep to their side (an ungrouped row cannot be dropped among groups and vice versa except via the into-group gesture). Windows: check the all-windows list order in the pane sidebar (T2337 shared order, T2338 into/out of group) and put ungrouped windows first; add an acceptance check. Ref docs/reference/pane-sidebar.md on main and PaneSidebarState.swift / PaneSidebarStateTests.swift in 6bd2962eb.

## In plain terms

In the sidebar's "all windows" list, a window whose title has no
"project: " prefix could sit right under a project group. Group members
are not indented, so it looked like one of that group's windows, and when
you folded the group it stayed behind. Now every ungrouped window is listed
first, above all the groups, and dragging keeps each kind on its own side,
the same as on the Mac.

## Goals

- [x] Ungrouped windows list above every group, by name or in their dragged order
- [x] Dragging a group stops below the ungrouped windows
- [x] A window dropped at the top level below a group lands at the end of the ungrouped windows
- [x] Losing its "project: " prefix (rename, drag out) puts a window with the ungrouped ones
