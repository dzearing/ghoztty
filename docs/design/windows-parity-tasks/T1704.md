# T1704 - Delete the composer's RichEdit fallback, GHOZTTY_COMPOSER_SURFACE and the dead quote-matching code

## Summary

With no harness pinned to it (T1703), remove the hidden RichEdit and its subclass from ViewerFeedbackBar.zig, richedit_tom.zig, the TOM undo suspension, the UTF-16 caret arithmetic, the derive-quotes-from-text matching in viewer_feedback_doc.zig, the GHOZTTY_COMPOSER_SURFACE override and ComposerSurface.ps1; the no-environment / controller-refused degrades become the failed-pane path T830's design says they are. Re-point the viewer-feedback guard-due Covers row and the seam-audit registry entry at the files that now carry the behaviour. Split out of T937.

## In plain terms

The feedback box in a viewer pane used to keep a second, hidden, old-style
text box behind the real one, as a fallback that nobody could reach any more.
This deletes it and everything that existed only to serve it. One thing gets
better along the way: a quote you had edited used to lose its link back to the
page the moment you added a second quote or a picture, and now it keeps it.

## Goals

- [x] The hidden RichEdit, its subclass, TOM undo suspension, UTF-16 caret arithmetic and `richedit_tom.zig` are gone
- [x] `GHOZTTY_COMPOSER_SURFACE` is gone from the app, the harness (`Set-ComposerSurface`) and the seam registry
- [x] A composer whose WebView2 cannot come up says so (`surface=none(...)` + a footer line) instead of degrading to a second engine
- [x] Text-matching quote derivation (`Registry.live`, `findLineAligned`, `insideQuote`, `lineTouchesQuote`) replaced by `shiftSpans`, which carries the page's spans across native splices
- [x] guard-due `viewer-feedback` Covers row and docs re-pointed at the files that carry the behaviour

## Design notes

- **No fallback, but not a dead pill.** T830's design says a failed second
  controller degrades to where a failed pane already is. The band still opens
  (closing it from inside `setFeedbackOpen(true)` would re-enter the pane's
  open path), logs `viewer feedback composer surface=none(no-environment|controller-refused)`
  at warn, and puts "The feedback box could not start" in its footer; the
  report text stays on the pane.
- **Quote spans are carried, not re-derived.** The derive-from-text matching
  was NOT dead: every native splice (`insertQuote`, `attachImage`) dropped the
  page's spans in `feedbackSetText` and re-derived them by matching passages at
  the next seed. That silently lost the identity of any quote the user had
  edited. `doc.shiftSpans` now moves the spans past the insertion (plus the new
  quote's own span, from `Insertion.block_start/block_end`); a chip landing
  inside a quote widens it, a quote landing inside one drops the old span. Pure,
  asserted in the none lane.
- **`ComposerSurface.ps1` kept, reduced.** The task said delete it; what it
  still does is the one-assertion proof every typing script makes that the page
  came up (`Wait-ComposerSurface`/`Get-ComposerSurface`), used by six scripts.
  Only `Set-ComposerSurface` (the env pin) was the dead half.
- **`GHOZTTY_TEST_BREAK_CHIP_RANGE` removed** with `chipRange`: no script set
  it any more, and the page deletes a chip as one node, so there is no native
  range left to break. `BREAK_UTF16` stays (T1710 drives it).
- Also dead with the RichEdit and removed: `chipAt`/`chipEndingAt`/`chipStartingAt`
  in `viewer_feedback_images.zig`, `ViewerFeedbackBar.owningEdit`/`handleChord`
  and their two routing blocks in `App.zig`. `clipboard_image.zig` is now
  uncalled too; filed as T1716 rather than widened into this change.
