# T2907 - +set-state needs_input never flashes the Windows taskbar button, while the Mac bounces the Dock icon

## In plain terms

When an agent in a background window stops and waits for an answer, the Mac
bounces Ghoztty's Dock icon so the user notices. On Windows the window title
gains " (question)", but nothing on the taskbar moves, so a user working in
another app never finds out the agent is waiting.

## Summary

Found while doing T1457 (rewriting the skill doc's `+set-state` paragraph to
describe what each platform actually does). Mac:
`BaseTerminalController.swift` (~line 4081-4107) calls
`NSApp.requestUserAttention(.informationalRequest)` when a window's aggregate
activity transitions to `needs_input`. Windows: `App.zig`'s `.activity_state`
handler (~line 10176) sets `surface.activity_state` and calls
`updateWindowTitle()` only - no `FlashWindowEx`, although the bell path in the
same file (~line 9071) already flashes the taskbar button for a backgrounded
window with `FLASHW_ALL | FLASHW_TIMERNOFG`.

Fix: on a window-aggregate transition INTO `needs_input` (not on every set),
when the window is not active, `FlashWindowEx` it the way the bell does. Then
update the `+set-state` row in `src/apprt/win32/skill_rewrite.zig` (added by
T1457; the Windows install currently says title suffix only) so the Windows
skill says the taskbar button flashes, and `docs/claude/cli.md` likewise.
