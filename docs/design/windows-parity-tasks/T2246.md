# T2246 - Build and eyeball T1359 on the Mac: the chooser's session card should name what a plain shell is running

## Summary

T1359 landed both halves from the Windows seat. The Mac half was written but
never compiled or run here:

- `src/apprt/embedded.zig` `ghostty_remote_connection_list_sessions` now emits
  `fg_cmd` in each JSON row (the lib lane compiled this on Windows).
- `macos/Sources/Features/Remote/SessionBrowserProbe.swift`: `BrowsedSession`
  decodes `fg_cmd` into `fgCmd` and exposes `command` (`fgCmd` else `argv`).
- `MachineChooserView.swift` session card's caption2 subline shows
  `session.command` instead of `session.argv`.

Build the Mac app and check it on screen. **A local Mac agent reports no
`fg_cmd` until T544** (the macOS arm of the foreground-command sampler) lands,
so the card can only light up for a Mac session after that - or today, for a
session on a Windows machine browsed from the Mac's chooser.

## Validation criteria

- [ ] `zig build -Doptimize=Debug` builds `Ghoztty-Debug.app` with no Swift errors
- [ ] Cmd-Shift-N chooser: a plain shell pane running `ping -c 60 127.0.0.1` shows that command under its cwd on its card within ~15 s (the agent's sample tick)
- [ ] the line disappears once the shell is back at its prompt
- [ ] a `--command` pane at rest still shows its argv, as before
