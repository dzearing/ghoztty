# T1078 - Wheel scroll and press-drag-release in a persistent-session pane have never been exercised

## Summary

T1067 built this seat's first pointer coverage - a posted move and a click at an agent-backed pane, asserted by the SGR report that comes back to the child (session-snapshot-reattach.ps1 M1b). The two gestures a user notices next are not covered anywhere: the WHEEL (a TUI's scrollback and any list widget) and a PRESS-DRAG-RELEASE (selection inside a TUI, which needs button-event tracking rather than any-event). Send-TestMouse already has -Action wheel and down/up, and the M1b child is a reusable raw-read TUI shape, so this is extending an arm rather than building one.

## In plain terms

Nobody had ever checked that scrolling the mouse wheel, or click-dragging to
select, works inside a full-screen program (an editor, a pager) running in a
pane whose shell survives app restarts. Now an automated test drives both
gestures at such a program and checks it receives them, so a regression shows
up as a red test instead of a user report.

## Goals

- [x] the wheel (both directions) is exercised against an agent-backed TUI
- [x] a press-drag-release is exercised under button-event tracking (`?1002h`)
- [x] the check can fail: a move with no button down must stay unreported
