# T3231 - perf-baseline -Phase cycle -AppEnv GHOZTTY_COMP_CHROME=1 sampled 87 threads at start on a pre-T3074 build where a direct test-desktop probe of the same exe and knob reads 141; the knob may not reach the cycle app, so chrome A/B runs measure nothing

## Summary

Found by T3074. `perf-baseline.ps1 -Build Debug -Phase cycle -SettledCycles 0 -AppEnv GHOZTTY_COMP_CHROME=1 -Exe <pre-T3074 zig-out>\bin\ghoztty.exe` reported cycle.start.threads = 87, identical to the fixed build. A direct probe (Start-OnTestDesktop, same exe, same knob, `chrome composition host ready` x3 in its stderr) reads 141 threads at one window and 257 at three on that build. Either the knob never reaches the app the cycle phase starts (the -AppEnv set at perf-baseline.ps1:459, the per-build child at :236-245) or the start sample is taken before the window builds its chrome host. The app stderr is deleted with $work at :1839, so the run leaves nothing to check. Fix: find which, and have the JSON record whether each -AppEnv knob took effect (e.g. count the knob's log line), so an A/B that measured nothing says so.
