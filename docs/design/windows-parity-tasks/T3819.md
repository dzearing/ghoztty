# T3819 - Windows release notes list Linux-only work and test-script commits: filter by seat and by what a Windows user can see

## Summary

Found 2026-11-26 while answering the user's "what's changed in the windows build lately" from release-notes/client/1.56.27-36.json - the files the Windows What's New window shows. A large share of each file is not Windows user-facing:
- Linux-only work from lane l (seat: linux tasks): e.g. 1.56.32 has eight "Linux single-window mode ..." items; 1.56.29 is mostly "On Linux the Settings window ...".
- Test / harness / bookkeeping commits that merely name a fix-tagged task: "label-weights.sh reloads with +reload --config" (1.56.34), "The T3651 fade acceptance greps the app's shade lines" (1.56.32), "Stamp seam-audit and unwired-hook-audit green" (1.56.27), "File the user's WSL, shell-picker and Settings-scroll reports" (1.56.27), "Record the green docs-routing and doc-claims runs" (1.56.35), "The Linux build compiles again ..." (1.56.35).
- Non-changes reported as New: "The all-windows stash well needs no more work" (1.56.35).

Cause (scripts/release-notes-author.ps1): an item is any non-chore commit naming a T<id> whose task tags include feature/fix/polish/perf/security. It never reads the task's `seat:`, and it does not distinguish the task's closing/code commit from the test, stamp, WIP and filing commits that also name it.

Fix: (1) skip tasks whose seat is not windows/all (linux and mac work belongs in their own platform's notes); (2) take one item per task - the commit the task's `commits:` list records (its closing code commit), not every commit that names it; (3) drop commits that touch only test/, docs/, scripts/, release-notes/ or task files; (4) drop subjects that start with Stamp/Record/File/Close/WIP/Note. Regenerate nothing already shipped, but re-run -DryRun on the 1.56.27-36 ranges to prove the output.

## Validation criteria

- [ ] Unit/fixture test over a synthetic range: a seat:linux fix, a test-only commit naming a fix task, a Stamp/Record commit and a real Windows fix -> only the Windows fix is listed; positive control shows today's script lists all four.
- [ ] -DryRun over the win-v1.56.31..win-v1.56.32 range lists no "Linux" item and no *.sh / acceptance / stamp line; result recorded here.
- [ ] A range with only Linux work still writes the plain "nothing new for Windows" line (the NOTHING TO SAY contract).
