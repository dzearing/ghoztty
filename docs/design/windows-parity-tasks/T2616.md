# T2616 - T2610 step 3d: window presenter lost-device and translucency rebuilds (generation bump: presenter rebuilds its context first, renderers rebuild against the new share context, SlotPair.reset) plus gl-device-lost.ps1 coverage of presenter and pane

## Summary

Builds on 3c. A reset is shared by the whole share group; any context that sees one tells the presenter. A window turning translucent after creation recreates the presenter with an alpha pixel format through the same generation bump. test\win32\gl-device-lost.ps1 grows a presenter-on section covering a loss seen first by the presenter and first by a pane.

## In plain terms

When the graphics driver resets or is replaced while Ghoztty is open, every
pane has to rebuild its drawing setup. With the new one-painter-per-window
design (still behind a switch), the panes and the window's painter share
that setup, so they have to rebuild together and in the right order, or the
panes come back invisible. After this, a driver reset on that path brings the
whole window back drawing, with no restart. A window turning see-through
needed nothing new: its drawing setup already supports transparency.

## Goals

- [x] A loss seen by any pane rebuilds the window's painter first, once
- [x] A loss seen first by the painter brings every pane along with it
- [x] Rebuilt panes draw again and reach the window's painted frame
- [x] Translucency after creation: checked, no rebuild needed (documented)

## What landed

- `WindowPresenter.zig`: `generation` + `lost_gen` (a pane's report, acted on
  only for the current generation); the thread's GL state is a `Live` that
  `rebuild` replaces whole on the `gl_robust` backoff; the presenter checks
  its own reset status per compose; debug-only
  `GHOZTTY_GL_SIMULATE_PRESENTER_RESET_AFTER`; after a rebuild every armed
  renderer is woken (`Surface.kickRenderer`). The compose skips a link from
  an older generation. `createSharedContext` is serialized (`share_lock`),
  resets stale handshake events, reads the share context only while the
  thread is parked, and returns the generation. `PaneLink` gained `stale`,
  `reportLost`, `presenterPast`, `sharedContext`, `rejoin`, `armed`.
- `OpenGL.zig`: a stale link is a loss (not reported); a real loss reports;
  `markLost` drops the presenter-path FBO/slot state; `rebuildContext` waits
  (50 ms polls, no attempt spent) until the presenter is past the lost
  generation, then makes the context through the share handshake and rejoins.
- Translucency: decided, not built. Pane and presenter pixel formats both ask
  8 alpha bits regardless of opacity, and `setTranslucent` never touched a
  context on the per-pane path either; design note updated.
