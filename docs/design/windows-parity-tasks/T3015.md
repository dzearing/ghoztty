# T3015 - PA-I01: the agent and every per-session pty holder commit a full 16 MB stack per thread, ~160 of the agent's 167 MB and 48-64 MB of each session's ~60-76 MB (server.zig:662, pty_host.zig:266)

## Summary

PA-I01 (audit-1, T2962). The PA-W01 stack tax (T2985: Zig 0.15.2 std.Thread passes default_stack_size 16 MB to CreateThread with flags 0, so it is committed) in the ghoztty-agent.exe image, which T2985's Summary does not name. Agent: 5 always-on threads (reaper session.zig:1724, handoff supervisor handoff.zig:422, sharing reconciler main.zig:2971, revoke watcher main.zig:2956, single-instance heartbeat single_instance.zig:1039), 1 holder-link reader per session (pty_holder_child.zig:451), 4 per app connection (main.zig:1850 worker, server.zig:662/668/674 writer, control, data readers) plus the roster pump on subscribe (server.zig:1928). Holder (a --pty-host re-exec, one per session): exit poller pty_host.zig:266, owner writer :424, ConPTY reader pty_child.zig:365, lazy input writer :501. Reconciliation against baseline-1 closes to 0.1 MB: attach +64.4 MB = 4 x 16; per session 19.15 = 16 + ~3; 1 session attached 167.4 vs 167.5 measured; holder 3-4 x 16 = 48-64 of 59.8-76.3 MB child private. Fix: explicit stack_size at each agent and holder spawn (or T2985's shared helper with STACK_SIZE_PARAM_IS_A_RESERVATION); readers keep 64 KB stack buffers (pty_child.zig:377, pty_host.zig:406, pty_holder_child.zig:474) and the agent holder reader runs the emulator parse, so size those 512 KB-1 MB and the rest 256 KB, or use the reservation flag. Also fold the four low-frequency agent tickers (handoff 60 s, sharing 5 s, revoke 5 s, heartbeat 10 s) into the reaper's 1 s loop. Risk low; running holders keep old stacks until their session ends; no wire change. Windows-only effect (macOS commits stacks lazily). Findings: docs/design/perf-audit/audit-1/I-findings.md.
