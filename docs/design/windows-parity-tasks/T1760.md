# T1760 - Chooser session cards still wear an open chip that the new Show button already says, which Mac dropped

## Summary

T1746 gave every live session card Mac's Show / Resume button. Mac removed its 'open' / 'attached' chips for exactly that reason (MachineChooserView.swift sessionDetailRow: a chip marks the EXCEPTION, and the row's button already draws open-vs-detached). The win32 card still paints a green 'open' badge beside every open session (chooser_sessions.badges), so an open row now says it twice. Drop the 'open' chip (keep activity, exit and the T520 'not in any window' warning), and move chooser-sessions.ps1's green-badge oracle (section 2) onto the Show button or the action log line. Screenshot: temp/t1746-chooser.png at T1746 close.

## In plain terms

In the machine chooser, every session that is already open in a window wore a
small green "open" label, right next to a button that also says "Show". Mac
removed that label because it said the same thing twice. Now Windows matches:
labels only appear for the unusual cases (busy, needs input, held by someone
else, not in any window).

## Goals

- [x] No "open" chip on a session card that is open in one of our windows
- [x] Busy / needs input / attached / not-in-any-window chips unchanged
- [x] The acceptance script proves the chip is gone, and can see it when it is there

## Validation criteria

- [x] `chooser_sessions.badges` returns no chip for a row open here (with or without `attached`), and only the activity chip for a busy open row - unit tests in the none lane (`floor-lane.ps1 -Lane all`).
- [x] The roster logs each listed row's chips (`chooser roster: row id=... open=... badges=...`), and every open row reads `badges=none` - `test\win32\chooser-sessions.ps1` section 2, 4 lines on the box.
