# T2134 - viewer-panes.ps1 T161 never finds the Chromium input child: the viewer split is most likely tucked behind a stacked row (T2108) and the script skips hidden viewers

## Summary

Found running the due harnesses for T2110 (2026-10-21). `test/win32/viewer-panes.ps1` fails one assertion, `T161 found the Chromium input child under the viewer host`. The scenario has P, a ctrl+d split and a `+split --view` viewer in one row. The discovery loop skips any `GhozttyViewer` that is not `Visible`. It is red with T2110's fix stubbed out as well, so the cause predates T2110. Its guard's Covers list does not name Window.zig, so nothing ran it after T2108 added stacking. Most likely cause (not yet confirmed): the row is too narrow for three panes at 300 DIP, so the viewer, which is not focused, is tucked. Fix: make the T161 window wide enough, or focus the viewer before the discovery. Decide whether the guard should cover Window.zig.

## In plain terms

The automated check for the viewer pane's keyboard shortcuts (reload, zoom,
jump to the address bar) had stopped running its checks. Since panes now
refuse to shrink below a readable width, the test's small window had no room
for its third pane, so the viewer under test was folded away behind its title
strip and the test could not reach it. The app was behaving as designed; the
test now opens a window wide enough for all three panes, and is re-run whenever
the window layout code changes.
