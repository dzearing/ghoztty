# T1808 - Measure background-blur on screen once runs can tell the user is away: run background-blur.ps1 (and re-run translucent-window.ps1, whose 09-27 result was taken over a game), then compare acrylic with Mac's blur side by side

## Summary

T1788 put `background-blur` on the Windows 11 acrylic backdrop. What it could
prove without the user's screen: the mechanism choice (unit tests) and that a
window launched with the blur on reads its backdrop attribute back as 3 and
logs `mechanism=acrylic` (from a background test desktop). What it could NOT
prove: that DWM actually blurs what shows through, that glyphs stay opaque
over it, and that a live reload flips it both ways. Those are sections A-E of
`test\win32\background-blur.ps1`, which must draw on the input desktop.

translucent-window.ps1 (T1787) flapped on 2026-09-27 for the same reason: it
ran over the user's fullscreen game. Re-run it under the same condition.

Then compare acrylic with Mac's plain blur side by side. Acrylic adds a tint
and noise that Mac does not; if the difference reads clearly to the eye, file a
decision (experience gap: "should a blurred window look frosted, like Windows,
or plain-blurred, like Mac?") rather than picking silently.

Gated on T1794: run only once a run can tell the user is away.

## Validation criteria

- [ ] `test\win32\background-blur.ps1` ALL PASS on the input desktop, with the
      user away (and its `-NegativeControl` fails B), which stamps the guard.
- [ ] `test\win32\translucent-window.ps1` ALL PASS under the same condition.
- [ ] Side-by-side comparison with Mac recorded in this file; a decision filed
      if acrylic reads visibly different.
- [ ] `Advisory = $true` dropped from the `background-blur` guard row.
