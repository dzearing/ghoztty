# T998 - A torn build cache still reads as a code failure everywhere except floor-lane

## Summary

The cache heal (T494, extended by T973) lives in floor-lane's lane loop, so only the four floor lanes get the recognize-delete-retry treatment. A staging build under launch-upgrade.ps1, an acceptance script that builds, or a bare 'zig build' hits exactly the same half-written cache entry with no recognition and no retry, and reports it as red code. Lift the detection into something every build path can call (a wrapper, or a pre-build sweep) so the diagnosis is never paid twice.

## In plain terms

When a crash or reboot leaves a half-written file in the compiler's cache, the
next build fails with an error that looks like the code is broken. The standard
test runs already knew to spot that, clean the bad file and try again, but a
delivery build, the test scripts' own rebuild, and a build typed by hand did
not. Now they all do, so a damaged cache costs one extra build instead of a
wrong diagnosis.

## Goals

- [x] the detect-and-heal decision lives in one shared function every build path calls
- [x] the delivery's staging build heals and retries once
- [x] the acceptance harnesses' rebuild (BuildFresh) and the on-demand test client build heal and retry once
- [x] a hand-run build has a wrapper (`scripts\zig-build.ps1`) that does the same
- [x] floor-lane keeps its behaviour, now through the shared function
