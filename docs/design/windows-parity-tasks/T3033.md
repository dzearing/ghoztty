# T3033 - PA-V01: the performance baseline never opens a viewer, so no viewer memory, process or CPU cost is measured (perf-baseline.ps1)

## Summary

PA-V01 (audit-1, T2963). scripts\perf-baseline.ps1 has five phases (idle, busy, resize, cycle, agent) and none opens a viewer, so every viewer cost in audit-1 is an estimate. Fix: a `viewer` phase that opens a markdown, a git-status: and a website viewer; records msedgewebview2.exe process count and private bytes (the environment's browser process and its children), app private bytes and GDI/USER objects; hides the tab for 60 s (renderer CPU and private bytes while hidden); then closes every viewer and waits 90 s (residual tree). Risk: WebView2 process discovery on the test desktop. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## Validation criteria

- [ ] the viewer phase runs on the test desktop for Debug and ReleaseFast and writes viewer.open, viewer.hidden and viewer.after_close blocks with method strings
- [ ] a -Compare of two consecutive runs is within tolerance on every viewer metric
- [ ] docs/design/perf-audit/README.md lists the phase
