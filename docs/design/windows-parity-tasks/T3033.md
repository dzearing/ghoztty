# T3033 - PA-V01: the performance baseline never opens a viewer, so no viewer memory, process or CPU cost is measured (perf-baseline.ps1)

## Summary

PA-V01 (audit-1, T2963). scripts\perf-baseline.ps1 has five phases (idle, busy, resize, cycle, agent) and none opens a viewer, so every viewer cost in audit-1 is an estimate. Fix: a `viewer` phase that opens a markdown, a git-status: and a website viewer; records msedgewebview2.exe process count and private bytes (the environment's browser process and its children), app private bytes and GDI/USER objects; hides the tab for 60 s (renderer CPU and private bytes while hidden); then closes every viewer and waits 90 s (residual tree). Risk: WebView2 process discovery on the test desktop. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## In plain terms

The tool that measures how much memory and processor time Ghoztty uses never
opened a document, diff or website pane, so every claim about what those panes
cost was a guess. It now opens all three, measures them shown, measures them
while hidden behind another tab, and measures what is left over after they
are closed.

## Goals

- [x] a `viewer` phase in `scripts\perf-baseline.ps1` (markdown, `git-status:`, website)
- [x] `open`, `hidden` and `after_close` blocks, each with a method string
- [x] runs on Debug and ReleaseFast, and two runs agree within tolerance
- [x] the README lists the phase

- [x] a -Compare of two consecutive runs is within tolerance on every viewer metric - final script: Debug run 6 vs 7 `COMPARE WITHIN TOLERANCE (51 metrics)`, Release run 3 vs 4 `COMPARE WITHIN TOLERANCE (51 metrics)`.
