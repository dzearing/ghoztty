# T2193 - zig build test-lib-vt (libghostty-vt and its C API, src/terminal/c) runs in no floor lane on this box, so its tests are never executed on Windows

## Summary

Found by T1237's whole-tree sweep. 23 test-bearing modules - `src\lib_vt.zig` and all of
`src\terminal\c\*.zig` (the libghostty-vt C API) - appear in none of the three test binaries
this box's floor runs (`test` win32, `test` none, `test-agent`). Their tests live in
`zig build test-lib-vt` (two `addTest`s over `mod.vt` / `mod.vt_c` in `build.zig`), and
`scripts\floor-lane.ps1` has no lane for that step, so on Windows they are compiled by
nothing and executed by nothing. T1237 declared them as an exemption in
`test\win32\lib\TestReachAudit.ps1` naming this task.

Fix: decide whether `test-lib-vt` builds and passes on Windows at all (measure it), then
either add it as a floor lane (and add its two binaries to the test-reach sweep's lane
set, dropping the exemption - section D5 turns red the moment the exemption is stale), or
record why it cannot run here and which seat does run it.

## Validation criteria

- [ ] `zig build test-lib-vt -Doptimize=Debug` measured on this box (pass / fail / does not build), result recorded here.
- [ ] Either: the lane runs in `floor-lane.ps1` and the `lib_vt` / `terminal.c` exemptions are gone with `test-reach-audit.ps1` green; or: the exemption's reason names the seat that runs it.
