# T986 - Show the picture itself in the composer's image chip, the way Mac's attachment does

## Summary

**Re-scoped on claim (2026-09-24).** The original premise was wrong: Mac's chip
does NOT show the picture. `ViewerFeedbackChipCell.drawChip`
(`macos/Sources/Features/Viewer/ViewerFeedbackComposer.swift:88`) draws the
LABEL `[Image #N]` in `controlAccentColor`, on an accent wash at 0.16 alpha with
a 0.45-alpha accent stroke; the thumbnail lives only in the carousel
(`ViewerFeedbackBar.swift:168`), exactly as it does here. Putting a picture in
the chip would have MADE the divergence this task set out to close.

What was actually different: the win32 chip (T936) had the wash, but its label
was the body colour and it had no edge. This task closes that - the label in
the accent (clamped to the 4.5:1 text floor against the wash) and a 1 px
accent edge - from one derivation, `chrome_theme.accentTokenOn`, which also now
produces the quote block's wash.

Deliberately NOT matched: Mac's chip label is a smaller monospaced face. The
composer's wrapped line count is measured as scrollHeight / line box, and an
inline run in a different face or size can stretch the line box by its own
ascent/descent - the same reason the chip has no vertical padding. Colour and
edge carry the "this is one attached object" signal without that risk.

## In plain terms

When you paste a screenshot into the feedback box, it shows up as a little
"[Image #1]" tag. On Mac that tag is drawn in your accent colour with a thin
outline, so it reads as an attachment rather than as typed text; on Windows it
was plain text on a faint tint. Now it looks the same as on Mac.

## Goals

- [x] Confirm what Mac's chip actually draws (label, not picture)
- [x] Label in the accent, clamped to text contrast on its wash
- [x] 1 px accent edge that does not change the composer's line height
- [x] One derivation shared with the quote block's wash
