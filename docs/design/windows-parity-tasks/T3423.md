# T3423 - Resolve-RemoteTestClient hands back a stale remote-test-client.exe: an existing exe is returned with no check that it is newer than src/remote, so a harness tests old client code

## Summary

test/win32/lib/TestClient.ps1 Resolve-RemoteTestClient returns the first existing candidate (the caller's -ClientExe, then this repo's zig-out) and builds only when none exists. remote-test-client is an on-demand target the normal build never refreshes, so after a src/remote change every harness that drives it keeps running the old binary. T3408: agent-pipe.ps1 read green for two days after T3254 changed how the client's OPENED reply is handled, then went red once the exe was rebuilt. Fix: rebuild (or refuse) when the exe is older than src/remote/*.zig, the same shape as BuildFresh for ghoztty.exe; demonstrate with a stale-exe negative.
