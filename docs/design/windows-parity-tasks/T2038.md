# T2038 - A lane that has not pulled for over an hour after the other lane pushed a close can still be handed that task: the T2033 reservation ends a TTL after the push, and next -Claim never checks whether this worktree is behind its upstream

## Summary

P2: bounded residual of T2033 (needs an hour-old unpulled lane); costs a re-done turn when it hits, never data. Fix shape: next -Claim reads this worktree's @{u} copy of a candidate task (no fetch) and skips one the upstream already shows closed, saying pull.

## In plain terms

Two work loops share one task list. When one loop finishes a task, the other is
kept off it for about an hour after the finish is published; a loop that has not
picked up the latest list by then could be handed the same, already-finished
task and redo it. Now the loop also asks git whether the published list already
shows the task closed, and skips it with a "pull" note if so.

## Goals

- [x] `next` (and `next -Claim`) skips a todo the upstream already shows closed when this worktree has not pulled that change, naming it `CLOSED UPSTREAM ... - pull`
- [x] the same holds for a stale in-progress copy (no RESUME of a task closed upstream)
- [x] a task this lane re-opened in its own commit is still handed out (only commits this worktree lacks count)
- [x] never fetches: worktrees share refs, so the other lane's push alone advances `@{u}`
