# T3329 - Linux L0: one wrapper for every Linux build/test that refuses to run when the box is short of memory

## Summary

WSL2 has taken 28 GB on this box before. `%USERPROFILE%\.wslconfig` is the
user's and is tuned for their other WSL work (`memory=48GB`, `swap=16GB`,
`vmIdleTimeout=-1`, so the VM never idles out) - **do not edit it**; an 8 GB cap
would break that work. Guard on the Windows side instead.

Add `scripts/linux/wsl-run.ps1`: the ONLY way a Linux build/test is started
from Windows (the Linux lane, `D:\git\ghoztty-l`, calls nothing else).

- Refuses (exit 2, plain message) when Windows free physical memory is below a
  floor (start at 16 GB; `Win32_OperatingSystem.FreePhysicalMemory`), so a WSL
  build never buries the two Windows lanes. Re-checks between steps.
- Caps build parallelism inside WSL (`zig build -j<n>`, n from the free memory),
  since one zig compile can reach several GB.
- Names the distro explicitly (`-d Ubuntu`, never the default, never
  `docker-desktop`).
- Runs the repo from a clone inside the distro's own filesystem (`~/ghoztty-l`,
  synced from the lane's pushes) or from `/mnt/d/git/ghoztty-l`. Measure both
  once; `/mnt` is usually far slower for zig's cache.
- Sets `PATH` so the Linux `ghoztty` comes first: WSL appends the Windows PATH,
  and a bare `ghoztty` could reach the user's Windows terminal through interop.

Nothing in the Windows floor, sweeps or the Windows lanes may call it. Plan:
docs/design/linux-port.md.

## In plain terms

Linux builds of Ghoztty run inside WSL on this same machine, and WSL has
eaten 28 GB here before, freezing everything else. This adds one launcher that
every Linux build and test must go through: it refuses to start when the
machine is short on memory, keeps the build from using more than the free
memory allows, never touches the user's own WSL settings, and shuts WSL back
down afterwards if it was off to begin with.

## Findings

- A linked worktree's `.git` file names a Windows path
  (`D:/git/ghoztty/.git/worktrees/ghoztty-l`); Linux git calls it "not a git
  repository". `-Repo mnt` exports `GIT_DIR`/`GIT_WORK_TREE` in /mnt form with
  `GIT_OPTIONAL_LOCKS=0` (so a Linux `git status` never rewrites the Windows
  index); the clone is made from the common `.git`.
- PS 5.1 `-File` turns `--` into an ambiguous parameter named `''` for any
  script with a `param()` block, and binds `uname -a`'s `-a` to `-AllowAnyLane`
  by prefix. The wrapper parses `$args` by hand. PS 5.1 also strips embedded
  `"` from a command line, hence `-CommandFile`.
- The distro has no zig and runs as root; the user keeps other work in `~`.
