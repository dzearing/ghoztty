# T2502 - Turn GHOZTTY_PANE_LAYER on by default once a layered terminal pane has been seen rendering on the real desktop: text, cursor, resize/divider drag, stack folds, and the translucency toggle (T2499's GPU-leak fix ships opt-in until then)

## In plain terms

T2499 found why closing a terminal split or tab keeps about 3 MB of graphics memory, and fixed it: each pane now gets its own drawing surface, which goes away when the pane does. The fix is switched off for now, because nobody has yet looked at a pane drawn that way on a real screen. This task is that look, and then switching it on for everyone.

## Summary

T2499's fix: `src/apprt/win32/pane_layer.zig` + `Surface.initOnce` make a terminal pane window a LAYERED child (constant alpha 255, `Window.composeOpaqueLayer`), so it presents into a pane-sized surface of its own instead of its top-level's. Measured with `GHOZTTY_PANE_LAYER=1`: `pane-close-memory.ps1` ALL PASS (49), A8 0.05-0.50 MB per close where it was 2.95-3.45; `window-close-memory.ps1 -Shape split/full` A8 0.20 / 0.00 MB. An open pane also costs ~6 MB of GPU instead of ~9.

What has NOT been checked, and why it is opt-in: what a layered GL pane looks like on screen. DWM composes only the input desktop, and off it the terminal surface reads back as a flat fill (`test\win32\lib\TestDesktop.ps1` CAPTURE LIMIT), so no off-desktop harness can see it, and the go.md rule bars input-desktop runs while the user is present.

The check, on the real desktop, with a debug build launched as `$env:GHOZTTY_PANE_LAYER='1'; zig-out\bin\ghoztty.exe`:

1. Text and cursor draw in a single pane and in both halves of a split (not black, not stale).
2. Drag a divider and resize the window: no worse than without the knob (`resize-flicker.ps1`, `stack-fold-slide.ps1` stay green with the knob set).
3. Fold a pane stack and unfold it (strip face fades over the card).
4. `background-opacity = 0.85`: panes are created un-layered (log has no `has its own layer`); with an opaque config, `toggle_background_opacity` to translucent makes the desktop show through the panes (`gave up its own layer` in the log). `translucent-window.ps1` with the knob set is the oracle.
5. Then flip the default: `pane_layer.enabled()` returns true unless the knob says `0`, `pane-close-memory.ps1` goes green as shipped, and the `pane-close-memory` guard ack (moved here from T2499) is released.

Known limit carried over: a translucent window keeps plain children, so it still leaks ~3 MB a closed pane. Closing that needs per-pixel alpha on the pane's own layer (or the composition present path, T2360); file it when this lands.
