# T2885 - The search bar, command palette and link preview still set hand-written 13/16 px fonts off the type ramp

## Summary

T1389's type-ramp sweep (`test\win32\type-ramp-audit.ps1`) found the surfaces in
`Surface.zig` that predate `type_ramp` and still write their own font heights:

| Site | Size | Surface |
|---|---|---|
| `Surface.zig` link preview (`self.link_font`) | 13 | the hovered-link preview tooltip |
| `Surface.zig` search bar (`self.search_font`, create + DPI rebuild) | 16 | the in-pane find bar's edit box |
| `Surface.zig` command palette (`self.palette_font`, create + DPI rebuild) | 16 | the palette's input box |

Plus three that equal a ramp size but are written by hand (the audit reports
them as `hand-ramp`, informational): `Surface.zig` `palette_paint_font` (14),
`Window.zig` `rename_font` (12), and `FONT_PX = 12.0` in `key_state_pill.zig`
and `readonly_badge.zig`.

The off-ramp ones are declared in the audit's allowlist as "pending T2885" so
the sweep is green today; this task removes those entries.

## In plain terms

The find bar, the command palette's input and the link preview use their own
slightly different text sizes, chosen before the app had one set of sizes.
Fix it and they read as part of the same app as every dialog.

## Details

- Decide each size against the ramp (12 caption / 14 body / 20 subtitle). The
  16 px input boxes most likely become body (14); check the Mac's find bar and
  palette input sizes first, since a deliberate Mac match is a declared
  exception rather than a defect (the drag ghost's 10 pt title is one).
- Move the hand-ramp literals onto `type_ramp` calls while there.
- Remove the matching `pending T2885` entries from `$Allow` in
  `test\win32\type-ramp-audit.ps1`; the audit fails on a stale entry, so it will
  say when each one is done.

## Validation criteria

- [ ] `test\win32\type-ramp-audit.ps1` ALL PASS with no `pending T2885` entry left
- [ ] Find bar, palette and link preview checked at 100% and 150% on the test desktop (capture, not by eye)
