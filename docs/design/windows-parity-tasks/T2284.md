# T2284 - Windows panes stack into strips below 300x200 DIP; Mac lowered the pane minimum to 225x125, so the same window holds more panes on show before any folds (Mac afc64dc53)

## Summary

Mac afc64dc53: minimum pane size 300x200 -> 225x125 (layout and fuzz tests updated). Windows: pane_stack_layout.zig Metrics.minimum_pane_* is 300 x 200 and pane_stack_grid.zig tests assume 300 DIP. Change the metric, re-derive the grid/fuzz test expectations, and re-run the stacked-pane harnesses.

## In plain terms

On Windows a pane refused to get narrower than about 35 columns (or shorter
than a dozen rows); squeeze past that and panes folded into strips at the
window's edge. The Mac app now lets a pane go down to about 26 columns by
seven rows before anything folds, so the same window keeps more panes on
show. With this change Windows matches it. Two drag glitches the smaller size
exposed are fixed too: at 150% scaling, grabbing a strip's grip and letting
go without moving could swap which pane showed, and folding a pane could
hand the cursor to a pane that was itself folded away.

## Goals

- [x] the pane minimum is 225 x 125 DIP, as on Mac
- [x] the unit, grid and fuzz tests are re-derived for it
- [x] a grip pressed and released in place leaves its row exactly as it was, even when pixel snapping left a pane a fraction under its minimum
- [x] a pane folded by a drag hands the caret to a pane on show, never to one folded inside a nested stack
- [x] the stacked-pane acceptance harness asserts the new minimum
