# T3074 - The window chrome host (chrome_comp.zig:643) and the sidebar/child host (child_comp.zig:211) still create their own D3D11 device each, and every pane still creates its own DirectComposition device; move them onto T2968's shared device

## Summary

T2968 put every pane's swap chain on one process-wide D3D11 device (gl_comp_present.zig DeviceCache): 10 panes 611 -> 116 threads. Still per-object: chrome_comp.zig:643 and child_comp.zig:211 each call D3D11CreateDevice (about 50 driver threads each on NVIDIA), and Presenter.init still makes a DComp device per pane (gl_comp_present.zig, dcomp-device stage). Expose DeviceCache.acquire to apprt/win32 and use it in both hosts. Then measure whether one DComp device per window is worth it: DComp commits are device-wide, so sharing one across renderer threads changes commit batching. Validate with perf-baseline -Phase cycle (start.threads should fall) and chrome/child-comp harnesses. viewer_toc_comp.zig is T-PA-V08's own card.
