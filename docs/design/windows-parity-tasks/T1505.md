# T1505 - Nine zig test files still spawn threads they can return without joining (31 sites on the thread-join-audit baseline)

## Summary

T702 shipped `test\win32\thread-join-audit.ps1`, which checks the rule T693 and
T536 applied by hand to `src\remote\connection.zig`: a thread spawned inside a
`test` block is joined on every path out of it. `connection.zig` is clean. The
sweep found the same defect in 31 sites across nine other files, recorded in
`test\win32\thread-join-audit.baseline.json` so a NEW one goes red while these
stay known:

| file | sites |
|---|---|
| `src\remote\agent\link_control.zig` | 8 |
| `src\remote\tcp_dial.zig` | 7 |
| `src\remote\agent\keepalive.zig` | 5 |
| `src\remote\pipe_stream.zig` | 5 |
| `src\remote\inbound_ring.zig` | 2 |
| `src\remote\agent\server.zig` | 1 |
| `src\remote\client_mux.zig` | 1 |
| `src\remote\socket_stream.zig` | 1 |
| `src\terminal\search\Thread.zig` | 1 |

## In plain terms

When one of these automated tests fails, it should print the thing that went
wrong. In these files a failure can instead hang the test run or take it down
with a crash somewhere unrelated, so the message you needed never appears.
Nobody sees this on a good day - it only happens on the day something is
already broken, which is the worst possible time for the test suite to stop
making sense.

## Goals

- [ ] Every site on the baseline is guarded (or joined unconditionally), and the
      baseline is rewritten to match
- [ ] The baseline reaches zero, at which point the ratchet in section C becomes
      a plain "no unjoined spawn anywhere" assertion

## Details

The guard shape, from T693 - it must DISARM, because a second join is UB, and it
must close the transport FIRST, because the spawned thread is parked on a read
that nothing else unblocks:

```zig
var ath_joined = false;
errdefer if (!ath_joined) {
    conn.shutdown();
    ath.join();
};
```

What "close the transport first" means is per-site and is the whole work here:
`connection.zig` calls `conn.shutdown()`, `pipe_stream`'s accepter threads are
parked on a `ConnectNamedPipe`, `tcp_dial`'s on an `accept`, `link_control`'s
loop exits on `stopLoop()`, and `keepalive`'s reader on its stream closing. A
guard that joins without unblocking converts a reported failure into a hang,
which is the same defect wearing the fix's clothes. Spot-checked when the
baseline was recorded:

- `src\remote\pipe_stream.zig:591` - `try dialHandle(alloc, name)` sits between
  the spawn and the join, and the thread writes into the `Accepter` on this
  frame's stack.
- `src\remote\agent\link_control.zig:452` - seven `try poll(...)` calls between
  the spawn and the join, with the thread writing into `link` and `fake`.
- `src\remote\agent\server.zig:4230` - the second `try std.Thread.spawn` can
  fail and leak the first thread.
- `src\terminal\search\Thread.zig:868` - `try ud.reset.timedWait(...)` between
  the spawn and the join. Shared-core code, so the fix wants the `lib` lane too.

Work it file by file rather than in one sweep: each file is a different
unblocking story, and the audit scores per file, so a commit per file lowers the
baseline visibly. Run `test\win32\thread-join-audit.ps1 -UpdateBaseline` in the
same commit that fixes sites - the audit FAILS on a baseline that is higher than
the tree, so it cannot silently drift.

The narrow escape hatch, for a site where the join genuinely cannot be missed
and the audit cannot see why: a `// thread-join-audit: <reason>` comment at the
spawn. A reason is required; a bare marker waives nothing.

## Validation criteria

- [ ] `powershell -NoProfile -File test\win32\thread-join-audit.ps1` is green
      with a lower total after each commit, and zero at the end
- [ ] The baseline file's counts equal what the sweep finds (the audit's own
      section C asserts this)
- [ ] For at least one fixed site per file, a deliberately-failed assertion
      between the spawn and the join REPORTS the failure rather than hanging or
      crashing - run the lane with `-Dtest-filter` over that test and paste the
      failure line
- [ ] `scripts\floor-lane.ps1 -Lane all` stays green (the `lib` lane matters for
      `src\terminal\search\Thread.zig`)
