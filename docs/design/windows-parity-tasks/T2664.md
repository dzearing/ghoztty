# T2664 - Settings model on Windows: undo applies only while the file still holds what Settings wrote, and every new line is checked by Ghostty's own parser on a scratch config before it is written (Mac 92103f39d SettingsModel/ConfigSchema)

## Summary

Split out of T2583. Mac 92103f39d puts two of the Settings write rules in the model layer, not in ConfigFileText/ConfigFileStore, so T2583 (which ported those two files) does not carry them:

1. **Undo only if unchanged**: an undo of a Settings edit applies only while the config file still holds exactly what Settings wrote; if the user edited the file in between, undo refuses instead of clobbering their edit.
2. **Scratch-config validation**: before a new value is written, the rendered line(s) are loaded by Ghostty's own config parser into a throwaway config; a value the parser rejects is refused with the row's message and the file is untouched. Today the Windows store refuses only what `ConfigFileText.render` can tell syntactically (line breaks, unreadable lines).

Build both on top of `src/apprt/win32/ConfigFileStore.zig` (`edit` returns the `Change`, which carries before/after text for the undo check) using `src/config/Config.zig` directly for the scratch parse - no C API. None-lane unit tests mirroring the Mac SettingsModel tests for both rules. Mac reference: docs/reference/settings.md 'Rules'.

## In plain terms

When the Settings window saves a value, two promises have to hold: a value
Ghostty would reject never lands in your config file (the row says what was
wrong instead), and Undo never overwrites something you typed into the file
yourself after Settings saved. The Windows file writer existed; this adds the
layer that keeps both promises, ready for the Settings window to sit on.

## Goals

- [x] Every value Settings writes is first parsed by Ghostty's own config parser; a rejection is the row's message and the file, backups and reload are untouched
- [x] Undo restores the file only while it still holds exactly what Settings wrote; otherwise it refuses with Mac's message and leaves the file alone
- [x] The Mac SettingsModel write-path tests have Windows counterparts in the none lane

## Validation criteria

- [x] `ConfigValidator` reports Ghostty's diagnostics for `font-size = abc` (`invalid value "abc"`), `cursor-style = wiggle`, an unknown action in a keybind and an unknown key, and none for valid plain/list/keyed/quoted lines - 6 none-lane tests in `src/apprt/win32/ConfigValidator.zig` (port of Mac `validatorUsesGhosttysParser`)
- [x] An invalid value is refused with no write, no backup, no reload; a good value clears the problem - `SettingsModel: invalid values are shown and never written` (+ render refusal, whole-list refusal, keyed and custom-binding refusals)
- [x] Undo puts the file back, and refuses an outside edit (content, line endings only, file deleted) with the file untouched; once the file is back to what Settings wrote, undo works again - 4 undo tests in `src/apprt/win32/SettingsModel.zig`
- [x] Negative control: a planted wrong expectation in `ConfigValidator.zig` failed the filtered run (97/98 passed, 1 failed), so the new tests are compiled and run
- [x] Floor: `floor-lane.ps1 -Lane all` - lib, none, win32, agent all PASS
