# T2664 - Settings model on Windows: undo applies only while the file still holds what Settings wrote, and every new line is checked by Ghostty's own parser on a scratch config before it is written (Mac 92103f39d SettingsModel/ConfigSchema)

## Summary

Split out of T2583. Mac 92103f39d puts two of the Settings write rules in the model layer, not in ConfigFileText/ConfigFileStore, so T2583 (which ported those two files) does not carry them:

1. **Undo only if unchanged**: an undo of a Settings edit applies only while the config file still holds exactly what Settings wrote; if the user edited the file in between, undo refuses instead of clobbering their edit.
2. **Scratch-config validation**: before a new value is written, the rendered line(s) are loaded by Ghostty's own config parser into a throwaway config; a value the parser rejects is refused with the row's message and the file is untouched. Today the Windows store refuses only what `ConfigFileText.render` can tell syntactically (line breaks, unreadable lines).

Build both on top of `src/apprt/win32/ConfigFileStore.zig` (`edit` returns the `Change`, which carries before/after text for the undo check) using `src/config/Config.zig` directly for the scratch parse - no C API. None-lane unit tests mirroring the Mac SettingsModel tests for both rules. Mac reference: docs/reference/settings.md 'Rules'.
