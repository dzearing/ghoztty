# T3243 - A local agent still walks the whole process table every second for a close-confirmation answer the local app never reads: stop advertising session_busy on a local-agent connection (both apps)

## Summary

T3235 measured the release agent's idle cost: the reaper thread's per-second process snapshot for META{has_descendants} (sampleDescendants, session.zig) was ~30 of 30 Mcycles/s; T3235 cut it to ~17 by replacing Toolhelp32 with one NtQuerySystemInformation and sharing the snapshot with the vanished-child sweep. The rest is avoidable: the only consumer is win32 Surface.shellIsIdle/commandRunning, and only when shellPid()==0, i.e. a cross-machine pane - a local-agent pane has r.local and child_pid, and walks its OWN table at close time. So a local-agent connection should not advertise capability.session_busy (connection.zig client_capabilities is the one list every dial path injects; the local dial needs its own list, or createOpts needs a local flag). Additive and skew-safe: an older agent never sampled without it, a newer agent with an older app keeps sampling. The Mac app never reads has_descendants at all, so it can withhold it on every connection - check with the Mac seat. Validate: perf-baseline -Phase agent idle_cpu_cycle_pct drops to the floor; close confirmation for a busy local agent pane still fires (existing close-confirm harness); a cross-machine pane still gets META{has_descendants}.
