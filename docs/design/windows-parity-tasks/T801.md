# T801 - Terminal output does not linkify Windows environment paths (%USERPROFILE%\foo) - the POSIX $VAR/ branch has no Windows spelling

## In plain terms

A tool prints a path written with a Windows environment variable in it —
`%USERPROFILE%\src\app` or `%LOCALAPPDATA%\ghoztty\ghoztty.log`. On the Mac
the equivalent (`$HOME/src/app`) is clickable; here that spelling stays dead
text, because the pattern only knows the dollar-sign form.

## Summary

`src/config/url.zig`'s rooted branch has a `$VAR/` form
(`(?:[\w][\w\-.]*\/)*(?<!\w)\$[A-Za-z_]\w*\/`), which is what makes
`$HOME/src/config/url.zig` match. T757 added the Windows drive and UNC
branch, but not this: a `%NAME%\…` prefix has no branch, so it never
matches. ✓ VERIFIED by the T757 no-match case `"%USERPROFILE%\\foo"` in
`test "url regex"`, which passes today.

Both open questions settled while implementing (mechanism calls, per go.md
5b):

- **The matcher does not expand.** The link text is what the pane shows,
  percents and all, exactly as the POSIX branch hands `$HOME/...` over
  literally. But `ShellExecuteW` does not substitute either, so a click
  would have opened nothing — expansion now happens at the point of
  opening, in `App.openUrl`, and only for text that OPENS with the
  `%NAME%` + separator pair. Percent-encoding inside a real URL
  (`https://example.com/a%20b`) is never touched.
- **The sigil has to LEAD the path.** `foo\%BAR%\baz` stays dead text, the
  same call T757 made when it left a bare backslash-relative path
  unmatched: on Windows the sigil is the whole signal. A `%VAR%` further
  along a path that already started with one is just body text, so
  `%LOCALAPPDATA%\%USERNAME%\cache` matches whole.

## Validation criteria

- [x] `%USERPROFILE%\src\app` and `%LOCALAPPDATA%\ghoztty\ghoztty.log`
      match as whole paths (cases added to `test "url regex"`) — plus
      forward slashes, `%ProgramFiles(x86)%`, spaces, a second variable
      mid-path, `:12:5` line refs and surrounding parens
- [x] Prose containing a stray percent (`50% done`, `a%b`, `100%\foo`,
      `foo%BAR%\baz.txt`, a bare `%USERPROFILE%`) does not match — the old
      `%USERPROFILE%\foo` no-match case is replaced by these
- [x] Every pre-existing case in that test still matches — no regression
      to the POSIX branches or to T757's Windows branch (`zig build test
      -Dtest-filter="url regex"`, green)
- [x] A clicked env-var path actually resolves: `envPathNeedsExpansion`
      unit test in `src/apprt/win32/App.zig` covers the link shapes and the
      URL/prose cases it must leave alone (win32 lane, green)
- [x] Standing floor green: `scripts\floor-lane.ps1 -Lane all`, plus
      `test\win32\terminal-link-paths.ps1` (the guard row covering
      `src/config/url.zig`)
