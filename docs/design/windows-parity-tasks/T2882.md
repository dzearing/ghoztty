# T2882 - An open dialog keeps its old light/dark controls and frame when a config reload changes window-theme or background

## Summary

T1374 re-themes a dialog's frame and common controls on the OS light/dark broadcast, but a config reload that moves window-theme (or a background that crosses the luminance line under auto/ghostty) never reaches the open dialogs: none of ActivityMonitor, MachineChooser, Rename, Banner, Confirm, HostSettings, NewProcess or AgentIntegrations has a config-change hook, so the body repaints in the new palette on its next paint while the frame and controls keep the old side. Fix: have App's config_change fan out to the open panels and call system_colors.applyPanelChrome + rethemeControls + repaintForColorChange; prove it in chrome-theme.ps1 by reloading a light->dark config with the rename dialog open and measuring its button. Also gives the T1374 flip path the live test it lacks (the OS flip cannot be run while the user is present).
