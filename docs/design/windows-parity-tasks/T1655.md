# T1655 - The viewer worktree poll can queue behind its own worker the way the diff poll did

## Summary

Found while fixing [[T1654]], which was the same shape in the diff probe: a
poll tick that lands while a worker is out is REMEMBERED and re-issued the
moment that worker lands, so on a repository slower than the interval the two
chain end to end and the probe is never idle.

`ViewerWorktreeProbe.kick` does exactly that - `if (self.thread != null) {
self.dirty = true; return .pending; }` - and `complete` re-kicks on the strength
of that flag. Three things make it far less likely to bite than the diff probe
did, which is why this is filed rather than changed in the same breath:

- the poll interval is 15 s, not 2 s, and a pane nobody can see is not polled
  at all;
- the answer is CACHED, so most ticks never reach a worker;
- the work is one short `git` call, not the five to six a diff listing makes.

But `dirty` is also doing a second, legitimate job in that flag: it means "the
`want_*` this worker was started for have since CHANGED", which genuinely must
be re-issued. So the fix is not the one-line drop T1654 took - it is separating
"the question moved" (re-issue) from "the clock ticked" (drop), the same
`explicit` / `poll` distinction `ViewerDiffProbe.disposition` now makes.

## In plain terms

A viewer pane asks in the background which checkout it belongs to, and re-asks
every fifteen seconds. If one of those questions is slow, the next one lines up
behind it instead of being skipped - so in the worst case the pane never stops
asking. Nobody has seen it happen; the identical bug in the git-diff pane was
real, so this one is worth closing before it is.

## Goals

- [ ] A worktree poll tick that lands on a busy probe is dropped, while a
      changed `want_*` still re-issues
- [ ] The rule is asserted the way T1654's is: a pure function, in a test that
      fails if the two cases are ever collapsed again

## Validation criteria

- [ ] A unit test in the win32 lane covers all four cases (idle/busy x
      changed-question/tick) and fails if a tick queues.
- [ ] `scripts\floor-lane.ps1 -Lane all` green, and the viewer harnesses the
      guard table names for `ViewerWorktreeProbe.zig` re-stamped.
