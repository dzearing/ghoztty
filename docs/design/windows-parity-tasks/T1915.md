# T1915 - Check on screen that a glass viewer pane shows the desk through its markdown page (T1885's composite, unverifiable off-desktop)

## Summary

T1885 makes template viewer pages transparent over a host-painted glass sheet (WebView2 DefaultBackgroundColor alpha 0 + a sheet laid under the in-process Chrome_WidgetWin_0 child via an unclipped GetDCEx). Every piece is proven in the win32 lane except the composite itself: an off-desktop hidden parent's surface reads back black. When runs can tell the user is away (same gate as T1808), open a markdown viewer beside a terminal in a glass window and screenshot: the page background must vary with the desk and match the terminal pane's sheet at the seam; a website pane must stay white. If the area under the web view shows stale/black pixels, the under-page paint is not reaching the browser's surface and needs another route (e.g. drop WS_CLIPCHILDREN in glass mode).

## In plain terms

With glass panes on, a markdown viewer beside a terminal is supposed to read as
the same sheet of tinted glass, not a solid dark card. The code for that landed
in T1885 but nobody had ever looked at it on a real screen. Now a script films
the window on screen (without ever showing it to the user or taking focus) and
checks the viewer page really is the same glass as the terminal next to it,
while an `.html` page keeps its own white background.

## Goals

- [x] an on-screen oracle that films a glass window with a terminal, a markdown viewer and an `.html` page, without taking the user's focus
- [x] the markdown page matches the terminal's glass at the seam, row by row
- [x] the `.html` page stays white on glass
- [x] a negative control proves the seam check can fail

## Validation criteria

- [x] The markdown page's sheet matches the terminal's across the seam at every row of the empty lower half - `scripts\glass-viewer-onscreen.ps1` ALL PASS (20): largest per-channel row gap 1 (tolerance 8); terminal sheet 19,34,45 vs page at seam 19,35,44.
- [x] No black (never-painted) pixels under the web view - same run: 0 of 49,312.
- [x] The glass page is not the opaque card (positive control) - same run: glass page 18,36,42 vs `--macos-pane-glass=false` card 13,17,23, gap 21.4.
- [x] An `.html` page keeps its own background on glass - same run: 255,255,255.
- [x] The seam check can fail - `-NegativeControl` (the solid arm's card scored as the glass page) goes red: gap 22, exit 1.
- [x] Never takes the user's focus - the window is a `GHOZTTY_DEBUG_GHOST=bottom` ghost filmed by WGC (comp-desk-onscreen technique); both arms assert the foreground never belonged to it.
