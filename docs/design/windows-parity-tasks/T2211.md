# T2211 - viewer-toc-emphasis looks for the selection wash colour anywhere in the card, so anti-aliased text can match it when the row fill is missing

## Summary

Test-CardHasColor (viewer-toc-emphasis.ps1 161-169, used at 280-283/313-315) passes on any pixel exactly equal to the derived wash over the WHOLE card window. Label anti-alias ramps and other row/header washes pass through intermediate colours, so an exact match can come from outside the selected row, which is the paint-nothing build section B claims to exclude. Score the selected row's rect, with an unselected row as the control. Found by the T1281 inventory.

## In plain terms

The test that checks the viewer's contents card highlights the section you are
on could pass even if no row were highlighted: it only asked whether the
highlight colour showed up in any single pixel, and the soft edges of the text
can produce that colour by accident. It now looks for an actual highlighted
row, checks it is the row the accent bar marks, and checks the row next to it
is not highlighted.

## Goals

- [x] the wash is scored as a solid ROW fill, not a pixel anywhere in the card
- [x] exactly one row carries it, and in A the accent bar sits on that row
- [x] B's wash is on the same row A's was
- [x] an unselected neighbouring row is the control in both states
