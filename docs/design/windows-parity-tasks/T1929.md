# T1929 - Other GUI harnesses that score a pane's background may still be measuring the glass desk since T1886 made glass panes the default

## Summary

viewer-error-card.ps1 went 13-red after T1886 (glass panes default) because its clearance band read the desk, not --background; fixed in T1019's commit with --macos-pane-glass=false (41/41). chrome-theme.ps1 had already opted out. Sweep every test\win32 script that asserts a pane/viewer background pixel and opt it out (or score glass deliberately), or a harness that is not due today goes red the next time its row fires.

## In plain terms

When the app made see-through "glass" panes the default, some automated
checks that read a pane's colour started reading the window behind the
pane instead. This task checked every such script. None is still exposed,
so no test is waiting to fail for that reason.

## Goals

- [x] list every test\win32 script that reads pixels and does not opt out of glass
- [x] for each one, show that it already passed with glass on, or can never see glass
- [x] opt out any that remain (none did)

## Validation criteria

- [x] Every pixel-reading script that does not pass `--macos-pane-glass` has
      a guard stamp (a recorded green run) from AFTER glass became the default
      (771a1a264, 2026-10-12 15:04), except the ten below. Checked by
      comparing each `test\win32\<name>.stamp.json` `generated` field with that
      commit's time. That includes all 33 scripts that pin `--background=`
      and read pixels (tab-strip, split-divider, menu-bar, desk-variant ...).
- [x] The ten without such a stamp were each read and cleared:
      - `window-color.ps1`: runs `--macos-pane-style=flat`, and
        `Window.paneGlass()` (src/apprt/win32/Window.zig:3395) needs the
        elevated style, so its panes are never glass.
      - `translucent-window.ps1`: `background-opacity = 0.6`, and
        `paneGlass()` is false in a translucent window (`!self.translucent`),
        so glass never applies. It is an input-desktop exception and was not run.
      - `overlay-zorder.ps1`, `viewer-composer.ps1`: no colour checks.
        overlay-zorder uses WindowFromPoint; viewer-composer mentions
        CopyFromScreen only in comments.
      - `chooser-kill-hover.ps1`: scores the machine chooser window, not a
        pane. It is red on a filed defect (T2018).
      - `rdp-session.ps1`, `notification-click-real.ps1`,
        `profile-latency.ps1`: input-desktop scripts with no pane-background
        check.
      - `asserted-nothing.ps1`, `foreground-audit.ps1`,
        `test-desktop-spike.ps1`: source audits and a spike, not pane checks.
- [x] No script change needed. The only defect of this shape was
      viewer-error-card.ps1, and T1019's commit fixed it.
