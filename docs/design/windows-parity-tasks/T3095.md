# T3095 - PA-W17: the sheet/desk-compose worker pool (sheet_workers.zig:46) spawns up to 4 std.Thread.Pool workers at the 16 MB default stack and keeps them for the life of the app, up to 64 MB private

## Summary

Audit-2 (T3072) area W. std.Thread.Pool.init defaults stack_size to SpawnConfig.default_stack_size (std Thread/Pool.zig:30, :59), and initPool passes none, so T2985's small-stack fix never reaches these workers. They start on the first desk compose of 64k px or more (PaneDesk.zig:1908, :2039-2041). Fix: pass .stack_size = thread_stack.config.stack_size to pool.init, and extend T3075's source audit to catch Pool.init as well as Thread.spawn(.{}).

## In plain terms

Ghoztty keeps a few helper threads around to draw window backgrounds quickly while you drag or resize. On Windows each of them was reserving and paying for 16 MB of memory up front and holding it until the app closed - up to 64 MB nobody needed. After this fix they pay only for what they actually use (a few dozen KB), with the same headroom available if they ever need it.

## Goals

- [x] The sheet/desk-compose pool's workers start with the small committed stack every other long-lived thread already uses.
- [x] A shared helper (`thread_stack.poolOptions`) so any future `std.Thread.Pool` gets the same treatment without re-deriving it.
- [x] A measured test proving a pool worker's commit drops from ~16 MB to under 1 MB, with a positive control.

## Validation criteria

- [x] A pool worker made with std's default options commits >= 15 MB (positive control) - `zig test src/os/thread_stack.zig`, test "poolOptions gives pool workers the small commit too (T3095)".
- [x] A pool worker made with `thread_stack.poolOptions` keeps the 16 MB reserve and commits <= 1 MB - same test, same run, 4 passed / 1 skipped (non-Windows only).
- [x] `sheet_workers.initPool` uses `thread_stack.poolOptions` - code read at src/apprt/win32/sheet_workers.zig `initPool`.
