# T3822 - Closing panes does not give their memory back: the app holds ~128 MB more after 12 panes open and close, then plateaus

## Summary

Measured by test\win32\wsl-pane-lifecycle.ps1 (T3820), Debug build, real WSL, 2026-11-26. App private bytes per round of three panes (split, tab, window) opened and closed: baseline 247.6 MB; after round 1 287.9; round 2 (closes within undo-timeout) 351.1; round 3 362.9; round 4 375.7; rounds 5-7 375.5-376.6. Handles 883 -> 1013 and flat after round 2; the agent 12.6 -> 16.3 MB and flat. So it is not a per-pane leak (flat from round 4), but ~128 MB stays as high water after the panes are gone - the user asked that closed panes' memory be freed. Find what holds it: parked pane windows (T2597, up to 16 per top-level) and their GPU allocations, parked closed WINDOWS (three new windows a round), font atlases/render targets, the allocator never returning pages. Measure a ReleaseFast build too (the Debug allocator alone may explain it), and per-component (pane_pool off, undo-timeout 0) before changing anything. Window reuse stays ON.
