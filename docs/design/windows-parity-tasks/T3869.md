# T3869 - PA-M22: a workspace that surrenders the shared window and then closes in place never detaches its UIA strips provider, which leaks and stays registered with a pointer to the freed Window

## Summary

From audit-5 (T3316). The only detach is in WM_DESTROY (Window.zig:24420-24423); the in-place close (Window.zig:23680-23684, closed_workspace) calls onDestroy directly with no HWND message, so strip_uia_root (created at :24082-24083) keeps refs and its window pointer (strip_uia_provider.zig:337-364). A UIA client (a screen reader) that calls in afterwards reads freed memory. Introduced where de91e717ed (T2122) meets the T3184/T3191 in-place close. Fix: detach strip_uia_root in the shared teardown that both paths run (T3012). Detail: audit-5/M-findings.md.
