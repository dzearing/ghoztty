# T1996 - In lane B, an acceptance script run BY HAND (the 'run:' line guard-due prints) still grades lane A's build: 283 scripts default -Exe/-Repo to the literal D:\git\ghoztty, and only acceptance-parallel.ps1 re-roots them

## Summary

Found in T1993, which fixed the RUNNER: acceptance-parallel.ps1 now passes the re-rooted -Exe/-Repo in every phase and refuses scripts whose body resolves the literal. But guard-due's 'run: powershell -NoProfile -File test\win32\x.ps1' line, the floor-lane harness members, suite-run.ps1 and any turn running a script by hand still take the param default D:\git\ghoztty\zig-out\bin\ghoztty.exe from D:\git\ghoztty-b. Fix options: derive the defaults from PSScriptRoot (283-file mechanical edit, then the injection becomes belt-and-braces), or a BuildMode.ps1 preflight that refuses an -Exe outside the script's own checkout. Needs a negative control: a lane-B-shaped fixture checkout running a script bare must not launch the other checkout's exe.

## In plain terms

A second copy of the work loop is about to run beside the first, each in its
own copy of the code. When the second copy ran a test by hand - the way the
"run this" hint tells it to - the test quietly launched and graded the FIRST
copy's program, so a broken change could look fine. Now such a test stops
before it starts anything, says which copy it would have tested, and gives the
exact command that tests the right one. The first copy notices nothing.

## Goals

- [x] a script run bare from another checkout is refused before its body runs, naming the re-rooted value to pass
- [x] the Test-Path fallback cannot silently swap in the other checkout's build
- [x] suite-run (and so the harness floor) passes re-rooted parameters, using the runner's own classifier
- [x] guard-due's `run:` line names the runner outside the literal checkout
- [x] lane A (the literal checkout) behaves exactly as before

## Design

Option 2 of the summary, made total: `test\win32\lib\CheckoutGuard.ps1`, loaded
by `BuildMode.ps1` (and so by CleanSlate/TestDesktop) and `TestScore.ps1`,
which between them reach 282 of the 285 scripts that spell the literal. On load
it finds the calling script, and when that script sits under
`<checkout>\test\win32` of a checkout other than `D:\git\ghoztty` it throws
REFUSED if any PARAMETER's current value is under the literal, or a
`Test-Path` fallback would fire for want of this checkout's build. It refuses
rather than re-roots: a script silently testing something other than what its
parameters say is the defect, not a fix. The 283-file PSScriptRoot edit was
rejected because it would make every harness's guard row due at once for no
behavior change in lane A, and the runner's classifier keys on the literal
defaults. `exit` from a dot-sourced file does not stop its caller (measured),
hence `throw`. Hatch: `GHOZTTY_TEST_FOREIGN_CHECKOUT=1`.

## Validation criteria

- [x] the runner still runs scripts green in worker mirrors (foreign checkouts) - `acceptance-parallel.ps1 due` over the guard's covered libraries
- [x] zig lanes unaffected - `floor-lane.ps1 -Lane all` PASS (lib/none/win32/agent)
