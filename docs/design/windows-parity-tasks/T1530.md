# T1530 - Rearrange mode gives every pane a drag header and shows the tab bar

## In plain terms

Turning on rearrange mode does not look like anything yet: the tab bar comes
up, and the panes sit there exactly as they were. There is nothing to take hold
of and nothing that says which pane you are about to move. After this, every
pane grows a slim bar across its top — a grip you can grab, the pane's own
title so you can tell them apart at a glance, and a button that sends the pane
off into a window of its own. Press Escape and it all goes away again.

## Summary

The visible half of the mode: while rearrange mode is on, every pane grows a header - a drag grip on the left, the pane title, and a button on the right that pops the pane into its own window - and the tab strip is forced visible because it is a drop target. Escape or the toggle leaves the mode.

## Goals

- [x] Every pane of the active tab carries a header while the mode is on.
- [x] The header takes REAL layout space at the top of the pane (Mac's choice — a header that occludes nothing), above the sticky banner.
- [x] Grip on the left, title in the middle, pop-out button on the right.
- [x] The whole band is the drag surface, not just the grip (the grip is a hint).
- [x] Escape leaves the mode, from a terminal pane, a viewer pane or the bare window — and only while the mode is on, so the terminal keeps its Escape every other moment.
- [x] The tab strip is forced visible while the mode is on (landed in T1524, re-asserted here).
- [x] A pane too small to carry a header gets none, and pays no inset for one.

## The pop-out button ships DISABLED, and why

Mac's header has a pop-out button that moves the pane into a window of its own.
That is cross-window pane relocation, which this apprt has never had — nothing
under `src/apprt/win32/` calls `SetParent` today — and T1532 owns it together
with the session-safety rule that keeps a relocated pane's agent session from
being read as closed.

So the button is drawn, measured and hit-tested here, and painted in a DISABLED
treatment behind one constant (`Window.pane_pop_out_supported`). That is a
state Mac's own header has (`PaneHeaderView.canPopOut` greys it on a window's
last pane) rather than an invention, and T1532 flips the constant. The
alternative — leaving the button out until then — moves the header's geometry
under the user on the day the feature lands, and a live button that loses a
session is worse than a greyed one that tells the truth.
