# T3353 - win32 +new-remote-window --host --name=X labels the TCP window's pill with the host, where Mac labels it X

## Summary

Mac's host/port openRemoteWindow builds Machine(name: name ?? registry name ?? host, namePinned: name != nil), so a direct-TCP window opened with --name shows that name. win32's RemoteMachine.tcp carries only host+port and displayName answers the host, so --name is only the IPC target there. T1736 fixed the relay half (RemoteMachine.relay.name + name_pinned); the TCP half wants the same optional pinned name on .tcp, set in IpcHandlers.finishRemoteWindow, and a TCP arm in test\win32\remote-pill.ps1. P3: direct TCP is a dev/test path, the relay is what users pick machines through.
