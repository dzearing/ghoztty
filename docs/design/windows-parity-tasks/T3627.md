# T3627 - Linux L11e-4: stacked-panes state that lasts on GTK - collapses and the focus history ride the session layout (PaneStackState.Persisted by leaf position), an undone close puts the stack back (Saved), and a restore never focuses a blade

## Summary

Follow-up of T3567 (docs/reference/stacked-panes.md 'Saved with the window', 'Tree changes keep collapses' - Undo). The GTK SplitTree's PaneStackState (priv.stacks) lives only as long as the tab: a relaunch lays every collapsed row out from scratch, and CloseUndo does not carry stackSaved. Port win32's session_layout stack field (persisted/adopt) into gtk SessionLayout.zig and CloseUndo.zig, and the restoredFocusTarget rule. Acceptance: session-restore.sh section with a collapsed row surviving a relaunch; cli-undo.sh section with an undone close keeping its strips.

**As landed:** the acceptance is one dedicated script, `test/linux/stack-persist.sh`, rather than sections in session-restore.sh and cli-undo.sh. It needs a 400px pane minimum and a user-made collapse, and neither of those scripts' configs or flows should carry them. GTK keeps one `PaneStackState` per tab (win32 keeps one per window), so a parked tab already keeps its rows inside its parked SplitTree, and only a parked PANE needs a `Saved`. GTK's capture is a change-checked write every second, so no `collapseStamp` re-save hook is needed. Found and filed: T3744 (a close beside a strip focuses the strip).

## In plain terms

On Linux, when you fold a pane away into a slim strip, that choice used to be forgotten. It was lost when the app restarted, and lost again when you closed a pane and then undid the close. Now a restart brings the window back with the same panes folded, the cursor lands in the pane you were last using (not in a folded one), and an undone close puts the pane back exactly as it was.

## Goals

- [x] A tab's collapsed rows and focus history are saved in the session layout (`pane_stack`, by leaf position)
- [x] A relaunch adopts them before the tab is shown, so the row comes back as the user left it
- [x] A restore puts the caret in the pane focused last, never in a strip (`restoredFocusTarget` via `paneOnShow`)
- [x] An undone close puts the row back exactly (`Saved` + `restoreScoped`), and a pane that was a strip comes back a strip without taking focus
- [x] What could not land here is filed (T3744)
