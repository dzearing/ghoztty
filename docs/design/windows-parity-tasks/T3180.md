# T3180 - Single-window mode: read macos-window-mode once at launch on Windows and offer it in Settings > Panes & Windows (takes effect at next launch)

## Summary

Latch Config.@'macos-window-mode' (separate|single, already parsed in src/config/Config.zig:3466) once at app start into a win32 WindowMode.current, with a test override; a Settings toggle on the Panes page with the Mac wording and a 'takes effect at next launch' hint. Separate stays byte-for-byte the current behaviour. Child of T3136 (split 2026-11-16). Design (T3136 Details): ONE shared top-level HWND; every workspace keeps its own Window controller; the workspace on show owns the HWND (GWLP_USERDATA, chrome, sidebar), a parked Window has hwnd=null and its pane child HWNDs are reparented (adoptPane-style SetParent, Window.zig:7278) under a hidden park host so they survive the shared HWND closing. Spec: docs/reference/window-modes.md. Acceptance goes in test/win32/single-window-mode.ps1 (one section per child).

## In plain terms

Mac lets you choose between every window being its own window and keeping them all in one window. This piece adds that choice to Windows Settings (Panes & Windows > Windows > "Open windows"), worded as on the Mac, and makes the app read it once when it starts, so a change takes effect the next time Ghoztty opens. Nothing else changes yet: the one-window behaviour itself arrives with T3181.

## Goals

- [x] The app reads `macos-window-mode` once at launch and keeps that answer for the whole run (`src/apprt/win32/window_mode.zig`, latched in `App.init`).
- [x] Settings > Panes & Windows has Mac's "Open windows" row (Each in its own window / All in one window) and says it takes effect the next time Ghoztty starts.
- [x] `separate` (the default) is exactly the current behaviour - nothing reads the latch yet except the Settings seam.

## Validation criteria

- [x] A launch whose config says `single` runs single; a Settings write to `separate` changes the file and the row but NOT the running mode; the next launch runs separate; no line means separate. (Verified: `test\win32\single-window-mode.ps1` section A, 17/17 ALL PASS on the test desktop; `-NegativeControl` fails as designed.)
- [x] The row's label, option labels, hint and placement match Mac's `SettingsPages.swift`. (Verified: section A + the `settings_pages` unit test in the none/win32 lanes.)
- [x] Latch semantics (first latch wins, override beats it, default separate). (Verified: `window_mode.zig` unit tests in every app-runtime lane.)
