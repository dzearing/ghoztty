# T1260 - The private-kill sweep cannot see a kill written as .Kill(), so two harnesses carry one it never reported

## In plain terms

There is one approved way for a test to shut down the terminal it is testing,
and a sweep that is supposed to find every script writing its own. The sweep
only recognises one spelling of "kill". A harness that writes the other spelling
is invisible to it - and two harnesses do exactly that today.

## Goals

- [x] the sweep recognises `.Kill()` and `Get-Process`-family queries
- [x] the throwaway-product kill is reported, then exempted with a stated reason
- [x] `-TeethCheck` plants a `.Kill()` violator and the sweep catches it

## Evidence (2026-09-01, found while working T1209)

`test\win32\lib\CleanSlateAudit.ps1` requires a `Stop-Process` within six
lines of a ghoztty process query (its line 90: `if ($forward -notmatch
'Stop-Process') { continue }`). A private kill written as

```powershell
foreach ($p in @(Get-Process -Name ghoztty ...)) { ... try { $p.Kill() } catch {} }
```

matches nothing, so `cleanslate-audit.ps1` reports `B2 no script carries a
private ghoztty kill (0 files)` while `update-real-msi.ps1` and
`update-graceful.ps1` both carry one.

Both are legitimate - `Stop-RepoGhoztty` REFUSES an exe outside the repo, and
the exe these two drive arrived through a real installer, so it is outside by
construction. That is what the stated-intent `# cleanslate-exempt: <reason>`
marker is for. The defect is that the sweep could not have told the difference:
an exemption nobody had to declare is not an exemption.

## What to do

- Widen the detector to `.Kill()` on a process object derived from a ghoztty
  query, the same way it already follows a pipeline into `Stop-Process`.
- Then declare the two throwaway-product harnesses with a real reason, or move
  their kill behind a named helper the sweep recognises as shared
  (`Stop-ThrowawayInstances` in `test\win32\lib\ThrowawayProduct.ps1` already
  is that helper - it just is not on the sweep's list of shared names).
- `-TeethCheck` must plant a `.Kill()` violator and require the sweep to find it,
  or this fix is the same shape as the hole it closes.

## Validation criteria

- [x] `cleanslate-audit.ps1 -TeethCheck` finds a planted `.Kill()` violator.
      (B6 PASS, 38 assertions, 2026-10-23.)
- [x] The sweep reports the two throwaway-product harnesses, and they are either
      exempted with a stated reason or converted. (Both harnesses had already

      then reported that helper's own kill at `ThrowawayProduct.ps1:230`, which

- [x] `cleanslate-audit.ps1` exits 0 afterwards. (ALL PASS, 36 assertions,
      guard stamped; update-real-msi + update-graceful re-run green after the
      lib edit.)
