# T1518 - agent-upgrade's N3 waits 60s for the mandatory-update dialog and misses it on a loaded box

## In plain terms

One of our long test runs asks the app to show its "you must update" question
and waits a minute for it to appear. On a busy machine it sometimes takes
longer than that, so the test reports a failure about a feature that works
fine. The next person then has to run the whole thing again - about six
minutes - to find out whether anything was actually broken.

## Summary

`test\win32\agent-upgrade.ps1` arm N (T625's negative control) launches the app
with a protocol skew and calls `Wait-Dialog $appPidN 60`. On 2026-09-13 during
T1511's batch 10 that call timed out and the run ended `1 FAILURE(S) (136
assertions passed)`; an immediate re-run of the same bytes was `ALL PASS (139
assertions)`. Nothing in the code under test changed between the two runs - the
turn's edits were scoring-only.

Arm N is the *last* of a long sequence of arms, so the box is at its busiest by
the time it runs, and its own setup starts a fresh app plus a fresh agent. The
60-second budget is the only thing between "the dialog is genuinely conditional
on notes" (the defect this control exists to catch) and "the launch was slow".

Every other arm that waits on the same dialog uses the same 60. The fix is not
simply a bigger number: a wait that ends in a timeout should be able to say
whether the app ever got as far as deciding, which the app log already records
(`Wait-LogMatch` on the skew decision is what arms J and K use). A control that
fails should distinguish "no dialog was raised" from "the app never reached the
decision".

## Validation criteria

- [ ] Arm N's failure names WHICH of the two it saw: the app never reached the
      update decision, or it reached it and raised no dialog.
- [ ] `test\win32\agent-upgrade.ps1` runs green three times back to back on this
      box with a floor lane running alongside (the load shape that produced the
      miss).
- [ ] The negative control still has teeth: with the dialog suppressed, N3 goes
      red rather than being waited away.
