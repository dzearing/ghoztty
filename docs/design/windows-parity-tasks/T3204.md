# T3204 - Single-window mode: run session-blades.ps1 A/E under macos-window-mode=single - a switch back to a workspace with a collapsed row never replays its blades (Mac switchingBackDoesNotReplayTheStack)

## Summary

T3194 put the caret on caretPaneOnShow before the adopt turn's first layout (Window.adoptWindow, logged 'workspace adopt caret ... moved_off_strip='). single-window-mode.ps1 G2 proves the ordering and a plain caret, but nothing yet drives a workspace whose focused pane is a strip of a collapsed row through a hand-off. Extend test/win32/session-blades.ps1 A/E (or add a section to single-window-mode.ps1) that collapses a row in a workspace, parks it, shows it again, and asserts moved_off_strip=true and no blade slide-out/in (stack slide log) on the switch back.

## In plain terms

In single-window mode, a workspace that has panes folded into blades must
come back exactly as you left it when you switch away and back: the same
pane on show and no fold animation replaying. The code for this landed
with T3194, but no test covered it. This adds the test.

## Goals

- [x] A test drives a single-window workspace with a folded row through a switch away and back
- [x] It watches the shared window the whole way and fails if a blade slides out or a glide runs
- [x] The negative control shows the new checks can go red

## Validation criteria

- [x] With the history naming the blade s3 first, the workspace restores in single mode with s1 alone on show and three blades: `session-blades.ps1` F setup, 6 assertions, ALL PASS (67).
- [x] A switch to a second workspace and back keeps s1 the only pane on show in every sample (52 samples over 1.5 s, max 1, 0 stray): `session-blades.ps1` F.
- [x] The app log shows the adopt turn's caret line and no `stack glide landing timer` or `stacked pane brought on show by focus` line after the switch: `session-blades.ps1` F.
- [x] After the second workspace is closed in place, `+list` reads the row as before (4 panes, 3 blades, s1 holds the caret): `session-blades.ps1` F.
- [x] `-NegativeControl` (collapse left out) fails 21 assertions, including F's sampling check (max 4 on show, 153 stray sightings): the oracle can go red.
- [x] Scoped harness floor PASS (345 s) and `unwired-hook-audit.ps1` ALL PASS after the script edit.

## Outcome

Section F of `test/win32/session-blades.ps1` (no product change). The
summary asked for `moved_off_strip=true`. On every scripted path the restore
has already moved the tab's focused pane off the blade (claim D), so the
adopt turn logs `moved_off_strip=false`. The section asserts the
user-visible outcome the Mac test asserts (no replay, same panes on show),
and only requires that the caret line was logged.
