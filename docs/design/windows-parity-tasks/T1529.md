# T1529 - Split-tree rearrange: move and swap panes while keeping pane identity

## In plain terms

Rearrange mode lets you pick a pane up and put it somewhere else. This is the
part that actually moves it: the pane lands where you dropped it, the panes it
left behind close the gap, and — the part you would notice instantly if it were
wrong — the pane you moved is still the same one. Its command is still running,
its scrollback is still there, the page a viewer was showing is still on screen.
A move that quietly rebuilt the pane would look like the terminal restarting
every time you dragged it.

## Summary

The tree-mutation half of rearrange mode: remove a leaf and insert it beside another leaf on a given side, and exchange two leaves in place, both within one window's split tree and across two trees. Panes keep their process, scrollback and session - every mutation rebuilds out of the EXISTING pane instances, the identity-preserving rule +rearrange already follows. Mac covers this with SplitTreeRearrangeTests.

## Goals

- [x] A leaf can be moved beside another leaf in the same tree, on any side.
- [x] The split a moved pane left behind collapses into its sibling.
- [x] A leaf can be moved into ANOTHER tree, and a source holding only that leaf comes back empty.
- [x] Two leaves can be exchanged in place, within one tree and across two.
- [x] A top-level insert spans the whole side of the window rather than nesting.
- [x] Every mutation carries the same view pointer through, at a balanced reference count.

## Validation criteria

- [x] Unit tests in the `none` lane cover each mutation: the four top-level sides, the wrap-vs-nest distinction, the empty-tree edges, zoom clearing, the move and the collapse it causes, the cross-tree move including the emptied source, and both swaps. 13 tests, all green under `zig build test -Dapp-runtime=none -Dtest-filter=T1529`.
- [x] A test view whose `ref` returns itself (as `PaneView` does) proves pane identity survives a move and a cross-tree move/swap, with reference counts landing back at one per live tree. Asserted in the two `IdentityTree` tests in `src/datastruct/split_tree.zig`.
- [x] Both zig test lanes, `test-agent` and the `lib` build stay green. `scripts/floor-lane.ps1 -Lane all`: lib PASS, none PASS, win32 PASS, agent PASS.
