# T3349 - commit guard: a rejected push cannot rebase while the task's tracker edits are still dirty, so the work commit stays unpushed and set-status records a sha the rebase then discards

## Summary

Seen in lane l on 2026-11-21 (T3329). go.md step 6 commits the work, then runs set-status (which edits the task file), then commits the tracker. When the branch has moved, the guard's retry of the FIRST push runs git pull --rebase and fails with 'cannot pull with rebase: You have unstaged changes' (exit 6), because the task file the claim already edited is dirty. The turn then passes the pre-rebase sha to set-status. The tracker commit's push does rebase, and that rewrites the work commit (97b0abc52 became a8aa4f0d0), so the task records a sha that is on no branch. Fix candidates: git pull --rebase --autostash in the guard's retry, and/or have the guard print the post-rebase sha of every rewritten commit so set-status gets the right one. Acceptance belongs in section W of test/win32/go-loop-guard.ps1.
