# T1591 - title-font.ps1 cannot catch a tab bar that never asks to be repainted

## Summary

T765's sweep of assertions leaning on the capture's own repaint. title-font.ps1 asserts 'config reload re-fonts the tab bar live' from a PrintWindow raster diff, and a PrintWindow repaints the whole client from current state - so the assertion passes with Window.invalidateTabBar deleted, because the probe invalidates for it. The font half has teeth (createTabFont really did run); the LIVE half does not, and a user on a real desktop would see the old raster until something else dirtied the strip. Give it the T252/T765 second oracle - a debug log line from invalidateTabBar, scored the way split-divider.ps1 scores the divider band count - and teeth-check it by compiling the invalidate out.

## In plain terms

When you change the tab title font in your config and reload, the tab bar should switch fonts immediately. The test for that could not tell the difference between "the app redrew the tab bar" and "the test's own screenshot redrew it", so a build that forgot to redraw would still pass. Now the app reports whether the reload asked for the tab bar to be redrawn, and the test checks that report.

## Goals

- [x] The reload reports how many times it asked the tab bar to repaint (debug builds)
- [x] title-font.ps1 fails when that repaint request is removed, even though its screenshot check still passes
- [x] title-font.ps1 stops flaking on the strip's leading slot (filed separately as T3293)

## Resolution

- **Oracle**: `Window.onConfigChange` now logs `config reload tab bar repaints asked=<n> visible=<bool>` (debug builds), the delta of a new `tab_bar_invalidations` counter that `invalidateTabBar` bumps whenever it invalidates a non-empty strip. title-font.ps1 reads it after the reload chord: `visible=true` is the in-band control, `asked>0` is the assertion.
- **Why not the update region** (tried first): the existing T765 line `config reload left update region` reports the whole client (0,0,982,741) for this reload with or without the strip's invalidate. The default `elevated` pane style repaints the desk on every reload, and that rect touches the strip. So the region check had no teeth, and the counter replaced it.
- **Raster flake fixed**: in about two of three launches the strip's leading slot (x < ~54 DIP) flips mid-launch between an empty dark square and a light panel with an icon and title text. The old signature sampled it, which scored ~1000-column diffs between two launches of one font (`reloaded Segoe UI matches the default raster` went red 2 of 3 runs). The sample now starts past the slot. The panel itself is filed as T3293.

## Validation criteria

- [x] Teeth: built with `onConfigChange`'s `invalidateTabBar()` commented out (`--prefix zig-out-t1591`). title-font.ps1 went red on `the reload itself asked for the tab bar repaint (invalidateTabBar x0)`, while `config reload re-fonts the tab bar live` still PASSED. That proves the gap and that the new oracle closes it
- [x] Real build: title-font.ps1 ALL PASS (14 assertions) on 3 consecutive runs, `invalidateTabBar x1`. It also passed through `acceptance-parallel.ps1 run`
- [x] `-NegativeControl` still fails (`diff A-vs-B=332`)
- [x] `floor-lane.ps1 -Lane all`: ALL LANES PASS (lib, none, win32, agent)
