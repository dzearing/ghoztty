# T1582 - Fork CI goes red whenever gitlab.gnome.org hiccups, because the msitools build clones it with no retry

## Summary

windows-cross builds msitools 0.106 from source by cloning https://gitlab.gnome.org/GNOME/msitools.git. On 2026-09-15 that host answered 503 and the whole job failed with exit 128, which turned the branch head red and blocked the next turn's validate gate on a defect that is not in our code. The clone is a single unguarded network call to a host we do not run. Wanted: a retry with backoff at minimum, and better a cached or mirrored source (a pinned tarball from a release asset, or the ubuntu package where the version allows) so a third party's bad minute cannot stop the loop. The same shape applies to any other from-source dependency the workflow clones.
