# T1793 - A pane that is attached when its holder dies closes like a normal shell exit, with no interrupted notice

## Summary

T1771 fixed the UNBOUND shape: a `--pty-host` holder that dies while no pane is
attached now leaves a relaunchable tombstone (`Session.markLost`), so the pane
that re-attaches says "Session interrupted" and names the command it did not
re-run. It deliberately left the BOUND shape alone: when a pane is attached at
the moment its holder dies, `SessionStore.onChildOutput` still calls
`markExited` and sends EXIT, and the app's `Surface.childExited` treats that
like the shell typing `exit` - the pane closes (or shows "Process exited" under
`wait-after-command`). By code reading, not yet measured on box.

The agent already knows the difference (`Child.wasLost()`, T1771). What is
missing is a way to tell the ATTACHED pane: e.g. an additive flag on the EXIT
frame (capability-gated, per the app<->agent compatibility rule in
`docs/claude/sessions.md`), which the app turns into the same notice + a fresh
shell in the same pane instead of a close. Holders are Windows-only today, so
the Mac seat owes nothing unless it grows holders.

## In plain terms

If the helper process behind a terminal you are looking at is killed, the
terminal just closes, as if your program had finished normally. It should stay
open, say your session was interrupted, and give you a fresh prompt.

## Goals

- [x] The pane stays open when its host dies, on the same session
- [x] It says "Session interrupted" (banner + scrollback), naming the command
- [x] What the program printed stays readable above the notice
- [x] A fresh shell, never a re-run of the command
- [x] Older agents and older apps keep today's behavior

## Design (2026-10-11)

New HELLO capability `holder_lost`. Agent: a bound session whose holder died,
bound by a peer that negotiated it, is `markLost` (no ring divider) and its
viewer gets `EXIT{lost: true, command}`; otherwise unchanged. App: the drain
treats a lost exit as a respawn, not a close - it copies a full-screen frame off
the alternate screen, undoes the dead program's modes, paints the notice + banner
(new `session_notice.Reason.host_lost`) for `restore`, a divider for `rerun`, the
press-a-key prompt for `prompt`, then RELAUNCHes in place with two new additive
fields, `fresh_shell` (never the recorded command) and `replay_from` (its own
stream position, so nothing is replayed twice). A respawn that fails falls back
to the old close.
