# T2409 - Double-clicking a grip between two stacked pane cards on Windows evens out the run on show, as double-clicking a split divider evens its splits (Mac 7e2d0a9da)

## Summary

Mac main 7e2d0a9da: double-clicking a grip between two cards in a pane stack evens out the run (TerminalSplitOperation.evenRun): the row's ratios when all of it is on show, else the run's shares (PaneStackState.show). Before, the second click began a drag. A grip where the run meets its strips has no double-click. Windows: add the same double-click to the win32 pane-stack grip (and make sure the second click does not start a drag); acceptance in the pane-stack scripts. Ref docs/reference/stacked-panes.md on main (doubleClickingAGripBetweenCardsEvensTheRun).

## In plain terms

With some panes folded away into blades at the edge of the window, the gaps
between the cards still on show could be dragged but not double-clicked:
double-clicking one did nothing, so the cards stayed uneven. Now a
double-click on any gap between two cards makes them all the same width,
just as double-clicking an ordinary divider does, and the folded blades stay
where they are.

## Goals

- [x] double-clicking a grip between two stacked cards evens out the cards on show
- [x] folded blades keep their strips; a grip where the run meets its strips does nothing on double-click
- [x] the second click of the double-click never starts a drag

## Validation criteria

- [x] the user's shape - three uneven cards and two folded blades - each card-to-card grip double-clicked leaves the cards equal within 1 px (549/549/550), blades unchanged (run edge at 1768 before and after), and moving the pointer afterwards changes nothing: section G of `test\win32\stack-collapse-drag.ps1`, ALL PASS (25) via `acceptance-parallel.ps1 run`; `-NegativeControl` (no double-click) fails G0/G1
