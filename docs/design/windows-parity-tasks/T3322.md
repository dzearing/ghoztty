# T3322 - An acceptance harness run by hand from lane B dials lane A's debug agent: both lanes' debug builds share one agent pipe, so the fixture's sessions land in the other lane's agent and the run goes red

## Summary

Found on T1635, 2026-11-21 (lane b). Running `test\win32\chooser-orphan-badge.ps1`
and `chooser-resume-remote.ps1` directly with `powershell -File` (with `-Exe`
pointing at `D:\git\ghoztty-b\zig-out`, which T1996 requires) went red in all
three rounds: `the agent owns the app's panes (found 0)`, `SETUP FAIL: direct
OPEN left no orphan`, and `the fixture windows produced no new agent sessions`.
The app's stderr said `local agent did not become dialable within 2000ms` and
`window opened without session persistence`. At the same moment
`\\.\pipe\ghoztty-agent-debug-David` was answered by **lane A's** agents:
three `D:\git\ghoztty\zig-out\bin\ghoztty-agent.exe` processes, with no
lane-B agent running. `+sessions --json` from the lane-B exe listed sessions
whose cwd was `D:\git\ghoztty\`.

The cause: a debug build derives its agent pipe, guard mutex and state dir from
the build mode plus `GHOZTTY_AGENT_INSTANCE`, and nothing sets that instance
from the loop lane. Each lane's `Stop-RepoGhoztty` is path-exact, so it cannot
clear the other lane's agent, and lane B's freshly spawned agent cannot take an
endpoint that lane A's agent already holds. The runner
(`scripts\acceptance-parallel.ps1`, any width) is unaffected: it mints
`GHOZTTY_AGENT_INSTANCE` per run (`scripts\lib\AcceptanceParallel.ps1:461/494`).
Run that way, the same pair was green 4 of 4 rounds. A hand-run harness, the
shape docs and task files hand out all the time, gets no isolation and no
refusal. The direct-OPEN fixture also leaves a held session in lane A's agent.

Fix shape (your call): when `scripts\lib\LoopLane.ps1` says the lane is not `a`
and `GHOZTTY_AGENT_INSTANCE` is unset, the shared harness libraries
(`BuildMode.ps1` / `CleanSlate.ps1`) either set a lane-qualified instance plus
`GHOZTTY_PIPE_SUFFIX` themselves, or refuse the way T1996 refuses a
foreign-checkout exe, naming the runner command. Prefer auto-isolation, so a
hand run just works.

## Validation criteria

- [ ] From lane B, a hand-run `powershell -File test\win32\chooser-orphan-badge.ps1 -Exe <lane-b exe> -ClientExe <lane-b client>` while a lane-A debug agent is alive either passes (auto-isolated) or refuses before launching anything, naming the runner command.
- [ ] A lane-A hand run is unchanged (historical names kept).
- [ ] A negative control: with the new isolation turned off, the same run reproduces the `found 0` red.
