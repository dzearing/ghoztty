# T3879 - Linux: Settings' folder row shows a path as ~ only when it is really under HOME - settings_controls.folderLabel matches the home prefix case-insensitively, which is right for Windows and wrong for Linux paths

## Summary

settings_controls.folderLabel (shared with win32) uses std.ascii.eqlIgnoreCase for the home prefix, so on Linux /ROOT/x (a different folder from /root/x) would read as ~/x. Make the comparison case-sensitive off Windows (builtin.os.tag), keep it case-insensitive on Windows, and add a none-lane unit test for both. Found in T3759.
