# T1535 - remote-disconnect claim F is red: a command typed into a LOCAL pane leaves no child process

## Summary

test\win32\remote-disconnect.ps1 section F fails at setup: it types 'ping -n 100 127.0.0.1' into a local pane and then finds ZERO descendants of the pane's shell within 12s, so the busy-pane confirmation it exists to check is never reached. Reproduced at HEAD (4aa32f447) with T1531's changes stashed, so it is NOT T1531's - three consecutive runs, same claim, same shape. The app's own stderr shows the title going to 'cmd.exe - PING  -N 100 127.0.0.1' and straight back to 'cmd.exe', i.e. the command starts and ends immediately, which is either the child dying early inside the ConPTY or the typed line arriving mangled. Either one is a real defect: a pane whose child exits the instant it starts is far worse than a red test. Start by reading the pane with '+read --name' after typing, and compare against a pane on the interactive desktop - a probe on the background test desktop saw the text never reach the shell at all, so the two halves may be different bugs. Claims A-E of the same script pass, so the disconnect/close/cancel offer itself is intact.
