# T1535 - remote-disconnect claim F is red: a command typed into a LOCAL pane leaves no child process

## Summary

test\win32\remote-disconnect.ps1 section F failed at setup: it types
`ping -n 100 127.0.0.1` into a local pane and then found ZERO descendants of
the pane's shell within 12s, so the busy-pane confirmation it exists to check
was never reached.

**Root cause: the test harness, not the product.** The app reads modifiers with
`GetKeyState`, which answers from the input queue the harness attaches to. That
queue starts life holding whatever was physically down when the app's UI thread
was created, and POSTED messages never update it - so a latch at launch is a
latch for the process's whole life. `Send-TestText` / `SendChord` built their
key state ON TOP of `GetKeyboardState`, i.e. on top of that ambient state.

Measured on box while nobody was at the keyboard: left shift read down in **17
of 60** samples, and caps lock was latched on. `+read` on the pane showed what
the shell actually received - `PING -N 100 127.0.0.1`. `ping` rejects the
uppercase `-N`, prints its usage and exits in milliseconds, which is why the
shell had no descendants. Earlier, with shift also stuck, the same typing was
eaten as chords entirely (`toggle_command_palette`, `new_window`,
`decrease_font_size`, `goto_tab`), and the pane showed `.ahy^G`.

The fix is in `test\win32\lib\TestDesktop.ps1`: `ClearMods()` releases every
modifier and clears the caps-lock toggle before every posted send - text,
chords, control keys and mouse - so the harness delivers the input it names
whatever the box's latches say. `SendText`'s per-character loop was factored
into `TypeInto` so the regression fixture drives the real path.

## In plain terms

The automated tests type into the terminal by posting keystrokes. If a shift
key happened to be held, or caps lock was on, the app believed that modifier was
held for its entire life - so the tests typed something other than what they
said, and one of them reported a broken terminal that was never broken. The
tests now release every modifier before each keystroke, and there is a new check
that deliberately jams shift and caps lock on and proves the typing still comes
out literal.
