# T3173 - perf-baseline's viewer phase does not measure a restored background-tab viewer, so T3036's renderer saving has no number

## Summary

T3036 stopped viewers restored into background tabs from starting their web view until first shown. Its acceptance (`test/win32/viewer-restore.ps1` section K) proves no page is fetched, but nothing measures what that saves: `scripts/perf-baseline.ps1`'s viewer phase (T3033, PA-V01) opens its viewers live and never restores a window. Add a restore arm to the viewer phase - write a window with viewer tabs behind the active one into the session manifest (section K's injection shape), relaunch, and record the count of `msedgewebview2.exe --type=renderer` processes under the app and the app's private bytes - so the baseline carries a number for the renderer-count criterion T3036 named (renderer count equals the number of viewers ever shown).

## Validation criteria

- [ ] perf-baseline viewer phase reports a restored-background-tab arm: renderer count equals viewers ever shown, before and after revealing one tab
- [ ] the arm goes red on a build that starts every restored viewer eagerly (negative control)
