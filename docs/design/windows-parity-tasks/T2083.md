# T2083 - Stacked panes: a collapsed row keeps its strips minimized when a pane in it closes, is stashed, moves away, or a split adds one

## In plain terms

When a row is folded into strips, closing, stashing or moving one of its
panes, or adding a split to it, must keep the row folded. Before these Mac
fixes, the row sprang back open and every strip came out.

## Summary

- Mac 3090ac2aa (`fix(macos): closing a pane in a collapsed row keeps its
  strips minimized`): a row's collapse ("pin") is keyed by its set of
  panes, so a pane leaving the row made the lookup miss. Fix:
  `PaneStackState.rowsDidChange` carries the pin over to the row's smaller
  key on every tree change (`Pin.removing`). The panes on show close up
  over the slot, strips stay on their sides, and slot sizes are kept. If
  the only pane on show closes, the strip before it comes out. The old pin
  is kept, so an undo or a restored stash brings the row back as it was.
  After a close the caret lands on a pane that is on show.
- Mac d26e51183 (`fix(macos): adding a pane to a collapsed row keeps its
  strips minimized`): the carry-over generalised to `Pin.carrying`, which
  covers panes that are gone, joined, or moved within the row. A pane that
  joins beside or inside the run is on show; one that joins among the
  strips stays a strip until focused. Reorders are measured from the
  laid-out order. Focus arriving before or after the tree change gives the
  same row.

Windows translation: the same pin-carrying rule in T2082's stack state
(pure, unit-tested), applied on every SplitTree mutation (close, stash,
`+rearrange`, a drag to another window or tab, split, undo).

## Goals

- [x] A collapse is carried over every tree change: a pane leaving the row
      (close, stash, move away), joining it (split, drop, restore), or moving
      within it keeps the strips minimized.
- [x] After a close the caret lands on a pane on show, never on a strip.
- [x] Mac's final rules from 2811a3043 come with it (a column emptied into
      its row keeps its place; rows off screen keep no stale collapse), so
      T2084 does not rewrite this.
- [ ] On-box proof: T2119, once T2084 gives Windows a collapse gesture.

## What landed

- `pane_stack_state.zig`: `rowsDidChange`, `paneOnShow`, `noteRows` (the
  Windows bridge: remembers the rows it last saw and diffs), plus
  `carriedRows` / `originOf` / `carriedShares` / `intersecting` - Mac's
  `carried`, `origin`, the shares closure and `intersecting`, line for line.
  One state serves the whole window here (Mac: one per window = one tab), so
  the rows handed in are every tab's, which keeps "rows off screen keep
  nothing" from wiping a background tab's collapse.
- `pane_stack_grid.appendRows`: a tab's tree -> its rows (stash-aware).
- `Window.zig`: `stackGridOf` calls `noteStackRows` before every layout, so
  every one of the ~15 places that replaces a tab's tree is covered without
  touching any of them; `closeSplitPane` routes the next-focus candidate
  through `paneOnShowAfter`.
- Mechanism choice (mine, not a decision: invisible to the user): diffing at
  layout time instead of calling from each mutation site. Every mutation is
  followed by `layoutSplits` synchronously, and a focus landing before the
  diff is handled by `rowsDidChange`'s own `bringOnShow` (Mac's
  "focus before or after gives the same row").
