# T3052 - PA-V20: pictures pasted into a feedback report stay in memory after their chip is deleted, and Send copies every picture again (viewer_feedback_images.zig:113)

## Summary

PA-V20 (audit-1, T2963). The image store has add but no remove (viewer_feedback_images.zig:113-130; caps 32 MB per image, 64 MB per pane at :55-56); a deleted chip's PNG stays until a successful send (ViewerPane.zig:1751) or pane close (:1015), across composer close/reopen; Send dupes every live PNG into the job arena (ViewerFeedbackSend.zig:259-267). Cost: up to 64 MB held per pane, 64 MB more transient on send. Fix: prune entries neither the text nor the undo journal references on composer close; lend the bytes to the worker. Risk: undo must still restore a chip's picture. Findings: docs/design/perf-audit/audit-1/V-findings.md.

## Validation criteria

- [ ] unit test: pruning keeps journal-referenced images (none lane)
- [ ] app private bytes after deleting a 10 MB chip and closing the composer drop by ~10 MB
