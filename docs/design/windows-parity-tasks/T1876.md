# T1876 - The desktop-launch audit does not see a splatted Start-Process (Start-Process @a with FilePath=$Exe): layout-blob-cross-lineage.ps1 starts its app on the user's desktop that way

## Summary

Found in T1860: layout-blob-cross-lineage.ps1's Start-App builds a hashtable (FilePath = $Exe, ArgumentList = --title=...) and runs Start-Process @a, a bare launch on the caller's desktop that DesktopLaunchAudit.ps1 cannot see because the exe is inside the splatted hashtable, not on the command line. T1860 caught the same script only through its Run-Cli +new-window and declared it '(T-this) pending migration'. This task: teach the audit the splat shape (resolve @name to a hashtable literal assigned in the same scope, read its FilePath/ArgumentList keys), sweep test\win32 for other hits, migrate layout-blob-cross-lineage.ps1 onto Start-OnTestDesktop/Invoke-OnTestDesktop (keeping its stderr log), delete its declaration, and plant a splatted violator in desktop-launch-audit.ps1 -TeethCheck.

## In plain terms

One of the automated tests opened a Ghoztty window on your screen every time it ran, and the check that is supposed to catch exactly that could not see it, because the test wrote its launch in a form the check never read. Now the check reads that form, and the test runs its windows on a hidden desktop like the rest.
