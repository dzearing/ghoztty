# T3206 - Single-window mode: Restore All switches the window to each workspace it rebuilds in turn instead of parking them behind the frontmost

## Summary

Found in T3187. `App.adoptRestoreAllLocal` / `adoptRestoreAll` build the restored windows in `frontmostLastOrder` and each with `background = false`, so in single-window mode every rebuilt workspace goes on show in turn (one hand-off and desk fade per window) before the frontmost, built last, ends on show. The end state is correct; the path there is a cascade of switches. Fix: in single mode build them parked (`restoreWindowShown(..., background = true)`, as `App.restoreParksBehindShown` does for the launch pass) and show the frontmost one once at the end (`showWorkspace`). Validation: a section in `test/win32/single-window-mode.ps1` that runs Restore All (machine chooser) and counts `workspace adopted the window` log lines - exactly one.

## Validation criteria

- [ ] Restore All in single mode: every rebuilt workspace is present, the frontmost on show, and exactly one hand-off logged
