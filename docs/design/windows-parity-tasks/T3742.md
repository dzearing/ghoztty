# T3742 - A wsl pane's prompt reflows late on a window resize: Ghoztty injects no prompt marks into wsl bash, so every resize takes the debounce that cmd and PowerShell panes no longer wait out

## Summary

Measured by prompt-reflow.ps1 -Wsl (T2259) on Ubuntu, three runs: a window-edge storm over an idle bash prompt decided all 57 resizes 'debounce' (0 live, 0 held, 0 redraw releases) and applied only 7-8 of them, where cmd and PowerShell panes are paced live. Cause: shell_integration.zig lists wsl in bare_shells_without_integration, so no OSC 133 marks reach the pane and Termio.resizePace never sees a prompt. Mac's local bash/zsh get integration injected, so the gap the user sees is a WSL prompt that redraws late on resize. Fix direction: carry Ghostty's bash integration into the wsl shell (resources dir through WSLENV plus an rcfile/ENV hook on the Linux side), with the same opt-out as the other shells. Done when prompt-reflow.ps1 -Wsl section E is ALL PASS.
