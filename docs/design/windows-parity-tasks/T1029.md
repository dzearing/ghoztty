# T1029 - Two acceptance scripts launch the repo build with no pre-flight at all, so neither the build-mode nor the staleness gate can speak

## Summary

test\win32\agent-pipe.ps1 and test\win32\test-desktop-spike.ps1 launch exes out of the repo's zig-out but never reach Assert-GhozttyIsolatedBuild - they dot-source neither BuildMode, CleanSlate, Isolation nor TestDesktop. Measured while landing T1028 (a text scan over the suite: 170 scripts drive the CLI, 9 never reach the pre-flight, and 7 of those only MENTION a verb in prose or play a fixture server). So both the endpoint-isolation refusal (T350) and the staleness refusal (T1028) are silent for them: they will happily grade a release-lineage build in the user's terminal, or a zig-out exe built before the code under test. The fix is one dot-source and one call each - but the durable half is the meta-check, the shape isolation-meta.ps1 already uses for its own property: a script that LAUNCHES an exe under zig-out must reach the pre-flight, proved by a sweep rather than by a list somebody keeps up to date. Note the harder half: 'launches an exe' has to be read off the AST (a Start-Process / call operator on a path under zig-out), because a text match on a +verb finds seven scripts that only talk about them.

## In plain terms

Before a test drives the Windows app, it checks two things: that the app it is
about to start is a private test build rather than the one the user is sitting
in front of, and that it was built from the code being tested. Two of the test
scripts skip both checks entirely, so they could quietly open windows in the
user's own terminal, or grade an out-of-date app, and nothing would say a word.

## Goals

- [x] Both scripts reach the pre-flight before they start anything (plus a third, upgrade-no-fork.ps1, that the new sweep found)
- [x] The property is CHECKED by a sweep, not kept in a list
- [x] The sweep proves it still bites, on a synthetic violator
