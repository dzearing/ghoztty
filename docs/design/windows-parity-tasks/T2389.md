## In plain terms

The frame lab needs a script of what to do to the window - drag this edge
back and forth, double-click the title bar, drag a divider - and a fixed
order for each test so its numbers mean something. This card writes that
script and that order, and proves them without touching the screen or the
mouse; the next cards plug in the real window, camera and mouse.

## What landed

`test\win32\lib\FrameLabCatalogue.ps1`:

- `Get-FrameLabInteractions` - all 13 interactions T2373 names; seven are
  pointer gestures, six are triggers that name T2391 as their driver.
- `Get-FrameLabGesture` - a GliSample path per pointer gesture from the
  scene's physical-pixel geometry: frame right/bottom/corner (grabbed 3 px
  inside the resize zone), divider (moves into the bigger side), sidebar edge,
  caption double-click (maximize + restore, bleed only), aero snap (drag to
  the work area's left edge and back). Edge gestures are even-legged shuttles,
  so they end where they started and the accounting run replays the same
  geometry; it returns the tracked edge, the grab offset, the motion window
  and a capture rect covering the gesture's reach, clipped to the monitor.
- `Get-FrameLabMatrix` - interaction x panes 1/4/9 x theme x DPI 100/150/200 x
  sidebar x stall 0/50/500: 2916 cells with stable ids. What cannot apply is
  pruned (a divider with one pane); what cannot RUN yet is listed and Blocked
  with the reason (triggers -> T2391; stalled cells -> the T2360 knob, which
  does not exist yet).
- `Invoke-FrameLabCell` - the T2384 23:50 protocol: presence first, a
  capture-only measurement run, Superseded frames dropped before scoring, a
  separate -Duplication accounting run of the identical path, the scene
  closed in a finally, SlotGaps beside the verdict.
- `Resolve-FrameLabCellVerdict` - skipped / aborted / fail / incomplete /
  pass; a clean cell with missing or frame-skipping accounting is
  `incomplete`, and a fail outranks that.

Design call (mechanism, not experience): the live pieces come in through a
`-Driver` hashtable of scriptblocks, so the protocol is one function proved
with fakes and the live driver (T2392) cannot reorder it.
