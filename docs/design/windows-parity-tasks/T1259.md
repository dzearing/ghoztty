# T1259 - The asserted-nothing sweep is red: one script can score green from an abort branch, and the uncounted-verdict ceiling was passed

## In plain terms

Two of the rules that stop a test run from claiming success it did not earn are
currently being broken, and the sweep that enforces them has been failing
quietly. One script can end a whole run with a green verdict from an early
abort; forty scripts print a final verdict with no count in it, so nothing can
tell a full run from an empty one - and the ceiling that number is only ever
allowed to fall through was passed three ago.

## Evidence (2026-09-01, found while working T1209)

`powershell -NoProfile -File test\win32\asserted-nothing.ps1` exits 1:

```
FAIL C1 no acceptance script can score green having asserted nothing
     soak.ps1:179 early-green - a pass verdict ends the run green before the
     final verdict: 'ALL PASS'
(40 script(s) still print an UNCOUNTED final verdict - T775 converts them)
FAIL C3 the uncounted-final count did not grow past 37
```

The ceiling is documented as a number that may only FALL, and the documented
remedy for exceeding it is to convert scripts, never to raise it
(`docs/claude/testing.md`, T962 - it went 2 over for eight days once already).

## Why nobody noticed

`asserted-nothing` has no row in `scripts\guard-due.ps1`. Same hole as
[[T1258]], found in the same sweep of the same afternoon.

## What to do

- Fix `soak.ps1`'s early-green branch: an abort path scores the run, it does not
  end it green.
- Convert at least three of the forty uncounted verdicts onto
  `Write-TestVerdict` to get back under the ceiling, and then keep going - the
  list is the T775 backlog.
- Give `asserted-nothing` a guard row so the ceiling cannot be passed unseen
  again.
