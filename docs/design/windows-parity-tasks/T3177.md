# T3177 - A relaunch never brings a collapsed row's blade out: restore picks the focused pane before the window shows (Mac dd77885aa focusOnFirstShow)

## Summary

Mac dd77885aa: on relaunch the toolkit focused a pane of its own choosing (the last, a trailing blade; or the first key view) after restore had focused the right one; focusing a blade brings it out and the expanded row was then saved, so collapsed rows came back side by side. Fix: decide the focus target before showing, make it the initial first responder, never place the caret on a blade, and in-place recovery keeps collapses. Windows restores pane_stack (T3126); verify whether WM_SETFOCUS/first-show or the initial focus on a restored win32 window can land on a blade and expand it, in both window modes, and fix to match. Ref: docs/reference/stacked-panes.md, window-modes.md.

## In plain terms

When you fold a row of panes down so only one shows and the rest sit as thin
strips, that fold should survive anything short of you opening it again. On
Windows it already survived a relaunch, but if the background helper that
keeps your shells alive crashed and the window quietly reconnected, the folded
row sprang open side by side. Now it stays folded, with the cursor where it was.
