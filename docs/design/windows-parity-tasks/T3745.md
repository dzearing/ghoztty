# T3745 - A relative XDG_CONFIG_HOME crashes the app at launch: Config.loadFile asserts an absolute path

## Summary

Found by T3734 (a test bug handed the app a garbage XDG_CONFIG_HOME): App.init -> Config.load -> loadDefaultFiles -> loadOptionalFile -> loadFile hits assert(std.fs.path.isAbsolute(path)) at src/config/Config.zig:4163 and the app dies at launch with reachedUnreachable (dump .dumps/ghoztty-20261125-062819-0.dmp). Upstream Ghostty has the same assert, so all three platforms crash on it. A relative or junk XDG_CONFIG_HOME should be ignored with a logged warning (XDG spec: a relative value is invalid and must be ignored) and fall back to the platform default, never kill the process. Fix where the default file paths are derived, add a unit test for a relative value, and a Windows launch test that sets XDG_CONFIG_HOME=relative and asserts a window comes up.

## In plain terms

If your environment set the config-folder variable to a relative folder name
(an unusual but legal-looking setup), Ghoztty crashed before any window
appeared. Now it ignores that value, as the standard says to, logs a warning,
and opens normally using the usual config folder. It applies on Mac, Windows
and Linux alike.
