# T3182 - Single-window mode: switch workspaces from the pane sidebar's all-windows list, goto_window/goto_tab walk them in sidebar order, and a new tab is a new workspace

## Summary

bringForward() for win32 (sidebar row click, --focus, ghoztty://focus, toast click): in single mode puts the workspace on show, else raises the HWND. goto_tab prev/next/last/N and goto_window walk workspaces in the sidebar order; the tab strip is off in single mode and new_tab opens a workspace. On show the focused pane takes the caret in the same turn without replaying the blade stack (Mac 8c6987575); the sidebar catches up on show (parked sidebars never redraw live). Child of T3136 (split 2026-11-16). Design (T3136 Details): ONE shared top-level HWND; every workspace keeps its own Window controller; the workspace on show owns the HWND (GWLP_USERDATA, chrome, sidebar), a parked Window has hwnd=null and its pane child HWNDs are reparented (adoptPane-style SetParent, Window.zig:7278) under a hidden park host so they survive the shared HWND closing. Spec: docs/reference/window-modes.md. Acceptance goes in test/win32/single-window-mode.ps1 (one section per child).
