# T2033 - A task finished in one lane is handed to the other lane before the finish is pushed: the shared claim ledger releases at set-status done, while the other worktree still reads the task as todo (T2012 worked twice, 2026-10-16)

## Summary

Lane B claimed T2012 at 18:04 and ran set-status done at 18:59 in D:\git\ghoztty-b; its commit reached origin at 19:00:31. Lane A ran next -Claim at 18:59 and got NEXT: T2012 - the T1981 ledger had released the claim, and lane A's checkout still said todo. Lane A then re-implemented the same fix for a whole turn and only found out when its push rebased onto B's. Fix: the ledger keeps a done task reserved (status=done-unpushed, with the sha) until the finishing lane's commit is on origin, and next -Claim in any lane skips a task the ledger marks done; prove it in loop-lanes.ps1 with a done-but-unpushed task that the other lane's next must not hand out.

## Validation criteria

- [ ] loop-lanes.ps1: a task marked done in lane B but not yet pushed is NOT handed out by lane A's `next -Claim`.
- [ ] Once B's commit is on origin, the reservation clears and nothing is left stuck.
- [ ] Negative control: with the old release-at-done behaviour the section goes red.
