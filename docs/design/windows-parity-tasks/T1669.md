# T1669 - The guard-due acceptance fixture is polluted by the wildcard audit rows - A2/C6/C10 have been red at HEAD since the sweeping rows landed

## Summary

test\win32\guard-due.ps1 builds a tiny fixture tree shaped like the go-loop row and asserts that nothing else in the real table matches it. The sweeping audit rows (argv-hazard, unroll-count, seam-audit) cover test\win32\*.ps1 / scripts\*.ps1 wildcards, so they match the fixture's deliberately-uncovered probe file scripts\uncovered-by-any-row.ps1 and drag three arms red: A2 (list excludes an uncovered script), C6 (an uncovered file changing does not make the row due) and C10 (a row covering nothing here is N/A, not DUE). Proven pre-existing at HEAD 3afaf4e73 during T884. Fix: scope the fixture arms to the row the fixture is shaped like (the -Json Name filter is already there for C7/C8), or give the fixture a probe filename no wildcard row can match. The gate that proves guard-due works must not be permanently red - that is the exact state it exists to prevent.

## In plain terms

Nothing a user of the terminal sees. We have a self-test for the bookkeeping
that tells us "this test suite has not been run since you changed the code it
covers". That self-test has been failing three of its own checks for a while,
for a reason that has nothing to do with the bookkeeping being wrong — its
pretend mini-project is accidentally matched by three recently added checks
that sweep every script in the repo. A self-test that is always red is a
self-test nobody reads.

## Validation criteria

- [ ] A2, C6 and C10 of `test\win32\guard-due.ps1` pass, and the reason they
      pass is the fixture being scoped to its own row — not a wildcard row
      being narrowed to suit the test.
- [ ] `test\win32\guard-due.ps1` is ALL PASS over an unmodified tree.
- [ ] The wildcard rows (`argv-hazard`, `unroll-count`, `seam-audit`) still
      cover what they covered before: `guard-due.ps1 list` names the same
      file counts for each as it does today.
