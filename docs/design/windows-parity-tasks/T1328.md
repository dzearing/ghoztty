# T1328 - Retire the -Local publish path so a release has exactly one definition

## Summary

T419 chose bash-on-Linux-CI as the one supported way to compile the MSI. daily-publish.ps1 -Local still routes to scripts\publish-windows-release.ps1, which packages inside the msitools-local Docker image, so there are two live definitions of how a Windows release is produced and only one of them ever runs. Either delete the -Local path and publish-windows-release.ps1's packaging half, or reduce it to a documented, guarded developer escape hatch that cannot drift from build-release-artifacts.sh. Whichever way it goes, release-artifacts.ps1 section A's cross-checks (artifact names agree across workflow, shared script and on-box script) must keep holding.

## In plain terms

There were two recipes for building a Windows release: the one the build
server actually uses, and an older one that ran on this PC inside Docker and
had not been used since September. A recipe nobody runs quietly goes stale, and
the day somebody reaches for it, it builds something different from what users
normally get. The old recipe is now gone, so every Windows release is built
the same way, by the build server.
