# T1801 - claude-code-fullscreen on Windows

## Summary

Part of Mac commit 7e78aacf4: a new config, `claude-code-fullscreen =
true|false` (default `true`, documented as "macOS"), sets
`CLAUDE_CODE_NO_FLICKER=1` in local and session-persistence panes unless the
user already chose a renderer: the variable is already set in the
environment, Claude's settings have a `tui` key, or the config has
`env = CLAUDE_CODE_NO_FLICKER=...`. It is never set on cross-machine (remote)
panes. The env is set in shared `src/Surface.zig`.

Windows translation: the same option and the same default, documented for
both platforms. Claude's settings live at `%USERPROFILE%/.claude/settings.json`
(the Mac reads `~/.claude/settings.json`), so check that the path resolution
uses the Windows home. Confirm the env reaches the ConPTY child in local panes
and in agent-hosted persistence panes (on Windows the agent builds the child
environment itself), and that it is not set on remote panes.

## In plain terms

On the Mac, Ghoztty starts Claude Code in its newer full-screen display mode,
which redraws cleanly when you resize a pane and keeps the whole conversation
re-wrapped. Windows now does the same by default, and still respects anyone
who already picked a mode in Claude itself. Before this change, a Windows user
who had picked the classic mode with `/tui` would have had that choice
silently overridden, because Ghoztty looked for Claude's settings in the wrong
folder.

## Goals

- [x] Windows panes (local and session-persistence) get the fullscreen renderer by default
- [x] Claude's settings are found where Claude keeps them on Windows (the profile folder)
- [x] Remote panes are left alone
- [x] Docs say macOS and Windows
