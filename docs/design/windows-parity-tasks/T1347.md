Filed 2026-09-04 during T1343: `test-reach-audit.ps1` went red twice and then
green twice over the same tree, and at the time the sweep kept only the last
line, so nobody knew which assertion had failed. The task asked for the flake

Outcome: **not reproducible; closed on evidence.** The machinery that would
have identified it now exists (T1734, commit 66a0b31d2): a red sweep row names
the failing assertion and keeps the transcript, and the sweep re-runs every red
row alone and labels it `REPRODUCED` or `NOT reproduced`. Over 250 harness-floor
sweeps that ran test-reach-audit between 2026-10-10 and 2026-10-24 (every
`%TEMP%\floor-lane-harness-*.log` still on the box), the audit was red twice and
**both reds reproduced alone**, so both were real and neither was a flake:

- 2026-10-14 22:54: B1/B2, the win32 lane genuinely failed to build that turn.

No red-in-suite / green-alone row occurred. T1734's root cause (Chromium
dropping a repeated click in the T926 viewer test) cannot be the 09-04 flake,
because that test landed on 2026-09-23; the 09-04 cause is unknown and has not
recurred. If it ever does, the sweep's row will name the assertion and say
`NOT reproduced`, which is the information this task lacked.
