# T2618 - Composition step 3d-4: a banner pane's unfocused dim becomes a visual that reaches over the band (drop the T2491 popup exception), now that the banner is a visual

## Summary

T2491 keeps the dim wash a popup on banner panes because a visual under the grid-offset root could not reach the band. With the banner a visual (T2559) a dim layer at (0,-band) sized to the slot can cover both; then seatDimOverBanner/shownDim have nothing to stack. Oracle: comp-present F/J5 with the dim as a visual on a banner pane, no GhozttyDimOverlay popup.

## In plain terms

When you split a window and one pane has a status banner on top, the pane you
are not typing in is greyed out - banner included. That grey layer used to be
a separate floating window laid over the pane, which has to be chased around
every time the pane moves. Now it is drawn as part of the pane itself, the
same way it already was for panes without a banner, so it can never lag or
peek out from behind the pane it belongs to.

## Goals

- [x] An unfocused pane whose banner is drawn inside the pane keeps its dim
      inside the pane too, reaching up over the banner band
- [x] A banner that is still a separate window keeps the old floating dim
- [x] The dim follows the banner whenever the banner switches between the two
