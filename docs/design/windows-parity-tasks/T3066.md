# T3066 - PA-C12: encodeKey re-takes the renderer mutex with a plain lock on every key press and release, giving up the T114 priority handoff during heavy output (Surface.encodeKey)

## Summary

PA-C12 (audit-1, T2964). src/Surface.zig:4304-4307 (Windows-only branch) locks renderer_state.mutex with plain lock() to read modes.win32_input, after src/apprt/win32/Surface.zig:6716-6722 already took the priority lock (T114) for the same event. Under a flood the plain lock waits behind the IO thread on both press and release. Fix: pass the already-read win32_input mode into keyCallback, or use lockPriority. Risk: low. Windows only. Findings: docs/design/perf-audit/audit-1/C-findings.md.

## Validation criteria

- [ ] key-to-PTY-write latency during a 64 MB type measured before and after (GHOZTTY_PERF or a harness)
- [ ] win32 input mode and key harnesses green
