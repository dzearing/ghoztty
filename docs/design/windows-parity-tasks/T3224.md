# T3224 - PA-V12 remainder: a viewer's document read (renderFileContent readFileAlloc) and its resource stat probes (takeIfFile) still run synchronously on the GUI thread - move the document read to a worker_pool job

## Summary

Split from T3044, which removed the double copy (file read straight into the response stream) and cut range chunks to 2 MB. Still synchronous on the UI thread: renderFileContent's readFileAlloc of the whole document (up to 32 MB) plus UTF-8 validate + JS build, and every resource request's statFile probes (takeIfFile, up to 3 per request) and the resource read itself inside WebResourceRequested. A document on a slow/network path stalls every terminal in the process. Fix: read+validate+build the script on a worker_pool job and post the result back (generation-tagged so a newer render wins); for resources, use the WebResourceRequested deferral and answer from a worker. Risk: ordering against the reload debounce (T391/T3037). Validation: latency probe typing in a terminal pane while a viewer opens a document on a throttled path.
