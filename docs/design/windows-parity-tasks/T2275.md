# T2275 - Windows pane sidebar rows cannot be dragged to reorder: Mac keeps its own per-window sidebar order, reorders by drag in both modes with rows sliding live, and a row drag never moves the pane out of the window (Mac e77422577, 543489bca, 0a547522d)

## Summary

Mac e77422577: drag to reorder in rail and expanded mode; a new drop target (sidebarOrder) in the same resolver. The list has its own per-window order (PaneSidebarOrder): the grid never changes, new panes go beside their tree neighbour, stashed panes keep their place, the order persists by pane id across restore. Rows slide live to make room (bounded animation). 543489bca: the dragged row IS the row, following the pointer vertically only, lifted over a solid backing, gliding to where it lands; drop geometry read outside each row's slide offset so the index does not chase the sliding rows. 0a547522d: a row's drag is a LIST drag - the pointer is clamped to its own sidebar before resolving, so a release over the grid or outside the window lands the row level with the pointer instead of moving the pane (Mac used to make a new window). Windows today: pane_sidebar drag moves panes (T1830/T1879 territory) and has no list order of its own.
