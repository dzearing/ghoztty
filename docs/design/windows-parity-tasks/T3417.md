# T3417 - Linux L9h: git diff viewer panes (git-status:, git-diff:<revspec>)

## Summary

Port the git diff panes of docs/reference/viewer-image-and-diff.md: spec parsing, run against --working-directory repo, the diff template (src/viewer/diff.js/diff.css), file tree side panel and filter, chunked append. Reuse the win32 pure diff logic (viewer_diff.zig, viewer_file_tree.zig) where it is platform-free.

## In plain terms

On Linux, opening a git diff in a side pane (`--view=git-status:` or
`--view=git-diff:main...HEAD`) used to show "Diff viewer panes are not on Linux
yet". Now it shows the diff: a list of changed files down the left (grouped
into staged / unstaged / untracked for the working tree, with folders you can
fold and a filter box), and the selected file's red/green changes on the right.
Buttons in the bar step to the next or previous change, across files, and
switch between one column and side by side. A working-tree diff updates on its
own when you edit or stage something elsewhere.

## Design (recorded per go.md 5b - mechanism, Claude's call)

- **Share the worker, not just the parser.** `ViewerDiffProbe.zig` already had
  the hard parts (one worker slot with deferred requests, the 15 s deadline,
  cancel-on-close, the T3038 fingerprint poll, untracked-file synthesis).
  Porting it would have been a second copy to drift, so it gained a
  `Notify` callback beside its HWND post, and `git_run.zig` gained a POSIX
  branch: git leads its own process group (`pgid = 0`) and the kill signals
  the group - the Linux analog of the kill-on-close job, and what ends a
  child still holding the stdout pipe. `viewer_worktree.parseRootPosix` keeps
  a Linux root's slashes; `viewer_prefs` stores under `$XDG_STATE_HOME/ghoztty`.
- **The panel is native GTK**, as the file card is native on Mac and win32: a
  `GtkPaned` start child (drag-resizable, width = the shared
  `viewer_prefs` card width) holding a header, a `GtkSearchEntry` and a
  `GtkListBox` (`navigation-sidebar` style) over `viewer_file_tree`'s rows.
- **Worker -> UI hand-off** is `g_idle_add` through a ref-counted link the
  viewer cuts on teardown, so an idle landing after the pane closed is a no-op.
- **The scroll target travels with the request on Linux** (`pending_scroll`):
  the probe does not carry it back, which is why win32 loses "enter the
  previous file at its last change" (filed as T3535).
