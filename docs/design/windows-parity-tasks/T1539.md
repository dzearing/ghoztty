# T1539 - Releasing a dragged pane over nothing opens it in a new window

## Summary

Split out of T1532, and the last of its four drops. `pane_drop.resolve` already
returns `.new_window{ point }` when the pointer is over no Ghoztty window at
all; this task makes that commit — a new top-level window created at the release
point, holding the dragged pane, with the relocation primitive T1538 builds.

Open questions this task owns: where the new window is placed relative to the
release point (Mac drops the frame so the pane sits under the pointer), what the
new window inherits (size, chrome mode, theme), and what the preview shows for a
drop the resolver deliberately does not highlight today (T1531 chose to preview
nothing rather than something hopeful).

## In plain terms

Drag a pane off the window and let go over the desktop, and it becomes a window
of its own — still running whatever it was running.

## Goals

- [x] A release over no Ghoztty window creates a window holding the dragged pane.
- [x] The new window appears where the pointer let go, not at a default spot.
- [x] The source window collapses or closes correctly.
- [x] The preview tells the truth about what releasing there will do.

## What was actually left to do

The behavior itself shipped inside T1538's commit (5ac049210): `pane_drop`
already resolved `.new_window` over open desktop, `newWindowFrameAt` places the
frame against the release point, `drop_highlight.forTarget` previews it, and
`commitPopOutDrop` creates an empty window at that rect and moves the live pane
into it. What had never been validated was the GESTURE - T1538's acceptance
covers the pane header's pop-out BUTTON, which reaches the same commit by a
different route and says nothing about a drag carried off the window. So this
task's deliverable is the test, per go.md's already-fixed path.

## Validation criteria

- [x] Dragging a pane off its window over empty desktop PREVIEWS a new window
      - claim E of `test\win32\rearrange-desktop-drop.ps1`, which also holds
      the preview to being window-sized (not the half-pane wash an in-window
      drop draws) and to standing under the pointer.
- [x] Releasing there opens a top-level window holding the SAME terminal HWND,
      so the shell/scrollback/session came with it - claim F, same script.
- [x] That window stands at the rect the preview promised (within 6px) - claim
      F, `Test-RectNear $newFrame $preview`.
- [x] The window the pane left keeps its remaining pane, which grows into the
      freed space, and stays open - claim F.
- [x] A window's LAST pane released over nothing previews NOTHING and does
      nothing (`pane_relocate.popOutAllowed`) - claim G.
- [x] The oracle discriminates: `-NegativeControl` inverts claim F to "no
      window opened" and the run scores 1 FAILURE(S).
- [x] Floor green: `scripts\floor-lane.ps1 -Lane all`.
