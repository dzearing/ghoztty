# T1679 - A Debug-build harness that reads the ghoztty.log sink is reading an empty file, and passes on it

## Summary

main_ghostty's logFn compiles the %LOCALAPPDATA%\ghoztty\ghoztty.log branch out of Debug builds, and a Debug build is the only thing an acceptance script may launch. So an oracle that reads that sink in an ordinary harness reads an empty string - and every -notmatch assertion over it passes for free. T901's first draft of section D did exactly this and scored green on nothing; it was caught only because a sibling -match assertion in the same block failed for an unrelated reason. Nothing in the harness floor asks the question. Proposal: an audit that flags any test\win32 script naming ghoztty.log unless it either asserts the sink is non-empty before reading it, or proves the build under test is release lineage (the shape log-append.ps1 already has as an explicit premise assertion). Six scripts name the path today; log-append, startup-failure and session-snapshot-reattach are demonstrably aware of the gate, and soak.ps1 and profile-latency.ps1 need checking.
