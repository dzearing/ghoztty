# T2781 - A cold +new-window still opens a stray blank window-1 beside the requested one when the local agent is slow to resolve (resolve-window-persist A, GHOZTTY_AGENT_RESOLVE_DELAY_MS=2500)

## Summary

Found by T2688 2026-11-06. With the 2.5s resolve hold, resolve-window-persist.ps1 section A lists rdA AND window-1 after a cold CLI auto-launch, which is the stray window T2162 (bf61f22e8) set out to remove; B (no hold) lists only rdB<n>. Launching zig-out ghoztty.exe --initial-window=false directly with the same hold and then sending +new-window --target=rdA opens ONLY rdA (log: 'IPC: new-window held until the local-agent resolve finishes', restore resolve served the held request, then 'deferring the startup window 5000ms', no fallback line), so the stray comes from the CLI auto-launch path (autoLaunchInstance + its re-send poll) under a slow resolve, not from the grace timer as tested directly. A detached debug app's stderr is lost, so capture it (e.g. a GHOZTTY test hook that names a stderr file for the auto-launched instance) before guessing. When fixed, section A's A3 ('the launch window is persisted too') must change: it currently relies on the stray window existing.
