# T3370 - Linux L7b: +new-window, +split and +rename work against the GTK app, with a pane-name registry so named targets are idempotent

## Summary

+new-window and +split are served by the GTK frontend (they still answer not-served-yet after T3336 landed +send-keys/+read). Includes the pane-name registry so --name/--target work and are idempotent (a named target that exists is focused, not recreated; a --name held by another pane in another window fails, T2250), +rename, and caller-window scoping through enterCallerScope with request.caller_pane. Replace the pane-id-only findSurface lookup in src/apprt/gtk/IpcHandlers.zig with name-or-id resolution. --focus needs xdg-activation on Wayland; the default is no-activate. Acceptance: a test/linux/cli-*.sh script run in the headless harness (test/linux/lib/headless.sh), driving the CLI only; ipc-server.sh I16 uses +split as its not-served example and must move to a verb still unserved.

## In plain terms

On Linux, a script or agent could already type into a pane and read it back,
but could not open a new window or a side pane, give one a name, or retitle a
window - the app answered "not served yet". Now it can, with the same rules as
Windows and the Mac: asking twice for the same named pane reuses it instead of
opening a second one, and two windows can each have their own pane called
`draft` without one agent's command landing in the other's window.

## Goals

- [x] `+split` opens a pane next to the caller's pane (or a named pane/window), with `--name`, `--command`, `--env`, `--direction`, `--percent`
- [x] `+new-window` opens a window, named by `--target` and/or with its pane named by `--name`, plus the inline `--split`
- [x] Named targets are idempotent, and pane names belong to their window (T2250)
- [x] `+rename` pins and clears a window's title
- [x] `+send-keys`/`+read` take names, not only pane ids
