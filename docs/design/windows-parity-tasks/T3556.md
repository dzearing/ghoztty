# T3556 - Linux feedback composer: on a desktop with the screenshot portal, + offers the system's interactive region capture like the Mac

## Summary

T3546 made the GTK composer's + (and Ctrl+Shift+S) capture the pane's page from the app's own render, because Wayland gives a client no global capture. The Mac's + is screencapture -i (pick any region on screen) and win32's is a region selector. On a real GNOME/KDE desktop, xdg-desktop-portal's org.freedesktop.portal.Screenshot with interactive=true is the native equivalent (the desktop draws the picker and hands back a file URI). Offer it when the portal answers, keep the own-render capture as the fallback (headless Weston, WSLg, no portal), and keep the same chip/strip/report path. Validation needs a portal; the headless harness has none, so the fallback path stays the tested one and the portal path needs a by-hand run or a fake portal on the session bus.
