# T2621 - Window presenter path: the layout pass's resize wait still keys on the pane's publish, not on the presenter's composed frame at the new geometry

## Summary

T2615 left the frame_event signal where it was: generic.zig signals it after drawFrameEnd, which on the presenter path means the slot was PUBLISHED, not composed. The design note's frame path says the layout pass waits on the presenter's composed frame for the new geometry. Needed for T2592's strip cure under a live drag.

## In plain terms

When you resize a window or drag a divider, Ghoztty waits a moment for each
pane to show its picture at the new size before carrying on, so you never see
a stale or half-drawn pane. With the new shared window painter (still behind
an opt-in switch), that wait was ending as soon as a pane had DRAWN its
picture, before the window painter had actually put it on screen at the new
size. Now it waits for the painter itself.

## Goals

- [x] On the presenter path the layout pass's wait ends on the presenter's swap, not the renderer's publish
- [x] The presenter knows the new pane rectangles before the wait starts
- [x] A frame composed into a pane's OLD rectangle cannot answer the wait for its new one
- [x] An acceptance section proves it, with teeth

## What landed

- `src/apprt/win32/Surface.zig`: `signalFrameDrawn` returns early on the
  presenter path; its bookkeeping is now `markFrameShown`, which the
  presenter calls. `presentLagSleep` is public so the presenter can apply the
  T1035 lag once per compose. The serial (unbatched) wait syncs the presenter
  first.
- `src/apprt/win32/Window.zig`: `endFrameWaitBatch` syncs the presenter
  before it waits (the trailing `syncPresenter` in `layoutSplits` ran after
  the wait). New `tracePresenterShown` (`resize trace pres-shown`).
- `src/apprt/win32/WindowPresenter.zig`: `sync` zeroes `presented_size` for
  every pane whose rectangle the pass changed, under the lock compose holds;
  `compose` reports every blitted pane (fresh or re-composed) after its swap.
- `src/renderer/gl_window_presenter.zig`: `geometryChanged`, unit-tested.
- Not handled: a box without the GL 3.2 blit/sync entry points composes
  background only, so its resize waits run out the one-frame budget.
