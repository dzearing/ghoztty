# T3336 - Linux L7a: +send-keys and +read work against the GTK app, with a CLI-driven acceptance script

## Summary

Originally "every CLI verb works against the GTK app" (L7). Split on
2026-11-21 so each verb lands with its own acceptance script; this card is
the first slice, `+send-keys` and `+read`, the pair every later verb's test
drives the app through. The rest are filed as children:

- T3370 (L7b) `+new-window`, `+split`, `+rename` and the pane-name registry
  that makes named targets idempotent.
- T3367 (L7c) `+close`, `+focus` (deps T3370).
- T3368 (L7d) `+rearrange` (deps T3370).
- T3369 (L7e) `+reload`.
- `+set-state` / `+set-banner` ride with the banner UI in T3339 (L10), and
  `+stash` / `+restore` / `+new-remote-window` / handoff-quit with sessions in
  T3337 (L8); both cards carry a note.

`+list` (with `--tty`) and `+version` were already served by T3335.

What landed (`src/apprt/gtk/IpcHandlers.zig`):

- `+send-keys --target=<pane id>`: the Mac's `handleSendKeys` byte for byte.
  With `--segments=`, text runs go through `writePtyBracketed` (framed when
  the program enabled mode 2004) and key runs through `writePtyRaw`; without
  it the flat `--keys=` payload is written raw. No LF rewriting: a POSIX pty
  takes LF as a line end, so the conhost mapping is win32's alone.
- `+read --name=<pane id> [--lines=N]`: the whole screen dumped under the
  renderer lock with priority (no reflow), tailed by the shared
  `read_tail.tail`; an empty pane answers success with empty text.
- Targets resolve by stable pane id (`$GHOZTTY_PANE_ID`, the `+list` id)
  across every window and tab; names arrive with T3370.

## In plain terms

A script or an agent can now type into a Linux Ghoztty pane and read back
what it shows, exactly the way it already does on the Mac and Windows. That
is the two-way channel every other command's test is built on.

## Goals

- [x] `+send-keys` writes text and keys into a GTK pane with the Mac's paste framing
- [x] `+read` returns the pane's screen, tailed by `--lines`
- [x] an acceptance script drives both through the CLI only, in the headless harness
- [x] the remaining verbs are filed as their own tasks

## Validation criteria
