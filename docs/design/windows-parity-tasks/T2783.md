# T2783 - rdp-perf-probe.ps1's off arm says only 'fps < 8' when it goes red: on 2026-11-04 it read 3-3.7 fps for a build that reads 10 today, and nothing recorded what the box was doing; print the box's state (CPU load, power plan/battery, other ghoztty instances, foreground app) beside a red spinner row

## Summary

T2691 found the 2026-11-04 red (`measured (off)`: unfocused spinner 3-3.7 fps,
threshold >= 8) was not code: the build that went red (ad0f40bde) reads 10 fps
on 2026-11-07, as does HEAD. Whatever the box was doing that day is lost,
because the harness prints only the number. When the off row (or the auto row's
`> 0`) fails, print what could explain a starved renderer: system-wide CPU
load over the measured window, the active power plan and AC/battery state,
the count of other `ghoztty.exe` processes, and the foreground process.
Report-only; it must not change the pass/fail rule.

- [ ] A forced red (e.g. a `-NegativeControl`-style threshold) prints the box-state block, and a green run does not.
