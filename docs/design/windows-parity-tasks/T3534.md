# T3534 - Linux image pane: Ctrl+C copies nothing (Mac and Windows copy the picture and its file)

## Summary

docs/reference/viewer-image-and-diff.md: in an image pane Cmd+C copies the picture itself plus its file URL, as Preview does with nothing selected (win32: T1872 + T1909, image_copy.zig). T3416 brought image panes to Linux without it, so Ctrl+C in a GTK image pane does nothing. Translate: on Ctrl+C with no selection in image mode, put a GdkContentProvider union of the decoded GdkTexture (gdk_texture_new_from_filename, or the PNG ViewerImage already serves for TIFF/HEIF/icns) and a text/uri-list of the file on the widget's clipboard. Acceptance: a test/linux step that copies and reads the clipboard formats back (a Wayland clipboard needs a focused surface; use the steps seam or read the provider's formats).

## In plain terms

On Linux, pressing Ctrl+C while looking at a picture in a viewer pane did
nothing. Now it copies the picture, so it pastes into an image editor or a
chat, and it copies the file too, so pasting into a file manager copies the
file - the same as on the Mac and Windows.

## Goals

- [x] Ctrl+C (and Ctrl+Insert) at an image pane puts the picture on the clipboard
- [x] ...together with the file (a uri-list and a file manager's copied-files list)
- [x] the page's other copies are untouched: Ctrl+Shift+C and the address/find fields' Ctrl+C
- [x] a headless test reads the clipboard back
