# T919 - A panicking zig test binary prints no stack trace on this box (Unable to dump stack trace: InvalidBlockIndex), so every test panic costs a cdb round-trip

## Summary

Reproduced while validating T811: a deliberately induced 'Invalid free' panic in the none lane printed 'thread 41056 panic: Invalid free' followed by 'Unable to dump stack trace: InvalidBlockIndex' twice and nothing else, so the panicking frame is unknown without attaching cdb. That is why T811's original 2026-08-12 incident needed scripts\crash-catch.ps1 and a dump to name Connection.destroy at all, and the same tax lands on every future test panic (T442, T443 and T536 all paid it). InvalidBlockIndex comes out of std.debug's PDB reader, so the first experiment is cheap and named: build the test binaries with -Dstrip=false (and check what .pdb the test artifacts actually emit next to the exe) and re-run the same induced panic to see whether the in-process trace resolves. If a flag fixes it, wire it into scripts\floor-lane.ps1 so every lane run has it. If it cannot be fixed, document the cdb recipe at the point of pain instead of in three task files.

## In plain terms

When one of our automated tests crashed on Windows, it often said only "Unable
to dump stack trace" instead of showing where it crashed, so every such crash
needed a slow debugger session to even locate. Now every Windows test build is
touched up right after it is linked, and a crashing test names the file and
line it died on.

## Root cause

LLD (the linker inside zig) writes PDBs that are valid MSF but put stream data
in the positions of Free Block Map slots it does not need (`k*4096+1`, `+2`,
k >= 1). `std.debug.Pdb`'s `Msf.init` (zig 0.15.2) refuses any stream block at
those positions with `error.InvalidBlockIndex`, so the panic handler cannot
symbolize anything. It is not a `-Dstrip` question: the test PDBs are full;
their layout is what trips the reader. Scan of the lane cache on 2026-09-23:
24 of 256 `ghostty-test.pdb` and 31 of 110 `ghoztty-agent-test.pdb` builds
affected, always blocks 28673/28674.

## Fix

`src/build/pdb_msf_fix.zig` (pure, unit-tested in the build-helpers binary) +
`pdb_msf_fix_main.zig` (host tool) + `PdbMsfFix.zig` (wiring): after every
Windows test link and before the run, relocate those blocks to the end of the
file, repoint the directory, and keep the Free Block Map exact. The map part is
load-bearing: cdb refuses a PDB whose map disagrees with its directory in
either direction ("file system or network error reading pdb" -> export symbols
only), found by experiment during this task. Wired for `ghostty-test` (none,
win32, releasesafe lanes), `ghoztty-agent-test` and the build-helpers test.
