# T2545 - Composition step 4c-iii: the flat pane style's window-owned pixels (gutters, divider lines, stack strip bands and names) compose on the chrome host - the flat style has no PaneDesk, so it needs its own bottom layer

## Summary

T2510 split, part iii. paintDividers/paintStripBandsAndNames for paneStyle != elevated paint the window DC directly; carry them on a flat-style background visual with the same mirror + dirty-rect shape as the desk. Oracle: WGC match knob on/off on flat style with a split, a stack and a hovered divider.

## In plain terms

With the compositor switch on (`GHOZTTY_COMP_CHROME=1`), a window using the
flat pane style used to draw everything between its panes by hand: the thin
divider lines, the background in the gaps, the glow on a divider you are
dragging, and the labelled strips of panes tucked into a stack. Now all of
that goes up as one layer on the compositor, and only the parts that changed
are sent each time - a dragged divider sends a thin strip, not the window. It
looks exactly the same as before. Rearrange mode and hero mode still draw by
hand in the flat style, and switch the layer off while they are showing. The
switch is still off by default.

## Goals

- [x] The flat style's gutters, divider lines, gutter bar and strips paint a persistent mirror and go up on the desk visual by dirty rectangle
- [x] The clears between a layout's moves (vacated gutters, vacated pane strips) follow it there, with the same exclusions
- [x] Rearrange headers, a hero tab or a translucent window put the flat style back on GDI, whole
- [x] On screen, the composed picture matches the hand-drawn one: a split, a held divider drag, the release, a stack, rearrange mode

## Design (2026-10-31)

`chrome_comp.FlatDesk` holds `mirror`, a DIB the desk area's size that holds
exactly what the window's own pixels would, and `shadow`, what the desk
visual holds. `Window.flatPass(ref, painter, bands)` runs a flat painter
into the mirror in client coordinates, clipped as `ref` is (its clip region
when it has one - the vacated-gutter clear's exclusions - else its clip box),
then `FlatDesk.changed` diffs the clip box against the shadow
(`diffRects`: consecutive rows differing over the same span are one
rectangle) and uploads those through `Host.deskUpload`. A new, moved or
back-from-GDI mirror is painted whole first (terminal background, then the
bands) and goes up whole.

Routed: the paint cycle and `paintMovedBands` (`paintFlatBands` = dividers
then strips), `clearVacatedGutters`, `clearVacatedPaneStrips`. Only the band
paint may put the flat desk on the compositor (`bands`); the clears only
follow it. The desk visual is shared with the elevated style's `PaneDesk`:
whichever takes it from the other takes it through `deskOffVisual` first, so
neither ever uploads rectangles over the other's picture. `flatEligible`
refuses headers, a hero tab and translucency; `repaintRearrangeHeaders` takes
the flat desk off before painting headers outside the cycle.

With the desk up the caption band rides the compositor too (T2543's
`captionBandFinish` keys on `deskLive`). `deskOffVisual` now also invalidates
the caption band when it was up, since a desk taken off outside a paint left
the window's own band unpainted. Debug seam for the oracle's negative
control: `GHOZTTY_COMP_CHROME_FLAT_FREEZE=1` drops the flat desk's dirty-rect
uploads.

Found while filming: on GDI the gutter bar's glow reaches ~11 px past the
grid and paints the terminal background over the bottom of the tab bar, and
the smear stays (T2569, filed). The visual is clipped below the caption, so
the compositor's band is whole; the oracle matches the drag frames below the
caption and checks the composed band separately.
