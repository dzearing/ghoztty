# T2813 - drag-perf.ps1 never exercises T2769's coalescing: each posted move is handled before the next arrives, so skipped_queued/skipped_frame stay 0 - add a burst arm (several moves posted with no wait) that asserts the pass is skipped for a queued move and the drag still lands (landed=N off=0)

## Summary

T2769 coalesces a drag's layout passes: a move whose successor is already
queued skips its pass (`skipped_queued`), and a move inside the current display
frame leaves its pass to the frame timer (`skipped_frame`). drag-perf.ps1
section F posts one move and waits for it to be handled before posting the
next, so on 2026-11-07 both counters read 0 at every pane count: the skip
branches are proven only by comp_drag.zig's unit tests, never in the running
app.

Fix: a burst arm in section F that posts several WM_MOUSEMOVEs back to back
with no wait between them, then releases the drag.

## Validation criteria

- [ ] the burst arm's drag summary reports `skipped_queued` > 0 (a queued move's pass was skipped)
- [ ] the drag still ends with every HWND at its final rect (`landed=N off=0`)
- [ ] negative control: under `GHOZTTY_COMP_DRAG_SERIAL=1` the burst arm's `skipped_queued` is 0
