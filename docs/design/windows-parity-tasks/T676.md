# T676 - Sweep the T117/T141-derived backlog for tasks a later turn already resolved

## In plain terms

Some cards in the queue describe problems that have since been fixed under a
different card, because the fix was reached from a user report rather than from
the card. Nobody notices until an agent picks one up and spends a turn finding
out there is nothing to build. This is a one-pass check over that family of
cards so the remaining count means what it says.

## Summary

T122 ("pane banners don't survive relaunch/re-attach on Windows") was picked up
on 2026-08-09 and found to be **entirely** shipped six days earlier by T422,
which arrived at the same missing manifest field from the user's report instead
of from the card. The turn produced no code — only verification and a close.

That is not a one-off shape. Both T122 and T422 were opened against the same
subsystem from two directions, and the same is plausible for the rest of the
family filed off T117 (the main-merge audit) and T141 (the CLI parity audit):
those audits filed cards in bulk from greps, and the intervening weeks of
user-report work has been closing the same ground opportunistically.

Cost of leaving it: the dashboard's M1 denominator counts work that does not
exist, and each phantom card burns a full turn's context to discover. Cost of
the sweep: one pass, and it is cheap per card — the check is "does the named
symptom still reproduce / does the named code still look the way the card says",
which for most is a grep against the file the card itself names.

## Details

Scope: every **open** (todo/in-progress/blocked) task whose `deps:` name T117 or
T141, plus any card whose Summary quotes a grep result ("zero hits", "contains
no X") as its evidence — a grep-derived claim is exactly the kind that a later
commit invalidates silently.

Known members at filing time (open, seat: win): T124, T149. Plus the T141 CLI
family, of which T169 and T170 were re-seated to `mac` on 2026-08-09 (they are
Swift work; the win32 half is already the reference implementation) — those two
should be re-checked from the Mac seat, not here.

For each card, one of three outcomes, recorded in the card:

1. **Still real** — leave it, but replace any stale grep evidence with what the
   code says today, so the next agent to claim it does not re-derive it.
2. **Superseded** — close as `skipped(superseded by T<id>; verified …)` with the
   same standard T122 was held to: name the commit that did it, walk the card's
   own claims point by point, and **re-verify on the box** rather than trusting
   the earlier turn's report.
3. **Partly superseded** — narrow the card's Summary to what genuinely remains
   and say what was already covered.

A close by supersession is not a scope cut, so it does not need the staleness
proposal path — but it does need evidence, because "I think this was fixed" is
how real gaps get closed by accident.
