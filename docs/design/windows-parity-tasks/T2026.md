# T2026 - floor-lane.ps1 defaults -Repo to D:\git\ghoztty, so a lane-B turn's floor (zig lanes AND the harness floor) silently builds and grades lane A's checkout and reports ALL LANES PASS

## Summary

Found in T2010 (lane B, 2026-10-16 17:12). `powershell -NoProfile -File scripts\floor-lane.ps1 -Lane harness` run from D:\git\ghoztty-b logged `FLOOR LOCK acquired ... (D:\git\ghoztty)` and `harness-floor.ps1 -Repo "D:\git\ghoztty" -Scoped`: scripts/floor-lane.ps1:194 is `[string]$Repo = 'D:\git\ghoztty'`. go.md step 3 tells every turn to run the lanes bare, so lane B's zig lanes and harness floor build and grade LANE A's tree. T1993/T1996 fixed the same literal for acceptance scripts; floor-lane was left out. Fix: default -Repo to the checkout the script lives in (Split-Path $PSScriptRoot -Parent), the way acceptance-parallel.ps1 does; check the other lane-sensitive defaults in floor-lane (build roots, lock names, stamps) at the same time; add a harness assertion that a bare run from a second checkout names that checkout.

## In plain terms

The second loop (lane B) runs its own copy of the repo, but its standard
"is everything still green?" check quietly tested the first loop's copy
instead. So lane B could break something and still be told it was all fine.
Now the check tests the copy it was started from, and says which one it is.

- [x] a harness assertion, with a negative control, that keeps it that way
