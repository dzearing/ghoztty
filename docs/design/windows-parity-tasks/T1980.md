# T1980 - user_env expands REG_EXPAND_SZ PATH entries against the spawning process's environment, so a process started without USERPROFILE/LOCALAPPDATA (service or installer context) hands shells literal %USERPROFILE%\... PATH entries

## Summary

Found while fixing T1972. `os/user_env.zig` `expand()` resolves `%VAR%` in REG_EXPAND_SZ registry values with ExpandEnvironmentStringsW, i.e. against the CURRENT process environment. The registry Path entries most users have (`%USERPROFILE%\AppData\Local\Microsoft\WindowsApps`, tool installers) depend on USERPROFILE / LOCALAPPDATA. A spawning process that lacks those (a service, an installer custom action, a stripped relaunch) would add the entry unexpanded, which no shell can resolve. Fix: expand against the env map being built (after the non-Path vars are merged), falling back to the process env. Unit-test the expansion with an env map that lacks USERPROFILE.
