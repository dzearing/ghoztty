# T2050 - A Windows machine removed from the account on another device keeps redialing the relay with its dead credential, and its 'Share this machine' box still reads ticked; a Mac stops and drops relay.env

## Summary

Mac (main 6dfb31232): a credential the relay answers 401 for is dead, so RelayHostAgent stops the relay agent and deletes relay.env. Windows: the uplink rides the session agent and never exits on revoke (it would take the local panes with it), so it redials 401s on backoff forever and the chooser checkbox (sharing.decide on credential PRESENCE) still shows the machine shared. Make the agent's rejection counter (revoked_after_rejections) park the uplink and drop or quarantine relay.env after two 401s, in the T1427 relay_suspend style, so the checkbox unticks and nothing redials. Acceptance: agent-sharing-uplink.ps1 with a loopback relay answering 401.

## In plain terms

If you remove a Windows PC from your account on another device, the PC was
never told: it kept knocking on the relay with a key that no longer works,
forever, and its "Share this machine" box still looked ticked. Now, after the
relay turns it away twice, the PC stops trying, forgets the dead key, and the
box unticks, the same as a Mac. Your open terminals on that PC are untouched,
and adding the PC back brings sharing back without a restart.

## Goals

- [x] Two consecutive 401s on the uplink's control dial drop relay.env and park the link, without exiting the session agent
- [x] A re-enroll that landed mid-streak is never deleted (only the refused token's file is dropped)
- [x] A fresh relay.env after the revoke brings the uplink back with no restart
