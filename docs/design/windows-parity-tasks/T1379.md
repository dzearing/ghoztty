# T1379 - The health line says the loop is down without saying what the pane was doing

## Summary

P2: the actor (the watchdog) now reads working/idle/unknown off the pane and logs it (T1370), the observer (go-loop-health.ps1) still decides on turn_age alone - so a DEGRADED line still sends a human to read the pane by hand, which is the step T1290 was trying to remove. Not P1: the recovery path is correct, this is only the report.

## In plain terms

When the loop stops making progress, the health check prints "DEGRADED" and
then tells whoever is reading it to go and look at the loop's window by hand to
find out why. The thing that recovers the loop already looks at that window
itself. After this, the health check looks too and says what it saw: still
working on a long job, sitting idle, a typed-but-unsent command, or the last
thing the session said (for example an "API Error: 529 Overloaded").

- [x] the health line carries `pane_state=working|idle|unknown|not-asked`
- [x] past the 180-minute backstop the note says what the pane was doing instead of "read it with +read"

- [x] `-Json` carries `pane_state`, `pane_composer`, `pane_last_output`
