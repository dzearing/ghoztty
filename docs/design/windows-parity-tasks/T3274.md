# T3274 - onInputDesktop() is cached forever at its first call, so an app started during a desktop switch keeps the wrong answer and the deferred-focus gate forwards asserts while another app is in front

## Summary

win32.zig on_input_desktop_cache (line ~2749) assumes the answer cannot change because the THREAD's desktop is fixed, but the INPUT desktop does change (lock screen, UAC, RDP). If the first query lands mid-switch and the names differ, it caches false for life: windowIsActive falls to GetActiveWindow and shouldForwardFocus returns true whenever active==0, so performDeferredFocus no longer drops WM_APP_SETFOCUS while another app holds the foreground. Found by the T3272 audit; not shown to cause T3272. Fix: re-query on WM_WTSSESSION_CHANGE / desktop switch (or a short TTL), with a none-lane test of the cache rule.
