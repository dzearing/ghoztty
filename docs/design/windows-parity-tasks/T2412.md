# T2412 - menu-bar.ps1 reads the shared debug LOCALAPPDATA, so a win-v9.9.9 update offer left by another harness adds an Install Update row and turns sections B/H red

## Summary

Found in T2356: %LOCALAPPDATA%\ghoztty\update-offer-debug.txt (version=9.9.9, written 2026-10-28 10:06 by some update harness run that never cleaned up) is restored at launch, so the menu grows the 'Install Update' row + separator and B counts 99 rows against the model's 97 (H fails with it). Worker-mirror runs are isolated and pass; the serial/alone run is not. Fix both halves: menu-bar.ps1 should run under its own LOCALAPPDATA (Set-GhozttyTestIsolation) and the update harness that left the offer should remove it in its finally.
