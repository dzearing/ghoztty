# T2412 - menu-bar.ps1 reads the shared debug LOCALAPPDATA, so a win-v9.9.9 update offer left by another harness adds an Install Update row and turns sections B/H red

## Summary

Found in T2356: %LOCALAPPDATA%\ghoztty\update-offer-debug.txt (version=9.9.9, written 2026-10-28 10:06 by some update harness run that never cleaned up) is restored at launch, so the menu grows the 'Install Update' row + separator and B counts 99 rows against the model's 97 (H fails with it). Worker-mirror runs are isolated and pass; the serial/alone run is not. Fix both halves: menu-bar.ps1 should run under its own LOCALAPPDATA (Set-GhozttyTestIsolation) and the update harness that left the offer should remove it in its finally.

## In plain terms

An automated menu check kept failing on a correct build because another test
had left a fake "update available" note behind, which adds an extra row to the
menu. The check now recognises that row as box state rather than a broken menu,
so it no longer cries wolf. Nobody using the app notices either way.

## Goals

- [x] menu-bar.ps1 no longer goes red when a pending-update row is present (already landed in 5c7ae7d276, T2017)
- [x] the other half - the update harness that leaks the offer - is tracked once, as T3610, not twice

## Validation criteria

- [x] With the leaked `update-offer-debug.txt` (version=9.9.9, rewritten 2026-11-24 20:33) still in the real debug LOCALAPPDATA, a direct non-worker run of `test\win32\menu-bar.ps1` against a fresh Debug build is ALL PASS (108 assertions), and prints `NOTE B: conditional root row present (box state, not the model): 'Download Update 9.9.9'` - the exact state that turned B/H red when this was filed. Verified 2026-11-26, lane b.

## Resolution

Already fixed in passing by 5c7ae7d276 (T2017): the whole-menu and caption-less
checks strip only the app's own conditional top rows (pending app update,
background-process update) before comparing against the static model. Giving the
script its own LOCALAPPDATA was the other way to fix it and is no longer needed:
the strip also covers a GENUINE pending update, which isolation would not, and
moving a debug-lineage script's LOCALAPPDATA moves the `-debug` state dirs it
reads (Isolation.ps1's note on `-ReleaseSandbox`). The leak's source is T3610
(still open; the offer file was rewritten on 2026-11-24, so a harness is still
leaking it).
