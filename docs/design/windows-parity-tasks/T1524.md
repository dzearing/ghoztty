# T1524 - The win32 app handles main's new toggle_rearrange_mode action instead of ignoring it

## In plain terms

Ghostty on the Mac just gained a "rearrange mode" you turn on from the command
palette or a keybinding. On Windows the same command exists in the palette — it
just does nothing, because the Windows side of the app never learned what to do
with it. This is the plumbing half: make the Windows app actually receive and
answer the command.

## Summary

`b18ee2d77` on `origin/main` added `toggle_rearrange_mode` to
`src/apprt/action.zig` and a matching entry in `src/input/command.zig`. The
win32 apprt's action switch needs a real arm for it; today it falls to the
unhandled path, so a user who binds the key or picks it from the palette gets
silence.

Scope here is the action plumbing and a visible mode state (in/out of rearrange
mode). The drag interaction itself is T1525.

## Goals

- [x] The win32 apprt handles `toggle_rearrange_mode` rather than falling through.
- [x] Toggling it twice returns the window to its normal state.

## Validation criteria

- [x] `zig build -Dapp-runtime=win32 -Doptimize=Debug` is green with the action handled.
- [x] An acceptance script in `test/win32/` drives the action and observes the window enter and leave rearrange mode.
