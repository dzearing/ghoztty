# T3111 - Release idle CPU rose 7x between baseline-1 and baseline-2 (0.03% to 0.21%); prove it is noise or find the new wakeup

## Summary

audit-2 (T3072, docs/design/perf-audit/audit-2.md line 52) shows release idle CPU 0.03% -> 0.21% of one core, passed as 'within tolerance' with no explanation, while debug went down (0.34 -> 0.23). An absolute tolerance hides a 7x relative rise on the build users run. Between the two baselines landed changes that add timers or deferred work at idle-adjacent paths (e.g. T2974's release-a-second-after-the-size-settles, T2975's hidden release, T2970's blink change). Rerun the idle phase on the release build at least 5 times at HEAD and at 4c8a7cd4f to get a distribution; if the rise is real, bisect the T2967-T3058 commits and attribute the wakeup (T2989 per-thread attribution if it has landed). Also give the idle metric a relative tolerance floor in perf-baseline.ps1 so a 7x change on a tiny base cannot pass silently. Child of T2957; audit-3 is T3101.
