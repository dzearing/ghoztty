# T985 - A quote the user edited in the composer files its original wording as the report's metadata

## Summary

T935 made a quoted block's identity live on its DOM node, so editing the passage now KEEPS its metadata instead of dropping it - which is the improvement, and which creates a question the report format has never had to answer. The body is rendered from the composer's text (the edited passage, prefixed with '> '), while the report's quotes array carries entry.text: the passage exactly as it was on the page. A reader sees two different wordings for one quote and nothing says which is which. Decide what the report should say - the original as provenance beside the edited text, the edited text with a note that it was changed, or something else - and make the source-line lookup (viewer_feedback_report.sourceLine) agree with it.

## In plain terms

When you quote a passage into a feedback report and then reword it before
sending, the report used to show the reworded version in its message but the
page's original wording in its details, with nothing saying which one you
meant. Now the details keep the original (so the agent can still find it in the
file) and add the version you edited it to, only when you actually edited it.

## Goals

- [x] Decide what the report says for a reworded quote (both wordings, labelled)
- [x] Windows report carries `editedText` when the quote was reworded
- [x] Mac report carries the same field, the same way
- [x] The process-feedback skill tells the agent which field means what

## Decision

Mechanism call, not an experience fork (go.md 5b): `quotes[].text` stays the
page's own wording, because that is what `sourceLine`, `blockText` and the
offsets all refer to, and the source file only ever contains the original.
A new optional `editedText` is emitted ONLY when the quote block in the
composer no longer reads as `text` (surrounding whitespace ignored); the body
already carries that wording. Additive and optional, so readers that do not
know it are unaffected. `sourceLine` is deliberately resolved against the
original — resolving the edit would fail or, worse, land on a wrong line.
