# T3398 - Linux L8c: the local agent starts at login - a systemd --user unit, XDG autostart when systemd is off

## Summary

The Mac loads a LaunchAgent and Windows writes an HKCU Run entry so the agent is back after a reboot or a crash without the app; the Linux app (T3337) only spawns it on demand, detached. Install a systemd --user unit (Restart=on-failure, same argv and env overrides as LocalAgent.spawnDetached) when systemd --user is reachable, else an XDG autostart .desktop entry; WSL needs [boot] systemd=true in /etc/wsl.conf, which is the user's file, so detect and fall back rather than edit it. Debug and release lineages get distinct unit names. Test inside the harness with a private XDG_CONFIG_HOME and never touch the user's own systemd.

## In plain terms

On a Mac or a Windows PC, the background helper that keeps your terminal
sessions alive starts again by itself after a reboot, so your shells are
there before you even open the app. On Linux it only started when you opened
Ghoztty. Now the Linux app registers it to start at login too, through the
user's systemd when that is running, or through the desktop's autostart
otherwise.

## Goals

- [x] write a `systemd --user` unit plus its enable link when the user's systemd is running
- [x] otherwise write an XDG autostart entry, and never leave both behind
- [x] run the agent exactly as the app's own spawn does, so either finds the other
- [x] keep debug, release and test lineages apart; write nothing from a dev build or a source checkout by default
- [x] prove it in the headless harness without touching the user's systemd or `~/.config`

## Design notes

- Backend = is the user's systemd reachable right now (`$XDG_RUNTIME_DIR/systemd/private`, else `/run/user/<uid>/...`). The app never runs `systemctl`: the enable link is the file `systemctl --user enable` makes, read at the next login, so nothing here starts, stops or reloads the user's systemd. WSL without `[boot] systemd=true` gets the desktop entry; `/etc/wsl.conf` is never edited.
- `Restart=on-failure` plus `RestartPreventExitStatus=183`: a crash comes back, but an agent that lost the single-instance lock to the one the app already spawned does not spin.
- A desktop `Exec` cannot set the environment, so it runs through `/usr/bin/env`; quoting follows the spec (four backslashes for one, `%%`). A value with a line break is refused, never written.
- Argv and env come from one helper (`spawnArgs`) shared with `spawnDetached`, so the login agent and the on-demand agent cannot drift.
- Gates are win32's: `GHOZTTY_AGENT_AUTOSTART` = `off` | `force` | `gate`; debug builds only under `force`/`gate`; an agent binary inside a source checkout only under `force` (Windows T1146).
- Not covered: a real login on a real systemd box (the harness has none), and the agent's environment under systemd is the user manager's, not the login shell's (the same position as the Mac's LaunchAgent).
- Found on the way: a relaunch that restores a saved layout loses its own `-e` command (T3594).
