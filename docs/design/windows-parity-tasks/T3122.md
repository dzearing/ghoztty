# T3122 - Activity Monitor probe redials, dials and machine-list fetches each create a fresh OS thread (activity_probe_conn.zig:415, activity_dial.zig:189, activity_machines.zig:219); each strands ~64 KB on NVIDIA

## Summary

Follow-up of T2990 (same NVIDIA per-thread leak, per connect/redial rather than per 1.5 s tick). T2990 moved the sampler onto a reusable_thread pool. Three other Activity Monitor workers still std.Thread.spawn + detach per request: the probe dial (redials an unreachable machine on a 30 s..5 min backoff, so up to 12 threads/hour per machine), the source dial, and the machine-list fetch. Per T2644 each thread created while a GL context is alive strands ~64 KB in nvoglv64. Move them onto a pool and assert the count in activity-monitor-probe-fail.ps1.
