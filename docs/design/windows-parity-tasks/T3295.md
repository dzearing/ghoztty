# T3295 - Restart Ghoztty and Background Sessions may no longer end any session: under holders (the default) killing the agent leaves every shell running for the next agent to re-adopt

## Summary

app-restart.ps1 R6 (T1592) measured the holder that owns a pane's job STILL RUNNING after restartForUpgrade killed the agent - the survive-an-agent-death property T905/T909 built. But the palette command and its dialog promise the opposite ('ends N sessions'), R3 only asserts that the agent pid changed (never that a session ended), and LocalAgent.restartForUpgrade's doc still says 'the agent owns every persistent PTY, so its children die with it'. Measure whether R3's session ids survive the relaunch; if they do, make the command end them (holder SHUTDOWN) or re-word it, assert it in R3, and fix the stale doc comment.

## In plain terms

The command palette's "Restart Ghoztty and Background Sessions" warns that
it will end your running terminal sessions, and you confirm that. Until now
it did not: every shell kept running in the background and came straight
back after the restart. Now it really ends them, so the restart gives you
fresh shells as promised. The one exception is a terminal that Ghoztty
itself was started from, which it leaves running and says so in its log,
because ending it would kill the restart halfway through.
