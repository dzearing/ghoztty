# T2322 - A failed Install Update must tell the user

## Summary

User report 2026-10-26: "i click install and restart. NOTHING HAPPENS". Part
three of the chain (T2320, T2321 are the causes).

Two failure points are invisible:

- Arming fails (`update apply: NOT armed err=...`, `update_install.zig` ~362):
  the app logs and stays up, the menu row stays, and the click visibly does
  nothing.
- msiexec fails in the applier (`exited 1603`): the app is relaunched on the
  old build with only a log line `Ghoztty could not finish updating, so it is
  still running the version you already had.`

Mac parity: check what Sparkle shows on the Mac for the equivalent failures
and match that experience.

## Goals

- [ ] a failed arm shows an error in the app (dialog or balloon) with the
      reason in plain words and a way forward (retry / open the download)
- [ ] the relaunched app after a failed msiexec says the update failed and why
      (the applier hands the reason over - e.g. a marker file the next start
      reads), including the MSI's own message for 1603 when it has one
- [ ] the automatic (idle) install failing does not spam, but the menu row
      shows that the last attempt failed

## Validation criteria

- [ ] acceptance on the test desktop: simulate an arm failure and an msiexec
      failure; read the shown text via WM_GETTEXT/UIA (positive control: the
      current build shows nothing)
