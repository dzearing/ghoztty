# T1735 - The viewer host-floor test's GoBack leg loses its navigation under full CPU load and waits out 30s on the website

## Summary

Found in the T1734 turn. With 32 busy-loop processes saturating the box, 1 of 3 runs of 'host floor: a real controller on a real window, on this box' (-Dtest-filter) failed at ViewerPane.zig ~7783: after pane.goBack() from the t390 website, waitFor(mode == .markdown, headings Iota) timed out with the pane still mode=web page_loaded=true location=http://127.0.0.1:<port>/t390.html. Log: %TEMP%\t1734-fix-2.log (4 status=9 CONNECTION_ABORTED completions before it). Same class as T1734's lost clicks: a WebView2 request issued while Chromium is still settling a previous navigation is dropped with no event. Investigate whether GoBack is issued before the forward load has truly settled, and gate on a signal that proves the history entry is walkable, or re-issue goBack when no NavigationStarting follows within a bound. Repro: 32 x powershell 'while(1){}' busy loops, then zig build test -Dapp-runtime=win32 -Doptimize=Debug '-Dtest-filter=host floor: a real controller'.

## In plain terms

One of the viewer's self-tests opens a website, presses Back, and expects the
markdown document to come back. On a very busy machine it sometimes pressed
Back a moment too early - before the browser had really moved to the website -
so Back went one page too far and the test waited 30 seconds and failed. The
test now waits until the browser itself reports it is on the website.

## Goals

- [x] Find why Back lands on the wrong page under load
- [x] Make the test wait on something only the browser can report
- [x] Green under the same 32-busy-loop load that reproduced it

## Root cause

The wait before Back checked three flags: web mode, can-go-back, page loaded.
`navigate()` sets the mode (and location) itself before the browser moves;
can-go-back was already true from older history entries; and a late
NavigationCompleted from the template's own load sets page_loaded. So all three
could be true while the TEMPLATE was still the current entry. Back from there
cancels the forward load and walks onto the older t390 website the T593 section
left behind - exactly the stuck state in the report (mode=web,
page_loaded=true, location=.../t390.html).
