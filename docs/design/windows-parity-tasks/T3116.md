# T3116 - Re-measure window-resize CPU after T2986's burst canvas: release build, repeated perf-baseline resize samples, to prove the drop beyond the 50% tolerance or tighten the bar

## Summary

T2986 made a SetWindowPos burst paint the desk on the edge drag's canvas; `size-burst-canvas.ps1` proves the desk renders drop 29 -> 3 (grow) / 29 -> 0 (shrink). Its CPU criterion was left open: one Debug `perf-baseline.ps1 -Phase busy` run read 28.3% resize CPU against baseline-2's 32.2%, a 12% drop that sits inside the script's 50% `cpu_pct` tolerance, and no release build was measured. Build zig-out-release, take 3+ resize samples per build before and after (A/B with `GHOZTTY_DESK_NO_CANVAS=1` on the same build is the cleanest control), and record the mean and spread. If the spread is far under 50%, propose a tighter resize tolerance in `$script:Tolerance`.

## Validation criteria

- [ ] release and debug resize CPU, 3+ samples each, canvas vs `GHOZTTY_DESK_NO_CANVAS`, recorded with spread
- [ ] T2986's open CPU criterion ticked or explained from those numbers
