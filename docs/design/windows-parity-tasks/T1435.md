# T1435 - A degraded remote pill must not squeeze the tab strip out of the titlebar

## Summary

T1433 landed D93's answer: the remote connection pill now says `winbox - Reconnecting... 3/5`
instead of `Reconnecting... 3/5`, so a dropping link widens the capsule by the machine name's
width on top of the status it already showed (measured: 92 px -> 189 px at 1.25 on a
`127.0.0.1` window). The pill's width is what sets `band_left`, which is the seam the tab strip
lays out against, so every wobble now moves the tab run by more than it used to. The name is
held to `max_name_degraded_dip` (72 DIP) precisely so this cannot run away, but nothing
MEASURES the outcome: `test/win32/remote-pill.ps1` reads the pill's own width and never asks
what happened to the tabs beside it. Add the check - a remote window with several tabs, narrow
enough to be interesting, dropped and then recovered, with the tab strip still laid out and
hit-testable at both widths.

## In plain terms

When a remote window's connection drops, the little connection badge in the
titlebar grows to say "Reconnecting...", and on a window with several tabs it
shares that row with the tabs. Nothing checked what that growth does to the
tabs. Now a test opens a remote window with four tabs, drops and restores the
connection, and checks every tab is still there and clickable each time.

## Goals

- [x] A harness that stands up a remote window WITH tabs and drops/recovers its link
- [x] It measures the tab strip (published hit regions), not just the pill
- [x] It proves the strip gives up exactly the pill's growth and gets it back
- [x] Whatever it found wrong is filed (T2899 + decision D109)
