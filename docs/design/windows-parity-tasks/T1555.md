# T1555 - About box links are never proven to actually open anything

## Summary

T714 gave the win32 About box a row of hyperlinks (Release notes, Commit, Docs,
GitHub) and `test\win32\ipc-version.ps1` proves the controls are there, sized,
visible and carrying the right labels - but nothing proves that ACTIVATING one
reaches the right URL. Both the click and the Enter paths end in
`App.openUrl` -> `ShellExecuteW`, so an acceptance script that exercised them
would launch a browser on the test desktop on every run, which is why T714
stopped at the controls.

`ViewerPane.zig` already solved exactly this: under a test lane a link is
RECORDED as `<kind>:<target>` instead of reaching `ShellExecuteW` (see the
comment at `ViewerPane.zig:3406` and its T594 note). Extending that recording
to `App.openUrl` - or hanging it off the same switch - would make the About
row's destinations assertable on the box: activate each link, read the
recording back, compare it to the URL `about_links` says that build earns.

The two cases worth proving are the conditional ones, because they are the ones
a unit test can get right while the wiring is wrong: a release build's version
link resolving to `.../releases/tag/win-v<version>`, and Enter on a focused
link FOLLOWING it rather than dismissing the dialog (`handleKey` declines the
key for a focused link; nothing on the box checks that it still does).

## In plain terms

The About box now has clickable links. We have checked that they are there and
that they say the right things, but not that clicking one actually goes where
it claims - a test that clicked would pop a web browser open every time it ran.
There is already a trick elsewhere in the app for recording where a link WOULD
have gone instead of going there; this is about reusing it here.

## Goals

- [ ] Link activation is recordable under a test lane instead of reaching the shell
- [ ] The About row's destinations are asserted on the box, per link
- [ ] Enter on a focused link is proven to follow it and leave the dialog open
- [ ] A release-shaped build is proven to produce the `win-v` tag URL

## Validation criteria

- [ ] An acceptance script activates each About link and reads back the exact
      URL, with no browser launched
- [ ] A negative control proves the assertion can fail (a wrong expected URL
      makes the run red)
