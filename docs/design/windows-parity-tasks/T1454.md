# T1454 - Sweep the whole open backlog for duplicate clusters the new similarity check can see

## Summary

T651 gave the tracker a title-similarity check, but it only fires at FILING time - it says nothing about the duplicates already sitting in the queue, and the first probe found one defect filed eight times (see T1453). Add a mode that scores every OPEN task against every other and reports the clusters above the threshold, ranked by size, so daily triage (go.md step 0.6) can work the backlog down instead of only holding the line on new intake. Cheapest shape is parity-tasks.ps1 similar -All reusing Get-SimilarTasks; the cost is O(n^2) over ~450 open titles, which is fine at PowerShell speed if the idf table is built once. Acceptance goes in section S of test\win32\parity-tasks-seat.ps1.

## In plain terms

The task tracker could warn about a duplicate only at the moment a new task was filed; duplicates already sitting in the queue stayed invisible, so the same problem could be counted and worked several times. There is now one command that lists every group of open tasks that look like the same problem, biggest group first, and the daily triage runs it.
