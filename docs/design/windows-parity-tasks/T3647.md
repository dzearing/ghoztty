# T3647 - Once Windows releases are signed, the installed ghoztty.com is unsigned beside a signed ghoztty.exe: decide whether to sign it or carry it again

## Summary

T2071 made the MSI derive ghoztty.com from ghoztty.exe at install time (one PE header word flipped), stripping the Authenticode table because the flip invalidates it. While releases are unsigned (T1203 has no certificate) this changes nothing: the derived twin is byte-identical to the ZIP's. The day a certificate lands, the MSI's ghoztty.exe is signed and its derived ghoztty.com is not, so SmartScreen/Defender reputation for the CLI entry point (what a bare 'ghoztty' runs) differs from the app's. Options: accept it (the .com is never double-clicked; SmartScreen judges downloads, not installed files), or carry a separately signed .com again only in signed releases (+20 MB). Decide when T1203 unblocks; validate with verify-release-clean and a Defender scan of an installed signed release.
