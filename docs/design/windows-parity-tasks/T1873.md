# T1873 - A performable: binding that cannot perform from a focused viewer swallows the key instead of handing it to the page

## Summary

Mac's ViewerKeyFallback passes a performable binding that did not perform back to the page as if unbound. On Windows the accelerator decision is made synchronously in AcceleratorKeyPressed and the action runs one message later (close actions must not run inside the controller's Invoke), so a performable binding is claimed before anyone knows whether it performs. Example: the default ctrl+shift+arrow previous_tab/next_tab on a window with one tab is swallowed rather than reaching the page (pre-existing since T394). Fix shape: answer performability synchronously for the native arms that can say (tab count, split count) without performing. Validation: a one-tab viewer window, ctrl+shift+left reaches the page's key log.

## Validation criteria

- [ ] In a one-tab window, ctrl+shift+left at a focused viewer reaches the page's key log (viewer-window-chords.ps1 arm).
- [ ] With two tabs the same chord still switches tabs and the page never sees it.
