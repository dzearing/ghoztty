# T2411 - New Windows windows always fill the screen: the maximized placement is applied before the window shows, never moved to the last window's position or cascaded (Mac 7e2d0a9da)

## Summary

Mac main 7e2d0a9da: new windows fill the screen - the maximized frame is re-applied before showing, never moved to the last window's position or cascaded (NewWindowMaximizeTests). Windows already defaults to maximized (T2342); verify that every new-window path (Ctrl+Shift+N, sidebar + buttons, +new-window, restore of a non-maximized saved window excepted) shows maximized on first paint with no flash at a cascaded/last-window rect, and add an acceptance check either way.

## In plain terms

On Mac, new windows were sometimes opened a little lower than the screen's top, or at the last window's spot, even though they are meant to fill the screen. On Windows every new window already fills the screen; this task proves it with the same check the Mac side added, so it cannot quietly regress.

## Goals

- [x] Re-verify Windows against Mac's defect (cascade or last-position moving a maximized window)
- [x] Acceptance case in the Mac test's exact shape: smaller restored memory, three windows in a row

## Validation criteria

- [x] Three new windows over a smaller restored 900x600 memory (startup, background `+new-window`, `--focus` `+new-window`) are each maximized at the SAME frame as the first and cover the work area - test/win32/new-window-maximized.ps1 case D, acceptance-parallel run ALL PASS 23/23
- [x] Each still restores down to the remembered size (the maximize is real, not a big restored window) - same case D
- [x] Zoom oracle can read false - case C (maximize=false) stays the negative control

## Evidence

- Re-verified 2026-11-09: no product change needed. On win32 the cascade (Window.zig, `cascade_step` from the previous window) only moves the restored rect handed to CreateWindowExW; the first show is `SW_MAXIMIZE` (focused) or `maximizeHidden` + `SW_SHOWNA` (background, T1966), and both put the window at its monitor's maximized frame. So the Mac defect - a maximized frame stepped down by `cascadeTopLeft` or replaced by `NSWindowLastPosition` - has no win32 analog; the cascade lands in the restore-down rect, which is the native Windows behaviour.
- Case D measured all three windows at -9,-9 3858x2118 over a 3840x2100 work area, IsZoomed true, restore-down 900x600.
- First-paint flash at a cascaded rect is not measured: `SW_MAXIMIZE` on a hidden window and the hidden style-maximize both size the window before it is visible, so there is no shown restored frame to catch.
