# T1024 - divergence-inventory.ps1 still fetches upstream into FETCH_HEAD instead of using the now-permanent upstream remote

## Summary

T957 added a permanent 'upstream' remote, but scripts\divergence-inventory.ps1 still runs 'git fetch --quiet <url> main', which lands in FETCH_HEAD and keeps no ref - the exact condition T957 exists to end. Every sha the inventory reports is therefore reachable from nothing the moment the next fetch overwrites FETCH_HEAD, which is how the upstream pull plan's shas came to be gc-bait in the first place. It should prefer the 'upstream' remote (calling upstream-remote.ps1 ensure when it is missing) and resolve upstream/<ref>, falling back to the URL fetch only when the remote genuinely cannot be added. -NoFetch already resolves a local ref, so the shape is there.

## In plain terms

The monthly report that measures how far this fork has drifted from upstream
Ghostty fetched upstream in a way that kept nothing: the commits it named could
be garbage-collected later, so the upstream-pull plan built on them could quietly
point at nothing. It now fetches through the permanent `upstream` remote, so the
commits it names stay in the repository.

## Goals

- [x] the URL fetch into FETCH_HEAD survives only as a loud fallback when the remote cannot be added
- [x] a remote that cannot fetch is an ERROR, not a report of a stale upstream
