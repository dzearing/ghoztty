# T1772 - A window recovered late from the session manager comes back under a new name when the launch's blank window took its old one

## Summary

T1002 restores windows only the agent remembers once a late agent answers. The launch could not read their names in advance, so it cannot reserve them (T976 reserves only carried manifest windows), and the blank stand-in window mints window-1 first. The recovered window-1 then gets a freshly minted name (log: IPC window name 'window-1' is already held by another target; minting a fresh one), and when the untouched stand-in is closed a moment later the name window-1 is left free but unused. Scripts that target --target=window-1 land nowhere. Fix: when the deferred pass retires the stand-in, hand its recorded name back to the restored window that asked for it (or rebuild into the stand-in's name registration). Repro: phase E of test/win32/restore-late-agent.ps1.
