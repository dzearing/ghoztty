# T3804 - pane-stack-strip.ps1 D8 cannot see a banner card on the composition path: the window capture does not hold the pane's banner visual (T2559), so 'a strip with a banner is the same glass top to bottom' would pass over a card left on a strip

## Summary

Found by T2334 (2026-11-26). Since T2559 a glass pane's banner card is drawn on the pane's own composition tree (app log: banner path visual=true) and its GhozttyBannerOverlay popup is hidden. pane-stack-strip.ps1's D8 proves a tucked strip carries no card by (a) counting shown popups over the strip and (b) comparing two pixel rows of the strip against the desk beside them. On the visual path both are blind: (a) the popup is hidden whatever the visual does, and (b) Get-TestWindowPixels -Sync does not capture the DirectComposition visual - with s1 brought on show and its card logged on show, the rows read exactly the no-card glass (rgb(32,54,75) vs rgb(31,50,67), desk-relative 0 levels). T2334 made the positive control path-aware (log line + no popup on show), which is honest but leaves D8 unable to catch the regression it exists for on the default path. Fix: find a capture that includes the pane's composition visual off the input desktop (or an app-side oracle: a log line naming the banner visual's shown/hidden state per pane on tuck/unfold), then make D8 assert the tucked pane's banner visual is hidden and the shown pane's is visible.
