# T1047 - hero-nav.ps1 reads focus once after a fixed sleep, the shape T342's flake came from

## Summary

Found while fixing T342. Focus in this app is asynchronous twice over - the
app's `SetFocus` is deferred (T48) and the dialog manager moves focus on the
app's own message loop - so a script that sleeps a fixed time and then reads
`Get-TestFocusedWindow` ONCE is racing the move, and reads the previous window
whenever the box is busy. That is precisely the shape T342 was filed for, and
its fix (poll for the move) is now in `Focus-ChooserControl`.

The instance this was filed for:

- `test\win32\hero-nav.ps1:488-489` - `Start-Sleep -Milliseconds 1200` then a
  single `Get-TestWindowClass -Window (Get-TestFocusedWindow ...)`. 1200ms is
  more forgiving than T342's 300ms, which is likely why it has not been seen
  red, but it is the same coin toss.

**Evidence refreshed at HEAD 2026-09-09 (T676 sweep), and the scope was
wrong.** The line numbers moved (`:464-465` -> `:488-489`), and "the remaining
instance in the suite" is no longer true: `grep -B2 Get-TestFocusedWindow` over
all of `test\win32` now finds the sleep-then-read-once shape in **15 files, ~38
sites** — heaviest are `activity-monitor.ps1` (16), `viewer-panes.ps1` (5),
`activity-monitor-remote.ps1` and `new-window-cwd.ps1` (2 each), with one apiece
in `activity-selection.ps1`, `agent-upgrade.ps1`, `clipboard-paste.ps1`,
`focus-follows-mouse.ps1`, `hero-nav.ps1`, `kb-actions.ps1`,
`local-split-no-command-rerun.ps1`, `mouse-nc-routing.ps1`,
`remote-inherit.ps1`, `test-desktop-harness.ps1`. Not all are defects —
`focus-defer.ps1`'s two hits are its own poll loop — so this is a list to
triage rather than a count to fix, but the card can no longer be planned as a
one-line change to `hero-nav.ps1`.

`test\win32\focus-defer.ps1` is the pattern to copy (it polls), and
`Wait-TestFocus` in `lib\TestDesktop.ps1` already exists for the case where
the EXPECTED window is known - which is the case here.

## In plain terms

A test that checks "the keyboard went to the right window" waits a fixed
moment and then looks once. If the machine is busy that moment is too short
and the test sees the old answer, so it fails for a reason that has nothing to
do with the product. Nothing is failing today; this is the same trap that
already cost one investigation, closed before it costs a second.

## Validation criteria
