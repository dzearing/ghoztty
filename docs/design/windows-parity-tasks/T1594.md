# T1594 - The pty-holder pipe namespace carries no lineage, so one agent's orphan sweep can shut down another lineage's live holders

## Summary

src\remote\agent\pty_host.zig defaultPipeName builds the holder control pipe as 'ghoztty-pty-host[-debug]-<USERNAME>-<session-id>' - no GHOZTTY_AGENT_INSTANCE segment, unlike the agent pipe, the guard mutex, the state dir and the holder's own --spec path (T167/T691 moved all of those). So holder_adopt.reapOrphans enumerates EVERY holder on the box in its build mode, and anything its own sessions.json does not claim is an orphan it shuts down - taking the shell subtree with it, since the holder owns the kill-on-close job. Two lineages of the same build mode therefore reap each other. Measured under T1593 on 2026-09-15: a sandboxed ReleaseFast agent with an empty roster probed the box's real live release holders as orphans. Nothing died only because a busy pipe refuses the dial, which is now the explicit rule (orphan_busy_budget_ms = 0) rather than an accident - but a holder caught momentarily free is still killable. The fix is to put the lineage in the pipe name the way every other endpoint carries it, and to teach the sweep that a name outside its own lineage is not its business. Ordering hazard: a recorded name in sessions.json is dialed verbatim, so only the PREFIX match in reapOrphans and the names NEW holders take may change - an agent upgrade must keep dialing the old names.

## In plain terms

A Ghoztty window keeps your shells alive in little background processes, one per
persistent session, and when the session manager starts up it tidies away any it
cannot account for — killing the shell underneath. Until now those background
processes were only labelled with your username, so a *test* copy of the session
manager (which knows about none of your real sessions) looked at your actual
running shells, decided they were abandoned, and tried to shut them down. It was
one unlucky moment of timing away from closing panes you were working in. Now
each copy labels its own processes, and will not touch anything that is not its
own.

## Goals

- [x] The holder control pipe carries the agent lineage, the way every other
      per-lineage endpoint already does.
- [x] A production run's pipe name is byte-for-byte what it was, so an agent
      upgrade keeps finding the holders it recorded.
- [x] The orphan sweep cannot see — and therefore cannot end — a holder
      belonging to any other lineage, in either direction.
- [x] No lineage name can be mistaken for another by prefix.
