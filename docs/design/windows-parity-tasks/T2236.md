# T2236 - next's CHECK FIRST misses an already-fixed task whose card names a code identifier but no concrete file path

## Summary

T1337 named diffNavOverflow and src/apprt/win32 (a directory); next reported 0 commits since, yet 91cf69005 had fixed it 13 days after filing. CHECK FIRST should also run git log -S for backticked/camelCase identifiers in the Summary (and treat a directory path as a prefix), so an already-fixed card is flagged before a turn re-builds it. Acceptance: a parity-tasks-seat section that files a card naming only an identifier a later commit added, and asserts CHECK FIRST names that commit.

## In plain terms

When the loop picks up a task, it first asks "has anything changed the code
this task is about since it was filed?" so it does not rebuild a fix that
already exists. That check only looked at file names, so a task that named a
function or message (like `diffNavOverflow`) was reported as untouched even
when a later commit had fixed it. Now it also searches history for the names
of the code the task mentions.

## Goals

- [x] `next`'s CHECK FIRST counts commits that added or removed an identifier the card names (git pickaxe)
- [x] a directory the card names scopes that search (it never counts on its own - the hub-file trap stands)
- [x] noise kept out: tracker docs, common tokens (>25 files), and tokens that are a tracked file's stem
- [x] acceptance section in parity-tasks-seat

## Decisions

- **Directory "as a prefix" means scope, not a signal.** The card asked for a
  named directory to be treated as a path prefix. Counting every commit under
  `src/apprt/win32` is exactly the hub-file trap Get-TaskCodePaths' comment
  records (17 cards at 300+ touches), so a directory instead narrows the
  identifier search; with no directory named it covers the code roots.
- **`next` only, not `stale-scan`.** One pickaxe pass costs 3-7s on this repo;
  once per pick is fine, 400 cards in a sweep is not. stale-scan's `named=`
  rows already cover the commonest already-fixed shape.
- **A file stem is not an identifier.** The first cut flagged T2238 with ten
  commits for `chrome_reposition` (the module chrome_reposition.zig), every
  one an import shuffle from a file split; the file signal owns that name.
