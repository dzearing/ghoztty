## In plain terms

A self-check that runs whenever the test scripts change kept failing when the
machine was busy and passing when it was quiet, and its report didn't say why.
The cause was one test clicking the same link three times in a row: under load,
the browser engine inside the viewer quietly ignored the repeated click. The
test now clicks a slightly different link each time, and a failing check now
prints which assertion failed and where its full log is.

- [x] Find why test-reach-audit is red inside the sweep and green alone

## Root cause

test-reach-audit B1 runs the whole win32 zig lane. In the sweep, the lane failed
in `ViewerPane` "host floor" at the T926 legs 4/5 (`waitFor(... Leg.routed(6|7))`,
30s, routed stuck at 5). Instrumented: the `ExecuteScript` ran and returned
`clicked https://ghoztty-page/t825-one.html`, yet no `NavigationStarting` was ever
raised. Chromium drops a click on a link whose previous navigation to that SAME
URL was cancelled a moment earlier. Reproduced 3/3 with 32 busy-loop processes
saturating the box, and 2/2 green with a 3s pause before each click. For a real
user this only means a quick repeat click on the same link is ignored, so the
defect is in the test.

Fix: legs 4 and 5 click `<page_url>?leg=4` / `?leg=5` (distinct URLs; same
off-site route), with the expected routed strings updated to match.
