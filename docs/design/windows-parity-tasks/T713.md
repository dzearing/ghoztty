# T713 - Relay sign-out on Windows does not close account remote windows or block new dials

## Summary

Mac's ed8482d25 makes sign-out close every remote window that was authenticated by the account and refuse new dials until sign-in, with sign-in restoring them. The win32 RelayAccountRow.signOut clears the DPAPI store only, so windows dialed on the signed-out account keep running and a fresh dial can still be attempted. Found by the T684 sweep.

## In plain terms

Signing out of your Ghoztty account used to leave every window you had opened
on another machine sitting right where it was - still connected, still showing
that machine's shells - even though the account that opened them was gone. Now
signing out closes those windows and leaves everything else alone: a window you
opened by typing a host and a port is yours, not the account's, and it stays.
The work on the other machine keeps running; nothing is killed. Sign back in
and the windows the sign-out took away come back.

## Goals

- [x] Sign-out closes every window the account opened, and nothing else
- [x] The sessions those windows held keep running on the machine that hosts
      them (built on T1390's detach pin; on-box oracle is T1554)
- [x] Signing back in brings those windows back
- [x] Nothing new can be dialed on the account while signed out

## Validation criteria

- [x] `relay_signout.isAccountBacked` says yes only for a relay window - a
      direct-TCP window and a local window are untouched (unit test, win32 lane)
- [x] The suspended store keeps one row per machine, unions session ids, drops
      empty ones, and is CONSUMED by the restore so one sign-out replays once
      (unit tests, win32 lane)
- [x] A sign-in replay rebuilds only the windows holding suspended sessions;
      with no filter it is still the chooser's whole-machine Restore All
      (`RestoreAllRelay.windowIsWanted` unit tests, win32 lane)
- [x] On the box, against a live relay + agent: a GUI sign-out closes the
      account-backed window, leaves a local window open, and a fresh relay dial
      is refused (`test\win32\relay-account.ps1` section 7b, ALL PASS, guard
      re-stamped)
- [ ] NOT measured here: that the far session kept running. The close reuses
      T1390's `DetachPin`, which `remote-disconnect.ps1` proves spares a far
      session; section 7b cannot see it (the agent's shells escape the process
      tree and `--relay` mode writes no session roster). T1554 carries it.
- [x] Floor green: `scripts\floor-lane.ps1 -Lane all`
