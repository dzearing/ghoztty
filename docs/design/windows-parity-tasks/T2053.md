# T2053 - remote-pill.ps1: the app under test dies with exit -1 right after start, so +new-remote-window finds no instance and the script scores 0 checks

## Summary

Seen 2026-10-17 during T1036 (lane b): 3 of 4 runs of remote-pill.ps1 ended 'SETUP FAIL: +new-remote-window exit 1 - No running Ghoztty instance found', with GUI POSTMORTEM 'CRASHED - 0xFFFFFFFF', no WER record, and stderr ending mid-stream after a pane-sidebar tips line. The 4th run (beside other scripts) got 11 checks in before failing on GetWindowRect. Control: HEAD's unmodified copy of the script fails identically, run serially at width 1, so T1036's one-line agent assert is not the cause. The guard was last stamped green 2026-10-14 (5cbfb36f3), so something since then or box state. First step: crash-catch.ps1 on the app launch to get a first-chance stack.

## In plain terms

Tests on this box kept reporting that the app "crashed" seconds after it
started, and only some of the time. The app was not crashing. One test in the
other loop's copy of the repo cleaned up after itself by killing every test
copy of Ghoztty on the machine, including the ones this loop was testing at
that moment. That test now only cleans up its own processes.

## Root cause

`0xFFFFFFFF` is exit code -1. That is the code PowerShell's `Stop-Process`
(.NET `Process.Kill`) passes to `TerminateProcess`, and no code path in the app
exits with it. A Zig panic or segfault handler exits 3, and a real fault exits
with an NTSTATUS. `agent-upgrade.ps1`'s `Stop-TestProcs` killed every
`ghoztty.exe` and `ghoztty-agent*` whose **command line** contained `zig-out`.
That matched lane B's app and agent (`D:\git\ghoztty-b\zig-out`) and every
parallel worker's mirror (`D:\git\.ghoztty-b-par\wN\zig-out`). It ran at the
start and end of each arm, so it fired many times per run.

Evidence: every lane-B `CRASHED 0xFFFFFFFF` on 2026-10-17 between 09:07 and
09:21 falls inside a lane-A `agent-upgrade.ps1` run. Those runs are the
acceptance-parallel dirs `085119`, `085749`, `090415` and `091450` (repo
`D:\git\ghoztty`), back to back from 08:51 to 09:20:29. The remote-pill run
that got 11 checks in shows the loopback agent's connection dropping first
(`ConnectionRefused`), with the app gone 3 s later. That is the
agent-then-app order of the kill loop. The script had been exempt from the
clean-slate audit, because of its `LIKE` pattern.
