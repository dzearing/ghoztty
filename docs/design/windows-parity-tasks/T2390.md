# T2390 - Frame lab output (T2373): stamp JSON (pass/fail per interaction x matrix cell with every metric, SlotGaps beside AdvanceRate) for the harness audit, plus an HTML report with an advance-rate/stall chart per interaction and a filmstrip of the worst frames with failing pixels outlined

## Summary

Split out of T2384 (2026-10-28); see T2373's Output section for the design. Inputs: T2389's per-cell results (FrameScore motion/bleed metrics, FrameCapture Stats incl. SlotGaps and the accounting run's skipped count) and the T2384 driver stamps via ConvertTo-FrameLabInputStamps (times in us from the first planned point, plus originQpc to line them up with frame slots). Filmstrip frames come from FrameCapture's kept PNGs (failing + 1% sample).

## In plain terms

The frame lab photographs every frame the screen shows while it drags the
window around, and scores each one. This card turns those scores into two
things: a results file a script can check (did anything bleed, was the motion
smooth, did we actually see every frame) and a page a person can read at a
glance, with a chart per gesture and the worst frames shown with the bad
pixels boxed.

## What landed

`test\win32\lib\FrameLabReport.ps1`:

- `ConvertTo-FrameLabCellRecord` - one `Invoke-FrameLabCell` result as a plain
  record: knobs, verdict, reasons, every FsMotion metric with **SlotGaps
  written beside AdvanceRate**, bleed findings counted by class, input timing
  (lateness p50/p95/max, achieved Hz), capture counts (superseded, queue
  drops, scorer errors), the accounting run. NaN becomes null.
- `New-FrameLabResults` / `Write-FrameLabResults` - the results JSON (schema
  `ghoztty-frame-lab-results/1`), run verdict DERIVED from the cells: fail >
  incomplete > pass, and a run that measured nothing is `no-result`, never pass.
- `Test-FrameLabResults` - the harness audit's reader: re-derives the verdict
  and refuses a disagreeing verdict, an unknown cell verdict, a measured cell
  without SlotGaps/AdvanceRate, a pass with nothing measured, a missing file.
- `New-FrameLabReportHtml` - self-contained page: verdict tiles, per
  interaction an SVG chart (advance rate vs 0.98, longest stall vs 1, misses in
  red) and a per-cell table, then a filmstrip of the worst frames (ranked by
  failing pixels, then class) with the PNG embedded as a data URI and each
  finding's box outlined in its class colour.

Design call (mechanism): GfcScorer is a bool, so per-frame findings for the
filmstrip come from the driver's Score block as an optional `Frames` list
(`Index; Png; Findings[Cls, Target, Detail, Pixels, At]`). T2392's live driver
must fill it, and must write the results file + report with these functions;
noted on T2392.
