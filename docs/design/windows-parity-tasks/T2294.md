# T2294 - Mac keepFocusOnShow can hand the caret to a pane folded inside a nested stack: a row drag that folds the focused pane picks the target item's most recent pane by rank alone (Windows fixed in T2284)

## Summary

`BaseTerminalController.keepFocusOnShow` (origin/main) moves the caret, when a row drag folds the focused pane, to the nearest item still on show and within it to `candidates.min { rank }`. When that item is a column whose own row is stacked, the most recently focused pane in it can be a strip of that nested stack, so the caret lands on a folded pane (the layout then brings it back on show, restacking the column under a drag of a different row).

Evidence: the Windows port (`stack_drag.zig` `focusAfterRestack`, a line-for-line port) failed `pane_stack_fuzz` seed 480 on exactly this once T2284 lowered the pane minimum: focus 5 folded, target item {9, 11}, rank picked 11, a strip of the column's nested row. Windows fix (T2284): prefer a candidate not minimized in any stack other than the drag's own row (`PaneStackState.stackMinimizing`), rank breaking ties, rank alone as the fallback.

Fix on Mac: the same preference in `keepFocusOnShow`, using the stacks the last layout noted, plus a unit test of a column whose nested row has its most-recent pane folded.

## Validation criteria

- [ ] a row drag that folds the focused pane beside a column with a stacked nested row moves the caret to the pane on show in that column (unit test)
- [ ] PaneStackFuzzTests / PaneLayoutTests stay green
