# T1798 - Exited shells in session-persistence panes are tombstoned on Windows

## Summary

Mac commit c6619717b (merged 7e58ccbdd, 2026-10-10). On POSIX the agent's only
reap check was the pty reader's EOF nudge, which usually fired before
`waitpid` could collect the child. The session stayed `alive` over a zombie:
the pane showed its last output, rejected input (`pty input write failed:
error.InputOutput`) and never reported the exit. The fix is all in shared
`src/remote/agent/`: the reader waits up to 500ms for the exit to become
reapable before nudging, and the reaper tick sweeps every alive session
(`SessionStore.reapExited`), framing EXIT outside the store lock.

Windows has no zombies, but the agent runs ConPTY children through the same
`session.zig`, and ConPTY's output pipe does not reach EOF when the child
exits (conhost keeps it open until `ClosePseudoConsole`). So the Windows
question is the same one from the other side: does a ConPTY child that exits
always get framed as EXIT? Verify that `reapExited`'s liveness test resolves
to a process-handle check (`WaitForSingleObject(h, 0)` / `GetExitCodeProcess`)
on Windows rather than a POSIX-only `waitpid`, and that the tick covers it.

## Validation criteria

- [ ] After T1796: in a persistence pane, `exit` (pwsh and cmd) and a
      delayed exit (`ping -n 3 localhost & exit`) each show the pane as
      exited within ~1s, `+sessions` lists the session as a tombstone, and
      typing produces no `input write failed` in the agent log.
- [ ] A child that closes its console and exits later is still reaped by
      the tick (the c6619717b "guarantee" case).
- [ ] An agent-lane unit test covers the Windows liveness branch;
      `floor-lane.ps1 -Lane agent` green.
- [ ] The acceptance script runs on the background test desktop and takes
      no foreground.
