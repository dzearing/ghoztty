# T1961 - Refuse a stale zig-out before any acceptance script starts, and run the changed feature's own acceptance first so a red stops the turn before the lanes (T1955 items 6-7)

## Summary

build-fresh-guard.ps1 exists but runs inside the harness floor, after the GUI tests have already measured a stale zig-out. Run the freshness check (and rebuild) before any acceptance script in the turn. Then order the turn to fail fast: the changed feature's own acceptance first, stopping at the first red, before the lanes and the floor. Write the order into go.md step 3.

Split out of T1955 (P0, user 2026-10-14: 'feels like the tasks are getting slower ... selectively run things?'). The measurements and the ranked plan are in T1955.md.

## In plain terms

When the loop tests its work, it used to sometimes test an out-of-date build:
every test then failed (or, worse, passed) for a reason that had nothing to do
with the change, and the whole batch had to be re-run. Now the test runner
checks the build once before anything starts and rebuilds it if needed. And the
turn tests the thing it just changed first, stopping at the first failure, so a
mistake costs minutes instead of a full half-hour sweep.

## Goals

- [x] The acceptance runner settles build freshness once, before any script starts (rebuild once, or refuse with nothing launched).
- [x] `-FailFast` stops starting scripts at the first red and names what it skipped.
- [x] `due` runs the most specific (changed feature's own) harness first.
- [x] go.md step 3 gives the fail-fast order.

## Design

- `scripts\lib\AcceptanceFresh.ps1` `Invoke-AcceptanceFreshPreflight` reuses
  BuildFresh's predicate (`Test-GhozttyFreshBuild`) and builder
  (`Invoke-GhozttyDebugBuild`) about the one exe every worker hard-links. Stale
  or missing -> rebuild once + witness (so a build that relinks nothing clears
  it); failed rebuild or `-NoRebuild` -> exit 4, nothing launched.
  `GHOZTTY_TEST_ALLOW_STALE=1` is honoured loudly, as the per-script gate does.
  The per-script gate (T1028) is unchanged and still stands behind it.
- Default is REBUILD, not refuse: the turn's job at that point is to test the
  tree as it stands, and a refusal would only make the agent type the same
  build command. `-NoRebuild` exists for a caller that wants the refusal.
- `Invoke-AcceptanceRun -FailFast`: on the first red row, the pending queue is
  cleared and no exclusive script starts; running ones finish and the red is
  still confirmed alone. The runner prints `NOT RUN (...)` and a run that left
  scripts unrun is never GREEN (exit 1).
- `Get-AcceptanceDueJobs` sorts by covered-file count (ties in guard order): a
  3-file row is a feature's own harness, a 400-file row is a sweep.
- Incidental fix: the runner threw at the end of a run over a `-Repo` that is
  not a git checkout (PS 5.1 Stop + native stderr from `git rev-parse`).
