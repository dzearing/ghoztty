# T2524 - Windows pane sidebar: an Ungrouped header pins over the lone windows whenever a group exists, folds like a group, and its +, x and pencil open an ungrouped window, close them, or name them all as a group (Mac 7bee055c9)

## Summary

Mac 7bee055c9 (PaneSidebarWindowGrouping.headsUngrouped): with at least one group and one lone window, the lone windows sit under a sticky 32pt 'Ungrouped' header with the group header's count and hover tools. Pinned on top, never dragged, not in windowOrder; a click folds it (shared fold state, not persisted; a group drag leaves it as it is). Its + opens a new untitled window from its first window as listed; its x closes its windows (the matching ones while searching); its pencil names them as a group: an empty field (placeholder 'Group name') retitles each '<name>: <title>', pinned, and the new group stands first among the groups, or, named as an existing group, they join it ahead of its windows. Not in the rail, not in this window's own Panes list. No group or no lone window: flat list, no header. Mac reference: docs/reference/pane-sidebar.md; PaneSidebarSyncWindowTests.ungroupedHeaderCaptures.

## In plain terms

In the all-windows sidebar, as soon as you have one named group of windows,
the windows that belong to no group now sit under their own "UNGROUPED"
heading at the top, with a count. You can fold them away, add a new
ungrouped window, close them all, or give them a group name in one go -
the same buttons a group's heading has. Mac shipped this on 2026-10-30.

## Goals

- [x] An Ungrouped header heads the lone windows whenever a group exists; none otherwise
- [x] It folds and unfolds them on a click, and is never dragged
- [x] Its + opens an untitled window that lands among them
- [x] Its x closes them (the matching ones while searching)
- [x] Its pencil opens an empty field ("Group name"): a new name makes them that group where they were; an existing group's name has them join it ahead of its windows
- [x] Not in the rail, and not in this window's own list

## Design (recorded, not a decision)

- The header is a project head whose window has no project (Mac:
  `PaneSidebarProjectHeader` with `project == nil`), so every project-head
  path - layout, sticky band, hover tools, fold transition, close-by-key -
  serves it unchanged. `pane_sidebar_outline.headsUngrouped` decides it;
  `buildLines` emits it once before the first lone window, with the lone
  windows a level in.
- Its fold lives in the shared project-fold set under the reserved key 0
  (a lone window's `project_key`): shared by every window's list, not
  persisted, and a group drag folds only the projects it names - matching
  Mac's `isUngroupedFolded`.
- Its pencil is a new rename target (`.ungrouped`); `rename_rules.namesGroup`
  refuses a name that could not read back as a group, and the order is kept
  with `window_order.renamingWindow` from the first lone window (inserts the
  new group's key there, or leaves the order so they join an existing one).
- Excluded from item drags (never a source, never a row a window can be let
  go into).
