# T2605 - An agent running inside an installed Ghoztty can discover the Ghoztty skill without the web: the app exports its skill location and a pointer README (env var in every pane + a well-known file + 'ghoztty +agent-setup' / '+help agents' that prints where the skill is and installs it for the calling agent), so no agent ever falls back to the archived ghoztty-claude-plugin repo

## In plain terms

A coding agent (Claude Code, Copilot) started inside Ghoztty had no way to
learn that Ghoztty ships its own skill. Asked to find it, Claude searched the
web and found only the old, archived plugin repository with out-of-date
instructions. Now every Ghoztty pane tells the agent where to look, and one
command prints the skill or installs it, offline.

## Goals

- [x] every pane's environment carries a hint naming the setup command
- [x] `ghoztty +agent-setup` explains the skill, prints it, and installs it for Claude Code or Copilot
- [x] `ghoztty --help` lists it
- [x] the Mac half filed (T2612)

## Summary

Point 3 of the 2026-11-01 user report (points 1-2 are T2604 and the repo
archive). Delivered:

- **`ghoztty +agent-setup`** (shared CLI, `src/cli/agent_setup.zig`): no flags
  prints a pointer README (what Ghoztty lets an agent do, that the skill is
  bundled, a warning off the archived `dzearing/ghoztty-claude-plugin`, and the
  exact commands); `--skill[=<file>]` prints SKILL.md or one reference file in
  the wording this platform installs; `--install=claude|copilot` runs the same
  install as "Set Up Agent Integrations..." (`agent_integration_service.install`).
  No IPC, so it works with the app closed.
- **`GHOZTTY_AGENT_SETUP=ghoztty +agent-setup`** baked into every win32 pane
  through the surface config `env` seam (`src/apprt/win32/Surface.zig`), which
  reaches exec, agent-backed and relaunched panes.
- The agent home + probe moved out of `AgentIntegration.zig` into
  `agent_home.zig`, so the CLI and the dialog cannot disagree on where a skill
  goes (and `GHOZTTY_AGENT_HOME` sandboxes both).

Decision (mechanism, mine per go.md 5b): the verb installs in-process rather
than over IPC, so an agent can set itself up even when the pane it runs in
belongs to a different build or no app answers. A well-known `AGENTS.md`
beside the install was not added: the env var + `--help` reach the agent
wherever it looks first, and a loose file would change the MSI/zip shape.
