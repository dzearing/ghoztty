# T815 - The agent lane STALLed under -Lane all and passed alone minutes later, with no diagnostic block to say which

## Summary

2026-08-12, T462's floor run: 'scripts\floor-lane.ps1 -Lane all' reported none#1=PASS win32#1=PASS agent#1=STALL after 763s; re-running 'floor-lane.ps1 -Lane agent' immediately afterwards passed in 326s with the tree otherwise identical. Two things to settle. (1) Is it real? A stall that only appears as the THIRD lane of a run points at contention or at a wedge the two earlier lanes arm, which is exactly what T401 warns about for acceptance scripts and does not currently say about lanes. (2) The report was unusable either way: the STALL line printed the last log line and nothing else - no process tree, no per-thread wait reasons - though floor-lane.ps1's whole reason to exist is that a wedge comes WITH a diagnostic. Reproduce with -Lane all -Repeat, and check whether the diagnostic block is skipped, empty, or swallowed by the transcript.

## In plain terms

When the test suite is run, one of its lanes can hang instead of finishing. The
run says `STALL` and then, at the bottom where anyone actually reads, says only
that the lane "died without an error line (crash, stall, or a kill)" - three
different problems offered as one answer, even though the run already knew which
one it was. All the evidence that would tell a hang from a merely slow test was
printed thousands of lines earlier and is gone by the time anyone looks. After
this, the bottom of a wedged run says WEDGED in so many words and carries the
snapshot the watchdog took - which lane, which processes, what each thread was
waiting on - so a hang is diagnosable from the last screenful.
