# T3796 - On Linux under WSLg, closing a window while the app keeps running may freeze the whole app: the same Mesa d3d12 hang T3656 found in quit teardown (gtk_widget_unrealize -> gdk_gl_texture_release -> futex) can strike any window destroy

## Summary

T3656 traced a quit that never finished to Mesa's d3d12 driver (WSLg) blocking forever inside gtk_widget_unrealize -> gdk_gl_texture_release -> a libgallium futex wait, about one window-mode.sh run in three. The quit now has an 8s backstop, but an ordinary window close (the window's close button, +close of a window's last pane) runs the same unrealize path with the app still running, and there no backstop can help: the main thread would hang and every window freeze. Check: loop a headless harness that opens two windows with GL surfaces and closes one (20+ times) and attach gdb (installed; docs/claude/linux.md Crash diagnostics) to any app whose IPC stops answering. If it reproduces, find what makes the GL texture download block (a fence on a context already gone? the GLArea texture still held by the renderer?) and avoid it before unrealize.
