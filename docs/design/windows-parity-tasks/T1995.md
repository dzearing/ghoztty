# T1995 - The dashboard's per-lane rows (T1984) are rendered by no DOM harness: dashboard-dom never stages two lanes, so a broken laneRows() ships green

## Summary

T1984 added `lanes` to the dashboard payload (`lanesState()` in
`scripts\task-dashboard.js`, proven by `test\win32\loop-lanes.ps1` E6 through
`--loop`) and `laneRows()` to the loop card in `task-dashboard.page.html`,
which renders one line per lane when two or more exist. That page half has no
harness: `test\win32\dashboard-dom.ps1` stages one lock, so `laneRows()`
returns nothing in every run and a typo in it would only surface on the day
lane b comes up (T1986).

Fix: give dashboard-dom a two-lane fixture (a payload with `lanes` of length 2,
one stopped, one with a claimed task) and assert the rendered rows; and the
single-lane case renders no lane row.

## Validation criteria

- [ ] dashboard-dom renders one `[data-lane]` row per lane for a two-lane payload, naming each lane's state and task.
- [ ] A one-lane payload renders no `[data-lane]` row (negative control).
