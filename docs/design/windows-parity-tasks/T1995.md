# T1995 - The dashboard's per-lane rows (T1984) are rendered by no DOM harness: dashboard-dom never stages two lanes, so a broken laneRows() ships green

## Summary

T1984 added `lanes` to the dashboard payload (`lanesState()` in
`scripts\task-dashboard.js`, proven by `test\win32\loop-lanes.ps1` E6 through
`--loop`) and `laneRows()` to the loop card in `task-dashboard.page.html`,
which renders one line per lane when two or more exist. That page half has no
harness: `test\win32\dashboard-dom.ps1` stages one lock, so `laneRows()`
returns nothing in every run and a typo in it would only surface on the day
lane b comes up (T1986).

Fix: give dashboard-dom a two-lane fixture (a payload with `lanes` of length 2,
one stopped, one with a claimed task) and assert the rendered rows; and the
single-lane case renders no lane row.

## In plain terms

The task dashboard shows one line per go-loop "lane" when more than one loop
runs on the box. Nothing tested that those lines actually appear, so a typo
in them would only be noticed by someone staring at the dashboard. Now the
dashboard's browser test feeds it two lanes and checks both lines, then one
lane and checks the lines go away.

## Goals

- [x] The dashboard browser test serves a fixed two-lane payload, whatever lanes this box really runs.
- [x] It checks each lane's line (state, turn, claimed task by title, supervisor) and that one lane shows no line.

## Validation criteria

- [x] dashboard-dom renders one `[data-lane]` row per lane for a two-lane payload, naming each lane's state and task. - `test\win32\dashboard-dom.ps1` C64-C66, ALL PASS (78 assertions) 2026-11-23.
- [x] A one-lane payload renders no `[data-lane]` row (negative control). - C67, after `/api/_unblock` drops the fixture to one lane; same run.
- [x] The new checks can go red: with `laneRows()` forced to return nothing, the same harness reported C64/C65/C66 FAIL (3 failures, 75 passed); page then reverted byte-for-byte.
