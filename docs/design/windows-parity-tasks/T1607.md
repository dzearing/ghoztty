# T1607 - A tab's hover tooltip repeats the folder twice when the tab title is already the folder

## Summary

tab-tooltip.ps1 sections A and E are red: the T556 two-line tip shows title AND cwd even when the title fits on its own, so a tab whose title IS the folder path reads the same path twice - once raw, once ~-shortened.

## In plain terms

Hovering a tab whose title is just its folder used to show that folder twice
in the tooltip - once in full, once shortened with `~`. It now shows it once.
This was already fixed by an earlier change; this card only confirms it.

## Goals

- [x] the tooltip names a folder-titled tab's folder once
- [x] a genuinely cut-off title still gets its own line above the folder

## Validation criteria

- [x] section A green: the tip names the start directory once, `~`-shortened - `test\win32\tab-tooltip.ps1` 2026-09-25 on a fresh Debug build
- [x] section E green: a title that fits keeps the tip cwd-only, and an elided title gets its own line above the cwd - same run
- [x] section G green: a title that only restates the cwd is not rescued - same run; ALL PASS (29 assertions)

## Resolution

Already fixed by ec17471fb (T1622, 2026-09-16): `tab_tooltip.tipTextTitled`
drops a title line that only restates the location. T1606 (4eb4bb746) then
widened the tab-tooltip guard row so this cannot go unnoticed again. No new
code here; the re-run above is the validation this card was owed.
