# T2572 - Composition step 5c-3: the stack glide is declared to DirectComposition - each card edge's 45 ms follower approach as cubic pieces on the pane visual's offset and clip - so a stalled UI thread no longer stops a fold mid-motion

## Summary

Split of T2554. After 5c-2 the visuals move but are stepped from the UI thread's frame clock. Declare the follower instead: an edge from x0 to target closes 1 - exp(-t/45ms) and snaps within 0.5 px, so its whole path is known at declaration (end at tau*ln(|d|/0.5)); fit it with comp_overlay.fitCurve (T2551) onto IDCompositionAnimation on OffsetX/OffsetY and the clip rect's edges. A retarget (a drag reshaping the row, Slide.retarget) re-declares every edge from the value its curve has reached now, the way BellBorder's retarget reads the reached opacity. The UI tick shrinks to a landing timer that runs endStackSlide. Debug seam to inject a UI stall at glide start (the GHOZTTY_DEBUG_BELL_FADE_STALL_MS shape). Oracle: per-window WGC capture advance >= 0.98 at 120 Hz with a 500 ms UI stall injected (T2463 / bell-fade-onscreen.ps1 technique), stepped arm freezes; T2485 chain-fold film 0 bad frames. Needs an idle box for the filmed half (T2552's finding).
