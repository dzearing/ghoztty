# T1586 - A pane with no known folder turns a banner's dot-relative path into a link to the drive root

## Summary

T539/T758 follow-up: a pane whose cached working directory is the EMPTY string is not null, so BannerOverlay.setText hands banner_markdown a non-null cwd of length 0 and joinPath turns .\a.txt into \a.txt - a link to the root of the current drive. T539's rule is that a dot-relative path with nothing to resolve against stays PLAIN TEXT rather than becoming a link that goes nowhere. The empty string arrives from IpcHandlers' +list seed, which writes surface.setPwd(copy orelse "") on purpose so a pane with no pwd is not re-asked forever. Fix is to treat an empty cached pwd as absent where PathContext is built, with a unit test in banner_markdown and an assertion in section 6k.

## In plain terms

A status banner can show a path like `.\build.log`, which should open the file
next to wherever the pane is. When the terminal does not know which folder the
pane is in, that path used to become a link to the top of the drive instead —
clicking it took you somewhere the text never meant. Now such a path stays
ordinary text until the pane's folder is known, which is what the Mac does.

## Goals

- [x] a banner's `.\…` / `..\…` / `~\…` path with an empty (unknown) folder stays plain text
- [x] a viewer opened from a banner link does not inherit an empty folder as its origin
- [x] absolute paths and URLs keep linking regardless

## Validation criteria

- [x] `.\a.txt`, `../a.txt`, `~/notes.md` produce no link with `cwd=""`/`home=""`, and `D:\out\a.txt` still does — new asserts in `banner_markdown.zig` "autolink: home and cwd resolve, and stay text without them"; `zig test src\apprt\win32\banner_markdown.zig` 33/33 green.
- [x] the test can fail — negative control: the same file with `nonEmpty` returning the empty string fails exactly that test (32 passed, 1 failed).
- [x] floor lanes (`scripts\floor-lane.ps1 -Lane all`) green.
- [x] Section 6k end-to-end assertion: NOT added, on purpose. Producing a pane whose cached folder is the empty string needs the OS-level cwd read to fail for a live shell, which cannot be arranged deterministically from a script; the parser is the one place the empty string is interpreted, so the unit test covers the decision exactly. `test\win32\pane-banner.ps1` was re-run over the changed `BannerOverlay.zig` as a regression check.
