# T3532 - Windows image pane: a save at the same pixel size throws away the zoom and scroll (Mac keeps both)

## Summary

Mac's ViewerImageView.reloadFromDisk keeps the zoom and the scroll offset across a live reload (a save, +reload, Cmd+R) when the picture comes back at the same pixel size, and re-fits only when the dimensions changed (docs/reference/viewer-panes.md, Live reload). win32's ViewerPane.loadImage resets image_zoom=1 / image_fitting=true on every load, so a zoomed-in screenshot snaps back to best-fit each time its file is saved. The Linux port (T3416) already does it: src/apprt/gtk/viewer_image.zig keptZoom is the pure rule (move it into win32's viewer_image.zig or import it), and the shared src/viewer/image.js now takes a 4th setImage argument 'keep' that holds the scroll for the transform that answers the load. win32 needs: remember natural size + zoom + fitting before a reload, pass keep=true when not fitting, and on 'loaded' use keptZoom before fitZoom; plus a viewer-image.ps1 section asserting zoom and scroll survive a same-size save and re-fit on a different-size one.
