# T3714 - A remote file opens in a win32 viewer: the app reads it through the agent's granted root, relative pictures and .md links served from a separate virtual host (Windows)

## Summary

T2219 landed the wire (capability viewer_fetch, VIEWER_OPEN/OPENED/FETCH/DATA/CLOSE 0x82-0x86) and the agent side (src/remote/agent/viewer_grants.zig). Nothing on the app side calls it yet. Build the client half: Connection rpcCall wrappers for VIEWER_OPEN and chunked VIEWER_FETCH (pull max_viewer_chunk_bytes pieces until eof, base64-decode, cap at max_viewer_file_bytes), advertise capability.viewer_fetch from the app, and a ViewerPane remote mode that renders those bytes through the existing template, serves relative assets for the page from a SEPARATE virtual host (never ghoztty-page, never local disk) by VIEWER_FETCH against the same grant, and sends VIEWER_CLOSE when the pane goes. A remote --view reaches the app through T3711. Against an agent without viewer_fetch the pane shows an error card naming the machine, never a local file of the same name.
