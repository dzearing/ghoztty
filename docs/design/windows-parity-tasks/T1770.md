# T1770 - test-client-build E2 flags build-locked-artifact.ps1 as an unwired client consumer, but that script builds the client as its test subject

## Summary

test\win32\test-client-build.ps1 section E finds consumers by the literal zig-out\bin\remote-test-client.exe path. T722's build-locked-artifact.ps1 (2026-09-14) names that path because it BUILDS the client to prove the locked-install guard, and never launches it - so E2 goes red and the test-client guard stays due for every edit to lib\TestClient.ps1 (surfaced by T998). Fix the discriminator (e.g. exempt scripts whose use is the build step itself, declared in the script) and demonstrate it still fails on a real unwired consumer.

## In plain terms

A self-check in the test suite makes sure every test that uses the agent test
client gets it the safe way. One test was wrongly flagged because it builds
that client on purpose. It had been let off by its filename. Now the test
declares the exemption itself, and the check proves it still catches a real
offender.
