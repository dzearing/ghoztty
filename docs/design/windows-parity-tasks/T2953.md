# T2953 - 4K fold glide: a laid tick's placement spends 5-10 ms off-CPU outside the desk blits (place ~15 ms, UI-thread CPU 7-12 ms), so 2 of 20 release drags still have one tick at 16.8-18 ms

## Summary

Found by T2952's stall probe (`stack trace stall` line, `GHOZTTY_STACK_TRACE=ring`). Soak 2 (`temp	2952-soak2.txt`, `-analysis.txt`; 20 x 4K ReleaseFast drags of `temp	2952-rel2`, release sandbox) had no blocked-blit episodes, but 5 laid ticks of 16.1-18.0 ms in 3 runs (2 runs over 16.7: 16.8 and 18.0 ms). Every one is `place_us` 14.5-16.3 ms with the desk blits only ~1.0-1.4 ms in total, yet the UI thread's own CPU over the tick is 6.7-15.7 ms: up to 10 ms of placement is spent off-CPU somewhere that is not a desk blit (candidates: `EndDeferWindowPos`, `SetWindowRgn`, the strip-face commit - each a window-manager call that can wait on DWM). Normal ticks run cpu/wall ~0.84.

Next: time each placement phase with thread cycles too (the probe's `Lap` shape) so the off-CPU part names its call, then decide whether it can be moved off the tick, batched or avoided.

## Validation criteria

- [ ] The off-CPU part of a slow place tick is attributed to a named call (wall vs cycles per phase).
- [ ] A change that removes it, measured over 20+ 4K release runs with 0 ticks over 16.7 ms from this shape, or a recorded finding that it is outside the app.
