# T3620 - Linux headless harness has no Wayland seat, so no test can prove a copy reaches another app's paste (wl-paste)

## Summary

The private headless Weston (test/linux/lib/headless.sh) exposes no wl_seat - a GTK 4 client there reports get_default_seat() == None - and a Wayland selection is only offered through a seat, so no second client can be offered the clipboard or PRIMARY. T3565 therefore reads the copy back from the app's own GdkClipboard (the read-clipboard seam). Find a headless compositor setup that has a seat with keyboard focus (weston with a test/fake seat module, or sway/wlroots headless with WLR_LIBINPUT_NO_DEVICES=1), without ever touching WSLg, and add a check to test/linux/copy-reflow.sh where an outside client (wl-paste or a GTK reader) receives the reflowed text.

## In plain terms

The Linux tests run the app on a hidden private screen, and that screen had
no keyboard or mouse "seat", so nothing could check that copying text in
Ghoztty actually lets another program paste it. The tests could only ask the
app what it thought it had copied. The harness can now start a second kind of
hidden screen that has a seat, and the copy test checks that a separate paste
program receives exactly the cleaned-up text.

## Goals

- [x] a headless compositor with a seat, as isolated as the Weston one (`hl_start_seat`: sway, no devices, no Xwayland)
- [x] a copy from the app reaches another client (`hl_key_serial` supplies the one key serial wlroots demands)
- [x] copy-reflow proves it with wl-paste for the clipboard, PRIMARY and Copy URL, with a negative control
- [x] the harness's own acceptance covers the new compositor

## Validation criteria

- [x] `hl_start_seat` comes up isolated on a private socket and a GTK client there has a seat, while under Weston it has none: `test/linux/headless-harness.sh` H23 (control, `seat=no`) and H24 (`isolated|wayland-1|yes`); `HEADLESS HARNESS: ALL PASS` (25 checks) via wsl-run, 2026-11-25.
- [x] a SIGTERMed seat harness leaves no sway, app or dir: H25 PASS.
- [x] `hl_key_serial` refuses outside the seat harness: H22 PASS.
- [x] a copy made before any key serial does NOT reach another client (the control that the outside checks can fail): copy-reflow P1 PASS (`Nothing is copied`).
- [x] wl-paste receives byte-identical clean prose from Ctrl+Shift+C (P3), the dragged paragraph from PRIMARY (P4) and the whole URL from Copy URL (P5); every existing R1-R22 still passes under sway: `COPY REFLOW: ALL PASS` (27 checks) via wsl-run, 2026-11-25.
- [x] Linux floor green on the commit: `scripts/linux/floor.sh` (see progress log).
