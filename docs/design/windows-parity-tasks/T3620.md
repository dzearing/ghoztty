# T3620 - Linux headless harness has no Wayland seat, so no test can prove a copy reaches another app's paste (wl-paste)

## Summary

The private headless Weston (test/linux/lib/headless.sh) exposes no wl_seat - a GTK 4 client there reports get_default_seat() == None - and a Wayland selection is only offered through a seat, so no second client can be offered the clipboard or PRIMARY. T3565 therefore reads the copy back from the app's own GdkClipboard (the read-clipboard seam). Find a headless compositor setup that has a seat with keyboard focus (weston with a test/fake seat module, or sway/wlroots headless with WLR_LIBINPUT_NO_DEVICES=1), without ever touching WSLg, and add a check to test/linux/copy-reflow.sh where an outside client (wl-paste or a GTK reader) receives the reflowed text.
