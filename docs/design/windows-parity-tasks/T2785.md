# T2785 - A window with two terminals and a viewer still strands ~0.65 MB of GPU memory per close on the composition path (1.5 MB steps), after T2606 fixed the single and split shapes

## In plain terms

Closing a window that holds two terminals and a document viewer still leaves a
little graphics memory behind - well under a megabyte a window on average -
so a long day of opening and closing such windows slowly grows the app. Closing
simpler windows no longer does.

## Summary

Found closing T2606 (2026-11-07, lane b, debug, RTX 4090, composition present
default ON, `GHOZTTY_PANE_LAYER` unset). T2606 fixed the main strand: the
overlay layers' `releaseShared` committed BEFORE releasing the pane's root
visual, so when an overlay outlived its presenter the root and its swap chain
stayed pending on an uncommitted DComp device. After that fix, GPU dedicated MB
per `test\win32\window-close-memory.ps1 -Report` run:

| shape | cycles | baseline -> end | reading |
|---|---|---|---|
| single (`--undo-timeout=0`) | 20 | 73.4 -> 76.4 | one 3 MB step, then flat (was 64.3 -> 106.4 over 40 before) |
| split (COMP_PRESENT=1, PANE_LAYER=0) | 20 | 69.9 -> 77.4 | fills to cycle 8, flat for 12 |
| viewer | 20 | 64.4 -> 70.4 | two 3 MB steps, 0.59 MB/window, passes |
| **full** (default) | 30 | 69.9 -> 89.4 | **still climbing in 1.5 MB steps to cycle 30**: A8 1.06 MB/window, red |
| full (default) | 10 | 69.9 -> 77.4 | A8 2.05 (mostly fill at 10 cycles) |

So the remainder needs the three-pane shape. A 1.5 MB step is about one
half-width pane's swap-chain buffers, which suggests the same kind of
last-holder-without-commit path somewhere T2606 did not cover - candidates:
the presenter's own `releaseCom` when a commit is refused mid-`BeginDraw`
(`bandCommitRetries`-style `DCOMPOSITION` refusal while the window thread is
uploading an overlay), a `Layer` whose owner is never `deinit`ed on window
close in a multi-pane window, or the chrome's `Overlay`/desk visuals.
Method that worked for T2606: bisect by disabling a source (a temporary env
knob that makes `Presenter.overlayTree` return null), 14-20 cycles each.

## Validation criteria

- [ ] `window-close-memory.ps1 -Cycles 30 -Report` (full shape, debug): GPU dedicated flat after the fill, A8 <= 1 MB a window
