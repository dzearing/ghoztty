# T3410 - Linux L9a: WebKitGTK foundation - a viewer widget renders a file or a website through the bundled viewer template

## Summary

Install libwebkitgtk-6.0-dev in scripts/linux/setup-distro.sh; the bundled zig-gobject package has no WebKit module, so hand-write a small extern binding (src/apprt/gtk/webkit.zig) and link webkitgtk-6.0 in addGtkNg. Build a GTK Viewer widget that serves the bundled src/viewer/ template and assets over a ghoztty-viewer:// URI scheme, reusing the pure viewer_content.zig (modeFor, candidateUnder guards, setMarkdown/setCode calls; move it to shared code if win32-only imports get in the way), and renders markdown, code, a live HTML file (read grant = its own directory) and an http(s) site. Headless acceptance: the page loads and the rendered markdown is readable back from the page.

## In plain terms

On the Mac and Windows you can open a README, a source file, a local web
page or a website in a pane next to your terminal. Linux had no browser
engine in the app at all. Now it links one (WebKitGTK), and a viewer can show
all four of those things. It is not a pane yet: putting it in the split
layout and reaching it from `+split --view` is the next card (T3411).
