# T1583 - a cross-machine pane's recorded directory goes stale, because a shell that never reports OSC 7 tells the app nothing when the user cd's

## Summary

T752 records each pane's working directory so a restored or fresh-swapped pane comes back in it. The value is what the APP knows: the OSC-7 pwd a shell reports, the OS-level cwd of a LOCAL shell process (which covers cmd.exe on this box), or the cwd the agent reported at ATTACH. A CROSS-MACHINE pane has neither of the first two: ghoztty injects no shell integration over a dialed connection, so a remote cmd.exe never reports OSC 7 and we have no local pid to read - the recorded value is then frozen at whatever the pane was opened/attached with, and a user who cd's somewhere else gets the old directory back on restore. The agent already knows the true answer (it reads the child's OS cwd for GET_CWD and for every SESSIONS row), so the fix is a push, not a poll: sample the session's cwd agent-side the way foreground_pid and has_descendants are sampled, push it as META{cwd} on the session's channel, and apply it client-side through the same two-step T166 uses for the ATTACH cwd. That also un-freezes what +list --json reports for a remote pane, which is stale today for the same reason. A capture-time GET_CWD is the shape to avoid: session-layout capture runs on the UI thread on every topology change and T412 measured what a blocking call there costs.

## In plain terms

When you open a terminal on another machine and change directory in it, Ghoztty
did not notice: it kept remembering the folder the pane was opened in. So a
restored window, or a new split beside it, came back in the wrong place. Now the
other machine tells Ghoztty every time the folder changes, and Ghoztty keeps
up. Shells that already report their own folder keep doing so and win.

## Goals

- [x] the agent tells the pane when its shell's directory moves
- [x] the pane records it the same way it records the directory at attach
- [x] a shell that reports its own directory (OSC 7) is never overridden
- [x] older agents and older apps keep working unchanged
