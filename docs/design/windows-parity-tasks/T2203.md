# T2203 - Ask the box, not the source: a harness that runs each acceptance script and fails if a repo ghoztty window ever reaches the interactive desktop

## Summary

Shape 2 of T1267. `lib\DesktopLaunchAudit.ps1` reads SOURCE, and its header is
right that no textual rule can be complete: T1267 widened it to the `.com`
twin, aliases and copies of the exe, and static-method CreateProcessW spawns,
and a launch spelled some other way (Invoke-Expression, a ProcessStartInfo
built field by field, a splat built at runtime) still slips through.

The measurement that cannot be defeated by spelling is the box's own answer:
run each acceptance script and, while it runs, poll for any ghoztty process
from the repo build (`ExecutablePath` under the worktree) that owns a visible
top-level window on the INTERACTIVE desktop. `AnyVisibleWindowOnInteractiveDesktop`
in `lib\TestDesktop.ps1` is already that measurement; what is missing is a
per-script runner that applies it and reports, per script, observed vs declared.

Constraint: the user is usually present. A script that DOES pull a window is
exactly what this would catch by doing it, so the runner must only ever run
scripts the static sweep already passes, and must be a deliberate opt-in run,
never part of the per-turn floor.

## Validation criteria

- [ ] a planted script that launches the app on the interactive desktop by a spelling the static audit cannot see is reported (negative control scores red)
- [ ] a run over the migrated suite reports zero unexpected windows
