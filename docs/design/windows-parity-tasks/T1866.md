# T1866 - Audit the other owned win32 tooltips for T1842's z-order lift: a topmost tooltip owned by a background window dragged that window above the user's frontmost one when created

## Summary

Found landing T1842. The pane sidebar created a `WS_EX_TOPMOST` tooltip
OWNED by its window on the window's first layout. For a window opened in the
background (`+new-remote-window`, T1797's contract), that creation lifted the
window above Ghoztty's frontmost window: `cli-focus-policy.ps1` arm R measured
the new window at z=6 over the frontmost at z=9, deterministic over two runs,
green with the tooltip disabled and green again with the tooltip created
UNOWNED (the T1842 fix). Other tooltips are created owned the same way:
`ViewerNavBar.tipEnsure` (owner = the bar), `ViewerFeedbackBar`,
`KeyStateIndicator`, and the tab strip's (`Window.tabTipEnsure`). Measure each
on a window opened in the background (arm R's shape: open, then read
`Get-TestZIndex` against the frontmost window); move any that lifts to the
unowned form, or to lazy creation on first hover.

## Validation criteria

- [ ] each owned tooltip site measured on a background-opened window (z-order vs Ghoztty's frontmost), result recorded per site
- [ ] any site that lifts its window fixed, and an arm in `cli-focus-policy.ps1` (or a sibling) that would catch a regression
