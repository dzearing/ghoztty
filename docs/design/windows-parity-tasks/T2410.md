# T2410 - Windows pane-stack strip shadows are lighter (30% on dark, 14% on light) and fade out inside the strip's rounded ends instead of being cut flat (Mac 7e2d0a9da)

## Summary

Mac main 7e2d0a9da: each strip's tight shadow (leaning away from the run onto the blade behind) is lighter - 30% opacity on dark, 14% on light - and is cast from a shape pulled in by the corner radius at each end so it fades inside the rounded corners, never masked off flat and never haloing past them; the mask removes only the card's own shape. Still follows collapse so it comes on as a card narrows. Windows: match in the win32 pane-stack strip shadow paint; note T2334 owns pane-stack-strip.ps1's colour model, so pixel claims go there or alongside. Ref docs/reference/stacked-panes.md on main (stripShadowsFadeAtTheirEnds).

## In plain terms

When a window is too narrow for all its panes, the extra ones fold into thin
strips at the edge, each casting a small shadow on the next. On Windows that
shadow was twice as dark as the Mac's and ended in a hard straight cut at each
end of the strip. Now it is as light as the Mac's and fades away inside the
strip's rounded ends.

## Goals

- [x] the strip shadow is 30% black on a dark theme, 14% on a light one
- [x] it fades out inside the strip's rounded ends instead of being cut flat
- [x] it never haloes past the strip's ends

## Validation criteria

- [x] Blade opacity is 0.3 dark / 0.14 light, still mixed in by collapse —
  `blade_shadow.zig` test "params" (zig test blade_shadow.zig; floor `none` lane PASS).
- [x] The caster is the strip pulled in along its length by the corner radius,
  capped at a quarter of its length, half way through a glide half of it —
  `casterOf` unit test.
- [x] Pixels: just inside a strip's end is lighter than its middle, darker
  further in, and nothing past the end (no halo, no flat cut) — "paint ... fades
  out at its ends" and the vertical-stack test. Before the fix the row inside
  the end was as dark as the middle, so `end > mid + 3` would fail.
- [x] On the box, the lighter shadow still lands visibly on the strip behind:
  `test\win32\blade-shadow.ps1` ALL PASS (8), 20 levels R+G+B darker beside the
  inner strip (threshold 12), plain strip face 20 DIP further out.
- [x] Floor: `floor-lane.ps1 -Lane all` lib/none/win32/agent PASS.
- NOT checked on the box: the end fade itself in real pixels. The harness reads
  one row across the strips; the end fade is a few pixels inside the window's
  own corner rounding and is held by the unit tests above.
