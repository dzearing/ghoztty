# T1664 - The dashboard ships a six-megabyte payload every five seconds, most of it text the page never renders

## In plain terms

The task board asks the server for fresh data every five seconds, and what
comes back is six megabytes - most of it the long write-ups inside each task,
which the board does not put on screen until you open a card. The browser has
to read all of it every time, so the page stutters and a phone or a laptop on a
slow link feels it worst. The board should be sent what it draws, and fetch the
rest when you actually open something.

## Summary

Measured 2026-09-19 while fixing T1660: /api/data is 6.15 MB. tasks is 4.33 MB of it and activity 1.44 MB. Per-task the bulk is progress (1.07 MB), summary (726 KB), plain (507 KB), validation (505 KB) and goals (292 KB) across 1693 tasks, and the page parses all of it on every 5s poll. The validation field is dead weight outright: nothing in scripts/task-dashboard.page.html reads t.validation, because the detail dialog fetches /api/task for the whole file - which is exactly the on-demand path the /api/task comment says exists so that whole files never ride in the poll payload. Shape to consider: drop validation, and move progress/plain/goals behind /api/task the same way, leaving the poll payload to what the table and cards actually render. Also worth knowing: the same 6 MB costs PowerShell's Invoke-WebRequest -UseBasicParsing about 4.5s of pure client time, which is why test/win32/task-dashboard.ps1 section G times the endpoint with Invoke-RestMethod instead.

## Validation criteria

- [ ] `/api/data` against the real tracker is well under a megabyte, measured
      the same way (`(Invoke-WebRequest .../api/data).RawContentLength`).
- [ ] Nothing the board renders is lost: the table, the cards, the in-flight
      panel and the search box behave identically, and the detail dialog still
      shows the whole task.
- [ ] `test\win32\task-dashboard.ps1` and `test\win32\dashboard-dom.ps1` stay
      green, with a size assertion added alongside section G's timing one so a
      field moving back into the payload goes red.
