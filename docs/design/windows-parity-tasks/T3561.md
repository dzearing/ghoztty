# T3561 - Linux: banner link right-click menu, and activity state shown in the window title on GTK

## Summary

Two smaller T3339 gaps. (1) A right-click on a banner link should open the same link menu viewer panes already have on GTK (viewer_links.menu / banner_link.build: open, reveal, side pane, new window, copy) - today GtkLabel shows its own Copy Link menu. (2) +set-state / OSC 7777 is stored and listed (+list state) but not shown: Mac and win32 append " (busy)" / " (question)" to the window title (displayLabel); GTK window titles come through tab property bindings in class/window.zig, so the suffix needs a hook there, and adw TabPage loading / needs-attention are the natural per-tab marks.

## In plain terms

On Linux, right-clicking a link in a pane's banner showed GTK's generic
"Copy Link" menu instead of the menu Mac and Windows show (open in browser,
side pane, new window, reveal, copy). And when a tool marked a pane as busy
or waiting on a question, nothing on screen said so. Now the banner link has
the same menu as everywhere else, and the window title reads "... (busy)" or
"... (question)" with a spinner or attention mark on the tab.

## Goals

- [x] Right-click on a banner link opens the shared link menu (rows, order and ids from `banner_link.build`, the viewer's own popover)
- [x] Each row does what it says: browser, reveal, side pane, new window, default app, copy path/link, focus
- [x] The window title carries " (busy)" / " (question)" for the most urgent pane, pinned titles included
- [x] Tabs show a spinner while busy and ask for attention on a move into needs_input

## Validation criteria

- [x] Window title suffix follows +set-state / OSC 7777 (busy, question, idle drops it, pinned title carries it) - S1t-S5t of `test/linux/cli-banner.sh` (WSL, headless Weston)
