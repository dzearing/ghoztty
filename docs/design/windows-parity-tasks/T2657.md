# T2657 - frame-lab.ps1 can never re-stamp its guard from a sweep: B/C/D are -Live opt-in (real cursor), the skips block the stamp, so any edit to FrameLabDriver.ps1 or frame-lab.ps1 leaves the guard DUE

## Summary

Since 88e29081e (2026-10-28) frame-lab.ps1's live sections B/C/D run only with `-Live`, because they move the real cursor, and a sweep never passes it. But the stamp rule at the end of the script requires `$script:skipped -eq 0`, so a sweep run reads `ALL PASS (21 assertions, 2 SKIPPED)` and never re-stamps. Any edit to the covered files (test/win32/frame-lab.ps1, test/win32/lib/FrameLabDriver.ps1) then leaves the `frame-lab` guard permanently DUE, and `validate` fails on it. Hit by T2564, which changed only the pure `Get-FrameLabSidebarPref` strings (section A, green); the guard was handed to this task with `guard-ack`.

Fix shape (same as T2060 for ghoztty-cleanup): split the guard so a sweep stamps the pure part. Either a `frame-lab` row covering section A that stamps on a non-`-Live` run with only the by-design live skip, plus a separate `frame-lab-live` advisory row for B/C/D; or count the "-Live not passed" skip as not-a-skip for the pure row. Validate: edit a covered file, run `frame-lab.ps1` with no flags, and see `GUARD CURRENT frame-lab`. Also run the negative control: a real SKIP in section A still blocks the stamp.
