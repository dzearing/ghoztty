# T2733 - comp-spike live oracle reads 0 for comp on 2026-11-05 (0.944 on 10-29): DWM no longer ticks the ghost window's compositor animations, while a surface redraw still produces a captured frame

## Summary

Live ghost runs on 2026-11-05 (T2465): comp captures 1 frame per run, edge never moves, for plain colour sprites too (so not T2465's surface code); gdi still scores 0.278. Ruled out: occlusion (uncovered spot on display 2 also fails), ghost alpha (255 fails the same), animation effects setting (SPI_GETCLIENTAREAANIMATION=1). Clue: a mid-glide surface redraw DID produce a 2nd captured frame, so capture works and the keyframe animations are what never apply. Windows update KB5127936 installed 2026-11-03, between the green and red runs. Blocks every live comp cadence number (T2465's WARP cadence, T2469+).

## In plain terms

The test that measures how smoothly the new animation approach runs stopped
seeing any motion on 2026-11-05, so none of its numbers could be trusted. On
2026-11-07 it sees motion again with no code change: the blindness came from
something about the computer's state at the time, which nobody wrote down.
Every run now writes down that state, so if it goes blind again the run says
what was different.

## Goals

- [x] Re-run the live oracle and find out whether it is still blind (it is not)
- [x] Test the one cause on file (a fully covered ghost) against today's run (disproved)

## Result (2026-11-07, lane A)

Same box, same build lineage, OS 26300.9818, ghost at the default 200,200:

| run | comp advance | verdict |
|---|---|---|
| `-Live -CheckOracle` | 0.944 (idle 0, gdi 0.271) | ORACLE PASS |
| `-Live -Modes comp -Surface warp -RebindAfterGlide 3 -CheckSurface` | 0.941 | SURFACE PASS, rebind 6 ms |
| `-Live -Modes comp -Surface hardware -CheckSurface` | 0.941 | SURFACE PASS |
| `-Live -CheckOracle` again, with BOXSTATE | 0.944 (gdi 0.274) | ORACLE PASS |

The BOXSTATE line for those green runs reads `uncovered=0.00` - the ghost
sat completely under a maximized Ghoztty window - so T2465's "DWM stops
compositor animations for a completely covered window" is NOT the cause (or
not alone). The 11-05 state is unrecoverable; what was missing was a record.

New `scripts\lib\CompBoxState.ps1`: `Get-UncoveredFraction` (pure),
`Get-CompBoxState` (read-only: uncovered fraction of the ghost rect against
visible uncloaked top-level windows, layered overlays counted apart, ghost's
monitor, foreground class + fullscreen, SPI_GETCLIENTAREAANIMATION, AC /
battery saver, transparency, OS build.UBR) and `Get-CompBlindHint`.
`scripts\comp-spike.ps1` prints `BOXSTATE ... mode=<m>` before each -Live run
and appends the comp run's line to an ORACLE/SURFACE FAIL. Harness
`test\win32\comp-box-state.ps1` + guard row `comp-box-state`.
