# T1496 - Run the win32 acceptance suite with real concurrency once every suite owns its lineage

## In plain terms

Running the whole Windows test suite takes hours, because the scripts have to go
one at a time. They had to: each one shut down the shared background helper the
others needed. Once every script owns its own helper (T691 and its tranches),
that reason is gone - and this is the job of actually spending it, so a full
suite run is minutes rather than an evening.

## Details

`scripts\suite-run.ps1` runs 241 scripts serially. Two things in it assume a
serial world and have to move with the same care the kill did:

- **the between-script leak sweep** (section I of `test\win32\suite-run.ps1`)
  kills anything running out of the repo's `zig-out`, which is precisely a
  concurrent script's app and agent. It needs the same lineage scoping
  `Stop-RepoGhoztty -ScopeToLineage` got, keyed on the child it just ran.
- **the confirm pass** re-runs every non-pass script alone. That stays serial on
  purpose: a red row that is green ALONE is the harness defect it is there to
  find, and running the re-run concurrently would destroy that distinction.

Worth measuring before choosing a width: these are GUI scripts on a background
desktop and the box has a finite amount of composited-window headroom, so the
useful degree of parallelism is an empirical number, not `[Environment]::ProcessorCount`.
Report it in the task rather than picking it.

## Validation criteria

- [ ] A suite run at width > 1 produces the SAME verdict set as a serial run
      (`suite-run.ps1 -Compare` is the existing oracle for exactly this)
- [ ] The between-script leak sweep no longer reaches a concurrent script's
      processes, demonstrated by a negative control
- [ ] The confirm pass still runs its re-runs alone
- [ ] Wall-clock for a full run, before and after, recorded in the task
