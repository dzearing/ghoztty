# T3278 - acceptance-parallel scores a CURRENT harness-floor run as ERROR (no ALL PASS line), so a green sweep reads red

## Summary

Found by T1523 on 2026-11-20. `acceptance-parallel.ps1 due` ran the
`harness-floor` row (`scripts\harness-floor.ps1 -Scoped`). The floor was
already verified green at 06:12, so it printed `HARNESS FLOOR CURRENT: ...
nothing to run` and `STAMPED harness-floor (634 files)`, and exited cleanly.
The runner looks for a verdict line and found none, so it scored the row
`ERROR` and the whole sweep ended `ACCEPTANCE RED ... error=1`, even though
the row had passed and stamped. Log:
`%TEMP%\ghoztty-acceptance-parallel\20261120-072542\56-harness-floor.log`.

Fix one of the two sides: have the runner accept `HARNESS FLOOR CURRENT` (and
`HARNESS FLOOR:` green) as a PASS verdict, or have `harness-floor.ps1` print a
standard `ALL PASS` verdict line when it has nothing to run. The second is
better, because every reader of the script gets the same verdict line.

## Validation criteria

- [ ] `acceptance-parallel.ps1 run -Scripts harness-floor.ps1` on a CURRENT floor scores the row PASS
- [ ] a red floor still scores FAIL (negative control)
