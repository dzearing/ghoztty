# T1931 - Work down the dip-rounding-audit baseline: move the harness's banker's-rounded DIP conversions onto Get-TestChromeDip

## In plain terms

Nothing a user sees. About 33 of the on-box tests work out "how many pixels is
this many points at this screen scale?" with a rounding rule that disagrees
with the app's, so on some screen scales they check a pixel the app never
drew. A sweep now stops new ones arriving (T1020); this moves the existing ones
onto the one correct helper.

## Summary

`test\win32\dip-rounding-audit.ps1` (T1020) found 54 banker's-rounded DIP
conversions across 33 scripts on 2026-10-14 - `bare-round`
(`[Math]::Round($dip * $scale)`) and `int-cast` (`[int](18 * $scale)`). They
are a per-file ratchet in `test\win32\dip-rounding-audit.baseline.json`. Move
each onto `Get-TestChromeDip` (`test\win32\lib\ChromeGeometry.ps1`), and
where a script restates a constant the module composes from several rounded
terms, compose the same terms (T314's rule). The 15 private `Px` copies the
audit lists are the hoist list: the correct ones can become calls to the
helper in the same pass.

Also correct ChromeGeometry.ps1's header, which says banker's and half-away
"agree at 100%, 125%, 150% and 200%" - they do not in general (18 DIP at 125%
is 22 vs 23; any odd DIP at 150%), as section B of the audit measures.

Cost note: each script edited re-dues its own guard row, so each batch must
re-run those harnesses on the test desktop. Batch by guard family (the
pane-sidebar-* scripts share one `Px`; the viewer-feedback-* scripts share one
`18 * $scale` site).

## Validation criteria

- [ ] `dip-rounding-audit.baseline.json` shrinks with each batch, rewritten
      with `-UpdateBaseline` in the commit that fixes the sites.
- [ ] Every script touched re-runs green (its guard row re-stamped).
- [ ] ChromeGeometry.ps1's header no longer claims the two roundings agree at
      125%/150%.
