# T3607 - Linux L10f: drag pane sidebar rows (panes, windows, groups) and the stash tray on GTK

## Summary

Split from T3558. The GTK pane sidebar (PaneSidebar.zig, pane_sidebar_all.zig) lists every window and searches, but nothing drags: dragging a pane row reorders its window's panes (win32 pane_sidebar_reorder/pane_sidebar_order), a window row or project header reorders the all-windows list (pane_sidebar_window_order keys, persisted under the config root), a grid pane dropped on another window's row joins that window (pane_sidebar_cross_drop), and dragging a pane into the stash tray stashes it - which needs +stash/+restore served on GTK first (T3596). docs/reference/pane-sidebar.md 'Drag to reorder', 'Reordering windows and groups', 'Stashing invariants'.

**Scope as landed (2026-11-24):** pane rows reorder their window's list, in
both the per-window and the all-windows list. The rest is split out:
window/group reorder T3697, the stash tray T3698, cross-window drops and the
grid handle into the sidebar T3699, keeping the order across a restore T3700.

## In plain terms

On Linux you could see your panes listed in the sidebar but not rearrange
them. Now you can drag a pane's row up or down to put the list in the order
you want; the panes on screen stay exactly where they are, and new panes
show up next to the one they were split from.

## Goals

- [x] a pane row drags and lands level with the pointer, among its own window's rows
- [x] the list only moves - the grid, the focus and the shells do not
- [x] one order per window, shown the same in the per-window and all-windows lists
- [x] a new split lands after its parent; a closed pane drops out
- [x] a stashed pane's row does not drag
- [x] the remainder filed (T3697, T3698, T3699, T3700)
