# T2071 - The installer carries ghoztty.com as a second 20 MB copy of the terminal: derive it from ghoztty.exe at install time instead

## Summary

Split from T1077. ghoztty.exe and ghoztty.com differ by ONE WORD (PE optional-header Subsystem), yet the MSI and portable ZIP each carry both in full (~19.9 MB extra compressed, ~45% of the download). Derive the .com at install time: copy ghoztty.exe and flip the Subsystem field (the same edit src/build/patch_subsystem_main.zig makes), from the existing MSI custom-action DLL, with a RemoveFile row so uninstall cleans it and upgrade/repair regenerate it. Validate: MSI shrinks by ~20 MB; after install, repair, upgrade and uninstall the .com is present/current/gone; 'ghoztty +list --json > f' from PowerShell still writes output; Defender leaves the derived file alone. Decide separately whether the portable ZIP keeps shipping both (it has no installer step) - default: it does, and READ-ME-FIRST says why. Rejected alternatives and measurements are in T1077's progress log.

## In plain terms

The Windows installer download is roughly twice as big as it needs to be,
because it contains two almost identical copies of the terminal program - one
for clicking and one for typing `ghoztty` in a shell. After this lands the
installer carries one copy and makes the second on your machine while it
installs, so the download is about 20 MB smaller and everything works exactly
as before.

## Goals

- [x] the installer no longer carries `ghoztty.com`; it writes it from `ghoztty.exe` while installing, repairing or upgrading
- [x] uninstalling removes it, so the install folder is not left behind
- [x] the build-time and install-time copies are made by the same code
- [x] the release read-back accepts the new package shape (and still accepts older releases)
- [x] a real install of a CI-built package shows the twin present after install and repair, and gone after uninstall

## Decisions

- **The portable ZIP keeps shipping both files.** It has no install step to
  derive one, and its READ-ME-FIRST already explains what `ghoztty.com` is.
- **Neither action can fail the install.** RemoveExistingProducts runs early
  (T2327), so the old version is gone before the twin is written; failing would
  roll back to no Ghoztty at all. A missing twin is logged in words and fixed
  by the next repair or update.
- **The derived twin carries no signature.** Authenticode hashes the field we
  flip, so a twin of a signed exe would carry a signature that no longer
  matches. Releases are unsigned today (T1203), so the installed twin is
  byte-identical to the ZIP's; once signing lands the installed twin becomes
  unsigned while the exe is signed - that trade is T3647.
- **Uninstall cleanup is an action, not a RemoveFile row**: wixl 0.106 has no
  RemoveFile element (checked `tools/wixl/wix.vala` at v0.106).
