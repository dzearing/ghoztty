# T1940 - Mac: verify the shared renderer's unchanged-frame skip (T1935) builds and never leaves a stale frame

## Summary

T1935 changed shared src/renderer (generic.zig frame_changed, Thread.zig force_frame + 500 ms bound). Metal draws on its display link so the skip should rarely engage there, but the Mac seat must build it and run its regression pass.

## In plain terms

A Windows fix for typing lag changed code the Mac app shares: a terminal pane
no longer redraws when nothing on it changed. The Mac app must still build, and
must never show an out-of-date pane because of it.

## What changed (T1935)

- `src/renderer/generic.zig`: `updateFrame` sets `frame_changed`, false only
  when the render state is clean AND the cursor, blink phase, focus, mouse and
  size hash is unchanged AND there is no preedit, overlay, kitty change, custom
  shader or scrollbar change.
- `src/renderer/Thread.zig`: `renderCallback` skips the draw when nothing
  changed, unless `force_frame` is set (any mailbox message sets it) or the
  last present is 500 ms old.
- On Metal `drawFrame` already returns early without `now` (display link), so
  the skip should rarely matter there. That is the claim to check.

## Validation criteria

- [ ] `zig build -Doptimize=Debug` builds the Mac app.
- [ ] Mac regression pass green.
- [ ] Manual: typing, selection, scrolling, cursor blink, IME preedit and a
      window that is hidden and shown again all draw at once, never stale.
