# T1558 - App-less dialogs draw at 96 DPI, so a warning on a scaled display is smaller than every other prompt

## Summary

The four remaining ConfirmDialog.showStandalone callers (startup_error, install_restart, install_maintenance, update_install) pass a flat scale of 1.0 in a PerMonitorV2-aware process, so on a 150% display their dialog is two thirds the size of every in-app prompt. T717 added ConfirmDialog.standaloneScale() and uses it for the url-scheme warning; adopt it at the other four and re-run each one's harness.

## In plain terms

Some of Ghoztty's warning boxes - the ones shown when there is no window yet,
like a startup failure or an update notice - come up noticeably smaller than
every other dialog on a display running at 125% or 150% scaling. They say the
right thing at the wrong size.

## Goals

- [ ] The startup-failure, install-restart, install-maintenance and
      update-install dialogs are drawn at the display's scale
- [ ] Each one's acceptance harness is re-run green over the change

## Validation criteria

- [ ] No `showStandalone` caller passes a hard-coded `1.0` any more
- [ ] `test\win32\startup-failure.ps1`, `install-restart.ps1`,
      `install-maintenance.ps1` and `update-apply.ps1` are ALL PASS
- [ ] Floor green: both `zig build test` lanes, `test-agent`, the `lib` build
