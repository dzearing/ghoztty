# T1822 - test-binary-soak and crash-databreak still run test binaries on the user's desktop: Start-Process -WindowStyle Hidden from the caller's process, so a win32 soak/databreak shows its banner windows on screen

## Summary

T1813/T1815 moved floor-lane, the soak daemon and floor-lane's cdb re-run onto GhozttyLaneDesktop. Three hand-run investigation paths still launch test binaries from the caller's (input) desktop: scripts\test-binary-soak.ps1 (Start-Process cmd /c ... lines ~373 and ~850, plus PsExe children ~508/~599), scripts\crash-databreak.ps1 (zig build via Start-Process ~343) and scripts\lib\DataBreak.ps1 (cdb via Start-Process ~126/~815/~1060). A win32-lane soak or databreak run therefore re-runs the banner tests on the user's screen. Fix: route each through Start-LaneProcess (scripts\lib\LaneDesktop.ps1) with cmd redirection, as CrashCatch.ps1 now does; measure from inside the child (the deskav crasher pattern in test\win32\crash-stacks.ps1 section 4a).
