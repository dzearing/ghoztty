# T2678 - Settings window: reach every row from the keyboard (Tab between fields, Reset/doc/chips by key) and name its controls to screen readers

## Summary

Found building T2675. The Settings window draws its own fields and routes
keys itself (the shortcut guide's pattern), so it has only what it wires: the
Search box takes typing, a clicked field takes typing/Enter/Esc, Tab commits
the field, and arrows/PageUp/PageDown scroll. Nothing moves focus INTO a row
without the mouse - Mac's SwiftUI form gives Tab through every field, the
doc (info) button, Reset and each value chip's remove button for free, and
VoiceOver names them (`accessibilityLabel("Reset <key> to default")`,
"Remove <value>", "Documentation for <key>"). On Windows none of the row
controls is reachable by keyboard and none is exposed to UI Automation.

Fix: a focus ring over the row controls (Tab / Shift+Tab walk Search -> each
visible row's field / info / Reset / chips, scrolling the focused one into
view; Space/Enter activate), drawn with the design system's focus treatment,
plus UIA names for the same controls (the pattern the win32 chrome already
uses, if one exists; else file it).

## Validation criteria

- [ ] Tab from Search reaches the first row's field, then its info and Reset buttons and chips, in visual order; Shift+Tab walks back.
- [ ] Space/Enter on Reset / a chip's remove / info act as the click does.
- [ ] The focused control scrolls into view.
- [ ] A UIA client sees named controls for the rows (`Reset font-size to default`, ...).
- [ ] `test/win32/settings-window.ps1` (or a sibling) covers it off-desktop.
