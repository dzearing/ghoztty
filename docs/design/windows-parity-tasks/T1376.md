# T1376 - parity-decisions.ps1 new can still mint a decision its own validate rejects (no task link, no options)

## Summary

T566 gave the decisions directory a validate that parity-tasks.ps1 validate relays, so a malformed decision now fails the pre-commit gate. The minting verb was not tightened to match: new -Title alone writes task: null and options: [], which validate reports as NO TASK LINK and (while the decision is open) NO OPTIONS, and the recommended-flag count is still only a warning rather than a refusal. So the loop can file a decision at step 5b and be stopped by its own gate at step 6, which is the shape that teaches people to reach for a hatch. Make new refuse what validate will reject - require -Task and at least two options with Pros and Cons and exactly one (Recommended) - so the two ends agree. Section D of test\win32\parity-decisions.ps1 is where the round trip is asserted.

## In plain terms

The tool that files a question for the user could write a question with no linked task or no real choices, and the checker that runs before every commit would then reject it - so the loop could trip over its own paperwork. Now the filing tool refuses such a question up front and says exactly what is missing, so whatever it writes always passes the checker.
