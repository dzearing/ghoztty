# T2706 - Pane drop targets on Windows measure the terminal, not the pane as drawn: a banner or rearrange header should count as part of the pane for triangles, center box, dividers and window edge

## In plain terms

On the Mac, when a pane has a banner on top, dropping onto the banner area
counts as dropping onto that pane. This checks Windows behaves the same and
fixes it if the banner area is a dead zone or belongs to the wrong target.

## Summary

main intake 2026-11-04, from 30d13ea14: Mac's targets now use `PaneFootprint`
(the pane as drawn, banner and rearrange header included) for the triangles,
center box, dividers and window edge. Test: `aBannerIsPartOfItsPaneToADrop`.

**Unverified** on Windows: the claim at filing is only that Mac changed. First
step is to read which rect the win32 drag loop hands `pane_drop.zig` for a pane
with a banner (`BannerOverlay.zig` insets the surface) and whether the banner
strip resolves to that pane. If it already does, close this with the evidence
and a regression test.

## Validation criteria

- [ ] Determined (with file:line) which rect a bannered pane contributes to the drop resolver
- [ ] A drop over a pane's banner strip resolves to that pane (unit or acceptance test)
