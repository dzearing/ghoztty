# T1286 - The capture-content floor has the same size blind spot the uniform guard just lost, so a big window's good capture reads as collapsed

## Summary

Get-TestCaptureContent samples a fixed 48x48 grid, so its step grows with the window exactly as Test-TestCaptureUniform's did before T1282. On a maximized 3858x2118 ghoztty window it steps 80x43 px, misses the 40 px caption band, and scores the capture 3 distinct / 0.90 top share - at or under hero-mode.ps1's collapse floor of 8 distinct / 0.90, i.e. it calls a healthy capture dead. Nothing measures a maximized window today, so this is latent; the next script that does inherits a false red. Give it the same MaxStep density bound, then re-derive the floor numbers the doc comment quotes.

## In plain terms

The test suite has a check that looks at a screenshot of the app and asks "is
there actually a picture here, or did the capture come back blank?". It looked
at too few dots on a very large window, so a big window whose only drawn part
is the thin title bar could be called blank when it was fine. It now looks
closely enough that a title-bar-sized strip cannot slip between its dots.

## Goals

- [x] the content score samples densely enough on any window size to see a 40 px caption band
- [x] the floor numbers quoted in the docs are re-measured under the new sampling
- [x] the one number density cannot fix (top-color share, an area fraction) is named as such, with what to floor big windows on instead

## What it actually was

`Get-TestCaptureContent` stepped a fixed 48x48 grid - 80x43 px on a maximized
3858x2118 window, whose rows land at y=8 and y=51, both outside a caption band
at 9..48. It now takes the same `-MaxStep` 16 density bound as
`Test-TestCaptureUniform` (T1282). The scan cannot stop early, so it costs every
sample: ~32k on a maximized window, measured at under 50 ms.

Re-measured 2026-10-24. Today's real maximized capture (caption-bar.ps1 section
6) scores 501 distinct / 0.939 top share, and the old grid already gave it 140 /
0.934: the window's chrome now carries a gradient frame and the sidebar, so the
blind spot is latent for band-only windows rather than live. The 3 / 0.90 in the
Summary does not reproduce. hero-mode's live shots score 727 / 0.60 and 1038 /
0.11, the committed screenshot 151 / 0.57 (was 87 / 0.57).

Top share does NOT become size-independent with density: it is the fraction of
the picture that is the single commonest color, and on a maximized window with
flat glass that really is ~94%. So hero-mode's combined floor stays calibrated
for hero-sized windows, and a big, mostly-uncapturable window is floored on
Distinct alone - which is what the new caption-bar.ps1 assertion does.
