# T2527 - Windows pane sidebar: a window row's right-click menu offers Create Group... (named in place), Move to Group, Remove from Group, each keeping the window's own name and pinning the title (Mac 7bee055c9)

## Summary

Mac 7bee055c9 adds a window-row context menu in either sidebar list (PaneSidebarView.windowMenu). Create Group... turns the row name into an empty in-place field (placeholder 'Group name'); Return retitles '<group>: <name>' into a new or existing group, Escape or empty changes nothing. Move to Group lists every other group (only when one exists). Remove from Group (grouped only) restores the bare name. Each pins the title as the user's (title_set_by_user) and moves it as a rename would: a new group where the window was, an existing group at the edge nearest it, out of one to the end of the ungrouped windows. An unusable group name (empty, over 40 chars, containing ': ') changes nothing. Windows has src/apprt/win32/pane_sidebar_menu.zig to extend. Mac reference: docs/reference/pane-sidebar.md; test PaneSidebarSyncWindowTests.groupsFromTheSidebar.

## In plain terms

Right-clicking a window's row in the sidebar did nothing on Windows. Now it
opens a small menu, as on Mac: **Create Group...** turns the row's name into
an empty box where you type a group name, **Move to Group** lists the other
groups, and **Remove from Group** takes a grouped window back out. The window
keeps its own name each time, and it moves only as far as the change asks.

## Goals

- [x] Move to Group lists every other group once, as listed, only when there is one
- [x] each keeps the window's own name, pins it as the user's, and moves it as a rename would
