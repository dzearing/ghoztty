# T3006 - PA-M06: +read formats the pane's whole scrollback on the UI thread under the renderer lock, then keeps the last 50 lines (~6 MB per call at 50k rows; IpcHandlers.zig:1377)

## Summary

PA-M06 (audit-1, T2961). src/apprt/win32/IpcHandlers.zig:1374-1381 selects from pages.getTopLeft(.screen) to the bottom-right and calls dumpTextLocked over all of it while holding renderer_state.lockPriority(); only at :1408 does read_tail.tail keep line_count lines. Estimated ~6 MB transient per call for a 50k x 120 scrollback, with the GUI thread and the pane's renderer blocked; an agent polling at 1 Hz churns ~360 MB/min. Fix: start the selection line_count plus a margin of rows above the bottom (keep margin for trailing blanks so the tail is identical). Risk low. Mac half: a seat-mac check of the Swift +read is filed. Baseline: docs/design/perf-audit/baseline-1.json (T2958); findings: docs/design/perf-audit/audit-1/M-findings.md.
