# T2155 - The win32 unit test 'T163: a popup is adopted as a pane, sized, and can close itself' fails under box load and passes alone

## Summary

Found in T1145 (2026-10-22, lane b): the full harness floor's test-reach-audit B1 went red on zig build test -Dapp-runtime=win32 at src/apprt/win32/ViewerPane.zig:12122 (T163 popup-adoption test) while lane a was also running; the alone re-run passed. A unit test that depends on box timing is a flake the scoped floor will keep hitting on a two-lane box. Find the timing dependence (WebView2 popup wait?) and make the test wait on the event rather than a clock.

## In plain terms

One of the automated checks for the built-in web viewer sometimes failed when the machine was busy running two build loops at once, then passed on its own. Nothing was wrong with the viewer: the check gave the embedded browser one minute to start, and a starved machine can take longer. The check now gives that start-up step a longer (still bounded) allowance, retries a browser that briefly refuses to start, and logs how long each start-up step took, so a future failure says which step was slow.

## Goals

- [x] Find which wait in the T163 popup test timed out (the controller wait, `WebView2ControllerTimeout`, not the popup event waits)
- [x] Give every live viewer test's controller wait one load-tolerant, still-bounded deadline
- [x] Retry a transient environment refusal in every live viewer test, not only the host floor
- [x] Log each start-up phase's time so a future red names the slow phase
