# T3595 - Linux L8d-1: the GTK app serves handoff-quit and advertises it in version, so a launch of another build can take over

## Summary

Split from T3399. The GTK IpcHandlers answered handoff-quit with 'not served (T3337)'. Port win32's T1070 server half: refuse via the shared ipc_handoff.refuseHandoffQuit, else reply success and quitNow after the reply is out (layout saved, agent panes detach); version carries handoff_quit + session_persistence. Acceptance test/linux/cli-handoff-quit.sh.

## In plain terms

When a different Ghoztty build is started while one is already running, the
new one can ask the running one to step aside ("Switch"). The Linux app used to
answer that request with "not supported yet". Now it agrees, finishes replying,
and quits the normal way - its terminals keep running in the background so the
new build picks them straight back up. It still says no to anything that is not
a genuinely different build.

## Goals

- [x] `handoff-quit` from a launch of another build is answered and the app quits after the reply
- [x] refused without a launch identity, and for the same build
- [x] the quit saves the layout and detaches the panes; the next launch re-attaches them
- [x] `+version` advertises `handoff_quit` and `session_persistence`
