# T3713 - Linux checks still NOT RUN for 'no seat' (pointer drag, popover, window activation) can now try hl_start_seat

## Summary

T3620 added hl_start_seat (headless sway with a wl_seat) and hl_key_serial to test/linux/lib/headless.sh. docs/claude/linux.md still records several checks as NOT RUN because Weston headless has no seat: a real pointer drag (tab/window drag), a popover that closes at once for want of a seat, window activation (no window is ever ACTIVE), and the press-key seam that stands in for real keys. For each, try it under hl_start_seat (sway also offers virtual-pointer and virtual-keyboard protocols, e.g. wtype for keys), and either convert the NOT RUN into a real check or record why the seat compositor still cannot answer it.

## In plain terms

The Linux app is tested inside a hidden, private display so it never touches
the user's screen. That display had no keyboard or mouse at all, so several
things could never be tested: whether a window really comes to the front,
whether a popup menu stays open, and whether real typed keys arrive. Now the
hidden display can hold a keyboard, and those three are real checks. The
mouse is still missing, so dragging is still untested (T3847).

## Goals

- [x] window activation: a real check on the seat compositor
- [x] the popover: a real check on the seat compositor
- [x] real keys (not the press-key seam): a real check
- [x] pointer drag: measured why the seat still cannot answer it, and filed T3847

## Findings (measured, 2026-11-26)

- sway's seat under `WLR_LIBINPUT_NO_DEVICES=1` reports capabilities 0. sway
  focuses every new window itself, but GTK's is-active follows
  `wl_keyboard.enter`, which never comes - so every `--focus` was declined.
  `hl_key_serial`'s wtype keyboard dies with its one key.
- A background `wtype -k Shift_L -s 3600000 -k Shift_L` holds a keyboard on the
  seat (`hl_seat_keyboard`): new `--focus` windows are activated. A raise of an
  OLDER window also needs `focus_on_window_activation focus` (sway's default
  `urgent` only marks it), now in `hl_start_sway_`'s config, and needs ~2s
  after sway mapped a new window or it is lost.
- The sidebar window-menu popover stays open on sway with or without a
  keyboard (an `xdg_popup.grab` at serial 0 is granted; no `popup_done`).
- Pointer: `swaymsg seat seat0 cursor set/press/release` reaches no client
  (no pointer capability); wlrctl (apt 0.2.2, not installed) creates a pointer
  per call, so no held button. T3847 builds a held virtual pointer.
