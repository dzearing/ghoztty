# T2792 - gl-device-lost.ps1 D/E red (17 failures) since T2514 made the composition present the default: the arms set only GHOZTTY_WINDOW_PRESENTER=1, and GHOZTTY_COMP_PRESENT now wins, so no pane ever hands its frames to the window presenter

## In plain terms

The test that checks a terminal recovers after the graphics driver resets
has been failing since yesterday. The app did not break. A change made a
different drawing path the default, so the path this test checks never
switches on.

## Summary

Found by T2732's due sweep (2026-11-07, lane b): `gl-device-lost.ps1`
sections D and E fail D1 "the pane hands its frames to the window
presenter" and everything after it (17 failures; A-C pass). Cause:
087055a50 (T2514, 2026-11-06 14:05) made `GHOZTTY_COMP_PRESENT` default on,
and `Window.ensurePresenter` -> `gl_window_presenter.choose` lets it win over
`GHOZTTY_WINDOW_PRESENTER` ("ignored: GHOZTTY_COMP_PRESENT is on and
wins"). The stamp was last green at 827aea0b5, before T2514.

Fix: in the D/E arms also set `GHOZTTY_COMP_PRESENT=0` (and restore it), and
add it to `$presenterKnobs` so the clean-up removes it. Then decide whether
the composition path itself needs a device-loss arm of its own (T1690 covers
WGL, D/E the presenter; the new default path has none).
