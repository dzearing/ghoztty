# T2400 - Dragging a pane divider flashes black unpainted areas that a later paint fills in, so pane resizing flickers constantly; every presented frame must already show each pane fully painted at its new size, as a game never presents a half-drawn frame

## Summary

User report 2026-10-28 (interactive, installed build 1.48.4+a691d5f4d): while resizing panes by dragging a split divider, the area a pane gains appears BLACK for one or more frames, then a catch-up paint fills it. It repeats on every mouse move, so the whole drag flickers. The user's bar, verbatim in spirit: every frame is painted correctly, like any video game - no bleeding and catching up. That means no frame may reach the screen with a pane at its new size before that pane's content (at minimum its background, ideally the reflowed grid) has been rendered at that size, for every pane the drag touches, presented together. T2359 claimed the divider drag already takes the synchronous-present path; the report shows that is not enough, or that it regressed. Find which frames show black (the T2373 frame lab's camera/scorer exist and can capture this even before its full matrix is live: its B-class bleed detector is exactly this), find why (swap chain / HWND resized before its frame is rendered, a DWM present of an unfilled client area, WM_ERASEBKGND/black class brush, panes presenting at different vsyncs), and fix it so the size change and the painted content land in the same present. Do NOT wait for T2396's idle-box matrix run or for T2360's Windows.UI.Composition rewrite: fix it on the current stack now, and keep the fix compatible with T2360. Acceptance: a WGC capture of a scripted divider drag (1, 4 and 9 panes, both orientations) has zero frames with unpainted (black or non-background) regions inside any pane and zero stale-size frames; and the user, dragging a divider in the relaunched installed build, sees no flicker. Mac counterpart: confirm the Mac divider drag has no such frames (it should not; CoreAnimation commits size and content together) and file a seat:mac task if it does.
