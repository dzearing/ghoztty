# T3892 - Linux: an idle GTK pane's released font atlases still hold their storage on llvmpipe - find the holder and prove the drop

## Summary

Found in T3775 (2026-11-28, Mesa 25.2.8 llvmpipe, allocation trace). An idle release replaces the frame's atlas textures with 1x1 ones (generic.FrameState.releaseAtlases; pane-seen atlas_bytes 1310720 -> 5), but in the trace window across an idle release no 1024 KB (grayscale) or 256 KB (color) block was freed, with or without T3775's sampler-free draw (OpenGL.dropReleasedFrameRefs), while the target's block was freed with it. Suspects: the atlas textures are still bound to texture units, or referenced by a sampler view outside the fragment stage, or by the share group (GtkGLArea contexts share with GDK's). Recipe: the LD_PRELOAD zig-cc shim and MARK lines described in docs/claude/linux.md 'Freeing the GL name is not freeing the memory (T3775)'. Done when an idle release frees both atlas blocks inside the release, shown in frame-release.sh (R5's private-memory threshold raised to the target plus the atlases, or a new R-check).
