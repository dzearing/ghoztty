# T2428 - With one pane streaming output as fast as it can (cmd for /L echo loop), the window stops answering mouse input for seconds: a divider press is not lit and a whole posted drag is never applied, and the pane sidebar still lists one pane seconds after a split; the UI thread must keep up with pointer input while a pane is busy

## Summary

Found by T2418 on 2026-10-28 with a ReleaseFast build of 6d44c9592 (sandboxed, work-area-sized window on a 3840x2100 monitor, pane sidebar expanded to 380). Probe: `temp\t2418\ghost-probe.ps1 -Exe zig-out-t2418rel\bin\ghoztty.exe -Big -Busy -Sidebar '1 0 380'` (WGC capture of a posted divider press + rightward drag, while the left pane runs `for /L %i in (1,1,200000) do @echo ...`). Without `-Busy` the same drag lights the bar on press and follows every move. With it: run 1 the bar was not lit for the first 18 captured frames after the press and lit later; run 2 (`-TickMs 2 -StepPx 10`) the bar never lit in 758 captured frames and the drag never happened (frames in `temp\t2418\20261028-182223\frames`, last one shows the panes at their pre-drag split). In both runs the pane sidebar still listed ONE pane several seconds after `+split` had made two. That reads as the GUI thread being starved while a pane streams output. It is an inference from the frames: the box CPU was also loaded (the WGC scorer kept up with only 64 of 758 frames), so the first step is to measure GUI-thread message latency under the same load (a timestamped WM_MOUSEMOVE -> handled log line), compare Debug vs ReleaseFast, and find what holds the thread (renderer frame waits, the IO thread's mailbox wakeups, sidebar roster polling). Users stream output all the time (Claude Code), so a drag or click that lands seconds late is user-visible. It may also be part of T2418's "the widening pane does not repaint while the drag is in progress".

Validation: with one pane under the same echo loop, a posted divider press lights the bar within a frame or two and a posted drag follows every move (WGC probe), and the sidebar lists a new split's pane at once.
