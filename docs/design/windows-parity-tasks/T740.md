# T740 - `` `e `` is the letter e in PowerShell 5.1, and the VT-strip helpers rely on it being ESC

## In plain terms

Several test scripts try to read the text out of a terminal recording by
stripping the invisible control codes first. The way they write "escape
character" only works in PowerShell 6 and later; on the 5.1 this box runs it
means the plain letter **e**. So the helpers delete every `e` from the text and
leave every control code in it. The checks built on them still pass, but they
are not checking what they say they are.

## Goals

- [x] One shared VT-strip helper, built on a character that really is ESC.
- [x] Both scripts that had the broken copy use it.
- [x] A standing sweep that stops a new script reintroducing `` `e ``, wired into
      the harness floor so something actually runs it.
- [x] The two scripts still pass end to end.

## The evidence

```powershell
PS> $s = "`e"; "len=$($s.Length) code=$([int][char]$s[0])"
len=1 code=101        # 101 = 'e', not 27
```

Dumping a captured WP-D3 snapshot through `Snapshot-Text` in
`test\win32\session-snapshot-reattach.ps1` produced
`C:\Us<e-removed>rs\David>` — the letters gone, the CSI sequences intact.

`Snapshot-Text` and its siblings then feed `-replace '\s',''` and a substring
match, so the assertions still find markers that happen to contain no `e` and
are never confronted with the sequences they meant to remove. A marker
containing an `e` would fail for a reason nobody could see.

## Where

`test\win32\session-snapshot-reattach.ps1` (`Snapshot-Text`) is the one that was
read directly; sweep `test\win32\` and `scripts\` for `` `e `` and `` `a `` (the
latter IS a real escape in 5.1, so only `` `e `` is wrong) rather than fixing one
site.

## The fix

Use `[char]27` (or `[regex]::Escape([string][char]27)`) explicitly, and add the
check to the harness-audit family (T725/T732) so a new script cannot reintroduce
it.

## Validation criteria

- [x] A sweep over `test\win32\` and `scripts\` reports zero uses of `` `e ``.
      `scripts\vt-escape-scan.ps1` — `CLEAN: 438 file(s)`.
- [x] `Snapshot-Text` (or its replacement) strips a real CSI/OSC sequence and
      keeps every letter, asserted against a fixture containing both.
      `test\win32\vt-escape-scan.ps1` section A, with the pre-fix regexes run
      over the same fixture as the oracle that it discriminates.
- [x] The scripts that used it stay ALL PASS with the corrected helper — the
      point is that they now assert what they claim, not that the verdict moves.

## What landed

- `test\win32\lib\VtText.ps1` — `Remove-VtSequences` / `Get-VtReadableText` /
  `ConvertFrom-VtSnapshotBase64`, built on `[char]27`, shared by both callers
  instead of the regexes being copied a second time.
- `scripts\vt-escape-scan.ps1` — the standing sweep. It walks each script with a
  small state machine rather than a regex, because the scoping IS the accuracy:
  a backtick-e is a finding only inside an *expanding* string, never in a
  single-quoted one (no escape processing at all), a comment (markdown inline
  code) or after a doubled backtick.
- `test\win32\vt-escape-scan.ps1` — acceptance for both halves, plus a negative
  control that plants a `` `e `` in a live file and asserts, inverted, that it
  goes unreported.
- Floor membership in `scripts\lib\HarnessFloor.ps1`, and the floor guard row in
  `scripts\guard-due.ps1` widened to cover the scanner itself.
