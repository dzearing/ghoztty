# T1510 - 200 acceptance scripts print their own ALL PASS, so T1039's unwound-run protection never reaches them

## Summary

T1039 made "a run that unwound may not print a green verdict, and may not stamp
its guard" structural - in `lib\TestScore.ps1`, behind `Write-TestVerdict`. It
holds for the 32 scripts that call that. The other **200** scripts in
`test\win32` that end in an `ALL PASS` line print it themselves, from their own
`$script:fail -eq 0` check, and **80 of those also write a guard stamp from the
same branch** - so on all of them the T1039 defect is exactly as it was.

Measured today on `viewer-feedback-capture.ps1`: a statement-terminating error
in the middle (an assignment to `$home`, which PowerShell makes read-only)
unwound the body, the `finally` cleaned up, and the script printed
`ALL PASS (14)` over a run whose full sweep is 92 assertions - and stamped
`viewer-feedback-capture`, telling the next turn the selector had been proven.
Nothing was red anywhere. Only reading the transcript caught it.

## In plain terms

The scripts that prove Ghoztty works can still crash halfway and announce that
everything passed. That was fixed once, but the fix only reached a sixth of
them: the rest end with a hand-written "ALL PASS" line of their own, and eighty
of those also record that the feature was tested. After this lands, a run that
did not reach its own end says so, is red, and records nothing - on every script
in the suite, not on the ones that happened to opt in.

## Goals

- [x] the gap is MEASURED: a sweep names every script whose verdict the scorer
      does not decide, and every script that stamps a guard unarmed
- [x] the gap cannot GROW: both counts sit under a ratchet with teeth
- [x] the exact shape this was found on is a demonstrated case of the rule
- [x] one script is converted end to end as the worked example, and its
      conversion is proven on a real process in both directions
- [ ] every `test\win32` script converted -> **T1511** (the 79 that stamp) and
      **T1512** (the rest, plus promoting the kinds to hard)

## What is left, and where it lives

The conversion itself is a burn-down of 198 files, each of which has to be RUN
green on the box, and most of which are GUI acceptance scripts that take
minutes. It is not one change and it was never going to fit one turn. It is
split rather than hidden: **T1511** takes the 79 scripts that also write a guard
stamp (the half whose damage outlives the run), **T1512** takes the remainder
and promotes `self-verdict` / `uncounted-final` / `unarmed-stamp` into
`Get-AssertedNothingHardKinds`, and **T775** - the same conversion seen from
T271's side - closes against T1512.

The two numbers are public on every run of `asserted-nothing.ps1`, so the gap is
a figure that has to fall rather than a thing to remember.

## Validation criteria

- [x] a converted script with a mid-run throw does NOT print a green verdict,
      exits non-zero, and writes no stamp - demonstrated on a real process:
      `viewer-feedback-capture.ps1` with the `$home` assignment put back in
      printed `1 FAILURE(S) (1 assertions passed)`, exited 1, and left the
      stamp file untouched. Before the conversion the same injection printed
      `ALL PASS (14)` and stamped.
- [x] the exact shape found today (assigning to a read-only automatic variable)
      is one of the demonstrated cases: section A9b-A9d of
      `test\win32\body-complete-audit.ps1`, run as a real process, asserting
      `RUN DID NOT FINISH (14 assertions passed)` and exit 2
- [x] the sweep reports both counts across `test\win32\*.ps1` and its
      teeth-check proves both assertions can fail: sections C4/C5 of
      `test\win32\asserted-nothing.ps1`, `-TeethCheck` green on a synthesized
      violator that is a real fixture put through the analyzer
- [ ] zero self-printed verdicts across the suite -> T1512
- [x] the P1-P3 floor and the converted suites still pass
