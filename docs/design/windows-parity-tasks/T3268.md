# T3268 - BuildFresh's source scan misses release-notes/*.json, which the build embeds: a release-notes commit leaves zig-out stale while the runner says BUILD FRESH, and agent-upgrade J5a goes red

## Summary

test\win32\lib\BuildFresh.ps1 Get-GhozttySourceHighWater scans build.zig, build.zig.zon and src\ only, but src\build\GhosttyReleaseNotes.zig embeds every release-notes\{client,agent}\*.json into ghoztty.exe. Seen 2026-11-19 (T1518): zig-out built 19:13, release-notes\agent\1.55.10.json landed 19:31 (97938eb7a), acceptance-parallel said BUILD FRESH, and agent-upgrade J5a (the What's new accessory) failed because the exe had no 1.55.10 notes to show. Every Windows release lands such a commit, so this recurs after each one. Fix: add release-notes\ (*.json) to the high-water scan, and prove it in build-fresh-guard.ps1.
