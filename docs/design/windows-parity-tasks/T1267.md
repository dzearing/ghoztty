# T1267 - The desktop-launch sweep cannot see a launch assembled as a string or spawned by a script's own CreateProcessW

## In plain terms

Our tests are not supposed to pop terminal windows onto your screen while you
work; a checker reads every test script and flags the ones that would. It only
recognised a few ways of writing "start the app", so scripts that spelled it
differently - through the console twin, a renamed copy, or their own low-level
launcher - slipped past it and could still throw windows at you. It now
recognises those spellings, and it immediately found two real scripts doing
exactly that, which are now listed and queued for fixing.

## Goals

- [x] the four pre-T1240 launch sites in cli-launch-cwd.ps1 are all reported
- [x] the `.com` twin, aliases/copies of the exe, and static-method spawns count as launches
- [x] the false positives the widening could create (decoys, the agent, relay binaries, `+list` wrappers, lpDesktop-routed spawns) are measured negatives
- [x] what the sweep newly found on the real tree is declared and filed, not ignored

## Summary

`lib\DesktopLaunchAudit.ps1` states its own blind spot in its header - an
invocation assembled as a STRING and handed to another interpreter is not a
command in the AST - and T1240 walked straight into the consequence.
`cli-launch-cwd.ps1` had FOUR launch sites; the sweep saw one:

- arm A: `cmd /c "cd /d <dir> && "<Com>" ..."` via `Start-Process cmd.exe` - a
  real GUI on the user's desktop, invisible to the sweep.
- arm C: the same shape with `$Exe` instead of the `.com` twin.
- arm D: `[T506Spawn]::StartDetached($Exe, ...)`, the script's own
  `CreateProcessW` P/Invoke - the exe is an ARGUMENT to a static method, so
  neither the command-name rule nor the `$Exe`-invocation rule fires.
- arm B: `Start-Process -FilePath $Exe` - the one the sweep flagged.

So a script can be declared migrated, pass the sweep, and still put three
windows on the user's screen. The declaration list burns down on a question
narrower than the one it is read as answering.

Two shapes to consider, and the second is the one with teeth:

1. Widen the AST rules: a `cmd.exe` / `powershell` invocation whose argument
   string CONTAINS the exe reference, and a call passing an exe-shaped variable
   to a `[Type]::Method(...)`. Both are heuristics, and the header is right that
   no textual rule can be complete.
2. Ask the BOX instead of the source: run each script and assert that no
   ghoztty process from the repo build ever reports a window to the interactive
   desktop while it runs. `AnyVisibleWindowOnInteractiveDesktop` already exists
   in `lib\TestDesktop.ps1` and is exactly this measurement; the missing piece
   is a harness that applies it per-script. That answers the question the list
   is read as answering, and it cannot be defeated by how a launch is spelled.

## Outcome

Shape 1 (widen the static rules), my call: the box-measuring harness is a
different, opt-in tool (it can only catch a window by showing it to the user),
so it is filed as T2203 rather than folded in. What the analyzer now reads:

- `$Com`-suffixed variables and `ghoztty(.exe|.com)` literals.
- Aliases: `$x = <ref>`, `$x = Join-Path ... 'ghoztty.exe'` (not the agent),
  `Copy-Item <ref> $x`, iterated. Decoys - a copy into the name from another
  program (cmd, ping, powershell), and a `.com` twin beside such a copy - are
  never the app.
- Static-method spawns `[T]::Start*/Spawn*/Launch*/Run*/Exec*/CreateProcess*`
  with a ghoztty argument, classified by the argv after the exe, EXCEPT when the
  method's own C# body (brace-matched, one call hop) assigns `lpDesktop`.
- `Start-Process <exe> -ArgumentList $param` inside a wrapper is scored at the
  wrapper's calls (ipc-timeout.ps1 only ever passes `+list`).

The first widened sweep reported 20 sites; 18 were measured false positives
(the agent, relay binaries, cmd/ping/powershell decoys, the spike's
`Run`->`Body` lpDesktop, a `+list` wrapper) and were turned into negatives
B32-B36. Two were real and had been opening windows on the user's desktop with
the audit green: upgrade-no-fork.ps1 (T2201) and update-real-msi.ps1 (T2202).
