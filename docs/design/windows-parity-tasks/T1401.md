# T1401 - Sweep the acceptance scripts for single-sample window lookups and comparisons that pass vacuously on null

## Summary

T1392 found both halves of this pattern in one place, `test\win32\viewer-feedback.ps1`:

```powershell
$contentBefore = Get-ContentTop $view.Pane          # one sample, no wait
Assert ($null -ne $contentBefore) "..."             # goes red on a slow box
...
Assert ($contentOpen -gt $contentBefore) "..."      # and this then passes for free
```

Two distinct defects that reinforce each other:

1. **The lookup had no wait loop**, alone among the window lookups in that file —
   every sibling (`Get-ViewerHost`, `Get-ChromeChild`) polls. The WebView2 widget
   is created asynchronously after the host window it hangs off, so a single
   sample is a race, and the assertion went red on a box where it simply arrived
   later.
2. **The comparison underneath passed VACUOUSLY** when that value was `$null`:
   PowerShell's `<int> -gt $null` is `<int> -gt 0`, which is true for any real
   pixel coordinate. So the one assertion that proves the page is actually inset
   by the composer's band had been asserting nothing whenever the first one
   failed — the interesting half was silently disarmed by the boring half.

Both are fixed in that file. The question this card asks is how many other
acceptance scripts carry either shape, since neither is visible in a green run —
that is the whole problem with a vacuous assertion.

## In plain terms

One of our tests was quietly not checking the thing it was written to check, and
we only found out because a different bug in the same six lines made it go red.
This is a sweep for the same mistake everywhere else, before the next one is
found the same way.

## What to look for

- **Single-sample lookups**: a `Get-*` of a window, control or child that is
  asserted non-null without a bounded retry loop, in a script whose other
  lookups poll. Anything created asynchronously (WebView2, a controller's host
  window, a late child) needs the wait.
- **Comparisons against a possibly-null value**: `-gt`, `-lt`, `-ge`, `-le`
  against a variable that an earlier assertion allowed to be `$null`. In
  PowerShell these coerce rather than throw. The rule to apply: if assertion B
  reads a value assertion A might have failed to produce, B asserts A's value is
  non-null too — or the harness stops at A.
- **`-eq $null` on an array-valued expression**, the sibling trap already
  recorded for this box (a function's array return unrolls, and a one-element
  result has a `$null` `.Count`).

## Findings (2026-11-10 sweep, all 503 `test\win32\*.ps1`)

Method: three PowerShell-AST passes over every script (each `Assert`/`Check`/
`Expect` call), plus a class search for every WebView2 child lookup.

**Comparisons against a possibly-null value**

| Site | Verdict |
|---|---|
| `viewer-feedback.ps1` D, `$contentTall -gt $contentOpen` | **FIXED** - `$contentOpen` is arm C's `Get-ContentTop` read, null-tested there and then compared unguarded (`<int> -gt $null` is true) |
| `viewer-feedback.ps1` D, `$contentTwoLine -lt $contentTall` | **FIXED** (guard added) - the non-vacuous direction today, but one flipped operator from vacuous |
| `chrome-theme.ps1` G2, `$gAfter -gt $gIdle` | **FIXED** - `Get-PaintCount` has an explicit `return $null`; G2 passed for free on exactly the run where G1 could not read the counter |
| `dpi-change.ps1` B3/B4, `$colsA1 -lt $colsA` | safe - the script `throw`s at line 159 when either baseline is null |
| `rearrange-mode-action.ps1` A, `$inMode -gt $baseline` | safe - `Write-TestAssertedNothing` at line 168 on a null baseline |

A wide pass (any helper-returned variable on the vacuous side) gave 303 sites in
127 files; spot-checked samples are `IndexOf`, `.Count`, `ElapsedMilliseconds`,
`[math]` arithmetic and helpers with no null path (`Get-LastLineNo` returns 0,
`Get-ProbeDistance` -1, `Get-MaxBlueTint` -255, `Get-BandH` 0) - noise, recorded
as such, not individually listed.

**Single-sample async lookups**: none left. Every `Chrome_WidgetWin_*` /
`Chrome_RenderWidgetHostHWND` lookup (split-dim-viewer x2, viewer-find,
viewer-panes x3, chooser-open-chord, hero-nav, tab-overview-action,
viewer-image, viewer-window-chords, rearrange-mode-action, viewer-feedback,
viewer-composer x3 via `Get-ComposerView`) sits in a bounded poll; T1392's was
the only one.

**`$x -eq/-ne $null` with the variable on the left**: 3 sites, all scalars
(`chooser-resume.ps1:328` a string id, `clipboard-retry.ps1:414` already
`$null -ne` first, `website-windows-download.ps1:423` a response object) - safe.

**Mechanical check - judgement**: a FULL check is not mechanical (whether a
helper can return `$null` is data flow; the wide pass is 303 sites of noise).
Two narrow shapes ARE precise - guarded-then-compared (4 hits, 2 real) and
explicit-`return $null` helper (2 hits, 1 real) - and belong as a new kind in
`lib\UnrollCountAudit.ps1`, which already binds a variable to its nearest
assignment and indexes repo helpers. Filed as **T2886** (P3).
