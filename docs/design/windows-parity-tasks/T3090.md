# T3090 - The font atlas never gives memory back: Atlas.clear keeps its grown size and a grown atlas is never shrunk, so a burst of CJK/emoji output leaves every font grid holding its peak atlas for the session

## Summary

The never-shrinks half of PA-R07 (audit-1, T2959), split off when T2973
fixed the upload half. `src/font/Atlas.zig` `grow` doubles the texture on
AtlasFull (SharedGrid.zig ~:320) and nothing ever makes it smaller:
`Atlas.clear` zeroes the data and resets the nodes but keeps the size and the
allocation. So one burst of CJK/emoji output leaves the grid - and the GPU
texture in each frame of each pane using it (T2973 left one texture per frame
per pane; sharing them is PA-R03) - at its peak size for the life of the grid.

Fix shape to decide: a shrink-on-clear when the glyph cache is flushed, or a
grid-level compaction once usage falls well under capacity; either must
invalidate the glyph cache's atlas regions. Measure first: `perf-baseline.ps1
-Phase cycle` GPU dedicated+shared memory after a `-BusyText cjk` run. Shared
code: Mac half rides the shared-renderer Mac task.

## Validation criteria

- [ ] a unit test: after a grow and a shrink/compaction, the atlas is smaller and still renders every live glyph
- [ ] measured: process GPU memory after a CJK burst returns toward the pre-burst figure
