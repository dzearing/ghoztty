# T2821 - Composition step 5c-4c: a card opening out of its strip is declared to DirectComposition once its new-size frame has landed, so a busy window thread no longer freezes an unfold (T2778 left unfolds on frames)

## Summary

T2778 handed a FOLDING card's face to the compositor whole (`Window.declareStripFace`, `Host.faceDeclare`): band, name and carried frame as three pictures, with the card clip, the places and the fade on the 45 ms follower. An OPENING card (T2458, `view.openingCarried()`) stays stepped from the window's thread, because its new-size frame is still being drawn while it widens: the face starts as the band alone and the frame lands mid-glide. So a busy window thread still freezes an unfold. Fix: declare from the frame the opening lands at, the same way T2778 declares a fold. Re-declare once when the frame lands (picture swap, same follower, `FaceDecl.reached`). The fade runs the other way (strength rising from 0), so check `fadeLine` and `FacePose.fadeKnee` for the 1-side clamp. Oracle: a stall arm on an unfold in `scripts\comp-glide-hold-onscreen.ps1` (the stall.13 shape), with `-NoDeclare` red; `pane-stack-unfold.ps1 -Tree` ALL PASS.
