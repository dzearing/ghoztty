# T3211 - No test drives a cross-machine Restore All in single-window mode: T3206 parked the relay arm (adoptRestoreAll) and re-resolves its chooser, but only the local arm is exercised

## Summary

Filed from T3206. `App.adoptRestoreAll` (the cross-machine Restore All arm,
`RestoreAllRelay`) now builds each window with `restoreParksBehindShown()` and
puts the last built on show once (`showRestoredFront`), and
`MachineChooser.onRestoreAll` re-resolves its chooser by id after the rebuild,
because that final hand-off cancels the chooser the surrendering workspace
owned. Section M of `test/win32/single-window-mode.ps1` proves both for the
LOCAL arm only. The relay arm differs in one way that matters: a dialed window
is built whole (`restoreWindowShown` skips the tab split when `tr.dialed` is
set), so a multi-tab remote window stays one workspace with tabs in single
mode - which may itself be a gap against Mac. Fix: a single-mode variant of
`test/win32/chooser-restore-all-remote.ps1` that counts `workspace adopted the
window` lines after the press (exactly one) and asserts the app survives.

## Validation criteria

- [ ] cross-machine Restore All in single mode: every rebuilt workspace present, the frontmost on show, exactly one hand-off, no crash
