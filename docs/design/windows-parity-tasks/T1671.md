# T1671 - Clicking a command-palette row picks the wrong command once the list has scrolled

## Summary

App.zig's WM_LBUTTONDOWN turns the click Y into a VISUAL row and assigns it straight to Surface.palette_selected, which is an ABSOLUTE index into palette_filtered. paintPalette scrolls the list once the selection passes the last visible row, so after arrowing down far enough (or with a short popup), clicking row N runs the command scroll_offset+N rows down instead. Found while landing T891, which added the section-header rows this hit-test now also has to skip (it does - clickPaletteRow refuses a header - but the offset was never applied). Fix: add the same scroll_offset paintPalette computes, ideally by hoisting that computation into one place both the paint and the hit-test call. Validation: a none-lane unit test over the shared row-at-Y derivation, plus an arm in test\win32\palette-order.ps1 that scrolls and clicks.

## In plain terms

In the command palette, if you arrowed down far enough that the list scrolled
and then clicked a command with the mouse, a different command ran - the one
that sat in that spot before the list scrolled, several rows higher up. Now a
click always runs exactly the command you see under the pointer.

## Goals

- [x] one derivation of the palette's scroll, shared by the painter and the click hit-test
- [x] a click on a scrolled list runs the row painted under the pointer

## Validation criteria

- [x] The scroll and row-at-Y math is unit-tested in the none lane: `palette_order.zig` tests `scrollOffset`, `rowAtY` (unscrolled, scrolled, past-the-end, zero-height) and `maxVisible` — `scripts\floor-lane.ps1 -Lane all`.
- [x] `paintPaletteInto` and the `WM_LBUTTONDOWN` hit-test both go through `palette_order.scrollOffset` (`Surface.paletteRowAtY`), so they cannot drift — code read.
- [x] On-box: `test\win32\palette-order.ps1` O5a/O5b — Enter on row 5 names `prompt_window_title`; a second launch arrowed until row 5 is the TOP slot, then clicked there, also runs `prompt_window_title`. ALL PASS (25 assertions).
- [x] Negative control: with the scroll offset subtracted back out of the hit-test (the pre-fix behaviour), O5b FAILS and the click runs `about` (row 0) — 1 FAILURE(S).
