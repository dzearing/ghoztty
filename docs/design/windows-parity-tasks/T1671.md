# T1671 - Clicking a command-palette row picks the wrong command once the list has scrolled

## Summary

App.zig's WM_LBUTTONDOWN turns the click Y into a VISUAL row and assigns it straight to Surface.palette_selected, which is an ABSOLUTE index into palette_filtered. paintPalette scrolls the list once the selection passes the last visible row, so after arrowing down far enough (or with a short popup), clicking row N runs the command scroll_offset+N rows down instead. Found while landing T891, which added the section-header rows this hit-test now also has to skip (it does - clickPaletteRow refuses a header - but the offset was never applied). Fix: add the same scroll_offset paintPalette computes, ideally by hoisting that computation into one place both the paint and the hit-test call. Validation: a none-lane unit test over the shared row-at-Y derivation, plus an arm in test\win32\palette-order.ps1 that scrolls and clicks.
