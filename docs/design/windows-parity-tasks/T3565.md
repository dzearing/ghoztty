# T3565 - Linux L11c: copy out of a TUI pastes as clean prose on GTK, and regex links span wrapped rows - prove it with a GTK acceptance test

## Summary

Port docs/reference/copy-reflow.md. The cleanup itself is shared core (src/terminal/hard_wrap.zig, called from src/Surface.zig), so the Linux work is to prove the GTK copy path (Ctrl+Shift+C, copy-on-select, the PRIMARY selection) reaches it, and fix any GTK clipboard path that bypasses it: a TUI that re-indents its own wrapped rows (Claude Code, Ink/wrap-ansi) must paste as unbroken paragraphs, and a URL the TUI wrapped across rows must open as one link. Acceptance in test/linux/ driving the CLI only (send-keys the fixture, read the clipboard with wl-paste inside the headless compositor).

## In plain terms

When you copy text out of a program like Claude Code that wraps its own
lines, the Mac pastes it back as normal paragraphs, and a long web address it
broke over two lines still opens as one link. This proves the Linux app does
the same - from the keyboard copy, from selecting with the mouse, and from
select-all - and makes sure a test clicking such a link can never open a
browser on the user's screen.

## Goals

- [x] confirm every GTK copy path reaches the shared cleanup (no GTK path builds clipboard text itself)
- [x] a terminal link click in a debug test run is recorded, never handed to the desktop
- [x] a GTK acceptance test proving clean-prose copy and one-link URLs across wraps
- [x] follow-ups filed for what the headless harness cannot prove yet

## Validation criteria

- [x] Ctrl+Shift+C and select-all put the paragraph back as one line, the URL whole, code lines kept apart - `test/linux/copy-reflow.sh` R9-R13 (wsl-run, ALL PASS)
- [x] copy-on-select from a mouse drag fills PRIMARY with exactly the paragraph as one line - R14/R15
- [x] the same check FAILS on the screen as laid out (`+read`), so it can go red - R7/R8 negative controls
- [x] Ctrl-hover lights the URL from either side of the seam, not from the skipped margin or the code row - R16-R19
- [x] Ctrl+click on the URL's last row opens the WHOLE URL, recorded under GHOZTTY_TEST_VIEWER_LINKS - R20; Copy URL copies it whole - R21
- [x] nothing left the app for the desktop - R22
- [ ] a paste into ANOTHER app (wl-paste) - not provable in this harness (no seat); T3620
