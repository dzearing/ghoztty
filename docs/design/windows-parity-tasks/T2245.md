# T2245 - No acceptance run closes a whole TAB holding a viewer, so the closeTabByIndex release order T1358 fixed is checked only by the source audit

## Summary

T1358's tree-swap audit found closeTabByIndex freeing a closing tab's tree before removing its slot (the T1356 crash shape) and fixed the order, but viewer-close.ps1 only closes windows and single panes. Add a section that closes a tab holding a terminal beside a focused viewer with the contents card up, with undo-timeout = 0 so the tab is really released rather than parked, in a window that keeps another tab, and asserts the app survives. Prove it red against the pre-T1358 order (T1133).

## In plain terms

Closing a whole tab that has a document viewer in it once could take the
entire app down, the same way closing a window with a viewer did. The fix
for the tab case was only checked by reading the source. Now a real test
opens a window with two tabs, puts a terminal and a viewer in one, closes
that tab from its x, and checks the app lives on and the cleanup happened in
the safe order.

## Goals

- [x] `viewer-close.ps1` closes a TAB holding a terminal and a focused viewer
      (contents card up) from the tab strip's x, in a window that keeps its
      other tab, with undo off so the tab is really released.
- [x] It goes red against the pre-T1358 `closeTabByIndex` order (T1133).
