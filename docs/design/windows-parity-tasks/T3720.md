# T3720 - Linux: a viewer page on glass takes its light/dark scheme from the desktop, not from the terminal background its ink sits over

## Summary

T3622 makes template viewer pages see-through over the pane's glass sheet, which is the terminal background tinted over the desk. win32 (viewer_glass.pageScheme, T1885) and Mac (the window appearance follows the terminal background) then tell the page prefers-color-scheme from that background; GTK's WebKit follows the desktop theme, so a light terminal on a dark desktop (or the reverse) would draw light ink on a light sheet. Fix: on glass, set the web view's color scheme from viewer_glass.pageScheme(on_glass, terminal background) (WebKitGTK 6: webkit_settings / adw style manager per view). Acceptance: viewer test with a light terminal background under a dark desktop scheme reads dark ink over the sheet.

**As built (2026-11-26):** WebKitGTK 2.52 has no per-view colour-scheme
setting (none in its headers), and the app's libadwaita style is the chrome's
too, so the PAGE holds the scheme (`src/apprt/gtk/viewer_glass_scheme.zig`).
`forced(on_glass, mode, sheet background)` is win32's
`viewer_glass.pageScheme` for template pages on glass, null otherwise; the
Surface hands the Viewer its sheet background with every glass sync, so a
config reload moves it. `applyJs` runs on every commit/load: it re-points each
template `<link>` at `?gz-scheme=<light|dark>`, rewrites a link's `media`
attribute and any readable inline `<style>`, and sets the root's
`color-scheme`; `null` restores the originals. The `ghoztty-viewer` scheme is
registered local, so page script cannot read the sheets' rules (`cssRules`
throws SecurityError - measured): the scheme handler answers the
`prefers-color-scheme` conditions in the CSS it serves instead
(`rewriteCss`). A website or a rendered `.html` file is not held (it draws its
own background, and its sheets are not ours); that half of the Mac/win32 rule
is T3849.

## In plain terms

On Linux a markdown or code viewer pane in the glass style shows its text
straight over the pane's tinted terminal colour. The page picked light or
dark text from the desktop's theme, so a light terminal on a dark desktop got
pale text on a pale background, hard to read. Now the page picks from the
terminal colour it sits on, like the Mac and Windows builds.

## Goals

- [x] On glass a template page's light/dark follows the terminal background, not the desktop
- [x] Off glass it follows the app style again (the hold is released)
- [x] A reload that changes the background moves the page's scheme with it
