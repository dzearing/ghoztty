# T1748 - Activity Monitor's Show all checkbox stays clickable when the machine cannot filter to Ghoztty's processes

## Summary

Mac disables the Show all toggle (forced on) when canFilterSpawned is false (RemoteActivityMonitorView.swift:1016-1024): with no root pid and no pane-attributed row there is no spawned set to narrow to, so the checkbox would do nothing. win32 leaves it enabled and clickable in that state (no EnableWindow anywhere in the panel), so unchecking it silently changes nothing. T1634 already gives it the right tooltip for that state (activity_help.showAll's pre-dates sentence); the control's enabled state should follow activity_help.canFilterSpawned, and a harness should drive a source with neither a root nor attribution.

## In plain terms

The Activity Monitor has a "Show all" checkbox that switches between every
process on the machine and only the ones Ghoztty started. When the machine
cannot tell which processes those are (an older agent, no Ghoztty pane on it),
the checkbox did nothing when clicked, yet still looked clickable. Now it is
greyed out in that state, the way it is on the Mac, and hovering it still says
why.

## Goals

- [x] "Show all" is disabled exactly when there is no spawned set to narrow to (no root pid, no pane-attributed row), and enabled again the moment one appears
- [x] Tab steps over the disabled checkbox instead of parking focus on it
- [x] Hovering the disabled checkbox still shows Mac's "pre-dates" sentence (a disabled control gets no mouse input, so the panel answers for it)
- [x] An acceptance harness that sees the checkbox both disabled and enabled

## Design notes

- Mac (`RemoteActivityMonitorView.swift:1016-1024`) disables the toggle and
  leaves its bound value alone; win32 does the same: `EnableWindow` follows
  `activity_help.canFilterSpawned`, and `show_all` is not rewritten (the
  filter already ignores it while `spawnedOnlyActive` is false).
  `activity_view.syncShowAllEnabled`, called from every `rebuild`.
- Focus is handed off before disabling a control that holds it (the same
  deaf-panel trap `refreshChrome` documents for hiding Kill), and
  `focusVisibility` drops the stop while disabled.
- comctl32's subclass tool never fires on a disabled control, so while
  disabled the checkbox's rect is a PAINTED help surface
  (`activity_hover.comctlShows` / `paintedAt`), placed under the control.
- The state cannot arise on this box on its own (every agent here sends
  `agent_pid`, a Local panel knows its own pid), so a debug-only seam,
  `GHOZTTY_TEST_ACTIVITY_NO_SPAWNED=1`, makes Local samples carry no root and
  no attribution - same fences as T1640's row-cap seam.

## Validation criteria
