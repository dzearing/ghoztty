# T1526 - A window's last pane can be dragged back into another window

## In plain terms

If a window has only one pane left, you should still be able to drag that pane
into another window — the empty window then goes away. Mac shipped rearrange
mode refusing exactly that drag and fixed it a commit later; Windows should
never ship the refusal in the first place.

## Summary

`fd7385c42` on `origin/main`: the drop policy treated a window's last pane as
undraggable (moving it would leave an empty window), so the natural
"fold this window back into that one" gesture did nothing. The fix allows the
move and tears the source window down. Mac's `PaneMovePolicyTests` is the
reference for the cases.

Do this as part of T1525 if the policy is written from scratch there; this card
exists so the case is not lost if T1525 lands without it.

## Goals

- [ ] Dragging a single-pane window's pane into another window moves it.
- [ ] The now-empty source window closes rather than lingering.

## Validation criteria

- [ ] A unit test covers the last-pane move policy.
- [ ] An acceptance script drags the last pane of a two-window layout and asserts one window remains.
