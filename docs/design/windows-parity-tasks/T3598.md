# T3598 - Linux: launching a different Ghoztty build while one runs asks Switch / Open Window / Cancel, as on Windows

## Summary

The launch half of win32's T1022/T1023/T1070 handoff on GTK. Today a second build's launch on Linux just finds the socket served and joins (or, with --gtk-single-instance=false, runs beside it) without telling the user the window they got is another build's. Port win32 App.zig's launchIdentity/handoffChoice/requestHandoffQuit flow: compare identities via +version, prompt with the shared ipc_handoff.mismatchPrompt (GtkAlertDialog), on Switch send handoff-quit (served since T3595), wait for the pid to exit, bind the socket and restore. Mac has no counterpart (single .app); this is Windows-born parity.

## In plain terms

If you start one copy of Ghoztty on Linux while a DIFFERENT version is already
running, it used to quietly hand you a window from the old one (or run a second
copy beside it). Now it asks, the way Windows does: **Switch** closes the old
version and starts the one you launched - your terminals come back in it -
**Open Window** opens the window in the version already running, and
**Cancel** does nothing. Starting the same version twice never asks.

## Goals

- [x] a launch of a different build shows Switch / Open Window / Cancel (no Switch against a build that cannot be switched)
- [x] Switch quits the running build and this launch takes over, re-attaching its terminals
- [x] Open Window opens the window (and its `-e` command) in the running build; Cancel opens nothing
- [x] the same build is never asked; anything that fails falls back to the old behavior
