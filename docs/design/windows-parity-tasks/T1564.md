# T1564 - The freshness gate judges build-graph-only sources by the app exe's timestamp, so editing build.zig forces a rebuild opt-in

## Summary

T722 could not run test\win32\build-locked-artifact.ps1 until GHOZTTY_TEST_REBUILD_STALE=1 was set, because Assert-GhozttyFreshBuild compared ghoztty.exe's build time against src\build\InstallUnlock.zig - a file that is part of the BUILD GRAPH and can never be inside the exe's module graph, so no amount of rebuilding makes the exe newer for the right reason. Every change to build.zig or src\build\*.zig hits this, and the opt-in it steers you to forces a full rebuild to clear a staleness that was never real. The gate should treat src\build\** (and build.zig) as build-graph sources covered by a build having RUN rather than by the exe's timestamp.
