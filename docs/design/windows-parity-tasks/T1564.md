# T1564 - The freshness gate judges build-graph-only sources by the app exe's timestamp, so editing build.zig forces a rebuild opt-in

## Summary

T722 could not run test\win32\build-locked-artifact.ps1 until GHOZTTY_TEST_REBUILD_STALE=1 was set, because Assert-GhozttyFreshBuild compared ghoztty.exe's build time against src\build\InstallUnlock.zig - a file that is part of the BUILD GRAPH and can never be inside the exe's module graph, so no amount of rebuilding makes the exe newer for the right reason. Every change to build.zig or src\build\*.zig hits this, and the opt-in it steers you to forces a full rebuild to clear a staleness that was never real. The gate should treat src\build\** (and build.zig) as build-graph sources covered by a build having RUN rather than by the exe's timestamp.

## In plain terms

The test scripts refuse to run when the terminal build looks older than its
source code. Editing the build script itself tripped that refusal even after a
fresh build, because the build script is not part of the program and the
program never gets "newer" than it. Now a build that has actually run clears
the refusal, so nobody has to reach for the override switch.

## Goals

- [x] build.zig and build-graph-only src\build\ files are judged by the newest compiled build runner, not by the exe
- [x] src\build\ files the exe imports (Config.zig and its local imports) and build.zig.zon stay on the exe's timestamp
- [x] the refusal text says a plain build clears a build-graph edit

## Validation criteria

- [x] a build.zig / InstallUnlock.zig edit with no build since is still refused, and a build runner compiled after it clears it - build-fresh-guard.ps1 section H (H3-H9), 55/55 via acceptance-parallel
- [x] an exe-imported src\build\Config.zig edit is NOT cleared by the runner, and code drift outranks a covered graph mark - H10-H12
- [x] the harness can go red - `-NegativeControl` run: 1 FAILURE (F2), exit 1
- [x] the real tree reads fresh (F2 positive control; runner preflight `BUILD FRESH`)

## Decision (mechanism, recorded per go.md 5b)

Proof that a build read a build-graph edit = the newest
`<repo>\.zig-cache\o\<hash>\build.exe` (zig compiles a new runner on the first
build after such an edit; ~4000 dirs scanned in ~45ms, cached per process).
Rejected: a stamp written from build.zig (shared core, and the install step
does not rewrite unchanged files, so no mtime signal). Residual: a bare
`zig build agent` after a build.zig edit that DOES change the exe compiles
the runner without rebuilding the exe; the turn's first test step is the
Debug `zig build`, which closes it.
