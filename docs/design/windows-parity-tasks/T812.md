# T812 - The chooser's CPU meter has no tooltip, so a reading over 100% has no units and a throttled stream looks stalled

## Summary

Mac's cpuMeterHelp explains the meter on hover: it names the units (a number over 100 is confusing without them) and, when the agent has stretched its own cadence under load, says so - otherwise a slow-moving meter reads as a broken one. The win32 meter draws the bar and the number with nothing to explain either. The interval the agent chose is already in every frame and already stored (chooser_cpu.Store.intervalMs), so this is the hover surface plus the wording, not new plumbing.

## In plain terms

The machine chooser shows a little CPU bar and a number beside each session.
The number can read 250%, which looks like a mistake until you know it counts
whole cores rather than the whole machine - and when the session list is slow
to update, a bar that barely moves looks broken rather than deliberately
slowed down. Hovering the meter now says both things in a tooltip, exactly the
way it already does on the Mac.

## Goals

- [x] hovering a session's CPU meter shows a tooltip naming the units
- [x] a stream the agent has throttled says so on a second line, and an
      ordinary one does not
- [x] the tooltip appears only where a meter is actually painted
- [x] moving off the meter takes the tooltip away

## Validation criteria

- [x] `chooser_cpu.helpText` reproduces Mac's `cpuMeterHelp` wording, including
      the throttled second line - four none-lane unit tests in
      `src/apprt/win32/chooser_cpu.zig` (units named; throttled line at 6s;
      a negative/NaN reading still spells 0%; the widest reading fits the
      buffer). Verified: `zig build test -Dapp-runtime=win32`.
- [x] the hit test answers the meter column only: reading-gated (a row the
      frame did not name has no tip), capability-gated (no column reserved =
      no tip), and scroll-aware - three tests in `SessionRoster.zig`. Verified:
      the same lane.
- [x] on the box, hovering a real meter derives the real text and moving off
      drops it, with a negative control under an agent that cannot serve the
      stream - section G of `test\win32\chooser-session-cpu.ps1`. Verified:
      ALL PASS (25 assertions), tip read back as
      `95% CPU across this session's whole process tree (100% = one core).`
- [x] the standing floor stays green (`scripts\floor-lane.ps1 -Lane all`).
