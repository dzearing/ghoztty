# T1548 - Activity Monitor rows have no hover detail: Name, %CPU, Window / Pane and Path carry no tooltip

## Summary

Mac puts a .help() on every process-table cell (RemoteActivityMonitorView.swift:1082-1142): the Name cell shows the full command, the Path cell the whole path, and the Window / Pane cell a multi-line detail naming the window, the pane, its position, its directory and its tty. The win32 panel has no tooltip infrastructure at all, so a truncated cell simply loses that information. T709 ported the Window / Pane column and deliberately left the detail string behind, since building the first row tooltip in this panel is its own piece of work; PaneAttribution.detail is the text to port once there is somewhere to put it.

**Re-verified 2026-11-20:** partly superseded. T1634 has since built the tooltip plumbing (`help_tooltip.zig`, `activity_hover.zig`) for the control bar, so what was left was the table cells themselves plus the pane detail string.

## In plain terms

In the Activity Monitor, a long process path or command got cut off with an ellipsis and there was no way to read the rest, and the Window / Pane column named a pane without saying anything more about it. Now resting the pointer on a Name, Path or Window / Pane cell shows the full text in a tooltip, the way the Mac app does. The Window / Pane tooltip lists the window, tab, pane, directory and shell PID.

## Goals

- [x] Name cell shows the full command (or the name when there is no command), Mac :1088
- [x] Path cell shows the whole path, Mac :1142
- [x] Window / Pane cell shows the pane's detail, or "Not started by a Ghoztty pane.", Mac :1129
- [x] PID, Memory and %CPU say nothing, as on Mac (the %CPU "unverified" tip is T1549's)

## Design notes

- **Shell PID instead of TTY.** ConPTY has no tty name, and the shell PID is what win32 attribution is seeded from, so the detail says `Shell PID: <n>` where Mac says `TTY:` (the `+list --tty` -> `--pid` translation).
- **A `Tab:` line for multi-tab windows.** Mac's window is one tab, so `Window:` already pins the pane down there. A win32 window can hold several tabs, so the detail adds `Tab: <title> (i of n)` (or `Tab: i of n`) when there is more than one.
- Cell tips answer anywhere in the cell (Mac's `.help()` on a cell does), are one surface per row (keyed on PID), drop on a wheel scroll, and re-check at show time that the same row is still under the pointer.
