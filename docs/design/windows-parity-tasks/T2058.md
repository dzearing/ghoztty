# T2058 - drag-perf.ps1 is red with all 11 assertions green: the GUI postmortem scores the three instances its own Kill-RepoInstances stopped (exit 0xFFFFFFFF) as crashes

## Summary

Seen 2026-10-17 by T2056 (acceptance-parallel due, logs %TEMP%/ghoztty-acceptance-parallel/20261017-122643): the drag-perf verdict read `1 FAILURE(S) (11 assertions passed)` with three `GUI POSTMORTEM ghoztty.exe pid ... verdict: CRASHED - 0xFFFFFFFF` blocks beside it. drag-perf ends each pane-count round with Kill-RepoInstances -> Stop-RepoGhoztty, whose Stop-Process leaves exit code -1, and the teardown postmortem read those as crashes.

**Corrected on claim (2026-10-17):** the title's diagnosis is half right. The three CRASHED blocks ARE bogus and are what this task fixes - but they never touched the score. The one FAILURE is a real assertion, printed to stderr (so it was in `03-drag-perf.err.log`, not the stdout log the filer read): `...and it got worse with every split ... 2 waits/move at 2 panes, 2 at 8`. That is T1854's defect (the harness scores 4 and 8 panes with the 2-pane sample), still open. drag-perf stays red until T1854 lands.

## In plain terms

When a test stops its own copy of the terminal on purpose, the test's crash reporter was announcing that the terminal had crashed. Anyone reading the log saw three crash reports for a run where nothing crashed. Now a deliberate stop is recorded as one, and only a terminal that died on its own gets a crash report.

## Goals

- [x] a kill through Stop-RepoGhoztty marks the harness launch record as killed, so the teardown postmortem skips it
- [x] a launch that died on its own before the stop is still reported (the mark is per stopped pid)
- [x] an acceptance section proves both, with a negative control
- [x] the real drag-perf failure is attributed to T1854 instead of to the postmortem

## Fix

`Set-GhozttyHarnessLaunchKilled` (test/win32/lib/AgentLineage.ps1, beside the existing `Get-GhozttyHarnessLaunchedPid` seam into TestDesktop's launch records) sets `Killed` on the record for one pid. `Stop-RepoGhoztty` (test/win32/lib/CleanSlate.ps1) calls it for every pid it actually stops. `Write-TestDesktopPostmortems` already skips `Killed` records (that is how `Remove-TestDesktop`'s own kill stays quiet), so no change was needed there.
