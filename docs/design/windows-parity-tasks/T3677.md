# T3677 - Linux: a close confirmation answered with Cancel stays in the window's dialog stack in the headless harness, and the window's next close request is spent dismissing it

## Summary

Found by T3563's test/linux/cli-remote-disconnect.sh: after close-dialog --op=window then --answer=cancel, the close-dialog seam still reads the dialog as open 15 s later, and the window's next gtk.Window.close() never reaches windowCloseRequest (libadwaita spends it on the stale dialog). An answer that changes the window (Disconnect, Close) leaves cleanly, so the working guess is a frame-clock stall in the headless Weston: nothing redraws, so AdwDialog's close never finishes. Disabling animations via the harness settings.ini did NOT help, so the guess is unproven. Establish whether a real WSLg window shows it (a person pressing Escape/Cancel then the window x), and either fix it or make the harness tick frames; then move cli-remote-disconnect.sh's W1 back onto rdp before W2. Related: +close --force already loops dismissOpenDialog because a dialog 'may still read as visible while it animates out'.

## In plain terms

On Linux, pressing Cancel on a "close this window?" question right after it
appeared left the question on screen anyway, and the window's next close did
nothing but dismiss it. Now Cancel always makes the question go away, and the
next close asks again as it should.

## Root cause

libadwaita 1.5 opens a presented dialog's sheet only on the dialog's second
frame tick (`map_tick_cb` in adw-dialog.c). Until then the sheet is not open,
so `adw_dialog_force_close` -> `adw_floating_sheet_set_open(FALSE)` returns
early: no `closing`, no `closed`, and the tick then opens the sheet anyway. Not
a frame-clock stall (which is why disabling animations did not help): the
headless Weston just ticks slowly enough that the harness's Cancel lands in
that window every run, and a fast Escape/Cancel on a real screen can too. Close
and Disconnect looked clean only because they destroy the window under the
dialog. Fix: `Dialog.close` (src/apprt/gtk/class/dialog.zig, `CloseRetry`)
force-closes, and when no `closed` came out of it retries on each frame tick
until one does (bounded at 240 frames). It logs `dialog close deferred` when
it has to.
