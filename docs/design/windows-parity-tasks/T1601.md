# T1601 - A --command= whose argument holds a quoted path does not run: quoting a path for the pane's shell has no working form

## Summary

Found by T782. test\win32\soak.ps1 split a pane with --shell=cmd and --command=powershell ... -File "<path>". Those quotes never reached the app: PowerShell 5.1 stripped them, so the pane ran the UNQUOTED form and the soak passed. Sending them intact (byte-exact argv, via Invoke-NativeExact) makes the pane run nothing at all - the soak reports 'no telemetry from this pane' and its altscr assertion goes red; measured both ways on 2026-09-15. So a --command= value that needs to quote a path for the pane's shell currently has NO form that works, and any asset path containing a space is unrunnable from a script. Establish what +split/+new-window do with a quoted token inside --command= (does the CLI re-split it, or is it handed to cmd whole?), decide the contract, document it beside --command= on both platforms, and give test\win32\soak.ps1 back its quoting. Acceptance: a split whose --command= runs a script from a path with a space in it.
