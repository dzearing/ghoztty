# T2005 - Lane B refuses ~107 acceptance scripts that hardcode the unscoped agent state dir or layout manifest: make them lineage-aware (Get-GhozttyAgentStateDir) or mark them # @lineage-safe with a reason

## Summary

Found in T1994. Since T1994 the acceptance runner gives every run from a
checkout other than D:\git\ghoztty (lane B's worktree) its own agent lineage,
because the box's default debug lineage there is lane A's agent. A script whose
code matches one of `$script:ApMainPatterns` in `scripts\lib\AcceptanceParallel.ps1`
(hardcodes `local-agent-debug`, hardcodes `session-layout-debug`, or drops
`GHOZTTY_AGENT_INSTANCE`) cannot honor a lineage, so lane B now REFUSES it as a
red row instead of letting it adopt lane A's agent. On 2026-10-16 that is 107
scripts (108 minus acceptance-parallel.ps1, already marked).

Fix, per script: replace the hand-spelled state dir / layout path with the
lineage-aware helpers (`Get-GhozttyAgentStateDir -Root $tmp` in
`test\win32\lib\AgentLineage.ps1`; a layout-path helper alongside it if none
exists - the manifest is lineage-suffixed since T691), or, where the match is
fixture text in a script that never starts an agent (isolation-meta,
agent-instance-lineage, ...), declare `# @lineage-safe - <why>`. Converted
scripts also stop being MAIN and become eligible for the parallel pool in lane A,
which is a speed win there too. Re-run each converted script green.

## Validation criteria

- [ ] `Get-AcceptanceScriptClass` over test\win32\*.ps1 reports 0 scripts with a non-empty `Unscoped`.
- [ ] Every converted script re-run green through `acceptance-parallel.ps1 run` (lane A), and a sample re-run from lane B's worktree.
- [ ] Each `# @lineage-safe` marker carries a reason that is true (the script starts no agent).
