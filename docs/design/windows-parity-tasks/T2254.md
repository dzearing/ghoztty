# T2254 - Mac build check for the T2249 merge: IPCServer.swift was rebuilt from main's per-window-name rework plus this branch's +new-window --name (T968), +reload --config (T893) and +list readonly (T574); nobody has compiled or run it

## Summary

The T2249 merge hit a conflict in `macos/Sources/Features/IPC/IPCServer.swift`:
main 71da9a680 reworked name resolution (`TargetLookup`, `lookup(_:from:)`,
`register(_:_:)`, `bringForward`, `focus.raisesWindow`), and this branch carried
three Mac-side changes main never had. The resolution took main's file and
re-applied the three against main's new API:

- **T968** `+new-window --name` names the first pane and is idempotent by it:
  now `resolveTarget(name)` + `bringForward` under `parsed.focus.raisesWindow`
  (was `!parsed.noActivate` + `makeKeyAndOrderFront`), and the first pane is
  registered with `register(_:.pane(...))` instead of writing `targetRegistry`.
- **T893** `+reload --config`, beside main's new `--caller-pane=` parse.
- **T574** `readonly` in `+list --json` (`IPCMessage.swift` already has it).

Nothing compiled it: this box has no Swift toolchain. Build, run the IPC unit
tests, and check the three behaviours (and that T968's name check agrees with
main's rule that a window name and a pane name never share).

## Validation criteria

- [ ] `zig build -Doptimize=Debug` builds the Mac app.
- [ ] IPC unit tests green (`TargetLookupTests`, `SplitNameCollisionTests`, `PaneNameScopeWindowTests`).
- [ ] `+new-window --name=x` twice opens one window; `+reload --config` reloads; `+list --json` shows `readonly: true` on a read-only pane.
