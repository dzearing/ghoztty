# T2166 - The dashboard server keeps running its old code after task-dashboard.js changes, so a new endpoint 404s until someone restarts it by hand

## Summary

pageVersion() includes the server file's mtime, so the PAGE reloads itself when task-dashboard.js changes - but the node process serving it is the old one, so any endpoint the new page calls (T1182's /api/prs) 404s until a manual -Stop and relaunch. The page now says so for /api/prs, but the general fix is the server noticing its own file changed and re-execing (or the hourly keepalive task restarting a server whose code is stale). Found on T1182.

## In plain terms

The tracker page refreshed itself when its server code changed, but the
program behind it kept running the old code, so new features on the page broke
until someone restarted it by hand. Now the server notices its own code
changed and quietly restarts itself onto the new version a few seconds later,
and a half-saved or broken edit leaves the old one running instead of nothing.

## Goals

- [x] the server re-execs onto new code after an edit settles and parses
- [x] an edit that does not parse keeps the old server answering
- [x] a cheap `/api/server` endpoint says which process and code are serving
