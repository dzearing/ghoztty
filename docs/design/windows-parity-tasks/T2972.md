# T2972 - PA-R06: every drawn frame re-uploads all cell buffers to the GPU, row by row, even when one row changed

## Summary

PA-R06 (audit-1, T2959). generic.zig:1993-1995 syncs uniforms, every bg cell and every fg row list per frame; opengl/buffer.zig:96-119 issues one setSubData per row list (rows + 2 GL calls) and only ever grows (len = total * 2, :108). Dirty-row tracking exists in rebuildCells but the upload ignores it. Cost estimated: ~29 KB bg + up to ~230 KB fg and ~48 GL calls per frame at 160x45. Fix: OpenGL swap_chain_count = 1 (OpenGL.zig:40) means the buffer holds the previous frame, so give each row a fixed slot and upload only dirty rows; skip uniforms when unchanged; cheap interim: one concatenated glBufferSubData. Risk medium: cursor-first/last instance ordering must be kept.

## In plain terms

Every time a terminal pane redraws, it used to send the whole screen's worth
of text and colour data to the graphics card again, in dozens of small
pieces, even when only the cursor line changed. Now it remembers what the
graphics card already has and sends only the part that is different, in one
piece. Busy output and many open panes should cost less CPU.

## Goals

- [x] the OpenGL buffer keeps a CPU mirror of what the GPU holds and uploads only the changed byte range
- [x] the per-row list upload becomes one glBufferSubData (instance order unchanged)
- [x] uniforms skip their upload when unchanged (falls out of the same mirror)
- [x] measured: busy-phase CPU no worse (resize CPU clearly better)

## Evidence

- First cut compared byte-by-byte (`std.mem.indexOfDiff` + a byte back-scan). It measured a REGRESSION on resize (B 25.4 / 28.3 / 28.2 vs A 17.8 / 21.1): walking ~260 KB per pane per unchanged frame one byte at a time cost more than the uploads it saved. Fixed by comparing 512-byte blocks with `std.mem.eql` (wide loads) and only byte-scanning inside the differing block; that is what took resize from 28% to 9-15%.
- The `due` sweep found four harnesses red on HEAD that are not this change's (red again on a forced rebuild with the original buffer.zig): close-undo + rearrange-undo -> T2921, test-desktop-harness -> T2884, overlay-zorder -> T2300.
- Also red on HEAD with and without this change: pane-close-memory (T2692), frame-clock G1/G2 (new T3087), drag-perf all-zero counters (T2690), machine-lock H2 (T2905). Every duplicate filed along the way was folded into its older owner and closed.
