# T3183 - Single-window mode: the desk gradient crossfades from the old workspace's to the new one's on a switch (0.35s, elevated style only)

## Summary

Mac deskEntrance/PaneDeskFade: draw the outgoing workspace's desk over the incoming one and fade it out over 0.35s; nothing fades in the flat style. Reuse the win32 desk renderer (desk_variant, T1832). Child of T3136 (split 2026-11-16). Design (T3136 Details): ONE shared top-level HWND; every workspace keeps its own Window controller; the workspace on show owns the HWND (GWLP_USERDATA, chrome, sidebar), a parked Window has hwnd=null and its pane child HWNDs are reparented (adoptPane-style SetParent, Window.zig:7278) under a hidden park host so they survive the shared HWND closing. Spec: docs/reference/window-modes.md. Acceptance goes in test/win32/single-window-mode.ps1 (one section per child).

## In plain terms

With every workspace in one window, each workspace can have its own
background colour wash. Until now, switching workspaces snapped the window's
background from one colour to the next. Now the old colour melts into the new
one over about a third of a second, the way it does on the Mac. Nothing
changes in the flat style (no background wash), when both workspaces share a
colour, or when Windows' "Animation effects" is off.

## Goals

- [x] a switch to a workspace with another gradient fades the old one out over the new (0.35s, ease-in-out)
- [x] the fade starts with the old desk whole - no flash of the new one first
- [x] no fade between two workspaces with the same gradient, in the flat style, or with Animation effects off
- [x] a close of the workspace on show (the window handed to the next) fades the same way (Mac's close goes through `show`)
- [x] a switch mid-fade ends the old fade cleanly (the surrendering workspace drops it)

## Validation criteria

- [x] the fade starts from the leaving workspace's shade with the old desk whole, steps, draws, and is over by 0.9s - `single-window-mode.ps1` J1 (39 frames, 40 desks, last_keep 0), on the test desktop
- [x] switching back fades the other way; the workspace that left carries no fade - J2
- [x] a switch mid-fade ends the parked one's fade and starts the adopter's - J2b
- [x] same shade to same shade starts no fade and renders no fade desk - J3
- [x] flat style / Animation effects off / same-shade decision, ease curve and the pixel blend - `desk_fade.zig` unit tests (none + win32 lanes)

## Notes

- Blended in `PaneDesk.ensureDesk` at the small size the gradient is rendered
  at, before the bilinear stretch: the stretch is linear, so this equals the
  full-size blend for one more small gradient a frame. The glass quarter copy,
  the sidebar's slice and the chrome glass band all read that same desk, so
  they fade with it.
- Mac draws the fade as a SwiftUI layer over the desk; here it is the desk's
  own pixels, so the cards, shadows and lights are composed over the faded
  desk exactly as they are over a still one.
