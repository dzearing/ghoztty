# T2342 - New Windows windows open maximized by default, as Mac's do now: main flipped the shared maximize default to true; check the win32 window paths honour it and keep the harnesses that assume a restored-size window explicit

## Summary

Mac a0aaed0f2 changes src/config/Config.zig maximize default false -> true (shared core, arrives with the merge task). win32 already honours config.maximize (Window.zig start_maximized; remembered placement, adopted popup and tear-off preview override it). After the merge: confirm a fresh window opens maximized (not fullscreen), +new-window and the Ctrl+Shift+N path, that session restore still applies the manifest's own maximized flag, and that maximize=false gives the remembered/default size. Acceptance harnesses that measure a window's size/position must set maximize=false in their isolated config or they go red. Release notes: 'New windows fill the screen by default.'

## In plain terms

Mac now opens new windows maximized (filling the screen, not full screen) unless you turn that off. The setting is shared, so Windows gets the same default once the code is merged. This task makes sure Windows opens new windows maximized correctly and that turning it off still gives the normal size.

## Goals

- [ ] A fresh window opens maximized (not fullscreen) on Windows
- [ ] +new-window and Ctrl+Shift+N follow the default; session restore keeps the saved maximized state
- [ ] maximize = false gives the remembered/default size
- [ ] Window-size harnesses set maximize = false explicitly

## Validation criteria

- [ ] Unit/config test for the default (none lane)
- [ ] On-box acceptance: new window reads IsZoomed true; with maximize=false it reads false
- [ ] Window-size harnesses stay green after the merge
