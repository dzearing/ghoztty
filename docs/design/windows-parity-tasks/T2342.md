# T2342 - New Windows windows open maximized by default, as Mac's do now: main flipped the shared maximize default to true; check the win32 window paths honour it and keep the harnesses that assume a restored-size window explicit

## Summary

Mac a0aaed0f2 changes src/config/Config.zig maximize default false -> true (shared core, arrives with the merge task). win32 already honours config.maximize (Window.zig start_maximized; remembered placement, adopted popup and tear-off preview override it). After the merge: confirm a fresh window opens maximized (not fullscreen), +new-window and the Ctrl+Shift+N path, that session restore still applies the manifest's own maximized flag, and that maximize=false gives the remembered/default size. Acceptance harnesses that measure a window's size/position must set maximize=false in their isolated config or they go red. Release notes: 'New windows fill the screen by default.'

## In plain terms

Mac now opens new windows maximized (filling the screen, not full screen) unless you turn that off. The setting is shared, so Windows gets the same default once the code is merged. This task makes sure Windows opens new windows maximized correctly and that turning it off still gives the normal size.

## Goals

- [x] A fresh window opens maximized (not fullscreen) on Windows
- [x] +new-window and Ctrl+Shift+N follow the default; session restore keeps the saved maximized state
- [x] maximize = false gives the remembered/default size
- [x] Window-size harnesses set maximize = false explicitly

## Validation criteria

- [x] Unit/config test for the default (none lane) - window_placement.zig `startMaximized` tests (the first reads `Config` defaults), floor-lane -Lane all PASS (lib/none/win32/agent)
- [x] On-box acceptance: new window reads IsZoomed true; with maximize=false it reads false - test/win32/new-window-maximized.ps1 ALL PASS 8/8 (A default zoomed with a smaller restore-down rect, B +new-window zoomed, C --maximize=false restored)
- [x] Window-size harnesses stay green after the merge - Start-OnTestDesktop pins --maximize=false; acceptance-parallel run over the 51 due harnesses: 44 PASS, the reds are all owned by open tasks (T2295 fold sizing - pane-stack-strip reproduced identically with the pin OFF, so not this change; T2318 hook-json; T2327 arp-version; T2354 overlay-zorder; T2355 the same fold cluster)

## Evidence

- The win32 code already honoured `maximize` (Window.zig) and `applyRestoreFrame` already overrides it with the manifest's own flag, so restored windows keep their saved state. The rule is now one pure function, `window_placement.startMaximized`, unit-tested in the none lane.
- Ctrl+Shift+N is the same Window.init path as `+new-window`. It is not driven on the test desktop because it needs real keyboard input.
- Start-OnTestDesktop prepends `--maximize=false` to every ghoztty.exe GUI launch (never to a `+verb` launch). `-DefaultMaximize` opts out, and only new-window-maximized.ps1 uses it.
