# T2956 - When the watchdog finds the loop's pane taken over by the user typing into the loop's own session, the new loop window's claim can be refused while the user keeps that session busy

## Summary

T1482 makes the watchdog open a new window instead of nudging a pane whose last typed prompt is the user's. If the user typed into the loop's OWN session (no /clear), the lock still names that pane and its transcript pulse moves while they work, so the new window's go.md step-0 claim reads the lock as held (BUSY) and stands down; the loop stays down until the user stops. Decide whether the watchdog should release the lock (or the claim take over) when the lock pane's session is judged foreign, and add a go-loop-resume arm for it.
