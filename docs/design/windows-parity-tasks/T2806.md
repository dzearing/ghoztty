# T2806 - Port Mac 2c9432071: every launch clears dead Claude plugin registrations (plugin-not-found / retired-marketplace load errors) via claude plugin uninstall, honours the recorded Switch/Keep choice for a working plugin, and refreshes an outdated built-in integration

## Summary

Mac commit 2c9432071 (main, 2026-11-07) replaced the one-shot plugin migration with a per-launch settle: ask 'claude plugin list --json', uninstall dead registrations whatever the user answered, follow the recorded Switch/Keep choice for a working plugin (ask once when none is recorded), remove the retired marketplace once empty, disable an orphaned enabledPlugins key, and refresh an outdated integration so skills/hooks never freeze at the version that first wrote them. Windows' T870 port is still the one-shot shape. Likely closes T1624 (the plugin coming back after retirement) - verify and close it with this commit. Source: macos/Sources/Features/Setup/ClaudePluginMigration.swift + AppDelegate+Setup.swift; tests ClaudePluginMigrationTests.swift.

## In plain terms

If the old Ghoztty plugin for Claude Code ever came back after Ghoztty took
over its job - even as a broken leftover Claude can no longer load - Ghoztty
stopped updating its own Claude skills and hooks for good, and nothing ever
refreshed them after an upgrade either. Now every launch quietly removes a
broken leftover, respects the user's Switch Over / Keep Plugin answer for one
that still works, and brings an outdated integration up to the running
version.

## Goals

- [x] Dead plugin registrations are removed at every launch, whatever the user answered
- [x] A working plugin follows the recorded answer; with none, the offer is asked once
- [x] A plugin the user switched away from that came back is removed without asking again
- [x] The retired marketplace and orphaned `enabledPlugins` keys are cleared
- [x] An outdated integration is refreshed at launch; a never-installed one is left alone

## Design (Windows translation)

- Pure logic in `src/apprt/win32/claude_plugin_migration.zig`
  (`settleOnLaunch`, `sweepLeftovers`, `clearRegistrationResidue`,
  `refreshIntegration`, `parseHealth`), same rules as Mac's
  `ClaudePluginMigration.settleOnLaunch`. The CLI seam is now `Cli`
  (run + read), passed as an argv to `claude` - no shell, so Mac's
  `shellQuoted` has no counterpart to port.
- The recorded answer already existed as `accepted`/`declined` in
  `<state dir>\claude_plugin_migration`, so Mac's new `ClaudePluginChoice`
  key maps onto it with no new file (`accepted` = switched, `declined` = kept).
- `AgentIntegration.launchCheck` runs the settle every launch (after the 3s
  settle-in sleep, Mac parity) once no first-run offer is pending; the
  first-run offer still takes precedence on the launch it is shown, and the
  settle runs on the next one (no two modals, no concurrent installs).
- Debug builds still never touch the real `~/.claude` (`setupEnabled`, Mac's
  `#if DEBUG` guard) unless `GHOZTTY_CLAUDE_SETUP=force`.
