# T3107 - A viewer pane whose WebView2 browser process dies stays blank on Windows: reload it (capped), and skip the diff viewer git-status poll while nobody can see the pane or the last listing is still running (Mac 6c854957d)

## Summary

Mac 6c854957d (Swift half): a viewer whose WebKit content process dies loads again (capped) instead of staying blank; the git-status poll skips its turn while the pane is not visible or the last listing still runs, superseded listings are not run, patches load on their own queue. On Windows: webview2_iface.zig declares remove_ProcessFailed but nothing subscribes - handle ICoreWebView2 ProcessFailed (render-process exited/unresponsive: Reload, capped; browser-process exited: recreate the controller) and port the poll gating to the win32 diff viewer. The pointer-location / sidebar-subtitle SwiftUI re-render items owe Windows nothing. Validation: kill the msedgewebview2 renderer of a viewer pane - it reloads; repeated kills stop at the cap with a visible message; a hidden diff pane runs no git status (process count/log).

## In plain terms

A document, diff or web page open in a side pane could go permanently blank if
the hidden browser process drawing it crashed, and nothing would bring it back
short of closing the pane. Now the pane quietly loads its page again; if the
page keeps crashing it stops after three tries and says so instead of sitting
blank.

## Goals

- [x] A pane whose page renderer dies or hangs reloads the page it is on
- [x] Capped at 3 reloads a minute; past that the pane shows "This page keeps crashing"
- [x] The browser process itself exiting shows a card instead of a blank (in-place recovery filed as T3115)
- [x] The git-status poll gating: already on Windows (hidden skip T2913, busy-drop T1654, newest-only coalescing); patch queue filed as T3114

## Validation criteria

- [x] Dead-renderer policy (reload / cap 3 in 60 s / browser gone / ignore other processes) - `viewer_process.zig` unit tests, every lane
