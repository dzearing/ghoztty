# T3719 - Linux: a glass pane's sheet keeps the old colour when a program changes the terminal background (OSC 11) - GTK ignores the color_change action

## Summary

T3622 paints the glass sheet in Surface.snapshotGlassSheet from the pane's --color tint or the configured background, and the renderer draws no background on glass. A program that sets the background at runtime (OSC 11, a theme switcher) changes only the renderer's colour, which glass no longer shows: the sheet stays the old colour. GTK lists .color_change as unimplemented (class/application.zig). Fix: handle color_change for the background on GTK, keep it on the Surface and queue a redraw, and have sheetBackground prefer it. Acceptance: a pane-style.sh check that writes an OSC 11 into a glass pane and sees the sheet move by 40% of the change.

**As built (2026-11-26):** `Application.colorChange` handles the core's
`color_change` action; a background change goes to
`Surface.setRuntimeBackground`, which keeps it and queues a redraw. The sheet's
colour is `pane_style.sheetBackground(runtime, tint, configured)`: the runtime
colour first, then the `--color` tint, then the config. A newer
`applyBackgroundTint` clears the runtime colour, so whichever came last wins,
like the Mac's one `SurfaceView.backgroundColor`. OSC 111 arrives as a
`color_change` carrying the default, so a reset puts the sheet back.

## In plain terms

On Linux a pane in the default glass style is a tinted sheet of its terminal's
background colour. When a program changed that colour while running (a theme
switcher, `vim` with a colour scheme), the sheet kept the old colour and the
change never showed. Now the sheet follows the program's colour and goes back
when the program resets it, as on the Mac.
