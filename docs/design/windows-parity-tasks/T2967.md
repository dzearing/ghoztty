# T2967 - PA-R01: a pane's renderer starts rebuilding its whole frame on every wakeup after about 100,000 frames, because the render-state reset counter is never zeroed (generic.zig:1366)

## Summary

PA-R01 (audit-1, T2959). generic.zig:1366-1370 tears down terminal_state once terminal_state_frame_count reaches 100_000 but never resets the counter, so every later updateFrame deinits and rebuilds the RenderState, forces a full row re-shape under the terminal mutex, and defeats the unchanged-frame skip (T1935). Reached in ~15-30 min of streaming, hours for a spinner pane. Fix: set the counter to 0 inside the if (upstream/main already does, generic.zig:1390 there; origin/main does not). Shared code: the Mac half is filed separately.

## Validation criteria

- [ ] terminal_state_frame_count is reset to 0 when the 100_000-frame teardown runs (generic.zig), matching upstream/main
- [ ] a unit test drives the counter past the threshold and asserts the teardown happens once per 100_000 frames, not on every frame after
