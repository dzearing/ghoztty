# T3645 - Linux: a hidden or idle GTK terminal pane gives back its render targets and font atlases

## Summary

docs/reference/memory.md 'Panes that are not drawing give back their frames', GTK half. Since T3571 a pane nobody can see stops BUILDING frames on Linux, but its three swap-chain targets and atlas copies stay allocated: the shared release (generic.zig releaseFrameResources) is gated by OpenGL.releaseHiddenTargetsNow / releaseIdleTargetsNow, which answer false off win32 (OpenGL.zig ~1588-1612). GTK draws on the main thread through GtkGLArea, so the release has to run there with the area's context current (not on the render thread, which has no GL context on GTK): on a pane going unseen (Surface.syncSeen) and after idle_release_ns on screen, then the first frame back draws in full (redraw_after_release / hiddenTargetsReleased). Measure with the software rasterizer like test/linux/pane-close-memory.sh (LIBGL_ALWAYS_SOFTWARE=1 puts GL memory in the app's own private memory): a background-tab pane's memory drops by about its targets' size, and it repaints correctly on show (capture-pane).
