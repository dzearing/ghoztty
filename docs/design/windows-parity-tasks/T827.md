# T827 - Prove +rearrange places viewer panes on Windows, the way main c0c86e88e proved it on the Mac

## Summary

Main c0c86e88e fixed a Mac defect where a layout naming a viewer pane failed with 'pane is no longer alive', making any window holding a preview pane permanently un-rearrangeable, and covered it with RearrangeLayoutTests plus scripts/e2e/rearrange-viewer.py. Reading IpcHandlers.handleRearrange, win32 does not have the defect by construction - it resolves every name to a *PaneView and never through a surface, checks tree membership, and its post-swap focus pick is PaneView-based with a first-leaf fallback - but nothing MEASURES that, so the property is currently an assertion in a task file. Add the on-box coverage (viewer pane in a mixed layout, viewer-only layout, dead pane, wrong window) and, if the check comes back red, promote to P1/M1 and fix.

## In plain terms

Ghoztty can preview a document beside your shell, and it can rearrange a
window's panes on command. On the Mac those two features used to be mutually
exclusive: the moment a window held a preview, asking to rearrange it came back
saying that preview "is no longer alive" - about a pane you were looking at.
Windows was written a different way and does not have that fault, but nobody had
ever checked. Now the box checks it on every build, so it cannot quietly start
having it.

      and says nothing about a pane being "no longer alive" - section A of

- [x] the topology `+list --json` reports afterwards is exactly the one asked
      for, ratios included - section A (`S(horizontal 0.4 S(vertical 0.5 ...))`).
- [x] the viewer is the SAME pane after the swap (id and url unchanged), so its
      rendered page and scroll position are untouched - section A.
- [x] the surviving terminals keep their shells (same pid) and their scrollback
      (a marker printed before the rearrange is still readable after it) -
      section A, via `+read`.
- [x] focus stays on the pane that had it, and a pane the layout omits is gone
      from the tree AND unregistered (`+read --name=` refuses it) - section A.
- [x] a VIEWER-ONLY layout succeeds and leaves the window with one focused
      viewer leaf - the case a surface-based focus pick could not answer -
      section B.
- [x] a layout naming a pane that no longer exists is refused, names the pane,
      and leaves the window UNCHANGED - section C.
- [x] a layout naming a live pane in another window is refused as
      "not in the target window", and neither window changes - section D.
- [x] the property is measured rather than asserted: `-NegativeControl` inverts
      section A's headline and the run fails with exactly ONE failure.
- [x] the harness is standing coverage, not a one-off: `guard-due.ps1` carries a
      `rearrange-viewer` row over `IpcHandlers.zig`, `PaneView.zig` and
      `split_tree.zig`, so a change to any of them makes it DUE.
- [x] the check came back GREEN (45 assertions), so the triage call holds: this
      stays P2 coverage and is not promoted to P1/M1.
