# T1879 - Another window's row in the all-windows sidebar cannot be dragged: Mac drags it into this grid, and drags this window's row onto another window's group to send it there

## Summary

Split from T1829. In Mac's all-windows scope a row is a drag source whatever
window it belongs to: dragging another window's row into this grid brings the
pane here, and dragging one of this window's rows onto ANOTHER window's group
in this sidebar sends the pane into that window's grid (the `.joinWindow`
target; the group lights with an accent outline while it is the target). Both
are the existing cross-window move, through the one drop resolver.

On Windows today a press on another window's row is only a click
(`PaneSidebar.maybeStartRowDrag` refuses it), and the outline's group headers
are not drop targets. Wanted: start the window drag (`beginSidebarDrag`) for a
foreign row, add each other window's group rect to `DropGeometry` as a join
target, paint the header outline while it is targeted, and route the commit
into that window.

## Validation criteria

- [ ] dragging another window's row into this grid moves the pane here
- [ ] dragging this window's row onto another window's group moves it there
- [ ] the target group shows the accent outline while hovered by the drag
- [ ] acceptance section in test\win32\pane-sidebar-drag.ps1 or pane-sidebar-all-windows.ps1
