## Commentary

### Yesterday

**A quiet day of sanding, after a loud day of building.** Monday was rearrange
mode — a whole Mac feature carried across in thirty hours. Yesterday the loop
spent itself on the things that make a build trustworthy rather than the things
that make it new, and closed twenty-six cards doing it.

Two of them you would have felt directly:

- **Asking Ghoztty for an update now always gets an answer.** Check for Updates
  could report "you are up to date" while the updater was actively sitting on an
  update it had already found and suppressed (T1563) — the worst possible
  failure for that button, because it is the one you press when you suspect
  something is wrong.
- **And the answer arrives in a window, not a balloon.** A tray balloon is
  something Windows is free to swallow — during a full-screen app, inside a
  focus-assist window, or just because. A manual check now opens a real dialog
  (T1565). The automatic offer still rides the balloon; that is filed as T1566
  and is in M1 as of this morning.

Around those, a run of smaller fixes to things you can see:

- **Float on Top** now pins the window you are actually on, and the one case
  where it cannot is documented as Windows' own rule (T720).
- The **find bar and the command palette** stopped reaching into the terminal
  underneath them — clicks and keystrokes land where you aimed them
  (T721, T742).
- A **tab can no longer widen** under a pointer that is simply resting on the
  strip (T737).
- A **pane that has to restart its shell** comes back in the folder you were in,
  rather than at your home directory (T752).
- A **page in a viewer pane** now gets its fonts, video and wasm served as what
  they are instead of as generic bytes (T750).
- A **banner's relative path** now means the folder the pane is in, which is
  what anyone writing one would assume (T758).

The rest — fourteen cards — was the test suite auditing itself: the harness
floor became a standing lane (T725), skip-visibility conversions, a fixed-sleep
wait replaced by a real clock, and the composited screenshot path that lets a
test photograph the strip between two panes again.

**What shipped:** `win-v1.36.25`, published yesterday morning from `d006146bf`.
It carries Float on Top, the palette and find-bar fixes, and both update-check
fixes.

**What is stranded:** thirty-seven commits have landed since that release and
are on nobody's machine — everything from mid-morning yesterday onward. That
includes the tab-widen fix (T737), the pane-restart directory fix (T752), the
viewer content-type fix (T750) and the banner path fix (T758). None of them is a
fix somebody reported and is waiting on, so this evening's publish picks them
up; but thirty-seven is the largest gap this month, and it is worth naming that
the daily cadence is now visibly the constraint rather than the floor.

### Reflection

**The seat imbalance is now the oldest fact in the project.** Every open task
untouched for longer than a month is a Mac task — the twenty-five oldest,
without exception, dating back to 2026-08-06. Not one of them is stale in the
sense the triage rules mean; they are simply unstaffed. This seat has closed
roughly a thousand cards in that window and the Mac seat has closed none, and
the cutover to `main` is gated on exactly one of them (T87, the Mac regression
build). Yesterday's digest suggested asking whether that criterion could be met
by CI rather than by a human at a Mac. That suggestion is now a month-old
pattern rather than an idea, and it deserves a decision filed against it rather
than another paragraph.

**The publish cadence has quietly become the bottleneck.** Thirty-seven commits
sat unreleased this morning; on 2026-09-03 the same arithmetic meant the user
re-downloaded a broken installer and re-reported a bug that was already fixed.
The request mechanism (`daily-publish.ps1 -Request`) closes that hole for
anything filed from a user report, and T1315 made it automatic — but it only
fires on user reports. Everything else waits for 17:00. On a day that closes
twenty-six cards, "once a day" means the average fix reaches the user about
twelve hours after it is correct. Publishing per task boundary is probably too
much; publishing when the stranded count crosses a threshold is probably right,
and is a small change to a script that already knows the number.

**The harness work is genuinely converging, and it is worth saying so.** For
three weeks these digests have circled the same complaint: the test suite was
the biggest consumer of turns. Yesterday the six static audits that had to be
remembered became a lane that cannot be forgotten (T725/T777), and the first
thing that lane did was find two of them red. That is the shape of a gate that
works. What is left is the backlog it exposed — T1568's unarmed stamps, T1123's
skip-visibility exceptions, T1523's twenty-one guard rows — and those are
bounded lists rather than an open-ended discipline problem.

**One smaller note, carried a third day:** the main-intake watermark's `note`
field is still a single JSON string holding every previous intake concatenated
together. It has crossed the point where it is unreadable, and it is exactly the
shape the feature-ideas ledger solved with a dated file. Filing it rather than
mentioning it again is the honest move; it goes in today.

## Feature ideas

### Knowing what you are running

- **A release that cuts itself when enough has piled up.** Ship the day's work
  when the stranded-commit count crosses a threshold, not only when the clock
  hits five — so a fix you are waiting on does not sit twelve hours behind a
  release that already went out. *High.*
- **Show me what is in this update before I take it.** The update prompt names
  the version; let it name the three things you would actually notice, pulled
  from the tasks the release carries. *High.*

### Getting out of your own way

- **Undo the last thing the terminal did to my layout.** One chord that reverses
  the last structural change — a closed pane, a split, a moved tab — regardless
  of which gesture caused it. Rearrange mode made layout changes cheap; this
  makes them safe. *High.*
- **A pane that refuses to run the wrong command.** Mark a pane as production or
  remote and have it hold a destructive command for one beat with a plain-language
  confirmation naming the machine. *Medium.*

### Reading what scrolled past

- **Pin a line so it stays on screen.** Pin the command, the error, or the URL
  you need while you keep scrolling — a sticky row at the top of the pane you can
  click to jump back. *High.*
- **Diff two runs of the same command.** Run it twice, ask for the difference,
  and get a viewer pane showing what changed instead of reading two screens side
  by side. *Medium.*

### Smaller frictions

- **Tell me which pane made that noise.** When a bell or a notification fires,
  mark the pane that fired it until you look at it. *Medium.*
- **A window that remembers its font size.** Zoom is per-window and resets;
  make it stick to the window across restarts, the way its size and position do.
  *Medium.*
