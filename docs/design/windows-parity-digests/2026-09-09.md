## Commentary

### Yesterday

**The pane-lag report got an answer, and it was not what anyone guessed.** The
user's complaint was that Claude Code feels sluggish in a Ghoztty pane compared
with the terminal Windows ships. Four turns took that apart in order and each
one ruled a suspect out: the display was innocent, then the parser, then the
relay that carries a kept-alive session. What was left was Windows itself —
it had been quietly running the session-keeper on the slow half of the CPU.
Moving the terminal's own plumbing off those cores took a burst of output from
about twice as slow down to about half again as slow. The rest of the gap is a
genuine trade-off and it is sitting in your Activity feed as **D94**.

**The feedback strip stopped being embarrassing.** Six small fixes landed on the
thing you use to report bugs: a see-through picture is see-through again, a row
of screenshots that runs off the edge now says so and the keyboard can reach
them, and Space in the screenshot picker takes a whole window cropped exactly.

**Three tests that could not fail were made able to fail.** A recurring theme
this week: a check that has never been observed going red is not a check. The
crash-and-restart floor turned out to have been fixed a month ago with nobody
ever running it.

**What shipped:** `win-v1.36.19` on 2026-09-08, carrying everything through the
pane-lag work. **What has not:** eight fixes landed after that release — the
whole feedback-strip batch, the harness work, and last night's daemon fix — and
they are on nobody's machine. Sixteen commits are stranded behind that tag. The
evening publish will carry them tonight; nothing here is a fix somebody is
waiting on, so no early request was filed.

### Reflection

The pane-lag chain is the best week of work this loop has done, and it is worth
naming why: **the report came with a number, and every turn since produced
another number.** "Feels slow" became 1.94x, then 1.55x, then a decision about
the remaining 0.55. Compare that with the harness tasks, where the recurring
finding is a check that was green because it could not be anything else. Same
lesson from both ends — a measurement that cannot come out badly is not a
measurement.

The stranded-commit count is the standing irritant. Sixteen commits behind a
release is a full day of work the user cannot run, and the one-a-day cadence
makes that structural rather than accidental. The publish-on-the-last-good-commit
idea has now appeared in the ideas ledger three days running, which is usually
the signal that it should stop being an idea.

Toward the cutover: nothing moved. **T1074** still waits on **T87** (the Mac
regression build, not this seat's) and **T1179**, and origin/main is quiet —
one docs-only commit in two days.

### Decisions

**D94 is open and it is a real fork in the road**: a restored pane can have
fast output or fast builds, not both, because the fast cores are only a third
of the machine. The recommendation is to keep your commands on the whole
machine and accept the narrowed gap. It needs your call because which one
matters is a question about how you work, not about the code.

## Feature ideas

### User-facing

- **Tell me what this release fixes, in my words** — High. The update prompt
  names a version; the reason to take it is buried in a digest you may not have
  read. Show the two or three plain-language headlines from the tasks the
  release carries.
- **A pane that reads back what you pasted** — High. After a multi-line paste,
  a one-line summary above the prompt ("pasted 40 lines, 3 of them start with
  `rm`") so a bad paste is caught before Enter.
- **Search everything this window has printed** — High. Find-in-page exists in
  viewers but not in a terminal pane's scrollback; a chord that searches back
  through what a pane has shown, with hits marked in the scrollbar.
- **Bookmark this spot in the scrollback** — Medium. Drop a mark before you run
  something noisy, jump back to it afterwards instead of scrolling by feel.
- **A quiet hour** — Medium. One switch that holds every notification and toast
  until you turn it off, and then tells you what it held.

### Technical

- **Publish the moment work is worth publishing** — High. Sixteen stranded
  commits this morning is the third day this pattern has shown up. Cut the
  release on the day's last good commit rather than a clock hour.
- **Measure the pane, not the theory** — Medium. The pane-lag chain needed a
  throughput number and had to invent one each turn. A standing benchmark
  script that reports pane-vs-conhost output rate would make the next
  performance report a measurement instead of an investigation.
- **A guard that reports its own age in the app** — Medium. `guard-due` knows
  which harness has not been run since the code moved; that answer is only
  visible at claim time, buried in 150 lines of CURRENT rows. Summarise to a
  count and show the exceptions.
