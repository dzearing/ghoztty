## Feature ideas

### Sessions you can see

- **Warn me before Windows restarts under me** — *High.* When Windows Update
  schedules a restart, the terminal should notice. It should say which panes
  are still busy and offer to postpone the restart from that same card. The
  reboot on the 21st is the kind that takes running work with it and tells
  nobody.
- **This shell is open in another window: go there, or open a copy** —
  *High.* When you open a session that is already on screen somewhere else,
  say so and offer both choices. Do not quietly pick one. Two windows fighting
  over one shell was a real report this week, and the honest answer is a
  question.
- **Mark the panes that will not come back** — *High.* A small, quiet mark on
  any pane whose shell is not being kept across a restart. Pair it with a
  one-click "keep this one". Today a kept pane and a throwaway pane look
  identical until the restart, which is the only moment the difference matters.
- **After a reboot, show me what ended and put it back** — *Medium.* On the
  first launch after Windows restarted, list the sessions the restart ended.
  That is separate from the ones you closed. Offer to reopen each in its folder
  with its window placement. A restore prompt should know the difference
  between "you closed this" and "the machine did".
- **Tell me how the app closed last time** *(new angle on the crash-restore
  ideas)* — *Medium.* The earlier ideas assume a crash leaves a record. This
  week's didn't. The next launch should say in plain words whether the last
  exit was a quit, a crash, a forced kill or an unexplained disappearance, and
  when.

### Stability

- **A day-long soak before every release** — *Medium.* Before a release goes
  out, run the release build for hours with real panes, splits, restores and
  floods. Hold the release if it ever disappears. Two silent deaths this week
  (T1685, T1686) are the class a quick test run never lasts long enough to see.
- **Rehearse the restart you are relying on** — *Medium.* A standing check that
  quits the app with several windows open, relaunches it, and asserts that every
  window and every kept session came back where it was. It should include the
  window opened in the first second. Each session bug this week was found by
  accident while testing something else.
