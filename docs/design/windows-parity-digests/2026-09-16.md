### Reflection

**The publish cadence stopped being a theme and became the defect.** Three
mornings running, this section has described commits sitting unreleased;
yesterday it was thirty-seven, today thirty-one, and today one of them is a fix
for the first thing you see after a reboot. The mechanism to fix it is filed
(T1588, publish when the stranded count crosses a threshold) and it is M1, but
it keeps losing to whatever the queue hands out. That is the same failure this
digest just diagnosed one paragraph up: a good idea filed at P2 is a good idea
that does not happen. It should be worked this week, not queued this week.

**A flat band is not a priority scheme.** Four hundred and fifty-seven open todos
for this seat, essentially all P2, and the ordering that results is "by id" — in
other words, by filing date, which is uncorrelated with worth. The re-triage
lever exists and is cheap (`set-priority` moves the head of the queue and
journals why), but nothing routinely *asks* the question, so it gets pulled only
when a digest notices. Making that a standing part of triage — promote the two
or three most user-visible open tasks each morning, deliberately — would cost
minutes and would keep the loop pointed at people rather than at file order.

**The harness work has genuinely turned the corner.** Yesterday's fourteen
internal cards were not the open-ended discipline problem of three weeks ago:
they were a bounded list that the harness floor lane produced, and they are being
worked off. The shape to watch now is that *finding* harness defects has become
cheap while *user-visible* work still arrives only by report or by parity sweep.
Cheap detection on one side and manual intake on the other is how a queue drifts
inward, and that drift is what this morning's reordering is pushing back on.

**And the seat imbalance is unchanged.** Eighty-eight open tasks are the Mac
seat's, twenty-five of them untouched since early August, and the cutover to
`main` is still gated on one of them (T87). A month of digests have now said
this. It is not a triage problem and it will not be solved by another paragraph.

## Feature ideas

### Getting to the thing that went wrong

- **Jump to the last command that failed.** One chord walks backwards through
  commands that exited non-zero, marking them in the scrollbar — instead of
  scrolling by hand through a thousand lines of successful output looking for the
  red one. *High.*
- **Copy the output of the last command without selecting it.** One chord grabs
  everything the previous command printed, exactly, with no mouse and no stray
  prompt lines. *High.*

### Working several panes at once

- **Type once, into every pane you chose.** Mark a set of panes and have your
  keystrokes go to all of them — the thing you want the moment you are running
  the same command on four machines. *High.*
- **Drop a file onto a pane and get its path, quoted properly.** Dragging a file
  in should insert a path the shell in that pane will actually accept, spaces and
  all, in that shell's own quoting. *High.*

### Smaller frictions

- **Rename a tab by clicking its name.** Double-click the title, type, done —
  rather than a CLI verb or a config file for something you want to do mid-task.
  *Medium.*
- **Follow the system when it goes dark.** Switch theme with Windows' own
  light/dark setting, at the moment it switches, without a restart. *Medium.*
- **Scrollback that survives a restart.** A restored session brings back its
  shell; it should bring back what that shell had already printed, so a restart
  does not erase the output you were reading. *Medium.*
- **Tell me how long that took, after the fact.** Every finished command quietly
  records its own duration, so you can ask "how long did that build take" when
  you did not think to time it. *Medium.*
