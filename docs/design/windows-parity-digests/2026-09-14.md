## Commentary

### Yesterday

**Rearrange mode is on Windows, and it shipped.** Main added it to the Mac two
days ago: turn on a mode, every pane grows a grab header, and you drag panes
between splits, tabs and windows with a preview of where the pane will land.
Yesterday it was built here end to end — the drop resolver that turns a mouse
position into "what would letting go mean", the split-tree moves that relocate a
pane without restarting its shell, the headers themselves, the in-window drag,
the drop onto another window's tab strip, the move into a different window, and
the release over the desktop that makes the pane a window of its own. Eight
tasks, one day, and the shell in a dragged pane keeps running through all of it.

Worth naming plainly: a Mac feature went from "main shipped it" to "Windows has
it" in about thirty hours. That is the lag this project has been trying to get
down to hours rather than days, and yesterday it was.

Around that, a run of things you can see:

- The **Activity Monitor** now says which window and pane owns a process, and
  its %CPU figure means something again (T709).
- The **machine chooser** opens on the machines it already remembers instead of
  an empty box, and its session list updates live (T710, T711).
- The **New Window picker** no longer freezes the terminal behind it (T712).
- **Signing out** closes the windows that account opened (T713), and the
  **About box** links out, with Help pointing at this project (T714).
- A **Ghoztty link that misses** now warns in Ghoztty's own dialog rather than a
  bare system message box (T717).

**What shipped:** `win-v1.36.23`, published at 02:16 this morning from
`f2761be48` — so it carries all of rearrange mode, the Activity Monitor column,
the chooser work and the About links. Everything above except the last two
items is installable right now.

**What is stranded:** nine commits have landed since that release — T715's quiet

### Reflection

Yesterday broke the pattern the last three weeks of digests kept circling. The
harness sweep is behind us, and the day was spent almost entirely on things a
user can see: a drag gesture, a process list, a picker, an About box. The
question this digest asked on Friday — *can the loop turn back toward the
user-facing queue?* — got answered by doing it.

What is worth watching now is the **shape of the follow-ups**. Rearrange mode
closed eight tasks and filed twelve, most of them polish on the thing just
built. That is healthy — it is what honest self-review looks like after a big
feature — but it means the backlog grows fastest exactly when the work is going
best. The discipline that matters is the M1 call: four of those twelve are
defects in a shipped feature and belong in the convergence target; the other
eight are real but are edges (second monitors, the seventh drop target, popping
out of a maximized window) and they should stay out of it until the four are
closed. A milestone that absorbs every follow-up stops being a milestone.

The cutover gap is unchanged and it is the one thing not moving: `ship-readiness`
still names T87 (the Mac regression build, which is not this seat's) and the
unmerged `origin/main` commits. Everything else on that list is a number this
seat can move; that one needs the Mac seat. It is now the longest-standing
blocker in the project, and it might be worth asking whether the criterion can
be met differently — a CI-run Mac build rather than a human at a Mac — since the
current arrangement has produced no movement in four weeks.

One smaller note, carried over and still true: the main-intake watermark's
`note` field is a paragraph-long archaeological record of every previous intake
concatenated into one JSON string. Nobody has read it in weeks. It wants the
dated-ledger treatment the feature ideas already have.

## Feature ideas

### Picking up where the drag left off

- **Throw a pane at a monitor.** Rearrange mode can drop a pane over the
  desktop to make a window; let a fling toward a screen edge or a second display
  place it there, maximized or half-snapped, without aiming. The gesture you
  already learned, doing the placement you actually wanted. *High.*
- **A layout you can draw.** Open a small grid, sketch the arrangement you want
  — two columns, a wide bottom strip — and have the window rearrange itself to
  match. Dragging is fine for one pane; it is tedious for a whole window.
  *Medium.*

### Getting back to work faster

- **Reopen the window I closed, not just the tab.** Closing a window with six
  panes is one keystroke and an irreversible one; offer the whole window back,
  splits and directories intact, for a few minutes after. *High.*
- **A pane that starts where the last one finished.** New split inherits not
  just the directory but the shell state you care about — the activated
  environment, the ssh session's host, the sudo timestamp — so the second pane
  is useful immediately. *Medium.*

### Knowing what the terminal knows

- **Tell me which panes are actually doing something.** One glance across every
  window: which panes are running, which are idle at a prompt, which are waiting
  on input, sorted by how long they have been that way. The Activity Monitor now
  knows the pane; this is the human-facing half. *High.*
- **A pane that names the machine in its own chrome.** A remote or WSL pane
  should look different, not just be labelled somewhere — a tinted header with
  the host name, so a `rm -rf` typed into the wrong pane is a thing you notice
  before Enter. *Medium.*

### Smaller frictions

- **Open the same layout every morning.** Mark a window as a startup layout and
  have it come back on launch, with each pane's command re-run or re-offered.
  *Medium.*
- **Let a viewer pane follow the pane beside it.** Point a viewer at "whatever
  file the shell last touched" and have it re-render as you work, instead of
  reopening it by hand after every edit. *Medium.*
