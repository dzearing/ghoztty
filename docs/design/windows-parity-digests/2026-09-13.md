## Commentary

### Yesterday

A full day and night of one thing: **making the test harnesses honest**. Nineteen
tasks closed, and the spine of them was T1510/T1511 — a sweep across roughly a
hundred acceptance scripts so that a run which *crashed halfway* can no longer
record itself as proof that the feature works. Before this, a harness that died
in its own middle still wrote a green stamp; the sweep put every one of them on a
shared scorer that knows the difference between "finished and passed" and "stopped
happening". T1517 closed the matching hole at the other end: a harness that hung
in its cleanup used to throw away the run it had just completed.

That is unglamorous work, and it is the right work. Every claim this project makes
about Windows parity rests on those scripts, and a stamp that can be written by a
crash is a claim with nothing behind it.

Alongside it, real user-facing fixes landed: a remote WSL pane now runs the
`--command` you gave it instead of reporting it missing (T704), a screenshot
capture starts on the screen you are reporting from (T706), a reader that captured
nothing says so instead of blaming the pane (T698), and overnight a keybinding
bound to "toggle tab overview" actually opens the pane overview (T708).

**What shipped:** `win-v1.36.22`, published at 01:24 this morning from `b3e5b8455`
— so it carries the bulk of the harness sweep and everything before it.
**What is stranded:** ten commits have landed since that release, including T708's
overview binding and T1012's persistence sweep. Nothing in there is a fix somebody
is waiting on, so the ordinary evening publish will pick them up.

### Today's focus

The queue has a new arrival that jumps most of it: **main shipped pane rearrange
mode** overnight (`b18ee2d77`, plus a fix in `fd7385c42`). On the Mac you can now
turn on a mode where every pane grows a grab header and you drag panes between
splits, tabs and windows, with a preview of where the pane will land. That is a
significant, visible capability, and Windows has nothing like it — moving a pane
today means closing it and opening a new one somewhere else. Three tasks are filed
(T1524, T1525, T1526) and all three are in M1.

Beyond that, the guard-due list is long this morning — a dozen acceptance harnesses
were edited by the T1511 sweep and have not been run since. That is the sweep's own
bill coming due, and working it off is what proves the sweep did not break anything.

### Reflection

Three weeks of digests keep circling the same theme, and yesterday was its purest
expression: **this project's real product right now is trustworthy evidence.** The
features are mostly there. What has repeatedly not been there is the ability to
believe a green line. Every gate added this month — the demonstration rule for new
gates, the guard-due staleness check, the push check, the CI verdict, and now the
crash-aware scorer — is the same lesson relearned at a different altitude: *a check
that has never been observed failing is indistinguishable from a check that cannot
fail.*

The cost of that lesson is visible in the shape of the backlog. 548 open tasks, and
a large fraction of them are infrastructure about infrastructure. That is defensible
while the harness was untrustworthy. It stops being defensible the moment the sweep
is finished — and it is finished. **The honest question for the next few days is
whether the loop can turn back toward the user-facing queue** and leave the harness
alone unless something actually goes red.

Rearrange mode is a good forcing function for that. It is a big, mouse-driven,
visual feature with no Windows counterpart, and it cannot be faked with a stamp.
It also lands squarely on the cutover gap: `ship-readiness.ps1` still names T87 and
the unmerged `origin/main` commits every time it runs, and every day main adds
another feature to that pile. Rearrange mode is now on it.

One process note worth acting on: the intake watermark's `note` field has grown
into a paragraph-long archaeological record — every previous intake concatenated
into one JSON string. It is unreadable, and nobody has read it in weeks. Worth
splitting into a proper dated ledger the way the feature ideas have one.

## Feature ideas

### Two views onto one pane

- **A second window onto the same pane.** Split a pane and have both halves show
  the *same* shell — read the error at the top while the build keeps scrolling at
  the bottom, no scrollback juggling. *High.*
- **Move panes with the keyboard, not just a drag.** Rearrange mode is arriving as
  a mouse gesture; give it a keyboard half — enter the mode, then arrow a pane into
  the neighbouring split, tab or window. Faster than dragging, and it is the only
  version that works over RDP. *High.*

### Organising a busy window

- **Tab groups.** Colour-label a run of tabs ("api", "web", "logs"), collapse a
  group to one chip, and have the grouping survive a restart. The browsers solved
  this years ago and a terminal with fifteen tabs has the same problem. *High.*
- **Click any crumb of the path to go there.** Show the pane's working directory as
  a breadcrumb in its header; clicking a segment changes directory to it.
  Navigation without typing a stack of `..` segments. *Medium.*

### Being told things properly

- **A taskbar badge when a background window wants you.** Per-pane toasts exist in
  the idea pile; this is the window-level version — the Windows taskbar button
  carries a count and flashes when a window you cannot see needs input or has
  finished. *Medium.*
- **A config reload that says what changed, and refuses a broken file without
  dropping you.** Save the config and get a short toast naming the settings that
  moved; a file that does not parse keeps the old config live and shows the parse
  error instead of half-applying. *Medium.*

### Small things with real friction behind them

- **Copy with the colours intact.** Put an HTML/RTF flavour on the clipboard
  alongside the plain text, so pasting a coloured diff or test run into a doc, chat
  or issue looks like what you saw. *Medium.*
