### Reflection

**The smoothness work has moved from "find the cause" to "trim the
budget".** A week ago each blade card named a cause: a whole-desk redraw,
a shape re-cut every frame, a resize the user never asked for. Yesterday's
cards measure milliseconds inside one frame. Fixes now land in tenths of a
millisecond, and each one needs a five-run A/B on a release build to be
believed. That is the right method, but it is slow. A standing 4K A/B
runner in the repo (today it is a hand-written script in `temp\` that each
turn rebuilds) would make every one of these cheaper.

**A perf measurement is only as clean as the box.** Lane B's compiles
skewed one 4K run to 55 dropped frames against 0-2 on a quiet box (T2944).
The timing lock keeps the other lane's timing scripts out, but not its
builds. Until that is fixed, any perf number taken while lane B is building
is suspect.

**A turn's progress log is its insurance.** This is the second day running
that a dead turn's work was recovered from its task file. The reset at
09:45 cost nothing because the findings and the A/B numbers were written
down before the commit.

## Feature ideas

### What you see and press

- **Type before the shell is ready, and lose nothing** - *High.* Open a
  pane and start typing straight away. Every key you press in its first
  second is held and arrives at the prompt in order, instead of the first
  few characters vanishing while the shell starts.
- **Bring your Windows Terminal setup with you** - *High.* The first time
  Ghoztty runs, it offers to bring over your Windows Terminal profiles:
  the shells, their starting folders, the colour scheme and the font. Your
  first window already starts and looks like the one you came from.
- **A link opens in the browser profile it belongs to** - *Medium.* A link
  printed in a work project's pane opens in your work Edge profile, and one
  from a personal folder opens in your personal profile, by a folder rule
  you set once. (New angle on choosing where a link opens.)

### Under the hood

- **Typing stays first in line when the PC is busy** - *Medium.* While a
  build or another app pins every core, keystrokes and the cursor still
  answer at once, because handling your input always runs ahead of
  background work.
- **The first window reuses yesterday's glyphs** - *Medium.* The letters
  drawn at your font size are kept on disk, so the first window after a
  restart shows sharp text at once instead of drawing every letter again.
